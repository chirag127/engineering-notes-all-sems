Change control is a methodology used to manage any change requests that impact the baseline of your project. It involves identifying, documenting, evaluating, approving, implementing, and reviewing changes in a systematic and consistent way. Change control helps to ensure that the project scope, schedule, cost, quality, and risks are properly managed and aligned with the project objectives and stakeholder expectations.

Change identification: This step involves recognizing the need for a change in the project, either from internal or external sources. The change request is formally documented and submitted to the change control board (CCB) for evaluation.

Change evaluation: This step involves analyzing the impact, feasibility, and benefits of the change request on the project. The CCB considers various factors, such as the project scope, schedule, cost, quality, and risks, as well as the stakeholder expectations and satisfaction. The CCB then decides whether to approve, reject, or defer the change request.

Change approval: This step involves communicating the decision of the CCB to the change requester and other relevant stakeholders. If the change request is approved, a change order is issued to authorize the change implementation. If the change request is rejected, a rationale is provided to the change requester and the change is closed. If the change request is deferred, a reason and a timeline are given to the change requester and the change is put on hold.

Change implementation: This step involves executing the approved change according to the change order. The project team updates the project plan, schedule, budget, and other documents to reflect the change. The project team also monitors and controls the change implementation to ensure that it meets the quality standards and the project objectives.

Change review: This step involves verifying and validating the change implementation and its outcomes. The project team checks if the change has been implemented correctly and if it has delivered the expected benefits. The project team also evaluates the performance and effectiveness of the change control process and identifies any lessons learned or best practices for future changes. The change is then formally closed and documented in the change log.
