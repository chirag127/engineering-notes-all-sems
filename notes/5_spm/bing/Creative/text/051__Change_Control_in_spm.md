### Change Control in SPM

Change control is a methodology used to manage any change requests that impact the baseline of your project. It’s a way to capture that change from the point where it’s been identified through every step of the project cycle. That includes evaluating the request and then approving, rejecting or deferring it. The purpose of this process is to make sure that you’re not changing things in the project that don’t need to be changed. The last thing you want to do is disrupt the project for no good reason, wasting valuable time and resources. Any changes that are approved are then documented. The change control process is part of the larger change management plan.

Some key points to remember about change control in SPM are:

- Change control is triggered by a change request, which is a formal petition for change in a project. It’s a document that explains what are the changes to be made and the main reasons why they should be implemented. Change requests can either be submitted by internal or external project stakeholders.
- Change control involves a change control board, which is a group of representatives from the project team that regularly meet to approve or disapprove change requests. If they approve a change request, it can turn into a change order, which is an agreement from both parties to change the conditions that were first drafted in the original contract.
- Change control requires a change log, which is a change management tool that’s used to document all the changes made to a project plan or any contracts. It’s a must-have tool for any project manager.
- Change control can be permanent or temporary, depending on the nature and duration of the change. A permanent change is a planned departure or modification or addition or deletion from an approved/qualified process/policy/document/system/material/method/equipment etc. A temporary change is a short-term deviation from an approved/qualified process/policy/document/system/material/method/equipment etc.
- Change control can improve the performance, engagement, innovation, and quality of a project. It can also help to adopt new technologies, implement new requirements, fix any bugs/errors, and reduce cost.
- Change control can also pose some challenges and risks, such as resistance from stakeholders, communication issues, scope creep, schedule delays, budget overruns, and quality problems. Therefore, change control should be carefully planned, executed, monitored, and controlled.
