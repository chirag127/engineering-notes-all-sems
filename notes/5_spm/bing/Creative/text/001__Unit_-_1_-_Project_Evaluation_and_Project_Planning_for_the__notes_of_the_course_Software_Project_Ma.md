## Unit - 1 - Project Evaluation and Project Planning

- Project evaluation is the process of assessing the feasibility, desirability, and viability of a software project before initiating it.
- Project planning is the process of defining the scope, objectives, tasks, resources, schedule, budget, and quality standards of a software project.
- Project evaluation and planning are essential for software project management, as they help to align the project with the stakeholders' expectations, identify and mitigate risks, allocate and optimize resources, and monitor and control the project progress and performance.
- Project evaluation and planning involve the following steps:

  - **Project initiation**: This is the first step, where the project idea or need is identified and analyzed. The project sponsor or initiator prepares a project proposal or a business case, which describes the problem or opportunity, the proposed solution, the expected benefits and costs, the feasibility and risks, and the alternatives and assumptions of the project. The project proposal is then reviewed and approved by the project stakeholders, such as the customers, users, managers, developers, and other interested parties.
  - **Project definition**: This is the second step, where the project scope and objectives are defined and agreed upon by the project stakeholders. The project scope defines the boundaries and deliverables of the project, while the project objectives define the desired outcomes and success criteria of the project. The project scope and objectives are documented in a project charter or a project scope statement, which serves as the basis for further planning and execution of the project.
  - **Project estimation**: This is the third step, where the project size, effort, duration, and cost are estimated based on the project scope and objectives. The project size is measured in terms of the number of functions, features, or requirements that the project will deliver. The project effort is measured in terms of the number of person-hours or person-days that the project will consume. The project duration is measured in terms of the calendar time that the project will take to complete. The project cost is measured in terms of the monetary resources that the project will require. The project estimation is done using various techniques, such as analogy, expert judgment, parametric, bottom-up, top-down, or hybrid methods. The project estimation is documented in a project estimate or a project budget, which serves as the input for further planning and execution of the project.
  - **Project scheduling**: This is the fourth step, where the project tasks, dependencies, milestones, and deadlines are identified and arranged in a logical sequence. The project tasks are the smallest units of work that the project will perform. The project dependencies are the relationships or constraints among the project tasks, such as precedence, resource, or technical dependencies. The project milestones are the significant events or deliverables that mark the progress or completion of the project. The project deadlines are the fixed dates or timeframes that the project must meet or adhere to. The project scheduling is done using various tools, such as Gantt charts, network diagrams, critical path method, or agile methods. The project scheduling is documented in a project schedule or a project plan, which serves as the guide for further execution and control of the project.
  - **Project resourcing**: This is the fifth step, where the project human, material, and financial resources are identified and allocated to the project tasks. The project human resources are the people who will perform the project tasks, such as the project manager, the project team, the project sponsor, the project stakeholders, and the project suppliers. The project material resources are the physical or tangible items that the project will use or produce, such as the hardware, software, equipment, tools, materials, or documents. The project financial resources are the monetary or intangible items that the project will spend or earn, such as the project budget, the project funding, the project revenue, or the project profit. The project resourcing is done using various techniques, such as resource leveling, resource allocation, resource loading, or resource management. The project resourcing is documented in a project resource plan or a project budget, which serves as the input for further execution and control of the project.
