### Formulating Network Model in SPM

- A network model is a graphical representation of the activities and their interrelationships in a software project.
- A network model can help to plan, schedule, monitor and control the project activities, as well as to identify the critical path and the slack time of each activity.
- A network model can be formulated using different methods, such as activity-on-node (AON), activity-on-arrow (AOA), or precedence diagramming method (PDM).
- In AON, each activity is represented by a node (box) and the dependencies between activities are represented by arrows (lines) connecting the nodes. The arrows can have different symbols to indicate the type of dependency, such as finish-to-start (FS), start-to-start (SS), finish-to-finish (FF), or start-to-finish (SF).
- In AOA, each activity is represented by an arrow (line) and the events of starting and finishing an activity are represented by nodes (circles). The nodes are numbered sequentially to indicate the order of events. A dummy activity (dashed line) is used to show a dependency that does not involve any work or time.
- In PDM, each activity is represented by a node (box) and the dependencies between activities are represented by arrows (lines) connecting the nodes. The arrows can have different symbols to indicate the type of dependency, as well as the amount of lag or lead time between the activities.
- To formulate a network model, the following steps are usually followed:
  - Identify the activities and their durations, based on the work breakdown structure (WBS) and the estimation techniques.
  - Identify the dependencies and the constraints between the activities, based on the scope statement, the project charter, and the expert judgment.
  - Choose a method to represent the network model, such as AON, AOA, or PDM, and draw the network diagram using the appropriate symbols and conventions.
  - Check the network diagram for errors, such as missing or redundant activities, incorrect dependencies, or illogical sequences.
  - Calculate the earliest and latest start and finish times, the duration, and the float of each activity, using the forward and backward pass techniques.
  - Identify the critical path, which is the longest path in the network diagram, and the critical activities, which are the activities with zero float.
  - Update and revise the network model as the project progresses, to reflect the changes in the project scope, schedule, and resources.
