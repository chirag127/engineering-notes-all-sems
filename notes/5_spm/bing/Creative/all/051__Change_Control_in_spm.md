### Change Control in spm

Change control is a methodology used to manage any change requests that impact the baseline of your project. It is a way to capture that change from the point where it is identified through every step of the project cycle. That includes evaluating the request and then approving, rejecting or deferring it. The purpose of this process is to make sure that you are not changing things in the project that do not need to be changed. The last thing you want to do is disrupt the project for no good reason, wasting valuable time and resources. Any changes that are approved are then documented. The change control process is part of the larger change management plan .

Some key elements of change control are:

- Change Control Board: A change control board is a group of representatives from the project team that regularly meet to approve or disapprove change requests. If they approve a change request, it can turn into a change order.
- Change Requests: A change request is a formal petition for change in a project. It is a document that explains what are the changes to be made and the main reasons why they should be implemented. Change requests can either be submitted by internal or external project stakeholders.
- Change Orders: Once the change control board has approved a change request, a change order is signed by the board and the clients or stakeholders. This is an agreement from both parties to change the conditions that were first drafted in the original contract.
- Change Log: A change log is a change management tool that is used to document all the changes made to a project plan or any contracts. It is a must-have tool for any project manager.

The role of the change request is usually the trigger that starts the process of change control. The change request can originate from stakeholders asking for new features, the need to repair something that proves faulty during the execution phase, upgrades or any number of other causes.

The process of change control can be summarized as follows:

- Creating a request for change
- Reviewing and assessing a request for change
- Planning the change
- Testing the change
- Creating a change proposal
- Implementing changes
- Reviewing change performance
- Closing the process

Some benefits of change control are:

- Improving performance
- Increasing engagement
- Enhancing innovation
- Including new technologies
- Implementing new requirements
- Reducing cost

Some challenges of change control are:

- Resistance to change
- Lack of communication
- Unrealistic expectations
- Inadequate resources
- Conflicting priorities

Some best practices for change control are:

- Define the scope and objectives of the change
- Identify the stakeholders and their roles
- Establish a clear and transparent process
- Communicate the change and its benefits
- Monitor and measure the change outcomes
- Provide feedback and support

A possible mnemonic to remember the steps of change control is:

**C**reate a request for change

**R**eview and assess a request for change

**P**lan the change

**T**est the change

**C**reate a change proposal

**I**mplement changes

**R**eview change performance

**C**lose the process
