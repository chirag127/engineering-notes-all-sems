### Formulating Network Model in spm

- A network model is a graphical representation of the activities and their interrelationships in a software project.
- A network model helps to plan, schedule, monitor and control the project activities and resources.
- A network model can also be used to analyze the project risks, uncertainties, trade-offs and alternatives.
- There are two main types of network models: activity-on-node (AON) and activity-on-arrow (AOA).
- In AON, the nodes (boxes) represent the activities and the arrows (lines) represent the dependencies or precedence relationships between the activities.
- In AOA, the arrows (lines) represent the activities and the nodes (circles) represent the events or milestones of the activities.
- The first step in formulating a network model is to identify the project activities and their dependencies.
- The second step is to assign durations and resources to each activity.
- The third step is to draw the network diagram using either AON or AOA notation.
- The fourth step is to calculate the critical path and the slack time for each activity.
- The critical path is the longest path in the network diagram that determines the minimum project duration.
- The slack time is the amount of time that an activity can be delayed without affecting the project duration.
- The fifth step is to update and revise the network model as the project progresses and new information becomes available.

- A mnemonic to remember the steps of formulating a network model is: IDARC (Identify, Draw, Assign, Revise, Calculate).
- A learning trick to understand the difference between AON and AOA is to think of AON as a box of chocolates and AOA as a string of pearls. In AON, each chocolate is an activity and the wrapper is the dependency. In AOA, each pearl is an event and the string is the activity.
