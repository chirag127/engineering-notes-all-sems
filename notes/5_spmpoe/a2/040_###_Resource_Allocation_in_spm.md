### Resource Allocation in spm

Resource allocation is an important concept in spm. It refers to allocating the available limited resources to various competing processes in an optimal manner. Some key points about resource allocation in spm are:

1. Resource allocation is non-deterministic: In spm, resource allocation is non-deterministic. The operating system does not know which process will request resources in advance and in what order. So, it cannot determine in advance how resources will be allocated to processes. The allocation is done on-demand as and when processes request resources.

2. Resource allocation is based on priorities: In spm, each process is assigned a priority. Higher priority processes are allocated resources first before lower priority processes. This ensures critical processes get resources and priority over less important processes. The priority of a process can be static (does not change) or dynamic (keeps changing based on factors like resource needs, time limits, etc.).

3. Resource allocation aims to maximize throughput and fairness: The goal of resource allocation in spm is to maximize throughput (number of processes completed per unit time) and fairness (each process gets a fair share of resources). However, these two goals can conflict with each other in which case a trade-off is made between throughput and fairness based on the requirements.

4. Common resource allocation strategies: Some common resource allocation strategies in spm are first-come, first-served (fcfs), shortest job first (sjf), shortest remaining time first (srtf), priority scheduling, round-robin, etc. The strategy to use depends on factors like whether preemption is allowed or not, importance of throughput or fairness, complexity of implementation, etc.
