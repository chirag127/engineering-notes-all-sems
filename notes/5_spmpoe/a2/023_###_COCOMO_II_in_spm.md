### COCOMO II in spm

COCOMO II is a regression model that estimates effort, schedule, and cost for software development projects. It was developed by Barry Boehm.

The basic COCOMO II model consists of three sets of formulas:

-   Early Design models - used in the early stages of software development when little detail is known. It uses number of Unadjusted Function Points (UFPs) as the size measure.
-   Post-Architecture models - used after the software architecture has been defined but before detailed design begins. It uses number of Function Points (FPs) as the size measure.
-   Detailed Design models - used when the software design is well understood. It also uses FPs as the size measure.

The set of formulas used depends on the stage of development and the amount of historical data available for calibration. The formulas estimate effort in person-months, schedule in months, and costs in dollars.

The inputs to COCOMO II are:

-   Size measure (FPs or UFPs) - quantifies the functionality and complexity of the software.
-   Scale factors - captures product, personnel, project, and environmental attributes that affect effort and schedule. The scale factors are each rated on a scale of very low to extra high.
-   Effort multiplier - adjusts the raw effort estimate up or down to account for development mode (organic, semi-detached, embedded) and team experience.

The key benefits of COCOMO II are:

-   It is calibrated using historical project data so estimates may be more accurate if sufficient relevant data is available.
-   It considers the effects of risks and scale factors on effort and schedule.
-   It provides a framework for managing software development projects based on estimating and tracking effort and progress.

However, the disadvantages are:

-   It requires detailed size estimates early in the project which can be difficult to obtain accurately.
-   It is based on expert judgment which can introduce bias.
-   It does not directly consider productivity impacts from modern tools and techniques.
-   The scale factors are subjective and open to interpretation.
