### Prioritizing Monitoring in spm

The following points discuss how to prioritize monitoring in software performance monitoring (spm):

1. Monitor business critical transactions: The transactions that are critical to business functions should be monitored first. These include transactions like order placement, payment processing, etc. Monitoring these transactions helps identify issues that can affect business.

2. Monitor resource intensive transactions: The transactions that consume a lot of resources like memory, CPU, database, etc. should be monitored next. These transactions can slow down the system and affect performance if not optimized. Monitoring them helps in finding bottlenecks and scaling resources.

3. Monitor error prone transactions: The transactions that have a high probability of errors should be monitored to identify and fix issues quickly. This helps in maintaining a good user experience and high system reliability.

4. Monitor throughput and response time: Throughput and response time of the overall system and major transactions should be monitored to gauge the performance of the system. This helps in taking actions before performance degrades beyond acceptable limits.

5. Monitor key performance indicators: The key performance indicators (KPIs) of the system like number of concurrent users, revenue, orders, etc. should be monitored to understand the business impact of performance issues. This helps correlate system metrics with business metrics.
