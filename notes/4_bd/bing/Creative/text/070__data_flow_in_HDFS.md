#### Data flow in HDFS

- HDFS stands for Hadoop Distributed File System, which is a distributed file system solution built to handle big data sets on off-the-shelf hardware. It can scale up a single Hadoop cluster to thousands of nodes.
- HDFS is a module of Apache Hadoop, an open-source framework capable of data storage, processing, and analysis. HDFS serves as a Hadoop file system, and its primary goal is to grant access to Hadoop file system data.
- HDFS features high throughput data access, increased fault tolerance, low cost of deployment, high portability, data locality, and flexibility.
- HDFS works by writing data once on the server and reading it several times. This reduces the overhead of repeated read/write actions and improves the speed of data processing.
- HDFS consists of two types of nodes: NameNode and DataNode. NameNode is the master node that manages the file system metadata and controls the access to files. DataNode is the slave node that stores the actual data blocks and performs read and write operations on them .
- HDFS splits the files into fixed-size blocks (default size is 64 MB) and distributes them across the DataNodes. Each block is replicated on multiple DataNodes for fault tolerance. The default replication factor is 3 .
- HDFS follows a master/slave architecture, where the NameNode communicates with the DataNodes and the client applications. The NameNode maintains a mapping of file names to blocks and their locations on the DataNodes. The DataNodes periodically send heartbeat and block report messages to the NameNode to report their status and the blocks they are holding .
- HDFS supports two types of data flow: read and write. In read operation, the client requests the NameNode for the block locations of the file it wants to read. The NameNode returns the list of DataNodes that have the replicas of the blocks. The client then contacts one of the DataNodes and reads the data from it. The client can read the data in parallel from multiple DataNodes if the file is split into multiple blocks .
- In write operation, the client requests the NameNode for a new file name and the list of DataNodes to store the blocks. The NameNode allocates the blocks and the DataNodes and returns them to the client. The client then writes the data to the first DataNode in the pipeline, which replicates it to the next DataNode, and so on. The client can write the data in parallel to multiple DataNodes if the file is split into multiple blocks.
- HDFS also supports some other data flow operations, such as append, delete, rename, and copy. These operations involve the communication between the NameNode and the DataNodes, and the update of the file system metadata.
- HDFS is designed to handle large files and streaming data access. It is not suitable for low-latency data access, random read/write operations, or multiple writers.
