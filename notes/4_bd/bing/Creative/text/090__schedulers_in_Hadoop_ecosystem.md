#### Schedulers in Hadoop Ecosystem

Schedulers are algorithms that are used to allocate resources and schedule tasks in a Hadoop cluster. They are responsible for managing the job queues and assigning the available slots to the jobs based on some criteria. Different types of schedulers have different advantages and disadvantages depending on the use case and the cluster configuration. The following are some of the common types of schedulers in Hadoop:

- **FIFO (First In First Out) Scheduler**: This is the default scheduler in Hadoop. It schedules the jobs in the order of their submission. The first job in the queue gets all the available slots until it finishes, and then the next job gets the slots, and so on. This scheduler is simple and easy to execute, but it does not consider the priority or the size of the jobs. Therefore, it is not suitable for a shared cluster where different users may have different requirements and expectations.  
- **Capacity Scheduler**: This scheduler allows multiple tenants to share a large Hadoop cluster. It divides the cluster into multiple queues, each with a predefined capacity of slots. Each queue can have its own access control, priority, and configuration. The jobs in each queue are scheduled in a FIFO manner, but the scheduler also tries to balance the overall cluster utilization by allocating the free slots to the queues that need them. This scheduler is more flexible and fair than the FIFO scheduler, but it requires more configuration and administration.  
- **Fair Scheduler**: This scheduler aims to provide a fair share of the cluster resources to each user or group over time. It organizes the jobs into pools, which can have different weights, minimum shares, and limits. The scheduler dynamically adjusts the number of slots assigned to each pool based on the demand and the fair share. The jobs in each pool are scheduled in a FIFO manner, but the scheduler can also preempt the running tasks if some pool is below its fair share for a long time. This scheduler is more responsive and adaptive than the capacity scheduler, but it may cause more overhead and fragmentation.
