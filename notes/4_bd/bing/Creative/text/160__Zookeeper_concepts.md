#### Zookeeper concepts

Zookeeper is a distributed coordination service that provides common services such as naming, configuration management, synchronization, and group services for distributed systems. Zookeeper has a simple client-server model, where clients are nodes (machines) that use the services, and servers are nodes that provide the services. Zookeeper has the following key concepts:

- **Znode**: A znode is a file that persists in memory on the Zookeeper servers. Znodes can store data, have a name, and a path. Znodes can be either regular or ephemeral. Regular znodes persist until they are explicitly deleted, while ephemeral znodes are automatically deleted when the client that created them disconnects. Znodes can also have sequential names, which means that Zookeeper appends a monotonically increasing number to the name of the znode. Znodes form a hierarchical namespace, similar to a file system.
- **Watch**: A watch is a notification mechanism that allows clients to be notified of changes to znodes. Clients can set watches on znodes, and Zookeeper will send a one-time notification to the client when the znode changes (such as data update, creation, deletion, or children change). Watches help clients to synchronize their state with the Zookeeper servers.
- **Session**: A session is a connection between a client and a Zookeeper server. Sessions have timeouts, which means that if the server does not hear from the client within a specified time, it will consider the session expired and release any resources held by the client, such as ephemeral znodes and watches. Clients can also explicitly close their sessions when they are done with Zookeeper.
- **Quorum**: A quorum is a majority of Zookeeper servers that agree on the state of the system. Zookeeper uses a consensus protocol to ensure that all the servers have a consistent view of the znodes and their data. A quorum is needed for any operation that changes the state of the system, such as creating, deleting, or updating znodes. Read operations can be served by any server, as long as it is up to date with the quorum.
