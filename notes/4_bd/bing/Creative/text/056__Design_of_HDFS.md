#### Design of HDFS

HDFS is a distributed file system that runs on commodity hardware and is designed to store and process large data sets with high throughput and fault tolerance. HDFS is based on the Google File System and is part of the Apache Hadoop project. Some of the key features and design principles of HDFS are:

- **Large files**: HDFS is optimized for storing and streaming very large files, typically in the range of gigabytes to terabytes. HDFS does not support random access or modifications to files, but rather provides a write-once-read-many access model.
- **Data blocks**: HDFS splits files into fixed-size blocks (default 128 MB) and distributes them across the nodes in the cluster. Each block is replicated on multiple nodes (default 3) to ensure availability and durability. HDFS uses a master-slave architecture, where a single NameNode manages the file system namespace and metadata, and multiple DataNodes store and serve the data blocks.
- **Data locality**: HDFS follows the principle of "moving computation is cheaper than moving data". HDFS tries to place the data blocks close to the nodes where they are processed, to reduce network traffic and improve performance. HDFS also supports rack-awareness, which means that it tries to place replicas of the same block on different racks, to increase fault tolerance and availability.
- **Scalability**: HDFS can scale to thousands of nodes and store petabytes of data. HDFS can handle node failures and network partitions by detecting and recovering from them automatically. HDFS can also rebalance the data blocks across the cluster to ensure even distribution of load and space utilization.
- **Portability**: HDFS can run on various types of hardware and software platforms, and supports different file formats and compression codecs. HDFS also provides a standard interface for applications to interact with the file system, such as the Hadoop FileSystem API, the Hadoop Shell, and the Hadoop Web UI.
