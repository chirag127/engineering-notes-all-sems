#### YARN

- YARN stands for Yet Another Resource Negotiator. It is a framework for managing and scheduling distributed computing resources in a cluster of nodes.
- YARN was introduced in Hadoop 2.0 as an improvement over the previous MapReduce framework, which was limited by its fixed two-stage data processing model.
- YARN decouples the resource management and scheduling functions from the data processing logic, allowing for a variety of applications to run on the same platform, such as MapReduce, Spark, Hive, HBase, etc.
- YARN consists of two main components: the Resource Manager and the Node Manager. The Resource Manager is the master daemon that runs on a dedicated node and oversees the allocation of resources to different applications. The Node Manager is the slave daemon that runs on each worker node and monitors the resource usage and health of the node.
- YARN also introduces the concept of Application Master, which is a process that coordinates the execution of a specific application on the cluster. The Application Master requests resources from the Resource Manager, launches and monitors containers on the Node Managers, and communicates with the client.
- A container is a unit of resource allocation in YARN, which consists of a certain amount of memory, CPU, disk, and network bandwidth. A container can run a single task or multiple tasks of an application, depending on the application logic and configuration.
- YARN provides a web-based user interface for monitoring and managing the cluster and the applications. The web UI can be accessed at http://<resource_manager_host>:8088 by default.
- YARN also provides a command-line interface for interacting with the cluster and the applications. The command-line tool is called yarn and can be used to submit, kill, list, and get the status of applications, as well as to view the logs and configuration of the cluster and the nodes.
- YARN is designed to be scalable, fault-tolerant, and flexible. It can support thousands of nodes and applications, handle node and application failures, and accommodate different types of workloads and frameworks.
