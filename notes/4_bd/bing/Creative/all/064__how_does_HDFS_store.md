#### How does HDFS store

- HDFS stands for Hadoop Distributed File System, which is a distributed file system designed to run on commodity hardware and to store large data sets.
- HDFS stores data in a distributed manner, by dividing the data into small pieces called blocks and storing them on different DataNodes in the cluster. Each block has a default size of 128 MB, which can be configured in the hdfs-site.xml file.
- HDFS follows a master-slave architecture, where the NameNode is the master server that manages the file system namespace, the metadata of the files and directories, and the access control of the clients. The DataNodes are the slave servers that store the actual data blocks and perform read and write operations on them as instructed by the NameNode.
- HDFS provides high throughput, fault tolerance, scalability, and data locality for the applications that run on Hadoop. HDFS also enables streaming access to file system data for MapReduce, which is a programming model for parallel processing of large data sets.
- HDFS replicates each block across multiple DataNodes to ensure data availability and reliability in case of node failures. The replication factor, which is the number of copies of each block, can be set globally or per file. The default replication factor is 3, which means each block has three copies on different nodes.
- HDFS uses a rack-aware replica placement policy, which means it tries to place the replicas of a block on different racks to reduce the network bandwidth and increase the fault tolerance. The policy is to place the first replica on the same node as the client, the second replica on a different rack, and the third replica on the same rack as the second one.
- HDFS supports a simple coherency model, where a file once created, written, and closed, need not be changed. This assumption simplifies the data consistency issues and enables high throughput data access. HDFS provides a write-once-read-many access model for files. A file can be appended to, but not modified otherwise.
