#### Developing a Map Reduce application

- MapReduce is a programming model and an associated implementation for processing and generating big datasets with a parallel, distributed algorithm on a cluster.
- A MapReduce program is composed of a map procedure, which performs filtering and sorting, and a reduce method, which performs a summary operation.
- The MapReduce system orchestrates the processing by marshalling the distributed servers, running the various tasks in parallel, managing all communications and data transfers between the various parts of the system, and providing for redundancy and fault tolerance.
- Writing a program in MapReduce follows a certain pattern. You start by writing your map and reduce functions, ideally with unit tests to make sure they do what you expect. Then you write a driver program to run a job, which can run from your IDE using a small subset of the data to check that it is working. If it fails, you can use your IDE's debugger to find the source of the problem. With this information, you can expand your unit tests to cover this case and improve your mapper or reducer as appropriate to handle such input correctly. When the program runs as expected against the small dataset, you are ready to unleash it on a cluster. Running against the full dataset is likely to expose some more issues, which you can fix as before, by expanding your tests and altering your mapper or reducer to handle the new cases. Debugging failing programs in the cluster is a challenge, so we'll look at some common techniques to make it easier. After the program is working, you may wish to do some tuning, first by running through some standard checks for making MapReduce programs faster and then by doing task profiling. Profiling distributed programs is not easy, but Hadoop has hooks to aid in the process.
- Before we start writing a MapReduce program, however, we need to set up and configure the development environment. We also need to understand some basic concepts and APIs, such as the Configuration API, the GenericOptionsParser, the Tool and the ToolRunner, and the MapReduce Web UI.
- The following are some of the steps involved in developing a MapReduce application:

  - **Configuration API**: A Configuration class is used to access the configuration XML and can be combined (if a var is repeated, last is used). You can use the Configuration class to set and get properties, such as the input and output paths, the number of reducers, the compression codec, etc. You can also use the Configuration class to pass custom parameters to your map and reduce functions, by using the set() and get() methods with your own keys and values.
  - **Configuring the Development Environment**: You need to have Java installed and configured, as well as Hadoop. You also need to have an IDE, such as Eclipse or IntelliJ IDEA, and a build tool, such as Maven or Gradle. You need to create a project and add the Hadoop dependencies to your pom.xml or build.gradle file. You also need to set the HADOOP_HOME environment variable to point to your Hadoop installation directory, and add the Hadoop bin directory to your PATH. You can use the hadoop classpath command to get the classpath for Hadoop and add it to your IDE's classpath.
  - **GenericOptionsParser, Tool and ToolRunner**: These are classes that help you parse the command-line arguments for your MapReduce program. The GenericOptionsParser class can handle the common Hadoop options, such as -conf, -D, -fs, -jt, etc. The Tool interface defines a run() method that takes a Configuration object and a String array of arguments. The ToolRunner class can run a Tool implementation, passing it a Configuration object and the remaining arguments after the GenericOptionsParser has processed the common options. You can implement the Tool interface in your driver class and use the ToolRunner to launch your program.
  - **Writing Unit Tests**: You can use the JUnit framework to write unit tests for your map and reduce functions. You can use the MRUnit library to mock the input and output of your functions and assert the expected results. You can also use the MiniDFSCluster and MiniMRCluster classes to create a mini Hadoop cluster in your test code and run your program against it.
  - **Running locally and in a cluster on Test Data**: You can run your program locally by setting the mapreduce.framework.name property to local in your Configuration object. This will run the map and reduce tasks in the same JVM as the driver, without using HDFS. This is useful for debugging and testing with a small dataset.
