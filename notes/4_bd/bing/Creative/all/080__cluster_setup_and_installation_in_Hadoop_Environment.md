#### Cluster setup and installation in Hadoop Environment

- A Hadoop cluster is a collection of machines that run the Hadoop software and store the data in a distributed manner.
- A Hadoop cluster can be configured in different modes, such as standalone, pseudo-distributed, and fully-distributed, depending on the number of nodes and the level of replication and fault tolerance required.
- To set up and install a Hadoop cluster, the following steps are generally followed:

  1. Install Java on all the machines in the cluster, as Hadoop is written in Java. The recommended Java versions are described at [HadoopJavaVersions](https://hadoop.apache.org/docs/current/hadoop-project-dist/hadoop-common/HadoopJavaVersions.html).
  2. Download a stable version of Hadoop from [Apache mirrors](https://hadoop.apache.org/releases.html) and unpack the software on all the machines in the cluster.
  3. Edit the file `etc/hadoop/hadoop-env.sh` to define the `JAVA_HOME` environment variable and optionally other variables for customizing the Hadoop daemons' process environment.
  4. Edit the file `etc/hadoop/core-site.xml` to define the `fs.defaultFS` property, which specifies the default file system for Hadoop. For example, `hdfs://localhost:9000` for a single-node cluster or `hdfs://namenode:9000` for a multi-node cluster, where `namenode` is the hostname of the machine running the NameNode daemon.
  5. Edit the file `etc/hadoop/hdfs-site.xml` to define the `dfs.replication` property, which specifies the number of replicas for each block in HDFS. For example, `1` for a single-node cluster or `3` for a multi-node cluster.
  6. Edit the file `etc/hadoop/yarn-site.xml` to define the `yarn.resourcemanager.hostname` property, which specifies the hostname of the machine running the ResourceManager daemon. For example, `localhost` for a single-node cluster or `resourcemanager` for a multi-node cluster, where `resourcemanager` is the hostname of the machine running the ResourceManager daemon.
  7. Edit the file `etc/hadoop/mapred-site.xml` to define the `mapreduce.framework.name` property, which specifies the MapReduce framework to use. For example, `yarn` for using YARN as the MapReduce framework.
  8. Optionally, edit the file `etc/hadoop/slaves` to list the hostnames of the machines running the DataNode and NodeManager daemons, one per line. This file is used by the start and stop scripts to manage the Hadoop daemons on the cluster. If this file is not edited, the start and stop scripts will only run the daemons on the local machine.
  9. Optionally, set up passphraseless SSH between the machines in the cluster, so that the start and stop scripts can run the Hadoop daemons remotely without prompting for passwords. This can be done by generating SSH keys and copying them to the authorized keys file on each machine. For more details, see [SSH Keys](https://www.ssh.com/academy/ssh/key).
  10. Start the Hadoop cluster by running the script `sbin/start-all.sh`, which will start the NameNode, DataNode, ResourceManager, NodeManager, and other optional services on the cluster. Alternatively, individual services can be started by running the scripts `sbin/start-dfs.sh` and `sbin/start-yarn.sh`.
  11. Verify the status of the Hadoop cluster by accessing the web interfaces of the Hadoop daemons, such as the NameNode web UI at `http://namenode:9870`, the ResourceManager web UI at `http://resourcemanager:8088`, and the MapReduce Job History Server web UI at `http://resourcemanager:19888`. Alternatively, use the command `bin/hdfs dfsadmin -report` to check the status of the HDFS cluster and the command `bin/yarn node -list` to check the status of the YARN cluster.
  12. Stop the Hadoop cluster by running the script `sbin/stop-all.sh`, which will stop the NameNode, DataNode, ResourceManager, NodeManager, and other optional services on the cluster. Alternatively, individual services can be stopped by running the scripts `sbin/stop-dfs.sh` and `sbin/stop-yarn.sh`.
