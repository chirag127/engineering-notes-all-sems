#### HDFS concepts

HDFS stands for Hadoop Distributed File System. It is a distributed file system that runs on commodity hardware and is designed to store and process large amounts of data. HDFS is one of the core components of Apache Hadoop, along with MapReduce and YARN. Some of the key concepts of HDFS are:

- **Cluster**: A HDFS cluster consists of a set of machines, called nodes, that communicate with each other over the network. Each node can perform different roles, such as NameNode, DataNode, or client.
- **NameNode**: The NameNode is the master node that manages the file system namespace and the metadata of all the files and directories in the cluster. It also controls the access to the files by clients and coordinates the replication and recovery of data blocks among DataNodes. There is only one active NameNode in a cluster, and optionally one or more standby NameNodes for high availability.
- **DataNode**: The DataNode is the worker node that stores and serves the data blocks of the files in the cluster. Each DataNode periodically sends a report of its available blocks to the NameNode, and follows the commands from the NameNode to create, delete, or replicate blocks. There can be hundreds or thousands of DataNodes in a cluster, depending on the size and configuration.
- **Block**: A block is the smallest unit of data storage in HDFS. Each file in HDFS is divided into one or more fixed-size blocks, usually 128 MB by default, and stored across multiple DataNodes. The blocks of a file are replicated for fault tolerance, and the replication factor can be set per file or per cluster. The default replication factor is 3, which means each block has three copies on different DataNodes.
- **Client**: The client is the node that accesses the files in the cluster through the HDFS API. The client can perform operations such as read, write, create, delete, or append files. To read a file, the client first contacts the NameNode to get the list of DataNodes that store the blocks of the file, and then reads the data from the DataNodes directly. To write a file, the client first asks the NameNode to allocate a new file and choose a set of DataNodes to host the blocks of the file, and then writes the data to the DataNodes in a pipeline fashion.
- **Streaming Data Access**: HDFS is designed for applications that need streaming access to their data sets, rather than interactive or random access. HDFS provides high throughput of data by optimizing the data transfer rate over the network and the disk I/O rate on the DataNodes. HDFS also supports data locality, which means moving the computation to the data, rather than moving the data to the computation. This reduces the network congestion and improves the performance of data processing.
- **Fault Tolerance**: HDFS is highly fault tolerant and can handle failures of nodes, disks, or network. HDFS detects the failures of DataNodes by using heartbeats and block reports, and automatically recovers the lost blocks by replicating them from other DataNodes. HDFS also supports the use of standby NameNodes, which can take over the role of the active NameNode in case of a failure. HDFS also maintains a persistent copy of the file system metadata on the local disk of the NameNode, and can use a secondary NameNode to create periodic checkpoints of the metadata for backup and recovery.
