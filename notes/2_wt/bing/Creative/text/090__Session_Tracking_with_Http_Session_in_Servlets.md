### Session Tracking with Http Session in Servlets

- Session tracking is the process of maintaining the state of a client-server interaction over multiple requests.
- HTTP is a stateless protocol, which means that each request is treated as a new one and the server does not remember the previous requests from the same client.
- Session tracking is useful for applications that need to store and retrieve information about a user's preferences, actions, or transactions.
- Session tracking can be implemented using various techniques, such as cookies, hidden form fields, URL rewriting, and Http session.
- Http session is an interface provided by the servlet API that allows the server to create and manage a session object for each client.
- A session object is a collection of key-value pairs that store information about the client and its requests.
- A session object is associated with a unique session ID that is generated by the server and sent to the client in a cookie or a URL .
- The client sends back the session ID in each request, and the server uses it to retrieve the corresponding session object .
- The session object is available to all the servlets and JSPs that the user accesses until the session is invalidated or expired .
- The session object can be created, accessed, modified, and deleted using the methods of the Http session interface .
- Some of the common methods of the Http session interface are:

  - `getSession()`: returns the current session object or creates a new one if none exists.
  - `getId()`: returns the session ID of the current session object.
  - `getAttribute(String name)`: returns the value of the attribute with the given name from the current session object .
  - `setAttribute(String name, Object value)`: sets the value of the attribute with the given name in the current session object .
  - `removeAttribute(String name)`: removes the attribute with the given name from the current session object.
  - `invalidate()`: invalidates the current session object and removes it from the server .
  - `setMaxInactiveInterval(int interval)`: sets the maximum time in seconds that the current session object can be inactive before it is expired .
  - `getMaxInactiveInterval()`: returns the maximum time in seconds that the current session object can be inactive before it is expired .
  - `isNew()`: returns true if the current session object is newly created, false otherwise.

- Session tracking with Http session is a convenient and secure way of maintaining the state of a client-server interaction, but it also has some limitations, such as:

  - The session object consumes memory on the server, which can affect the performance and scalability of the application.
  - The session object can be lost or corrupted due to server failure, network failure, or malicious attacks.
  - The session object can be stolen or hijacked by other clients if the session ID is not protected or encrypted.
  - The session object can be disabled or rejected by the client if the client does not support or allow cookies or URL rewriting.
