## Unit 5 - Servlets

- Servlets are Java programs that run on a web server and handle HTTP requests and responses.
- Servlets can be used to create dynamic web pages, process user input, interact with databases, and implement web services.
- Servlets are compiled into bytecode and loaded by a servlet container, which is a component of a web server that provides the runtime environment and services for servlets.
- Servlets follow a request-response model, where each servlet has a service method that receives an HttpServletRequest object and an HttpServletResponse object as parameters, and performs some logic based on the request, and sends a response back to the client.
- Servlets can be configured and initialized using annotations or web.xml deployment descriptor, which specify the servlet name, URL mapping, initialization parameters, load-on-startup order, and other properties.
- Servlets have a life cycle that consists of three phases: initialization, service, and destruction.
  - Initialization: The servlet container calls the init method of the servlet once, when it is first loaded or requested. The init method can be used to perform any one-time setup tasks, such as creating database connections, loading configuration files, etc.
  - Service: The servlet container calls the service method of the servlet for each request that matches the servlet's URL mapping. The service method can delegate the request to other methods, such as doGet, doPost, doPut, doDelete, etc., depending on the HTTP method of the request. The service method can also access the request parameters, headers, cookies, sessions, and attributes, and manipulate the response status, headers, cookies, and output stream.
  - Destruction: The servlet container calls the destroy method of the servlet once, when the servlet is unloaded or the web server is shut down. The destroy method can be used to perform any cleanup tasks, such as closing database connections, releasing resources, etc.
- Servlets can communicate with other servlets or web components using request dispatching, which is the process of transferring the control of a request from one servlet to another servlet or JSP page, within the same web application or across different web applications.
  - Request dispatching can be done using two methods: forward and include.
    - Forward: The forward method of the RequestDispatcher interface transfers the control of the request to another servlet or JSP page, and the response from that servlet or JSP page is sent back to the client. The original servlet does not send any response to the client, and the URL in the browser does not change.
    - Include: The include method of the RequestDispatcher interface invokes another servlet or JSP page, and includes the response from that servlet or JSP page in the response of the original servlet. The original servlet can send some response to the client before or after the include method, and the URL in the browser does not change.
- Servlets can also communicate with other servlets or web components using shared objects, which are objects that can be stored and retrieved by multiple servlets or web components within the same web application or across different web applications.
  - Shared objects can be stored and retrieved using four scopes: application, session, request, and page.
    - Application: The application scope is the broadest scope, and it is shared by all the servlets and web components within the same web application. The application scope can be accessed using the ServletContext interface, which provides methods to set and get attributes, and to access other resources and information about the web application.
    - Session: The session scope is specific to each user session, and it is shared by all the servlets and web components within the same web application that belong to the same user session. The session scope can be accessed using the HttpSession interface, which provides methods to set and get attributes, and to manage the session state, such as creating, invalidating, and checking the session.
    - Request: The request scope is specific to each request, and it is shared by all the servlets and web components that are involved in processing the same request, such as using request dispatching. The request scope can be accessed using the HttpServletRequest interface, which provides methods to set and get attributes, and to access other information about the request.
    - Page: The page scope is the narrowest scope, and it is specific to each JSP page. The page scope can be accessed using the PageContext interface, which provides methods to set and get attributes, and to access other objects and information about the JSP page.
