#### Various Size Oriented Measures in Software Design

In software development, size-oriented measures are used to estimate the size of software projects, which is a crucial component in project planning and management. These measures help in determining the development effort, cost, and duration of a software project. In this section, we will discuss various size-oriented measures used in software design.

1. Lines of Code (LOC): 

The LOC metric is the most commonly used size-oriented measure in software design. It is simply the count of lines of code in a program, including comments and blank lines. It is a simple and easy-to-understand metric, but it has several limitations. LOC does not provide any indication of the quality, efficiency, or complexity of a program. It also does not take into account the differences in programming languages, coding styles, or the use of libraries and frameworks.

2. Function Points (FP):

Function Points are a size-oriented measure that takes into account the functionality provided by a software system. It is based on the user's perception of the software's functionality, rather than the actual code. Function Points are calculated based on the complexity of the inputs, outputs, queries, and files used by the software system. They provide a more accurate estimate of the size of a software project than LOC, as they account for the complexity and functionality of the software.

3. Object Points (OP):

Object Points are similar to Function Points, but they are based on the complexity of the objects used in the software system, rather than the functionality. Object Points take into account the complexity of the data used by the software, as well as the complexity of the operations performed on the data. They provide a more accurate estimate of the size of a software project than LOC or Function Points, as they account for both the functionality and data complexity.

4. Source Lines of Code (SLOC):

Source Lines of Code is a variation of the LOC metric that only counts the lines of code that are written by the developer, excluding comments and blank lines. This metric provides a more accurate estimate of the effort required to develop the software, as it only includes the lines of code that are directly related to the software's functionality.

5. Object-Oriented Measures:

Object-oriented measures are size-oriented measures that are specific to object-oriented programming. These measures take into account the complexity of the classes, methods, and inheritance hierarchy used in the software system. They provide a more accurate estimate of the size of an object-oriented software project than LOC, as they account for the complexity of the object-oriented design.

Mnemonics and Learning Tricks:

Unfortunately, there are no easy-to-remember mnemonics or learning tricks for these size-oriented measures. However, it is important to understand the differences between these measures and their limitations in order to choose the appropriate metric for a software project. Remember that no single metric can provide a complete picture of the size and complexity of a software project, and it is best to use a combination of metrics to provide a more accurate estimate.
