## Unit 2 - Software Requirement Specifications (SRS)

Software Requirement Specifications (SRS) is a document that outlines the requirements for a software project. It is a crucial part of the software development life cycle that helps to ensure that the software meets the needs of the stakeholders. Here are some important points to remember about SRS:

1. Definition: SRS is a document that outlines the functional and non-functional requirements of a software project. It is a communication bridge between the development team and stakeholders.

2. Purpose: The purpose of SRS is to define the requirements for a software project, so that the development team can understand what needs to be built and how it should function. It helps to ensure that the software meets the needs of the stakeholders.

3. Mnemonics: The mnemonic to remember the key components of SRS is FURPS+ (Functionality, Usability, Reliability, Performance, Supportability, and + other factors such as security, legal, etc.)

4. Key Components: The key components of SRS include:

  - Introduction: A brief overview of the software project and its purpose.

  - Functional Requirements: A description of the features and functionality of the software.

  - Non-Functional Requirements: Descriptions of the software's performance, reliability, usability, and supportability.

  - System Models: Diagrams and other visual representations of the software's architecture and design.

  - Appendices: Any additional information or documentation that may be useful to the development team.

5. Advantages: SRS helps to ensure that the software meets the needs of the stakeholders, reduces development costs, and speeds up the development process.

6. Disadvantages: SRS can be time-consuming and difficult to create, and it may not capture all of the requirements accurately.

7. Examples: Some examples of software that would require an SRS include operating systems, web applications, and mobile apps.

In conclusion, SRS is an important document that outlines the requirements for a software project. It helps to ensure that the software meets the needs of the stakeholders and is an essential part of the software development life cycle. Remembering the key components of SRS and the FURPS+ mnemonic can be helpful in creating an effective SRS document.
