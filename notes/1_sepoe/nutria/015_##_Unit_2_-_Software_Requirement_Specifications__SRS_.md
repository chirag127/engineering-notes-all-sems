
## Unit 2 - Software Requirement Specifications (SRS) 

Software Requirement Specifications (SRS) is a document that describes the intended behavior of a software system. It is used to define the requirements of a software system and provide a detailed description of the system's functionality. The SRS should provide a clear and concise description of the software system's purpose, behavior, and constraints. It should also provide a detailed description of the system's inputs, outputs, and other components.

The SRS should be written in a way that is easy to understand and should include the following components: 

* Overview: A brief description of the system and its purpose. 
* Requirements: A list of the system's requirements, including functional, performance, interface, and other requirements. 
* Use Cases: A description of how the system will be used by the user. 
* Design Constraints: A list of any design constraints that must be taken into account when designing the system. 
* User Interface: A description of the system's user interface. 
* System Architecture: A description of the system's architecture. 
* Test Cases: A list of test cases that can be used to verify the system's functionality. 

Mnemonic: SRS stands for Software Requirement Specifications. 

Learning Trick: When writing the SRS, try to think of the system from the user's perspective. Ask yourself what the user wants from the system and how the system should behave in order to meet those needs.
