
### Review and Management of User Needs in Requirement Engineering Process in SRS

The requirement engineering process in software requirements specification (SRS) involves the review and management of user needs. This process is essential for ensuring that the software meets the requirements of the users, as well as any other stakeholders involved in the project.

The review and management of user needs in SRS consists of the following steps:

1. Identifying user needs: This step involves gathering information about the users and their needs. This information can be gathered through interviews, surveys, focus groups, and other methods.

2. Analyzing user needs: This step involves analyzing the gathered information to determine the users’ needs. This analysis should include both quantitative and qualitative analysis.

3. Defining user needs: This step involves defining the user needs in a clear and concise manner. This should include both functional and non-functional requirements.

4. Validating user needs: This step involves validating the user needs to ensure that they are realistic and achievable. This can be done through user testing, prototyping, and other methods.

5. Documenting user needs: This step involves documenting the user needs in the SRS. This should include both the functional and non-functional requirements.

6. Managing user needs: This step involves managing the user needs throughout the development process. This includes monitoring changes, updating the SRS, and addressing any issues that arise.

Mnemonic: 
FADVMDM - Identify, Analyze, Define, Validate, Document, Manage
