

# Cyclomatic Complexity Measures in software design

* Cyclomatic complexity is a software metric used to measure the complexity of a program. It is computed using the control flow graph of the program, which shows the paths that the program can take.
* The cyclomatic complexity of a program is the number of linearly independent paths through the source code.
* It is used to measure the complexity of a program and can be used to identify potential areas of the program that may need refactoring in order to improve its maintainability.
* To calculate cyclomatic complexity, the number of decision points in the program is determined. A decision point is an instruction that can cause the program to take a different path.
* The cyclomatic complexity of a program is the number of decision points plus one.
* Cyclomatic complexity can be used to identify potential areas of the program that may need refactoring in order to improve its maintainability.
* It is also a good indicator of the number of tests that should be written to adequately test a program.
* A good rule of thumb is to keep cyclomatic complexity below 10. If it is higher than 10, it indicates that the program may be too complex and should be refactored.
* Mnemonics and learning tricks can be used to remember the cyclomatic complexity measure. For example, the acronym **V(G) = E - N + 2** can be used to remember the formula for calculating the cyclomatic complexity of a program, where **V(G)** is the cyclomatic complexity, **E** is the number of edges, and **N** is the number of nodes.
