
### SRS Document

* Software Requirements Specification (SRS) documents are written specifications of software requirements. 
* They are used to communicate what the software should do, and how it should be designed and built.
* SRS documents are typically written by software engineers, and include detailed descriptions of the software's features, functions, behavior, and user interface.
* The document should also include any constraints, assumptions, and requirements that the software must meet. 
* It should also include any performance requirements, such as response times and throughput.
* SRS documents should be written in a clear, concise, and unambiguous way, so that they can be easily understood by all stakeholders.
* SRS documents should be reviewed and approved by all stakeholders before the software development process begins.
* Mnemonics and learning tricks can be used to help remember and understand the content of an SRS document. For example, the acronym FURPS (Functionality, Usability, Reliability, Performance, Supportability) can be used to remember the five main categories of requirements that should be included in an SRS document.
