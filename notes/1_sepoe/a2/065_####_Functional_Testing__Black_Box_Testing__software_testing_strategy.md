#### Functional Testing (Black Box Testing) software testing strategy

Functional Testing, also known as Black Box Testing, is a software testing method that validates the functionality of a software application without looking at its internal structure (implementation details). In this testing technique, the tester provides input to the system and compares the output with the expected output to identify any deviation or bug.

Some key points about Functional Testing:

- It is a type of non-invasive testing. The tester does not need to know the internal code structure and design of the application.
- It is usually done by client or end-user. The tester performs testing from an external or end-user perspective.
- Focuses on the functionality specified in requirements and specifications. The app is tested against what it is supposed to do, not how it is implemented.
- Testing both valid and invalid inputs and checking system's behavior and output.
- Does not require knowledge of programming languages or software frameworks/environments.
- Can be applied to almost every software system.
- Challenging to automate as it requires human evaluation of outputs.

Some Mnemonics/Tricks to remember:

- Think of a 'Black Box' with inputs and outputs. You don't see what's inside.
- Check what the system 'Should Do' vs what it 'Does'.
- Test both valid and invalid inputs (including boundary values). Invalid inputs can reveal bugs.
- Think from an end-user perspective.

Advantages:

- Requires no knowledge of coding/internal structure.
- Useful for UAT (User Acceptance Testing).
- Mimics how end-users interact with the system.

Disadvantages:

- Difficult to automate.
- Time-consuming for large systems.
- May not detect performance/security issues.
- Does not provide details on the root cause of bugs.

Applications: Almost every software system. Especially user-facing applications where functionality is key.
