### SRS Document

- SRS stands for Software Requirements Specification.
- It is a document that describes the external behavior of a software product to be developed.
- It includes a detailed description of the functional and non-functional requirements.
- It helps the developers and stakeholders understand the requirements in a structured manner.
- It acts as a blueprint for the software development process.
- Key parts of an SRS:

- Introduction: Purpose, Scope, Definitions, References, Overview
- Overall description: Product perspective, User characteristics, General constraints
- System features: Functional requirements, External interface requirements
- System constraints: Non-functional requirements (performance, security, etc.)
- Mnemonics: "INTRO" covers Introduction, "OD" covers Overall description, "SF" covers System features, "SC" covers System constraints. Easy to remember.
- Learning tricks: Read the SRS thoroughly, understand use cases and diagrams, list functional and non-functional requirements, see how they are related. This helps in understanding the system and its requirements as a whole.
- Advantages: Acts as a communication medium between stakeholders, Reduces ambiguity, Documents the product to be built, Helps estimate costs and timelines.
- Disadvantages: Can get outdated if not updated, Might be ignored if not properly followed, Can be difficult to write as it needs expertise.
- Applications: Used in the software development lifecycle to gather, document, and validate client requirements before building the software.
