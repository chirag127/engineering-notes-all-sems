#### Compliance with Design and Coding Standards (Coding Standards) Static testing strategy

- Coding standards static testing involves reviewing the code for adherence to coding standards and design guidelines. This ensures consistency, readability, maintainability and testability of the code.
- Some key things to check in coding standards testing are:
- Naming conventions - Check that variables, functions, classes, etc. follow the prescribed naming conventions like using underscores or camelCase, avoiding spelling mistakes, etc.
- Indentation - Check that proper indentation is followed as per the style guide. Correct indentation makes the code easily readable and identifiable.
- Comments - Check that proper and sufficient comments are included as per the guidelines. Comments make the code readable and understandable.
- Separation into functions - Check that the code is modularized into proper functions that perform dedicated functionality. This increases reusability and maintainability.
- Code complexity - Check that the code is not too complex and is easily understandable. High complexity reduces readability and testability.
- Error handling - Check that proper error handling mechanisms are in place as per the guidelines. This makes the code robust and fault-tolerant.
- etc.

Some advantages of coding standards testing are:
- Increased readability and understandability of the code
- Improved maintainability as all code follows a consistent style
- Higher reusability of the code due to modularization
- Better testability due to reduced complexity and proper error handling

However, the disadvantage is that coding standards testing can be time-consuming for large code bases. Also, adherence to standards needs to be balanced with other critical factors like performance, scalability, etc.
