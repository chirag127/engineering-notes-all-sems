### Static Testing Strategies in Software Testing

Static Testing Strategies refer to the type of software testing where the software is not executed. The following are some common Static Testing Strategies:

1.  Review - Code review is done to detect defects early by identifying coding errors or potential bugs. Reviews are done by developers themselves or by others. Reviews can be walkthroughs, inspections or formal reviews.
2.  Inspection - A type of review where the software product is checked in a systematic and detailed manner. A group of experts inspect the software product either manually or using automated tools. Inspections help find defects and suggest improvements.
3.  Walkthrough - An informal review where developers walk through the product explaining its functionality and logic. Issues are identified and suggestions are provided to improve the product.
4.  Structural Testing - Analysis of the internal structure of the software to identify issues. Tools like control flow analysis and data flow analysis are used to analyze the code and find defects.
5.  Formal Verification - Mathematical techniques are used to prove the correctness of the software. Tools like model checkers and theorem provers are used to verify specifications, designs and code.

 Mnemonics: Some mnemonics to remember Static Testing Strategies:
- REVIEW - Code Review, Inspection, Walkthrough
- VERIFY - Formal Verification
- STRUCTURE - Structural Testing

Advantages:
- Detects defects early in the SDLC before executing the software.
- Cost effective as execution of software is not required.
- Improves software quality.

Disadvantages:
- May not detect all types of defects especially UI and performance related defects.
- Requires highly skilled resources to perform effective reviews and analysis.
- Can be time consuming for large and complex software products.
