### Similarity and Differences from Conventional Engineering Processes

Similarities:

- Requirements analysis: Just like conventional software engineering, requirements are gathered and analyzed in machine learning projects. The key tasks of understanding the problem, identifying stakeholders, and documenting requirements are still required.
- Planning: An iterative planning process is still needed to break down machine learning projects into phases and tasks, estimate work, and allocate resources.
- Modeling: The process of representing the problem domain using a mathematical model is similar to conventional modeling tasks. Machine learning models are a type of mathematical model of the domain.
- Evaluation: The machine learning model's performance still needs to be evaluated, tested, and validated, similar to evaluating conventional software.

Differences:

- Less focus on designing and coding: Machine learning projects spend less time on low-level design and coding since the machine learning algorithms are coded libraries. The effort is more on data gathering/cleaning and algorithm selection/tuning.
- More data-focused: Machine learning projects are very data-intensive. A significant amount of time is spent on data collection, cleaning, analysis, and ensuring high quality data to train the models. This data focus is not as significant in most conventional software projects.
- More experimentation: Machine learning projects involve a lot of experimentation to select and tune algorithms and models. Trying different algorithms and hyperparameter values is common. This experimentation is not typically as extensive in conventional software projects.
- Less determinism: The output of machine learning models can be hard to determine exactly since it depends on the data and training process. The same code and inputs can lead to different outputs. Conventional software is typically more deterministic, with the same inputs leading to the same outputs.
- Requirements may be harder to gather: Requirements can be harder to elicit for machine learning projects since people may not know exactly what machine learning can accomplish or what outputs to expect from the models. This can make requirements gathering more challenging than in some conventional software projects.
