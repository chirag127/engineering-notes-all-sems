### Water Fall Model in SDLC

The Waterfall model is a sequential design process in Software Development Life Cycle. It consists of the following phases:

1. Requirement Analysis: The first stage is to gather and analyze the requirements of the software to be developed. The requirements are then documented in a Software Requirement Specification (SRS) document.

2. Design: The SRS document is studied and a design is created. The software architecture is defined in this phase. The design is represented using diagrams like UML diagrams.

3. Implementation: The design is implemented in a programming language in this phase. The developed software is tested for functionality and bugs.

4. Testing: The software is rigorously tested in this phase. Various testing types like unit testing, integration testing, system testing, acceptance testing, etc. are performed.

5. Deployment: If the software successfully passes all testing, it is deployed in the customer environment or released to the market.

6. Maintenance: There are chances that some bugs are found or new requirements come up after deployment. Such changes are incorporated in this phase.

Advantages: Simple and easy to understand. Each phase has specific deliverables and review points.

Disadvantages: Inflexible. Moving back to the previous phase is difficult. Lengthy process.

Mnemonics:

- "Requirements to Design to Code to Test to Deploy to Maintain"

Applications: Suitable for small projects where requirements are well understood.
