### Integration Testing in Software Testing

Integration Testing is a level of software testing where individual software modules are combined and tested as a group.

The purpose of Integration Testing is to verify the functionality, performance, and reliability of the integrated modules.

- Integration Testing is performed after unit testing and before system testing.
- Modules are integrated slowly in a progressive manner. Bottom-up approach or Top-down approach can be used.
- In Bottom-up approach, low-level modules are integrated first and then higher-level modules. In Top-down approach, high-level modules are integrated first and then lower-level modules.
- The goal is to uncover errors in the interfaces and interactions between the integrated components.
- Test cases are designed to exercise the interfaces between modules.
- Some key things to check in Integration Testing:
  - Interfaces between modules are proper.
  - Data exchange between modules is correct.
  - Control flow or sequencing between modules is proper.
  - Performance of integrated modules.
- Mnemonics to remember: IIT (Integration Interface Testing), MIT (Module Interface Testing)
- Advantages: Detects interface defects early, easy to isolate and fix defects.
- Disadvantages: Difficult to identify and isolate defects precisely to a module. Debugging is more difficult as number of components increase.
- Example: Integrating unit tested modules of order management system and testing the data and control flow between the modules.
- Applications: Useful for large systems where system testing is not feasible on the whole system at once due to complexity and time required.
