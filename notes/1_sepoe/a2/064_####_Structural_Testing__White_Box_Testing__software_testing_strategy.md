#### Structural Testing (White Box Testing) software testing strategy

Structural Testing, also known as White Box Testing, is a software testing technique that focuses on the internal structure of the software to test execution paths and verify logic.

Some key points about Structural Testing:

- It requires internal knowledge of the software, like code coverage, to design effective test cases.
- Test cases are designed to exercise specific paths or statements in the code.
- The goal is to verify that all independent paths have been exercised.
- It helps identify faults in the internal structure of the software.
- It is also known as "glass box testing" or "open box testing".

Some tips and mnemonics to remember Structural Testing:

- "Verify internal structures" - The focus is on internal paths and logic, not external functionality.
- "Coverage is key" - Aim for code coverage and path coverage to test software thoroughly.
- "See inside the box" - Testers need visibility into the source code to design effective tests.

Advantages:

- Helps identify bugs and defects in the internal structure.
- Increases the possibility of detecting unhandled exceptions and abuse cases.
- Provides a measurable coverage metric, like code coverage or path coverage.

Disadvantages:

- Requires significant knowledge of the internal code/logic.
- Can be time-consuming to design enough tests to achieve adequate coverage.
- The coverage metrics themselves do not guarantee that all bugs will be found.

Examples of Structural Testing:

- Statement coverage - Execute each statement in the code at least once.
- Branch coverage - Exercise each branch/decision point in the code.
- Path coverage - Exercise each possible path through the code.

Applications:

- Unit testing - Good for testing individual modules/functions.
- Integration testing - Can be used to verify connections between components.
- Regression testing - Can help identify impacts of changes by measuring coverage changes.
