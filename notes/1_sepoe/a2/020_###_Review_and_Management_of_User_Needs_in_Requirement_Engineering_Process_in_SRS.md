### Review and Management of User Needs in Requirement Engineering Process in SRS

The following points cover the review and management of user needs in the requirement engineering process for Software Requirements Specification (SRS):

1. Identify and gather user needs: The initial step is to identify the actual users of the software and gather their needs through interviews, questionnaires, focus groups, etc. The gathered needs should be documented for further processing.
2. Analyze and understand user needs: The collected user needs should be analyzed to understand them comprehensively. Any ambiguity or confusion in the needs should be clarified by discussing with the users. The analyzed needs illustrate the problems or requirements of the users that the software must address.
3. Prioritize user needs: Not all user needs have the same importance or priority. The analyzed user needs should be prioritized based on their impact and relevance. The priority of needs can be decided in consultation with the users and project stakeholders. Higher priority needs should be addressed first in the SRS.
4. Refine and validate user needs: The prioritized user needs may be too broad or unclear. They should be refined into specific and unambiguous needs that can be directly implemented or validated. The refined needs should be validated by the users to ensure they reflect the actual requirements accurately. Invalid or incorrect needs should be re-elaborated.
5. Allocate user needs to software requirements: The verified user needs should be allocated to specific software requirements that can satisfy them. Multiple user needs can be addressed by a single requirement or a single need can elicit multiple requirements. The allocation should be done diligently to avoid incorrect or missing mappings. The allocated requirements make up the core SRS content.

The above steps ensure that the SRS incorporates all necessary user needs and includes precise software requirements to satisfy those needs. Following a systematic process leads to a comprehensive and robust SRS. Using mnemonics or tricks can aid in remembering the process steps, e.g:

IUPRUV: Identify, Understand, Prioritize, Refine, Validate, Use

However, these mnemonics are not essential if the process steps are straightforward to recall. The SRS can include detailed diagrams or examples if they enhance the understandability of the user needs and requirements. The process also has the advantages of addressing actual user needs and validating the SRS but can be time-consuming and tedious for complex software.
