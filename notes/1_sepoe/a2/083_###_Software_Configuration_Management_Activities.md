### Software Configuration Management Activities

The core software configuration management activities are:

1. Configuration identification - Identifying the configuration items that make up a system and versioning them. This is where components are identified and baselined.
2. Configuration control - Controlling changes to the configuration. This is where change requests are submitted, analyzed, and either approved or denied.
3. Configuration status accounting - Tracking and reporting the status of components and change requests. This provides visibility into the exact configuration of a system and its components at any given point in time.
4. Configuration auditing - Ensuring compliance with the configuration management plan. This is where periodic audits are conducted to verify the completeness and correctness of the configuration data.

*Mnemonic:* "ICAC" - Identification, Control, Accounting, Auditing

*Learning trick:* Think of config mgmt as "controlling the chaos" (many components/changes) by properly identifying, controlling changes, tracking status, and auditing.

Advantages of config mgmt:
- Traceability - Can trace back to requirements and changes
- Visibility - Know exact state of system and components at any time
- Control - Can properly evaluate and approve/deny changes
- Reproducibility - Can recreate specific configurations and versions

Disadvantages:
- Overhead - Additional time/cost required for config mgmt activities
- Complexity - Systems with many components/changes can be difficult to manage

Examples: Software builds, documentation, hardware/software components

Applications: All complex systems/products requiring visibility and control over configurations and changes
