### Elicitation in Requirement Engineering Process in SRS

- Elicitation is the process of extracting requirements from stakeholders. It is the first step in Requirement Engineering process for preparing Software Requirements Specification (SRS).
- Some techniques used for elicitation are:
- Interviews - Meeting stakeholders and discussing the system requirements. Can be structured, semi-structured or unstructured.
- Questionnaires - Written set of questions that stakeholders fill out. Can reach geographically distributed stakeholders but limited depth of information.
- Observation - Observing stakeholders performing tasks and noting system needs. Useful for understanding current processes but may miss stakeholder insights.
- Workshops - Bringing stakeholders together to focus on requirements. Useful for resolving conflicts or obtaining group consensus but can be inefficient for large groups.
- Prototyping - Developing prototypes to help stakeholders visualize requirements. Useful for complex systems but can be time-consuming to develop multiple iterations.

** Mnemonics **: Some mnemonics to remember elicitation techniques -

- IQWO - Interviews, Questionnaires, Workshops, Observation
- ACRV - Analysis, Contextual Inquiry, Requirements, Visioning (another set of elicitation techniques)

** Tips **: Some tips for effective elicitation -

- Involve right stakeholders - Include all stakeholders impacted by system and those needed to approve/fund.
- Set context - Explain purpose of elicitation and how information will be used.
- Listen actively - Pay attention and reflect back to confirm understanding.
- Ask open-ended questions - Go beyond yes/no to get detailed information.
- Observe users in environment - Note constraints and uncommon scenarios.
- Prototype and iterate - Use prototypes to stimulate feedback and refine requirements.
