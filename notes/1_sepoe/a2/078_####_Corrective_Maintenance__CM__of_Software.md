#### Corrective Maintenance (CM) of Software

Corrective Maintenance (CM) of Software refers to the modifications made to software to fix defects or bugs that have been discovered in the operational software. The main objectives of Corrective Maintenance are:

- Fix errors and bugs found in the software.
- Replace faulty components or modules to rectify faults.
- Improve the software reliability and performance.

Some key points to remember about Corrective Maintenance:

- CM is reactive as it is carried out in response to problems found.
- CM is inevitable as software will always have some defects that will need fixing.
- CM can be unplanned and disruptive as fixing faults can take time and resources.
- CM needs to be properly planned and tracked to minimize disruption.
- Verification and validation activities are important to identify faults early before CM.
- Well-documented software with modular architecture can aid CM.
- Automated fault diagnosing and debugging tools can assist in CM.

Mnemonics:

- CM is reactive: Think of CM as firefighting to put out software fires (defects).
- CM disrupts: Imagine CM as road repair work disrupting traffic. Proper planning is necessary.

Advantages: Improves software reliability, fixes bugs and errors, satisfies user needs.
Disadvantages: Can be disruptive, time and cost consuming, may introduce new bugs.

Examples: Patch releases to fix bugs, replacing faulty modules, debugging and fixing errors.
Applications: All software will require CM to fix defects and satisfy user needs.
