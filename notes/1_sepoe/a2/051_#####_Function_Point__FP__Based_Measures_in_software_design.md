##### Function Point (FP) Based Measures in software design

- Function Point (FP) analysis is a method to measure software size based on its functionality.
- It counts the number of inputs, outputs, inquiries, internal files, and external interfaces of a software application.
- Each of these five components is assigned a complexity weighting factor and a function point count is computed as a weighted sum of the component counts.
- The total function point count provides an estimate of the functionality of the software and can be used to compare software packages or to estimate effort and cost.
- Advantages: Accounts for functionality, Language and platform independent, Widely used.
- Disadvantages: Subjective, Difficult to automate, Does not consider non-functional requirements.
- Mnemonics: Think of FP as Feature Points. Imagine you are counting features (inputs, outputs, etc.) and assigning weights to complex features. The total weighted feature count gives FP.
- Learning Tricks: Focus on understanding the 5 components and complexity factors well. Practice FP analysis on some sample applications to get a hands-on feel.
- Examples: A calculator app may have 10 inputs, 2 outputs, 5 inquiries, 3 internal files, 1 external interface. If average complexity, its FP count could be: 10*3 + 2*4 + 5*3 + 3*7 + 1*5 = 65.
- Applications: Software sizing, Estimation, Costing, Benchmarking.
