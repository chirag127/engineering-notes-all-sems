### Verification and Validation in SRS

Verification and Validation (V&V) are important aspects of Software Requirements Specification (SRS). They help in ensuring that the software being developed meets the user requirements.

**Verification** - It is the process of checking whether the software specification matches the user requirements. It is done at each stage of SRS development to check for correctness, completeness and consistency of the specifications. Methods for verification include-

- Reviews - Individual or team review of SRS by peers or experts
- Walkthroughs - Step-by-step presentation of SRS to identify errors
- Inspections - Methodical examination of SRS using a checklist of common errors

**Validation** - It is the process of checking whether the software meets the user needs. It is done after verification to ensure the final SRS satisfies the actual requirements. Methods for validation include-

- Prototyping - Developing prototypes and getting user feedback
- Simulation - Simulating software using models and getting user evaluation
- Cases & Scenarios - Analyzing use cases and scenarios to check if SRS meets goals

**Mnemonics** - To remember V&V - "Verify before Validate" or "Check correctness, then check user need".

**Advantages** - Helps catch errors and mismatches early, increases user satisfaction, reduces rework.
**Disadvantages** - Can be time-consuming and expensive, especially for large systems.
