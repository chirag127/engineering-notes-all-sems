# Software Engineering

Software Engineering is the systematic approach to the development, operation, maintenance, and retirement of computer software. It involves analyzing user needs, designing the software, developing the software, testing, deploying, and maintaining the software.

Some key points to learn and remember:

- Requirements Analysis: Capturing what the user needs and wants and documenting them. Use cases and user stories can be helpful in this process.
- Design: Coming up with solutions to meet the requirements. Things like architecture design, interface design, and component design are considered. UML diagrams like class diagrams and sequence diagrams are useful tools.
- Implementation: Translating the design into a machine-readable programming language. Programming, coding, and debugging take place here.
- Testing: Checking if the software meets the requirements and identifying and fixing any bugs or defects. Different types of testing like unit testing, integration testing, system testing, etc. are performed.
- Deployment: Releasing the software for user use. Things like installation, configuration, migration, and infrastructure management are considered.
- Maintenance: Improving the software after it is deployed to fix bugs or defects, add new features, or adapt to new environments.

Some useful mnemonics and tricks to remember:

- Waterfall model: Requirements -> Design -> Implementation -> Testing -> Deployment
- Agile methodology: Iterative and incremental approach with continuous testing and feedback
- SOLID principles: Single responsibility, Open-closed, Liskov substitution, Interface segregation, Dependency inversion
- DRY: Don't repeat yourself. Eliminate duplication.
- KISS: Keep it simple, stupid. Simpler is better.
- YAGNI: You aren't gonna need it. Don't overengineer.
