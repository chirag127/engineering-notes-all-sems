## Unit 3 - Software Design

- Software design refers to the process of planning a software solution to a problem. It includes low-level component and algorithm implementation issues as well as high-level architectural issues.
- The main steps in software design are:

1. Analyze the problem and determine requirements - Determine what the software needs to do and who will use it. Identify functional and non-functional requirements.
2. Create design models and diagrams - Create models of the software using tools like UML (Unified Modeling Language) to depict components and how they interact. Common diagrams include use case diagrams, class diagrams, sequence diagrams, and activity diagrams.
3. Choose a software architecture - Choose an architectural pattern that suits the needs of the system, for example, client-server, layered, event-driven, etc. The architecture defines the basic structure and terminology of the system.
4. Design core components - Design the main components that will be used to build the system and how they will interact and communicate with each other. Focus on maximizing stability, reusability, and efficiency.
5. Add details to components - Flesh out the components by specifying algorithms, interface details, data models, and other elements. Refine the design to handle errors and edge cases.
6. Review and test - Have other developers review the design and test early prototypes to identify and fix any issues before full implementation begins.

Some tips for software design:
- Keep the design as simple as possible to solve the problem. Avoid unnecessary complexity.
- Reuse existing designs and components when possible to save time and effort.
- Ensure a good separation of concerns so components are loosely coupled and highly cohesive.
- Consider scalability and how the system will handle growth.
- Include documentation to explain the rationale behind the design and how the components work together.
- Use established design principles and patterns as applicable.

The key benefits of software design are:
- It provides a blueprint for system implementation.
- It enables identifying and resolving issues early to reduce rework.
- It facilitates communication between stakeholders and developers.
- It allows for estimating costs and timescales for a project.
