## Unit 2 - Hadoop and Map Reduce

- Hadoop is an open-source framework that allows distributed processing of large-scale data sets across clusters of computers using simple programming models.
- MapReduce is a programming model and an associated implementation for processing and generating large data sets with a parallel, distributed algorithm on a cluster.
- The basic idea of MapReduce is to split the input data into independent chunks that are processed by the map tasks in a completely parallel manner. The framework sorts the outputs of the maps, which are then input to the reduce tasks. Typically both the input and the output of the job are stored in a distributed file system. The framework takes care of scheduling tasks, monitoring them and re-executes the failed tasks.
- The MapReduce framework consists of the following components:
  - JobTracker: the master node that coordinates all the jobs and tasks in the cluster.
  - TaskTracker: the slave node that runs the map and reduce tasks assigned by the JobTracker.
  - JobClient: the client program that submits the MapReduce job to the JobTracker and monitors its progress.
  - Hadoop Distributed File System (HDFS): the distributed file system that stores the input and output data of the MapReduce jobs.
- The MapReduce programming model has the following phases:
  - Map: the user-defined function that takes a key-value pair as input and produces a set of intermediate key-value pairs as output.
  - Shuffle: the framework phase that transfers the intermediate key-value pairs from the map tasks to the reduce tasks based on the intermediate keys.
  - Reduce: the user-defined function that takes an intermediate key and a set of values associated with that key as input and produces a set of output key-value pairs as output.
  - Output: the final output of the MapReduce job that is written to HDFS or other file systems.
- The MapReduce programming model has the following advantages:
  - It is scalable and fault-tolerant, as it can handle large data sets across multiple nodes and recover from node failures.
  - It is simple and expressive, as it abstracts the details of parallelization, distribution, load balancing and fault tolerance from the user.
  - It is flexible and extensible, as it supports various data types, formats, sources and destinations, and allows customizing the map and reduce functions, the partitioning, sorting and grouping of the intermediate data, and the configuration of the job parameters.
- The MapReduce programming model has the following disadvantages:
  - It is not suitable for interactive or iterative applications, as it has high latency and overhead for each job execution.
  - It is not efficient for complex data processing, as it requires multiple MapReduce jobs to be chained together, which increases the I/O and network costs.
  - It is not optimal for some types of computations, such as graph algorithms, machine learning algorithms, and join operations, as it does not exploit the data locality and structure, and imposes a rigid key-value data model.
- Some examples of applications that use MapReduce are:
  - Word count: a simple application that counts the frequency of each word in a large text corpus.
  - Inverted index: an application that builds an index of words and their locations in a collection of documents, which can be used for information retrieval and text mining.
  - PageRank: an application that computes the importance of web pages based on the hyperlink structure of the web graph, which can be used for web search and ranking.
  - K-means clustering: an application that partitions a set of data points into a number of clusters based on their similarity, which can be used for data analysis and machine learning.
