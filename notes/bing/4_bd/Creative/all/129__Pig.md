### Pig

- Pig is a high-level scripting language that allows users to write complex data analysis programs for large-scale data sets.
- Pig is built on top of Hadoop, an open-source framework for distributed storage and processing of big data.
- Pig programs are compiled into a series of MapReduce jobs that are executed by Hadoop.
- Pig provides a set of built-in operators and functions that can perform common data transformations and manipulations, such as filtering, grouping, joining, sorting, aggregating, etc.
- Pig also supports user-defined functions (UDFs) that can be written in Java, Python, Ruby, or other languages and invoked from Pig scripts.
- Pig has two modes of execution: local mode and MapReduce mode. In local mode, Pig runs on a single machine without Hadoop. In MapReduce mode, Pig runs on a Hadoop cluster and utilizes its distributed file system (HDFS) and parallel processing capabilities.
- Pig has two components: Pig Latin and Pig Engine. Pig Latin is the scripting language that users write Pig programs in. Pig Engine is the component that compiles Pig Latin scripts into MapReduce jobs and executes them on Hadoop.
- Pig Latin has a simple and expressive syntax that resembles SQL. A Pig Latin script consists of a series of statements that define data flows. Each statement consists of a relation (a named data set), an operator, and one or more expressions or parameters.
- Pig Latin supports both structured and unstructured data. A relation in Pig Latin is a bag of tuples. A tuple is an ordered set of fields. A field can be of any type, such as int, float, chararray, bytearray, map, tuple, or bag.
- Pig Latin supports schema definition and inference. Users can optionally specify the schema of a relation using the AS clause. If the schema is not specified, Pig will infer it from the data at runtime.
- Pig Latin supports nested data structures, such as maps, tuples, and bags. A map is a collection of key-value pairs. A tuple is an ordered set of fields. A bag is a collection of tuples. These data structures can be nested within each other to represent complex data types.
- Pig Latin supports four types of operators: load/store operators, relational operators, diagnostic operators, and evaluation operators. Load/store operators are used to read data from or write data to external sources, such as files, databases, etc. Relational operators are used to perform data transformations and manipulations, such as filtering, grouping, joining, sorting, aggregating, etc. Diagnostic operators are used to display information about the data or the execution, such as dump, describe, explain, illustrate, etc. Evaluation operators are used to compute values from the data, such as arithmetic, string, comparison, logical, etc.
- Pig Latin supports three types of functions: built-in functions, user-defined functions, and macros. Built-in functions are predefined functions that can be used in Pig Latin scripts, such as SUM, COUNT, AVG, CONCAT, etc. User-defined functions are custom functions that can be written in Java, Python, Ruby, or other languages and invoked from Pig Latin scripts. Macros are reusable code snippets that can be defined and called from Pig Latin scripts.
- Pig Latin supports three types of comments: single-line comments, multi-line comments, and documentation comments. Single-line comments start with -- and end at the end of the line. Multi-line comments start with /* and end with */. Documentation comments start with /** and end with */ and can be used to generate documentation for Pig scripts using Javadoc.

Some examples of Pig Latin scripts are:

-- Load data from a file into a relation called input
input = LOAD 'data.txt' USING PigStorage(',') AS (name:chararray, age:int, salary:float);

-- Filter the input relation to keep only the records where age is greater than 30
filtered = FILTER input BY age > 30;

-- Group the filtered relation by name and calculate the average salary for each name
grouped = GROUP filtered BY name;
averaged = FOREACH grouped GENERATE group AS name, AVG(filtered.salary) AS avg_salary;

-- Store the averaged relation into a file
STORE averaged INTO 'output.txt' USING PigStorage(',');

-- Define a user-defined function in Python that returns the length of a string
@outputSchema("length:int")
def string_length(str):
  return len(str)

-- Register the user-defined function and use it in a Pig Latin script
REGISTER 'string_length.py' USING jython AS myfuncs;
input = LOAD 'data.txt' USING PigStorage(',') AS (name:chararray, age:int, salary:float);
lengths = FOREACH input GENERATE name, myfuncs.string_length(name) AS name_length;
DUMP lengths;
