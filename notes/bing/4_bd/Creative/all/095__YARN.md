#### YARN

- YARN stands for **Yet Another Resource Negotiator**. It is a component of Hadoop that manages the resources and scheduling of tasks in a Hadoop cluster.
- YARN was introduced in Hadoop 2.0 to overcome the limitations of Hadoop 1.0, which relied on a single JobTracker for resource management and job scheduling .
- YARN consists of the following main components :
  - **Resource Manager**: It is the master daemon of YARN that runs on a dedicated machine. It is responsible for allocating resources to different applications and managing the cluster-level policies. It has two sub-components:
    - **Scheduler**: It performs scheduling based on the resource requests from the applications and the available resources in the cluster. It is a pure scheduler that does not perform any monitoring or tracking of the applications. It supports different scheduling policies, such as FIFO, fair, and capacity.
    - **Application Manager**: It is responsible for accepting the application submissions, negotiating the first container for the application, and launching the Application Master for each application. It also maintains the state of the applications and handles the failures of the Application Masters.
  - **Node Manager**: It is the slave daemon of YARN that runs on each node in the cluster. It is responsible for managing the containers, monitoring the resource usage, and reporting to the Resource Manager. It also executes the commands from the Application Master and the Resource Manager.
  - **Application Master**: It is the per-application daemon of YARN that runs in a container allocated by the Resource Manager. It is responsible for negotiating the resources from the Resource Manager, managing the life cycle of the tasks, and monitoring the progress and status of the application. It also communicates with the Node Manager to launch and stop the containers.
  - **Container**: It is the basic unit of resource allocation in YARN. It represents a fixed amount of memory, CPU, disk, and network bandwidth that can be used by an application. A container can run one or more tasks of an application, depending on the application logic and configuration.
- YARN supports different types of applications, not only MapReduce. For example, YARN can run Spark, Hive, Pig, and Tez applications. Each application has its own Application Master that implements the application-specific logic and interacts with the YARN framework.
- YARN provides the following benefits:
  - **Scalability**: YARN can scale up to thousands of nodes and handle millions of tasks, by distributing the resource management and job scheduling functions among multiple daemons.
  - **Efficiency**: YARN can utilize the cluster resources more efficiently, by allowing multiple applications to share the same resources and by supporting dynamic resource allocation based on the application needs and the cluster availability.
  - **Flexibility**: YARN can support different types of applications and frameworks, by providing a common platform for resource management and a pluggable interface for application-specific logic.
  - **Compatibility**: YARN can run the existing MapReduce applications without any changes, by providing a backward-compatible MapReduce Application Master that mimics the behavior of the JobTracker.
- A possible mnemonic to remember the components of YARN is **RANC** (Resource Manager, Application Master, Node Manager, Container). A possible learning trick to understand the role of each component is to compare them with the roles in a school:
  - The Resource Manager is like the principal, who allocates the classrooms and teachers to different courses and enforces the school policies.
  - The Scheduler is like the timetable, which decides when and where each course will be held based on the course requests and the classroom availability.
  - The Application Manager is like the admission officer, who accepts the course enrollments, assigns the first classroom for each course, and launches the course coordinator for each course.
  - The Node Manager is like the janitor, who maintains the classrooms, monitors the resource usage, and reports to the principal. He also executes the commands from the course coordinator and the principal.
  - The Application Master is like the course coordinator, who negotiates the classrooms and teachers from the principal, manages the life cycle of the lessons, and monitors the progress and status of the course. He also communicates with the janitor to start and stop the classrooms.
  - The Container is like the classroom, which represents a fixed amount of space, furniture, equipment, and utilities that can be used by a course. A classroom can hold one or more lessons of a course, depending on the course logic and configuration.
