#### HDFS concepts

HDFS stands for Hadoop Distributed File System. It is a distributed file system that runs on a cluster of commodity hardware devices and provides high throughput access to large data sets. HDFS is one of the core components of Apache Hadoop, an open source framework for distributed processing and analysis of big data.

Some of the key concepts of HDFS are:

- **Blocks**: HDFS divides each file into fixed-size blocks, usually 128 MB, and stores them across multiple data nodes in the cluster. Each block is replicated on a configurable number of data nodes (default is 3) to ensure fault tolerance and availability. HDFS does not store any metadata (such as file name, permissions, etc.) with the blocks. Instead, it maintains a separate namespace for the files and directories, which is stored on a dedicated node called the NameNode.
- **NameNode**: The NameNode is the master node of the HDFS cluster. It manages the namespace and the metadata of the file system, such as the file names, permissions, locations of the blocks, etc. The NameNode also coordinates the read and write operations from the clients to the data nodes. The NameNode keeps the entire file system metadata in memory for fast access and periodically saves a copy of it to a local disk, called the FsImage. The NameNode also maintains a log of the changes made to the file system, called the EditLog. The NameNode is a single point of failure in HDFS, so it is usually configured with a backup node or a high availability mode to ensure reliability.
- **DataNode**: The DataNode is the worker node of the HDFS cluster. It stores the actual data blocks of the files and serves the read and write requests from the clients. The DataNode also performs periodic block reports to the NameNode, informing it about the blocks it is storing and their health status. The DataNode also performs block replication, deletion, and rebalancing as instructed by the NameNode. The DataNode is designed to handle failures gracefully and can be added or removed from the cluster dynamically.
- **Client**: The client is the application or the user that interacts with the HDFS cluster. The client can perform various operations on the file system, such as creating, deleting, reading, writing, appending, and renaming files and directories. The client communicates with the NameNode to get the metadata of the file system and the locations of the blocks. The client then directly contacts the DataNodes to perform the actual data transfer. The client also handles the failures and retries of the DataNodes by consulting the NameNode for the latest block locations. The client can use various APIs or tools to access the HDFS cluster, such as Java, C, Python, WebHDFS, etc.
