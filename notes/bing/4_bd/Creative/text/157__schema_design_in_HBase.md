#### Schema design in HBase

- HBase is a NoSQL database that does not support joins or secondary indexes, but provides fast and scalable access to data by using a single primary key.
- HBase schema design is based on the following concepts:
  - Row key: This is the unique identifier for each row in a table. It is used to sort and locate the data. It should be carefully chosen to avoid hotspots and ensure even distribution of data across regions.
  - Column family: This is a logical grouping of columns that share some common characteristics, such as compression, encoding, or versioning. Each column family is stored separately on disk, so it is advisable to limit the number of column families per table to avoid performance degradation.
  - Column qualifier: This is the name of a column within a column family. It can be dynamic and vary from row to row. It can also be used to store nested entities or complex data types by concatenating multiple values or attributes.
  - Cell: This is the smallest unit of data in HBase. It consists of a row key, a column family, a column qualifier, a timestamp, and a value. The value can be any binary data, such as a string, a number, or an image.
  - Timestamp: This is the time when a cell was inserted or updated. It can be either assigned by the client or generated by the server. It is used to keep track of multiple versions of a cell and to perform time-based queries or scans.
- HBase schema design supports denormalization and wide tables, which means that data can be duplicated or stored in multiple columns or rows to optimize read performance and avoid joins. However, this also increases the write and storage costs and may introduce inconsistency issues.
- HBase schema design also supports filters, which are predicates that can be applied to a scan or a get operation to limit the results or to perform some transformations on the data. Filters can improve the read performance by reducing the amount of data transferred from the server to the client. Some common filters are:
  - PrefixFilter: This filter matches rows that have a row key that starts with a given prefix.
  - ColumnPrefixFilter: This filter matches columns that have a column qualifier that starts with a given prefix.
  - SingleColumnValueFilter: This filter matches rows that have a specific value in a given column.
  - PageFilter: This filter limits the number of rows returned by a scan operation.
