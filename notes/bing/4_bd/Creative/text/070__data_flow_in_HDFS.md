#### Data flow in HDFS

HDFS stands for Hadoop Distributed File System, which is a storage layer of Hadoop that stores data in a distributed and reliable manner. HDFS splits a file into one or more blocks and stores them across a cluster of DataNodes. The NameNode manages the file system namespace and the metadata of the blocks. The client interacts with the NameNode and the DataNodes to perform read and write operations on HDFS files.

The data flow in HDFS can be summarized as follows:

- **Write operation**: The client creates a file by calling `create()` on the DistributedFileSystem (DFS) object, which is an instance of Hadoop FileSystem. DFS makes a remote procedure call (RPC) to the NameNode to create a new file in the file system's namespace, with no blocks associated with it. The NameNode checks if the file already exists or if the parent directory is valid, and returns an exception if any of these conditions are not met. The NameNode also grants a lease to the client to create the file, which prevents other clients from writing to the same file. The client then writes data to the file by calling `write()` on the DFSOutputStream object, which is a wrapper of the Java OutputStream. The DFSOutputStream splits the data into packets, which it writes to an internal queue called the data queue. The data queue is consumed by the DataStreamer, which is a thread that asks the NameNode to allocate new blocks by picking a list of suitable DataNodes to store the replicas. The list of DataNodes forms a pipeline, and the DataStreamer streams the packets to the first DataNode in the pipeline. The first DataNode stores the packet and forwards it to the second DataNode, and so on until the last DataNode. The DataStreamer also maintains an internal queue of packets that are waiting for an acknowledgement from the DataNodes, called the ack queue. The last DataNode in the pipeline sends back an acknowledgement to the previous DataNode, which relays it back to the DataStreamer. The DataStreamer removes the acknowledged packets from the ack queue. If a packet fails to be acknowledged by a certain timeout or a DataNode fails, the pipeline is broken and a new pipeline is constructed by the DataStreamer. The write operation is complete when the client calls `close()` on the DFSOutputStream, which flushes all the remaining packets to the DataNodes and tells the NameNode to complete the file. The NameNode commits the file creation by removing the lease and adding the file to the namespace.

- **Read operation**: The client opens a file by calling `open()` on the DFS object, which returns a DFSInputStream object, which is a wrapper of the Java InputStream. The client then reads data from the file by calling `read()` on the DFSInputStream, which contacts the NameNode to fetch the locations of the blocks of the file. The NameNode returns a list of DataNodes for each block, sorted by their proximity to the client. The client then contacts the closest DataNode for the first block of the file and starts reading data from it. If the read fails or the DataNode is not available, the client tries the next DataNode in the list. The client can also perform a seek operation to move to a different position in the file, which may involve contacting the NameNode again to get the new block locations. The read operation is complete when the client has read all the data from the file or calls `close()` on the DFSInputStream.
