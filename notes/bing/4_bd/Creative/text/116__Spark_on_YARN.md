#### Spark on YARN

- Spark on YARN is a mode of running Spark applications on a cluster of machines managed by YARN (Yet Another Resource Negotiator), which is a resource manager for Hadoop.
- Spark on YARN requires a binary distribution of Spark that is built with YARN support. Binary distributions can be downloaded from the downloads page of the project website. To build Spark yourself, refer to Building Spark.
- To make Spark runtime jars accessible from YARN side, you can specify `spark.yarn.archive` or `spark.yarn.jars` in the `spark-defaults.conf` file or as command-line options. These options point to a compressed archive or a list of jars that contain the Spark classes and dependencies.
- Spark on YARN supports two deployment modes: `cluster` and `client`. In `cluster` mode, the Spark driver runs on a YARN container on one of the cluster nodes. In `client` mode, the Spark driver runs on the machine that launches the Spark application, and the YARN resource manager allocates containers for the Spark executors.
- Spark on YARN can use dynamic allocation to scale the number of executors up and down based on the workload. This feature requires an external shuffle service to be enabled on each node in the cluster, which preserves the shuffle files of the executors that are removed. The external shuffle service can be configured by setting `spark.shuffle.service.enabled` to `true` and `yarn.nodemanager.aux-services` to `spark_shuffle`.
- Spark on YARN can also use the YARN timeline server to store the application history. This feature can be enabled by setting `spark.yarn.historyServer.address` to the URL of the timeline server and `spark.eventLog.enabled` to `true`. The timeline server can be accessed through the YARN web UI or the Spark history server UI.
