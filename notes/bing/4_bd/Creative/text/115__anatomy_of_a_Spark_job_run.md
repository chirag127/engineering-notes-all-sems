#### Anatomy of a Spark job run

- A Spark job is a parallel computation that runs on a cluster of nodes and consists of one or more stages.
- A stage is a set of tasks that perform the same computation on different partitions of the input data.
- A task is a unit of work that runs on a single executor and processes a single partition of the input data.
- An executor is a process that runs on a worker node and executes tasks assigned by the driver.
- A driver is the process that coordinates the execution of a Spark job and runs the user-defined main function.
- A Spark job is created when the driver submits a Spark application to the cluster manager, which allocates resources for the job.
- A Spark job is divided into stages based on the dependencies between the RDDs (Resilient Distributed Datasets) that are involved in the computation.
- A stage can be either a shuffle stage or a result stage, depending on whether it involves shuffling data across the network or not.
- A shuffle stage is a stage that requires data to be transferred from one or more parent stages to child stages, such as when performing a join or a group-by operation.
- A result stage is a stage that computes the final result of the job, such as when performing an action like collect or save.
- A stage is further divided into tasks based on the number of partitions of the RDD that is being computed.
- A task is executed by an executor on a worker node and reads data from one or more partitions of the input RDD, applies the user-defined function, and writes the output to a partition of the output RDD or to an external storage system.
- A task can also read and write data from a shuffle file, which is a temporary file that stores the intermediate data produced by a shuffle stage.
- A task can also communicate with the driver through an accumulator, which is a shared variable that can be updated by tasks and read by the driver.
- A task can also report metrics to the driver, such as the number of records processed, the amount of memory used, and the duration of the task.
- A task can also fail due to various reasons, such as an exception in the user code, a network error, a disk error, or a timeout.
- A task failure can trigger a task retry, a stage retry, or a job failure, depending on the type and frequency of the failure and the spark.task.maxFailures configuration parameter.
- A task retry is a re-execution of the same task on the same or a different executor, which can be done up to spark.task.maxFailures times before failing the stage.
- A stage retry is a re-computation of the entire stage and its parent stages, which can be done up to spark.stage.maxFailures times before failing the job.
- A job failure is a termination of the Spark job, which can be handled by the user code or by the cluster manager, depending on the spark.submit.deployMode configuration parameter.
- A job failure can also trigger a job resubmission, which is a re-submission of the same Spark application to the cluster manager, which can be done up to spark.yarn.maxAppAttempts times before giving up.
