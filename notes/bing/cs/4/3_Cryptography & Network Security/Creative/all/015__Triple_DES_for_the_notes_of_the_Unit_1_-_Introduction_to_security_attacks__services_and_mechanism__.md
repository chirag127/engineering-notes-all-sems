- Triple DES (3DES or TDES) is a symmetric-key block cipher, which applies the DES cipher algorithm three times to each data block.
- The Data Encryption Standard (DES) is a symmetric-key algorithm based on a Feistel network, which operates on 64-bit blocks of data using a 56-bit key.
- DES was published in 1975 and became a widely used standard for encryption, but it was later shown to be vulnerable to brute-force attacks and differential cryptanalysis.
- Triple DES provides a relatively simple method of increasing the key size of DES to protect against such attacks, without the need to design a completely new block cipher algorithm.
- Triple DES uses three 56-bit keys (K1, K2, K3), which can be chosen independently or derived from a single 112-bit or 168-bit key.
- Triple DES can operate in different modes, such as:
  - Electronic Codebook (ECB): Each 64-bit block of plaintext is encrypted independently with the same key. This mode is simple but insecure, as identical blocks of plaintext produce identical blocks of ciphertext, revealing patterns and repetitions in the data.
  - Cipher Block Chaining (CBC): Each 64-bit block of plaintext is XORed with the previous block of ciphertext before being encrypted with the key. This mode introduces randomness and prevents identical blocks of plaintext from producing identical blocks of ciphertext. The first block of plaintext is XORed with an initialization vector (IV), which is a random 64-bit value.
  - Cipher Feedback (CFB): The key is used to encrypt an IV, and the resulting ciphertext is XORed with the first segment of plaintext to produce the first segment of ciphertext. The ciphertext segment is then fed back to the encryption function and XORed with the next segment of plaintext, and so on. This mode allows encryption of data that is not a multiple of 64 bits, as the segment size can be smaller than a block.
  - Output Feedback (OFB): The key is used to encrypt an IV, and the resulting ciphertext is XORed with the first segment of plaintext to produce the first segment of ciphertext. The ciphertext is not fed back to the encryption function, but the IV is. This mode also allows encryption of data that is not a multiple of 64 bits, and it prevents error propagation, as a single bit error in the ciphertext only affects the corresponding bit in the plaintext.
  - Counter (CTR): A counter value is encrypted with the key, and the resulting ciphertext is XORed with the first segment of plaintext to produce the first segment of ciphertext. The counter value is incremented by one and encrypted again for the next segment, and so on. This mode also allows encryption of data that is not a multiple of 64 bits, and it enables parallel encryption and decryption, as each segment can be processed independently.
- Triple DES can use different schemes for applying the three keys, such as:
  - Encrypt-Decrypt-Encrypt (EDE): The plaintext is encrypted with K1, decrypted with K2, and encrypted again with K3. This scheme is the most common and compatible with single DES, as setting K1=K2=K3 reduces to single DES encryption.
  - Encrypt-Encrypt-Encrypt (EEE): The plaintext is encrypted with K1, encrypted again with K2, and encrypted again with K3. This scheme is less common and not compatible with single DES, as setting K1=K2=K3 does not reduce to single DES encryption.
  - Decrypt-Encrypt-Decrypt (DED): The plaintext is decrypted with K1, encrypted with K2, and decrypted again with K3. This scheme is equivalent to EDE with reversed keys, as setting K1=K3 and K2=K2 produces the same result as EDE with K1=K2 and K3=K3.
  - Decrypt-Decrypt-Decrypt (DDD): The plaintext is decrypted with K1, decrypted again with K2, and decrypted again with K3. This scheme is equivalent to EEE
