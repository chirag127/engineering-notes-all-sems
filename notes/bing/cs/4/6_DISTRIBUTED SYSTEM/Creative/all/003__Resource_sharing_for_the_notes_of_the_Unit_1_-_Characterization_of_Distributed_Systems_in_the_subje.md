### Resource sharing for the notes of the Unit 1 - Characterization of Distributed Systems in the subject of DISTRIBUTED SYSTEM

- Resource sharing means that the existing resources in a distributed system can be accessed or remotely accessed across multiple computers in the system.
- Resources can be hardware (such as disks and printers), software (such as files, windows and data objects) or data (such as databases and web pages) .
- Resource sharing can improve the performance, reliability, scalability and availability of distributed systems .
- Resource sharing can be achieved in different ways, such as:
  - Data migration: the process of transferring data from one location to another location in the system. For example, a file can be copied from one computer to another computer for faster access.
  - Computation migration: the process of transferring a computation from one computer to another computer in the system. For example, a task can be executed on a remote computer that has more processing power or less load.
  - Process migration: the process of transferring a running process from one computer to another computer in the system. For example, a process can be moved to a different computer for load balancing or fault tolerance.
  - Load sharing: the process of distributing the workload among multiple computers in the system. For example, a web server can distribute the requests from clients to different web servers for better performance.
- Resource sharing can be implemented in a centralized or decentralized manner. Centralized resource sharing involves a single entity that manages the resources and allocates them to the requests. Decentralized resource sharing involves multiple entities that cooperate to share the resources and handle the requests.
- Resource sharing can be challenged by some issues, such as:
  - Heterogeneity: the diversity of hardware, software and data in the system. For example, different computers may have different operating systems, architectures, protocols and formats.
  - Transparency: the ability to hide the complexity and details of the system from the users and applications. For example, users should not be aware of the location, replication, migration or failure of the resources.
  - Security: the protection of the resources and the system from unauthorized access, modification or damage. For example, the system should ensure the confidentiality, integrity and availability of the resources and the communication.
  - Scalability: the ability to handle the growth of the system in terms of size, complexity and demand. For example, the system should be able to add or remove resources and computers without affecting the performance or functionality of the system.

- A mnemonic to remember the four challenges of resource sharing is **HATS** (Heterogeneity, Transparency, Security, Scalability).
- A learning trick to understand the difference between data migration, computation migration and process migration is to use the analogy of a library. Data migration is like borrowing a book from the library and taking it home. Computation migration is like asking the librarian to find a book for you and bring it to you. Process migration is like moving to a different library while reading a book.
