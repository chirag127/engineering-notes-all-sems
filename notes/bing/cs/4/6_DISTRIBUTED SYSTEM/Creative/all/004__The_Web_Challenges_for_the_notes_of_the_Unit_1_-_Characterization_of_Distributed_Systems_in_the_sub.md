### The Web Challenges for the notes of the Unit 1 - Characterization of Distributed Systems in the subject of DISTRIBUTED SYSTEM

- A distributed system is a collection of independent computers that appear to the users as a single coherent system.
- The web is an example of a distributed system that enables users to access services and run applications over a heterogeneous collection of computers and networks.
- The web challenges for distributed systems are the problems and difficulties that arise when designing, implementing, and maintaining distributed systems that operate on the web.
- Some of the major web challenges for distributed systems are :

  - **Scalability**: The ability of a distributed system to handle increasing load and demand without degrading its performance or functionality. Scalability can be achieved by adding more resources, such as servers, nodes, or bandwidth, or by improving the efficiency of the system, such as using caching, load balancing, or replication techniques.
  - **Heterogeneity**: The diversity and variability of the hardware, software, network, and data formats that are involved in a distributed system. Heterogeneity can pose challenges for interoperability, compatibility, and portability of the system components and services. Heterogeneity can be addressed by using common standards, protocols, and interfaces, such as HTTP, XML, JSON, or REST.
  - **Security**: The protection of the distributed system and its data from unauthorized access, modification, or damage. Security can be compromised by various threats, such as hackers, viruses, worms, or denial-of-service attacks. Security can be enhanced by using encryption, authentication, authorization, or firewall techniques.
  - **Fault tolerance**: The ability of a distributed system to continue operating correctly despite the occurrence of failures or errors in some of its components or services. Fault tolerance can be achieved by using redundancy, backup, or recovery techniques, such as checkpoints, logging, or consensus algorithms.
  - **Consistency**: The property of a distributed system that ensures that all the components or services have a coherent and agreed-upon view of the system state and data. Consistency can be violated by concurrent or conflicting updates, network delays, or partitions. Consistency can be maintained by using synchronization, coordination, or replication techniques, such as locks, transactions, or quorum protocols.
  - **Transparency**: The property of a distributed system that hides the complexity and details of its implementation and operation from the users and applications. Transparency can improve the usability, reliability, and efficiency of the system. Transparency can be achieved by using abstraction, encapsulation, or middleware techniques, such as RPC, RMI, or CORBA.

- A mnemonic to remember the web challenges for distributed systems is **SHFCTT** (pronounced as shift), which stands for **S**calability, **H**eterogeneity, **F**ault tolerance, **C**onsistency, and **T**ransparency.
