### Token based and non token based algorithms for the notes of the Unit 2 - Distributed Mutual Exclusion in the subject of DISTRIBUTED SYSTEM

- Distributed mutual exclusion (DME) is the problem of ensuring that only one process at a time can access a shared resource in a distributed system.
- There are two main types of algorithms for DME: token based and non token based.
- Token based algorithms use a unique token that is passed among the processes to grant access to the critical section. Only the process that holds the token can enter the critical section. The token is then transferred to another process that requests it.
- Non token based algorithms use messages to coordinate the access to the critical section. A process that wants to enter the critical section sends a request message to a set of other processes and waits for their replies. The replies indicate whether the process can enter the critical section or not, based on some ordering criteria such as timestamps or logical clocks.
- Some examples of token based algorithms are:
  - Suzuki-Kasami algorithm: This is a modification of Ricart-Agrawala algorithm, a permission based (non token based) algorithm that uses REQUEST and REPLY messages to ensure mutual exclusion. In Suzuki-Kasami algorithm, the token is a vector that records the number of requests made by each process. The token is initially held by an arbitrary process. When a process wants to enter the critical section, it sends a REQUEST message to the token holder with its process id and the number of requests it has made. The token holder compares the request number with the corresponding entry in the token vector. If the request number is greater, it means that the process has not entered the critical section since its last request, and the token holder sends the token to the requesting process. Otherwise, the token holder ignores the request. When a process receives the token, it enters the critical section and updates the token vector. When it exits the critical section, it sends the token to the next process that has the highest request number in the token vector.
  - Raymond's algorithm: This is a tree based algorithm that organizes the processes into a logical tree. The token is initially held by the root of the tree. When a process wants to enter the critical section, it sends a REQUEST message to its parent in the tree. The parent forwards the request to its parent, and so on, until the request reaches the token holder. The token holder sends the token to the process that requested it, along the reverse path of the request. When a process receives the token, it enters the critical section and becomes the new root of the tree. When it exits the critical section, it sends the token to one of its children that has requested it, or keeps the token if no child has requested it.
- Some examples of non token based algorithms are:
  - Lamport's algorithm: This is a timestamp based algorithm that uses logical clocks to order the requests for the critical section. Each process maintains a logical clock that is incremented whenever it sends or receives a message. When a process wants to enter the critical section, it sends a REQUEST message to all other processes with its process id and its current logical clock value. It also adds its request to a local queue, ordered by the logical clock values. When a process receives a REQUEST message, it sends a REPLY message to the requesting process with its current logical clock value, and adds the request to its local queue. When a process receives a REPLY message from all other processes, it checks if its request is at the head of its local queue. If yes, it means that it has the highest priority among all the requests, and it enters the critical section. When it exits the critical section, it removes its request from the local queue and sends a RELEASE message to all other processes. When a process receives a RELEASE message, it removes the corresponding request from its local queue.
  - Ricart-Agrawala algorithm: This is an optimization of Lamport's algorithm that reduces the number of messages exchanged. In this algorithm, a process does not send a REPLY message immediately when it receives a REQUEST message. Instead, it defers the reply if it is in the critical section or if it has a pending request with a higher priority than the received request. When a process exits the critical section or receives a REPLY message for its pending request, it sends a REPLY message to all the processes whose requests it has deferred. The rest of the algorithm is the same as Lamport's algorithm.
- Some advantages of token based algorithms are:
  - They do not require global synchronization of clocks
