### Techniques for Message Ordering for the notes of the Unit 1 - Characterization of Distributed Systems in the subject of DISTRIBUTED SYSTEM

- Message ordering is the problem of ensuring that messages sent by different processes in a distributed system are received in a consistent and predictable order.
- Message ordering is important for achieving coordination, consistency, and correctness among distributed processes.
- There are different types of message ordering, depending on the application requirements and the system model.
- Some of the common techniques for message ordering are:

  - **FIFO (First-In-First-Out) ordering**: This technique ensures that messages sent by the same process are received in the order they were sent. For example, if process P sends messages m1, m2, and m3 to process Q, then Q will receive them in the same order: m1, m2, and m3. FIFO ordering can be implemented by attaching a sequence number to each message and buffering out-of-order messages at the receiver.
  - **Causal ordering**: This technique ensures that messages that are causally related are received in the same order by all processes. Two messages are causally related if one message could have influenced the other. For example, if process P sends a message m1 to process Q, and Q sends a message m2 to process R, then m1 and m2 are causally related. Causal ordering can be implemented by using vector clocks, which are arrays of logical timestamps that capture the causal dependencies among messages.
  - **Total ordering**: This technique ensures that messages sent by any process are received in the same order by all processes. For example, if process P sends a message m1 to processes Q and R, and process Q sends a message m2 to processes P and R, then all processes will receive the messages in the same order, either m1, m2 or m2, m1. Total ordering can be implemented by using a centralized sequencer, which assigns a global sequence number to each message and broadcasts it to all processes, or by using a distributed consensus algorithm, which allows processes to agree on a common order of messages.
  - **Atomic broadcast**: This technique ensures that messages sent by any process are either received by all processes or none. Atomic broadcast is a stronger form of total ordering, which also guarantees reliability and fault-tolerance. Atomic broadcast can be implemented by using a reliable multicast protocol, which ensures that messages are delivered to all processes despite failures and network partitions, or by using a distributed commit protocol, which ensures that messages are delivered to all processes only if they agree to do so.
