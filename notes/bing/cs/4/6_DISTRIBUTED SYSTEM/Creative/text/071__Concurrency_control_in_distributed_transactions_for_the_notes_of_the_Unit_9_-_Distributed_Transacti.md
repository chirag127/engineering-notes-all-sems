### Concurrency control in distributed transactions

- Concurrency control is the process of managing the concurrent execution of transactions in a distributed system, such that the ACID properties are preserved .
- ACID stands for Atomicity, Consistency, Isolation, and Durability, which are the desirable properties of a transaction.
- A distributed system is a system that consists of multiple interconnected nodes (such as computers or servers) that communicate and coordinate their actions by passing messages.
- A distributed transaction is a transaction that accesses and updates data on multiple nodes in a distributed system .
- Concurrency control in distributed transactions is challenging because of the following issues :
  - Network latency and failures: The communication between nodes may be slow, unreliable, or disrupted, which can affect the coordination and synchronization of transactions.
  - Data replication and consistency: The same data may be stored on multiple nodes for availability and performance reasons, which can lead to inconsistency and conflicts if transactions update different copies of the data.
  - Distributed deadlock: A deadlock is a situation where two or more transactions are waiting for each other to release some resources, and none of them can proceed. A distributed deadlock is a deadlock that involves transactions on different nodes, which is harder to detect and resolve than a local deadlock.
- There are different approaches and algorithms for concurrency control in distributed transactions, such as  :
  - Locking-based protocols: These protocols use locks to prevent concurrent transactions from accessing or modifying the same data. A lock is a mechanism that grants exclusive or shared access to a data item to a transaction. A transaction must acquire a lock before accessing a data item, and release it after finishing. There are different types of locks, such as read locks, write locks, exclusive locks, and shared locks. There are also different locking protocols, such as two-phase locking (2PL), strict 2PL, conservative 2PL, and tree-structured locking.
  - Timestamp-based protocols: These protocols use timestamps to order the transactions and ensure serializability. A timestamp is a unique identifier that reflects the start time or the priority of a transaction. A transaction must obtain a timestamp before executing, and use it to compare with the timestamps of other transactions or data items. There are different timestamp-based protocols, such as basic timestamp ordering (BTO), optimistic concurrency control (OCC), and multiversion concurrency control (MVCC).
  - Validation-based protocols: These protocols use validation or certification to check the correctness of transactions before committing them. A transaction must pass a validation test before committing, and abort otherwise. The validation test may involve checking the read and write sets of the transaction, or comparing the transaction's timestamp with the commit time of other transactions. There are different validation-based protocols, such as two-phase commit (2PC), three-phase commit (3PC), and Paxos commit.
