### Architectural models for the notes of the Unit 1 - Characterization of Distributed Systems in the subject of DISTRIBUTED SYSTEM

- Architectural models describe the organization of components across the network and their interrelationship.
- Architectural models can be classified into different types based on the placement of parts, the degree of distribution, and the level of abstraction.
- Some common architectural models are:

  - Layered architecture: In this model, different components are organized in layers. Each layer communicates with its adjacent layer by sending requests and getting responses. This model simplifies the design and implementation of distributed systems by separating the functionality and responsibilities of each layer. For example, the OSI model and the TCP/IP model are layered architectures for network protocols.
  - Object-based architecture: In this model, the components are distributed objects that encapsulate data and behavior. The objects communicate with each other by invoking methods using a common object request broker (ORB). This model supports reusability, modularity, and interoperability of distributed systems by hiding the implementation details and exposing the interfaces of the objects. For example, the Common Object Request Broker Architecture (CORBA) and the Distributed Component Object Model (DCOM) are object-based architectures for distributed systems.
  - Data-centered architecture: In this model, the components are processes that access and manipulate a shared data repository. The data repository can be either passive (such as a database or a file system) or active (such as a blackboard or a tuple space). This model facilitates coordination, synchronization, and consistency of distributed systems by providing a common data model and a global view of the data. For example, the Google File System (GFS) and the Apache Hadoop Distributed File System (HDFS) are data-centered architectures for distributed systems.
  - Event-based architecture: In this model, the components are publishers and subscribers that communicate through asynchronous events. The events are propagated by an event service or a message broker that decouples the publishers and subscribers. This model enables scalability, flexibility, and dynamism of distributed systems by allowing the components to join and leave the system without affecting the others. For example, the Java Message Service (JMS) and the Apache Kafka are event-based architectures for distributed systems.
  - Service-oriented architecture: In this model, the components are services that provide well-defined functionality and quality of service. The services are loosely coupled and communicate through standard protocols such as SOAP or REST. This model promotes reusability, interoperability, and composability of distributed systems by exposing the services as self-describing and discoverable entities. For example, the Web Services Description Language (WSDL) and the Universal Description, Discovery and Integration (UDDI) are service-oriented architectures for distributed systems.
  - Peer-to-peer architecture: In this model, the components are peers that have equal roles and responsibilities. The peers cooperate and coordinate with each other to achieve a common goal or to share resources. This model supports decentralization, fault-tolerance, and self-organization of distributed systems by eliminating the need for a central authority or a server. For example, the BitTorrent and the Napster are peer-to-peer architectures for distributed systems.
