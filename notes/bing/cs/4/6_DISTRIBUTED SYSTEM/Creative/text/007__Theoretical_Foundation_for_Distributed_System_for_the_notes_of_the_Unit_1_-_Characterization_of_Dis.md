### Theoretical Foundation for Distributed System

A distributed system is a system whose components are located on different networked computers, which communicate and coordinate their actions by passing messages to one another. Distributed computing is a field of computer science that studies distributed systems and their properties, such as scalability, fault-tolerance, consistency, and concurrency.

Some of the theoretical foundations for distributed system are:

- **Limitations of distributed system**: Due to the absence of a global clock, a shared memory, and a reliable communication channel, distributed systems face some inherent challenges, such as synchronization, coordination, agreement, and consistency . For example, it is impossible to achieve consensus among a set of processes in an asynchronous network with one faulty process.
- **Logical clocks**: A logical clock is a mechanism to order events in a distributed system based on their causal relationships, rather than their physical timestamps. A logical clock assigns a logical timestamp to each event, such that if event A causally precedes event B, then the timestamp of A is smaller than the timestamp of B. There are different types of logical clocks, such as Lamport's clocks and vector clocks.
- **Lamport's clocks**: Lamport's clocks are a type of logical clocks that use a single integer to represent the logical timestamp of an event. Each process maintains its own local clock, which is incremented by one before each event. When a process sends a message, it attaches its current clock value to the message. When a process receives a message, it updates its clock to the maximum of its own clock and the received clock value, and then increments it by one.
- **Vector clocks**: Vector clocks are a type of logical clocks that use a vector of integers to represent the logical timestamp of an event. Each process maintains a vector of size n, where n is the number of processes in the system. The i-th entry of the vector represents the local clock of the i-th process. When a process executes an event, it increments its own entry in the vector. When a process sends a message, it attaches its current vector to the message. When a process receives a message, it updates each entry of its vector to the maximum of its own entry and the received entry.
- **Concepts in message passing system**: A message passing system is a model of communication in a distributed system, where processes exchange messages to transfer information and coordinate actions. Some of the concepts in message passing system are:

  - **Message ordering**: Message ordering is the property that defines how messages are delivered to the processes in a consistent and predictable way. There are different types of message ordering, such as FIFO, causal, and total ordering.
  - **Message reliability**: Message reliability is the property that guarantees that messages are delivered to the processes without loss, duplication, or corruption. There are different types of message reliability, such as best-effort, at-most-once, at-least-once, and exactly-once delivery.
  - **Message buffering**: Message buffering is the mechanism that stores messages temporarily at the sender or the receiver side until they are delivered or processed. Message buffering can affect the performance and the correctness of the message passing system, depending on the buffer size, the buffer management policy, and the message ordering requirement.
