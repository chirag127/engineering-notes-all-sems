### Token based and non token based algorithms for the notes of the Unit 2 - Distributed Mutual Exclusion in the subject of DISTRIBUTED SYSTEM

- Distributed mutual exclusion (DME) is the problem of ensuring that only one process at a time can access a shared resource in a distributed system.
- There are two main approaches to solve DME: token based and non token based algorithms.
- Token based algorithms use a special message, called a token, that grants the permission to enter the critical section. Only the process that holds the token can access the shared resource. The token is passed among the processes in a predefined order or based on requests.
- Non token based algorithms use timestamps to order the requests for the critical section and to resolve conflicts between simultaneous requests. In the non token based algorithms, a process communicates with a set of other processes to determine who should execute the critical section next.
- Some examples of token based algorithms are:
  - Suzuki–Kasami algorithm: This is a modification of Ricart–Agrawala algorithm, a permission based algorithm that uses REQUEST and REPLY messages to ensure mutual exclusion. In Suzuki–Kasami algorithm, the token contains a vector of sequence numbers, one for each process, that indicates the latest request of each process. The token is sent to the process with the highest request number. The algorithm reduces the number of messages from O(n^2) to O(n) per critical section entry.
  - Raymond's algorithm: This is a tree based algorithm that organizes the processes into a logical tree. The token is initially held by the root of the tree. A process that wants to enter the critical section sends a REQUEST message to its parent in the tree, and the parent forwards the request to the root. The token is passed along the path from the root to the requesting process. The algorithm reduces the number of messages from O(n) to O(log n) per critical section entry.
- Some examples of non token based algorithms are:
  - Lamport's algorithm: This is a logical clock based algorithm that uses timestamps to order the requests. A process that wants to enter the critical section broadcasts a REQUEST message with its timestamp to all other processes. A process that receives a REQUEST message replies with an ACK message if it is not in the critical section or it has a later timestamp. A process can enter the critical section when it receives ACK messages from all other processes. The algorithm requires O(n^2) messages per critical section entry.
  - Maekawa's algorithm: This is a voting based algorithm that uses a subset of processes, called a quorum, to grant permission to enter the critical section. A process that wants to enter the critical section sends a REQUEST message to all processes in its quorum. A process that receives a REQUEST message replies with a VOTE message if it has not voted for another process. A process can enter the critical section when it receives VOTE messages from all processes in its quorum. The algorithm reduces the number of messages from O(n^2) to O(sqrt(n)) per critical section entry, but it introduces the possibility of deadlock.
