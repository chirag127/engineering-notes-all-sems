### Comparison of methods for concurrency control

Concurrency control is the process of managing the simultaneous execution of transactions in a distributed system, such that the consistency and correctness of the data are preserved. Concurrency control techniques can be classified into two categories: locking-based and non-locking-based.

- Locking-based techniques use locks to prevent conflicting operations on the same data item by different transactions. A lock is a permission to access a data item in a certain mode, such as read or write. A transaction must acquire a lock before accessing a data item, and release the lock after finishing the access. Locking-based techniques can ensure serializability, which is the property that the concurrent execution of transactions is equivalent to some serial execution of the same transactions. However, locking-based techniques may suffer from problems such as deadlock, livelock, and starvation.

- Non-locking-based techniques do not use locks, but rely on other mechanisms to control concurrency, such as timestamps, versions, or validation. Non-locking-based techniques can avoid the problems of locking-based techniques, but may incur more overhead or complexity. Non-locking-based techniques can ensure different levels of consistency, such as snapshot isolation, causal consistency, or eventual consistency.

Some of the common methods for concurrency control are:

- Two-phase locking (2PL): This is a locking-based technique that requires a transaction to acquire all the locks it needs before releasing any lock. 2PL can be divided into two phases: a growing phase, where the transaction acquires locks and performs operations, and a shrinking phase, where the transaction releases locks and commits or aborts. 2PL ensures serializability, but may cause deadlock.

- Timestamp ordering (TO): This is a non-locking-based technique that assigns a unique timestamp to each transaction, and orders the transactions according to their timestamps. A transaction can perform an operation on a data item only if its timestamp is compatible with the timestamps of previous operations on the same data item. Otherwise, the transaction is aborted and restarted with a new timestamp. TO ensures serializability, but may cause high abort rate.

- Multi-version concurrency control (MVCC): This is a non-locking-based technique that maintains multiple versions of each data item, and assigns a timestamp to each version. A transaction can read the latest version of a data item that is older than or equal to its timestamp, and can write a new version of a data item with its timestamp. MVCC ensures snapshot isolation, which is a weaker form of consistency than serializability, but allows more concurrency and avoids aborts due to read conflicts.

- Validation concurrency control (VCC): This is a non-locking-based technique that divides the execution of a transaction into three phases: a read phase, where the transaction reads data items and performs computations, a validation phase, where the transaction checks if its read set is still valid, and a write phase, where the transaction writes data items and commits. VCC ensures serializability, but may cause high validation overhead.
