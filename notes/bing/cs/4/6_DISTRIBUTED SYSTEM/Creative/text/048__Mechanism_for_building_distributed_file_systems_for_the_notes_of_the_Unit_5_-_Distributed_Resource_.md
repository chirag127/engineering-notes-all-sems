### Mechanism for building distributed file systems

A distributed file system (DFS) is a file system that allows access to files from multiple hosts sharing via a computer network. A DFS provides location transparency and redundancy to improve data availability in the face of failure or heavy load by allowing more than one physical node to handle file operations.

Some of the mechanisms for building distributed file systems are:

- Use of file models: The DFS uses different conceptual models of a file, such as unstructured, structured, or record-oriented. The file model determines how the file is organized, accessed, and modified. For example, an unstructured file model treats the file as a sequence of bytes, while a structured file model imposes some logical structure on the file, such as records, fields, or objects.
- Use of file accessing models: A DFS may use one of the following models to service a client's file access request when the accessed file is a remote file:
  - Upload/download model: The client downloads the entire file from the server, modifies it locally, and uploads it back to the server when done. This model reduces network traffic but increases the risk of inconsistency if multiple clients access the same file concurrently.
  - Remote access model: The client sends file operations to the server, which executes them and returns the results. This model ensures consistency but increases network traffic and latency.
  - Remote service model: The client sends a high-level request to the server, such as a query or a transaction, which is processed by the server and returns the results. This model reduces network traffic and latency but requires the server to have more functionality and intelligence.
- Use of file sharing semantics: A shared file may be simultaneously accessed by multiple users or processes. The file sharing semantics define the rules for coordinating concurrent accesses and ensuring consistency. Some of the common file sharing semantics are:
  - UNIX semantics: The file system guarantees that any change made by one user is immediately visible to all other users. This semantics provides the strongest consistency but requires frequent synchronization between the clients and the server.
  - Session semantics: The file system guarantees that any change made by one user is visible to that user for the duration of the session, but not necessarily to other users. This semantics provides weaker consistency but reduces synchronization overhead.
  - Immutable semantics: The file system guarantees that once a file is created, it cannot be modified or deleted. This semantics provides the weakest consistency but eliminates synchronization altogether.
- Use of file replication: File replication is the primary mechanism for improving file availability and performance in a distributed systems environment. A replicated file is a file that has multiple copies with each copy located on a separate file server. File replication can be classified into two types:
  - Static replication: The file system creates and maintains a fixed number of replicas for each file. The replicas are usually placed on different servers to increase availability and load balancing. Static replication is suitable for read-only or rarely updated files.
  - Dynamic replication: The file system creates and deletes replicas for each file on demand, based on the access patterns and system conditions. The replicas are usually placed on the servers that are closest to the clients or have the least load. Dynamic replication is suitable for frequently updated or unpredictable files.
