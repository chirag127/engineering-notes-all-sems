## Unit 9 - Distributed Transactions

- A distributed transaction is a database transaction that involves two or more network hosts.
- A distributed transaction requires a transaction manager that coordinates the operations on different hosts and ensures the atomicity, consistency, isolation, and durability (ACID) properties of the transaction.
- A distributed transaction can be initiated by a client application, a database server, or a transaction manager.
- A distributed transaction can use different protocols to communicate and commit, such as two-phase commit (2PC), three-phase commit (3PC), or consensus protocols.
- A distributed transaction can be affected by various factors, such as network latency, concurrency, failures, and security.
- A distributed transaction can be implemented using different technologies, such as Microsoft Distributed Transaction Coordinator (MS DTC), SQL Server, or Azure SQL Managed Instance .
- A distributed transaction can have advantages and disadvantages, such as increased availability, scalability, and performance, but also increased complexity, overhead, and risk of inconsistency.
