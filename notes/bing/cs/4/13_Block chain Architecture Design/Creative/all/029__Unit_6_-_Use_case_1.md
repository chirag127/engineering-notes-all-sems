## Unit 6 - Use case 1

- Use case 1 is a technique for modeling the interactions between a system and its external actors.
- A use case 1 describes a scenario of how a user can achieve a specific goal using the system.
- A use case 1 consists of a name, a brief description, a list of actors, a list of preconditions, a main flow of events, a list of postconditions, and optionally some alternative flows and exceptions.
- A use case 1 diagram is a graphical representation of the use cases 1 and their relationships using UML notation.
- A use case 1 diagram shows the system boundary, the actors, and the use cases 1 using symbols such as ovals, rectangles, and lines.
- A use case 1 diagram can help to identify the functional requirements, the scope, and the stakeholders of a system.

Here is an example of a use case 1 diagram for an online shopping system:

```
+--------------------------+
|      Online Shopping     |
|        System            |
+--------------------------+
|                          |
|    +----------------+    |
|    |  Place Order   |    |
|    +----------------+    |
|            |             |
|            |             |
|    +----------------+    |
|    |  Make Payment  |    |
|    +----------------+    |
|            |             |
|            |             |
|    +----------------+    |
|    |  Confirm Order |    |
|    +----------------+    |
|                          |
+--------------------------+
       |             |
       |             |
       |             |
+------+-----+ +-----+------+
| Customer  | |  Bank      |
+-----------+ +------------+
```

- In this diagram, the system boundary is shown by the rectangle with the system name.
- The actors are shown by the stick figures with the actor names. Actors are the external entities that interact with the system.
- The use cases 1 are shown by the ovals with the use case 1 names. Use cases 1 are the functions that the system provides to the actors.
- The relationships between the actors and the use cases 1 are shown by the solid lines. Relationships indicate who can initiate or participate in a use case 1.
- The relationships between the use cases 1 are shown by the dashed lines. Relationships indicate the dependencies or the order of execution of the use cases 1.

Some advantages of using use case 1 diagrams are:

- They are simple and easy to understand by both technical and non-technical stakeholders.
- They can help to elicit and validate the user requirements and expectations from the system.
- They can help to identify the scope and boundaries of the system and avoid feature creep.
- They can help to communicate and document the system functionality and behavior.

Some disadvantages of using use case 1 diagrams are:

- They are not very detailed and may not capture all the nuances and complexities of the system.
- They may not address the non-functional requirements, such as performance, security, or usability of the system.
- They may not show the internal structure or the data flow of the system.
- They may not be sufficient for testing or implementation purposes and may need to be complemented by other models or specifications.
