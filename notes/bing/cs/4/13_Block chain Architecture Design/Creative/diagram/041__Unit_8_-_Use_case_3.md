## Unit 8 - Use case 3

A use case diagram is a graphical representation of the interactions between a system and its users. It shows the different types of users (actors) and the goals they want to achieve (use cases) with the system. A use case diagram can also include relationships, such as include, extend, and generalize, between the use cases and actors.

To draw a use case diagram, you need to follow these steps:

- Identify the system boundary, which is the scope or context of the system. Draw a rectangle to represent the system boundary and label it with the system name.
- Identify the actors, which are the external entities that interact with the system. Draw a stick figure to represent each actor and label it with the actor name. Place the actors outside the system boundary.
- Identify the use cases, which are the goals or functions that the actors want to achieve with the system. Draw an oval to represent each use case and label it with the use case name. Place the use cases inside the system boundary.
- Draw lines to connect the actors and the use cases they are involved in. These lines represent the communication or association between the actors and the use cases.
- Optionally, you can add relationships between the use cases, such as include, extend, and generalize, to show how they are related. Use a dashed arrow with a label to indicate the type of relationship. For example, an include relationship means that one use case always includes another use case, while an extend relationship means that one use case optionally extends another use case under certain conditions. A generalize relationship means that one use case is a special case of another use case.
