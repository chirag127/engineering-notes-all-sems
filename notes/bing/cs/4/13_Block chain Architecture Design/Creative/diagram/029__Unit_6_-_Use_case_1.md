A use case is a description of how a user interacts with a system to achieve a goal. A use case diagram is a visual representation of the relationships between the user and the system, as well as the different scenarios that can occur. A use case diagram consists of actors, use cases, and associations.

## Unit 6 - Use case 1

The following diagram illustrates a possible use case for Unit 6 - Use case 1, which is about a web programming department that has a conflict between its members.

```
+-----------------+       +-----------------+       +-----------------+
|  Project Lead   |       |  Senior Dev     |       |  Junior Dev     |
+-----------------+       +-----------------+       +-----------------+
        |                         |                         |
        |                         |                         |
        |                         |                         |
        |                         |                         |
        |                         |                         |
        |                         |                         |
        |                         |                         |
        |                         |                         |
        |                         |                         |
        |                         |                         |
        |                         |                         |
        |                         |                         |
        |                         |                         |
        |                         |                         |
        |                         |                         |
        |<------------------------|------------------------>|
        |    Assign tasks        |    Work on tasks       |
        |                         |                         |
        |                         |                         |
        |                         |                         |
        |                         |                         |
        |                         |                         |
        |                         |                         |
        |                         |                         |
        |<------------------------|------------------------>|
        |    Review code         |    Submit code         |
        |                         |                         |
        |                         |                         |
        |                         |                         |
        |                         |                         |
        |                         |                         |
        |                         |                         |
        |                         |                         |
        |<------------------------|------------------------>|
        |    Resolve conflict    |    Express feedback    |
        |                         |                         |
        |                         |                         |
        |                         |                         |
        |                         |                         |
        |                         |                         |
        |                         |                         |
        |                         |                         |
        +-------------------------+-------------------------+
```

The actors are the project lead, the senior developer, and the junior developer. The use cases are assign tasks, work on tasks, submit code, review code, express feedback, and resolve conflict. The associations are the lines that connect the actors and the use cases, indicating who participates in what use case. The arrows show the direction of the communication or action. The diagram shows the basic flow of events, as well as the alternative scenario where a conflict arises between the senior and junior developers, and the project lead has to intervene.
