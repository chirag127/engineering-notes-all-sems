According to one of the sources, the design primitives of blockchain are based on three aspects: transaction design, consensus design and block design. These aspects define how the transactions are structured, validated and stored in the blockchain. A possible diagram for the design primitives of blockchain is shown below:

```
+-----------------+      +-----------------+      +-----------------+
|                 |      |                 |      |                 |
| Transaction     |      | Consensus       |      | Block           |
| Design          |      | Design          |      | Design          |
|                 |      |                 |      |                 |
+-----------------+      +-----------------+      +-----------------+
|                 |      |                 |      |                 |
| - Data model    |      | - Protocol      |      | - Structure     |
| - Scripting     |      | - Incentives    |      | - Header        |
| - Validation    |      | - Attacks       |      | - Body          |
| - Privacy       |      | - Variants      |      | - Merkle tree   |
|                 |      |                 |      |                 |
+-----------------+      +-----------------+      +-----------------+
```

The diagram illustrates the basic components of each design aspect and how they relate to each other. The transaction design defines the data model, scripting language, validation rules and privacy mechanisms of the transactions. The consensus design defines the protocol, incentives, attacks and variants of the consensus mechanism that ensures the agreement among the nodes. The block design defines the structure, header, body and Merkle tree of the blocks that store the transactions.
