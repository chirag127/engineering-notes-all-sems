## Unit 4 - Hyperledger Fabric (A)

- Hyperledger Fabric is a permissioned, modular, and extensible blockchain platform that supports smart contracts and various consensus mechanisms.
- Hyperledger Fabric is one of the projects under the Hyperledger umbrella, which is hosted by the Linux Foundation and aims to advance cross-industry blockchain technologies.
- Hyperledger Fabric is designed to be flexible and scalable, allowing for different network configurations and use cases across various industries and domains.
- Hyperledger Fabric consists of several components, such as:
  - **Peers**: The nodes that execute and validate transactions, store the ledger, and run chaincode (smart contracts).
  - **Orderers**: The nodes that order and batch transactions into blocks, and broadcast them to the peers.
  - **Clients**: The applications that interact with the network, submit transactions, and query the ledger.
  - **Channels**: The private subnets of communication between a subset of peers, allowing for data isolation and confidentiality.
  - **Chaincode**: The business logic that defines the rules and operations of the network, written in a general-purpose programming language such as Go, Node.js, or Java.
  - **Endorsement policy**: The policy that specifies which peers need to endorse (approve) a transaction before it can be committed to the ledger.
  - **Membership service provider (MSP)**: The component that manages the identities, certificates, and access rights of the network participants.
  - **Consensus mechanism**: The algorithm that ensures the consistency and finality of the ledger across the network. Hyperledger Fabric supports pluggable consensus protocols, such as Raft, Kafka, or Solo.
- Hyperledger Fabric follows a transaction flow that involves the following steps:
  - **Proposal**: A client sends a transaction proposal to a set of endorsing peers, specifying the chaincode function to invoke and the arguments to pass.
  - **Simulation**: The endorsing peers simulate the transaction by executing the chaincode function with the given arguments, and produce a read-write set, which captures the current and proposed state of the ledger.
  - **Endorsement**: The endorsing peers sign the read-write set and send it back to the client, along with a response message.
  - **Ordering**: The client collects the endorsements and submits the transaction to the orderer, which validates the signatures and timestamps, and batches the transactions into blocks.
  - **Validation**: The orderer delivers the blocks to the peers, which validate the transactions against the endorsement policy and the current state of the ledger, and mark them as valid or invalid.
  - **Commitment**: The peers append the valid transactions to their copy of the ledger, and update the state accordingly. The invalid transactions are discarded, but still recorded on the ledger for audit purposes.
