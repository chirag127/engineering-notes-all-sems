### Requirements for the consensus protocols for the nodes of the Unit 2 - Consensus in the subject of Blockchain Architecture Design

- A consensus protocol is a set of rules that determines how a decentralized computer network reaches agreement on which transactions are valid and which are not .
- A consensus protocol prevents a single entity from controlling a blockchain or distorting the “truth” of what should be recorded. It also ensures that all nodes have a consistent view of the state of the network and the history of transactions.
- A consensus protocol should satisfy the following requirements  :
  - **Security**: The protocol should be able to resist attacks from malicious nodes or external adversaries who may try to compromise the integrity, availability, or validity of the network.
  - **Performance**: The protocol should be able to process transactions efficiently and quickly, without sacrificing security or decentralization.
  - **Scalability**: The protocol should be able to handle a large number of nodes and transactions, without degrading the performance or security of the network.
  - **Fairness**: The protocol should be able to reward the honest nodes for their participation and contribution to the network, and penalize the dishonest or malicious nodes for their misbehavior or inactivity.
  - **Incentive compatibility**: The protocol should be able to align the interests of the nodes with the goals of the network, and discourage any selfish or rational behavior that may harm the network.
  - **Robustness**: The protocol should be able to tolerate failures, errors, or disruptions in the network, and recover from them without losing consistency or consensus.
  - **Adaptability**: The protocol should be able to adjust to the changing conditions of the network, such as the number of nodes, the network latency, the transaction volume, or the security threats.
