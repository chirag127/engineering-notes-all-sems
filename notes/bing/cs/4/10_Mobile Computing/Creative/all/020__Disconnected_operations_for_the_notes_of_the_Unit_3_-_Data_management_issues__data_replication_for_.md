### Disconnected operations for the notes of the Unit 3 - Data management issues, data replication for mobile computers, adaptive clustering for mobile in the subject of Mobile Computing

- Disconnected operation is a mode of computing that allows mobile devices to access and execute applications even when they are temporarily disconnected from the network or when they choose to work offline .
- Disconnected operation is useful for mobile computing because it enables high availability, fault tolerance, and energy efficiency for mobile devices that may face network failures, bandwidth limitations, or power constraints  .
- Disconnected operation can be achieved by using various techniques, such as:
  - Data replication: This involves creating and maintaining multiple copies of data on different servers or devices, so that mobile devices can access the data locally or from nearby servers when they are disconnected  . Data replication can be classified into two types:
    - Eager replication: This ensures that all replicas are updated as soon as a change occurs in any replica, thus maintaining strong consistency. Eager replication requires reliable and fast network connections, and may incur high communication and synchronization overheads.
    - Lazy replication: This allows replicas to diverge temporarily, and updates them only when they reconnect to the network, thus allowing weak consistency. Lazy replication can tolerate network failures and delays, and can reduce communication and synchronization costs. However, it may also cause conflicts and inconsistencies among replicas that need to be resolved.
  - Mobile computation: This involves moving the computation from the server to the mobile device, or vice versa, depending on the network availability and the device capabilities. Mobile computation can be implemented using two approaches:
    - Code shipping: This involves sending the code from the server to the mobile device, or from the mobile device to the server, so that the computation can be performed locally or remotely. Code shipping can reduce network traffic and latency, and can adapt to the device resources and preferences. However, it may also raise security and compatibility issues, and may require additional code management and verification.
    - Result shipping: This involves sending the result of the computation from the server to the mobile device, or from the mobile device to the server, so that the computation can be performed remotely or locally. Result shipping can simplify the code management and verification, and can enhance the security and compatibility of the computation. However, it may also increase network traffic and latency, and may not adapt well to the device resources and preferences.
  - Adaptive clustering: This involves grouping mobile devices into clusters based on their proximity, connectivity, or similarity, so that they can share data and computation among themselves when they are disconnected from the network. Adaptive clustering can improve the data availability, load balancing, and fault tolerance for mobile devices. However, it may also incur high overheads for cluster formation and maintenance, and may cause data inconsistency and redundancy among clusters.

- Some mnemonics and learning tricks for disconnected operation are:
  - DR MAC: Data Replication, Mobile computation, Adaptive Clustering
  - Eager beaver, lazy river: Eager replication, lazy replication
  - Code or result, ship it fast: Code shipping, result shipping
  - Cluster together, share and care: Adaptive clustering
