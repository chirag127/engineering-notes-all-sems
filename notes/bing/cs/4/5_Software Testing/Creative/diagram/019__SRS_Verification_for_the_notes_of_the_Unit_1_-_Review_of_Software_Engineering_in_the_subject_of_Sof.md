SRS Verification is the process of checking whether the Software Requirement Specification (SRS) document is consistent, complete, correct, and unambiguous. It is done by the testing person or a group of persons by using any verification method (like peer reviews, walkthroughs, inspections, etc).

The following diagram illustrates the basic steps of SRS Verification:

```
+----------------+      +----------------+      +----------------+
|                |      |                |      |                |
|  SRS Document  +----->+  Verification  +----->+  Review Report |
|                |      |                |      |                |
+----------------+      +----------------+      +----------------+
```

The SRS Document is the input for the verification process. It contains the functional and non-functional requirements of the software system. It is a formal document that acts as a representation of the software that enables the users to review whether it is according to their requirements.

The Verification process is the activity of checking the SRS Document for any errors, inconsistencies, ambiguities, or incompleteness. It can be done by using various techniques, such as:

- Peer Reviews: A group of peers review the SRS Document and provide feedback and suggestions for improvement.
- Walkthroughs: A presenter walks through the SRS Document and explains the requirements to a group of reviewers, who ask questions and identify any issues or gaps.
- Inspections: A group of inspectors examine the SRS Document in detail and use a checklist to find any defects or violations of standards.

The Review Report is the output of the verification process. It contains the results of the verification, such as the number and types of defects found, the severity and priority of the defects, the recommendations for correction, and the approval or rejection of the SRS Document. It is used to improve the quality of the SRS Document and the software system.
