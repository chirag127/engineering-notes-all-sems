### Issues for the notes of the Unit 6 - Object Oriented Testing in the subject of Software Testing

- Object oriented testing (OOT) is a testing approach that is based on the concepts of object oriented programming, such as encapsulation, inheritance, and polymorphism.
- OOT faces some challenges and issues that are different from those of traditional testing methods, such as:
  - How to test a base class and its subclasses that inherit its methods and attributes?
  - How to test the dynamic binding of methods that are overridden or overloaded in subclasses?
  - How to test the interactions and collaborations among objects that communicate through messages?
  - How to test the reusability and modifiability of objects that are designed to be reused in different contexts?
  - How to test the complexity and scalability of object oriented systems that may have many classes and objects?
- Some of the possible solutions or techniques to address these issues are:
  - Using the Unified Modeling Language (UML) to model the structure and behavior of the object oriented system and to derive test cases from the diagrams.
  - Applying the principles of class testing, such as testing the constructors, destructors, accessors, mutators, and other methods of each class, and testing the class invariants and contracts.
  - Applying the principles of integration testing, such as testing the interfaces and collaborations among classes and objects, and testing the scenarios and use cases of the system.
  - Applying the principles of system testing, such as testing the functional and non-functional requirements of the system, and testing the performance, reliability, security, and usability of the system.
  - Applying the principles of regression testing, such as retesting the modified or affected parts of the system after a change, and using test automation tools to support the testing process.
