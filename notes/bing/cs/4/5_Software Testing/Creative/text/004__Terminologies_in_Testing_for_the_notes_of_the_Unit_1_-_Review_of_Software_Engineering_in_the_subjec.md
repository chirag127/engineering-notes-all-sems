### Terminologies in Testing

Software testing is the process of verifying and validating that a software product meets the requirements and expectations of the stakeholders. Software testing involves various terms and concepts that are essential to understand and apply in practice. Here are some of the common terminologies in software testing:

- **SDLC (Software Development Life Cycle)**: It is an international standard for software life-cycle processes that defines all the tasks required for developing and maintaining software. It consists of several phases, such as planning, analysis, design, implementation, testing, deployment, and maintenance .
- **Test Level**: It is a specific instantiation of a test process that corresponds to a particular stage of the SDLC. There are four main test levels: unit testing, integration testing, system testing, and acceptance testing .
- **Test Type**: It is a group of test activities that aim to evaluate a specific quality attribute of the software, such as functionality, performance, usability, security, etc. There are many test types, such as functional testing, non-functional testing, regression testing, load testing, etc .
- **Test Design Technique**: It is a method or procedure for deriving and selecting test cases based on the test objectives, test basis, and test criteria. There are three main categories of test design techniques: specification-based, structure-based, and experience-based .
- **STLC (Software Test Life Cycle)**: It is a subset of the SDLC that focuses on the testing activities and deliverables. It consists of several phases, such as test planning, test analysis, test design, test implementation, test execution, test evaluation, and test closure .
- **Informal Testing**: It is a type of testing that does not follow any formal process, documentation, or standards. It is usually performed by the developers or testers during the development or testing phases to check the basic functionality or quality of the software. Examples of informal testing are ad hoc testing, exploratory testing, etc .
- **Test Planning**: It is the first phase of the STLC that involves defining the test objectives, scope, strategy, approach, resources, schedule, risks, and deliverables for the testing project. It results in the creation of a test plan document that guides the testing activities and provides a basis for monitoring and controlling the testing process .
- **Test Documentation**: It is the set of documents that describe the test basis, test design, test cases, test procedures, test data, test results, test reports, and other information related to the testing project. Test documentation helps to ensure the quality, consistency, traceability, and reusability of the testing process and products .
- **Test Case**: It is a set of input values, preconditions, expected results, and postconditions that define a single test scenario to be executed on the software under test. A test case specifies what to test, how to test, and what to expect from the test .
- **Test Suite**: It is a collection of test cases that are related by some criteria, such as test type, test level, test objective, etc. A test suite helps to organize, manage, and execute the test cases in a logical and efficient way .
- **Test Data**: It is the data that is used as input for the test cases or to verify the expected results of the test cases. Test data can be generated, collected, or modified from various sources, such as databases, files, user inputs, etc. Test data should be valid, realistic, and sufficient to cover the test scenarios .
- **Test Environment**: It is the combination of hardware, software, network, and other resources that are required to execute the test cases on the software under test. The test environment should be configured and maintained to ensure the reliability, repeatability, and accuracy of the test results .
- **Test Execution**: It is the phase of the STLC that involves running the test cases on the software under test and recording the test results. Test execution can be performed manually or automatically using test tools. Test execution should follow the test plan and the test procedures .
