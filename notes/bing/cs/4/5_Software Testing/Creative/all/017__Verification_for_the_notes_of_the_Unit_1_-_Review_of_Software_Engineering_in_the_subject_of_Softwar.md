### Verification for the notes of the Unit 1 - Review of Software Engineering in the subject of Software Testing

- Verification is the process of checking or verifying the credentials, data or information to confirm their credibility and accuracy.
- In the field of software engineering, verification is the process of evaluating software product, to ensure that the development phase is being carried out accurately, to build the desired software product.
- Verification is the process of checking that a software achieves its goal without any bugs. It verifies whether the developed product fulfills the requirements that we have.
- Verification is a static testing technique, which means it does not involve executing the code. It can be done by inspections, reviews, walkthroughs, or audits.
- Verification answers the question: "Are we building the product right?". It ensures that the software conforms to its specifications and design.
- Verification can be done at any stage of the software development life cycle, but it is usually done before validation.
- Verification can help to detect errors, defects, inconsistencies, or deviations from standards in the software product. It can also improve the quality, reliability, and performance of the software product.
- Verification can be done by the developers, testers, or quality assurance team, depending on the type and level of verification.
- Verification can be done by using various methods, tools, or techniques, such as formal methods, static analysis, code reviews, checklists, standards, or metrics.
- Verification can be classified into two types: dynamic verification and static verification.
  - Dynamic verification, also known as experimentation, dynamic testing, or simply testing, is the process of verifying the software product by executing it with various inputs and observing its outputs. It is good for finding errors, bugs, or failures in the software product.
  - Static verification, also known as analysis or static testing, is the process of verifying the software product by examining its code, design, documentation, or specifications without executing it. It is useful for proving the correctness of a software product or finding potential errors, bugs, or vulnerabilities in the software product.

- A possible mnemonic to remember the difference between verification and validation is: "Verification is the process of checking the work products, while validation is the process of checking the software product." Another possible mnemonic is: "Verification is building the product right, while validation is building the right product."
