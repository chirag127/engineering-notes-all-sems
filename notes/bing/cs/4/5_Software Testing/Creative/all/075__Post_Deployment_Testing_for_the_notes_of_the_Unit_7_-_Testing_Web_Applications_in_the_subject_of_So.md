### Post Deployment Testing for the notes of the Unit 7 - Testing Web Applications in the subject of Software Testing

- Post deployment testing is a type of testing in which the software is tested after it is being deployed to production.
- The purpose of post deployment testing is to ensure that the software functions as intended in the real environment and meets the user expectations and requirements.
- Post deployment testing involves the following activities  :
  - Post-deployment verification: The QA or Test lead verifies the software application as per the test plan and test cases and compares them with the previous or existing ones.
  - User acceptance testing: The end users or stakeholders test the software application and provide feedback on its usability, functionality, performance, and quality.
  - Regression testing: The software application is tested for any defects or issues that might have been introduced during the deployment process or due to changes in the environment or configuration.
  - Performance testing: The software application is tested for its speed, scalability, reliability, and resource consumption under different load and stress conditions.
  - Security testing: The software application is tested for its vulnerability to various types of attacks and threats and its compliance with security standards and policies.
  - Monitoring: The software application is monitored for its availability, performance, errors, and usage using various tools and metrics.
  - Maintenance: The software application is updated, patched, or fixed as per the user feedback, bug reports, or change requests.
- Post deployment testing can be done manually or using automation tools, depending on the complexity, scope, and frequency of the testing .
- Post deployment testing can be done using different strategies, such as rolling update, blue-green, canary, or feature flag, depending on the risk, impact, and cost of the deployment.
- Post deployment testing can be done using different methods, such as smoke testing, sanity testing, exploratory testing, or heuristic testing, depending on the time, resources, and objectives of the testing.
- Post deployment testing can be done using different techniques, such as checklist, scenario, use case, or user story, depending on the level, type, and coverage of the testing.
- Post deployment testing can be done using different levels of testing, such as unit, integration, system, or acceptance, depending on the granularity, scope, and purpose of the testing.
- Post deployment testing can be done using different types of testing, such as functional, non-functional, or structural, depending on the aspect, attribute, or component of the software application that is being tested.

- A possible mnemonic to remember the post deployment testing activities is **VURPSMM** (Verification, User acceptance, Regression, Performance, Security, Monitoring, Maintenance).
- A possible learning trick to remember the post deployment testing strategies is to associate them with colors or animals, such as **rolling update** (red, rolling stone), **blue-green** (blue, green), **canary** (yellow, bird), **feature flag** (white, flag).
- A possible learning trick to remember the post deployment testing methods is to associate them with shapes or objects, such as **smoke testing** (circle, smoke), **sanity testing** (square, sanity), **exploratory testing** (star, exploration), **heuristic testing** (triangle, heuristic).
