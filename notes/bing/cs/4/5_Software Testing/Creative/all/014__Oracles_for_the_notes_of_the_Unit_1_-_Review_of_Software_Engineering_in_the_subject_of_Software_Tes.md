### Oracles for the notes of the Unit 1 - Review of Software Engineering in the subject of Software Testing

- An oracle is a mechanism for determining whether a test has passed or failed.
- An oracle compares the output of the system under test, for a given test-case input, to the expected output.
- An oracle can be based on specifications, documentation, models, heuristics, or human judgment  .
- An oracle can be classified into four types:
  - Specified oracles: based on formal or informal specifications of the system behavior, such as requirements, design documents, or user manuals.
  - Derived oracles: based on some transformation or derivation of the system output, such as equivalence partitioning, boundary value analysis, or metamorphic testing.
  - Inferred oracles: based on some inference or learning from the system behavior, such as machine learning, data mining, or statistical analysis.
  - Consensual oracles: based on some consensus or agreement among different sources of information, such as experts, users, or peers.
- An oracle can be complete or partial, depending on whether it can determine the correctness of the system output for all or some test cases.
- An oracle can be explicit or implicit, depending on whether it is a separate entity or embedded in the system under test.
- An oracle can be static or dynamic, depending on whether it is fixed or adaptable to the system context.
- An oracle can be automated or manual, depending on whether it can be executed by a machine or a human.
- An oracle can have different levels of accuracy, reliability, and efficiency, depending on the quality of its design and implementation.
- An oracle can have different challenges and limitations, such as the oracle problem, the oracle cost, the oracle uncertainty, and the oracle inconsistency.
