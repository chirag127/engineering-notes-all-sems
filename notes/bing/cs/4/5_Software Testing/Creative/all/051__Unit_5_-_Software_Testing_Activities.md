## Unit 5 - Software Testing Activities

Software testing is the process of verifying and validating that a software product meets the specified requirements and expectations of the stakeholders. Software testing activities are the tasks and procedures that are performed during the software testing process. Software testing activities can be classified into four main levels: unit testing, integration testing, system testing and acceptance testing. Each level has a different purpose and scope, and requires different techniques and tools.

- **Unit testing**: Unit testing is the process of testing individual components or units of software to ensure that they function correctly and independently. A unit is the smallest testable part of a software system, such as a function, a class, a module or a method. Unit testing is usually done by the developers using testing frameworks such as PHPUnit, Mocha, RSpec, etc. Unit testing helps to find and fix defects at an early stage, improve the quality and maintainability of the code, and facilitate refactoring and integration.

- **Integration testing**: Integration testing is the process of testing the interactions and interfaces between two or more units or components of software to ensure that they work together as expected. Integration testing can be done at different levels, such as component integration testing, subsystem integration testing, system integration testing, etc. Integration testing is usually done by the testers using tools such as Postman, SoapUI, Selenium, etc. Integration testing helps to find and fix defects in the interfaces and dependencies, verify the functionality and performance of the integrated system, and ensure the compatibility and interoperability of the components.

- **System testing**: System testing is the process of testing the whole software system as a single entity to ensure that it meets the functional and non-functional requirements and specifications. System testing can be done using different types of tests, such as functional testing, performance testing, security testing, usability testing, reliability testing, etc. System testing is usually done by the testers using tools such as JMeter, LoadRunner, Burp Suite, etc. System testing helps to find and fix defects in the system as a whole, verify the quality and functionality of the system, and ensure the compliance and satisfaction of the stakeholders.

- **Acceptance testing**: Acceptance testing is the process of testing the software system by the end-users or customers to ensure that it meets their needs and expectations. Acceptance testing can be done using different types of tests, such as user acceptance testing, alpha testing, beta testing, etc. Acceptance testing is usually done by the end-users or customers using the actual or simulated environment of the system. Acceptance testing helps to find and fix defects from the user's perspective, verify the usability and suitability of the system, and ensure the acceptance and satisfaction of the end-users or customers.

Some mnemonics and learning tricks for the unit 5 - software testing activities are:

- To remember the four levels of testing, you can use the acronym **UIAS** (Unit, Integration, System, Acceptance).
- To remember the order of testing, you can use the phrase **"Unit tests integrate systems and accept results"**.
- To remember the purpose of each level of testing, you can use the following table:

| Level | Purpose |
| --- | --- |
| Unit | **U**nderstand and verify the functionality of each unit |
| Integration | **I**nteract and verify the interfaces between units |
| System | **S**atisfy and verify the requirements and specifications of the system |
| Acceptance | **A**pprove and verify the needs and expectations of the end-users or customers |
