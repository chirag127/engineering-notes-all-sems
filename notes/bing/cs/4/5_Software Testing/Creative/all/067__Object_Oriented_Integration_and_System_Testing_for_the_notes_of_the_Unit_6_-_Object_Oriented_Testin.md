### Object Oriented Integration and System Testing for the notes of the Unit 6 - Object Oriented Testing in the subject of Software Testing

- Object Oriented Integration and System Testing are two levels of testing that are performed on object oriented software systems.
- Object Oriented Integration Testing is the process of testing the interactions and dependencies between the classes and objects that form the software system. It ensures that the methods and attributes of the classes and objects work correctly when they are invoked or accessed by other classes and objects.
- Object Oriented System Testing is the process of testing the functionality and performance of the whole software system as a single entity. It ensures that the software system meets the requirements and specifications of the user and the client.
- Object Oriented Integration and System Testing differ from conventional integration and system testing in several ways, such as:
  - Object Oriented Integration Testing focuses on the communication and collaboration between the objects, rather than the data flow and control flow between the modules.
  - Object Oriented System Testing requires more attention to the user interface, the graphical components, and the dynamic behavior of the software system, rather than the input and output data and the static structure of the software system.
  - Object Oriented Integration and System Testing need to consider the features and challenges of object oriented paradigms, such as encapsulation, inheritance, polymorphism, abstraction, etc.
- Object Oriented Integration and System Testing can be performed using various strategies and techniques, such as:
  - Thread-based testing: This strategy involves testing the sequences of interactions between the objects that form a thread of execution or a use case scenario. It helps to verify the functional requirements and the logical flow of the software system.
  - Use-case-based testing: This strategy involves testing the software system from the perspective of the user or the actor. It helps to verify the user requirements and the usability of the software system.
  - Cluster testing: This strategy involves testing the groups or clusters of classes and objects that have high cohesion and low coupling. It helps to reduce the complexity and the number of test cases for the software system.
  - Sandwich testing: This strategy involves testing the software system using a combination of top-down and bottom-up approaches. It helps to balance the advantages and disadvantages of both approaches and to achieve better coverage and efficiency of the software system.
- A possible mnemonic to remember the four strategies of Object Oriented Integration and System Testing is: **TUCS** (Thread, Use-case, Cluster, Sandwich).
- A possible learning trick to understand the difference between Object Oriented Integration and System Testing is to use an analogy of a car. Object Oriented Integration Testing is like testing the parts of the car, such as the engine, the wheels, the brakes, etc., and how they work together. Object Oriented System Testing is like testing the whole car, such as the speed, the mileage, the comfort, etc., and how it meets the expectations of the driver and the passengers.
