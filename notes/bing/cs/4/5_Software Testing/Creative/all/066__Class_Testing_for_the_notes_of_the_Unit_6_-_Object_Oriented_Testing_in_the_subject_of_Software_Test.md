### Class Testing for the notes of the Unit 6 - Object Oriented Testing in the subject of Software Testing

- Class testing is the process of verifying that the implementation of a class conforms to its specification. 
- Class testing is similar to unit testing in traditional testing, but it also involves some aspects of integration testing, since each object defines a scope of interaction among methods and attributes. 
- Class testing can be done at two levels: intra-class testing and inter-class testing. 
- Intra-class testing focuses on testing the methods and attributes of a single class, while inter-class testing focuses on testing the interactions and collaborations among different classes. 
- Some techniques for class testing are:

  - Fault-based testing: This technique involves designing test cases based on the possible faults or errors in the class implementation, such as incorrect initialization, boundary violations, memory leaks, etc. 
  - Method testing: This technique involves testing each method of the class individually, using various input values, preconditions, and postconditions. 
  - State-based testing: This technique involves testing the state behavior of the class, such as how the class changes its state in response to different events, methods, and attributes. 
  - Scenario-based testing: This technique involves testing the class in the context of a realistic scenario or use case, such as how the class interacts with other classes and objects in the system. 

- Some advantages of class testing are:

  - It helps to ensure the correctness and reliability of the class implementation. 
  - It helps to detect and isolate faults at an early stage of development. 
  - It helps to improve the maintainability and reusability of the class. 

- Some disadvantages of class testing are:

  - It can be time-consuming and complex, especially for large and complex classes. 
  - It can be difficult to design effective test cases that cover all the possible scenarios and states of the class. 
  - It can be challenging to test the class in isolation, without considering the dependencies and interactions with other classes and objects. 

- A possible mnemonic to remember the techniques of class testing is: **FMS** (Fault-based, Method, State-based) or **FMS-S** (Fault-based, Method, State-based, Scenario-based). 
- A possible learning trick to understand the concept of class testing is to think of a class as a black box that has inputs (methods and attributes) and outputs (results and behaviors). The goal of class testing is to check if the black box works as expected, by providing different inputs and observing the outputs.
