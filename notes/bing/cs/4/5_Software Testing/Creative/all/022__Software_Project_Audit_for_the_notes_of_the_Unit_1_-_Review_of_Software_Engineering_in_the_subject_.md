### Software Project Audit for the notes of the Unit 1 - Review of Software Engineering in the subject of Software Testing

- A software project audit is a formal review of a software project to check its quality, progress or adherence to plans, standards and regulations.
- A software project audit can be conducted by internal or external auditors who are not members of the software development organization.
- A software project audit can have various objectives, such as :
  - Assessing the compliance of the software product, process or set of processes with specifications, standards, contractual agreements or other criteria.
  - Identifying the potential risks and weaknesses of the software project and recommending corrective actions or improvements.
  - Evaluating the performance and productivity of the software development team and the IT department.
  - Verifying the accuracy and completeness of the project documentation and deliverables.
  - Ensuring the quality and reliability of the software product and its alignment with the user requirements and expectations.
  - Measuring the effectiveness and efficiency of the software development process and its alignment with the project management methodology and best practices.
- A software project audit can be performed at different stages of the software development life cycle, such as :
  - Before the start of the project, to review the project plan, scope, budget, schedule, resources, risks, assumptions and constraints.
  - During the project execution, to monitor the project progress, performance, issues, changes, quality and deliverables.
  - After the project completion, to evaluate the project outcomes, benefits, lessons learned, customer satisfaction and feedback.
- A software project audit can follow different approaches, such as :
  - Process-based audit, which focuses on the software development process and its compliance with the standards and regulations.
  - Product-based audit, which focuses on the software product and its compliance with the specifications and requirements.
  - Risk-based audit, which focuses on the potential risks and vulnerabilities of the software project and its mitigation strategies.
  - Performance-based audit, which focuses on the performance and productivity of the software development team and the IT department.
- A software project audit can use different techniques, such as :
  - Interviews, which involve asking questions to the project stakeholders, such as the project manager, the software developers, the testers, the customers, the users, etc.
  - Questionnaires, which involve sending surveys or forms to the project stakeholders to collect their opinions, feedback, ratings, etc.
  - Observations, which involve watching the project activities, processes, interactions, behaviors, etc.
  - Document reviews, which involve examining the project documentation, such as the project plan, the requirements, the design, the code, the test cases, the reports, etc.
  - Data analysis, which involve analyzing the project data, such as the metrics, the indicators, the logs, the records, etc.
- A software project audit can produce different outputs, such as :
  - Audit report, which summarizes the audit findings, conclusions, recommendations and action plans.
  - Audit checklist, which lists the audit criteria, questions, evidence and results.
  - Audit scorecard, which measures the audit performance, quality and compliance using a scoring system.
  - Audit feedback, which provides the audit feedback, comments, suggestions and improvement areas to the project stakeholders.
