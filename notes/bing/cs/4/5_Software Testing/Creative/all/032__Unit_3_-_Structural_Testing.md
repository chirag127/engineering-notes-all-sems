## Unit 3 - Structural Testing

Structural testing is a type of software testing that focuses on the internal structure, design, and implementation of the software. It is also known as white-box testing, glass-box testing, or logic-driven testing. The main objective of structural testing is to verify that the software conforms to its specified design and that all the possible paths and conditions in the code are executed and tested.

Some of the topics covered in this unit are:

- **Code coverage**: Code coverage is a measure of how much of the source code is executed during testing. It can be expressed as a percentage or a ratio of the number of covered statements, branches, paths, or conditions to the total number of possible statements, branches, paths, or conditions in the code. Code coverage helps to identify the untested or dead code and to assess the quality and completeness of the test cases.

- **Control flow testing**: Control flow testing is a technique of structural testing that analyzes the sequence of events or actions that occur in the software. It uses a graphical representation of the software, such as a flowchart, a control flow graph, or a program dependency graph, to identify the possible paths that can be followed during execution. Control flow testing aims to cover all the paths or a subset of them, such as statement coverage, branch coverage, or path coverage.

- **Data flow testing**: Data flow testing is a technique of structural testing that analyzes the movement and usage of data in the software. It uses a graphical representation of the software, such as a data flow graph or a program dependency graph, to identify the possible data flows that can occur during execution. Data flow testing aims to cover all the data flows or a subset of them, such as definition-use coverage, all-uses coverage, or all-du-paths coverage.

- **Mutation testing**: Mutation testing is a technique of structural testing that evaluates the effectiveness of the test cases by introducing small changes or faults in the software and checking if the test cases can detect them. The changes or faults are called mutants and they are generated by applying mutation operators, such as replacing an operator, changing a variable, or deleting a statement. Mutation testing aims to measure the mutation score, which is the ratio of the number of killed mutants (detected by the test cases) to the total number of mutants.

Some of the advantages of structural testing are:

- It can detect errors that are not visible at the functional level, such as memory leaks, buffer overflows, or logic errors.
- It can improve the maintainability, readability, and modularity of the code by enforcing coding standards and conventions.
- It can increase the confidence and reliability of the software by ensuring that all the possible scenarios and edge cases are tested.

Some of the disadvantages of structural testing are:

- It can be time-consuming and complex to perform, especially for large and dynamic software systems.
- It can be difficult to achieve high levels of code coverage, especially for path coverage or data flow coverage, due to the combinatorial explosion of the possible paths or data flows.
- It can be dependent on the implementation details of the software, which may change frequently and require frequent updates of the test cases.

Some of the mnemonics and learning tricks for structural testing are:

- **COCO**: A mnemonic to remember the four types of code coverage: statement coverage, branch coverage, path coverage, and condition coverage.
- **FUBAR**: A mnemonic to remember the four types of mutation operators: flip (change an operator), use (change a variable), break (delete a statement), and add (insert a statement).
- **DUDE**: A mnemonic to remember the three types of data flow coverage: definition-use coverage, all-uses coverage, and all-du-paths coverage.
