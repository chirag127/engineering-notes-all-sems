### Scheme for the notes of the Unit 4 - Regression Testing in the subject of Software Testing

- **Definition**: Regression testing is a type of software testing technique that re-runs functional and non-functional tests to ensure that a software application works as intended after any code changes, updates, revisions, improvements, or optimizations .
- **Purpose**: The purpose of regression testing is to verify that the software quality and functionality are not degraded or broken due to the code changes, and to detect any new defects or bugs that may have been introduced .
- **Types**: There are different types of regression testing, such as:
  - **Unit regression testing**: This type of testing focuses on the individual units or components of the software, such as classes, methods, or functions. It is usually performed by the developers using tools like JUnit, NUnit, or TestNG .
  - **Integration regression testing**: This type of testing verifies the interaction and communication between the units or components of the software, such as modules, subsystems, or services. It is usually performed by the testers using tools like SoapUI, Postman, or RestAssured .
  - **System regression testing**: This type of testing validates the entire software system as a whole, including its functionality, performance, security, usability, and compatibility. It is usually performed by the testers using tools like Selenium, Ranorex, or Katalon  .
  - **Sanity regression testing**: This type of testing is a subset of system regression testing that checks the basic functionality and stability of the software after a minor code change or bug fix. It is usually performed by the testers using tools like Selenium, Ranorex, or Katalon  .
  - **Smoke regression testing**: This type of testing is another subset of system regression testing that checks the critical functionality and performance of the software after a major code change or feature addition. It is usually performed by the testers using tools like Selenium, Ranorex, or Katalon  .
- **Techniques**: There are different techniques for selecting and executing the test cases for regression testing, such as:
  - **Retest all**: This technique involves re-running all the existing test cases for the software, regardless of the scope and impact of the code changes. It is the most comprehensive but also the most time-consuming and resource-intensive technique .
  - **Regression test selection**: This technique involves selecting and re-running only the test cases that are relevant and affected by the code changes, based on some criteria or algorithm. It is more efficient and effective than retest all, but also more complex and challenging to implement .
  - **Test case prioritization**: This technique involves ranking and re-running the test cases based on their importance and urgency, such as their coverage, severity, frequency, or risk. It is useful for optimizing the regression testing process and maximizing the test results .
  - **Test case minimization**: This technique involves reducing and re-running the test cases that are redundant, obsolete, or irrelevant, based on some criteria or algorithm. It is helpful for eliminating the unnecessary and duplicated test cases and improving the test efficiency .
- **Tools**: There are different tools that can support and automate the regression testing process, such as:
  - **Selenium**: Selenium is a popular testing tool that provides testing application features. Developers can use the Selenium WebDriver to create and execute automated test scripts for web applications using various programming languages, such as Java, Python, C#, or Ruby .
  - **Ranorex Studio**: Ranorex Studio automates tests for mobile, desktop, and web apps. It is used by testers and developers to create and execute automated test scripts using a graphical user interface, a code editor, or a combination of both .
  - **Katalon Studio**: Katalon Studio is a comprehensive testing tool that supports various types of testing, including web, mobile, API, and desktop testing.
