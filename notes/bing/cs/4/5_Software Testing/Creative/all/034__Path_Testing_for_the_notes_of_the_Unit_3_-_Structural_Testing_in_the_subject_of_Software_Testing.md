### Path Testing for the notes of the Unit 3 - Structural Testing in the subject of Software Testing

- Path testing is a white-box testing technique that aims to cover all the possible paths of execution in a program or a module.
- Path testing is based on the control flow graph of the program, which represents the code as a set of nodes and edges, where nodes are statements or blocks of code and edges are transitions or branches between them.
- Path testing uses cyclomatic complexity, a metric that measures the number of linearly independent paths in a program, to determine the minimum number of test cases required to cover all the paths.
- Path testing can be performed at different levels of granularity, such as statement level, decision level, or loop level, depending on the complexity and size of the program.
- Path testing can help in detecting errors in the logic, control flow, and data flow of the program, as well as improving the code quality and maintainability.

Some of the path testing techniques are:

- **Basis path testing**: This technique involves finding a basis set of paths, which are linearly independent and can generate all other paths in the program by combining them. A basis set can be obtained by applying the following steps:
  - Draw a control flow graph of the program.
  - Calculate the cyclomatic complexity of the graph using one of the following formulas:
    - V(G) = E - N + 2, where E is the number of edges and N is the number of nodes in the graph.
    - V(G) = P + 1, where P is the number of predicate nodes (nodes with two or more outgoing edges) in the graph.
    - V(G) = R, where R is the number of regions in the graph.
  - Identify the independent paths in the graph by using a spanning tree and adding one edge at a time that is not in the tree. The number of independent paths should be equal to the cyclomatic complexity.
  - Generate test cases to exercise each independent path in the basis set.

- **Decision to decision path testing**: This technique involves breaking the control flow graph into various decision to decision paths, which are paths that start and end at a predicate node. A decision to decision path can be further divided into subpaths, which are paths that start and end at a simple node (a node with one incoming and one outgoing edge). The test cases are generated by covering all the decision to decision paths and their subpaths.

- **Loop testing**: This technique involves testing the loops in the program, such as while, for, do-while, etc. The test cases are generated by considering the following aspects of the loops:
  - The number of iterations of the loop (zero, one, many, etc.).
  - The initialization and termination conditions of the loop.
  - The data values and variables used in the loop.
  - The nesting and concatenation of the loops.

Some of the advantages of path testing are:

- It can achieve high coverage of the code and detect errors that are not visible at the interface level.
- It can improve the reliability and performance of the program by eliminating redundant or unreachable paths.
- It can help in debugging and tracing the execution of the program.

Some of the disadvantages of path testing are:

- It can be time-consuming and complex to perform, especially for large and complex programs with many paths and branches.
- It can be difficult to generate test cases that cover all the paths, especially if some of the paths are infeasible or rarely executed.
- It can be difficult to verify the correctness of the test cases and the test results.
