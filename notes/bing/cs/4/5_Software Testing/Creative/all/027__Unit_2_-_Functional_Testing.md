## Unit 2 - Functional Testing

- Functional testing is a type of software testing that verifies that the software system performs and functions correctly according to the design specifications.
- Functional testing covers the following aspects of a software system:
  - Basic functionality: the system executes all the functions and commands as expected.
  - Usability: the system is user-friendly and easy to operate and understand.
  - Accessibility: the system is accessible to all types of users, including those with disabilities.
  - Compatibility: the system works well with other systems, platforms, devices, browsers, etc.
  - Error handling: the system handles errors and exceptions gracefully and provides appropriate messages and actions.
  - Security: the system protects the data and resources from unauthorized access and malicious attacks.
- Functional testing can be performed at different levels of software development, such as unit testing, integration testing, system testing, and acceptance testing.
- Functional testing can be done manually or with the help of automated tools and frameworks.
- Functional testing can be done in two ways: black-box testing and white-box testing.
  - Black-box testing: the tester does not have access to the internal structure or code of the system and only tests the functionality based on the input and output.
  - White-box testing: the tester has access to the internal structure or code of the system and tests the functionality based on the logic and flow of the code.
- Functional testing can be done using various techniques, such as equivalence partitioning, boundary value analysis, decision table testing, state transition testing, use case testing, etc.
- Functional testing can be done using various types of test cases, such as positive test cases, negative test cases, edge test cases, etc.
- Functional testing can be done using various types of test data, such as valid data, invalid data, boundary data, etc.
- Functional testing can be done using various types of test design, such as test scenarios, test scripts, test cases, test steps, etc.
- Functional testing can be done using various types of test documentation, such as test plan, test strategy, test report, test summary, etc.
- Functional testing can be done using various types of test metrics, such as test coverage, defect density, defect severity, defect priority, etc.
- Functional testing can be done using various types of test tools, such as test management tools, test automation tools, test data generation tools, test reporting tools, etc.

Some mnemonics and learning tricks for functional testing are:

- To remember the aspects of functional testing, use the acronym **BUCES** (Basic functionality, Usability, Compatibility, Error handling, Security).
- To remember the levels of functional testing, use the acronym **UIAS** (Unit testing, Integration testing, System testing, Acceptance testing).
- To remember the ways of functional testing, use the acronym **BW** (Black-box testing, White-box testing).
- To remember the techniques of functional testing, use the acronym **EBDUS** (Equivalence partitioning, Boundary value analysis, Decision table testing, State transition testing, Use case testing).
- To remember the types of test cases, use the acronym **PNE** (Positive test cases, Negative test cases, Edge test cases).
- To remember the types of test data, use the acronym **VIB** (Valid data, Invalid data, Boundary data).
- To remember the types of test design, use the acronym **SCTS** (Test scenarios, Test scripts, Test cases, Test steps).
- To remember the types of test documentation, use the acronym **PSTRS** (Test plan, Test strategy, Test report, Test summary).
- To remember the types of test metrics, use the acronym **CDDSP** (Test coverage, Defect density, Defect severity, Defect priority).
- To remember the types of test tools, use the acronym **MAGRT** (Test management tools, Test automation tools, Test data generation tools, Test reporting tools).
