### Composite Applications for the notes of the Unit 3 - Service-Oriented Applications in the subject of Service Oriented Architecture

- A composite application is an application that consists of functionality drawn from several different sources, such as other applications, systems, modules, or web services.
- A composite application can leverage existing assets and create new business models by integrating and orchestrating different services across different constituents.
- A composite application requires a service-oriented architecture (SOA) in order to become a reality. A SOA is a modular architectural framework that enables software components to interact seamlessly.
- A SOA is based on the principles of loose coupling, abstraction, reusability, composability, and interoperability of services.
- A service is a self-contained unit of functionality that can be accessed and executed by a client or another service through a well-defined interface.
- A service interface defines the contract between the service and its consumers, specifying the inputs, outputs, and behaviors of the service.
- A service can be implemented using any technology or platform, as long as it conforms to the service interface and adheres to the service contract.
- A service can be exposed and accessed using various protocols and standards, such as web services, REST, SOAP, WSDL, etc.
- A service can be composed of other services, forming a service composition or a composite service. A service composition can be achieved using various techniques, such as orchestration, choreography, mediation, etc.
- A service orchestration is a centralized approach to service composition, where a single entity (such as a business process engine) controls the flow and logic of the service interactions.
- A service choreography is a decentralized approach to service composition, where each service collaborates with other services based on predefined rules and agreements, without a central coordinator.
- A service mediation is a technique to facilitate service composition by providing common functions, such as routing, transformation, validation, security, etc., between different services.
- A service component is a reusable unit of implementation that provides one or more services. A service component can be deployed and managed independently, and can be configured and composed dynamically.
- A service component architecture (SCA) is a set of specifications that describe a programming model for building applications and systems using a SOA .
- SCA extends and complements previous approaches to implementing services and builds on open standards such as web services .
- SCA defines a component model that supports the development, assembly, deployment, and management of service components.
- SCA defines a set of annotations and XML-based descriptors that can be used to specify the properties, references, and interfaces of service components, as well as the bindings, policies, and wires that connect them.
- SCA supports various implementation types, such as Java, BPEL, C++, etc., and various binding types, such as web services, JMS, RMI, etc., for service components.
- SCA provides a uniform and consistent way to access and invoke services, regardless of their implementation and binding types.
- SCA enables the separation of concerns between the business logic and the non-functional aspects of service components, such as security, transactions, reliability, etc.
- SCA allows the developers to focus on the business logic of service components, while the deployers and administrators can configure and apply the non-functional aspects using policies and bindings.
- SCA supports the dynamic discovery and invocation of services, as well as the dynamic configuration and composition of service components, using a service registry and a domain manager.
- SCA enables the development of composite applications that can span multiple technologies, platforms, and domains, and can be easily adapted to changing business requirements.

Some possible mnemonics and learning tricks for the topic are:

- SOA: Service-Oriented Architecture
  - S: Software components interact Seamlessly
  - O: Orchestration and composition of services
  - A: Abstraction and loose coupling of services
- SCA: Service Component Architecture
  - S: Service components are reusable and configurable
  - C: Component model supports various implementation and binding types
  - A: Annotations and descriptors specify the properties and connections of components
- Service composition techniques: Orchestration, Choreography, Mediation
  - O: One entity controls the flow and logic
  - C: Collaboration between services based on rules and agreements
  - M: Mediation between services by providing common functions
