### Review and Management of User Needs in Requirement Engineering Process in SRS

- Requirement engineering (RE) is the process of eliciting, analyzing, specifying, validating, and managing the requirements of a software system.
- User needs are the expectations, preferences, goals, and problems of the intended users of the software system.
- Review and management of user needs are important activities in RE to ensure that the software system meets the user needs and satisfies the user requirements.
- Review of user needs involves checking the completeness, consistency, correctness, clarity, and feasibility of the user needs, as well as resolving any conflicts or ambiguities among them.
- Management of user needs involves prioritizing, tracing, and controlling the changes of the user needs throughout the RE process and the software development life cycle.
- Some of the techniques and tools for review and management of user needs are:
  - Interviews, surveys, questionnaires, observations, and focus groups for eliciting and validating user needs.
  - Use cases, scenarios, user stories, and personas for specifying and analyzing user needs.
  - Prototypes, mockups, and wireframes for demonstrating and verifying user needs.
  - Requirement specification documents, such as software requirement specification (SRS), for documenting and communicating user needs.
  - Requirement traceability matrix (RTM), for linking user needs to user requirements, design specifications, test cases, and code modules.
  - Requirement management software, such as Jira, Trello, or Rational DOORS, for organizing, tracking, and updating user needs and their status.
