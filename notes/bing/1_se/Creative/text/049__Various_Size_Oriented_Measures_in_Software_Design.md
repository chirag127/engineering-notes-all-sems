#### Various Size Oriented Measures in Software Design

- Size oriented measures are based on the assumption that the size of the software product is an indicator of its complexity, effort, and quality.
- Size oriented measures can be classified into two categories: direct measures and indirect measures.
- Direct measures are based on the physical attributes of the software product, such as lines of code, number of statements, number of modules, etc.
- Indirect measures are based on the logical attributes of the software product, such as functionality, requirements, design, etc.
- Some examples of direct measures are:
  - Source Lines of Code (SLOC): the number of lines of code in the source program, excluding comments and blank lines.
  - Statement Count: the number of executable statements in the source program, excluding declarations and comments.
  - Function Point (FP): a measure of the functionality delivered by the software product, based on the number and complexity of inputs, outputs, inquiries, files, and interfaces.
- Some examples of indirect measures are:
  - Use Case Point (UCP): a measure of the functionality delivered by the software product, based on the number and complexity of use cases and actors.
  - Feature Point (FEP): a measure of the functionality delivered by the software product, based on the number and complexity of features.
  - Object Point (OP): a measure of the functionality delivered by the software product, based on the number and complexity of classes, methods, and attributes.
- Size oriented measures can be used for various purposes, such as estimating effort, cost, and schedule, evaluating productivity and quality, and comparing different software products or processes.
