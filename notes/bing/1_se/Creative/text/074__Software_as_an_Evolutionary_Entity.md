### Software as an Evolutionary Entity

- Software evolution is the continual development of a piece of software after its initial release to address changing stakeholder and/or market requirements.
- Software evolution is important because organizations invest large amounts of money in their software and are completely dependent on this software.
- Software changes are inevitable because there are many factors that change during the life cycle of a piece of software, such as user needs, business goals, technology advances, security threats, etc.
- Software evolution can be fully manual (based on changes by software engineers), partially automated (e.g. using refactoring tools) or fully automated.
- Software evolution has been greatly impacted by the Internet, which enables faster and more frequent delivery of software updates, as well as more feedback from users and customers.
- Software evolution can be seen as a process of co-evolution with the software's domain, which includes the problem space, the solution space, and the application context .
- Software evolution can be guided by software planning, which can and should be based on process and system measures and models, obtained and maintained as a continuing process activity.
- Software evolution can be governed by software evolution laws, which are empirical observations that describe the patterns and trends of software change over time. Some examples of software evolution laws are:

  - Lehman's laws of software evolution, which state that software systems must be continually adapted or they become progressively less satisfactory, that the complexity of software systems increases unless work is done to maintain or reduce it, that the functionality of software systems tends to grow over time, etc.
  - Belady and Lehman's law of increasing change, which states that the number of changes per unit time in a software system increases as the system evolves.
  - Gall's law of software evolution, which states that software systems are best developed by starting with a simple system that works and then adding complexity incrementally.
