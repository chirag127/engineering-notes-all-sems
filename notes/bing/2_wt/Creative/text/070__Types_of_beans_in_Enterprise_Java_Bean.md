### Types of beans in Enterprise Java Bean

Enterprise Java Bean (EJB) is a Java component that can be used to create Java applications that run on a server. EJBs can contain business logic, data access, and messaging functionality. There are three types of EJBs, each with different characteristics and use cases   :

- **Session beans**: Session beans encapsulate business logic that can be invoked by a client, either locally or remotely. Session beans do not have a persistent state, meaning they do not store data across invocations. There are three subtypes of session beans:
  - **Stateless session beans**: Stateless session beans do not maintain any conversational state with the client. They are typically used for simple and short-lived operations, such as validating user credentials or performing calculations. Stateless session beans can be pooled and reused by different clients, improving performance and scalability.
  - **Stateful session beans**: Stateful session beans maintain a conversational state with the client, meaning they can store data and information related to a specific client session. They are typically used for complex and long-lived operations, such as shopping carts or online banking transactions. Stateful session beans are not pooled and are tied to a single client, requiring more resources and memory.
  - **Singleton session beans**: Singleton session beans are instantiated only once per application and are shared by all clients. They are typically used for global and application-wide operations, such as caching, logging, or configuration. Singleton session beans can be accessed concurrently by multiple threads, requiring synchronization and locking mechanisms to ensure data consistency and integrity.
- **Message-driven beans**: Message-driven beans are a type of session bean that process messages asynchronously from a message queue or topic. Message-driven beans are typically used for event-driven and decoupled operations, such as sending notifications, processing orders, or updating inventory. Message-driven beans do not have a conversational state with the client or the message provider, and can be pooled and reused by different messages, improving performance and scalability.
- **Entity beans**: Entity beans are deprecated since EJB 3.0 and are replaced by Java Persistence API (JPA) entities. Entity beans used to represent persistent data stored in a database, and provide methods for creating, retrieving, updating, and deleting data. Entity beans had two subtypes:
  - **Container-managed persistence (CMP) entity beans**: CMP entity beans delegated the data access and mapping logic to the EJB container, which automatically generated the SQL queries and statements based on the entity bean definition and configuration. CMP entity beans were easier to develop and maintain, but had less flexibility and control over the data access and mapping logic.
  - **Bean-managed persistence (BMP) entity beans**: BMP entity beans implemented the data access and mapping logic manually, using JDBC or other APIs to interact with the database. BMP entity beans had more flexibility and control over the data access and mapping logic, but required more coding and testing effort.
