### Flow control in transport layer

- Flow control is a mechanism that regulates the amount of data that can be sent by a sender to a receiver at a given time.
- Flow control is needed in transport layer because it prevents data loss due to congestion, buffer overflow, or mismatched speeds between the sender and the receiver.
- Flow control can be implemented by using feedback messages, such as acknowledgments, window sizes, or congestion signals, that inform the sender about the status of the receiver and the network.
- Flow control can be classified into two types: stop-and-wait and sliding window.
- Stop-and-wait flow control is a simple method that allows the sender to send one data unit at a time and wait for an acknowledgment from the receiver before sending the next one. This method ensures reliable delivery but has low efficiency and high latency.
- Sliding window flow control is a more advanced method that allows the sender to send multiple data units without waiting for acknowledgments, as long as the number of unacknowledged data units does not exceed a certain limit, called the window size. This method improves the efficiency and reduces the latency, but requires more complex logic and buffer management.
- An example of a transport layer protocol that uses stop-and-wait flow control is User Datagram Protocol (UDP), which is a connectionless and unreliable protocol that does not guarantee delivery, order, or error correction of data units.
- An example of a transport layer protocol that uses sliding window flow control is Transmission Control Protocol (TCP), which is a connection-oriented and reliable protocol that ensures delivery, order, and error correction of data units. TCP also adapts its window size dynamically based on the network conditions and the receiver's feedback, using algorithms such as slow start, congestion avoidance, and fast recovery.
