### Transport layer protocols

- Transport layer protocols are responsible for providing end-to-end communication services for applications over a network.
- Transport layer protocols lie between the application layer and the network layer in the protocol stack.
- Transport layer protocols can be classified into two types: connection-oriented and connectionless.
- Connection-oriented protocols establish a logical connection between the sender and the receiver before exchanging data, and terminate the connection after the data transfer is complete. They also provide reliable data delivery, flow control, congestion control, and error recovery mechanisms. An example of a connection-oriented protocol is the Transmission Control Protocol (TCP).
- Connectionless protocols do not establish or terminate connections, and do not guarantee reliable data delivery, flow control, congestion control, or error recovery. They simply send datagrams (packets) from the sender to the receiver, without any acknowledgement or feedback. An example of a connectionless protocol is the User Datagram Protocol (UDP).
- Transport layer protocols identify applications communicating with each other by means of port numbers. Port numbers are 16-bit numbers that are assigned to specific applications or services by the Internet Assigned Numbers Authority (IANA). Port numbers 1 to 1023 are well known and reserved for standardized services, such as HTTP (80), FTP (21), and SSH (22). Port numbers 1024 to 49151 are registered and used by various applications, such as Skype (1024), BitTorrent (6881), and Minecraft (25565). Port numbers 49152 to 65535 are dynamic and used for temporary or ephemeral connections.
- Transport layer protocols also provide segmentation and reassembly of data. Segmentation is the process of dividing a large data stream into smaller segments that can fit into the network layer packets. Reassembly is the process of reconstructing the original data stream from the received segments at the destination. Segmentation and reassembly help to reduce the network congestion and improve the efficiency of data transmission.
- Some of the transport layer protocols that are defined and implemented in the Internet protocol suite are:

  - TCP: Transmission Control Protocol is a connection-oriented, reliable, and full-duplex protocol that provides byte-stream service to the applications. TCP uses a three-way handshake to establish and terminate connections, and uses sequence numbers, acknowledgements, timers, and retransmission to ensure reliable data delivery. TCP also uses sliding window mechanism to provide flow control and congestion control. TCP is widely used for applications that require reliable and ordered data delivery, such as web browsing, email, file transfer, and remote login.
  - UDP: User Datagram Protocol is a connectionless, unreliable, and best-effort protocol that provides datagram service to the applications. UDP does not use any handshake, sequence numbers, acknowledgements, timers, or retransmission to establish or terminate connections, or to ensure reliable data delivery. UDP also does not provide any flow control or congestion control. UDP is widely used for applications that require fast and real-time data delivery, such as voice over IP, video streaming, online gaming, and DNS queries.
  - DCCP: Datagram Congestion Control Protocol is a connection-oriented, unreliable, and congestion-controlled protocol that provides datagram service to the applications. DCCP uses a four-way handshake to establish and terminate connections, and uses sequence numbers and acknowledgements to detect packet loss and provide feedback. DCCP also uses various congestion control mechanisms to adapt to the network conditions and avoid congestion collapse. DCCP is designed for applications that can tolerate some packet loss, but require congestion control, such as multimedia streaming, telephony, and online games.
  - SCTP: Stream Control Transmission Protocol is a connection-oriented, reliable, and message-oriented protocol that provides multiple streams of data to the applications. SCTP uses a four-way handshake to establish and terminate connections, and uses sequence numbers, acknowledgements, timers, and retransmission to ensure reliable data delivery. SCTP also uses sliding window mechanism to provide flow control and congestion control. SCTP supports multiple streams of data within a single connection, which allows for parallel and independent transmission of messages. SCTP also supports multihoming, which allows for multiple network paths between the endpoints. SCTP is designed for applications that require reliable and ordered delivery of messages, such as telecommunication signaling, web services, and file transfer.
