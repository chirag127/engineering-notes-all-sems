### Basic concepts of Cryptography in application layer

Cryptography is the science of securing communications from unauthorized parties. It involves the use of mathematical techniques to transform data into unintelligible forms and back. Cryptography can provide confidentiality, integrity, authenticity, and non-repudiation to the data transmitted or stored in applications.

Some of the basic concepts of cryptography in the application layer are:

- **Plain text** and **cipher text**: Plain text is the original data or message that needs to be protected. Cipher text is the encrypted data or message that is unreadable by anyone without the proper key. An example of plain text is "Hello, world!" and an example of cipher text is "Uryyb, jbeyq!" (using ROT13 encryption).
- **Algorithm** and **key**: An algorithm is a set of rules or steps that defines how to encrypt or decrypt data. A key is a secret value that is used as an input to the algorithm. The key determines the output of the algorithm and must be known by both the sender and the receiver of the encrypted data. An example of an algorithm is AES (Advanced Encryption Standard) and an example of a key is "1234567890abcdef".
- **Encryption** and **decryption**: Encryption is the process of transforming plain text into cipher text using an algorithm and a key. Decryption is the reverse process of transforming cipher text into plain text using the same or a different algorithm and key. An example of encryption is using AES and "1234567890abcdef" to encrypt "Hello, world!" into "3q2+7w4w9v/6WsQ6Liw="
- **Symmetric** and **asymmetric** cryptography: Symmetric cryptography is a type of cryptography that uses the same key for both encryption and decryption. It is fast and efficient, but it requires a secure way of sharing the key between the sender and the receiver. An example of symmetric cryptography is AES. Asymmetric cryptography, also known as public key cryptography, is a type of cryptography that uses a pair of keys for encryption and decryption: a public key and a private key. The public key can be shared with anyone, but the private key must be kept secret. The public key can be used to encrypt data, but only the private key can decrypt it, and vice versa. It is more secure and flexible, but it is slower and more complex than symmetric cryptography. An example of asymmetric cryptography is RSA (Rivest-Shamir-Adleman).
- **Digital signature** and **digital certificate**: A digital signature is a way of proving the authenticity and integrity of a message or a document. It is created by encrypting a hash (a fixed-length summary) of the message or document with the sender's private key. The receiver can verify the signature by decrypting it with the sender's public key and comparing the hash with the original message or document. A digital certificate is a way of proving the identity and validity of a public key. It is issued by a trusted authority (a certificate authority or CA) and contains information such as the public key, the owner's name, the expiration date, and the CA's signature. An example of a digital signature is using RSA and SHA-256 (Secure Hash Algorithm) to sign a message. An example of a digital certificate is using X.509 (a standard format for certificates) to certify a public key.
