### Common Approaches to Real Time Scheduling

Real-time scheduling is the process of assigning tasks to resources (such as processors, communication links, etc.) in a way that meets the timing constraints of the tasks. There are different approaches to real-time scheduling, depending on the characteristics of the tasks, the resources, and the system requirements. Some of the common approaches are:

- **Clock-driven approach**: This approach is also known as time-driven or table-driven approach. It is mainly used for hard real-time systems, where all the properties of the tasks (such as arrival time, execution time, deadline, period, etc.) are known at design time. In this approach, a scheduler uses a precomputed table that specifies which task to execute at each time instant. The table is generated offline using some algorithm that guarantees the feasibility of the schedule. The scheduler is triggered by a periodic timer interrupt, and it simply follows the table to dispatch the tasks. The advantage of this approach is that it has low runtime overhead and predictable behavior. The disadvantage is that it is inflexible and cannot handle dynamic changes in the system.

- **Priority-driven approach**: This approach is also known as event-driven or dynamic approach. It is mainly used for soft or firm real-time systems, where some of the properties of the tasks (such as arrival time, execution time, deadline, etc.) are not known at design time, or may vary at runtime. In this approach, a scheduler assigns a priority to each task based on some criteria, such as deadline, criticality, urgency, etc. The scheduler is triggered by events, such as task arrival, completion, preemption, etc. The scheduler always selects the highest priority task that is ready to execute, and preempts the currently running task if its priority is lower. The advantage of this approach is that it is flexible and can handle dynamic changes in the system. The disadvantage is that it has higher runtime overhead and less predictable behavior.

- **Weighted round-robin approach**: This approach is a variation of the round-robin approach, which is a commonly used technique in time-shared systems. In this approach, each task is assigned a weight, which represents its relative importance or share of the processor. The scheduler allocates a fixed time slice to each task, and cycles through the ready tasks in a circular order. However, instead of giving each task the same time slice, the scheduler gives each task a time slice proportional to its weight. For example, if task A has weight 2 and task B has weight 1, then task A will get twice as much time as task B. The advantage of this approach is that it is simple and fair, and can provide some degree of differentiation among the tasks. The disadvantage is that it does not consider the timing constraints of the tasks, and may cause deadline misses or poor performance.

Some possible mnemonics and learning tricks for the topic are:

- To remember the difference between clock-driven and priority-driven approaches, you can use the acronym CDP: Clock-Driven is Precomputed, Priority-Driven is Dynamic.
- To remember the difference between hard, soft, and firm real-time systems, you can use the analogy of a cake: Hard real-time systems are like a cake that has to be baked exactly on time, otherwise it is useless. Soft real-time systems are like a cake that can be baked a little late, but it will lose some quality. Firm real-time systems are like a cake that can be baked a little late, but it will be discarded if it is too late.
- To remember the weighted round-robin approach, you can use the formula: Time slice = Weight / Sum of weights. For example, if task A has weight 2 and task B has weight 1, then the sum of weights is 3, and the time slice for task A is 2/3 and for task B is 1/3.
