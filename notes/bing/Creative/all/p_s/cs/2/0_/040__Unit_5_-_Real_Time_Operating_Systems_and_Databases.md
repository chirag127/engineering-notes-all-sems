## Unit 5 - Real Time Operating Systems and Databases

- A **real-time operating system (RTOS)** is an operating system that guarantees a certain capability within a specified time constraint. For example, an operating system that is designed to make sure that a specific object is available to a robot on the assembly line is an example of an RTOS.
- An RTOS is different from a general-purpose operating system, such as Windows or Linux, which is designed to handle a variety of tasks and may not be able to guarantee a response time for a specific task.
- An RTOS typically has a **kernel**, which is the core part of the operating system that manages the basic functions, such as memory management, task scheduling, and inter-process communication. The kernel is usually **preemptive**, which means that it can interrupt a running task to switch to another task that has a higher priority or a deadline.
- An RTOS may also have **middleware**, which is a software layer that provides additional services, such as networking, file systems, or graphical user interfaces. Middleware may be optional or configurable, depending on the needs of the application.
- An RTOS may also have **application software**, which is the software that performs the specific functions of the device or system. Application software may be written in a high-level language, such as C or C++, or in a low-level language, such as assembly or machine code.
- A **real-time database** is a database system that can handle data workloads that are in constant flux and are extremely time-sensitive. Unlike traditional databases, which store data that is persistent and changes less frequently, real-time databases need to process data that is dynamic and volatile, such as sensor readings, stock prices, or user interactions.
- A real-time database may have different requirements than a traditional database, such as:
  - **Concurrency control**: A real-time database needs to ensure that multiple transactions can access and modify the data without causing inconsistencies or conflicts. Concurrency control techniques, such as locking, timestamping, or optimistic methods, may be used to achieve this.
  - **Data freshness**: A real-time database needs to ensure that the data is up-to-date and reflects the current state of the system. Data freshness may be measured by the **age** of the data, which is the difference between the current time and the time when the data was generated, or by the **deadline** of the data, which is the time by which the data must be processed or delivered.
  - **Data consistency**: A real-time database needs to ensure that the data is accurate and reliable, and that it does not violate any integrity constraints or business rules. Data consistency may be achieved by using **validation**, which is the process of checking the data for errors or anomalies, or by using **replication**, which is the process of copying the data to multiple locations or servers for redundancy or fault tolerance.
  - **Data availability**: A real-time database needs to ensure that the data is accessible and retrievable at any time, and that it does not suffer from any failures or interruptions. Data availability may be achieved by using **backup**, which is the process of storing the data in a secondary location or device for recovery purposes, or by using **load balancing**, which is the process of distributing the data or the workload among multiple servers or nodes for performance or scalability purposes.
- A real-time database may use different data models or structures than a traditional database, such as:
  - **Relational model**: A relational model organizes the data into tables, which consist of rows and columns. Each row represents a record or an entity, and each column represents an attribute or a property. A relational model may use **SQL** (Structured Query Language) as a standard language for defining, manipulating, and querying the data.
  - **Key-value model**: A key-value model organizes the data into pairs of keys and values, where each key is a unique identifier and each value is an arbitrary data item. A key-value model may use **NoSQL** (Not Only SQL) as a general term for various non-relational data models and languages that are designed for scalability, performance, and flexibility.
  - **Time-series model**: A time-series model organizes the data into sequences of values that are indexed by time. Each value represents a measurement or an observation that is taken at a specific point in time. A time-series model may use **TSDB** (Time Series Database) as a specialized type of database that is optimized for storing and analyzing time-series data.
