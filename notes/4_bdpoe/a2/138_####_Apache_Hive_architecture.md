#### Apache Hive architecture

Hive architecture consists of the following main components:

-   Metastore: It is a database that stores metadata or data about data. It stores information about the tables, partitions, schemas, columns, etc. By default, Derby database is used as the metastore but MySQL and PostgreSQL can also be used.
-   Driver: It is the interface between the HiveQL commands and the metastore and execution engines. It parses the HiveQL statements and converts them into an execution plan with the help of the metastore and optimizer.
-   Compiler: It compiles the HiveQL statements into MapReduce jobs and Tez or Spark jobs.
-   Optimizer: It optimizes the execution plans to make the execution efficient based on the metadata in the metastore.
-   Execution Engine: It executes the jobs generated by the compiler. Hive supports three execution engines:
    -   MapReduce: Default execution engine that runs on Hadoop MapReduce.
    -   Tez: Execution engine that runs on Apache Tez and provides better performance than MapReduce engine.
    -   Spark: Execution engine that runs on Apache Spark and provides faster processing and low latency.

Some key points to remember:

- Hive sits on top of Hadoop to provide data summarization, querying, and analysis.
- HiveQL is a SQL-like language used to query data in Hive.
- Hive converts HiveQL statements into MapReduce/Tez/Spark jobs which are executed on Hadoop.
- The metastore stores metadata or schema of the data which is used by the optimizer and compiler to generate efficient execution plans.
- The driver, compiler, and optimizer work together to convert the HiveQL queries into execution plans which are then executed by the execution engine.
