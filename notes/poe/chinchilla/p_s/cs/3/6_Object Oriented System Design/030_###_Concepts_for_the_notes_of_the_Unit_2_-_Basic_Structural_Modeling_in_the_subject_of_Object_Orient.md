### Concepts for the notes of the Unit 2 - Basic Structural Modeling in the subject of Object Oriented System Design

In this unit, we will cover the fundamental concepts of Basic Structural Modeling in Object Oriented System Design. These concepts are essential to understand the internal structure and organization of an object-oriented system. Here are the key concepts that we will cover in this unit:

1. Class Diagrams:
    - Class diagrams are the most commonly used diagrams in object-oriented modeling.
    - They represent the classes and their relationships in an object-oriented system.
    - Class diagrams are used to depict the static structure of a system, i.e., the objects, attributes, and methods of the classes.
    - They are also used to show the inheritance and association relationships between classes.
    - Class diagrams are used to specify the overall architecture of a system and are an essential tool for software design and development.

2. Object Diagrams:
    - Object diagrams represent the objects and their relationships at a particular point in time.
    - They are used to depict the dynamic structure of a system, i.e., the objects and their interactions during runtime.
    - Object diagrams are useful to understand the behavior of a system and debug it.

3. Composite Structure Diagrams:
    - Composite structure diagrams are used to represent the internal structure of a complex object, which comprises several interconnected parts.
    - They show the relationship between the components and how they collaborate to achieve a specific functionality.
    - Composite structure diagrams are used to model complex systems, such as computer networks or embedded systems.

4. Component Diagrams:
    - Component diagrams represent the components of a system and their relationships.
    - They are used to depict the physical structure of a system, i.e., the components and their interactions.
    - Component diagrams are useful for software development, as they show the dependencies between the components of a system.

5. Deployment Diagrams:
    - Deployment diagrams represent the physical deployment of components in a system.
    - They show how the components are deployed on nodes, such as servers or workstations.
    - Deployment diagrams are used to specify the hardware requirements of a system and to plan its deployment.

In conclusion, Basic Structural Modeling is an essential concept in Object Oriented System Design. It helps to understand the internal structure and organization of a system and is an essential tool for software design and development. By studying the concepts covered in this unit, you will be able to create effective class diagrams, object diagrams, composite structure diagrams, component diagrams, and deployment diagrams.
