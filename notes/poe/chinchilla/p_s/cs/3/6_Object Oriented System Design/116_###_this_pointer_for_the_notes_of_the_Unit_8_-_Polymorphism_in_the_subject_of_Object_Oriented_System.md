#### Various Size Oriented Measures in Software Design

Software size is an important factor in software design and development. Various size-oriented measures have been developed to measure the size of software systems. These measures help in estimating the effort required for software development, testing, and maintenance. In this section, we will discuss various size-oriented measures in software design.

1. Lines of Code (LOC)
   - LOC is the most commonly used measure of software size.
   - It measures the number of lines of code in a software system.
   - It is easy to understand and calculate.
   - However, it does not take into account the complexity of the code.

2. Function Points (FP)
   - FP measures the functionality provided by a software system.
   - It takes into account the complexity of the code and the functionality provided.
   - It is a more accurate measure of software size than LOC.
   - However, it requires more effort to calculate than LOC.

3. Object Points (OP)
   - OP measures the functionality provided by a software system in terms of objects.
   - It takes into account the complexity of the code and the functionality provided.
   - It is a more accurate measure of software size than LOC and FP.
   - However, it requires more effort to calculate than LOC and FP.

4. Source Lines of Code (SLOC)
   - SLOC measures the number of lines of code in a software system excluding comments and blank lines.
   - It is a more accurate measure of software size than LOC.
   - However, it requires more effort to calculate than LOC.

5. Program Understanding (PU) Points
   - PU points measure the effort required to understand a software system.
   - It takes into account factors like code complexity, documentation, and code readability.
   - It is a more accurate measure of software size than LOC.
   - However, it requires more effort to calculate than LOC.

6. Use Case Points (UCP)
   - UCP measures the complexity of a software system based on the number of use cases it supports.
   - It takes into account the complexity of the code and the functionality provided.
   - It is a more accurate measure of software size than LOC.
   - However, it requires more effort to calculate than LOC.

Advantages of size-oriented measures:
- They provide a quantitative measure of software size.
- They help in estimating the effort required for software development, testing, and maintenance.
- They provide a basis for comparing different software systems.

Disadvantages of size-oriented measures:
- They do not take into account the quality of the code.
- They do not take into account factors like code reusability and maintainability.

Examples of size-oriented measures:
- In a software development project, the team estimates the effort required based on the size of the software system measured in LOC or FP.
- In a software maintenance project, the team estimates the effort required based on the size of the software system measured in SLOC.

Applications of size-oriented measures:
- They are used in software development projects to estimate the effort required for software development, testing, and maintenance.
- They are used in software maintenance projects to estimate the effort required for maintenance activities.
