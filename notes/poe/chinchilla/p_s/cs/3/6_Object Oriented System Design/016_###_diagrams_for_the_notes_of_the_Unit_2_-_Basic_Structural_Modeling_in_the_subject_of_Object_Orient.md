### Diagrams for the Notes of the Unit 2 - Basic Structural Modeling in the Subject of Object Oriented System Design

Diagrams are an essential tool for modeling and designing object-oriented systems. They help us to understand the structure of the system, its components, and their relationships. In this unit, we will learn about the various types of diagrams used in object-oriented system design. 

Here are some of the most important diagrams that we will cover in this unit:

1. Class Diagram: A class diagram is a type of structural diagram that shows the classes and their relationships in a system. It is used to model the static structure of the system. A class diagram consists of classes, attributes, and operations. It also shows the relationships between classes such as inheritance, association, and aggregation.

2. Object Diagram: An object diagram is a type of structural diagram that shows the instances of classes in a system. It is used to model the dynamic structure of the system. An object diagram consists of objects, their attributes, and their relationships. It shows how the objects interact with each other at a particular point in time.

3. Package Diagram: A package diagram is a type of structural diagram that shows the packages and their relationships in a system. It is used to organize the classes and other components of the system into logical groups. A package diagram consists of packages, classes, and other components. It also shows the dependencies between packages.

4. Component Diagram: A component diagram is a type of structural diagram that shows the components and their relationships in a system. It is used to model the physical structure of the system. A component diagram consists of components, interfaces, and dependencies. It also shows the relationships between components such as composition and delegation.

5. Deployment Diagram: A deployment diagram is a type of structural diagram that shows the physical deployment of the components in a system. It is used to model the hardware and software components of the system and their relationships. A deployment diagram consists of nodes, components, and their relationships. It also shows the communication paths between the components.

Advantages of using diagrams in object-oriented system design:
- They help to visualize the system structure and its components.
- They simplify the understanding of the relationships between the components.
- They facilitate communication among the stakeholders of the system.
- They aid in identifying potential design problems and errors.

Disadvantages of using diagrams in object-oriented system design:
- They can be complex and difficult to understand if not designed properly.
- They require a significant amount of time and effort to create.
- They need to be updated frequently to reflect changes in the system.

Examples of diagrams in object-oriented system design:
- A class diagram for a banking system that shows the classes, attributes, and operations of the system.
- An object diagram for a shopping cart application that shows the instances of classes and their relationships.
- A package diagram for a customer relationship management system that shows the logical grouping of the classes and other components.
- A component diagram for a web application that shows the physical components of the system and their relationships.
- A deployment diagram for a mobile app that shows the deployment of the components on different devices.

Applications of diagrams in object-oriented system design:
- They are used in the software development life cycle for analysis, design, and implementation.
- They are used in the documentation of the system for future reference.
- They are used in the communication of the system design to the stakeholders.
