### Common Mechanisms for the notes of the Unit 2 - Basic Structural Modeling in the subject of Object Oriented System Design

In the Unit 2 of the subject of Object Oriented System Design, we will learn about Basic Structural Modeling. This unit will focus on the various mechanisms that are used to model the structural aspects of an object-oriented system. In this section, we will discuss some common mechanisms for the notes of the Unit 2 - Basic Structural Modeling in the subject of Object Oriented System Design.

#### Class Diagrams
A class diagram is a type of structural diagram that shows the relationships between objects and classes in a system. It is a widely used mechanism for modeling the structure of an object-oriented system. In class diagrams, we represent classes as rectangles and the relationships between them as lines connecting the rectangles. There are various types of relationships like inheritance, association, aggregation, and composition.

#### Object Diagrams
An object diagram is a type of structural diagram that shows the instances of classes in a system. In object diagrams, we represent objects as rectangles and the relationships between them as lines connecting the rectangles. Object diagrams are useful for understanding how objects interact with each other at a particular point in time.

#### Package Diagrams
A package diagram is a type of structural diagram that shows the organization of classes in a system. In package diagrams, we represent packages as rectangles and the relationships between packages as lines connecting the rectangles. Package diagrams help us to understand the overall structure of a system and how classes are organized into different packages.

#### Component Diagrams
A component diagram is a type of structural diagram that shows the components and their dependencies in a system. In component diagrams, we represent components as rectangles and the relationships between them as lines connecting the rectangles. Component diagrams help us to understand the overall architecture of a system and how different components interact with each other.

#### Deployment Diagrams
A deployment diagram is a type of structural diagram that shows the physical deployment of components in a system. In deployment diagrams, we represent nodes as rectangles and the components as boxes inside the nodes. The relationships between nodes are shown as lines connecting the rectangles. Deployment diagrams help us to understand how the components are deployed on different nodes in a system.

Overall, these common mechanisms are used to model the structural aspects of an object-oriented system. They help us to understand the relationships between classes, objects, packages, components, and nodes in a system. By using these mechanisms, we can design better object-oriented systems that are easier to understand, maintain, and extend.
