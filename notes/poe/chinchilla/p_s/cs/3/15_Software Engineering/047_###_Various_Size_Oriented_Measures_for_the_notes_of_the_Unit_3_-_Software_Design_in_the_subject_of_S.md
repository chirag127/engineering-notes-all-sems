### Various Size Oriented Measures for the notes of the Unit 3 - Software Design in the subject of Software Engineering

Size-oriented metrics are used to measure the size of the software product or process. These metrics are based on the size of the software code or the size of the software development process. In this unit, we will discuss various size-oriented measures that are used in software design. These measures are as follows:

1. Lines of Code (LOC): LOC is the most common size-oriented measure used in software engineering. It measures the number of lines of code in a software product. It is used to estimate the cost and effort required to develop and maintain the software. However, LOC has some limitations as it does not consider the quality, complexity, and readability of the code.

2. Function Points (FP): FP is a size-oriented measure that is used to measure the functionality of a software product. It measures the number of inputs, outputs, inquiries, files, and interfaces of a software product. It is used to estimate the size and complexity of the software product. However, FP has some limitations as it does not consider the quality and complexity of the software code.

3. Object Points (OP): OP is a size-oriented measure that is used to measure the size of the software product based on the number of objects and their attributes. It is used to estimate the cost and effort required to develop and maintain the software. However, OP has some limitations as it does not consider the quality and complexity of the software code.

4. Source Lines of Code (SLOC): SLOC is a size-oriented measure that is used to measure the number of lines of code in a software product excluding comments and blank lines. It is used to estimate the cost and effort required to develop and maintain the software. However, SLOC has some limitations as it does not consider the quality, complexity, and readability of the code.

5. Cyclomatic Complexity (CC): CC is a size-oriented measure that is used to measure the complexity of a software product. It measures the number of independent paths through the software code. It is used to estimate the risk and maintainability of the software product. However, CC has some limitations as it does not consider the quality and readability of the code.

In conclusion, size-oriented metrics are important in software engineering as they help in estimating the cost, effort, and complexity of a software product. However, these metrics have some limitations as they do not consider the quality, complexity, and readability of the code. Therefore, it is important to use these metrics in combination with other metrics to get a complete picture of the software product.
