### Draw the use case diagram and specify the role of each of the actors for the notes of the Unit 1 - Introduction of Software Engineering Lab in the subject of Software Engineering Lab.

In software engineering, a use case diagram is a graphical representation of the interactions between actors (users) and the system under consideration. Use cases are used to capture the functional requirements of a system in a clear and concise way.

In Unit 1 - Introduction of Software Engineering Lab, we learn about the use case diagrams and the role of different actors in the system. The use case diagram is a powerful tool for software engineers to identify the requirements of a system and to ensure that all necessary functionality is included in the design.

The actors in a use case diagram are the users or external systems that interact with the system being modeled. Each actor has a specific role in the system, and their interactions with the system are defined by use cases. 

The following are the actors and their roles for the notes of the Unit 1 - Introduction of Software Engineering Lab in the subject of Software Engineering Lab:

#### Actors:

1. User: The user is the primary actor in the system. They interact with the system to perform tasks and achieve their goals. The user can be a customer, an employee, or any other person who interacts with the system.

2. Administrator: The administrator is responsible for managing the system. They have the authority to add or remove users, update system settings, and perform other administrative tasks.

3. System: The system is the software being modeled by the use case diagram. It interacts with the users and performs the tasks required by the use cases.

#### Roles:

1. View Notes: This use case allows the user to view the notes of the course.

2. Add Notes: This use case allows the administrator to add notes to the system.

3. Edit Notes: This use case allows the administrator to edit existing notes in the system.

4. Delete Notes: This use case allows the administrator to delete notes from the system.

5. Search Notes: This use case allows the user to search for notes based on specific criteria.

By creating a use case diagram, we can clearly define the roles and interactions between the actors and the system. This helps to ensure that the system meets the requirements of the users and provides the necessary functionality to achieve their goals.
