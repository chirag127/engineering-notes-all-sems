### System models for the notes of the Unit 4 - Agreement Protocols in the subject of DISTRIBUTED SYSTEM

In the field of distributed systems, system models refer to the various ways in which multiple computers or nodes are connected and interact with each other to achieve a common goal. There are several system models that are commonly used in distributed systems, each with their own advantages and disadvantages. In this unit, we will focus on the system models that are used for agreement protocols.

#### 1. Centralized System Model

The centralized system model is a system model where all the nodes in the system are connected to a single central node. This central node is responsible for executing all the tasks in the system and making all the decisions. In this model, all the communication between the nodes in the system goes through the central node. This model is easy to implement and manage, but it is also a single point of failure. If the central node fails, then the entire system will fail.

#### 2. Decentralized System Model

The decentralized system model is a system model where there is no single central node in the system. Rather, the nodes in the system are connected to each other in a peer-to-peer fashion. In this model, each node is responsible for its own tasks and decisions, and communication between the nodes is done directly. This model is more fault-tolerant than the centralized model, as there is no single point of failure. However, it can be more difficult to manage and coordinate the nodes in the system.

#### 3. Hierarchical System Model

The hierarchical system model is a system model where the nodes in the system are organized into a hierarchical structure. In this model, there are multiple levels of nodes, with each level having a different level of responsibility. The nodes at the top of the hierarchy are responsible for making the high-level decisions, while the nodes at the bottom of the hierarchy are responsible for executing the low-level tasks. This model is more fault-tolerant than the centralized model, and it can also be easier to manage than the decentralized model. However, it can be more difficult to implement and may require more resources.

#### 4. Hybrid System Model

The hybrid system model is a combination of two or more of the above system models. In this model, different parts of the system may use different system models depending on the specific requirements of that part of the system. For example, a system may use a centralized model for some tasks and a decentralized model for others. This model can be very flexible and can be tailored to the specific needs of the system. However, it can also be more complex to implement and manage.

Mnemonics and learning tricks:
Unfortunately, there are no easy-to-remember mnemonics or learning tricks for these system models. However, it may be helpful to think of each model as a different way of organizing the nodes in the system, with different tradeoffs in terms of fault-tolerance, manageability, and complexity.
