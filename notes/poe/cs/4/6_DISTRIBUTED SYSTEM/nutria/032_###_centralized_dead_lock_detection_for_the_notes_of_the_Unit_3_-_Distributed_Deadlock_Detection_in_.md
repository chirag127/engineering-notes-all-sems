
## Centralized Deadlock Detection for the Notes of Unit 3 - Distributed Deadlock Detection in the Subject of DISTRIBUTED SYSTEM

Deadlock detection is a process of detecting deadlocks in distributed systems. It is an important part of distributed system management and is used to identify and prevent deadlocks from occurring. 

A deadlock is a situation in which two or more processes are blocked, waiting for resources that are held by other processes. In distributed systems, deadlocks may arise due to the lack of coordination between processes.

Centralized deadlock detection is a process of detecting deadlocks in distributed systems using a centralized algorithm. This algorithm requires a centralized server to keep track of the resources and processes in the system.

The algorithm works by assigning each process a unique identifier. The server then keeps track of the resources that each process has requested and the resources that it has been granted. If a process requests a resource that is already held by another process, the server will detect a deadlock.

The advantages of centralized deadlock detection include:

- Easy to implement - the server only needs to keep track of the resources and processes in the system.
- Efficient - since the server is centralized, it can detect deadlocks quickly.
- Reliable - since the server is centralized, it can detect deadlocks accurately.

The disadvantages of centralized deadlock detection include:

- High cost - since the server is centralized, it can be expensive to maintain.
- Complexity - since the server is centralized, it can be difficult to set up and maintain.
- Scalability - since the server is centralized, it can be difficult to scale with the size of the system.

In summary, centralized deadlock detection is an efficient and reliable process of detecting deadlocks in distributed systems. However, it is expensive and complex to set up and maintain.
