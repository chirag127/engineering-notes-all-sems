
### Transactions for the Notes of the Unit 8 - Transactions and Concurrency Control in the Subject of DISTRIBUTED SYSTEM

- A transaction is a unit of work that is performed against a database. It is the fundamental concept of a distributed system.
- Transactions are used to ensure data integrity and consistency in a distributed system.
- A transaction consists of a set of operations that must all be completed for the transaction to be successful.
- Transactions are used to ensure that all operations are completed in a consistent manner, and that no data is lost or corrupted.
- The ACID (Atomicity, Consistency, Isolation, Durability) properties of transactions ensure that the data remains consistent and reliable throughout the duration of the transaction.
- Transactions can be used to implement concurrency control, which ensures that multiple transactions can be executed concurrently without corrupting the data.
- Two-phase commit protocols are used to ensure that all transactions are committed in a consistent manner.
- The concept of distributed transactions is used to ensure that all operations in a distributed system are completed in a consistent manner.
- Distributed transactions can also be used to implement distributed locking, which ensures that multiple transactions can be executed concurrently without conflicting with each other.
- Mnemonics and learning tricks for transactions and concurrency control include:
  - **A**tomicity: All operations must be completed for the transaction to be successful.
  - **C**onsistency: All operations must be consistent with the data model and the database.
  - **I**solation: All operations must be isolated from each other.
  - **D**urability: All operations must be durable and persistent.
  - **2PC**: Two-phase commit protocols are used to ensure that all transactions are committed in a consistent manner.
  - **DL**: Distributed locking is used to ensure that multiple transactions can be executed concurrently without conflicting with each other.
