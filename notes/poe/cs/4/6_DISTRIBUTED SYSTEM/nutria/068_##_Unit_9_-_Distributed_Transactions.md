
## Unit 9 - Distributed Transactions

A distributed transaction is a type of database transaction that involves multiple nodes, or computers, that are all connected to the same network. Distributed transactions can be used to move data between multiple databases, update multiple databases at once, and ensure that all data is consistent across all databases.

### Advantages

- Distributed transactions allow for data to be moved between multiple databases, which can be useful for applications that need to access data from multiple sources.
- Distributed transactions can help ensure that all data is consistent across all databases, which can help prevent data corruption.
- Distributed transactions can improve performance by reducing the amount of time required to move data between multiple databases.

### Disadvantages

- Distributed transactions can be complex to implement and maintain.
- Distributed transactions can be difficult to debug and troubleshoot.
- Distributed transactions can be slow, as they require multiple nodes to communicate with each other.

### Mnemonics

- **D**istributed **T**ransactions **A**re **C**omplex: D-TAC can be used to remember the complexity of distributed transactions.
- **M**ultiple **D**atabases **A**re **I**nvolved: MD-AI can be used to remember that multiple databases are involved in distributed transactions.
