
### Recovery in Concurrent Systems for the Notes of the Unit 6 - Failure Recovery in Distributed Systems in the Subject of DISTRIBUTED SYSTEM

Recovery in concurrent systems is a key component of distributed systems. It is important to understand the different techniques used to ensure that the system is able to recover from failure in a timely and reliable manner.

- **Checkpointing**: This is a technique used to store the state of a distributed system at a certain point in time. This allows the system to recover from a failure by restoring the state of the system to the checkpointed state.
- **Rollback Recovery**: This is a technique used to rollback the state of a distributed system to a previous state. This is used to ensure that the system is able to recover from a failure without losing any data.
- **Logging**: This is a technique used to log the state of a distributed system. This allows the system to recover from a failure by restoring the state of the system to the logged state.
- **Fault-Tolerance**: This is a technique used to ensure that the system is able to tolerate faults and continue to operate. This is done by replicating data and components of the system to ensure that the system is able to recover from a failure.
- **Replication**: This is a technique used to replicate data and components of a distributed system. This ensures that the system is able to recover from a failure without losing any data.
- **Redundancy**: This is a technique used to ensure that the system is able to tolerate faults and continue to operate. This is done by creating redundant components of the system to ensure that the system is able to recover from a failure.
- **Mnemonics and Learning Tricks**: To help remember the different techniques for recovery in concurrent systems, it can be helpful to use mnemonics and learning tricks. For example, the acronym "CRFLR" can be used to remember the techniques of Checkpointing, Rollback Recovery, Logging, Fault-Tolerance, Replication, and Redundancy.
