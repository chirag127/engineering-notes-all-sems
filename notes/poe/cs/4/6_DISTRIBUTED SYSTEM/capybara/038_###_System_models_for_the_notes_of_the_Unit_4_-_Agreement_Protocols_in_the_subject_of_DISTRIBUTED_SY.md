### System models for the notes of the Unit 4 - Agreement Protocols in the subject of DISTRIBUTED SYSTEM

In the study of distributed systems, system models serve as a guide for describing the interactions between different components of a system. There are three commonly used system models that are used to understand the behavior of distributed systems:

1. Client-server model:
   - This model involves a server that provides services to multiple clients.
   - The clients send requests to the server, which processes these requests and sends back responses to the clients.
   - A common example of this model is a web server that provides resources to web browsers.

2. Peer-to-peer model:
   - This model involves a network of peers that communicate with each other to share resources.
   - Each peer acts as both a client and a server, and can request and provide resources to other peers in the network.
   - A common example of this model is file-sharing applications like BitTorrent.

3. Hybrid model:
   - This model combines aspects of both the client-server and peer-to-peer models.
   - It involves a central server that coordinates the actions of multiple peers in the network.
   - The peers can communicate with each other directly, or through the server as an intermediary.
   - A common example of this model is online gaming, where a central server coordinates the actions of multiple players.

Mnemonics and learning tricks:
- To remember the client-server model, think of a waiter in a restaurant taking orders from multiple customers and bringing them their food.
- To remember the peer-to-peer model, think of a group of friends sharing their snacks with each other during a study session.
- To remember the hybrid model, think of a coach directing a team of players during a game, where the players can also communicate with each other directly.

Understanding these system models is crucial for designing and implementing distributed systems, as it provides a framework for understanding how different components of the system interact with each other. By understanding the strengths and weaknesses of each model, system architects can design systems that are optimized for specific use cases and performance requirements.
