### Object Oriented Integration and System Testing

- Integration testing is done to identify faults in the interaction between integrated components/modules.
- In object oriented integration testing, interactions between objects are tested.
- Object oriented integration testing can be done in three ways:
	- Big bang approach - All modules are integrated at once and tested. Risky if modules have complex dependencies.
	- Incremental approach - Modules are integrated incrementally and testing is done after each integration. Recommended approach.
	- Sandwich/hybrid approach - Some modules are integrated in increments and some are integrated at once.
- Object oriented system testing involves testing the system as a whole. It is black-box testing and tests if the system meets specified requirements.
- System tests are derived from requirements. Samples of different inputs are used to test system's functionality, performance, compatibilities, etc.
- Object oriented system testing checks core OOP concepts like encapsulation, inheritance, polymorphism in the integrated system.
- Advantages: Finds integration faults and ensures system meets requirements.
- Disadvantages: Difficult to trace faults, testing all combinations of inputs/scenarios is challenging.

**Mnemonics:**

- IIT - Incremental Integration Testing
- BBT - Big Bang Testing
- SHT - Sandwich Hybrid Testing

**Learning tricks:**

- Think of integration testing as joining Lego blocks - join incrementally and test after each addition for best results.
- For system testing, try extremes of inputs and think from user's perspective to test relevant scenarios.
- Test core OOP concepts by trying to access private data, override methods, use superclass methods, etc.
