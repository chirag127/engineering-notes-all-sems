### Terminologies in Testing for the notes of the Unit 1 - Review of Software Engineering in the subject of Software Testing

**Testing**: Testing is the process of evaluating a system or its components with the intent of finding whether it satisfies the specified requirements or not. It involves executing the system/component under controlled conditions, judging whether the expected outputs are produced or not, and checking whether the system works as per the requirements.

**Quality Assurance (QA)**: QA is the process of ensuring that the product meets the specified standards of quality including functional performance, reliability, and user experience. QA activities are usually performed internally, often as a team separate from testers, to help control processes and prevent defects.

**Defect**: A defect is a variance from desired product behavior or functionality. Defects are identified during testing. A defect is also known as a bug.

**Bug**: A bug is a defect that can cause the system to produce an incorrect or unexpected result or to behave in unintended ways. Bugs are identified and fixed as part of defect or bug fixing.

**Test Case**: A test case is a set of conditions or variables under which a tester determines whether a system under test meets requirements or works correctly. It includes inputs, expected results, and execution preconditions.

**Test Plan**: A test plan is a document that describes the testing approach, objectives, focus areas, and resources/schedule for intended software testing activities. It helps testing teams organize tests and is often required documentation for regulatory compliance.

**Test Suite**: A test suite is a collection of test cases that are intended to be used to test a software program to show that it has some specified set of behaviors.

**Debugging**: Debugging is the process of finding and resolving defects/bugs within the code that is causing the software to behave unexpectedly or incorrectly. Debugging is usually done by developers once defects are identified by testers.

**Verification vs Validation**:
- Verification: Are we building the product right? (i.e. according to specifications)
- Validation: Are we building the right product? (i.e. meets customer needs)

Verification activities help evaluate whether the product is being developed according to the specifications, while validation activities help evaluate whether the product meets the intended use and customer needs. Both are important for software quality.
