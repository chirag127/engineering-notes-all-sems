### Priority category for the notes of the Unit 4 - Regression Testing in the subject of Software Testing

1. Regression Testing:
- Testing conducted to determine whether a change to the system has introduced new unintended/undesirable bugs/defects.
- Performed when changes are made to the existing software (enhancements/bug fixes) to ensure that the changes have not impacted the existing functionality.
- Helps to build confidence in the changes made and provide information to take corrective actions if required.
- Prioritize tests that were most frequently executed and tests that are more critical to the functionality and business.

Mnemonics:
- RECURSE - Re-test Critical functionality,Executeargest test suites,Cover important features,Use scripted tests,Regression test Early,Save time and cost

2. Types of Regression Testing:
- Retest All - Executing all tests again. Very expensive but gives high confidence.
- Selective - Executing a subset of tests. Choose most important tests.
- Progressive - Gradually increasing the scope of testing in each iteration.
- Some More (Mnemonics) - System, Mission critical, Operations affected, Most used, Error prone

Advantages:
- Detects bugs early and avoids cascading effects.
- Provides confidence in changes made.
- Prevents software erosion.

Disadvantages:
- Time consuming and expensive process.
- Tedious and repetitive task.
- Challenging to determine right set of tests to be included.

Applications:
- After every bug fix.
- After enhancements or new features addition.
- Before major releases.
