### Failure for the notes of the Unit 1 - Review of Software Engineering in the subject of Software Testing

- Software Failure: The software product does not meet the requirements or expectations. It can be due to bugs, defects, or errors in the software.
- Types of Software Failure:
    - Build Failure: The software product is unable to compile or build successfully due to syntax errors or missing dependencies.
    - Runtime Failure: The software builds successfully but crashes or produces incorrect results at runtime due to logical errors.
    - Functional Failure: The software performs unwanted or undefined actions due to improper logic or algorithms.
    - Usability Failure: The software is difficult to use or has a bad user experience due to poor UI/UX design.
- Causes of Software Failure:
    - Incorrect requirements: The software is built to satisfy the wrong requirements.
    - Complexity: The software is too complex to implement and test all possible scenarios.
    - Bugs: Logical, coding, or syntax errors that result in undesired behavior.
    - Lack of testing: Insufficient testing leads to the presence of critical bugs or errors in the released software.
    - Poor design: Bad software architecture or system design leads to failures.
    - Time pressure: Strict deadlines can lead to compromises in quality and rushed releases with bugs.
- Failure cannot be completely eliminated but can be reduced by:
    - Clear requirements and specifications
    - Simplicity in design
    - Extensive testing (manual + automated)
    - Code reviews and proper debugging
    - High-quality development and project management practices
