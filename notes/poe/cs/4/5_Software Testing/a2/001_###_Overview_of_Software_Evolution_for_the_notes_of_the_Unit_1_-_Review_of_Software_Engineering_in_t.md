### Overview of Software Evolution for the notes of the Unit 1 - Review of Software Engineering in the subject of Software Testing

Software evolution refers to the process of developing and maintaining software so that it continues to meet the changing requirements of its users. As software is used, requirements change and defects are detected. The software must change to accommodate these new needs.
Software evolution is an inevitable process for almost all software. There are three main reasons for software evolution:

1. Accommodating changing requirements - As users gain experience with a software product, they identify additional features or functionalities that would be desirable. The software must change to add these new capabilities.
2. Fixing defects - As software is executed, defects or "bugs" are often found. The software must be modified to correct these defects.
3. Improving performance - As software is executed, opportunities for performance improvements may become apparent. The software may need to be changed to take advantage of these performance enhancement possibilities.

The topics we will cover in this unit related to software evolution include:

- Managing software change - The processes and tools used to control changes to software to ensure high quality software evolution.
- Impact analysis - Determining the effects of a change to software to focus testing and verification efforts on the right areas.
- Software refactoring - Restructuring existing software to make future changes easier while preserving external behavior.
- Software maintenance - The overall process of modifying and adapting software after delivery to correct faults, improve performance, or other attributes, or to adapt the software to a changed environment.

The goal of software evolution is to produce high quality changes to software that meet user needs in a manageable and efficient manner. Effective software evolution processes and tools are critical to achieving this goal.
