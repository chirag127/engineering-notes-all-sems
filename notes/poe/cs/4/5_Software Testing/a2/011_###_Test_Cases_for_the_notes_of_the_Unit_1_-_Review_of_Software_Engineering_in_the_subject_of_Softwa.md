### Test Cases for the notes of the Unit 1 - Review of Software Engineering in the subject of Software Testing

- Test cases are a set of conditions or variables under which a tester will determine whether an application under test meets requirements or works correctly.
- Test cases are designed to cover scenarios that can help identify bugs or defects in the software.
- Well-designed test cases are reusable and can be applied to multiple builds or releases of an application.
- Some tips for writing good test cases:
    - Be precise and unambiguous. Test cases should leave no room for confusion or misinterpretation.
    - Include all necessary details. Don't leave out steps or specifications that are required to execute the test case.
    - Be objective and measurable. Test cases should have definitive pass/fail criteria.
    - Automate when possible. Automated test cases can be rerun quickly and minimize manual error.
    - Group related test cases together. This can make it easier to understand and navigate test cases.
- Mnemonics: TEST - Thorough, Executable, Specific, Traceable
    - Thorough: Test cases should cover all scenarios and inputs/outputs. Leave no gaps.
    - Executable: Test cases should be actionable steps that can be run to test the software.
    - Specific: Test cases should be detailed and specific, not vague.
    - Traceable: The results of test cases should be recordable to track pass/fail and identify issues.
- Avoid unnecessary mnemonics or tricky learning techniques if they do not aid in comprehension. Simple and straightforward is best for learning fundamentals.
- Examples of test cases:
    - Test login with correct credentials
    - Test login with incorrect credentials
    - Test adding a new user
    - Test uploading a file
    - Test searching the application
    - Test boundary/edge cases (max input values, min input values, special characters, etc.)
