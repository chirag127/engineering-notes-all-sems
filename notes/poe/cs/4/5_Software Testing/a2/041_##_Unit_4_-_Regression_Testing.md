## Unit 4 - Regression Testing

Regression Testing is a type of testing to confirm that a recent program or code change has not adversely affected existing features. It ensures that the changes made to the software did not disrupt the existing functionality.

Points to remember:

1. Regression Testing is performed after making changes to the software to verify that the changes have not impacted the existing functionality.
2. It is a rerun of the previously executed tests to check for any new errors or bugs and to ensure that the software still performs as expected.
3. Often Automated Regression Testing is performed where scripts are created to rerun a suite of tests automatically. This saves time and effort.
4. If any new bugs are found, they are fixed and Regression Testing is performed again to confirm bug fixing. This cycle continues until the software is stable and functioning as expected.
5. Regression Testing is important as even small changes can sometimes disrupt the existing code and introduce new bugs. By performing regular Regression Testing, such issues can be caught early.

Advantages:

- Helps identify new bugs or errors introduced by recent changes.
- Confirms that existing features work as expected even after changes.
- Automation saves time and effort in repetitive testing.

Disadvantages:

- Can be time-consuming and repetitive.
- Automated Regression Testing requires initial effort to create scripts.
- If test cases are not comprehensive, some bugs may go undetected.

Applications: Regression Testing is commonly performed in software development and maintenance projects to ensure high quality software. It is an important part of the Software Testing Life Cycle.

Mnemonics:

- RERUN the tests - Think of Regression Testing as rerunning existing tests.
- CHECK for new bugs - Regression Testing checks if new bugs were introduced.
