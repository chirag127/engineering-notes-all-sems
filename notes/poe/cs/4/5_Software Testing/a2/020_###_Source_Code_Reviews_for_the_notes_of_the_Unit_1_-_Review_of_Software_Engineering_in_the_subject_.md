### Source Code Reviews for the notes of the Unit 1 - Review of Software Engineering in the subject of Software Testing

Source code review is a systematic examination of the source code to find and fix the defects. It helps to improve the quality of the software.

Points to cover in source code review:

- Code clarity: The code should be easy to read and understand. Use meaningful names for variables and functions. Remove unnecessary complexities.
- Correctness: The logic should be correct as per the requirements. Check for logical errors, incorrect calculations or comparisons, etc.
- Security: Check for vulnerabilities like buffer overflows, SQL injections, etc. and get them fixed.
- Performance: Review the code for ineffective algorithms or solutions which may impact the performance. Optimize the code for efficiency.
- Code convention: The code should follow standard conventions and styles like proper indentation, commenting, etc. This increases readability and maintainability.
- Memory management: Check for proper allocation and de-allocation of memory to avoid leaks or inefficient usage of memory.

Tips for effective source code review:

- Review the code in small chunks instead of the whole code at once. This makes review more thorough.
- Have a checklist of what to look for to stay focused.
- Understand the requirements and functionality of the code properly before starting the review.
- Keep an open mind and look for both positives and negatives in the code. Provide constructive feedback.
- Test the code and check if it is working as expected. This aids in finding logical flaws.
- Note down the issues found and get them resolved. Follow up to ensure proper fixes are done.

Source code review is a powerful technique to improve code quality if done systematically and effectively. It spreads knowledge across the team and enables collective code ownership. Continuous review of code leads to more robust and reliable software.
