### Regression Test cases selection for the notes of the Unit 4 - Regression Testing in the subject of Software Testing

The following points can be considered for selecting regression test cases:

1. **Test cases for previously fixed bugs:** Test cases which detected bugs earlier should be selected for regression testing to ensure that the bug is fixed and has not resurfaced.
2. **Test cases for key areas of the system:** Select test cases that exercise key areas or important functionality or business logics of the system. This helps to identify if any impact has occurred to critical parts of the system due to changes.
3. **Representative test cases:** Select test cases that exercise typical and common scenarios. This helps to uncover common issues and ensures basic functionality is working.
4. **Stress and boundary test cases:** Select stress and boundary value test cases to test the system under extreme conditions and verify that functionality at boundaries is working fine. For example, maximum and minimum input values or input values at boundaries of validity.
5. **Test cases with high priority and severity:** Select test cases which have high priority and severity to focus testing efforts on critical areas of the system. This ensures that major defects are identified early.

**Mnemonics:**
- PREM: Previous bugs, Representative scenarios, Extreme conditions, Main functionality
- PEST: Previous bugs, Essential scenarios, Stress scenarios, Top priority

**Advantages:** Helps uncover regression defects early, focuses testing efforts, verifies critical functionality

**Disadvantages:** May miss some areas if only select test cases are chosen, manual selection of test cases can be time-consuming for large systems
