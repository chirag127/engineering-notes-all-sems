### Risk Analysis for the notes of the Unit 4 - Regression Testing in the subject of Software Testing

- Risk analysis is performed to identify the potential risks in the software that can affect the quality of the product and cause business loss.
- Some of the risks that can be identified in regression testing are:
- Functional risks: There can be risks of introduction of new bugs or defects in the functionalities that were working fine previously due to recent code changes. These can be identified by thoroughly regression testing all the functionalities.
- Performance risks: There can be risks of degradation in performance of the software due to recent code changes or upgrades. Performance regression testing is done to identify such risks and ensure that the performance criteria are met.
- Compatibility risks: There can be risks of the software becoming incompatible with other softwares or platforms due to recent upgrades or changes. Compatibility regression testing is done to mitigate such risks.
- Mnemonics:
- Functional bugs: Code changes can lead to functional glitches
- Performance lags: Upgrades can lead to performance drags
- Compatibility breaks: Changes can lead to compatibility flakes

- Advantages: Helps identify and mitigate the risks early thereby reducing the overall cost of fixing the bugs or issues later.
- Disadvantages: Regression testing requires a lot of time and effort. As the size of the software increases, the regression testing effort also increases exponentially leading to more time and cost.
- Examples: Regression testing a shopping cart functionality after enhancing the payment gateway, regression testing a software's performance after increasing the database size, regression testing a software's compatibility with various browsers and devices after upgrading the UI framework.
