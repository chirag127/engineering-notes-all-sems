### Test Data for the notes of the Unit 5 - Software Testing Activities in the subject of Software Testing

1. Test data refers to the input values that are given to the software under test to validate its functionality and performance.
2. Test data can be categorized into following types:
	- Valid input: The input which satisfies all the requirements and conditions specified for a software under test. For example, a valid username and password.
	- Invalid input: The input which violates the specifications and conditions of a software under test. For example, an invalid username or password.
	- Extreme values: Input values which lie on the boundaries of valid input domain. For example, maximum and minimum values in a range.
	- Boundary values: Input values which lie on the boundaries of equivalence partitions. For example, values which change the processing logic.
	- Special values: Reserved input values which need special handling. For example, NULL values in databases.
3. Test data can be generated in following ways:
	- Using requirements specifications: Extract test data directly from functional/non-functional requirements.
	- Using knowledge of the application: Use data with specific characteristics which can reveal defects. For example, use very long strings for buffer overflow testing.
	- Using commercially available tools: Use tools like data generators and fuzzers to generate large volumes of data.
	- Using captured production data: Use real data from production systems for more realistic testing. However, it may lack coverage of invalid and boundary scenarios.
