### Scheme for the notes of the Unit 4 - Regression Testing in the subject of Software Testing

1. Introduction to Regression Testing
- Regression Testing is a type of software testing to confirm that a recent program change has not adversely affected existing features.
- It ensures that the software application is stable even after recent code changes or updates.
- It is done after enhancement, maintenance or bug fixes to ensure that the changes have not introduced new bugs or impacted the existing functionality.
- Mnemonic: Re-check the REGress, to avoid the MESS.

2. Reasons for Regression Testing
- To ensure high quality software and user experience.
- To minimize the risks from introducing new bugs due to changes in code.
- To check if the recent changes have working as intended and not impacted the existing functionality.
- To confirm that the software is reliable even after updates and can be deployed to users.

3. Types of Regression Testing
- Unit Regression Testing - Testing individual units or components.
- Partial Regression Testing - Testing a partial system with few components integrated.
- Complete Regression Testing - Testing the whole system.
- Selective Regression Testing - Testing only the affected areas of the software due to recent changes.

4. Process of Regression Testing
- Review the changes made to the software - Code, configuration, environment, etc.
- Identify the areas of the software that may get affected by the changes.
- Select the type and scope of regression testing required - Unit, partial, complete or selective.
- Execute the regression test cases and analyze the results.
- Report any bugs or issues noticed.
- Retest the defects and ensure fixes before deployment.
