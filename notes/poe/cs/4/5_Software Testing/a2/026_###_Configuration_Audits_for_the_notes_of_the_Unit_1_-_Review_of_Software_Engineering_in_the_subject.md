### Configuration Audits for the notes of the Unit 1 - Review of Software Engineering in the subject of Software Testing

Configuration audits are performed to verify that the software product complies with the specifications and requirements and is ready for the next phase of testing or deployment. The key points to cover in configuration audits are:

- Verification of the software build: Check that the correct software build is deployed and no interim or incorrect builds have crept in. Check version numbers, build dates, etc. to confirm the correct build is being tested.
- Compliance with specifications: Verify that all functional and non-functional specifications have been implemented correctly in the build. Check for any missed or partially implemented features.
- Code changes and migrations: Ensure that any code changes or code migrations have been done correctly and as per the requirements. Verify through code reviews or testing if required.
- Correctness of dependencies and integrations: Confirm that all external dependencies and internal module integrations have been implemented correctly. Check for any broken or incorrect integrations or interfaces.
- Documentation updates: Check if all relevant documentation like user manuals, design specifications, etc. have been updated with the latest changes made to the software build.
- Readiness for testing/deployment: Confirm if the build is ready for testing or deployment. Check if any high severity defects are present in the build and if all necessary testing has been completed successfully.

Some advantages of configuration audits are:

- They help detect errors and issues early and reduce defect leakage to subsequent phases.
- They ensure continuity and consistency across software builds.
- They reduce risks by verifying readiness for testing and deployment.

Overall, configuration audits should be performed meticulously as they determine if the software product is ready for the next stage in the development lifecycle.
