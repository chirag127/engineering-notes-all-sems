### Exploratory Testing

- Exploratory Testing is an informal software testing technique. 
- It is not based on formal test cases and test scripts. 
- The tester learns about the system and tests it while exploring the software. 
- The tester executes test cases and notes down defects and also learns about the system in the process. 
- Some key points about Exploratory Testing:

* It is performed without formal test cases and test documentation.
* The tester learns and understands the system on the go and executes tests simultaneously.
* It works well for complex systems where comprehensive test documentation is difficult to produce.
* It complements other testing techniques like automated testing or scripted testing.
* Bug finding ability depends on the skill and knowledge of the tester.
* It is a hands-on approach and suits agile methodologies.

- Advantages: 
    - Can discover unexpected defects
    - Flexible and can be performed early
    - Cost effective as it does not require detailed planning and documentation
- Disadvantages:
    - Dependence on individual tester's skills
    - Difficult to measure test coverage as it is unstructured
    - May miss less obvious defects if the tester does not thoroughly explore the system

- Mnemonics: EXPLORE the software to FIND bugs

- Some tips for effective Exploratory Testing:
    - Have a broad and open mindset
    - Note down any bugs or issues encountered
    - Try different input combinations and data
    - Think from an end user's perspective
    - Check for performance issues and memory leaks too
    - Document the key steps to reproduce bugs

- Overall, Exploratory Testing is a useful technique to complement other testing methods and to discover unexpected bugs in a hands-on manner. It is well suited for agile methodologies but may require skilled testers to be effective.
