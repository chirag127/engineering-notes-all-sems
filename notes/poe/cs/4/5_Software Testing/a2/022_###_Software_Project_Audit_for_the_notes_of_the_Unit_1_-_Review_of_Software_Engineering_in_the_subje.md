### Software Project Audit for the notes of the Unit 1 - Review of Software Engineering in the subject of Software Testing

Software Project Audit is the systematic examination of a software product, service, or system to evaluate whether or not it complies with specified requirements and to identify areas where requirements are not met.

Some of the key points to cover in Software Project Audit are:

- Review the software requirements specification (SRS) document and verify that all requirements have been implemented correctly.
- Review the design documents and verify that the software has been developed as per the design. Check for any deviations and get them corrected.
- Review the code for correctness, efficiency, and maintainability. Check for coding standards compliance, memory leaks, etc.
- Review the testing process and artifacts. Verify test cases have been written to cover all requirements. Check for adequate test coverage.
- Review user manuals and other documentation to ensure completeness, accuracy, and easy understandability.
- Interview the project team and stakeholders to uncover any issues or areas of concern.
- Evaluate the software's performance, security, and quality attributes.
- Provide recommendations and suggest corrective actions wherever required.

Some advantages of Software Project Audit are:

- Identification of defects and issues early on.
- Alignment of the actual product with the specified requirements.
- Improvement in software quality, reliability, and maintainability.
- Learning opportunities for the team to improve future projects.

Some disadvantages of Software Project Audit are:

- Can be time-consuming and tedious for large, complex projects.
- Requires highly skilled auditors with technical expertise.
- Can be an expensive process, especially if done repeatedly.

**Mnemonics:**

- SAFe PRIDE - Software Audit For Engineering Product Review & Improvement For Development & Enhancement

**Notes:** Keep the audit team independent of the development team. Schedule audits at major milestones and at the end of the project. Take corrective actions on the recommendations provided.
