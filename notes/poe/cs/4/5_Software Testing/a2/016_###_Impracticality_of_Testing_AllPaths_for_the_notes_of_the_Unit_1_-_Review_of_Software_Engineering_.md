### Impracticality of Testing AllPaths for the notes of the Unit 1 - Review of Software Engineering in the subject of Software Testing

- It is impossible to test all possible paths through a software due to following reasons:
- The number of possible paths increases exponentially with the number of decisions in the software. Even for a small software with 10-20 decisions, the number of possible paths can run into thousands or millions. It is not feasible to test all paths in a limited time frame.
- The cost of testing all paths is prohibitive as it will take an enormous amount of time and effort. The cost will far outweigh the benefits due to impracticality.
- Some paths may never get executed in practice. For example, a path with an unlikely combination of inputs may never get executed by users. It is not useful to test such paths that are rarely executed or unimportant from usage perspective.
- It leads to inappropriate allocation of testing resources. The resources should instead be focused on testing the most important and frequently used paths thoroughly instead of trying to cover all paths superficially.
- Mnemonics: Too many paths, too little time! Focus on important paths, not all paths.

Thus, it is impractical and not useful to aim to test all possible paths through a software. The testing resources should be utilized to test the significant and frequently used paths in depth to uncover maximum defects. Trying to test all paths is an inefficient strategy which leads to poor allocation of testing resources.
