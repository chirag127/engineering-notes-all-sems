## Unit 3 - Structural Testing

Structural testing is a type of software testing that focuses on the internal structure of the software being tested. It involves testing individual components or modules of the software to ensure that they function as intended and work together properly. 

Here are some important points to understand about structural testing:

- Structural testing is also known as white-box testing, because it involves examining the internal workings of the software being tested.
- The goal of structural testing is to identify defects or errors in the software code, such as missing or incorrect statements, logic errors, or other issues that could cause the software to behave improperly or produce incorrect results.
- There are several techniques that can be used to perform structural testing, including statement coverage, branch coverage, condition coverage, and path coverage. Each of these techniques involves tracing the execution of the software code to ensure that all statements, branches, conditions, or paths are tested.
- Statement coverage involves testing each individual statement in the code to ensure that it is executed at least once during testing.
- Branch coverage involves testing each possible branch in the code, to ensure that all possible outcomes are tested.
- Condition coverage involves testing each possible combination of conditions in the code, to ensure that all possible scenarios are tested.
- Path coverage involves testing every possible path through the code, to ensure that all possible sequences of statements and branches are tested.
- Structural testing is often performed by software developers or testers who are familiar with the code and can identify potential issues or areas of concern.
- One advantage of structural testing is that it can identify defects or errors that may not be caught by other types of testing, such as functional testing or user acceptance testing.
- One disadvantage of structural testing is that it can be time-consuming and complex, especially for large or complex software systems.
- Mnemonic: A helpful mnemonic for remembering the four techniques for structural testing is "SBCP" - Statement coverage, Branch coverage, Condition coverage, and Path coverage.

Examples of applications of structural testing include:

- Testing individual functions or components of a software system to ensure that they work correctly and integrate properly with other components.
- Testing the overall behavior of a software system by tracing the execution of the code and verifying that it produces the expected results.
- Identifying and correcting defects or errors in software code, to improve the quality and reliability of the software.

Overall, structural testing is an important technique for ensuring the quality and reliability of software systems, and should be included as part of a comprehensive software testing strategy.
