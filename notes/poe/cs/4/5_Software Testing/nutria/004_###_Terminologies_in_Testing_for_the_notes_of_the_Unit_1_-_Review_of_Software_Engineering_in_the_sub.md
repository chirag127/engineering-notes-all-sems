
### Terminologies in Testing for the notes of the Unit 1 - Review of Software Engineering in the subject of Software Testing

1. **Test Case**: A test case is a set of conditions or variables under which a tester will determine whether a system under test satisfies requirements or works correctly.

2. **Test Suite**: A test suite is a collection of test cases that are used to test a software program to show that it has some specified set of behaviours.

3. **Test Plan**: A test plan is a document detailing the objectives, scope, approach and focus of a software testing effort. It identifies test items, the features to be tested, the testing tasks to be performed, the personnel responsible for each task, and any risks requiring contingency planning.

4. **Test Data**: Test data is any data that is used by a tester to verify that a system is functioning correctly. Test data can be either valid or invalid.

5. **Test Environment**: A test environment is a set of processes, tools and resources used to test the functionality of a system. It includes the hardware, software, network and other physical components that are necessary for the system to operate.

6. **Test Strategy**: A test strategy is a document that outlines the approach to be taken when testing a system. It describes the scope of the testing to be performed, the resources to be used, and the objectives and goals of the testing effort.

7. **Test Script**: A test script is a set of instructions that a tester uses to execute a test case. It is usually written in a scripting language such as Bash, Python, or Perl.

8. **Test Metrics**: Test metrics are measurements used to evaluate the effectiveness of a testing effort. These metrics can include the number of test cases executed, the number of defects found, and the time taken to execute the tests.

9. **Code Coverage**: Code coverage is a measure of how much of the source code of a program has been tested. It is usually expressed as a percentage and is used to determine the effectiveness of a testing effort.

10. **Regression Testing**: Regression testing is the process of retesting a system after changes have been made to ensure that the changes have not introduced any new bugs or caused any existing bugs to resurface.
