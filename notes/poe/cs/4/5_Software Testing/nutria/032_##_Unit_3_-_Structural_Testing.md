
## Unit 3 - Structural Testing

Structural Testing is a type of software testing that is used to validate the structure of the code. It focuses on the internal structure of the application and how the different components interact with each other. Structural Testing is used to ensure that the code is written correctly and is free of errors.

**Mnemonics and Learning Tricks**

One way to remember the different components of Structural Testing is to use the acronym S.T.A.R.T.:

* **S**tructure - Validate the structure of the code.
* **T**est - Test the code to ensure it works correctly.
* **A**nalyze - Analyze the code to check for errors.
* **R**efactor - Refactor the code to make it more efficient.
* **T**race - Trace the code to identify any problems.

**Advantages**

* Structural Testing helps to identify errors in the code before they become problems.
* It can be used to find bugs and other problems that would otherwise be difficult to detect.
* Structural Testing can be used to ensure that the code is written in a way that is easy to understand and maintain.

**Disadvantages**

* Structural Testing can be time consuming and expensive.
* It can be difficult to test all possible scenarios.
* It can be difficult to find all the errors in the code.

**Examples**

* Testing the structure of an object-oriented program.
* Testing the structure of a database query.
* Testing the structure of a web service.

**Applications**

Structural Testing can be used in a variety of applications, including:

* Web applications
* Mobile applications
* Desktop applications
* Database applications
* Embedded systems
