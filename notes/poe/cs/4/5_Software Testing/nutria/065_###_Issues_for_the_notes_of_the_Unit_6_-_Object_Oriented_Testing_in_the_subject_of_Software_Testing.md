
### Issues for the notes of the Unit 6 - Object Oriented Testing in the subject of Software Testing

Object Oriented Testing is a type of software testing that focuses on the structure and behavior of software objects. It is used to verify that the objects interact with each other in the expected manner.

The main issues associated with Object Oriented Testing are:

1. **Testability:** Object Oriented Testing can be difficult to test due to the complexity of the objects and the interactions between them.

2. **Performance:** Object Oriented Testing can be slow due to the large number of objects and interactions that must be tested.

3. **Maintainability:** Object Oriented Testing can be difficult to maintain due to the complexity of the objects and the interactions between them.

4. **Readability:** Object Oriented Testing can be difficult to read due to the complexity of the objects and the interactions between them.

5. **Scalability:** Object Oriented Testing can be difficult to scale due to the complexity of the objects and the interactions between them.

To help with these issues, there are a few mnemonics and learning tricks that can be used when testing object-oriented software. 

* **S.T.A.R.**: This mnemonic stands for **S**tructure, **T**esting, **A**nalysis, and **R**eporting. It helps to remind the tester to consider the structure of the objects, perform tests, analyze the results, and report the findings.

* **A.C.E.**: This mnemonic stands for **A**nalysis, **C**onfiguration, and **E**valuation. It helps to remind the tester to analyze the objects, configure the tests, and evaluate the results.

* **C.O.D.E.**: This mnemonic stands for **C**onstruction, **O**bjects, **D**esign, and **E**valuation. It helps to remind the tester to construct the objects, design the tests, and evaluate the results.

By using these mnemonics and learning tricks, testers can better understand the structure and behavior of objects and ensure that the software is functioning as expected.
