## Unit 2 - Cloud Enabling Technologies Service Oriented Architecture

Service Oriented Architecture (SOA) is an architectural style that organizes software applications as a set of services that can be consumed by other applications. In SOA, services are provided to form applications that make use of the services.

Some key points about SOA are:

- Services are loosely coupled, autonomous units that provide functionality to other applications.
- Services communicate with each other by passing data in a well-defined, shared format.
- Services are discoverable by other applications.
- Services can be reused across multiple applications.
- The boundaries of services are explicit and the interactions between services are based on open protocols and standards.

Advantages of SOA:

- Increased interoperability between systems.
- Flexibility as services can be reused and recombined to create new applications.
- Scalability as load can be balanced across multiple service instances.
- Potential for cost savings through reuse of services.
- Language and platform independence. Services can be developed in any language and executed on any platform.

Disadvantages of SOA:

- Can be complex to implement due to distribution of processes and data across multiple services.
- Testing and debugging can be challenging due to dependency on multiple services.
- Performance overhead due to remote calls and data transformations.
- Versioning of services and managing dependencies between service versions can be difficult.
- Security implications around exposing services and data externally.

Examples of SOA implementations:

- Microsoft .NET Services
- IBM WebSphere
- Oracle Fusion Middleware
- Amazon Web Services

SOA is enabling for cloud computing as it allows applications and resources to be exposed as services that can be accessed over a network. This service-oriented approach aligns well with the cloud model of on-demand access to computing resources.
