### Pattern-based Architecture for Service-oriented Applications

Some of the key patterns used in service-oriented architecture are:

- Service Layer Pattern: This pattern suggests that business logic should be encapsulated in services. Services are coarse-grained, loosely-coupled, and platform/language-independent.
- Service Façade Pattern: This pattern suggests using a unified service interface to access multiple underlying services. The façade service provides a single coarse-grained service interface to the client.
- Service Requester Pattern: This pattern suggests using a unified service requester to access multiple services in a standard way. The service requester handles service lookup, invocation, and other common tasks.
- Service Agent Pattern: This pattern uses an intermediary agent to perform tasks on behalf of a service or a client. Agents can be used for tasks like filtering, aggregation, monitoring, etc.
- Service Hosting Environment Pattern: This pattern suggests using a standardized hosting environment to deploy and execute services. The hosting environment provides common services to the hosted services like threading, persistence, security, logging, administration, etc.

Some pros of using a pattern-based architecture:

- Patterns promote reuse and standardization leading to faster development and maintenance.
- Patterns provide solutions to commonly occurring problems.
- Patterns can be composed together to solve complex problems.

Some cons of using a pattern-based architecture:

- It can be difficult to choose the right patterns for a problem.
- Applying patterns in the wrong context can lead to unwanted complexity and inefficient solutions.
- Documentation and comprehension of patterns may not always be easy.

Mnemonics and learning tricks:

- SLAP - Service Layer, Façade, Agent, Pattern (to remember the key patterns)
- SOHOST - Service Oriented HOSTing environment pattern (to remember the hosting environment pattern)
