### Nonfunctional Properties for Services

The nonfunctional properties for services are as follows:

- Performance: The time taken to execute a service. It should have fast response time and high throughput. Eg: Caching data, Load balancing, replication, etc can improve performance.
- Scalability: The capability of a system to handle increased load. Eg: Adding more servers, using load balancers, etc.
- Reliability: The capability of the system to operate continuously without failure. Eg: Using redundant components, failover mechanisms, etc.
- Availability: The degree to which a system or component is operational and accessible when required for use. Eg: Using redundant infrastructure and providing failover capabilities.
- Security: The protection of the system and data from unauthorized access. Eg: Authentication, authorization, encryption, etc.
- Maintainability: The ease with which a software system can be modified to correct faults, improve performance or other attributes, or adapt to a changed environment. Eg: Well-documented code, logging capabilities, monitoring tools, etc.

Some mnemonics and learning tricks for remembering the nonfunctional properties:

- **PARASMS**: Performance, Availability, Reliability, Scalability, Maintainability, Security
- **PERFORM**: Performance, Efficiency, Reliability, Flexibility, Operability, Maintainability, Manageability

Advantages of considering nonfunctional properties:

- The system can handle load and scale well.
- The system will be robust and reliable with less downtime.
- The system and data will be secure from threats.
- The system can be easily maintained and errors can be handled.

Disadvantages of ignoring nonfunctional properties:

- The system may crash or become unresponsive under heavy load.
- The system may not be reliable and experience frequent downtimes.
- The system and data can be vulnerable to attacks due to lack of security.
- The system may be difficult and time-consuming to maintain and update.
