
### Standards and Guidelines for SOA 

This section provides an overview of the standards and guidelines for Service Oriented Architecture (SOA) for the notes of Unit 1 - Introduction: SOA and MSA Basics in the subject of Service Oriented Architecture. 

##### Mnemonics and Learning Tricks

* SOA: Service Oriented Architecture 
* MSA: Microservice Architecture 

##### Overview 

SOA is an architectural style that defines how to design distributed applications and services. It is based on the principles of service-orientation, which are designed to help developers create loosely coupled distributed applications that are easy to maintain and scale. SOA is a way of designing applications that allows them to be broken down into smaller, more manageable components, which can then be reused in other applications. 

MSA is an architecture style that is based on the principles of SOA. It is designed to help developers create applications that are highly scalable and resilient. It is based on the idea of breaking down applications into smaller, independent components, which can then be deployed and managed independently. 

##### Benefits 

* SOA and MSA provide a way to design applications that are more flexible and easier to maintain. 
* SOA and MSA provide a way to design applications that are more resilient and can handle large workloads. 
* SOA and MSA make it easier to develop and deploy applications across multiple platforms. 
* SOA and MSA make it easier to integrate applications with existing systems. 
* SOA and MSA make it easier to create applications that are more secure. 

##### Disadvantages 

* SOA and MSA can be difficult to implement in large organizations. 
* SOA and MSA can require a lot of time and effort to design and develop. 
* SOA and MSA can be difficult to maintain and manage. 
* SOA and MSA can be expensive to implement.
