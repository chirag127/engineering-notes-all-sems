## Unit 3 - Permissioned Blockchains

Permissioned blockchains are private blockchains where the consensus process is controlled by a pre-selected set of nodes. In permissioned blockchains, access to the network is restricted to only authorized nodes.

- Nodes in the network are known, identified and vetted
- Only authorized nodes can participate in the consensus process
- The consensus process can be optimized for performance since the number of nodes is limited
- Identity of nodes is known, allowing enforcement of rules around participation in the network
- Use cases include financial transactions, record-keeping within organizations, etc. where privacy and restricted access are important

Advantages:
- Faster transaction times since a limited number of nodes participate in the consensus process
- Greater privacy and control as only authorized nodes have access
- Ability to integrate with existing systems and regulations e.g. GDPR compliance, KYC/AML processes

Disadvantages:
- Centralization - restricted access means loss of some decentralization
- Single points of failure - if authorized nodes go down or are compromised, the blockchain network is affected
- Less resilient to attacks - with fewer nodes, permissioned blockchains may be more vulnerable to attacks

Mnemonics and learning tricks:
- Think of permissioned blockchains like private clubs - only members are allowed in
- Transactions on permissioned blockchains are like transactions in a company's database - private and restricted to certain individuals

Examples: Fabric, Quorum, R3 Corda

Applications: Financial transactions, supply chain tracking, healthcare records, etc.
