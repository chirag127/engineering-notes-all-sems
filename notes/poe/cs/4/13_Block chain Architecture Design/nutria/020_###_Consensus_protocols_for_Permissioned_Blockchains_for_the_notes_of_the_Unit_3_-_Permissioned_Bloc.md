
### Consensus protocols for Permissioned Blockchains for the notes of the Unit 3 - Permissioned Blockchains in the subject of Block chain Architecture Design

Permissioned blockchains require a consensus protocol to ensure that all participants agree on the same state of the ledger. The consensus protocol determines how transactions are validated, how the ledger is updated, and how conflicts are resolved.

The most common consensus protocols used in permissioned blockchains are:

- Practical Byzantine Fault Tolerance (PBFT): PBFT is a consensus protocol that provides reliability in asynchronous systems, meaning that it can tolerate faults and still reach consensus. It is used in permissioned blockchains to ensure that all participants agree on the same state of the ledger.

- Proof of Work (PoW): PoW is a consensus protocol that requires participants to solve a cryptographic puzzle in order to validate transactions and update the ledger. It is used in permissioned blockchains to ensure that all participants agree on the same state of the ledger.

- Proof of Stake (PoS): PoS is a consensus protocol that requires participants to stake a certain amount of cryptocurrency in order to validate transactions and update the ledger. It is used in permissioned blockchains to ensure that all participants agree on the same state of the ledger.

- Delegated Proof of Stake (DPoS): DPoS is a consensus protocol that requires participants to stake a certain amount of cryptocurrency in order to validate transactions and update the ledger. It is used in permissioned blockchains to ensure that all participants agree on the same state of the ledger.
