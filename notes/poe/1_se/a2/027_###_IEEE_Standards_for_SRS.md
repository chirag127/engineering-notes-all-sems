### IEEE Standards for SRS

The IEEE has established a standard for software requirements specifications, IEEE 830-1998. The standard proposes a generic template for SRS and defines the following major sections:

1. Introduction
- Purpose
- Scope
- Definitions, Acronyms, and Abbreviations
- References
- Overview

2. Overall Description
- Product Perspective
- Product Features
- User Characteristics
- General Constraints

3. System Features
- Functional Requirements
- External Interface Requirements
- Performance Requirements
- Logical Database Requirements
- Design Constraints
- Software System Attributes
- Organizing The Functional And Performance Requirements

4. External Interface Requirements
- User Interfaces
- Hardware Interfaces
- Software Interfaces
- Communications Interfaces

5. Other Requirements
- System Quality
- Safety
- Reliability
- Security
- Legal
- Privacy
- Cultural and Political
- Regulatory

Some tips/mnemonics to remember the sections:

- INTRO: Introduction
- OD: Overall Description
- SYS: System Features
- EXT: External Interface Requirements
- OTHER: Other Requirements

Advantages of following the standard:
- Provides a systematic approach to capture requirements
- Reduces ambiguity and improves understanding
- Facilitates review and validation
- Aids traceability

Disadvantages:
- May be overwhelming for small projects
- Difficult to customize for every project
- Does not define how to actually capture the requirements
