### Information Modelling in Software Requirement Specification (SRS)

Information modelling in SRS involves -

1. Identifying the main entities (objects/components) of the software system. For e.g. - User, Product, Order, etc.
2. Determining attributes of each entity. For e.g. - User may have attributes like Name, Age, Address, etc. Product may have attributes like Price, Quantity, etc.
3. Specifying relationships between different entities. For e.g. - A User places an Order for one or more Products.
4. Representing the information model visually using diagrams like class diagrams, entity-relationship (ER) diagrams, etc.

**Mnemonics** - "Entities, Attributes, Relationships" or "EAR" can be used to remember the 3 key steps in information modelling.

**Advantages** - Provides a abstract view of data in the system. Helps identify data requirements and interactions between data. Can be used to create database schema.

**Disadvantages** - May be time-consuming for large systems. Requires technical knowledge to create accurate diagrams and models.

**Applications** - Useful in database design, object-oriented programming, etc.
