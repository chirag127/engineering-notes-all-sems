## Unit 2 - Software Requirement Specifications (SRS)

### What is SRS?
- SRS stands for Software Requirement Specification.
- It is a detailed description of the intended purpose and environment for a software system.
- It basically captures the functional and non-functional requirements of the software.
- It serves as a communication tool between the clients, developers and testers.

### Contents of SRS
- Introduction
- Overall description
- External interface requirements
- Functional requirements
- Performance requirements
- Logical database requirements
- Design constraints
- Software system attributes
- Other requirements

### Tips to write a good SRS
- Be precise and unambiguous
- Use consistent terminology
- Prioritize requirements
- Separate functional and non-functional requirements
- Include diagrams and illustrations if required
- Get it reviewed by all stakeholders

### Advantages of SRS
- Acts as a blueprint for software development
- Reduces ambiguity and misunderstanding
- Facilitates estimation and risk management
- Used for validation and verification
- Helpful in outsourcing projects

### Disadvantages of SRS
- Difficult and time-consuming to write
- Requirements may change leading to rework
- May discourage flexibility and creativity in design
- documentation can get outdated if not maintained properly
