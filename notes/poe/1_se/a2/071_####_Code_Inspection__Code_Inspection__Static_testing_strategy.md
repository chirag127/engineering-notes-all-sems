#### Code Inspection (Code Inspection) Static testing strategy

Code Inspection is a Static Testing technique in which the code is examined by a team of experts to find defects. It is a manual testing approach and does not require executing the code. The team reviews the code line by line and identifies issues, bugs, logical flaws, inefficiencies, security vulnerabilities, etc.

Advantages:
- Early detection of bugs. Issues are identified early without executing the code.
- Inexpensive as it does not require specialized tools. Only requires technical experts to review the code.
- Easy to implement and can be done at any stage of SDLC.

Disadvantages:
- prone to human errors. The issues identified depend on the skills and focus of the reviewers.
- Tedious and time-consuming for large codes. Manually going through line by line can be tiresome and inefficient for huge codes.
- Does not guarantee complete test coverage. There can still be defects left unidentified.

Mnemonics:
- 'Eyes' on code - Experts examining code
- 'Manual' testing - no tools or automation required

 Applications:
- Reviewing critical codes
- Verifying security and efficiency
- Early bug detection

To summarize, Code Inspection is a manual Static Testing technique in which a team of experts reviews the code line by line to identify bugs, issues, and flaws. Though inexpensive and easy to implement, it can be prone to human errors and time-consuming for large codes. It is best suited for reviewing critical codes and detecting bugs early.
