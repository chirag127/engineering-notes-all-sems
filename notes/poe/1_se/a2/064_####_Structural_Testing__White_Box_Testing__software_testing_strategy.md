#### Structural Testing (White Box Testing) software testing strategy

- Structural Testing, also known as White Box Testing, is a software testing technique that validates the internal structure of the code.
- It is based on the examination of programming code and uses code knowledge to identify inputs that will exercise paths through the code.
- The key techniques used in Structural Testing are:
- Control Flow Testing - Ensuring that all conditional logic and loops are tested
- Data Flow Testing - Ensuring that all possible paths through the code are executed
- Path Testing - Testing to traverse each path through the code at least once
- Branch Testing - Testing each decision or branch point in the code
- Some Mnemonics and learning tricks for remembering are:
- Think "Internal" for White Box Testing as it checks internal coding structure
- Code paths, conditions and loops are checked thoroughly like a "microscope"
- Two types of paths - across conditionals (branches) and loops (iterations)
- "Coverage" in terms of branches, conditions, paths and statements is measured
- Pros: Pinpoints coding issues, complements Black Box Testing, can be automated
- Cons: Requires coding knowledge, may require complex paths to be tested
- Used for critical software to check robustness and identify complex bugs
