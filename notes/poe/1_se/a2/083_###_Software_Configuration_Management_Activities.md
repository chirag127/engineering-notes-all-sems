### Software Configuration Management Activities

The key Software Configuration Management (SCM) activities are:

1. Configuration Identification - Identifying the configuration items that make up the system. This includes baselining the items and maintaining the baselines. Mnemonic: I (dentify) C (onfiguration) I (tems).
2. Configuration Control - Controlling changes to the configuration items. This includes formally approving changes and ensuring all changes are properly tracked and recorded. Mnemonic: C (ontrol) C (hanges).
3. Configuration Status Accounting - Tracking and reporting the status of configuration items and change requests. This includes status accounting of changes from proposed to approved to implemented. Mnemonic: C (hange) S (tatus) A (ccounting).
4. Configuration Audit - Regularly auditing the configuration items and change records against the baselines to confirm integrity and compliance. This ensures accuracy and completeness of SCM data. Mnemonic: C (onfiguration) A (udit).
5. Configuration Verification and Validation - Verifying/validating that the product or system fulfills its intended purpose. This is done throguh reviews, inspections, testing, and analysis. Mnemonic: C (onfiguration) V&V.

Advantages:
- Maintains integrity/consistency of system.
- Supports impact analysis of changes.
- Aids defect tracking and resolution.
- Enables reproducibility.

Disadvantages:
- Can be bureaucratic and add overhead.
- Baseline management can be complex for large systems.
- Tool support may be required for large systems.
