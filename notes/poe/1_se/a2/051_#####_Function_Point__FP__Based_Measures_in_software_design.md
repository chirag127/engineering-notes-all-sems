##### Function Point (FP) Based Measures in software design

Function Point Analysis (FPA) is a method to measure software size based on functionality. It counts various functionalities of the system and assigns weights to them to compute an overall functional size.

Some key points about Function Point Analysis:

- It is a logical, not a physical measure of software size. It focuses on what the system does, not how it does it.
- It counts the inputs, outputs, inquiries, files, and interfaces of the system. Each is assigned a weight, and the total weighted count becomes the system's function point count.
- It can be used to estimate effort, cost, and schedule for software development and to compare systems.
- It is a language-independent metric as it focuses on functionality.
- It is best suited for data- and transaction-intensive systems. It may be difficult to apply to artificial intelligence or real-time systems.

Some mnemonics to remember the components counted in FPA:

- DICE - Data, Interfaces, Complexity, External inputs
- FIPS - Files, Interfaces, Processing, External outputs

Advantages:

- It is a logical measure of software size independent of technology or language.
- It is a structured method with explicit rating procedures and counting rules.
- It can be used early in SDLC to estimate effort and cost.

Disadvantages:

- It can be difficult to apply and time-consuming to compute, especially for large systems.
- The weighting system is based on judgments that can introduce inaccuracies.
- It works best for data- and transaction-intensive systems but may not be suitable for other types of systems.
