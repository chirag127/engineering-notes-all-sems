### Review and Management of User Needs in Requirement Engineering Process in SRS

- User needs are the core aspects of software requirement specification (SRS) document. Hence, it is important to review and manage user needs effectively in the requirement engineering process.

- Some key steps to review and manage user needs are:

1. Elicit user needs from multiple stakeholders: Requirements should be gathered from all the stakeholders including end users, customers, managers, etc. This helps in getting a holistic view of the system needs.

2. Remove ambiguity and duplication: The elicited user needs may be ambiguous or duplicated. These should be identified and removed by clarifying the needs or consolidating the duplicated ones.

3. Prioritize user needs: Not all user needs have the same importance. Hence, the elicited needs should be prioritized based on factors like criticality, frequency of use, dependencies, etc. This helps in determining high priority needs to be addressed first.

4. Verify and validate user needs: The elicited and documented user needs should be verified and validated by demonstrating prototypes or taking user feedback. This ensures that the captured needs are accurate and complete.

5. Allocate user needs to releases: The prioritized user needs are allocated to different releases of the software. Critical and high priority needs are addressed in early releases while less important needs are pushed to later releases. This helps in effective management of user needs based on available resources and timelines.

- Overall, reviewing and managing user needs effectively is crucial to produce a comprehensive and viable SRS that meets the key objectives and constraints of the system in a pragmatic way. Using the above steps helps in this endeavour.
