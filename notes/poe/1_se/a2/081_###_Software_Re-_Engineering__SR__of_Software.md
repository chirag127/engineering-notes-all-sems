### Software Re-Engineering (SR) of Software

Software Re-Engineering (SR) is the examination and alteration of a system to reconstitute it in a new form and the subsequent implementation of the new form. SR is usually initiated to reduce problems with software systems due to their deterioration over time or due to other issues like inefficient software architecture, software errors or obsolete components.

The steps involved in SR are:

1. Reverse Engineering - Understanding the existing system by analyzing its documentation and code.
2. Requirements Analysis - Determining the requirements of the new system.
3. Design - Coming up with a new design for the system based on requirements.
4. Implementation - Implementing the new design.
5. Testing and integration - Testing the new components and integrating them into the system.

Advantages of SR:
- Improves software maintainability and reduces technical debt.
- Increases software reliability and quality.
- Reduces time and cost of development of new software products with similar functionality.
- Prepares software for new technologies or platforms.

Disadvantages of SR:
- Requires skilled analysts and developers.
- Can be time-consuming and expensive for large, complex systems.
- Risk of introducing new bugs or errors during re-engineering.
- If not done properly, can lead to loss of functionality or incompatibility issues.

Examples of SR:
- Re-engineering a desktop application to a web application.
- Re-designing the architecture of an application to scale better.
- Migrating software to a new technology stack or platform.
- Improving software design to enhance testability or maintainability.

Mnemonic: RDSP - Reverse, Define, Design, Program
 trick to remember the steps in SR.
