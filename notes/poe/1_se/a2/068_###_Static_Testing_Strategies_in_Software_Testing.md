### Static Testing Strategies in Software Testing

Static Testing is a type of Software Testing that is performed without executing the software. It analyzes the source code, requirements and documentation of the software to find defects.

Some popular Static Testing Strategies are:

1. Code Review: The source code is reviewed manually by a team of software developers and testers to identify bugs, defects, insecure code, violations to coding standards, etc. It is a line by line review of the code.

 Mnemonics: RASCAL - Review And Static Code Analysis Language

Advantages:
- Inexpensive
- Early detection of bugs
- Finds logical flaws and security loopholes
- Shares knowledge within the team

Disadvantages:
- Difficult to review large code bases
- Subjective and prone to human errors
- Does not check runtime behaviors

2. Walkthrough: The requirements, design or code is walked through by the author with team members. The author explains the contents and team members analyze and provide feedback.

3. Inspection: A formal evaluation of work products by a team at defined checkpoints. It has well-defined procedures, entry and exit criteria. Defects are recorded and tracked.

4. Static Code Analysis: Automated analysis of source code to detect bugs, security vulnerabilities, quality and consistency issues by using tools. It checks for conformance to coding standards and detects anti-patterns.

Advantages:
- Fast
- Scalable to large code bases
- Detects a wide range of issues

Disadvantages:
- May have false positives
- Requires additional tool setup and maintenance
- Limited to analyses that the tools are designed for
