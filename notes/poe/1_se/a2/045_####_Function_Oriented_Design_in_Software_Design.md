#### Function Oriented Design in Software Design

- In Function Oriented Design, the software is designed around functions/operations/processing logic. The primary focus is on functions and what functions are required in the software.
- The software is viewed as a set of independent functions that transform inputs into outputs. The interactions and relationships between functions are minimized.
- Each function in the software is designed independently and interactions between functions are dealt with at a later stage. This makes the design process simpler and more straightforward.
- However, this approach can lead to tightly coupled components and inefficient software if the interactions between functions are not properly handled.
- Useful Mnemonics:
    - Think about functions and processing logic first
    - What are the key functions and what do they do?
    - Design functions independently; interconnect later
- Advantages:
    - Simplicity - Easy to understand and design as primary focus is on functions
    - Components are highly cohesive as focused on single functions
- Disadvantages:
    - Can lead to tightly coupled components if interdependencies between functions not properly handled
    - May result in inefficient software if interactions between functions are neglected during initial design
- Examples: Device drivers, software libraries, etc. where primary focus is on key functions.
- Applications: Suitable for designing software which can be viewed as a collection of independent functions. Not suitable for large, complex software where interactions between components are significant.
