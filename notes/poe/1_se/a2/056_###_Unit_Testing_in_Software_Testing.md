### Unit Testing in Software Testing

Unit Testing is a type of software testing where individual units or components of a software are tested. The purpose is to validate that each unit of the software performs as designed.

A unit is the smallest testable part of any software. It can be an individual function, procedure, etc.

Unit Testing is done after the completion of a unit development. It helps to identify issues early on and reduces bugs slipping into later stages of the SDLC.

Some key points about Unit Testing:

- Focuses on testing individual units of code.
- Performed by the developers as white-box testing.
- Uses test suites to validate units. A test suite contains test cases.
- Test cases are designed to cover maximum logic paths.
- Isolated from outside components and inputs are simulated.
- Aids in software design problems detection and refactoring code.

Advantages:
- Increases software quality and reliability.
- Simpler to find and fix bugs early.
- Forces software architecture to be more modular.
- Provides documentation about the intent of code.
- Reduces time required for integration and system testing.

Disadvantages:
- Can be time-consuming to develop testing code and suites.
- Difficult to test complex interactions between components.
- Does not check for integration issues between components.

Some useful mnemonics and learning tricks:

- Think of units as Lego blocks. Assemble and test one block at a time.
- 3 C's of Unit Testing - Correctness, Completeness, Consistency.
- Red (Fail) - Green (Pass) - Refactor. The TDD approach.
- I.S.O.L.A.T.E - Input, State, Output, Logic, Access, Time, Environment.
