###### Control Flow Graphs in software design

Control flow graphs (CFGs) are a representation of all paths that might be traversed through a program during its execution. They are a formalism for describing and analyzing control flow in programs.

* A CFG is a directed graph where:
** Nodes represent basic blocks of code (straight-line code segments with only one entry and exit point)
** Edges represent control flow between basic blocks (the flow of control from one block to another)
* The start node has no incoming edges and the end node has no outgoing edges
* Useful for:
** Visualizing control flow
** Analyzing control flow (detecting loops, finding all possible execution paths, etc.)
** Optimizing code (reducing branches, common subexpression elimination, etc.)

Mnemonics for remembering parts of a CFG:
* Nodes are blocks - basic blocks of code
* Edges are control flow - flow of control between blocks
* Start is where we begin - no incoming edges
* End is where we're done - no outgoing edges

Advantages:
* Provides a clear, visual representation of control flow
* Enables formal analysis of control flow
* Useful intermediate representation for optimization

Disadvantages:
* May be more complex than source code for humans to understand
* Constructing CFGs can be challenging for complex control flow
* Does not contain data flow information - only control flow
