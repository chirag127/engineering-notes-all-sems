## Unit 3 - Software Design

- Software design refers to the process of planning a software solution to a problem. It includes low-level component and algorithm implementation issues as well as high-level architectural issues.
- The key aspects of software design are:

1. Decomposition - The process of breaking down a system into smaller parts that are more manageable and easier to understand. For example, breaking down a problem into subproblems.
2. Abstraction - The process of identifying common patterns and generalizing them into broader concepts. For example, abstracting from specific animals to the broader concept of animals.
3. Modularity - The process of partitioning a system into modules that can be designed, implemented, and tested independently.
4. Hierarchy - The process of organizing system components into a hierarchical tree structure. For example, organizing a system into main modules which consist of submodules.
5. Control hierarchy - The process of organizing system components into higher and lower levels of control. For example, implementing a system using a central controller to coordinate subsystems.

- Important software design principles include:

1. Keep the design as simple as possible.
2. Separation of concerns - Separate the system into distinct sections such as logic, input, and output, and process each section independently.
3. Loose coupling - Minimize the interdependencies between different system modules.
4. High cohesion - Maximize the functional relatedness within modules.
5. Encapsulation - Hide the implementation details of a module from other modules.
6. Modularization - Design the system as a set of smaller modules that can be implemented and tested independently.

- UML (Unified Modeling Language) is a standardized modeling language to visualize, specify, construct, and document artifacts of a software system. UML uses diagrams with symbols and arrows to represent the design of software. Some common UML diagrams are:

1. Use case diagram - Represents the interactions between the system and external users or systems.
2. Class diagram - Represents classes and the relationships between them.
3. Sequence diagram - Represents the sequence of messages exchanged between objects during a runtime scenario.
4. Activity diagram - Represents the flow of control or data in a system.
5. State machine diagram - Represents the states and transitions of a system.
