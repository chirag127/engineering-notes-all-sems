### Acceptance Testing in Software Testing

Acceptance testing is a level of software testing where a system is tested for acceptability. The purpose of this test is to evaluate the system's compliance with the business requirements and assess whether it is acceptable for delivery.

Points to remember:

- Acceptance testing is conducted by the client or the end user of the system.
- It is performed when the functional testing is completed and aims to check if the software meets the expected business requirements.
- The Acceptance test cases are based on business requirements and user expectations.
- Acceptance testing can be both black-box and white-box. Black-box tests the system's functionality while white-box tests verifies the design and implementation.
- Types of Acceptance Testing:
-- User Acceptance Testing (UAT): The system is tested by the intended users.
-- Operational Acceptance Testing (OAT): The system is tested for operational readiness by the IT team.
-- Contract Acceptance Testing: The system is tested to check if it meets the contractual obligations, requirements and specifications.
- Advantages: Verifies the system with client requirements, increases the chance of customer satisfaction and project success.
- Disadvantages: This testing is time-consuming, costly and requires active customer involvement which may not always be possible.

Mnemonics to remember:
- Think AAT for Acceptance Testing
- USER, OPERATION, CONTRACT for types of Acceptance Testing
- BBA for Black-Box and White-Box Acceptance Testing
