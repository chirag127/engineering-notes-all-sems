### Design Strategies in Software Design

Following are some of the key design strategies used in software design:

1. Decomposition: Breaking down a complex problem into smaller manageable subproblems. This makes the problem solving easier and efficient. Example: Breaking down a large software into smaller modules/components.

2. Abstraction: Hiding the complexity of lower level details and showing only essential features. This reduces complexity and focuses on what is important. Example: An API abstracts away the complex software/hardware details and provides a simple interface to the user.

3. Modularity: Dividing the system into separate modules that can be independently created and then used together. This increases organization, reuse and maintainability. Example: Dividing a software into modules/components like data access layer, business logic layer, presentation layer, etc.

4. Coupling: The degree of dependence between modules/components. Lower coupling is desirable as it reduces interdependency and increases modularity. Example: Loosely coupled components have fewer dependencies and can work independently.

5. Cohesion: The degree to which the elements inside a module/component belong together. Higher cohesion is desirable as it increases the focus and purpose of the module. Example: A component with highly cohesive methods/functions that all relate to a common task.

**Mnemonics:** CDCMA can be used to remember the first letters of the strategies - CDCMA -> Component, Decompose, Coupling, Modularize, Abstract.

**Advantages:** Easy to understand, modify, maintain and reuse the software.
**Disadvantages:** May introduce extra complexity if not implemented properly.
**Applications:** Used in software engineering to design quality software solutions in a systematic manner.
