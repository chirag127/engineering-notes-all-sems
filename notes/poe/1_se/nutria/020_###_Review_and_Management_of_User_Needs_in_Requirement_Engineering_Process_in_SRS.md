
### Review and Management of User Needs in Requirement Engineering Process in SRS

1. Requirement Engineering Process: This is a process that involves eliciting, analyzing, documenting, and managing user needs in order to create a software system that meets the user’s needs. It involves determining the user’s requirements, understanding the user’s context, and creating a system that meets the user’s needs.

2. User Needs: User needs are the needs of the users of a system. These needs can be functional, non-functional, or even emotional. User needs should be identified and documented in order to create a system that meets the user’s needs.

3. Review: Review is an important step in the Requirement Engineering Process. It involves reviewing the user needs, the system design, and the system implementation to ensure that the system meets the user’s needs.

4. Mnemonics and Learning Tricks: Mnemonics and learning tricks are useful tools for remembering and understanding the Requirement Engineering Process. For example, the acronym "REPS" can be used to remember the steps in the process: Requirement Elicitation, Analysis, Design, and Implementation.

5. Advantages: The Requirement Engineering Process provides a structured approach for understanding user needs and creating a system that meets those needs. It ensures that all user needs are identified and addressed, and that the system is designed to meet those needs.

6. Disadvantages: The Requirement Engineering Process can be time-consuming and costly. It requires a significant amount of effort to identify, analyze, and document user needs, and to design and implement a system that meets those needs.

7. Examples: The Requirement Engineering Process can be used to design and implement a variety of systems, such as web applications, mobile applications, and desktop applications.

8. Applications: The Requirement Engineering Process can be used in a variety of contexts, such as software engineering, web development, and mobile development.
