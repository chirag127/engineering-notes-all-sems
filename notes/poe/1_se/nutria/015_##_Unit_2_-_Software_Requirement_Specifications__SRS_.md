
## Unit 2 - Software Requirement Specifications (SRS)

SRS is a document that describes the requirements of a software system. It is written by the software development team and contains the details of the system's functionality, user interface, performance, and other requirements.

**Mnemonic:** SRS stands for Software Requirement Specifications.

The purpose of SRS is to provide a clear and concise description of the software system's requirements. It should include all the necessary information required to develop, test, and deploy the software.

The SRS document should be written in a way that is easy to understand and can be used by all stakeholders. It should include the following sections:

- **Objective:** Describes the purpose of the software system and its expected outcomes.
- **Scope:** Describes the scope of the software system, its features, and how it will be used.
- **Functional Requirements:** Describes the functional requirements of the system.
- **Non-Functional Requirements:** Describes the non-functional requirements of the system, such as performance, reliability, security, etc.
- **User Interface:** Describes the user interface of the system.
- **System Architecture:** Describes the system architecture of the system, including the hardware and software components.
- **Testing:** Describes the testing process and requirements for the system.
- **Deployment:** Describes the deployment process and requirements for the system.

The SRS document should be reviewed and approved by all stakeholders before development can begin. It is important to ensure that the document is accurate and complete before development begins.
