#### Entity bean in Enterprise Java Bean

An Entity Bean represents a persistent data object which is mapped to a database table.

- It has a primary key which uniquely identifies the bean.
- It has a life cycle with various states - Does Not Exist, Pooled, Method-Ready andBean-Managed Persistence.
- It can be found using its primary key or by executing a finder method.
- It supports transactions via container-managed or bean-managed transactions.
- It can be cached in the bean container to improve performance.

**Mnemonics:**
- *EJB - Entity Java Bean* - Remember EJB for Entity Bean.
- *Persistent data object* - It represents persistent data which is stored in a database.
- *Primary key* - Uniquely identifies the entity bean.
- *Various states in life cycle* - Learn the various states like Pooled, Method-Ready, Does Not Exist, etc.

**Advantages:**
- Persistent data can be mapped to entity beans.
- ACID properties are supported via transactions.
- Performance is improved via caching of entity beans.

**Disadvantages:**
- Complex programming model.
- Vendor specific interfaces.
- Tedious deployment process.

**Applications:**
- Enterprise applications which need to store persistent data in a database.
- Applications which need ACID transactions to maintain data consistency.
