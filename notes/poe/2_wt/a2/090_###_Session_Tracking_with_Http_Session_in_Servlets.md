### Session Tracking with Http Session in Servlets

- HttpSession object is used to track a user across multiple requests.
- When a user first visits a web application, a HttpSession object is created for that user.
- A unique session ID is generated by the server and sent to the client in a cookie or URL rewriting.
- On subsequent requests, the client sends back the session ID, allowing the server to associate the request with the correct HttpSession object.
- Any object can be bound to a session and later retrieved. This is useful for storing user-specific information, cart data, etc.
- Advantages:
    - Simple to implement.
    - Data is stored on the server, so it is secure.
    - Scales well.
- Disadvantages:
    - If session data becomes too large, performance may suffer.
    - Reliance on client to always send correct session ID. Client can be spoofed to hijack another user's session.
    - Sessions time out eventually. Need to implement logic to handle expiry of sessions.
- Example:
    ```java
    HttpSession session = request.getSession();
    session.setAttribute("username", username);
    
    String username = (String) session.getAttribute("username");
    ```
- Mnemonics:
    - Imagine you are attending multiple classes (requests) and the instructor (server) remembers you by your unique roll number (session ID). The instructor stores your details/info (session data) using your roll number.
- To conclude, HttpSession is a simple and effective way to track users across requests and store user-specific data on the server side. However, care must be taken to ensure security and scalability of the application.
