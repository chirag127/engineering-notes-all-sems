# Event handling in Core Java

### What are Events?
- Events are notifications sent by an application to notify the occurrence of an action or an occurrence.
- They are used to enable applications to respond to user actions or system occurrences.
- In Java, events are objects that encapsulate the state change in the source.

### Sources of Events
- User actions like button clicks, key presses, mouse movements, etc.
- System events like window closing, idle time expiring, low memory, etc.

### Types of Events
- Low-level events - Generated by user actions like button clicks, key presses, etc. Handled by the underlying OS and AWT/Swing libraries.
- High-level events - Generated by application logic. Used to notify other application components of state changes.

### Handling Events
- Event listeners - Interfaces that contain methods to handle events.
- Event sources - Objects that generate events and maintain a list of listeners.
- Register listeners - Listeners are registered with event sources.
- Raise events - Events are raised/fired by event sources.
- Listeners handle events - Appropriate listener methods are invoked by the event source.

**Mnemonics:**
- Think of event handling as a restaurant - Event source is the waiter, listeners are the customers and events are the food orders. Waiter registers the customers and serves food (raises events) when the orders (events) occur. Customers (listeners) then enjoy the food (handle events).
