
### Change Control in spm

* Change control is the process used to ensure that all changes to a system, such as software, hardware, and data, are tracked, approved, and documented.
* It is an important part of the Software Project Management (SPM) process, as it helps ensure that changes are made in a controlled and consistent manner.
* Change control typically involves the following steps:
    1. Identifying the change: The first step of change control is to identify the change that needs to be made. This could be a bug fix, a new feature, or an update to existing code.
    2. Documenting the change: Once the change has been identified, it should be documented in detail. This document should include the purpose of the change, the expected outcome, and any risks associated with the change.
    3. Approving the change: After the change has been documented, it must be approved by the appropriate parties. This could include the project manager, the development team, and any stakeholders involved in the project.
    4. Implementing the change: Once the change has been approved, it can be implemented. This could involve writing new code, updating existing code, or making changes to the system configuration.
    5. Testing the change: After the change has been implemented, it should be tested to ensure that it works as expected. This could involve unit testing, integration testing, or user acceptance testing.
    6. Monitoring the change: After the change has been tested, it should be monitored to ensure that it is functioning correctly. This could involve tracking metrics such as system performance or user engagement.

Mnemonics:

* CIDAPT: Identify, Document, Approve, Implement, Test, Monitor.
