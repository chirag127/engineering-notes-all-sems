### Software Configuration Management in spm

Software Configuration Management (SCM) refers to the process of identifying and defining the software configuration items (CIs), controlling the changes to these CIs, recording and reporting the status of the CIs, and verifying the completeness and correctness of the CIs.

The key aspects of SCM are:

1. Configuration Identification - Identifying the configuration items that make up a system and baselining them. CIs are the components that may change and need to be controlled.
2. Configuration Control - Controlling the release and change of CIs. This ensures only approved changes are made. Changes are made via change requests and change control boards.
3. Configuration Status Accounting - Recording and reporting the status of CIs and changes to them. This tracks the version and location of CIs.
4. Configuration Auditing - Ensuring that the CIs that make up a system are correct and complete and that the configuration information is an accurate representation of the system.

The goals of SCM are to:

- Minimise wasted effort and rework.
- Increase software quality.
- Maximise productivity.
- Facilitate management control.

Advantages of SCM:

- Tracks software versions and changes.
- Supports collaboration and teamwork.
- Supports software reuse.
- Provides visibility to management.
- Supports testing and release management.

Disadvantages of SCM:

- Can be bureaucratic and introduce delays.
- Requires effort to set up and maintain.
- Needs skilled personnel to administer.
- Complex systems may be hard to manage.
