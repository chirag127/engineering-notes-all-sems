#### Anatomy of a Map Reduce Job Run

MapReduce is a programming model used for processing large data sets in a distributed computing environment. It divides the input data into smaller chunks and processes them in parallel, thereby reducing the overall processing time. In this section, we will discuss the anatomy of a MapReduce job run, which consists of the following stages:

1. Input Stage: The input stage involves the following steps:

  - Input data is divided into smaller chunks, known as input splits.
  - Each input split is assigned to a mapper task for processing.
  - The number of mappers is determined based on the size of the input data and the cluster configuration.

2. Map Stage: The map stage involves the following steps:

  - Mapper tasks read the input data and process it to generate key-value pairs.
  - Each mapper task works on a single input split and generates multiple intermediate key-value pairs.
  - The output of the map stage is a set of intermediate key-value pairs.

3. Shuffle and Sort Stage: The shuffle and sort stage involves the following steps:

  - Intermediary key-value pairs generated by the map stage are sorted and grouped based on their keys.
  - The sorted key-value pairs are then partitioned into multiple groups, with each group corresponding to a reducer task.
  - Reducer tasks are responsible for processing the key-value pairs in each group.

4. Reduce Stage: The reduce stage involves the following steps:

  - Reducer tasks receive the key-value pairs generated by the map stage and sorted by the shuffle and sort stage.
  - Each reducer task processes the key-value pairs in its assigned group to generate the final output.
  - The final output of the reduce stage is stored in the output directory.
