### Static Testing Strategies

Static testing strategies involve analyzing the software artifacts without actually executing the code. Some common static testing strategies are:

1. Reviews: Reviews involve manual inspection of the software artifacts by a team of experts to identify errors and issues. Some types of reviews are:
- Informal review: A casual review of the code by colleagues to get feedback.
- Walkthrough: The author explains the code line-by-line to reviewers who ask questions.
- Technical review: A formal, structured review involving a team evaluating the code against defined criteria.

Advantages: Cheap and can identify non-functional issues.
Disadvantages: Limited coverage and depends on reviewers' expertise.

2. Static analysis tools: Automated tools analyze the software code to detect errors, code smells, and security vulnerabilities. Some examples are:
- Compiler: Checks for syntax errors.
- Linting tools: Check for code formatting and potential bugs.
- Static code analyzers: Check for more complex bugs and security flaws.

Advantages: Thorough and automated.
Disadvantages: May produce false positives and limited to types of errors the tool checks for.
