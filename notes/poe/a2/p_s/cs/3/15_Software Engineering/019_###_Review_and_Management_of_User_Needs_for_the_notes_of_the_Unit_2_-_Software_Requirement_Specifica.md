### Review and Management of User Needs

1. Identify the actual user needs: It is important to identify the actual user needs rather than assuming what the user needs. This can be done by conducting interviews, surveys, focus group studies, etc. with the potential users to understand their requirements clearly.
2. Prioritize user needs: Not all user needs have the same priority. The user needs should be prioritized based on their relevance and importance. The prioritization can be done by taking inputs from users and stakeholders. The needs with higher priority should be addressed first.
3. Resolve conflicting user needs: It is possible that different users may have conflicting needs or requirements. These conflicting needs should be resolved through discussions and by evaluating the pros and cons of each need. A compromise may have to be made to accommodate conflicting needs.
4. Remove unnecessary user needs: Some user needs may not be feasible or necessary to implement. These needs should be identified and removed from consideration to avoid wasting time and effort in implementing them. The unnecessary needs can be filtered out by evaluating their relevance to the software objectives and overall utility.
5. Continuously review user needs: The user needs may evolve over time or with changing requirements. Hence, user needs should be continuously reviewed and tracked throughout the software development process. This allows to address new or changed needs and ensure that the final product meets the current user requirements.

The above points can be explained in detail with examples and diagrams for better understanding. The user needs management is an important step in requirements engineering to build the right product that satisfies the user demands. Proper review and management of user needs leads to the formulation of accurate and feasible software requirements.
