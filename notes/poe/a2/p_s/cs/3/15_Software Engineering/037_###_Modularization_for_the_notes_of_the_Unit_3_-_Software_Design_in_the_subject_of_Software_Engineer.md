### Modularization for the notes of the Unit 3 - Software Design in the subject of Software Engineering

Modularization refers to the process of breaking down a software system into multiple modules (independent components) that are interconnected. The key points about modularization are:

1. Modules should be loosely coupled: The modules should have minimal dependencies on each other and interact through well-defined interfaces. This enables isolation of modules and increased reusability.
2. Modules should be highly cohesive: The functions and components within a module should be closely related and directed towards a specific goal. This increases understandability and maintainability.
3. clear interfaces: The interfaces between modules should be well-defined. This enables interaction between modules through the interfaces.
4. Information hiding: The modules should hide the internal implementation details and only expose the interfaces to other modules. This increases robustness and reduces side effects.
5. Divide and conquer: Breaking down a complex system into smaller modules makes the system more comprehensible, manageable and testable. The components can be designed and developed independently and integrated later.

Advantages of modularization:
- Increased comprehensibility and manageability.
- Increased reuse of modules.
- Isolation of errors and side effects.
- Parallel and distributed development.
- Adaptability to change.

Disadvantages of modularization:
- Increased inter-module communication overhead.
- Difficulty in identifying module interfaces.
- Risk of over- modularization or under-modularization.

Examples of modules:
- Functional modules (for e.g. a billing module)
- Object-oriented modules (for e.g. a customer class)
- Physical modules (for e.g. a database access module)

Applications of modularization:
- In programming languages like Java, C++, etc.
- In operating system design.
- In software product lines.
- In microservices architecture.
