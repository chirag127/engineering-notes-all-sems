### Software Re-Engineering

- Software Re-Engineering is the examination and alteration of a system to reconstitute it in a new form and the subsequent implementation of the new form.
- It is usually done to reduce problems with software maintenance by reducing complexity and restructuring software systems.
- The goals of software re-engineering are to reduce software development and maintenance costs, decrease software defects, increase software maintainability, and increase software extensibility.
- The steps involved in software re-engineering are:

1. Understanding the existing system - Analyzing the existing software architecture, code, databases, etc. to understand the system and its problems.
2. Determining software re-engineering approach - Deciding whether to restructure or reimplement the system and choosing techniques like reverse engineering, restructuring, translation, etc.
3. Re-engineering the software - Applying the chosen techniques to re-engineer the software. This could involve restructuring code, redesigning databases, translating to new languages, etc.
4. Evaluation and testing - Evaluating the re-engineered software and testing it to ensure it meets requirements.
5. Migrating to the new system - Shifting from the old system to the re-engineered system. This could be done gradually or at once.

- Some advantages of software re-engineering are reduced software maintenance costs, increased software quality, improved software performance and reliability, and extended software lifespan.
- However, software re-engineering also has some disadvantages like high initial costs, risk of introducing new defects, and lack of supporting tools and techniques.
- Software re-engineering has applications in legacy system modernization, software productivity improvement, and software quality enhancement. It is a crucial technique for managing and maintaining complex software systems.
