### Testing for Functionality for the notes of the Unit 4 - Software Testing in the subject of Software Engineering

- Software Testing is done to check if the software is functioning as per the requirements.
- Testing for functionality involves checking if each feature and functionality of the software is working as intended.
- Some ways to test functionality are:
    - Equivalence Partitioning - dividing input data into partitions and testing one input from each partition.
    - Boundary Value Analysis - testing boundary values of input partitions.
    - Cause-Effect Graphing - exploring combinations of inputs and causes and effects to test functionality.
    - Syntax Testing - testing valid and invalid inputs.
    - Error Guessing - guessing potential errors and testing for them.
- Advantages: Finds bugs and ensures correct functioning of features.
- Disadvantages: May miss bugs if test cases are not comprehensive.
- Examples: Testing login functionality with correct and incorrect passwords, testing calculator functionality with various inputs, etc.
- Applications: Testing functionality is important in software testing to deliver a product that meets requirements.

#### ARP

- ARP stands for Address Resolution Protocol.
- It is a protocol used to map IP addresses to MAC addresses.
- The process involves sending a broadcast ARP request packet asking for the MAC address of the target IP address. The device with the target IP address responds with its MAC address.
- The requesting device then stores the IP-MAC address mapping in its ARP cache to use for future communications.
- Advantages: Enables communication between devices in a local network using IP addresses.
- Disadvantages: ARP caches can contain stale data and be vulnerable to ARP spoofing attacks.
- Examples: A computer sends an ARP request asking for the MAC address of the router's IP, the router responds with its MAC address.
- Applications: ARP is a key protocol used in local area networks to enable IP-based communication.
