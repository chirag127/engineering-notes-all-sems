### Function Point (FP) Based Measures

- Function Point Analysis (FPA) is a technique to measure the size of software based on its functionality.
- It counts the number of functions provided by the software and adjusts it based on complexity to arrive at an FP measure.
- The key steps in FPA are:

1. Identify the user inputs, outputs, external interfaces, and logical files of the software. These are collectively called function types.

2. Assign unadjusted function point (UFP) values to each function type. The values depend on number and complexity of the function types.

3. Adjust the UFP based on 14 general system characteristics (called GSCs) to arrive at adjusted function point (AFP). The GSCs reflect the complexity of the software.

- The FP count represents a size measure for the software which can be used to:

- Estimate effort and cost for software development.
- Assess productivity in terms of FP per unit effort/cost.
- Compare sizes of multiple software for bidding, planning, or benchmarking.

- Some advantages of FP based measures:

- Account for functionality of software rather than just lines of code.
- Provide a standardized approach to measure software size.
- Consider complexity in calculation through GSCs.

- Some disadvantages:

- Subjective: Assignment of FP values and rating of GSCs involve subjective assessment.
- Additional effort: FPA requires analysis of software functionality and applications of criteria, adding to effort.
- Not useful for very small or real-time embedded software.

- FP based measures have applications in project planning, productivity assessment, and software benchmarking. They provide a alternative, indirect way to estimate effort and cost for software projects.
