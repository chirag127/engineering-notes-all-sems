### Change Control Process

- Change control process is a formal process used to document, assess, approve or reject, and incorporate changes to software. It ensures that only tested and approved changes are implemented in software.
- The steps involved in change control process are:

1. Request for change - Any stakeholder can request for a change in the software by filling out a change request form. The form should describe the details of the requested change.
2. Analysis of change request - The change request is then reviewed by a change control board. They assess the implications and impact of the proposed change on other software modules, schedule, and budget.
3. Approval or rejection - The change control board either approves or rejects the change request based on the analysis. If approved, it proceeds to the next step else the requester is informed about the rejection.
4. Incorporation of change - The approved change is incorporated into the software by the development team.
5. Testing and documentation - The software with the incorporated change is tested to ensure that no new errors are introduced. All the documentation is also updated with the change.
6. Release - The updated software is released to the customers/stakeholders.

Advantages:
- Prevents uncontrolled changes to software.
- Evaluates the impact of changes before actual incorporation.
- Maintains integrity and consistency of software.

Disadvantages:
- Change control process can be time-consuming.
- Might reject changes that could actually benefit the software.
- Conflicts can arise between developers and customers regarding change requests.
