## Unit 2 - Software Requirement Specifications (SRS)

- Software Requirement Specification (SRS) is a detailed description of the intended purpose and environment for software under development. It includes a complete description of the software to be developed with all the inputs and outputs, functional requirements, performance requirements, design constraints, etc.
- The SRS is developed by the Software Requirements Analysis task of the Software Engineering process. It acts as a communication medium between the client and the developer.
- The key points to be covered in an SRS are:
- Introduction
    - Purpose
    - Scope
    - Definitions and Acronyms
- Overall Description
    - Product Perspective
    - Product Functions
    - User Characteristics
    - Constraints
    - Assumptions and Dependencies
- System Features
    - Functional Requirements
    - External Interface Requirements
- Performance Requirements
- Logical Database Requirements
- Design Constraints
- System Environment
    - Operating system
    - Hardware platform
- Attributes
    - Reliability
    - Security
    - Safety
    - Maintainability
    - Portability
- Advantages
    - Acts as a reference for both client and developer and minimises ambiguity.
    - Forces both the parties to be explicit in defining the software to be developed.
    - Early identification of missing functionality or inconsistent requirements.
- Disadvantages
    - Difficult to modify if requirements change.
    - Tedious and time-consuming to produce.
    - Requires skilled analysts and could be expensive.
