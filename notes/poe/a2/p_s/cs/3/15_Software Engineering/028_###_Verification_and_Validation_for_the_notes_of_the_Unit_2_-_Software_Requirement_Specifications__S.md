### Verification and Validation for the notes of the Unit 2 - Software Requirement Specifications (SRS) in the subject of Software Engineering

1. Verification:
- Verification is the process of checking whether the software meets the specified requirements.
- It is done at every stage of software development to check for errors and bugs.
- Types:
-- Requirements verification: Checking if the requirements accurately reflect the customer's needs.
-- Design verification: Checking if the design implements the requirements.
-- Code verification: Checking if the code implements the design.

2. Validation:
- Validation determines whether the software meets the user's operational needs and fits the intended purpose.
- It is done at the end of the development process.
- Types:
-- Alpha testing: Done in-house in a controlled environment by the developers.
-- Beta testing: Done by a select group of customers in their own environment.
-- Acceptance testing: Final testing done by the customer to determine if the software is acceptable.

**Advantages:** Ensures the software quality by detecting and rectifying errors early. Reduces cost and rework. Increases reliability and user satisfaction.

**Disadvantages:** Can be time-consuming and tedious. Increases project cost and time. Not all errors can be detected.

**Examples:** Unit testing, integration testing, system testing.

**Applications:** Widely used in the software industry to deliver high-quality products that meet customer requirements.
