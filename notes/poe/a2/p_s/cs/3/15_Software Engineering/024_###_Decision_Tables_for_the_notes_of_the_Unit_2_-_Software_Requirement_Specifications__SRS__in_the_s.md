### Decision Tables

- Decision tables are a technique to specify conditional logic in a tabular format.
- They provide a systematic way to explore and document all possible combinations of conditions and resulting actions.
- A decision table has conditions in rows and actions in columns. Each cell in the table specifies an action or set of actions to be performed for a particular combination of conditions.
- They are useful for:
-- Specifying complex logic
-- Identifying potential incompleteness or inconsistencies in specifications
-- Automating code generation from specifications
- The components of a decision table are:
-- Condition stubs: Column labels for conditions
-- Condition entries: Possible values or ranges of values for each condition
-- Action stubs: Column labels for actions or rules
-- Action entries: The actions to be taken or rules to be executed for each combination of conditions
- Advantages:
-- Compact and simple notation
-- Shows all combinations explicitly
-- Identifies missing or inconsistent logic
-- Can be processed easily by machines to generate code
- Disadvantages:
-- May be difficult to read for complex problems
-- Determining completeness can be difficult
-- May be inefficient if most combinations have the same action
