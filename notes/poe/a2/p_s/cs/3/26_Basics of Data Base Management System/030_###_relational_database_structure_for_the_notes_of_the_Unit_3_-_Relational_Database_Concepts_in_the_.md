### Relational Database Structure

A relational database stores data in tables (also known as relations) that are made up of rows and columns.

- **Tables** - A table is a collection of related data entries and it consists of columns and rows. Columns define the data type and rows contain the actual data values.
- **Columns** - Columns define the schema of the table and determine the datatype and constraints for the data stored in each column. Each column has a unique name and stores a specific type of data.
- **Rows** - Rows contain the actual data for the table. Each row contains data for each of the columns and must contain a unique value for the primary key column(s).
- **Schema** - The schema defines the structure of the database including the tables, columns, datatypes, and relationships. It ensures consistent data storage and maintains data integrity.
- **Data Integrity** - Data integrity ensures accuracy and consistency of data in a database. It is enforced through constraints, primary keys, foreign keys, etc.
- **Constraints** - Constraints are rules applied to data in a database table. They are used to limit the type of data that can go into a table. Examples - NOT NULL, UNIQUE, PRIMARY KEY, FOREIGN KEY, CHECK, etc.

Advantages:
- Structured data storage
- Data consistency and integrity
- Easy data access and manipulation using SQL
- Scalability

Applications: Databases, Accounting systems, CRM, ERP, etc.
