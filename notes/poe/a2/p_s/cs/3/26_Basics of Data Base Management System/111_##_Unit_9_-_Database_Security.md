## Unit 9 - Database Security

- Authorization - Granting access rights to database users. This is done through credentials like username and passwords along with access privileges defined for each user. This ensures that users can only access data that they are authorized to access and not other sensitive data.
- Access control - Controlling how users can interact with data in the database. This is implemented through permissions, roles, and views which restrict the type of SQL operations that can be performed by users on data. For example, a user can be given only SELECT privilege on some tables and not allowed to perform INSERT, UPDATE or DELETE.
- Encryption - Converting data into unreadable code that cannot be understood by unauthorized users. This is done using encryption keys and algorithms. Encryption is used to protect data in storage as well as data in transit between the database and applications. However, this can impact performance as the database has to encrypt and decrypt data every time it is accessed.
- Auditing - Tracking and maintaining records of database activities including login attempts, SQL queries executed, data access, etc. This is useful for monitoring suspicious activities, identifying security breaches, and maintaining regulatory compliance. The audit data can be analyzed to understand patterns of abuse and take appropriate actions.
- Patching - Installing updates including security patches released by database vendors. These patches fix vulnerabilities in the database software that can be exploited by attackers to gain access. Patching ensures that the latest security protections are in place to safeguard the database against known vulnerabilities and risks.
- Backup - Creating copies of database data and configuration to use in the event of loss or corruption of data. Backups are essential for disaster recovery but they also pose a security risk if they are not properly secured as they contain sensitive data. Encryption and access control should be applied to backups to prevent them from being misused.
- Segregation of duties - Separating database administration duties among multiple teams or individuals. For example, one team can handle setup and upgrades while another team handles tuning and monitoring. This is done to prevent misuse or abuse of power as it is more difficult for a single person to compromise a system when responsibilities are segregated. However, this can also make coordination more challenging with multiple teams working on the database.
