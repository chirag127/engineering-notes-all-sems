### Mapping Constraints

The following are the mapping constraints that can be applied on an ERD:

1. One-to-one: An entity in a table can be mapped to at most one entity in another table. For example, one employee can have at most one office or one student can have at most one course.
2. One-to-many: An entity in a table can be mapped to many entities in another table. For example, one department can have many employees or one course can have many students.
3. Many-to-one: Many entities in a table can be mapped to one entity in another table. This is the inverse of one-to-many mapping. For example, many employees can belong to one department or many students can take one course.
4. Many-to-many: Many entities in a table can be mapped to many entities in another table. For example, many students can take many courses or many employees can work on many projects. This type of relationship requires an intermediate connecting table.

The mapping constraints determine how the entities in the ERD can be connected to each other. They define the number of connections that are possible between two entities. Selecting the appropriate mapping constraint is important for designing an accurate and efficient database.
