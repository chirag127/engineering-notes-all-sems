## Unit 3 - Software Design

1. Software Design Process
- Analysis: Gather requirements and understand the problem
- Design: Come up with a high-level solution and architecture
- Implementation: Code the software and build components
- Testing: Check that the software meets requirements and fix bugs
- Deployment: Release the software for use

2. Software Architecture and Design Principles
- Separation of Concerns: Break system into modular components with separate responsibilities
- Coupling: Minimize dependencies between components
- Cohesion: Maximize relatedness of components
- Abstraction: Hide complexity and separate interfaces from implementation details
- Layered architecture: Split into layers (presentation, business logic, data access, etc.)
- Pipelines: Pass data through a sequence of processing steps
- Microservices: Build app as small, modular services

3. Design Patterns
- Creational: Factory Method, Singleton, Builder, Prototype
- Structural: Adapter, Bridge, Composite, Decorator, Facade, Flyweight, Proxy
- Behavioral: Chain of Responsibility, Command, Iterator, Mediator, Memento, Observer, State, Strategy, Template Method, Visitor

4. Methods for Software Design
- Use cases: Describe user interactions and main flows through the system
- Sequence diagrams: Model logic and data flow between components
- Class diagrams: Model core objects/classes and relationships
- State diagrams: Model the states of components and transitions between states
- Activity diagrams: Model the flow of data and control between components
