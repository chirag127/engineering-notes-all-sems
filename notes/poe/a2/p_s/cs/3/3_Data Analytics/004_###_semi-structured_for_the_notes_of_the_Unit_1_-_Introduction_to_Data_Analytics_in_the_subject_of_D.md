### Semi-structured data

- Semi-structured data refers to data that does not have a fixed data model or schema.
- The data is self-descriptive and consists of tags or other markers to separate semantics.
- Examples of semi-structured data include:

- JSON data - JavaScript Object Notation data in key-value pairs with hierarchy
- XML data - eXtensible Markup Language data with tags to denote semantics
- YAML data - YAML Ain't Markup Language data that is human-readable
- CSV data - Comma-Separated Values data with values separated by commas

Advantages:

- Flexibility - schema can be modified as needed without affecting the data
- Simplicity - less complex than relational databases
- Compatibility - can be converted to other data formats

Disadvantages:

- Querying can be difficult without a fixed schema
- Schema discovery is required to understand the data
- Storage requirements can be high due to repetition

Applications:

- Web APIs that return flexible data
- Configuration files
- Data exchange between systems with different schemas

**Summary:** Semi-structured data has an implicit data model and contains tags or markers to separate elements. It offers flexibility but can be challenging to query. Examples include JSON, XML, YAML, and CSV.
