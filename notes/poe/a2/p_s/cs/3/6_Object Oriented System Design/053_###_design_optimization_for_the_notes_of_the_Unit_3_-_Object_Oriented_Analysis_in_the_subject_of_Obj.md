### Design Optimization for Object Oriented Analysis

1. Identify core objects: First step is to identify the core objects of the system. These are the main entities that the system is going to deal with. For e.g. in a library management system, the core objects can be books, students, library staff, etc.
2. Define attributes and behaviors: Then define attributes which describe the state of the core objects and behaviors which describe the functionality and actions performed by the core objects. Attributes can be data like name, id, etc. Behaviors can be functions like issue book(), return book(), etc.
3. Define relationships: Next define the relationships between the core objects. There can be association, aggregation, composition, inheritance, etc. relationships between the objects. These relationships need to be identified and properly defined.
4. Do sequence and interaction diagrams: Use sequence and interaction diagrams to model the dynamic behavior of the system. These diagrams show the message exchanges between objects and the order of execution of methods. They are useful to visualize the complete flow of logic and identify any issues.
5. Refactor as needed: If required, refactor the classes and relationships. Sometimes the initial design may not be optimal and flaws may come up when drawing sequence/interaction diagrams or on implementation. The design can be improved by refactoring - organizing packages/classes, segregating responsibilities, making relationships more meaningful, etc.
6. Review and finalize: Finally, review the complete object oriented analysis and design with all team members and finalize the design. Get approvals and then move on to the implementation phase.
