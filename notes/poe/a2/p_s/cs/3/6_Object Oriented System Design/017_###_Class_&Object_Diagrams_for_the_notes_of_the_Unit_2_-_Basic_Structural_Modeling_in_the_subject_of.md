### Class & Object Diagrams

Class diagrams are static structure diagrams that show the classes of the system, their relationships, and the operations and attributes of the classes.

- Class: A class represents a set of objects that share the same structure and behaviour. It consists of attributes that represent the state of the object, and methods that represent the behaviour of the object.
- Attributes: Attributes are the variables that determine the state of the objects. They are depicted as labels inside the class boxes.
- Methods: Methods are the operations that express the behaviour of the objects. They are depicted as labels inside the class boxes.
- Relationships: Relationships show the static connections between classes. Different types of relationships are:
- Association: Association represents a general relationship between classes. It is depicted as a solid line between classes.
- Aggregation: Aggregation is a special type of association and represents a part-whole relationship. It is depicted as a solid line with a hollow diamond at the whole side.
- Composition: Composition is a special type of aggregation and represents a strong whole-part relationship. It is depicted as a solid line with a filled diamond at the whole side.
- Inheritance: Inheritance represents an "is-a" relationship and is depicted as a solid arrow from the child class to the parent class.

Object diagrams show the instances of the classes at a particular moment and the links between the objects. They areclose to the actual system execution and are useful to model the static aspects of a system.

The key points to keep in mind while drawing class and object diagrams are:
- Identify the main classes and their attributes and methods.
- Establish the relationships between classes.
- For object diagrams, identify key objects and links between objects.
- Keep the diagrams as simple as possible.
- Use appropriate notations.

Advantages:
- Help understand the static structure of the system.
- Aid in communication with stakeholders.
- Detect design flaws early.

Disadvantages:
- Can get complex for large systems.
- Require detailed knowledge of the system.
- Can be misinterpreted.

Applications:
- Analysis and design of software systems.
- Modelling the structure of systems.
- Documentation and communication.
