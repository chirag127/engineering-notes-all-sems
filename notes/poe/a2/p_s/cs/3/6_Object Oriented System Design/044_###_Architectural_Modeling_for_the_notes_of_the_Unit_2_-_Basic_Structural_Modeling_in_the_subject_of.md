### Architectural Modeling

Architectural modeling is the process of developing architectural models. An architectural model is a type of abstract model that represents the structure of a software system. It focuses on the decomposition of a system into components and connectors and the characterization of those components and connectors.

Some key points about architectural modeling -

- It helps in understanding the overall structure of the system and how components interact with each other.
- It identifies major components and connectors of the system.
- It determines critical properties of components and connectors like scalability, flexibility, reusability, etc.
- It acts as a bridge between requirements and design models. It transforms requirements into an abstract system design.
- It is used for communication between stakeholders. It helps in conceptualizing and reasoning about the system.
- There are no standard notations for architectural modeling. Box and line diagrams, UML component diagrams, etc. are commonly used.

Advantages -

- It enhances communication between stakeholders.
- It identifies and resolves architectural design issues early.
- It acts as a blueprint for lower-level design models.
- It makes the system's design modular, flexible, and reusable.

Disadvantages -

- It may be difficult to derive from user requirements.
- Its notation is not standardized.
- It lacks implementation and platform details. So, multiple architectural models may exist for a system.

Examples -

- Layered architecture - Divides system into layers (presentation, business, data access, etc.).
- Microkernel architecture - Provides a minimal set of services and enables plugging in additional services.
- Pipes and filters architecture - Components are connected via pipes and data is filtered/processed sequentially.
- Client-server architecture - System is divided into server-side components and client-side components.
- Service-oriented architecture - System is composed of services that can be used by clients.

Applications -

- It is widely used in designing complex software systems.
- It influences other software engineering activities like testing, deployment, etc.
- It enables evaluating architectural trade-offs and reusability.
- It enables managing architectural changes and complexity.
