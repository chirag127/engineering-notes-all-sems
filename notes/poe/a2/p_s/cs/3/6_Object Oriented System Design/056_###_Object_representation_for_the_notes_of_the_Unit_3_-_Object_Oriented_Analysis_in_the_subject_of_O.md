### Object representation for the notes of the Unit 3 - Object Oriented Analysis in the subject of Object Oriented System Design

- Objects in a system can be represented using UML notations like class diagrams, object diagrams, use case diagrams, sequence diagrams, etc.
- Class diagrams represent the static structure of a system. They show classes, relationships, attributes, operations, etc. Class diagrams are used to model the concepts and things in a problem domain.
- Object diagrams represent instances of classes at a particular moment. They show objects, links between objects, and the values of object attributes. Object diagrams are used to model a particular scenario of a system.
- Use case diagrams represent high-level system functions. They show use cases, actors, and relationships between them. Use case diagrams are used to capture the requirements of a system.
- Sequence diagrams represent interactions between objects for a particular scenario. They show objects, lifelines, and messages. Sequence diagrams are used to model the dynamic behavior of a system.
- Other UML diagrams like activity diagrams, state machine diagrams, component diagrams, deployment diagrams, etc. can also be used to represent objects and aspects of a system from different perspectives.
- Representing a system using UML notations helps in having a common vocabulary to communicate between stakeholders, visualizing and analyzing the system, and generating code from the models. It leads to the smooth designing and development of a robust system.
