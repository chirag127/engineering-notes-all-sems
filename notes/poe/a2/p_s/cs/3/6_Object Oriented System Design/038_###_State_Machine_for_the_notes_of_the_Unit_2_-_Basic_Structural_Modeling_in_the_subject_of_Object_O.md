### State Machine

A state machine is a behavioral model that represents the states of an entity and the transitions between those states. It is used to represent the dynamic behavior of a system.

- States: The various conditions or statuses that an entity can have. For example, a traffic light can have states like red, yellow and green.
- Transitions: The changes that occur when the state machine moves from one state to another. This happens due to some events or conditions. For example, the transition from red to green state in a traffic light happens when the timer expires.
- Events: The occurrences that trigger a change of state. For example, the timer expiry is the event that triggers the transition from red to green in a traffic light.

Advantages:
- Helpful in modeling reactive systems that respond to events.
- Useful for sequential logic and flow of control.
- Easy to understand and visualize.

Disadvantages:
- May become complex if there are multiple states and transitions.
- Difficult to scale for large and complex systems.

Applications:
- UI state machines: To model the states of a user interface.
- Communication protocols: To model the sequence of messages exchanged.
- Embedded systems: To model the modes of operation.

Examples:
- Vending machine: States like idle, paid, selecting item, dispensing, sold out, etc. Transitions based on events like money insertion, button presses, item dispense, etc.
- TCP connection: States like closed, listen, syn-sent, syn-received, established, fin-wait-1, fin-wait-2, close-wait, last-ack, time-wait, etc. Transitions based on events like connection establishment, data transmission, connection closure, etc.
