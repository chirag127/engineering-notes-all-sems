### Class Diagrams

- Class diagrams are the main diagrams used for structural modeling in OO system design. They show the static structure of a system.
- Classes are represented by rectangles divided into compartments. The top compartment contains the class name. The middle compartment contains the attributes of the class. The bottom compartment contains the operations of the class.
- Relationships between classes are represented by arrows. The arrowhead shows the direction of the relationship.
- Common relationships are:
-- Association: A simple link between two classes. Indicates that instances of the two classes are somehow related or interact.
-- Aggregation: A "has-a" relationship. One class contains or is made up of instances of another class. The containing class does not have full control over the lifecycle of the contained class.
-- Composition: A strong type of aggregation. The containing class has full control over the lifecycle of the contained class. If the containing class is destroyed, so are the instances of the contained class.
-- Inheritance: An "is-a" relationship. One class (child) inherits attributes and behaviors from another class (parent). The child class can be substituted for the parent class.

### Component Diagrams

- Component diagrams show the high-level components that make up a system, and the dependencies between them.
- Components are represented by icons, and dependencies by directed arrows.
- Components can represent logical groupings of classes, or actual executable modules.
- The diagrams are useful for visualizing an architectural overview of a system and the runtime interactions between components.
