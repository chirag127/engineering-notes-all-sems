### Object Oriented Modelling

Object Oriented Modelling is a technique to model problems as a collection of interacting objects. Following are the key points about Object Oriented Modelling:

1. Problem domain is represented as objects: The problem domain is represented as a collection of objects with properties and behaviors. For example, a 'Customer' object will have properties like name, age, address, etc. and behaviors like placeOrder(), payBill(), etc.
2. Objects interact with each other: Objects interact with each other by sending and receiving messages. For example, a 'Customer' object can send a message to a 'Product' object to place an order.
3. Object Relationships: Objects have relationships between them. For example, a 'Customer' object can be related to multiple 'Order' objects and an 'Order' object can be related to multiple 'Product' objects. These relationships can be one-to-one, one-to-many or many-to-many.
4. Encapsulation: Objects hide their internal details from other objects and only expose their interfaces to interact with other objects. This is known as encapsulation and provides modularity.
5. Reusability: Objects can be reused in other contexts as they are modular and independent. For example, a 'Customer' object designed for an e-commerce application can be reused in a billing application with few modifications.

Advantages: Object Oriented Modelling produces modular designs, enables reusability, maps well to real world problems and is easy to understand.
Disadvantages: It can lead to over-engineering if taken to an extreme and models can become complex if there are too many objects and relationships.

Applications: Object Oriented Modelling is widely used in software applications to model complex problems in various domains like e-commerce, healthcare, banking, etc. UML (Unified Modelling Language) is a standard notation to create object oriented models.
