### Documenting design considerations for the notes of the Unit 3 - Object Oriented Analysis in the subject of Object Oriented System Design

1. Identify objects:
- Identify nouns in the problem statement and use cases. These nouns will become candidate objects.
- Group related nouns into potential classes.
- Ensure each class has a clearly defined responsibility and purpose.

2. Define object relationships:
- Determine how objects interact and connect based on the verbs in the use cases and problem statement.
- The interactions between objects are modeled as relationships (associations).
- Determine cardinality and optionality of each end of a relationship.

3. Attribute and behaviors:
- Define the attributes (data) and behaviors (methods) for each object.
- Attributes describe the state of an object. Behaviors describe the functionality of an object.

4. Classes and Inheritance:
- Review the candidate classes and generalize/specialize classes using inheritance as applicable.
- Ensure proper "is-a" relationships if inheritance is used.

5. Analysis artifacts:
- Use cases - capture high-level functionality and requirements
- Class diagrams - show object relationships and classes
- Activity/sequence diagrams - show object interactions and logic flow
- Other UML diagrams as needed

The analysis should result in a set of detailed specifications describing the objects, classes, and interfaces of the system. These artifacts are inputs to object-oriented design. Thorough analysis leads to a flexible system that can accommodate change.
