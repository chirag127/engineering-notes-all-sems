### Object design for the notes of the Unit 3 - Object Oriented Analysis in the subject of Object Oriented System Design

1. Identify objects:
- Look for nouns and noun phrases in the problem statement and use cases. These typically represent objects.
- Identify objects from the data that is being input and output. The data attributes become the properties of the objects and the transformations on data can be modeled as methods of the objects.
- Identify objects from responsibilities and behaviors. Objects are responsible for doing tasks or know how to perform certain operations.

2. Define object relationships:
- Objects rarely exist in isolation. Identify interactions between objects and model them as relationships.
- Common types of relationships include:
-- Association: A simple relationship between two objects.
-- Aggregation: A "has-a" relationship where the aggregated object can exist independently.
-- Composition: A "has-a" relationship where the composed object cannot exist independently.
-- Generalization: An "is-a" relationship between a general and more specific class.

3. Define object interfaces:
- Specify the capabilities of an object through its interface which includes methods and properties.
- Define the inputs and outputs of methods along with any side effects.
- Ensure interfaces are coherent and provide proper encapsulation.

4. Review and refine:
- Evaluate the object model for simplicity, completeness, consistency, flexibility, and scalability.
- Refactor as needed by combining or separating objects and updating interfaces and relationships.
- Get feedback from others and incorporate it into iterations of the design.
