### Conceptual model of the UML for the notes of the Unit 1 - Introduction: The meaning of Object Orientation in the subject of Object Oriented System Design

1. UML stands for Unified Modeling Language. It is a standardized general-purpose modeling language in the field of software engineering.
2. UML uses graphical notations to express the design of software projects. It provides a visual modeling language to visualize, specify, construct, and document software systems.
3. The main components of UML are:
- Use case diagrams: Represent the functionality of a system and the users who interact with the system.
- Class diagrams: Represent the static structure of a system. Shows classes, interfaces, and their relationships.
- Object diagrams: Instance-level view of a system, similar to class diagrams. Shows objects and their relationships.
- Sequence diagrams: Represent interactions between objects and the sequence of messages exchanged between the objects. Show the dynamic behavior of a system.
- Activity diagrams: Represent the flow of activities/actions in a system. Show the dynamic behavior.
- Statechart diagrams: Represent the states of a component and the events that cause the transition between the states. Show the dynamic behavior.
- Collaboration diagrams: Similar to sequence diagrams but focus on object interactions.
- Component diagrams: Represent the organization of physically deployed software components. Show the static structure.
- Deployment diagrams: Represent the hardware used in system implementations and the execution environments and artifacts deployed on the hardware. Show the static structure.

4. The main purpose of UML is to provide a common language/notation that can be understood by all stakeholders of a software system. It promotes better communication between stakeholders and reduces misunderstandings. It is platform independent and can be used throughout the software development lifecycle.
