### Use case Diagrams

- Use case diagrams are used to visually represent the functional requirements of a system.
- They show the interactions between the system and external actors/users.
- Use case diagrams are typically included as part of a system's requirements analysis to model the system's high-level functionality.
- They provide an overview of the relationship between the system and users/actors and help elicit and organize system requirements.

**Components of a Use Case Diagram:**

- System boundary: A rectangle used to enclose the system.
- Actors: Represent users/stakeholders of a system. They are external to the system and interact with it. Depicted as stick figures.
- Use cases: Represent high-level functionalities/capabilities of the system. Depicted as ovals.
- Relationships: Show interactions between actors and use cases. Mainly include:

-- <<include>>: Use case A includes use case B if the execution of A cannot be completed without also completing B.
-- <<extend>>: Use case A extends use case B if the execution of A typically includes the execution of B but B's execution is optional.
-- Communicates with: A line between an actor and a use case indicating that the actor communicates with the system to execute the use case.

**Advantages:**

- Helps elicit and organize system requirements.
- Provides an overview of the functionality of the system and its interactions with users.
- Easy to understand and create.
- Can be used as a communication tool between stakeholders.

**Disadvantages:**

- Does not show sequence/temporal logic.
- Does not capture detailed logic/process.
- The level of detail is limited.
- Does not show data/objects.
