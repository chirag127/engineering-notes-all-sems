## Designing Test Suites

A test suite is a collection of test cases that are intended to be used to test a software program to verify that it has some specified set of behaviours.

- **Purpose:** The purpose of designing a test suite is to maximise the testing coverage and effectiveness and to minimise the cost of testing. A good test suite should test all important/critical functionality and combinations of inputs/data to uncover as many bugs as possible.
- **Coverage criteria:** The different coverage criteria to keep in mind while designing a test suite are -
    - Requirements coverage - Test cases that exercise different system requirements
    - Statement coverage - Test cases that execute all statements in the program at least once
    - Branch coverage - Test cases that execute both the true and false branch of every conditional statement
    - Path coverage - Test cases that exercise all possible paths through the program
- **Techniques to design test suites:** Some useful techniques to design effective test suites are -
    - Equivalence partitioning - Dividing input data into partitions that are expected to exhibit similar behaviour
    - Boundary value analysis - Choosing test cases at boundaries of the input partitions
    - Cause-effect graphing - Identifying dependencies between inputs and their effects to design test cases
    - Error guessing - Anticipating errors and designing test cases to expose them
    - Random testing - Generating random inputs to test the software
    - Pairwise testing - Combining inputs in pairs to test for interactions
    - Orthogonal array testing - N-dimensional extension of pairwise testing
- **Advantages and disadvantages:** The pros of a well-designed test suite are complete testing and bug detection. The cons are that designing an exhaustive test suite can be difficult and time-consuming, the cost of testing increases with the number of test cases, and it still does not guarantee that all bugs will be found.
