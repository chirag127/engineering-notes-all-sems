## Modeling UML Class Diagrams and Sequence diagrams for the notes of the Software Engineering Mapping with Virtual Lab Lab in the subject of Software Engineering

Class Diagrams:

- Class diagrams are static structure diagrams that show the classes in a system and the relationships between them.
- They are used to model the static view of a system.
- Classes are represented by rectangles divided into compartments.
- Relationships between classes are represented by arrows.
- Common relationships are:
-- Association - represents a relationship between instances of two classes.
-- Generalization - represents an inheritance relationship between a general class and more specific subclasses.
-- Dependency - represents that one class requires another for functionality.
- Class diagrams are useful to:
-- Visualize, specify, and document the structure of a system.
-- Aid in communication between stakeholders.
-- Serve as a basis for programming and testing.

Sequence Diagrams:

- Sequence diagrams are interaction diagrams that show how objects interact with each other over time.
- They are used to model the dynamic behavior of a system.
- Objects are shown as lifelines arranged vertically, and messages are shown as arrows between the lifelines.
- The vertical arrangement represents the time.
- Sequence diagrams are useful to:
-- Model the logic of complex logic interactions.
-- Document the logic of a system.
-- Aid in programming by describing the interactions required.
