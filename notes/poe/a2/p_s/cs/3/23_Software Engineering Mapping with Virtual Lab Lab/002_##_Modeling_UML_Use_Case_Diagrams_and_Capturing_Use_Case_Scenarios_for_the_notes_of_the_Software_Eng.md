## Modeling UML Use Case Diagrams and Capturing Use Case Scenarios

- Use case diagrams are used to visualize the functionality of a system using actors and use cases.
- Actors represent the users of a system. They can be human users or other systems.
- Use cases represent high-level functionalities/goals of a system that provide some observable value to the actors.
- Use case diagrams show the interaction between actors and use cases. They are used to capture the requirements of a system.
- To model a use case diagram:

1. Identify the actors that will interact with the system.
2. Identify the key goals/functionalities of the system i.e. the use cases.
3. Show the interaction between actors and use cases. An actor can interact with multiple use cases and vice versa.
4. Use arrows to depict relationships/interactions. The arrowhead points to the use case.

- To capture use case scenarios:

1. Identify the main success scenario. This shows the basic flow of events.
2. Capture extensions and exceptions. These show alternate flows and error conditions respectively.
3. Write brief descriptions of each scenario in a structured format using actors, use cases and extension points.
4. Include relevant details like preconditions, postconditions, triggers, inputs, outputs etc. for each scenario.

- Advantages: Helps understand system functionality, identifies system requirements, facilitates communication between stakeholders.
- Disadvantages: Can be complex for large systems, does not show the sequence/timing of interactions, abstract nature can lead to inconsistencies.
- Applications: Requirements analysis, designing system architecture.
