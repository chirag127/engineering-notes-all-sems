## Estimation of Test Coverage Metrics and Structural Complexity

- Test coverage metrics are used to measure the adequacy of a test suite. Some commonly used test coverage metrics are:
	- Statement coverage: Proportion of statements executed by the test suite.
	- Branch coverage: Proportion of branches (where the control flow diverges) executed by the test suite.
	- Path coverage: Proportion of possible paths through the code executed by the test suite.
- Higher test coverage does not necessarily mean better quality tests. 100% statement coverage just means all statements were executed, but does not guarantee that all possible inputs or data values were tried.
- Structural complexity refers to the control flow structure of the code. Some measures of structural complexity are:
	- Cyclomatic complexity: Number of independent paths through the code. Calculated from the control flow graph.
	- Nesting depth: Maximum level of nested control structures (if-else, loops, etc.).
	- Number of parameters: Can increase cognitive complexity for programmers.
- High structural complexity makes code harder to understand, debug and test thoroughly. It is a good practice to keep methods/functions simple and modular to reduce complexity.
