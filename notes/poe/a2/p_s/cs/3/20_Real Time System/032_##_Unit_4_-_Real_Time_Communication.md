## Unit 4 - Real Time Communication

Real time communication refers to the exchange of information with minimal latency. Some key aspects of real time communication are:

1. Low latency - The time taken for a packet of data to be sent from one point to another is very low. This is essential for applications like video calling, online gaming, etc. where even small delays can degrade the user experience.
2. Reliability - The packets of data must be reliably delivered within the required latency constraints. Some amount of packet loss is tolerable but beyond a threshold, it can affect the communication.
3. Scalability - The real time communication system must be able to scale to handle a large number of simultaneous connections and throughput requirements.
4. Interactivity - The low latency and reliability ensure a high degree of interactivity where the users can exchange information with imperceptible delays.

Some examples of real time communication are:

- Video calling - Requires low latency and high reliability for a good user experience.
- Online gaming - Requires low latency so that players can interact with minimal lag.
- Chat applications - Although tolerable to slight delays, requires reliable delivery of messages.
- Live streaming - Requires minimal latency so that the viewer experiences the stream with little buffering.

The key technologies enabling real time communication are:

- WebRTC - Allows web apps to capture media and establish peer to peer real time communication.
- Socket.io - Enables real time bidirectional communication over websockets.
- TCP/IP - Although not designed for real time communication, can be tuned for reliability and low latency.
- UDP - A lightweight transport layer protocol which can be used for low latency communication by sacrificing some reliability.
