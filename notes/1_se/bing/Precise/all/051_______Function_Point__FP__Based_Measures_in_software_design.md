##### Function Point (FP) Based Measures in software design

Function Point (FP) is a measure of the functionality provided by a software system. It is a standardized method for measuring the size of a software application in terms of the functionality it provides to the user. The method was developed by the International Function Point Users Group (IFPUG) and is widely used in the software industry.

The main advantages of using Function Point (FP) based measures in software design are:

1. **Independence from technology:** FP measures are independent of the technology used to implement the software, making it possible to compare the size of software systems developed using different technologies.

2. **User-oriented:** FP measures are based on the functionality provided to the user, rather than the technical complexity of the software. This makes it easier for non-technical stakeholders to understand the size of a software system.

3. **Standardized:** The FP counting method is standardized, making it possible to compare the size of software systems developed by different organizations.

4. **Useful for estimation:** FP measures can be used to estimate the effort and cost required to develop a software system.

The main steps involved in counting Function Points are:

1. Identify the functional user requirements of the software system.
2. Classify the functional user requirements into five categories: External Inputs (EI), External Outputs (EO), External Inquiries (EQ), Internal Logical Files (ILF), and External Interface Files (EIF).
3. Assign a complexity level (low, average, or high) to each functional user requirement based on its characteristics.
4. Use the IFPUG complexity tables to determine the number of Function Points for each functional user requirement.
5. Calculate the total number of Function Points for the software system by summing the Function Points for all functional user requirements.

There are no widely accepted mnemonics or learning tricks for Function Point (FP) based measures in software design. However, one way to remember the five categories of functional user requirements is to use the acronym FURPS, which stands for Functionality, Usability, Reliability, Performance, and Supportability. These are the five main quality attributes of a software system, and each of the five categories of functional user requirements can be mapped to one of these quality attributes.

In summary, Function Point (FP) based measures provide a standardized, user-oriented, and technology-independent way to measure the size of a software system. They are widely used in the software industry and can be useful for estimation and comparison purposes. However, there are no widely accepted mnemonics or learning tricks for FP based measures, and the counting process can be complex and time-consuming.
