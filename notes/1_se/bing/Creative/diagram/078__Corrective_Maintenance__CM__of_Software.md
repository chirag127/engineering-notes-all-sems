Corrective Maintenance (CM) of Software is a type of maintenance strategy that is used to correct errors and faults within software applications that could impact various parts of the software, including the design, logic, and code. CM is performed after a failure or a breakdown of the software is detected, and its main objective is to restore the software to its normal working condition. CM can be either planned or unplanned, depending on the severity and frequency of the failure. CM can also be used as part of a wider strategy to plan the maintenance of the software.

The following diagram illustrates the basic steps of CM of Software using ASCII characters:

```
+-----------------+       +-----------------+       +-----------------+
|                 |       |                 |       |                 |
|  Failure        |       |  Diagnosis      |       |  Repair         |
|  Detection      | +---> |  and Analysis   | +---> |  or Replacement |
|                 |       |                 |       |                 |
+-----------------+       +-----------------+       +-----------------+
```

The diagram shows that CM of Software involves three main steps:

- Failure Detection: This is the process of identifying and reporting the failure or the malfunction of the software. This can be done by the users, the developers, the testers, or the monitoring tools. Failure detection can also be triggered by routine inspections or condition monitoring.
- Diagnosis and Analysis: This is the process of finding the root cause and the extent of the failure. This can be done by using debugging tools, log files, error messages, or other methods. Diagnosis and analysis can also involve testing and verifying the software to determine the impact of the failure on the functionality and the performance of the software.
- Repair or Replacement: This is the process of fixing the failure or the defect in the software. This can be done by modifying the code, the design, or the logic of the software, or by replacing the faulty component or module with a new or a backup one. Repair or replacement can also involve retesting and validating the software to ensure that the failure is resolved and the software is working as expected.
