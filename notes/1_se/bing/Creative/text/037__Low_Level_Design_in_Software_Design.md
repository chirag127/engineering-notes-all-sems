### Low Level Design in Software Design

Low level design (LLD) is a component-level design process that follows a step-by-step refinement process. This process can be used for designing data structures, required software architecture, source code and ultimately, performance algorithms . LLD describes class diagrams with the help of methods and relations between classes and program specs. It describes every module in detail by incorporating the logic behind every component in the system. It delves deep into every specification of every system, providing a micro-level design. LLD is also known as object-level design or micro-level or detailed design.

The main objective of preparing low-level design is to mitigate any additional burden developers face during the development phase by clearly laying out details. The LLD is essentially a go-to document for the developers; reference material with all the technicalities involved, a well laid out map, with the intention to make development a very smooth journey.

The input to LLD is high level design (HLD), which is a general system design that defines the components and how these components will be communicating with one another. The high-level design fixes the what, and the low-level design is all about hows. The LLD has exhaustive application detailing that concentrates on how the different parts of the unit will work together. It gets into the details of how the components and classes work, the various properties of the classes, the definitions of the database, and the interfaces.

To create a low-level design, the following steps are recommended:

- Use object-oriented principles to process the user requirements. The user should have a strong grip on OOPS concepts such as inheritance, encapsulation, polymorphism, and abstraction.
- Use Unified Modelling Language (UML) diagrams to represent the structure and behavior of the classes, methods, and relations between them. UML diagrams include class diagrams, sequence diagrams, use case diagrams, etc.
- Use SOLID principles to ensure that the design is cohesive, loosely coupled, easy to maintain, and extensible. SOLID principles include single responsibility, open-closed, Liskov substitution, interface segregation, and dependency inversion.
- Use pseudocode or flowcharts to describe the logic and algorithm of each module or method. Pseudocode or flowcharts help to visualize the steps and conditions involved in the implementation of the functionality.
- Use comments and documentation to explain the purpose, functionality, and assumptions of each module or method. Comments and documentation help to improve the readability and understandability of the code and design.

Some of the benefits of low-level design are:

- It helps to reduce the complexity and ambiguity of the system by breaking it down into smaller and simpler components.
- It helps to improve the quality and efficiency of the code by ensuring that each component is well-defined, testable, and reusable.
- It helps to facilitate the communication and collaboration among the developers, testers, and other stakeholders by providing a common language and reference point for the system.
- It helps to reduce the errors and bugs in the system by enabling early detection and correction of any design flaws or inconsistencies.
