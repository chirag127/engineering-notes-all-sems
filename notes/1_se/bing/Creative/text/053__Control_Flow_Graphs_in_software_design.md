###### Control Flow Graphs in software design

- A control flow graph (CFG) is a graphical representation of the control flow or computation during the execution of programs or applications .
- Control flow graphs are mostly used in static analysis as well as compiler applications, as they can accurately represent the flow inside of a program unit .
- The control flow graph was originally developed by Frances E. Allen .
- A control flow graph is composed of nodes and edges. Nodes represent basic blocks, which are sequences of instructions that have a single entry point and a single exit point. Edges represent the possible paths of control flow between the nodes.
- There are two designated nodes in a control flow graph: the entry node, which allows the control to enter the graph, and the exit node, which allows the control to leave the graph.
- Control flow graphs can show the different paths that can be traversed during a program execution, depending on the conditions and decisions made by the program .
- Control flow graphs can help in identifying the syntactic structures of a program, such as loops, branches, and subroutines .
- Control flow graphs can also help in finding unreachable or dead code, optimizing the code, testing the code coverage, and generating intermediate code .
- Control flow graphs use different symbols to represent the different types of nodes and edges, such as circles, diamonds, rectangles, and arrows.
- Control flow graphs can be drawn for different types of statements and loops, such as if-else, while, do-while, and for .
