### Decision Tables in Software Requirement Specification (SRS)

- A decision table is a tabular representation of the logic and rules that govern the behavior of a software system based on different combinations of inputs and conditions.
- A decision table consists of four quadrants: condition stubs, condition entries, action stubs and action entries.
- Condition stubs are the names or labels of the inputs and conditions that affect the system's behavior.
- Condition entries are the possible values or states of the inputs and conditions, usually represented by symbols such as Y (yes), N (no), - (don't care) or * (any value).
- Action stubs are the names or labels of the outputs or actions that the system performs based on the inputs and conditions.
- Action entries are the indicators of whether an output or action is executed or not, usually represented by symbols such as X (execute), - (don't execute) or / (optional).
- A decision table can have one or more rules, which are the horizontal rows that define the relationship between the condition entries and the action entries.
- A decision table can be used to specify the functional requirements of a software system in a clear, concise and unambiguous way, as well as to verify the completeness and consistency of the requirements.
- A decision table can also be used to design test cases, as each rule represents a possible scenario or situation that the system should handle correctly.
