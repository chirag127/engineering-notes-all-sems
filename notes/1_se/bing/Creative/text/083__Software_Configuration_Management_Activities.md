### Software Configuration Management Activities

Software configuration management (SCM) is a process to systematically manage, organize, and control the changes in the documents, codes, and other entities during the software development life cycle. The primary goal is to increase productivity with minimal mistakes. SCM is part of cross-disciplinary field of configuration management and it can accurately determine who made which revision.

Software configuration management includes following activities:

- **Configuration identification** – Identifying configurations, configuration items and baselines. Configuration items are the software components that need to be managed and controlled, such as source code modules, test cases, and requirements specifications. Baselines are the approved versions of configuration items that serve as reference points for further development. Configuration identification is a method of determining the scope of the software system and creating a unique name and version number for each configuration item .

- **Configuration control** – Implementing a controlled change process. Configuration control is the process of managing and documenting the changes to the configuration items and baselines. It involves reviewing, approving, and implementing the change requests from the stakeholders. Configuration control ensures that only authorized changes are made and that the integrity and quality of the software system are maintained .

- **Configuration status accounting** – Recording and reporting all the necessary information on the status of the development process. Configuration status accounting is the process of collecting, storing, and reporting the information about the configuration items and baselines, such as their current version, location, modification history, and dependencies. Configuration status accounting provides visibility and traceability of the software system and supports decision making and auditing .

- **Configuration auditing** – Verifying that the software system meets the specified requirements and standards. Configuration auditing is the process of checking that the configuration items and baselines are consistent, complete, and correct. It involves conducting formal and informal reviews and inspections to ensure that the software system conforms to the design specifications, quality criteria, and regulatory requirements. Configuration auditing also verifies that the configuration management process is followed and that the configuration management records are accurate and up-to-date .

- **Software release management and delivery** – Preparing and distributing the software system to the end users. Software release management and delivery is the process of packaging, labeling, and delivering the software system and its associated documentation to the intended customers or users. It involves planning, scheduling, coordinating, and executing the release activities, such as testing, installation, configuration, and deployment. Software release management and delivery ensures that the software system is delivered in a timely, reliable, and secure manner .
