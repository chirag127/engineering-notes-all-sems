#### Structural Testing (White Box Testing) software testing strategy

- Structural testing, also known as white box testing, is a software testing strategy that focuses on the internal structure, design, and implementation of the software system.
- The main objective of structural testing is to verify that the software conforms to the specified design and coding standards, and that it has adequate coverage of all possible paths, branches, statements, and conditions in the code.
- Structural testing requires the tester to have access to the source code and detailed knowledge of the programming logic and techniques used in the software development.
- Structural testing can be performed at different levels of testing, such as unit testing, integration testing, and system testing, depending on the scope and complexity of the software system.
- Some of the common techniques and tools used for structural testing are:

  - Code review: A manual inspection of the source code to identify errors, defects, and violations of coding standards and best practices.
  - Static analysis: An automated analysis of the source code to detect syntactic, semantic, and logical errors, as well as potential security vulnerabilities and performance issues.
  - Code coverage: A measurement of how much of the source code is executed by the test cases, expressed as a percentage or a ratio. Code coverage can be calculated at different levels, such as statement coverage, branch coverage, condition coverage, and path coverage.
  - Code metrics: A quantitative assessment of the quality and complexity of the source code, based on various attributes and indicators, such as lines of code, cyclomatic complexity, cohesion, coupling, maintainability index, and defect density.
  - Debugging: A process of locating and fixing errors and defects in the source code, using various tools and techniques, such as breakpoints, watchpoints, step-by-step execution, and logging.
  - Profiling: A process of measuring and analyzing the performance and resource consumption of the software system, such as CPU time, memory usage, disk I/O, network traffic, and response time, using various tools and techniques, such as timers, counters, monitors, and tracers.
