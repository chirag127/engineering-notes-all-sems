### Software Development Life Cycle (SDLC) Models

- Software Development Life Cycle (SDLC) is a process that describes the stages involved in developing a software product from planning to deployment and maintenance.
- SDLC models are different approaches or methodologies that guide the software development process and define the tasks, roles, and deliverables for each stage.
- Some of the common SDLC models are:

  - **Waterfall model**: A linear and sequential model that follows a fixed set of phases in a strict order. Each phase must be completed and verified before moving to the next phase. The phases are: requirement analysis, design, implementation, testing, deployment, and maintenance. This model is suitable for well-defined and stable projects with clear requirements and minimal changes.
  - **Agile model**: An iterative and incremental model that focuses on delivering working software in short cycles called sprints. Each sprint involves planning, designing, developing, testing, and reviewing the software. The requirements and design are flexible and can be changed based on customer feedback and changing needs. This model is suitable for dynamic and complex projects with uncertain requirements and frequent changes.
  - **Spiral model**: A hybrid model that combines the features of the waterfall and agile models. It follows a circular approach that consists of four phases: planning, risk analysis, engineering, and evaluation. Each phase is repeated until the software meets the customer's expectations and quality standards. This model is suitable for large and risky projects that require extensive testing and evaluation.
  - **V-model**: An extension of the waterfall model that emphasizes the verification and validation of the software at each stage. It follows a V-shaped structure that maps the testing activities to the corresponding development activities. The phases are: requirement analysis, system design, architectural design, module design, coding, unit testing, integration testing, system testing, and acceptance testing. This model is suitable for projects with well-defined and testable requirements and high quality standards.
  - **Prototyping model**: A model that involves creating a simplified version of the software called a prototype that demonstrates the key features and functionality of the software. The prototype is shown to the customer and refined based on their feedback until it meets their requirements and expectations. The prototype is then used as a basis for developing the final software. This model is suitable for projects with unclear or evolving requirements and high user involvement.
