### SRS Document

- An SRS document is a Software Requirements Specification document that describes what the software will do and how it will be expected to perform .
- It also describes the functionality the product needs to fulfill the needs of all stakeholders (business, users)  .
- An SRS document is a comprehensive description of a software system that determines what features a system must have and how its features must function .
- An SRS document is a written agreement between the client and the developers on every detail of the app .
- An SRS document is a blueprint or roadmap for the software development process that provides a single source of truth for all the teams involved .
- An SRS document helps to keep the teams aligned, ensure that each requirement is met, and make vital decisions on the product’s lifecycle .
- An SRS document consists of four main parts: an introduction, system and functional requirements, external interface requirements, and non-functional requirements .
- The introduction provides the purpose, scope, definitions, acronyms, abbreviations, references, and overview of the document .
- The system and functional requirements describe the behavior and capabilities of the software system in terms of use cases, scenarios, user stories, or functional specifications .
- The external interface requirements specify the interfaces between the software system and other systems, such as hardware, software, or users .
- The non-functional requirements define the quality attributes, constraints, and assumptions of the software system, such as performance, security, reliability, usability, or maintainability .
- An SRS document should be clear, concise, consistent, complete, correct, traceable, verifiable, modifiable, and prioritized   .
- An SRS document should be written in a formal and structured language, such as natural language, structured natural language, design description language, or graphical notation .
- An SRS document should be updated and revised throughout the software development process to reflect any changes or feedback from the stakeholders  .
