### Integration Testing in Software Testing

- Integration testing is a type of software testing where software modules are integrated logically and tested as a group  .
- The purpose of integration testing is to expose defects in the interaction between these software modules when they are integrated.
- Integration testing focuses on checking data communication among these modules.
- Integration testing is also known as 'I & T' (Integration and Testing), 'String Testing' and sometimes 'Thread Testing'.
- Integration testing is conducted after unit testing and before system testing.
- Integration testing can be performed using different approaches, such as  :
  - Big Bang Testing: All the modules are grouped together and tested as a whole .
    - Advantages: Works best for small systems. Yields quick results.
    - Disadvantages: Greater difficulty in locating faults. Potential for overlooking a component. All units need to be complete, so testing can’t begin early. High-risk modules don’t get specialized attention.
  - Incremental Testing: The modules are integrated and tested one by one or in small groups .
    - Advantages: Locating and fixing faults is easier. Testing can begin early. Critical modules can be tested first .
    - Disadvantages: Stubs or drivers may be needed for missing modules. Some modules may be tested more than once .
    - Types of Incremental Testing:
      - Bottom-up Testing: Lower-level modules are integrated and tested first, then higher-level modules are tested and integrated  .
        - Advantages: Locating and fixing faults is easier. No need to wait for all units to be completed before testing begins.
        - Disadvantages: Critical, high-level components are tested last. Not possible to create an early prototype.
      - Top-down Testing: High-level modules are integrated and tested first, then lower-level modules are tested and integrated  .
        - Advantages: Locating and fixing faults is easier. It’s possible to create an early prototype. Tests performed based on priority reveal major flaws you can fix before complete integration.
        - Disadvantages: Stubs have to be created for missing modules. Lower-level units are often inadequately tested.
      - Sandwich Testing: A combination of bottom-up and top-down testing, where the middle-level modules are tested first, then the lower-level and higher-level modules are tested and integrated .
        - Advantages: Reduces the need for stubs and drivers. Allows parallel testing of different levels. Covers more scenarios and interactions .
        - Disadvantages: More complex and costly. Requires more coordination and communication among testers .
- Integration testing requires a test plan, test cases, test data, and test environment.
- Integration testing can be done manually or using automated tools.
- Some popular integration testing tools are:
  - Programming-language specific tools: These are tools designed to test software coded in a specific coding language, for example, JUnit for Java, PyTest for Python, NUnit for .NET, etc.
  - Rare-language tools: These are tools used for rarer languages or languages with fewer tests available, for example, Testwell CTC++ for C and C++, TestNG for Groovy, etc.
  - Multiple-language tools: These are tools that can test software coded in different languages, for example, Selenium for web applications, SoapUI for web services, etc.
- Integration testing is important because  :
  - It ensures the quality and functionality of the software system as a whole.
  - It detects and fixes interface errors and data flow issues among modules.
  - It verifies the compliance of the system with the specified functional requirements.
  - It reduces the risk of failures and defects in the later stages of testing and deployment.
  - It improves the reliability, performance, and security of the system.
