### Software Configuration Management Activities

Software Configuration Management (SCM) is a process to systematically manage, organize, and control the changes in the documents, codes, and other entities during the Software Development Life Cycle. The primary goal is to increase productivity with minimal mistakes. SCM is part of cross-disciplinary field of configuration management and it can accurately determine who made which revision.

Software Configuration Management includes following activities :

1. **Configuration identification** – Identifying configurations, configuration items and baselines. Configuration items are the software components that need to be managed and controlled, such as source code modules, test cases, and requirements specifications. Baselines are the approved versions of configuration items that serve as a reference point for further development. Configuration identification is the process of naming, describing, and grouping the configuration items and baselines in a consistent and logical way.
2. **Configuration control** – Implementing a controlled change process. Configuration control is the process of managing and documenting the changes to the configuration items and baselines. It involves evaluating, approving, tracking, and implementing the change requests from various stakeholders. Configuration control ensures that only authorized and consistent changes are made to the software system.
3. **Configuration status accounting** – Recording and reporting all the necessary information on the status of the development process. Configuration status accounting is the process of collecting, storing, and reporting the information about the configuration items and baselines, such as their versions, locations, dependencies, and change history. Configuration status accounting provides visibility and traceability of the software system throughout its life cycle.
4. **Configuration audits and reviews** – Verifying the completeness and correctness of the configuration items and baselines. Configuration audits and reviews are the process of checking and validating that the configuration items and baselines conform to the requirements, standards, and specifications. Configuration audits and reviews ensure that the software system meets the quality and performance criteria.
5. **Release management and delivery** – Preparing and distributing the software system to the end users. Release management and delivery is the process of packaging, testing, and deploying the software system to the intended environment. Release management and delivery ensures that the software system is delivered in a timely and reliable manner.

A possible mnemonic to remember the software configuration management activities is **CICAR** (Configuration Identification, Configuration Control, Configuration Status Accounting, Configuration Audits and Reviews, Release management and delivery).
