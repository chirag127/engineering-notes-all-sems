## Unit 5 - Software Maintenance and Software Project Management

- Software maintenance is the process of modifying and updating software after delivery to correct faults, improve performance, or adapt to changing environments.
- Software project management is the practice of planning, organizing, and controlling software development activities to achieve specific goals within time, budget, and quality constraints.
- Software maintenance and software project management are closely related, as both involve managing software evolution, ensuring product quality, and satisfying customer requirements.
- Some of the topics covered in this unit are:

  - Software as an evolutionary entity: Software evolution is the process of creating software and then upgrading it on a regular basis for different purposes, such as adding new features or removing obsolete functionality. Software evolution can be classified into four types:
    - Corrective maintenance: Fixing errors or defects in the software.
    - Adaptive maintenance: Adapting the software to new or changing environments, such as hardware, operating systems, or standards.
    - Perfective maintenance: Enhancing the software by adding new features, improving performance, or increasing usability.
    - Preventive maintenance: Improving the software structure or documentation to make it easier to maintain in the future.
  - Software maintenance models: Software maintenance models are frameworks that describe the activities, processes, and resources involved in software maintenance. Some of the common software maintenance models are:
    - Quick fix model: A simple and informal model that involves making immediate and minimal changes to the software without proper documentation or testing.
    - Iterative enhancement model: A structured and formal model that involves dividing the software into modules and applying a cycle of analysis, design, implementation, and testing to each module.
    - Reengineering model: A radical and comprehensive model that involves redesigning and rebuilding the software from scratch, using new technologies, methods, or tools.
  - Software project management phases and best practices: Software project management phases are the stages of a software project, from inception to completion. Each phase has its own objectives, deliverables, and activities. The four main software project management phases are :
    - Inception: The phase where the project scope, requirements, features, risks, constraints, and plan are defined and justified.
    - Elaboration: The phase where the project plan and the architectural design are validated and refined, and the risks are managed and mitigated.
    - Construction: The phase where the software is developed, tested, and integrated, following the chosen SDLC model, framework, and methodology.
    - Transition: The phase where the software is deployed, delivered, and accepted by the customer, and the project is closed and evaluated.
  - Software project management tools and techniques: Software project management tools and techniques are the software applications, methods, and practices that help software project managers and teams to perform their tasks more effectively and efficiently. Some of the common software project management tools and techniques are :
    - Project management software: Software that provides features such as task management, scheduling, resource allocation, budgeting, reporting, and collaboration for software projects. Examples are Teamwork, Jira, Trello, etc.
    - Configuration management: The process of controlling and tracking the changes made to the software and its components, such as code, documents, data, etc. Examples are Git, SVN, CVS, etc.
    - Test-driven development (TDD): A software development methodology that involves writing tests before writing code, and then writing code that passes the tests. This helps to ensure the quality and functionality of the software. Examples are JUnit, NUnit, PyTest, etc.
    - Information system development: The process of designing, developing, and implementing information systems that support the business processes and objectives of an organization. Examples are ERP, CRM, MIS, etc.

- Some of the mnemonics and learning tricks for this unit are:

  - To remember the four types of software maintenance, use the acronym CAPT: Corrective, Adaptive, Perfective, and Preventive.
  - To remember the four phases of software project management, use the acronym ICE-T: Inception, Elaboration, Construction, and Transition.
  - To remember the difference between software maintenance and software project management, use the phrase: Software maintenance is about fixing and improving the software, while software project management is about planning and delivering the software.
