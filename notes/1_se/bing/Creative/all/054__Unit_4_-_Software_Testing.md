## Unit 4 - Software Testing

Software testing is the process of evaluating and verifying that a software product or application does what it is supposed to do. The benefits of testing include preventing bugs, reducing development costs and improving performance. Software testing is part of the quality assurance process that covers the entire software development life cycle .

There are many different types of software tests, each with specific objectives and strategies. Some of the common types of software testing are:

- **Functional testing**: Checking functions by emulating business scenarios, based on functional requirements. Black-box testing is a common way to verify functions .
- **Non-functional testing**: Assessing software properties non-critical to functionality but imperative for a positive user experience. Examples are performance testing, usability testing, stress testing and load testing .
- **Maintenance testing**: Fixing bugs and releasing new features to a live application. Examples are confirmation testing and regression testing .

Software testing methods are traditionally divided into white- and black-box testing. These two approaches are used to describe the point of view that the tester takes when designing test cases. A hybrid approach called grey-box testing may also be applied to software testing methodology .

- **White-box testing**: Testing the internal structure and logic of the code. The tester has access to the source code and can design test cases based on the code coverage. Examples are unit testing and integration testing .
- **Black-box testing**: Testing the external functionality and behavior of the software. The tester does not have access to the source code and can design test cases based on the specifications and requirements. Examples are system testing and user acceptance testing .
- **Grey-box testing**: Testing the software with partial knowledge of the internal structure and logic of the code. The tester has access to some of the source code and can design test cases based on the combination of white- and black-box testing techniques .

Some of the mnemonics and learning tricks for software testing are:

- **EPIC**: A mnemonic for the four levels of testing: **E**nd-to-end testing, **P**erformance testing, **I**ntegration testing and **C**omponent testing.
- **CRUD**: A mnemonic for the four basic functions of a software system: **C**reate, **R**ead, **U**pdate and **D**elete. These functions can be used as test cases for functional testing.
- **FURPS**: A mnemonic for the five categories of non-functional requirements: **F**unctionality, **U**sability, **R**eliability, **P**erformance and **S**ecurity. These categories can be used as test criteria for non-functional testing.
- **Pesticide paradox**: A term that describes the phenomenon that if the same tests are repeated over and over again, they eventually stop finding new bugs. The solution is to regularly review and revise the test cases to cover new scenarios and conditions.
