### Documentation in Requirement Engineering Process in SRS

- Documentation in requirement engineering process is the activity of creating a Software Requirements Specification (SRS) document that describes what the software will do and how it will be expected to perform.
- An SRS document is a blueprint or roadmap for the software development process that defines the purpose, scope, functionality, quality, and constraints of the software product .
- An SRS document also serves as a contract between the development team and the customer, as it confirms that the team understands the customer's problems and needs, and that the customer agrees with the proposed solution.
- The benefits of documentation in requirement engineering process are  :
  - It provides valuable customer feedback and ensures alignment of expectations and requirements.
  - It breaks down the work into smaller and manageable pieces and facilitates planning and estimation.
  - It serves as a parent document for other documents that follow, such as design specifications, test cases, user manuals, etc.
  - It helps to identify and resolve problems early in the development process and reduces the risk of rework and wasted time.
  - It helps to validate the product and verify that it meets the customer's requirements and expectations.
- The steps to write an SRS document are   :
  - Define the purpose of the product and the scope of the project with an outline or a template.
  - Describe the product's features, functions, behaviors, and interfaces, as well as the user roles, scenarios, and use cases.
  - Detail the specific requirements, both functional and non-functional, such as performance, reliability, security, usability, etc.
  - Deliver the SRS document for approval by all the stakeholders, such as the customer, the developers, the testers, the managers, etc.
- The format of an SRS document may vary depending on the project, the organization, and the standards used, but some common elements are   :
  - Introduction: It provides an overview of the document, its purpose, scope, objectives, assumptions, definitions, acronyms, references, etc.
  - System Overview: It provides a high-level description of the system, its context, its goals, its benefits, its constraints, its dependencies, etc.
  - System Requirements: It provides a detailed description of the system's functionality, behavior, and quality attributes, as well as the user requirements, data requirements, interface requirements, etc.
  - System Models: It provides a graphical representation of the system's structure, behavior, and interactions, such as data flow diagrams, entity-relationship diagrams, state transition diagrams, etc.
  - System Evolution: It provides a description of how the system may change or evolve over time, such as new features, enhancements, maintenance, etc.
  - Appendices: It provides any additional information that may be useful or relevant, such as glossary, bibliography, index, etc.

- A mnemonic to remember the steps to write an SRS document is **D3A**: **D**efine, **D**escribe, **D**etail, **A**pprove.
- A mnemonic to remember the format of an SRS document is **ISMSA**: **I**ntroduction, **S**ystem Overview, **S**ystem Requirements, **M**odels, **S**ystem Evolution, **A**ppendices   .
