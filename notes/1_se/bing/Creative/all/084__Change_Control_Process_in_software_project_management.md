### Change Control Process in software project management

- Change control is the process of managing and assessing changes to a software project and its procedures. Change control can help a project manager to regulate the project and alter it based on changing environments, conditions or requirements.
- Change control is part of a larger change management plan, which defines the roles and responsibilities for managing change within a team or organization .
- Change control involves creating and maintaining a change log, where all the change requests and their statuses are recorded .
- A change request is a formal document that outlines a request for change and the impact of the change on the project scope, schedule, budget, quality and risks . A change request can be submitted by any stakeholder, internal or external.
- A change control board is a group of representatives from the project team that regularly meet to review, approve, reject or defer change requests. A change control board can also issue change orders, which are agreements between the project team and the clients or stakeholders to change the original contract terms.
- The change control process typically consists of the following steps :
  - Step 1: Document the change request. When a change request occurs, the first step is to categorize and record it in the change log. The change request should include the following information: the description of the change, the reason for the change, the impact of the change, the priority of the change, the proposed solution, the estimated cost and time, and the approval status .
  - Step 2: Conduct a formal change evaluation. Next, the project team will meet and formally evaluate the change request. The evaluation should consider the following criteria: the alignment of the change with the project objectives, the feasibility of the change, the benefits and drawbacks of the change, the risks and dependencies of the change, and the alternatives to the change .
  - Step 3: Plan the change. If the change request is approved, the next step is to plan the change. This involves updating the project plan, the project scope, the project schedule, the project budget, the project quality standards, and the project risk register to reflect the change .
  - Step 4: Design software changes. If the change request involves software changes, the next step is to design the software changes. This involves creating or modifying the software requirements, the software architecture, the software design, the software code, and the software testing plan to implement the change.
  - Step 5: Conduct an internal software review. If the change request involves software changes, the next step is to conduct an internal software review. This involves verifying and validating the software changes, performing code reviews, testing the software changes, and documenting the software changes.
  - Step 6: Conduct a final assessment. The final step is to conduct a final assessment of the change request. This involves comparing the actual results of the change with the expected results, measuring the performance and quality of the change, identifying the lessons learned from the change, and closing the change request in the change log .

- A possible mnemonic to remember the steps of the change control process is: **D**ocument, **E**valuate, **P**lan, **D**esign, **R**eview, **A**ssess, or **DEPDRA**.
- A possible learning trick to understand the change control process is to use a real-life example of a software project change, such as adding a new feature, fixing a bug, or improving the user interface. For each step of the change control process, think of what actions you would take, what documents you would update, and what outcomes you would expect. This can help you to visualize and apply the change control process in practice.
