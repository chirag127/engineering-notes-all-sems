### Static Testing Strategies in Software Testing

1. Code Review - Manually checking the source code for errors, bugs, security loopholes, etc. The code is reviewed by fellow programmers or software testers. Code review can identify maximum number of bugs, if done thoroughly.
2. Static Analysis - Using automated tools to analyze the source code. These tools check for compliance to coding standards, memory leaks, undefined variables, dead code, etc. Some commonly used static analysis tools are Splint, FlawFinder, FindBugs, PMD, etc.
3. Structural Testing - Analyzing the internal structure of the software to identify complexity, redundancy, etc. Usually done using graph theory. Helps in estimating risk areas in software.
4. Formal Verification - Using mathematical techniques to verify and validate software. Helps in establishing correctness of software. Appropriate for critical software. Techniques like model checking, theorem proving, etc. are used.

The above testing strategies analyze the software from its source code without actually executing it. These help identify maximum bugs earlier in the software development lifecycle and reduce the overall cost of testing and bug fixing. However, static testing may not identify all bugs as the software behavior cannot be determined without execution. Hence, static testing should be complemented with dynamic testing strategies for comprehensive software testing.
