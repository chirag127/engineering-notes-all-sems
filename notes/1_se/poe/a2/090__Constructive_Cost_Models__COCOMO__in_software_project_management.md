### Constructive Cost Models (COCOMO) in software project management.

1. COCOMO stands for Constructive Cost Models. It is a regression model based on lines of code, used to estimate effort, cost, and schedule when planning software projects.
2. COCOMO was created by Barry Boehm in 1981. It provides a basic way to estimate software development effort based on program size expressed in estimated lines of code (LOC).
3. There are three COCOMO models:
- Basic COCOMO: Estimates effort and cost. Requires only one input - lines of code.
- Intermediate COCOMO: Estimates effort, cost, and schedule. Requires four inputs - lines of code, program type, hardware constraints, personnel quality.
- Detailed COCOMO: Estimates effort, cost, and schedule. Requires 15 inputs related to software, hardware, personnel, etc.
4. The COCOMO models use effort to derive estimates of cost and schedule. Effort is expressed in person-months or person-years. These metrics can then be converted to time and cost. The more complex the software, the more effort and cost is required.
5. advantages:
- COCOMO is simple and easy to use.
- It relates program size to effort, so it is understandable and credible.
- It has been widely used and tested on many projects.
- Disadvantages:
- The COCOMO models are quite crude and the estimates can be inaccurate.
- The input parameters are difficult to estimate.
- COCOMO does not adequately consider factors like software complexity and team capability.
