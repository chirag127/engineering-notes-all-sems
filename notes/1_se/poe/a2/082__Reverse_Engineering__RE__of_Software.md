### Reverse Engineering (RE) of Software

1. Reverse Engineering (RE) is the process of analyzing a software system to identify its components and their interrelationships and create representations of the system in another form or at a higher level of abstraction.
2. The purpose of RE is to extract knowledge or design information from the system to facilitate tasks such as software maintenance, code understanding, system re-engineering and software security auditing.
3. The key steps in RE are:
- Obtaining the software and associated documentation.
- Studying the software's external behavior and functionality.
- Identifying the software's major components and the relationships between them.
- Creating representations of the software at various levels of abstraction.
- Validating the accuracy of the reverse-engineered representations.
4. Some RE techniques are:
- Static analysis - examining source code, executable code, documentation.
- Dynamic analysis - analyzing the software during execution using debugging, tracing or monitoring.
- Decompilation - converting executable code into a higher-level language.
- Pattern analysis - identifying repetitive patterns in the software to infer its structure.
