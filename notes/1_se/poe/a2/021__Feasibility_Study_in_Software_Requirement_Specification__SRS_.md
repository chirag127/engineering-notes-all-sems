### Feasibility Study in Software Requirement Specification (SRS)

- Technical Feasibility: This checks if the technology needed to develop the software is available or not. Things to consider are:
- Do we have the required expertise available?
- Do we have the required infrastructure, tools, and software available?
- Is the technology stable and mature enough to be used?

- Economic Feasibility: This checks if the software can be developed within the budget constraints. Things to consider are:
- Cost of resources (hardware, software)
- Cost of development (salaries, infrastructure, etc.)
- Cost of maintenance
- Expected revenue from the software
- If expected revenue > cost, then economically feasible else not.

- Legal Feasibility: This checks if the software meets the legal and regulatory requirements. Things to consider are:
- Licenses and agreements required
- Laws and regulations to be adhered to (privacy, security, etc.)
- If the software is violating any existing laws or agreements, then it is not legally feasible.

- Operational Feasibility: This checks if the software can be integrated with existing systems and if the organization is capable of handling the changes brought about by the software. Things to consider are:
- Changes required in the existing infrastructure/software/skills to accommodate the new software
- If the organization can bear the resource and operational changes required, then it is operationally feasible else not.

The above feasibility checks help determine if the SRS can actually be implemented or not. Only if all the feasibility studies result in a positive outcome should the SRS be accepted and implemented.
