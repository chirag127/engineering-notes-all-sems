### Change Control Process in software project management

1. Request for change: Any stakeholder can raise a request for change at any time during the project. The request is submitted in a prescribed change request form. The form contains details of the required change, reason for change, priority of change etc.

2. Analysis of change request: The change request is then analysed by the change control board (CCB) or change review board. The board evaluates the implications of accepting or rejecting the change request. They assess the impact on cost, schedule and scope.

3. Decision making: The board decides either to accept or reject the change request. If accepted, the implementation details are worked out. If rejected, the requester is informed about the reasons for rejection.

4. Implementation of change: The accepted change is implemented under proper planning and the project parameters like cost and schedule are updated. The change is integrated with the existing project plans.

5. Update documentation: All project documents like scope statement, WBS, schedule baselines etc. are updated to incorporate the change.

The change control process ensures that only approved changes are included in the project. It helps to have a systematic approach to deal with changes and avoid uncontrolled changes which can derail the project. Proper documentation of the change facilitates communication to all stakeholders and maintains the integrity of project baselines.
