### TCP Congestion Control in Transport Layer

- TCP stands for Transmission Control Protocol. It is a transport layer protocol that facilitates the transmission of packets from source to destination. It is a connection-oriented protocol that means it establishes the connection prior to the communication that occurs between the computing devices in a network.
- TCP is a reliable protocol as it follows the flow and error control mechanism. Flow control ensures that the sender does not overwhelm the receiver with more data than it can handle. Error control detects and corrects the errors that may occur during the transmission of packets.
- Congestion control is another mechanism that TCP uses to avoid or reduce the congestion in the network. Congestion occurs when the network resources, such as routers, links, or buffers, are overloaded and cannot handle the incoming traffic. Congestion can cause packet loss, delay, and reduced throughput.
- TCP congestion control aims to achieve two goals: efficiency and fairness. Efficiency means that the network utilization is maximized and the packet loss is minimized. Fairness means that each TCP connection gets an equal share of the network bandwidth.
- There are three phases that TCP uses for congestion control: slow start, congestion avoidance, and congestion detection:
  - Slow start: In the first phase of congestion control, the sender starts with a small number of packets, called the congestion window (cwnd), and gradually increases it by one packet for each acknowledgment (ACK) received from the receiver. This way, the sender probes the network capacity and avoids sending too many packets at once. The slow start phase ends when the cwnd reaches a threshold value (ssthresh), which is dynamically adjusted based on the network conditions.
  - Congestion avoidance: In the second phase of congestion control, the sender increases the cwnd more slowly, by one packet per round-trip time (RTT), instead of one packet per ACK. This way, the sender tries to maintain a steady flow of packets and avoid causing congestion. The congestion avoidance phase continues until a packet loss is detected, which indicates that the network is congested.
  - Congestion detection: In the third phase of congestion control, the sender detects the congestion by either a timeout or a duplicate ACK. A timeout occurs when the sender does not receive an ACK for a packet within a certain time interval. A duplicate ACK occurs when the receiver sends an ACK for a packet that it has already acknowledged, which implies that some packets are missing or out of order. When a congestion is detected, the sender reduces the cwnd by half and sets the ssthresh to the new cwnd value. Then, the sender enters the slow start phase again and repeats the process.
- TCP congestion control uses an algorithm called AIMD (Additive Increase Multiplicative Decrease) to adjust the cwnd. AIMD increases the cwnd additively in the congestion avoidance phase and decreases it multiplicatively in the congestion detection phase. This algorithm ensures that the cwnd oscillates around the optimal value and converges to a fair allocation of the network bandwidth among the TCP connections.
- A mnemonic to remember the three phases of TCP congestion control is SAC: Slow start, Avoidance, and Congestion detection. A mnemonic to remember the AIMD algorithm is AMID: Additive, Multiplicative, Increase, and Decrease.
