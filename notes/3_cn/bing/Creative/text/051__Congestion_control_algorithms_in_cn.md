### Congestion control algorithms in computer networks

Congestion control algorithms are mechanisms that control the entry of data packets into the network, enabling a better use of a shared network infrastructure and avoiding congestive collapse. Congestive collapse is a state where the network performance degrades significantly due to excessive traffic. Congestion control algorithms use packet losses and delays as signals to infer congestion and decide how fast to send data. Some of the congestion control algorithms are:

- **Leaky bucket algorithm**: This algorithm is used to shape bursty traffic into a steady stream by using a finite queue that outputs packets at a constant rate. The queue is analogous to a bucket with a small hole in the bottom. No matter at what rate packets enter the queue, the output rate is fixed. When the queue is full, additional packets are dropped and lost. This algorithm ensures that the network is not overloaded by the sender, but it may waste network resources if the output rate is lower than the available bandwidth. 
- **Token bucket algorithm**: This algorithm is a modification of the leaky bucket algorithm that allows for some variation in the output rate. The queue is analogous to a bucket that contains tokens. Each token represents a permission to send a packet of a predefined size. Tokens are generated at a constant rate and added to the bucket. When a packet arrives, it consumes a token from the bucket and is sent to the network. If the bucket is empty, the packet has to wait until a token is available. This algorithm allows the sender to transmit packets at a higher rate than the token generation rate, as long as there are enough tokens in the bucket. This algorithm can utilize the network resources more efficiently, but it may also cause more congestion if the sender sends too many packets in a short time. 
- **TCP congestion control**: This algorithm is implemented by the Transmission Control Protocol (TCP), which is widely used for reliable data transmission over the internet. TCP congestion control consists of four components: slow start, congestion avoidance, fast retransmit, and fast recovery. TCP maintains a congestion window (CWND) that indicates how many packets can be sent without waiting for an acknowledgment. The algorithm works as follows:

  - Slow start: When a TCP connection is established, the CWND is set to a small value, typically one or two packets. For every acknowledgment received, the CWND is increased by one packet. This means that the CWND grows exponentially, doubling every round trip time (RTT). This phase continues until the CWND reaches a threshold value (SSTHRESH) or a packet loss occurs.
  - Congestion avoidance: When the CWND reaches the SSTHRESH, the CWND is increased by one packet per RTT, instead of per acknowledgment. This means that the CWND grows linearly, increasing by one packet every RTT. This phase continues until a packet loss occurs.
  - Fast retransmit: When a packet loss is detected by the receiver, it sends a duplicate acknowledgment for the last packet received. When the sender receives three duplicate acknowledgments, it assumes that the packet after the last acknowledgment was lost and retransmits it. The CWND is reduced to half of the previous value, and the SSTHRESH is set to the new CWND. This phase avoids waiting for a timeout to retransmit the lost packet, which would cause a long delay.
  - Fast recovery: After retransmitting the lost packet, the sender enters the fast recovery phase, where it increases the CWND by one packet for every duplicate acknowledgment received. This phase continues until the sender receives a new acknowledgment, indicating that the lost packet was received. The CWND is then set to the SSTHRESH, and the sender resumes the congestion avoidance phase. This phase allows the sender to recover quickly from a single packet loss, without reducing the sending rate too much.
