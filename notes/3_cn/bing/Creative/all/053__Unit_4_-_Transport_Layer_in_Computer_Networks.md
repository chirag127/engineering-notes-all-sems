## Unit 4 - Transport Layer in Computer Networks

The transport layer is the fourth layer in the OSI model and the Internet protocol suite. It provides end-to-end communication services for applications running on different hosts. It also provides services such as connection-oriented communication, reliability, flow control, and multiplexing.  

Some of the main topics covered in this unit are:

- Transport layer services: The transport layer provides various services to the application layer, such as end-to-end delivery, addressing, reliable delivery, flow control, and multiplexing.  
- Transport layer protocols: The transport layer protocols are implemented in the end systems but not in the network routers. The most common transport layer protocols are the Transmission Control Protocol (TCP) and the User Datagram Protocol (UDP). TCP provides connection-oriented, reliable, and ordered data transfer, while UDP provides connectionless, unreliable, and unordered data transfer. Other transport layer protocols include the Datagram Congestion Control Protocol (DCCP) and the Stream Control Transmission Protocol (SCTP).  
- TCP and UDP sockets: A socket is an interface between the application layer and the transport layer. It allows an application to send and receive data using a transport layer protocol. A TCP socket is identified by a four-tuple of source IP address, source port number, destination IP address, and destination port number. A UDP socket is identified by a two-tuple of destination IP address and destination port number.  
- TCP connection management: A TCP connection is established by a three-way handshake between the sender and the receiver. The sender initiates the connection by sending a SYN segment with a sequence number x. The receiver responds with a SYNACK segment with a sequence number y and an acknowledgment number x+1. The sender completes the connection by sending an ACK segment with an acknowledgment number y+1. A TCP connection is terminated by a four-way handshake. The sender sends a FIN segment to indicate that it has no more data to send. The receiver sends an ACK segment to acknowledge the FIN segment. The receiver then sends a FIN segment to indicate that it has no more data to receive. The sender sends an ACK segment to acknowledge the FIN segment.  
- TCP reliable data transfer: TCP ensures reliable data transfer by using sequence numbers, acknowledgments, timers, and retransmissions. Each TCP segment has a sequence number that indicates the byte number of the first data byte in the segment. The receiver sends an acknowledgment that indicates the byte number of the next expected data byte. The sender uses a timer to detect lost segments and retransmits them if the timer expires before receiving an acknowledgment. TCP also uses a sliding window protocol to control the amount of unacknowledged data that the sender can have in the network.  
- TCP flow control: TCP uses flow control to prevent the sender from overwhelming the receiver with too much data. The receiver advertises a window size in each acknowledgment that indicates how much buffer space it has available to receive data. The sender can only send data that fits within the receiver's window. The receiver can adjust the window size dynamically based on its buffer occupancy.  
- TCP congestion control: TCP uses congestion control to avoid overloading the network with too much data. TCP uses a congestion window to limit the amount of data that the sender can have in the network. The congestion window is adjusted based on the feedback from the network, such as packet loss, delay, and duplicate acknowledgments. TCP uses four algorithms to implement congestion control: slow start, congestion avoidance, fast retransmit, and fast recovery.  
- UDP datagram transfer: UDP provides a simple and efficient way of sending and receiving datagrams. UDP does not provide any reliability, ordering, or flow control services. Each UDP datagram has a header that contains the source port number, destination port number, length, and checksum. The checksum is used to detect errors in the datagram. UDP is suitable for applications that do not require reliable or ordered delivery, such as streaming media, online gaming, and DNS.  

Some of the mnemonics and learning tricks for this unit are:

- To remember the services provided by the transport layer, use the acronym E.A.R.F.M. (End-to-end delivery, Addressing, Reliable delivery, Flow control, Multiplexing).
