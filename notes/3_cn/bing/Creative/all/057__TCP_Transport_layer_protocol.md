#### TCP Transport layer protocol

- TCP stands for Transmission Control Protocol. It is one of the core protocols of the Internet Protocol Suite, which provides reliable, ordered, and error-checked delivery of data between applications running on hosts connected by a network.
- TCP operates at the transport layer, which is the fourth layer of the OSI model. The transport layer is responsible for providing end-to-end communication services for applications, such as multiplexing, segmentation, flow control, congestion control, and error detection and correction.
- TCP uses a connection-oriented approach, which means that before any data can be exchanged, a TCP connection must be established between the sender and the receiver. A TCP connection is identified by a four-tuple: source IP address, source port number, destination IP address, and destination port number. A port number is a 16-bit number that identifies a specific process or application on a host.
- TCP uses a three-way handshake to establish a connection. The sender initiates the connection by sending a SYN segment, which contains the initial sequence number (ISN) and other parameters. The receiver responds with a SYN-ACK segment, which acknowledges the SYN and contains its own ISN and parameters. The sender then sends an ACK segment, which acknowledges the SYN-ACK and completes the handshake. The connection is now established and data can be exchanged.
- TCP uses a sliding window mechanism to control the flow of data and avoid congestion. The sliding window is a variable-sized buffer that indicates how much data can be sent or received at any time. The sender maintains a send window, which indicates how much data it can send before receiving an acknowledgment from the receiver. The receiver maintains a receive window, which indicates how much data it can receive before sending an acknowledgment to the sender. The size of the window is dynamically adjusted based on the network conditions and the feedback from the receiver.
- TCP uses sequence numbers and acknowledgments to ensure reliable and ordered delivery of data. Each byte of data sent by the sender is assigned a sequence number, which is incremented by one for each subsequent byte. The receiver sends an acknowledgment (ACK) segment, which contains the sequence number of the next byte it expects to receive. If the sender does not receive an ACK within a certain time, it assumes that the segment was lost or corrupted and retransmits it. If the receiver receives a segment with an out-of-order sequence number, it discards it and sends a duplicate ACK to indicate the expected sequence number. The sender can use the duplicate ACKs to detect and recover from packet loss.
- TCP uses checksums to detect and correct errors in the data. A checksum is a value computed from the data that is sent along with the data. The receiver computes the checksum from the received data and compares it with the checksum sent by the sender. If they match, the data is assumed to be error-free. If they do not match, the data is assumed to be corrupted and the receiver discards it and sends a negative acknowledgment (NACK) to the sender. The sender then retransmits the data.
- TCP provides various options and flags to enhance its functionality and performance. Some of the common options and flags are:

  - Maximum Segment Size (MSS): This option specifies the maximum size of the TCP segment that can be sent or received by a host. It is used to avoid fragmentation and improve efficiency.
  - Window Scale: This option allows the sender and the receiver to use a larger window size than the 16-bit value in the TCP header. It is used to improve the throughput of TCP connections over high-bandwidth networks.
  - Selective Acknowledgment (SACK): This option allows the receiver to acknowledge non-contiguous blocks of data, rather than only the next expected byte. It is used to improve the recovery from packet loss and reduce the number of retransmissions.
  - Timestamp: This option allows the sender and the receiver to exchange timestamps with each segment, which can be used to measure the round-trip time (RTT) and avoid spurious retransmissions.
  - Urgent Pointer: This flag indicates that the segment contains urgent data that should be processed immediately by the receiver. It is used to implement out-of-band data transmission, such as interrupting a long file transfer.
  - Push: This flag indicates that the sender has pushed the data to the network and the receiver should deliver it to the application as soon as possible. It is used to improve the responsiveness of interactive applications, such as telnet or SSH.
  - Reset: This flag indicates that the sender or the receiver wants to abort the connection. It is used to handle error conditions, such as an invalid segment or a refused connection.
