### Debugging for the notes of the Unit 5 - Software Testing Activities in the subject of Software Testing

- Debugging is the process of finding and fixing errors in software code  .
- Debugging is an important part of software testing, as it helps to ensure the quality and functionality of the software product .
- Debugging can be applied to different types of errors, such as syntax errors, logic errors, run-time errors, and interface errors.
- Debugging involves the following steps :
  - Identifying the problem: This can be done by reproducing the error, analyzing the symptoms, and using debugging tools or modes to examine the code execution.
  - Isolating the source of the problem: This can be done by using breakpoints, tracing, logging, and testing techniques to narrow down the location and cause of the error.
  - Correcting the problem: This can be done by modifying the code, applying patches, or using workarounds to eliminate the error.
  - Testing the correction: This can be done by running the software again, verifying the expected output, and checking for any side effects or new errors.
- Debugging can be made easier by following some principles and best practices, such as :
  - Reporting errors early and clearly: This can help to save time and effort by reducing the scope of debugging and providing useful information for debugging.
  - Writing clean and modular code: This can help to avoid errors, improve readability, and simplify debugging.
  - Using debugging tools and techniques: This can help to automate and facilitate debugging, such as debuggers, compilers, APIs, unit tests, code reviews, and pair programming.
  - Testing and debugging iteratively: This can help to detect and fix errors as soon as possible, and prevent them from accumulating and affecting the software quality.

- A possible mnemonic to remember the steps of debugging is **IICC** (Identify, Isolate, Correct, Test).
- A possible learning trick to understand the difference between debugging and testing is to think of debugging as a **reactive** process that responds to errors, while testing is a **proactive** process that prevents errors.
