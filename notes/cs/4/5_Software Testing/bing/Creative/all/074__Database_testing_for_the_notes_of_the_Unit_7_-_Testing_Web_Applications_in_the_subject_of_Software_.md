### Database testing for the notes of the Unit 7 - Testing Web Applications in the subject of Software Testing

- Database testing is the process of checking that everything is in order with regards to the database. This is done under a controlled testing environment. The process is also known as back-end testing or data testing.
- Database testing involves checking things such as the schema, tables, triggers, data integrity, data consistency, data security, data performance, etc. of the database under test .
- Database testing is important because it ensures that the data values and information received and stored into the database are valid and accurate. Database testing also helps to prevent data loss, save aborted transaction data, and prevent unauthorized access to the information .
- Database testing is a layered process, as it usually covers several different areas. When doing a complete database test, one needs to test the user interface layer, the business layer, the data access layer, and the database itself.
- Database testing can be divided into two types: structural database testing and functional database testing.

#### Structural database testing
- Structural database testing is the process of testing the database structure, such as the schema, tables, columns, keys, indexes, stored procedures, triggers, etc. It verifies that the database design and implementation are correct and follow the specifications.
- Some of the common tasks in structural database testing are:
  - Schema testing: checking that the database schema is consistent with the data model and the application requirements. It involves verifying the names, data types, constraints, and relationships of the tables and columns.
  - Database table and column testing: checking that the tables and columns are created and populated correctly. It involves verifying the data values, data formats, data ranges, data uniqueness, data nullability, data defaults, etc. of the columns.
  - Keys and indexes testing: checking that the primary keys, foreign keys, and indexes are defined and implemented correctly. It involves verifying the referential integrity, data consistency, data uniqueness, and data performance of the keys and indexes.
  - Stored procedures testing: checking that the stored procedures are written and executed correctly. It involves verifying the input parameters, output parameters, return values, error handling, logic, and performance of the stored procedures.
  - Trigger testing: checking that the triggers are written and executed correctly. It involves verifying the trigger events, trigger actions, trigger conditions, and trigger performance of the triggers.
  - Database server validations: checking that the database server is configured and running correctly. It involves verifying the server version, server settings, server security, server performance, server backup, server recovery, etc. of the database server.

#### Functional database testing
- Functional database testing is the process of testing the database functionality, such as the data integrity, data consistency, data security, data performance, etc. It verifies that the database meets the functional requirements and expectations of the application.
- Some of the common tasks in functional database testing are:
  - Checking data integrity and consistency: checking that the data values and information stored in the database are accurate and reliable. It involves verifying the data quality, data validity, data completeness, data accuracy, data timeliness, data relevance, etc. of the data.
  - Login and user security: checking that the database access and authentication are secure and controlled. It involves verifying the user roles, user permissions, user passwords, user sessions, user logs, user audits, etc. of the database users.
  - Load testing: checking that the database can handle the expected load and volume of data and transactions. It involves verifying the data scalability, data throughput, data concurrency, data availability, data reliability, data resilience, etc. of the database.
  - Stress testing: checking that the database can handle the extreme load and volume of data and transactions. It involves verifying the data robustness, data stability, data durability, data recovery, data backup, data restore, etc. of the database.

#### Mnemonics and learning tricks
- To remember the types of database testing, one can use the acronym SFFL, which stands for Structural, Functional, Load, and Stress testing.
- To remember the tasks in structural database testing, one can use the acronym STKIST, which stands for Schema, Table, Key, Index, Stored procedure, and Trigger testing.
