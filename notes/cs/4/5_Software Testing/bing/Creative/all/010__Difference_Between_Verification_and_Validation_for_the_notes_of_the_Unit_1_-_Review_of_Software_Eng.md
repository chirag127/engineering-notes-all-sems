### Difference Between Verification and Validation for the notes of the Unit 1 - Review of Software Engineering in the subject of Software Testing

- Verification and validation are two important processes in software testing that ensure the quality and functionality of the software product.
- Verification is the process of checking that the software meets the specifications and design requirements . It is a static testing technique that does not involve executing the code . Verification aims to answer the question: "Are we building the product right?"  .
- Validation is the process of checking that the software meets the customer's needs and expectations . It is a dynamic testing technique that involves executing the code . Validation aims to answer the question: "Are we building the right product?"  .
- The main difference between verification and validation is the purpose of each process. Verification determines if the software conforms to the specifications, while validation determines if the software is useful and usable for the end user .
- Verification is done by the quality assurance team using methods like reviews, walkthroughs, inspections, and desk-checking . Validation is done by the testing team with the involvement of the quality assurance team using methods like black box testing, white box testing, and non-functional testing .
- Verification is done before validation, usually in the early stages of the software development cycle . Validation is done after verification, usually at the end of the software development cycle .
- Verification can find the bugs early in the development cycle, which can save time and cost . Validation can find the bugs that verification cannot catch, which can improve the customer satisfaction and reliability of the software .
- The goal of verification is to ensure the quality of the software architecture, design, code, and documentation . The goal of validation is to ensure the quality of the software product and its functionality .

#### Example of verification and validation

- Suppose a software company is developing a calculator application for a client. The client has given the following requirements:

  - The calculator should be able to perform basic arithmetic operations like addition, subtraction, multiplication, and division.
  - The calculator should have a clear and user-friendly interface with buttons for numbers and operators.
  - The calculator should display the result of the calculation on the screen.

- The verification process will check if the software meets these requirements by reviewing the design documents, code, and test cases. For example, the verification team will check if the code follows the coding standards, if the test cases cover all the scenarios, and if the design documents are consistent and complete.
- The validation process will check if the software meets the customer's needs and expectations by testing the functionality and usability of the software. For example, the validation team will check if the calculator can perform the arithmetic operations correctly, if the interface is easy to use and understand, and if the result is displayed on the screen.
