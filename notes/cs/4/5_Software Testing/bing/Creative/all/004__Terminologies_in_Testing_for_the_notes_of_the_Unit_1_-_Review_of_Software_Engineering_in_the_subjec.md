### Terminologies in Testing for the notes of the Unit 1 - Review of Software Engineering in the subject of Software Testing

- **Software Testing**: The process of verifying and validating that a software product or system meets the specified requirements and expectations of the stakeholders.
- **Test Level**: A specific instantiation of a test process that targets a particular component or system under test. Examples of test levels are unit testing, integration testing, system testing, and acceptance testing.
- **Test Type**: A group of test activities that aim to evaluate a specific quality attribute of a test object. Examples of test types are functional testing, non-functional testing, structural testing, and change-related testing.
- **Test Design Technique**: A procedure or method that helps to derive and select test cases based on the test object, test basis, and test objective. Examples of test design techniques are equivalence partitioning, boundary value analysis, decision table testing, and state transition testing.
- **STLC (Software Test Life Cycle)**: A sequence of phases or activities that define and control the testing process. The typical phases of STLC are test planning, test analysis, test design, test implementation, test execution, test evaluation, and test closure.
- **Informal Testing**: Testing carried out without following any formal process, documentation, or test design technique. Examples of informal testing are ad hoc testing, exploratory testing, and error guessing.
- **Test Planning**: The activity of establishing the scope, approach, resources, and schedule of the testing activities. Test planning also involves defining the test objectives, criteria, and deliverables.
- **Test Documentation**: The set of artifacts that describe the test basis, test items, test cases, test procedures, test data, test results, and other information related to the testing process. Examples of test documentation are test plan, test specification, test report, and defect report.
- **Test Case**: A set of input values, execution preconditions, expected results, and execution postconditions that are developed for a particular test objective. A test case defines what to test, how to test, and what to expect from the test.
- **Test Procedure**: A document that specifies a sequence of actions for the execution of a test. A test procedure may include test cases, test scripts, test data, test environment, and instructions for the tester.
- **Test Script**: A set of instructions that can be executed by a test tool or a human tester. A test script may be written in a programming language, a scripting language, or a domain-specific language.
- **Test Data**: The data that is used as input or output for a test case or a test procedure. Test data may be generated, selected, or modified by the tester or a test tool.
- **Test Environment**: The hardware, software, network, and other components that are required to execute a test. The test environment should be configured and maintained to support the test objectives and requirements.
- **Test Execution**: The process of running a test on a test object using a test procedure and test data. Test execution may be performed manually or automatically by a test tool.
- **Test Result**: The outcome of a test execution, which may include the actual result, the expected result, the pass/fail status, and any deviations or anomalies.
- **Actual Result**: The system status or behavior after a test execution. The actual result is compared with the expected result to determine the pass/fail status of the test.
- **Expected Result**: The system status or behavior that is predicted by the test case before a test execution. The expected result is derived from the test basis and the test objective.
- **Pass/Fail Status**: The result of comparing the actual result and the expected result of a test execution. A test passes if the actual result matches the expected result, and fails otherwise.
- **Deviation**: Any condition that deviates from the expected result or the test objective of a test execution. A deviation may indicate a defect in the test object, a flaw in the test design, or an inconsistency in the test basis.
- **Anomaly**: Any condition that deviates from the expectations based on the requirements specifications, design documents, standards, etc. An anomaly may be found by testing or other means, such as reviews or inspections.
