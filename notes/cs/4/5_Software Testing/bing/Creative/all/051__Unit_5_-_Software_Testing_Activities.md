## Unit 5 - Software Testing Activities

Software testing activities are the tasks and processes that are performed to evaluate and verify the quality and functionality of a software product or application. Software testing activities can be classified into different types and levels, depending on the objectives, scope, and methods of testing. Some of the common software testing activities are:

- **Planning**: This is the first activity where the process of testing software originates. It consists of defining the objectives, scope, strategy, and resources for testing. It also involves identifying and analyzing the potential risks and mitigations for testing. To carry out this activity, it is important to create a document called a test plan, which outlines the testing approach, schedule, roles, responsibilities, tools, and deliverables for testing.

- **Design**: This is the activity where the test cases and test data are designed based on the test plan and the requirements of the software. Test cases are the specific steps and expected results that are used to verify the software functionality and quality. Test data are the inputs and outputs that are used to execute the test cases. To carry out this activity, it is important to use various techniques, such as equivalence partitioning, boundary value analysis, decision tables, state transition diagrams, etc., to design effective and efficient test cases and test data.

- **Execution**: This is the activity where the test cases and test data are executed on the software under test, using either manual or automated methods. Manual testing is done by a person who interacts with the software and follows the test cases and test data. Automated testing is done by a machine that runs a test script that was written in advance. The execution activity produces the actual results and outcomes of testing, which are then compared with the expected results and outcomes.

- **Reporting**: This is the activity where the results and outcomes of testing are documented and communicated to the stakeholders. It involves identifying, logging, and tracking the defects or issues that are found during testing. It also involves generating and analyzing various metrics and reports that measure the progress, quality, and effectiveness of testing. To carry out this activity, it is important to use various tools, such as defect tracking systems, test management systems, dashboards, etc., to record and report the testing information.

- **Evaluation**: This is the activity where the overall quality and functionality of the software are evaluated based on the testing results and outcomes. It involves determining whether the software meets the specified requirements and expectations of the stakeholders. It also involves assessing whether the testing objectives and criteria have been met and whether the testing process has been successful. To carry out this activity, it is important to use various techniques, such as reviews, inspections, audits, etc., to evaluate the software and the testing.

These are the general software testing activities that are performed at different levels of testing, such as unit testing, integration testing, system testing, and acceptance testing. Each level of testing has its own objectives, scope, and methods of testing, and requires different types of test cases, test data, and test tools. The software testing activities can also be performed in different phases of the software development life cycle, such as waterfall, agile, or DevOps, depending on the software development methodology and the testing approach .

Some possible mnemonics and learning tricks for the software testing activities are:

- **P**lan, **D**esign, **E**xecute, **R**eport, **E**valuate: **PDERE** (sounds like "peder", a Danish word for "father")
- **P**repare, **D**o, **C**heck, **A**ct: **PDCA** (a well-known quality improvement cycle)
- **P**izza, **D**onuts, **E**ggs, **R**ice, **E**nchiladas: **PDERE** (a list of foods that start with the same letters as the testing activities)
