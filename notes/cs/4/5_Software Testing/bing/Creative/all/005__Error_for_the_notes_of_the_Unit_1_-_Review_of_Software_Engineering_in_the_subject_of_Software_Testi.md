### Error for the notes of the Unit 1 - Review of Software Engineering in the subject of Software Testing

- Error is a human action or mistake when developing, using, or operating a system or software application.
- Error is a situation that happens when the development team or the developer fails to understand a requirement definition and hence that misunderstanding gets translated to buggy code.
- Error is the difference between the actual output of software and the correct output.
- Error can be classified into three types: syntax error, semantic error, and logical error.
  - Syntax error: a violation of the rules of the programming language, such as missing a semicolon or a bracket. Syntax errors are usually detected by the compiler or the interpreter.
  - Semantic error: a violation of the meaning or the logic of the program, such as using an incorrect variable name or a wrong data type. Semantic errors are harder to detect than syntax errors, and may cause the program to produce unexpected results or crash.
  - Logical error: a violation of the intended functionality or the specification of the program, such as a wrong formula or a missing condition. Logical errors are the most difficult to detect and debug, and may cause the program to produce incorrect or incomplete results.
- Error can be prevented by following good software engineering practices, such as:
  - Writing clear and consistent requirements and specifications.
  - Using appropriate tools and methods for design, coding, testing, and debugging.
  - Applying coding standards and conventions.
  - Performing code reviews and inspections.
  - Conducting thorough and systematic testing.
  - Documenting and tracing errors and their resolutions.
- Error can be detected by using various techniques, such as:
  - Static analysis: analyzing the source code or the design without executing the program, such as using a compiler, a code analyzer, or a model checker.
  - Dynamic analysis: analyzing the behavior or the output of the program during execution, such as using a debugger, a profiler, or a monitor.
  - Testing: executing the program with a set of inputs and comparing the outputs with the expected results, such as using unit testing, integration testing, or system testing.
  - Verification and validation: checking whether the program meets the requirements and the specifications, such as using formal methods, simulation, or prototyping.
- Error can be measured by using various metrics, such as:
  - Error density: the number of errors per unit of code, such as errors per line of code, errors per function, or errors per module.
  - Error rate: the frequency of errors during a period of time, such as errors per hour, errors per day, or errors per month.
  - Error severity: the impact or the consequence of an error, such as minor, major, critical, or fatal.
  - Error cost: the amount of resources or money spent to prevent, detect, or correct an error, such as error prevention cost, error appraisal cost, error internal failure cost, or error external failure cost.

A possible mnemonic to remember the types of errors is:

**S**yntax errors are **S**imple to find.

**S**emantic errors are **S**ubtle and **S**neaky.

**L**ogical errors are **L**ethal and **L**ong-lasting.
