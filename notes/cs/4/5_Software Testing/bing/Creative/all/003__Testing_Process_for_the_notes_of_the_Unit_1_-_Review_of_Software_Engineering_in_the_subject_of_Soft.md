### Testing Process for the notes of the Unit 1 - Review of Software Engineering in the subject of Software Testing

- Software testing is the process of evaluating and verifying that a software product or application does what it is supposed to do.
- Software testing helps to prevent bugs, reduce development costs, improve performance, and ensure quality and customer satisfaction.
- Software testing follows a common process, which can be summarized as follows  :

  1. **Planning and Control**: This step involves defining the scope, objectives, strategy, and approach for testing. It also includes identifying the resources, tools, risks, and schedule for testing activities. The test plan and test strategy documents are the main outputs of this step.
  2. **Test Analysis and Test Design**: This step involves reviewing the test basis, such as requirements, specifications, and design documents, to identify the test conditions and test cases. It also involves designing the test data, test environment, and test procedures. The test cases and test data are the main outputs of this step.
  3. **Implementation and Execution**: This step involves setting up the test environment, preparing the test data, and executing the test cases. It also involves logging the test results, comparing the actual outcomes with the expected outcomes, and reporting any defects or issues. The test results and defect reports are the main outputs of this step.
  4. **Evaluating Exit Criteria and Reporting**: This step involves checking whether the testing objectives have been met, and whether the exit criteria, such as the number of defects, test coverage, and quality standards, have been satisfied. It also involves summarizing the test activities, results, and findings in a test report. The test report is the main output of this step.
  5. **Test Closure**: This step involves finalizing and archiving the test artifacts, such as test cases, test data, test results, and defect reports. It also involves evaluating the test process, identifying the lessons learned, and making recommendations for improvement. The test closure report is the main output of this step.

- There are many different types of software testing, each with specific objectives and strategies, such as:

  - **Acceptance testing**: Verifying whether the whole system works as intended.
  - **Integration testing**: Ensuring that software components or functions operate together.
  - **Unit testing**: Validating that each software unit performs as expected. A unit is the smallest testable component of an application.
  - **Functional testing**: Checking functions by emulating business scenarios, based on functional requirements. Black-box testing is a common way to verify functions.
  - **Performance testing**: Testing how the software performs under different workloads. Load testing, for example, is used to evaluate performance under real-life load conditions.
  - **Regression testing**: Checking whether new features break or degrade functionality. Sanity testing can be used to verify menus, functions and commands at the surface level, when there is no time for a full regression test.
  - **Stress testing**: Testing how much strain the system can take before it fails. Considered to be a type of non-functional testing.
  - **Usability testing**: Validating how well a customer can use a system or web application to complete a task.

- A test management plan helps to prioritize which types of testing provide the most value, given the available time and resources.
- Testing effectiveness is optimized by running the fewest number of tests to find the largest number of defects.
- Testing can be time-consuming, so it is important to follow a robust process and use appropriate tools and techniques to ensure quality and efficiency.

- A possible mnemonic to remember the steps of the software testing process is: **PATEE** (Planning, Analysis, Implementation, Evaluation, and Closure).
- A possible learning trick to remember the types of software testing is: **AIF PURS** (Acceptance, Integration, Functional, Performance, Usability, Regression, and Stress).
