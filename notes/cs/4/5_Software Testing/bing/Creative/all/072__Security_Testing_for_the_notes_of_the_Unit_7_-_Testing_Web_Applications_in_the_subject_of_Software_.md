### Security Testing for the notes of the Unit 7 - Testing Web Applications in the subject of Software Testing

- Security testing is a process of identifying, preventing, and mitigating security vulnerabilities in web applications. It involves assessing the security of web applications by examining their code, architecture, and deployment environment.
- Security testing is important for web applications because they are often exposed to various types of attacks from malicious users, such as SQL injection, cross-site scripting, broken authentication, denial-of-service, etc. These attacks can compromise the confidentiality, integrity, and availability of the web application and its data.
- Security testing can be performed at different stages of the software development life cycle, such as design, development, testing, and deployment. However, security testing should not be treated as a one-time activity, but rather as a continuous process that requires regular updates and maintenance.
- Security testing can be classified into two types: static and dynamic. Static security testing involves analyzing the source code or configuration files of the web application for potential vulnerabilities, using tools such as code analyzers, scanners, or manual reviews. Dynamic security testing involves testing the web application in a running state, using tools such as penetration testing, vulnerability scanners, or manual testing.
- Security testing can also be categorized into four levels: unit, integration, system, and acceptance. Unit security testing focuses on testing individual components or modules of the web application for security flaws. Integration security testing focuses on testing the interactions and interfaces between different components or modules of the web application for security flaws. System security testing focuses on testing the web application as a whole for security flaws. Acceptance security testing focuses on testing the web application against the security requirements and expectations of the stakeholders.
- Security testing can follow a general methodology that consists of the following steps:
  - Understanding the business requirements and security goals of the web application.
  - Gathering data for security testing, such as the web application's architecture, functionality, features, technologies, dependencies, etc.
  - Creating a test plan and a traceability matrix that map the security test cases to the security requirements and risks.
  - Deciding the tools and techniques for security testing, such as manual or automated, static or dynamic, black-box or white-box, etc.
  - Executing the security test cases for the web application, using the selected tools and techniques, and recording the results and observations.
  - Creating a detailed report that summarizes the security testing process, findings, recommendations, and remediation steps.
- Security testing can be based on various standards and frameworks that provide guidelines and best practices for web application security, such as the OWASP Web Security Testing Guide (WSTG), the OWASP Top 10, the NIST SP 800-115, the ISO/IEC 27034, etc .
- Security testing can be enhanced by using some mnemonics and learning tricks, such as:
  - STRIDE: a model for identifying and classifying security threats based on six categories: Spoofing, Tampering, Repudiation, Information disclosure, Denial of service, and Elevation of privilege.
  - DREAD: a model for assessing and prioritizing security risks based on five factors: Damage potential, Reproducibility, Exploitability, Affected users, and Discoverability.
  - CIA: a model for evaluating the security objectives of a web application based on three principles: Confidentiality, Integrity, and Availability.
  - AAA: a model for implementing the security controls of a web application based on three functions: Authentication, Authorization, and Accounting.
  - OWASP: a model for remembering the most common web application security risks based on the acronym of the Open Web Application Security Project.
  - SANS: a model for remembering the most common web application security testing tools based on the acronym of the SysAdmin, Audit, Network, and Security Institute.
