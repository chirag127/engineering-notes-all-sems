### Impracticality of Testing All Data for the notes of the Unit 1 - Review of Software Engineering in the subject of Software Testing

- Testing all data is impractical because it is impossible to test every possible input and output combination for a software system.
- Testing all data is also inefficient because it would require a lot of time, resources, and effort that could be better spent on other aspects of software development and maintenance.
- Testing all data is unnecessary because most software systems have a finite set of valid inputs and outputs that can be identified and tested using various techniques such as equivalence partitioning, boundary value analysis, decision tables, etc.
- Testing all data is risky because it could introduce new errors or defects into the software system that were not present before testing, or mask existing errors or defects that were not detected by testing.
- Testing all data is unrealistic because it assumes that the software system is deterministic and behaves the same way for every input and output, which is not always the case in real-world scenarios where factors such as environment, user behavior, hardware, software, network, etc. can affect the software system's performance and functionality.

Some mnemonics and learning tricks for the impracticality of testing all data are:

- IIEUNR: Impractical, Inefficient, Unnecessary, Risky, Unrealistic
- TADIRU: Testing All Data Is Risky and Unrealistic
- FIVE: Finite, Identifiable, Valid, Equivalence
- BAD: Boundary, Analysis, Decision
