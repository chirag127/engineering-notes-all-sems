### Overview of Software Evolution for the notes of the Unit 1 - Review of Software Engineering in the subject of Software Testing

- Software evolution is the process of developing software initially, then timely updating it for various reasons, such as to add new features, to remove obsolete functionalities, to fix errors and bugs, to improve performance or reliability, to adapt to changing environment or requirements, or to enhance security .
- Software evolution is important because organizations invest large amounts of money in their software and are completely dependent on this software. To maintain the value of these assets to the business, they must be changed and updated. The majority of the software budget in large companies is devoted to changing and evolving existing software rather than developing new software.
- Software evolution processes depend on the type of software being maintained, the development processes used, and the skills and experience of the people involved. Proposals for change are the driver for system evolution. They should be linked with components that are affected by the change, thus allowing the cost and impact of the change to be estimated. Change identification and evolution continues throughout the system lifetime.
- The software evolution process consists of four stages:
  - Evolution: The stage in a software system’s life cycle where it is in operational use and is evolving as new requirements are proposed and implemented in the system.
  - Servicing: The stage where the software remains useful but the only changes made are those required to keep it operational, i.e., bug fixes and changes to reflect changes in the software’s environment. No new functionality is added.
  - Phase-out: The stage where the software may still be used but no further changes are made to it.
  - Close-down: The stage where the software is no longer available for use.
- The software evolution process also involves change implementation, which is an iteration of the development process where the revisions to the system are designed, implemented and tested. A critical difference is that the first stage of change implementation may involve program understanding, especially if the original system developers are not responsible for the change implementation. During the program understanding phase, the developers have to understand how the program is structured, how it delivers functionality and how the proposed change might affect the program.
- Urgent changes may have to be implemented without going through all stages of the software engineering process, such as if a serious system fault has to be repaired to allow normal operation to continue, or if changes to the system’s environment (e.g., an OS upgrade) have unexpected effects.
- Software evolution is also influenced by the dynamic behavior of software systems, as they are maintained and enhanced over their lifetimes. Software evolution is particularly important as systems in organizations become longer-lived. A key notion behind this seminal work by Belady and Lehman is the concept of software system entropy, which is a measure of the disorder or complexity of a system. As software evolves, it tends to become more complex and less structured, unless work is done to maintain or reduce that complexity.
- Software evolution can be classified into three types:
  - Corrective evolution: The process of fixing the faults or bugs in the software system.
  - Adaptive evolution: The process of modifying the software system to cope with the changes in its environment, such as hardware, platform, or operating system.
  - Perfective evolution: The process of adding new functionality or improving the existing functionality of the software system to meet the user requirements.

Mnemonics and learning tricks:

- To remember the four stages of software evolution process, use the acronym **ESPC** (Evolution, Servicing, Phase-out, Close-down).
- To remember the three types of software evolution, use the acronym **CAP** (Corrective, Adaptive, Perfective).
- To remember the concept of software system entropy, use the analogy of a **garden**. A garden needs regular maintenance and pruning to keep it tidy and beautiful. Similarly, a software system needs regular refactoring and restructuring to keep it simple and elegant.
