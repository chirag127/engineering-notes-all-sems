## Unit 4 - Regression Testing

- Regression testing is the process of retesting a software system after changes have been made to ensure that the changes have not introduced new defects or broken existing functionality.
- Regression testing can be done at different levels of testing, such as unit testing, integration testing, system testing, or acceptance testing.
- Regression testing can be done manually or automatically, depending on the availability of test cases, test tools, and resources.
- Regression testing can be classified into three types: retest all, selective, and test suite minimization.
  - Retest all: This approach involves re-executing all the existing test cases for the modified software system. This is the most thorough but also the most expensive and time-consuming approach.
  - Selective: This approach involves re-executing only a subset of the existing test cases that are relevant to the changes made in the software system. This is the most common and practical approach, but it requires a method to select the appropriate test cases.
  - Test suite minimization: This approach involves reducing the size of the test suite by eliminating redundant or obsolete test cases, while maintaining the same test coverage and fault detection capability. This is the most efficient but also the most challenging approach, as it requires a method to measure and optimize the test suite quality.
- Regression testing can be performed using different techniques, such as:
  - Retest all: This technique does not require any specific technique, as it re-executes all the test cases.
  - Selective: This technique can use various criteria to select the test cases, such as:
    - Coverage-based: This criterion selects the test cases that cover the modified code or functionality.
    - Fault-based: This criterion selects the test cases that have detected faults in the previous versions of the software system.
    - Priority-based: This criterion selects the test cases that have higher priority or importance, based on factors such as risk, complexity, or customer requirements.
    - History-based: This criterion selects the test cases that have failed or passed in the previous executions of the software system.
  - Test suite minimization: This technique can use various methods to reduce the test suite size, such as:
    - Greedy: This method iteratively selects the test case that covers the most uncovered code or functionality, until a desired test suite size or coverage is reached.
    - Genetic: This method uses a genetic algorithm to generate and evolve test suites, based on a fitness function that measures the test suite quality.
    - Clustering: This method groups the test cases into clusters based on their similarity or dissimilarity, and then selects one representative test case from each cluster.
- Regression testing can have various benefits, such as:
  - Detecting and preventing regression faults, which are faults that occur when a change in one part of the software system affects another part that was previously working correctly.
  - Improving the software quality and reliability, by ensuring that the software system meets the specified requirements and expectations after changes.
  - Increasing the software development efficiency and productivity, by reducing the rework and debugging efforts caused by regression faults.
  - Enhancing the software maintenance and evolution, by facilitating the incorporation of new features and modifications in the software system.
- Regression testing can also have some challenges, such as:
  - Selecting the appropriate test cases for regression testing, which requires a trade-off between the test suite size, coverage, and fault detection capability.
  - Automating the regression testing process, which requires the availability of test tools, test scripts, and test data, as well as the maintenance and update of these artifacts.
  - Managing the regression testing resources, which involves allocating and scheduling the human and hardware resources for regression testing, as well as monitoring and reporting the regression testing results and status.
