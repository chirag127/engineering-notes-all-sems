### Test Data for the notes of the Unit 5 - Software Testing Activities in the subject of Software Testing

- Test data is data used in software test execution. The data can be preloaded in the system or input by the tester or test automation tool during test execution.
- Test data is important for both positive testing and negative testing. Positive testing verifies that the software functions as expected for given inputs, while negative testing checks the software's ability to handle invalid, unexpected, or erroneous inputs.
- Test data should be created before test execution, as it can be time-consuming and difficult to generate or manage test data during test execution. Creating test data in advance can also help to cover all possible test scenarios and ensure the quality of the software.
- Test data can be generated using different techniques, such as:
  - Synthetic generation: creating artificial data that is realistic, consistent, and compliant with the business rules and domain logic of the software under test.
  - Production cloning: copying a subset of real data from the production environment, ensuring that the data relationships are intact and the data is anonymized or masked to protect sensitive information.
  - Data subsetting: selecting a representative sample of data from a larger data set, based on certain criteria or filters, to reduce the size and complexity of the test data.
  - Data masking: transforming or obfuscating sensitive data, such as personal or financial information, to protect it from unauthorized access or disclosure, while preserving its format and functionality.
  - Data generation tools: using software tools that can automatically generate test data based on predefined rules, templates, or models.
- Test data management is the process of planning, designing, storing, and maintaining test data throughout the software testing life cycle. Test data management aims to ensure that the test data is available, accessible, secure, and traceable for testing purposes.
- Test data management can involve the following activities:
  - Test data analysis: identifying the test data requirements, such as the type, format, volume, and source of the data, based on the test cases and test objectives.
  - Test data design: defining the test data strategy, such as the test data generation technique, the test data storage location, and the test data maintenance plan.
  - Test data provisioning: creating, acquiring, or importing the test data, and ensuring that it is ready and valid for test execution.
  - Test data maintenance: updating, deleting, or archiving the test data, and ensuring that it is consistent and synchronized with the software changes.
  - Test data governance: establishing the roles, responsibilities, policies, and procedures for test data management, and ensuring that the test data is secure, compliant, and traceable.
- Test data can be used for different types of software testing, such as:
  - White box testing: testing the internal structure, logic, or code of the software, using test data that is derived from the code itself. Test data for white box testing can be selected to cover as many branches, paths, statements, or conditions as possible in the code.
  - Black box testing: testing the functionality, usability, or performance of the software, using test data that is derived from the software requirements or specifications. Test data for black box testing can be selected to cover as many positive, negative, or boundary cases as possible in the software.
  - Performance testing: testing the speed, scalability, or reliability of the software, using test data that is representative of the expected workload or user behavior. Test data for performance testing can be selected to simulate different scenarios, such as normal, peak, or stress load.
  - Security testing: testing the vulnerability, confidentiality, or integrity of the software, using test data that is malicious, invalid, or corrupted. Test data for security testing can be selected to exploit different threats, such as injection, cross-site scripting, or denial-of-service attacks.
