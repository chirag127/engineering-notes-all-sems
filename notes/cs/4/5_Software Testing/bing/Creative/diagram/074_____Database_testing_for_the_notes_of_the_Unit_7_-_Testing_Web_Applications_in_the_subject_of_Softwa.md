### Database testing for the notes of the Unit 7 - Testing Web Applications in the subject of Software Testing

- Database testing is a type of software testing that checks the schema, tables, triggers, etc. of the database under test. It also checks data integrity and consistency .
- Database testing plays an important role in every web application. It protects the web app from vulnerabilities like data loss, saves aborted transaction data, and prevents unauthorized access to information.
- Database testing involves creating complex queries to load/stress test the database and check its responsiveness. It also involves checking the data quality, accuracy, and validity.
- Database testing can be done using various tools, such as MS-Access, MS SQL Server, SQL Server, Oracle, Oracle Financial, MySQL, PostgreSQL, DB2, Toad, Admirer, etc. These tools vary in cost, robustness, features, and security.
- Database testing can be classified into four types:
  - Structural testing: It checks the database structure, such as tables, columns, indexes, views, etc.
  - Functional testing: It checks the database functionality, such as stored procedures, triggers, functions, etc.
  - Non-functional testing: It checks the database performance, security, reliability, scalability, etc.
  - Regression testing: It checks the database for any changes or defects after modifications.
- Database testing can be performed using various techniques, such as:
  - White box testing: It involves testing the database internals, such as code, logic, design, etc.
  - Black box testing: It involves testing the database outputs, such as data retrieval, data manipulation, data update, etc.
  - Gray box testing: It involves testing the database with partial knowledge of its internals.
- Database testing can be done at different levels, such as:
  - Unit testing: It involves testing the individual components of the database, such as tables, columns, triggers, etc.
  - Integration testing: It involves testing the interaction between the database and other components, such as web server, application server, etc.
  - System testing: It involves testing the database as a whole, along with the web application and other systems.
  - User acceptance testing: It involves testing the database from the user's perspective, such as usability, functionality, etc.
- Database testing can be done using various methods, such as:
  - Manual testing: It involves testing the database manually, using SQL queries, scripts, tools, etc.
  - Automated testing: It involves testing the database using automated tools, such as Selenium, QTP, TestComplete, etc.
- Database testing can be done using various strategies, such as:
  - Positive testing: It involves testing the database with valid inputs and expected outputs.
  - Negative testing: It involves testing the database with invalid inputs and unexpected outputs.
  - Boundary testing: It involves testing the database with extreme inputs and outputs.
  - Equivalence testing: It involves testing the database with inputs and outputs that belong to the same class or category.
- Database testing can be done using various scenarios, such as:
  - Data consistency: It involves checking the data integrity and errors while editing, deleting, modifying the form or performing any DB-related functionality.
  - Data validation: It involves checking the data quality, accuracy, and validity while entering, retrieving, or updating the data.
  - Data migration: It involves checking the data transfer and transformation from one database to another.
  - Data backup and recovery: It involves checking the data backup and restoration in case of any failure or disaster.
  - Data security: It involves checking the data protection and access control from unauthorized users or hackers.
