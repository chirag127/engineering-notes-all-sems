### Validation for the notes of the Unit 1 - Review of Software Engineering in the subject of Software Testing

- Validation is the process of checking whether the software product meets the requirements and expectations of the customer and the stakeholders.
- Validation is also known as verification, quality assurance, or acceptance testing.
- Validation can be performed at different levels of software development, such as unit testing, integration testing, system testing, and user acceptance testing.
- Validation can be done by using various techniques, such as reviews, inspections, walkthroughs, audits, testing, and demonstrations.
- Validation can be done by different roles, such as developers, testers, customers, users, and independent evaluators.
- Validation can be done by using different criteria, such as functionality, usability, reliability, performance, security, and maintainability.
- Validation can be done by using different standards, such as IEEE, ISO, CMMI, and Agile.
- Validation can be done by using different tools, such as test automation tools, test management tools, defect tracking tools, and quality metrics tools.
- Validation can be done by using different methods, such as black-box testing, white-box testing, gray-box testing, and exploratory testing.
- Validation can be done by using different strategies, such as top-down testing, bottom-up testing, big-bang testing, and incremental testing.
- Validation can be done by using different models, such as waterfall model, spiral model, V-model, and iterative model.
- Validation can be done by using different types, such as functional testing, non-functional testing, regression testing, and smoke testing.
- Validation can be done by using different levels, such as alpha testing, beta testing, and gamma testing.
