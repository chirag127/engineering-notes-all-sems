### Configuration Audits

- Configuration audits are independent evaluations of the system's functionality, performance, and consistency with the relevant requirement specifications.
- Configuration audits help ensure that configuration items (CIs), which are the components of a software system, have been developed and completed in accordance with the documents and requirements that define them .
- Configuration audits are part of the configuration management process, which is a systems engineering process that tracks and monitors changes to a software system's configuration metadata.
- Configuration audits are performed for all releases of a software system, but audits of interim, internal releases may be less formal and rigorous, as defined by the project.
- There are two types of configuration audits: the Functional Configuration Audit (FCA) and the Physical Configuration Audit (PCA).
  - The FCA verifies that the CIs meet the functional and performance requirements specified in the functional baseline.
  - The PCA verifies that the CIs are consistent with the physical baseline, which includes the design, documentation, and test results.
- Configuration audits are conducted by a team of independent reviewers, who may include representatives from the customer, the developer, the quality assurance, and the configuration management.
- Configuration audits are documented in a configuration audit report, which summarizes the findings, recommendations, and corrective actions of the audit.
