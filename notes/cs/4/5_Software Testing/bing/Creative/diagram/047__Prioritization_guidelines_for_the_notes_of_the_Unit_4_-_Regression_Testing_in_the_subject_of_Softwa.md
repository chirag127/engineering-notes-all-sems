### Prioritization guidelines for the notes of the Unit 4 - Regression Testing in the subject of Software Testing

The following diagram illustrates the basic steps for prioritizing test cases for regression testing using an ASCII art:

```
+-------------------+     +-------------------+     +-------------------+
| Identify the test |     | Categorize the    |     | Execute the test  |
| cases that cover  |     | test cases based  |     | cases in the      |
| the changed or    |     | on priority       |     | order of priority |
| affected modules  |---->| levels (high,     |---->| (high to low)     |
| of the application|     | medium, low)      |     |                   |
+-------------------+     +-------------------+     +-------------------+
```

The priority levels of the test cases can be determined by various factors, such as:

- The criticality and business impact of the application functionality
- The defect proneness and complexity of the modules
- The frequency and recency of the changes made to the modules
- The negative and positive test scenarios
- The delivery timelines and test resources

The test case prioritization of regression testing helps to:

- Detect and fix the most important defects early in the testing process
- Reduce the test execution time and cost
- Improve the product quality and customer satisfaction
- Manage the risks associated with software delivery
