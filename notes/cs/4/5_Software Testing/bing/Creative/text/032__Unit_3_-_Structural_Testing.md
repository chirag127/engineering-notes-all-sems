## Unit 3 - Structural Testing

Structural testing is a type of software testing that focuses on the internal structure, design, and implementation of the software. It is also known as white-box testing, glass-box testing, or logic-driven testing.

The main objectives of structural testing are:

- To verify that the software conforms to the specified design and coding standards.
- To measure the quality attributes of the software, such as complexity, cohesion, coupling, modularity, etc.
- To identify and eliminate errors, defects, and faults in the software logic, data flow, control flow, etc.
- To improve the test coverage and effectiveness by using various techniques and tools.

Some of the common techniques and tools used for structural testing are:

- Code review: A manual or automated process of examining the source code for errors, defects, violations, and improvements.
- Static analysis: A process of analyzing the source code without executing it, using tools that check for syntax, semantics, style, quality, security, etc.
- Dynamic analysis: A process of analyzing the behavior and performance of the software during execution, using tools that monitor, measure, and report various aspects of the software.
- Code coverage: A measure of how much of the source code is executed by a test suite, using tools that collect and report coverage data.
- Control flow testing: A technique of designing test cases based on the paths and branches in the software logic, using tools that generate and execute test cases from the control flow graph.
- Data flow testing: A technique of designing test cases based on the definitions and uses of variables in the software, using tools that generate and execute test cases from the data flow graph.
- Mutation testing: A technique of evaluating the quality of a test suite by introducing artificial faults or mutations in the software and checking if the test suite can detect them, using tools that generate and execute mutants and compare the results with the original software.
