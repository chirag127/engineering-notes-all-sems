### Regression Test cases selection

- Regression testing is the process of retesting the modified parts of the software and the parts that might be affected by the modifications to ensure that no new defects are introduced.
- Regression test cases are the test cases that are executed during regression testing to verify the functionality and performance of the software after the changes.
- Regression test cases selection is the process of choosing a subset of test cases from the existing test suite to perform regression testing in an efficient and effective manner.
- Regression test cases selection can be done based on various criteria, such as:
  - The impact of the changes on the software components and their dependencies.
  - The coverage of the test cases on the software requirements and specifications.
  - The fault-proneness of the software components and their history of defects.
  - The priority and severity of the test cases and their expected outcomes.
  - The cost and time of executing the test cases and their availability of resources.
- Regression test cases selection can be done using various techniques, such as:
  - Retest all: This technique involves retesting all the test cases in the test suite regardless of the changes. This technique ensures high coverage and reliability, but it is also very expensive and time-consuming.
  - Retest affected: This technique involves retesting only the test cases that are directly or indirectly affected by the changes. This technique reduces the cost and time of testing, but it also requires a good understanding of the software structure and dependencies.
  - Test case prioritization: This technique involves ranking the test cases based on their importance and executing them in the order of their priority. This technique improves the effectiveness and efficiency of testing, but it also requires a good estimation of the test case priority and outcome.
  - Test case minimization: This technique involves removing the redundant or obsolete test cases from the test suite to reduce the size and complexity of testing. This technique saves the cost and time of testing, but it also requires a good analysis of the test case coverage and fault-detection capability.
