### Data Flow Testing

- Data flow testing is a type of structural testing that focuses on the data variables and their usage in a program.
- Data flow testing aims to ensure that the data variables are defined before they are used, and that they are not overwritten or deleted before they are used.
- Data flow testing uses a data flow graph to represent the program structure and the data dependencies among the statements.
- A data flow graph consists of nodes and edges, where nodes represent statements or blocks of statements, and edges represent the flow of control and data between the nodes.
- A data flow graph also shows the definition and use of data variables in the nodes and edges, using the following notations:
  - d(x): a definition of variable x
  - u(x): a use of variable x
  - c-use(x): a computational use of variable x, where x affects the output or the control flow of the program
  - p-use(x): a predicate use of variable x, where x is used in a conditional statement
- Data flow testing uses the concept of du-paths, which are paths in the data flow graph that start from a definition of a variable and end at a use of the same variable.
- Data flow testing defines various coverage criteria based on the du-paths, such as:
  - All-du-paths coverage: every du-path in the data flow graph is covered by at least one test case
  - All-uses coverage: every use of every variable in the data flow graph is covered by at least one du-path
  - All-c-uses/some-p-uses coverage: every computational use of every variable in the data flow graph is covered by at least one du-path, and some predicate use of every variable is covered by at least one du-path
  - All-p-uses/some-c-uses coverage: every predicate use of every variable in the data flow graph is covered by at least one du-path, and some computational use of every variable is covered by at least one du-path
- Data flow testing can be applied at different levels of granularity, such as statement level, block level, or procedure level.
- Data flow testing can be used to detect various types of errors, such as:
  - Initialization errors: a variable is used before it is defined
  - Unreachable code: a statement or a block of statements is never executed
  - Unused variables: a variable is defined but never used
  - Overwritten variables: a variable is defined more than once before it is used
  - Inconsistent variables: a variable is defined in different ways in different paths before it is used
