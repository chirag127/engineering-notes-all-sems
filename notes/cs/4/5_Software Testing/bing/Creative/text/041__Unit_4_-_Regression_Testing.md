## Unit 4 - Regression Testing

- Regression testing is the process of retesting a software system after changes have been made to ensure that the changes have not introduced new defects or adversely affected the existing functionality.
- Regression testing can be done at different levels of testing, such as unit testing, integration testing, system testing, or acceptance testing.
- Regression testing can be performed manually or automatically, depending on the availability of test cases, test tools, and resources.
- Regression testing can be classified into three types: retest all, selective retest, and test suite minimization.
  - Retest all is the simplest approach, where all the existing test cases are executed again after any change. This ensures complete coverage, but it is also time-consuming and costly.
  - Selective retest is the most common approach, where only a subset of test cases are executed based on the impact analysis of the changes. This reduces the testing effort, but it also requires a good understanding of the dependencies and traceability between the test cases and the requirements.
  - Test suite minimization is the most advanced approach, where the test cases are optimized to achieve the same coverage with fewer test cases. This minimizes the testing effort, but it also requires sophisticated techniques and tools to identify the redundant and obsolete test cases.
- Regression testing can be enhanced by using various strategies, such as prioritization, categorization, and automation.
  - Prioritization is the process of ranking the test cases based on their importance, risk, or frequency of execution. This helps to focus on the most critical test cases and reduce the testing time.
  - Categorization is the process of grouping the test cases based on their characteristics, such as functionality, performance, security, or usability. This helps to organize the test cases and execute them in a logical order.
  - Automation is the process of using software tools to execute the test cases and compare the actual and expected results. This helps to improve the efficiency, accuracy, and consistency of the testing process.
