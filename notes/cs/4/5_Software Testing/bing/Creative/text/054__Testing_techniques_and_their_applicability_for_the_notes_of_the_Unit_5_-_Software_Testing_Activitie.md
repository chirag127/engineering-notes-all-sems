### Testing techniques and their applicability

Testing techniques are the methods applied to evaluate a system or a component with a purpose to find if it satisfies the given requirements. Testing of a system helps to identify gaps, errors, or any kind of missing requirements differing from the actual requirements.

There are many different types of testing techniques, each with specific objectives and strategies. Some of the common testing techniques are:

- **Unit testing**: Validating that each software unit performs as expected. A unit is the smallest testable component of an application. Unit tests are very low level and close to the source of an application. They consist in testing individual methods and functions of the classes, components, or modules used by your software. Unit tests are generally quite cheap to automate and can run very quickly by a continuous integration server .
- **Integration testing**: Ensuring that software components or functions operate together. Integration tests verify the interactions and data flows between the units or modules of the system. They can be done at different levels of granularity, such as component, subsystem, or system level. Integration tests can be performed using different approaches, such as top-down, bottom-up, or sandwich .
- **Functional testing**: Checking functions by emulating business scenarios, based on functional requirements. Functional tests verify that the system behaves as expected by the users and meets their needs. Functional tests can be done using different techniques, such as black-box, white-box, or gray-box. Black-box testing is a common way to verify functions without knowing the internal structure or logic of the system  .
- **Non-functional testing**: Testing how the system performs under different conditions or constraints, such as usability, security, reliability, performance, etc. Non-functional tests evaluate the quality attributes of the system that are not directly related to its functionality. Non-functional tests can be done using different tools and methods, such as load testing, stress testing, usability testing, security testing, etc  .
- **Regression testing**: Checking whether new features break or degrade functionality. Regression tests ensure that the system still works as expected after changes or modifications are made. Regression tests can be done using different techniques, such as retesting, selective testing, or test automation. Regression tests can be performed at different levels, such as unit, integration, or system level  .
- **Acceptance testing**: Verifying whether the whole system works as intended. Acceptance tests validate that the system meets the acceptance criteria and the expectations of the stakeholders. Acceptance tests can be done by different parties, such as developers, testers, customers, or users. Acceptance tests can be performed using different methods, such as alpha testing, beta testing, or user acceptance testing  .

The applicability of testing techniques depends on various factors, such as the type and scope of the system, the development methodology, the testing objectives, the available resources, the time constraints, the quality standards, etc. Testing techniques should be selected and applied based on the context and the needs of the project. Testing techniques should also be aligned with the testing levels and the testing phases of the software development life cycle. Testing techniques should be planned and documented in a test management plan, which helps to prioritize and optimize the testing process .
