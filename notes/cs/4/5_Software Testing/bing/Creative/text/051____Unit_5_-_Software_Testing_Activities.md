## Unit 5 - Software Testing Activities

- Software testing is the process of verifying and validating that a software product meets the requirements and expectations of the stakeholders.
- Software testing activities include planning, designing, executing, and evaluating test cases, as well as reporting and tracking defects, and improving the quality of the software product.
- Software testing activities can be classified into four main categories: static testing, dynamic testing, functional testing, and non-functional testing.

### Static testing
- Static testing is the process of examining the software artifacts, such as requirements, design, code, and documentation, without executing them.
- Static testing can be performed manually or with the help of tools, such as code analyzers, syntax checkers, and code reviews.
- Static testing can detect errors, inconsistencies, ambiguities, and deviations from standards and best practices in the software artifacts.
- Static testing can also improve the maintainability, readability, and reusability of the software artifacts.

### Dynamic testing
- Dynamic testing is the process of executing the software product or its components under specified conditions and observing the results.
- Dynamic testing can be performed at different levels of granularity, such as unit testing, integration testing, system testing, and acceptance testing.
- Dynamic testing can also be performed at different stages of the software development life cycle, such as alpha testing, beta testing, and regression testing.
- Dynamic testing can verify the functionality, performance, reliability, security, and usability of the software product.

### Functional testing
- Functional testing is the process of testing the software product or its components against the functional requirements and specifications.
- Functional testing can be performed using black-box testing, white-box testing, or gray-box testing techniques.
- Black-box testing is the technique of testing the software product without knowing its internal structure or logic.
- White-box testing is the technique of testing the software product by knowing its internal structure or logic.
- Gray-box testing is the technique of testing the software product by having some knowledge of its internal structure or logic, but not all.
- Functional testing can validate the correctness, completeness, and accuracy of the software product.

### Non-functional testing
- Non-functional testing is the process of testing the software product or its components against the non-functional requirements and expectations, such as performance, reliability, security, usability, compatibility, and maintainability.
- Non-functional testing can be performed using various tools and techniques, such as load testing, stress testing, security testing, usability testing, compatibility testing, and maintainability testing.
- Non-functional testing can evaluate the quality, efficiency, effectiveness, and satisfaction of the software product.
