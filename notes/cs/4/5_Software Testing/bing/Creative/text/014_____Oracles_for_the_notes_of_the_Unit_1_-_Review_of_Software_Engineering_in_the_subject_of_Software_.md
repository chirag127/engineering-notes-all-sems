### Oracles

- An oracle is a mechanism for determining whether a test has passed or failed.
- An oracle compares the output of the system under test, for a given input, to the expected output.
- An oracle can be a human, a document, a program, or a combination of these.
- An oracle can be derived from various sources, such as specifications, requirements, domain knowledge, or previous versions of the system.
- An oracle can be complete, partial, or inconsistent, depending on how well it can determine the correctness of the system's output.
- An oracle can be deterministic, nondeterministic, or probabilistic, depending on how it handles the variability of the system's output.
- An oracle can be explicit, implicit, or heuristic, depending on how it is defined and implemented.
- An oracle can be static, dynamic, or adaptive, depending on how it changes over time or in response to the system's behavior.
- An oracle can be internal, external, or hybrid, depending on where it is located and how it interacts with the system under test.
- An oracle can be exact, inexact, or approximate, depending on how precise it is in comparing the system's output to the expected output.
- An oracle can be formal, informal, or semi-formal, depending on how rigorously it is specified and verified.
- An oracle can be online, offline, or mixed, depending on when it is applied and how it affects the system under test.
- An oracle can be automated, manual, or semi-automated, depending on how much human intervention is required or desired.
- An oracle can be reusable, disposable, or configurable, depending on how it can be applied to different tests or systems.
- An oracle can be efficient, effective, or optimal, depending on how it balances the trade-offs between cost, quality, and coverage.
