### Issues for the notes of the Unit 6 - Object Oriented Testing in the subject of Software Testing

- Object oriented testing (OOT) is a testing approach that is based on the object oriented paradigm, which involves concepts such as classes, objects, inheritance, polymorphism, encapsulation, and dynamic binding.
- OOT differs from conventional testing methods, which are based on functions, procedures, modules, and data structures, and which focus on testing the input-output behavior of the software.
- OOT faces some challenges and issues that are specific to the object oriented paradigm, such as:
  - How to define and test a class, which does not have a clear input-output specification, but rather a state and a set of methods that can communicate with each other and with other classes through messages.
  - How to test the dependencies and interactions among classes, methods, messages, and variables, which are more complex and dynamic than in conventional systems.
  - How to test the inheritance hierarchy, which can introduce changes and variations in the behavior of subclasses and superclasses, and which can affect the testing of polymorphism and dynamic binding.
  - How to test the concurrency and synchronization issues that arise from the object oriented paradigm, which allows multiple objects to exist and communicate simultaneously.
- OOT requires additional testing techniques and strategies to address these issues, such as:
  - Class testing, which involves testing the methods and state of a class, as well as its constructors, destructors, and operators.
  - Integration testing, which involves testing the interactions and collaborations among classes, objects, and components, as well as the interfaces and contracts among them.
  - System testing, which involves testing the functionality and performance of the entire object oriented system, as well as its compatibility and usability with other systems and users.
  - Regression testing, which involves testing the impact of changes and modifications in the object oriented system, such as adding, deleting, or modifying classes, methods, or messages.
- OOT can benefit from the use of the Unified Modeling Language (UML), which is a standard notation and tool for modeling, designing, and documenting object oriented systems. UML can help in identifying and specifying the classes, objects, methods, messages, and relationships in the system, as well as in generating test cases and test scenarios based on the UML diagrams.
