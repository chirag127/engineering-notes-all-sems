### Terminologies in Testing

Software testing is a process of verifying and validating that a software product or system meets the specified requirements and expectations. Software testing involves various terms and concepts that are essential to understand and apply in practice. Here are some of the common terminologies in software testing:

- **Test level**: A specific instantiation of a test process. There are different test levels, such as unit testing, integration testing, system testing, and acceptance testing, that have different objectives, scope, and focus. Test levels are usually defined in a test plan or a test strategy document.
- **Test type**: A group of test activities that are aimed at testing a specific characteristic of a software product or system, such as functionality, performance, usability, security, etc. Test types are usually defined in a test plan or a test strategy document.
- **Test design technique**: A method or procedure for deriving and selecting test cases based on the test objective, test basis, and test criteria. There are different test design techniques, such as black box testing, white box testing, boundary value analysis, equivalence partitioning, etc., that have different advantages and disadvantages.
- **STLC (Software Test Life Cycle)**: A sequence of phases or activities that are performed during the software testing process. The STLC typically includes the following phases: test planning, test analysis, test design, test implementation, test execution, test evaluation, and test closure. The STLC may vary depending on the project context, test methodology, and test management tools.
- **Informal testing**: Testing carried out without following any formal or structured process, such as test planning, test design, test documentation, test reporting, etc. Informal testing is usually done by developers, testers, or users who have no or little knowledge of the software requirements and specifications. Informal testing is also known as ad hoc testing, exploratory testing, or error guessing.
- **Test planning**: The activity of defining the scope, approach, resources, schedule, and deliverables of the software testing process. Test planning is usually done at the beginning of the testing process and documented in a test plan document. Test planning helps to ensure that the testing process is aligned with the project objectives, requirements, and constraints.
- **Test documentation**: The set of documents that describe the test basis, test design, test cases, test procedures, test data, test results, test reports, and test logs of the software testing process. Test documentation provides evidence of the testing process and helps to communicate, monitor, and control the testing activities and outcomes. Test documentation may follow a standard format, such as IEEE 829, or a customized format, depending on the project context and test methodology.
- **Test case**: A set of input values, execution preconditions, expected results, and execution postconditions that are developed for a specific test objective. A test case defines what to test, how to test, and what to expect from the test. A test case may also include test identifiers, test descriptions, test priorities, test dependencies, etc. Test cases are usually derived from the test basis and the test design technique.
- **Test procedure**: A set of test cases that are executed in a specific order. A test procedure defines when to test, in what sequence, and with what interdependencies. A test procedure may also include test identifiers, test descriptions, test prerequisites, test environment, test tools, etc. Test procedures are usually derived from the test cases and the test plan.
- **Test data**: The data that are used as input or output for the test cases. Test data may be generated, selected, or modified from existing sources, such as databases, files, or user inputs. Test data should be realistic, valid, and sufficient to cover the test objectives and criteria. Test data may also include test identifiers, test descriptions, test sources, test formats, etc.
- **Test execution**: The activity of running the test cases or test procedures using the test data on the test object. Test execution may be done manually or automatically, depending on the test type, test level, and test tool. Test execution may also involve test monitoring, test control, and test debugging activities.
- **Test result**: The outcome of a test execution, such as pass, fail, inconclusive, blocked, etc. Test results indicate whether the test cases or test procedures have met the expected results or not. Test results may also include test identifiers, test descriptions, test data, test logs, test defects, test metrics, etc.
