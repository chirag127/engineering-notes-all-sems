### Priority category for the notes of the Unit 4 - Regression Testing in the subject of Software Testing

- Regression testing is the process of retesting a software system after changes have been made to ensure that the changes have not introduced new defects or degraded the existing functionality.
- Regression testing can be classified into three priority categories based on the impact and likelihood of the changes affecting the system: high, medium, and low.
- High priority regression testing is performed when the changes are critical or risky, such as fixing major bugs, adding new features, or modifying the core functionality of the system. High priority regression testing should cover all the test cases that are directly or indirectly related to the changes, as well as the test cases that verify the most important or frequently used features of the system.
- Medium priority regression testing is performed when the changes are moderate or less risky, such as fixing minor bugs, enhancing existing features, or refactoring the code. Medium priority regression testing should cover the test cases that are directly related to the changes, as well as the test cases that verify the most relevant or commonly used features of the system.
- Low priority regression testing is performed when the changes are trivial or negligible, such as fixing typos, updating documentation, or changing the user interface. Low priority regression testing should cover the test cases that are directly related to the changes, as well as the test cases that verify the basic functionality of the system.
