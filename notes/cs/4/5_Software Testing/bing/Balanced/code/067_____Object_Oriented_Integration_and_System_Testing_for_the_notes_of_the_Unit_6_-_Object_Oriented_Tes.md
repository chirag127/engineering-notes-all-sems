### Object Oriented Integration and System Testing

- Object oriented integration testing is the process of testing the interactions and dependencies among the classes and objects of an object oriented system.
- Object oriented system testing is the process of testing the functionality and performance of the whole system as a single entity.
- Object oriented integration and system testing differ from conventional testing in the following ways:
  - Object oriented testing focuses on the behavior and state of the objects, rather than the structure and functions of the modules.
  - Object oriented testing requires more attention to the inheritance, polymorphism, and dynamic binding features of the system, which may introduce new types of faults and complexities.
  - Object oriented testing may involve testing at different levels of abstraction, such as class, cluster, subsystem, and system levels.
  - Object oriented testing may require more use of test drivers and stubs to simulate the interactions among the objects and classes.
- Object oriented integration and system testing can be performed using various strategies, such as :
  - Thread-based testing: This strategy tests the functional aspects of the system by integrating the classes and objects that contribute to a specific thread of control or scenario.
  - Use-case-based testing: This strategy tests the functional and non-functional aspects of the system by integrating the classes and objects that are involved in a specific use case or user requirement.
  - Cluster testing: This strategy tests the structural and behavioral aspects of the system by integrating the classes and objects that form a cohesive group or cluster based on some criteria, such as inheritance, collaboration, or cohesion.
  - System testing: This strategy tests the overall quality and performance of the system by integrating all the classes and objects and verifying the system against the specifications and expectations of the stakeholders.
