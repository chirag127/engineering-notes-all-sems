# Issues for the notes of the Unit 6 - Object Oriented Testing in the subject of Software Testing

Object oriented testing (OOT) is a testing approach that is based on the principles of object oriented programming, such as encapsulation, inheritance, polymorphism, and dynamic binding. OOT aims to test the functionality, reliability, and quality of object oriented software systems.

However, OOT also faces some challenges and issues that are different from or more complex than those in traditional testing methods. Some of these issues are:

- **Class testing**: Class testing is the testing of a single class or a group of related classes as a unit. Class testing involves testing the methods, attributes, constructors, and destructors of a class, as well as the interactions between the class and its clients or collaborators. Class testing also requires testing the inheritance and polymorphism features of a class, such as testing the base class and the derived classes, testing the overridden and overloaded methods, and testing the dynamic binding of methods at runtime.
- **Integration testing**: Integration testing is the testing of the interactions and dependencies between different classes or components of a system. Integration testing involves testing the communication, coordination, and collaboration between the objects of different classes or components, as well as testing the interfaces, contracts, and protocols between them. Integration testing also requires testing the design patterns, frameworks, and architectures that are used to structure and organize the system.
- **System testing**: System testing is the testing of the whole system as a single entity. System testing involves testing the functional and non-functional requirements of the system, such as testing the performance, usability, security, reliability, and compatibility of the system. System testing also requires testing the system in different environments, scenarios, and configurations, as well as testing the system with different types of users, inputs, and outputs.
- **Regression testing**: Regression testing is the testing of the system after changes or modifications have been made to it. Regression testing involves testing the system to ensure that the changes have not introduced any new errors or defects, and that the system still meets the original requirements and specifications. Regression testing also requires testing the system to ensure that the changes have not affected the existing functionality, quality, or behavior of the system.
- **Test case design**: Test case design is the process of identifying, selecting, and generating test cases for testing the system. Test case design involves defining the test objectives, criteria, and strategies, as well as choosing the test data, methods, and tools. Test case design also requires considering the test coverage, test adequacy, and test effectiveness, as well as the test cost, time, and resources. Test case design for object oriented software systems is more challenging than for traditional software systems, as it has to deal with the complexity, diversity, and variability of the object oriented features and concepts.
