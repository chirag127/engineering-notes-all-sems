### Regression Test Cases Selection

Regression testing is the process of retesting the software after changes are made to ensure that the existing functionality is not affected. Regression test cases selection is the technique of choosing the most appropriate and effective test cases for regression testing. The following are some of the notes on regression test cases selection for Unit 4 - Regression Testing in the subject of Software Testing:

- Regression test cases selection aims to increase the testing efficiency and effectiveness by reducing the cost, time, and effort of regression testing, while maintaining or improving the coverage and fault detection capability.
- Regression test cases selection can be classified into three categories based on the level of information available: code-based, specification-based, and model-based.
- Code-based regression test cases selection techniques use the information from the source code, such as control flow graphs, data flow graphs, or program slices, to identify the affected parts of the code and select the test cases that cover them .
- Specification-based regression test cases selection techniques use the information from the software specification, such as functional requirements, use cases, or user stories, to identify the affected parts of the specification and select the test cases that cover them .
- Model-based regression test cases selection techniques use the information from the software models, such as state machines, Petri nets, or UML diagrams, to identify the affected parts of the models and select the test cases that cover them .
- Some of the factors that influence the regression test cases selection are: the frequency and size of the changes, the criticality and complexity of the software, the availability and quality of the test cases, the test environment and resources, and the testing objectives and criteria .
- Some of the best practices for regression test cases selection are  :
  - Select test cases that cover the recent or frequent code changes or functional changes, as they are more likely to introduce defects or affect the existing functionality.
  - Select test cases that cover the critical or core features of the software, as they are more important for the user satisfaction and business value.
  - Select test cases that have a high probability of detecting faults, such as boundary value analysis, equivalence partitioning, or error guessing.
  - Select test cases that have a high impact on the user interface, usability, performance, security, or compatibility of the software, as they are more visible and relevant for the user experience.
  - Select test cases that have a high code coverage, such as statement coverage, branch coverage, or path coverage, as they can exercise more parts of the code and reveal more defects.
  - Select test cases that are independent and reusable, as they can reduce the dependency and redundancy of the test cases and improve the maintainability and scalability of the test suite.
  - Select test cases that are automated or easy to automate, as they can save time, effort, and resources and increase the reliability and consistency of the testing process.
  - Select test cases that are updated and verified, as they can ensure the validity and accuracy of the test cases and avoid false positives or false negatives.
  - Select test cases that are prioritized and optimized, as they can help to execute the most important and effective test cases first and eliminate the unnecessary or ineffective test cases.
