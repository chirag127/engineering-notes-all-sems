### Terminologies in Testing for the notes of the Unit 1 - Review of Software Engineering in the subject of Software Testing.

1. Software testing - The process of evaluating a software item to detect differences between given input and expected output. It is aimed at checking whether the software meets the specified requirements and to identify possible bugs.
2. Test case - A set of conditions or variables under which a tester will determine whether a system under test satisfies the requirements or works correctly. It includes inputs, execution preconditions, test execution steps, expected results, and actual results.
3. Test suite - A collection of test cases that are intended to be used to test a software program to show that it has some specified set of behaviors.
4. Test plan - A document describing the scope, approach, resources, and schedule of intended test activities. It identifies test items, the features to be tested, the testing tasks, who will do each task, and any risks requiring contingency planning.
5. Bug - A flaw in a system that can cause the system to work incorrectly. Also known as a defect.
6. Bug report - A document reporting on any flaw found during testing that could lead to incorrect or unexpected behavior. A good bug report contains a description of the bug, steps to reproduce it, expected behavior, and actual behavior.
