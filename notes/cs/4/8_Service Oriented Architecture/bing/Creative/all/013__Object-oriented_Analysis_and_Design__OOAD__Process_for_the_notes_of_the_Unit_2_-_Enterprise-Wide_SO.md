### Object-oriented Analysis and Design (OOAD) Process for the notes of the Unit 2 - Enterprise-Wide SOA in the subject of Service Oriented Architecture

- Object-oriented analysis and design (OOAD) is a technical approach for analyzing and designing an application, system, or business by applying object-oriented programming, as well as using visual modeling throughout the software development process to guide stakeholder communication and product quality.
- OOAD is typically conducted in an iterative and incremental way, where the outputs of OOAD activities are analysis models (for OOA) and design models (for OOD) respectively.
- The intention is for these models to be continuously refined and evolved, driven by key factors like risks and business value.
- OOAD is a main technique heavily used by both OOD and OOA activities in modern software engineering.

#### Object-oriented Analysis (OOA)
- Object-oriented analysis (OOA) is the process of analyzing the problem domain for a software system, and identifying the concepts, attributes, and behaviors that are relevant to the system.
- OOA aims to capture the static and dynamic aspects of the problem domain, and define the requirements for the proposed system.
- OOA uses object-oriented models, such as use cases, class diagrams, sequence diagrams, and state diagrams, to represent the functional and non-functional requirements of the system.
- OOA also involves identifying the relationships and collaborations among the objects, and applying the principles of abstraction, encapsulation, inheritance, and polymorphism to create a logical structure for the system.

#### Object-oriented Design (OOD)
- Object-oriented design (OOD) is the process of transforming the analysis models into design models that are ready for implementation.
- OOD aims to map the concepts, attributes, and behaviors identified in OOA to the real-world entities and operations that are supported by the chosen programming language, platform, and framework.
- OOD uses object-oriented models, such as class diagrams, sequence diagrams, and state diagrams, to represent the structure and behavior of the system.
- OOD also involves applying design patterns, principles, and best practices to improve the quality, reusability, and maintainability of the system.

#### OOAD Process
- The OOAD process is not a rigid or prescriptive one, but rather a flexible and adaptable one that can be tailored to the needs and preferences of the project and the organization.
- However, a general OOAD process can be described as follows:

  1. Identify the problem domain and the scope of the system.
  2. Define the functional and non-functional requirements of the system.
  3. Create the analysis models using object-oriented models, such as use cases, class diagrams, sequence diagrams, and state diagrams.
  4. Validate and verify the analysis models with the stakeholders and the users.
  5. Refine and revise the analysis models based on feedback and changes in requirements.
  6. Create the design models using object-oriented models, such as class diagrams, sequence diagrams, and state diagrams.
  7. Apply design patterns, principles, and best practices to improve the quality, reusability, and maintainability of the system.
  8. Validate and verify the design models with the developers and the testers.
  9. Refine and revise the design models based on feedback and changes in implementation.
  10. Implement the design models using the chosen programming language, platform, and framework.
  11. Test and debug the system using various testing techniques and tools.
  12. Deploy and maintain the system using various deployment and maintenance techniques and tools.

#### Mnemonics and Learning Tricks
- A possible mnemonic to remember the steps of the OOAD process is **IDCVRRAPVRRITD** (I Don't Care Very Rarely About People's Views, Really, I'm Too Daring).
- A possible learning trick to remember the difference between OOA and OOD is that OOA focuses on **what** the system should do, while OOD focuses on **how** the system should do it.
