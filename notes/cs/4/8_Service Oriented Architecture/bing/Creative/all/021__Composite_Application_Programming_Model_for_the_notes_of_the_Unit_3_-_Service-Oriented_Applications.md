### Composite Application Programming Model for the notes of the Unit 3 - Service-Oriented Applications in the subject of Service Oriented Architecture

- A composite application is a software application built by combining multiple existing functions into a new application.
- A composite application can use business sources (e.g., existing modules or even web services) of information, while mashups usually rely on web-based, and often free, sources.
- A composite application can be built using any technology or architecture, but it is often associated with service-oriented architecture (SOA).
- A composite application consists of functionality drawn from several different sources, which may be individual selected functions from within other applications, or entire systems whose outputs have been packaged as business functions, modules, or web services.
- A composite application often incorporates orchestration of "local" application logic to control how the composed functions interact with each other to produce the new, derived functionality.
- A composite application can support user interactions beyond those provided by the leveraged applications, or act as a service.
- A composite application can be built by leveraging other composite applications.
- A composite application can be modeled using the service component architecture (SCA), which describes how service components can be assembled to form composites.
- A composite application can be deployed on distributed, heterogeneous networks of computers, and can be used for large, scientific applications that often include high performance computations .

#### Advantages of composite application programming model

- It enables reuse of existing functions and components, reducing development time and cost.
- It allows flexibility and agility in creating new applications that meet changing business needs.
- It facilitates interoperability and integration of heterogeneous systems and data sources.
- It supports scalability and performance of complex applications .
- It promotes modularity and loose coupling of components, enhancing maintainability and reliability.

#### Disadvantages of composite application programming model

- It requires coordination and governance of multiple components and services, increasing complexity and management overhead.
- It may introduce security and quality of service issues, as the composite application depends on external sources of information and functionality.
- It may face compatibility and standardization challenges, as different technologies and architectures may have different interfaces and protocols.
- It may incur network latency and bandwidth consumption, as the composite application communicates with remote components and services .

#### Examples of composite application programming model

- A travel booking application that combines flight, hotel, car rental, and payment services from different providers into a single user interface.
- A weather forecasting application that integrates data from satellites, radars, sensors, and models from different sources into a comprehensive analysis and visualization .
- A customer relationship management (CRM) application that leverages data and functionality from enterprise resource planning (ERP), email, social media, and analytics systems into a unified dashboard.

#### Mnemonics and learning tricks for composite application programming model

- A possible mnemonic to remember the definition of a composite application is: **C**ombining **O**ld **M**odules **P**roduces **O**riginal **S**olutions **I**n **T**echnology **E**nvironments (COMPOSITE).
- A possible learning trick to understand the concept of a composite application is to compare it to a collage, where different pieces of art are combined to create a new artwork. The pieces of art can be seen as the existing functions or components, and the collage can be seen as the composite application. The collage can have different styles and themes, depending on how the pieces of art are arranged and orchestrated. The collage can also be part of a larger artwork, such as a mural or a gallery, just like a composite application can be part of a larger system or service.
