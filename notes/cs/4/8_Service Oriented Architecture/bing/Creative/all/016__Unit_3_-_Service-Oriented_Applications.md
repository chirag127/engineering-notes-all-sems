## Unit 3 - Service-Oriented Applications

- Service-oriented applications are software systems that are composed of loosely coupled, interoperable, and reusable components called services.
- Services are self-contained units of functionality that provide a well-defined interface to other services or clients.
- Services can be implemented using different technologies, platforms, and languages, and can communicate using standard protocols and formats, such as SOAP, REST, XML, JSON, etc.
- Service-oriented applications aim to achieve high modularity, reusability, scalability, reliability, and maintainability of software systems, by following the principles of service orientation, such as abstraction, autonomy, discoverability, composability, etc.
- Service-oriented applications can be designed using different architectural styles, such as service-oriented architecture (SOA), microservices, serverless, etc., depending on the requirements and constraints of the system.
- Service-oriented applications can leverage various technologies and tools to support the development, deployment, integration, discovery, orchestration, monitoring, and testing of services, such as web services, service registries, service buses, service meshes, cloud computing, etc.

Some mnemonics and learning tricks for Unit 3 - Service-Oriented Applications are:

- To remember the principles of service orientation, use the acronym **SADACOC** (pronounced as sad-a-coc), which stands for **S**tatelessness, **A**bstraction, **D**iscoverability, **A**utonomy, **C**omposability, **O**rchestration, and **C**ontract.
- To remember the difference between SOAP and REST, use the analogy of **P**ostal **S**ervice and **E**mail. SOAP is like sending a letter through the postal service, which has a fixed format, envelope, and address. REST is like sending an email, which has a flexible format, header, and URL.
- To remember the difference between SOA and microservices, use the analogy of **M**onolithic and **M**odular **B**uildings. SOA is like a monolithic building, which has a large and complex structure, centralized governance, and shared resources. Microservices are like modular buildings, which have small and simple structures, decentralized governance, and independent resources.
