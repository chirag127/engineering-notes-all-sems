
### SOA Strategy – Best Practices 

1. Design services to be autonomous and loosely coupled. This means that each service should be able to function independently, and should not rely on other services to do its job.

2. Design services to be highly cohesive. This means that each service should be focused on a single task and should not be responsible for multiple tasks.

3. Design services to be stateless. This means that each service should not maintain any state information and should not depend on any previous requests to complete its task.

4. Design services to be platform independent. This means that services should be able to run on any platform without the need for any modifications.

5. Design services to be secure. This means that services should be protected from unauthorized access and malicious attacks.

6. Design services to be scalable. This means that services should be able to accommodate increased load without compromising performance.

7. Design services to be reliable. This means that services should be able to handle errors gracefully and should be able to recover from them quickly.

8. Design services to be extensible. This means that services should be able to be extended or modified without having to rewrite the entire service.
