### Resource sharing for the notes of the Unit 1 - Characterization of Distributed Systems in the subject of DISTRIBUTED SYSTEM

- Resources: In distributed systems, resources such as data, processing power, memory, etc. are shared among multiple nodes. This allows efficient utilization of available resources.
- Transparency: The distribution of resources should be transparent to the users. The users should not be aware of the physical location of resources and should be able to access them in a uniform manner.
- Concurrency: The resources can be accessed concurrently by multiple users, thereby increasing throughput. However, concurrency control is required to prevent inconsistent results.
- Fault tolerance: Even if some nodes fail, the system should continue to function using resources from other nodes. Fault tolerance mechanisms are required to handle node failures and network failures.
- Scalability: It should be possible to add more resources to the system by adding more nodes in a straightforward manner. The system should be able to use the additional resources to improve performance.

Advantages:
- Efficient utilization of resources
- Scalability
- Fault tolerance
- Transparency

Disadvantages:
- Complex to implement
- Difficult to maintain consistency and concurrency control
- Prone to failures which can affect the entire system
- Security issues due to resource sharing

Applications: Cloud computing, peer-to-peer systems, distributed databases, etc.

Mnemonics:
- Think of sharing 'CARFTS' (resources, concurrency, fault tolerance, transparency, scalability)
- Imagine multiple users accessing shared 'CRAFTS' (concurrency, resources, fault tolerance, scalability, transparency)
