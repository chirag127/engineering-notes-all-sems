## Unit 5 - Distributed Resource Management

- Distributed resource management refers to the process of managing and allocating resources in a distributed system.
- Some key aspects of distributed resource management are:
    - Resource discovery - Finding available resources in the system.
    - Resource allocation - Allocating available resources to tasks/processes.
    - Load balancing - Distributing workload evenly across resources.
    - Fault tolerance - Handling resource failures and ensuring continuity of service.
    - Scheduling - Determining order of execution/access to resources.
    - Accounting - Monitoring resource usage for purpose like billing, analysis, etc.
- Examples of distributed resources that may need management are:
    - Computers/processors in a cluster
    - Storage devices in a distributed storage system
    - Network bandwidth in a network
- Challenges in distributed resource management:
    - Heterogeneity of resources and systems. Resources may have different capacities/capabilities.
    - Lack of centralized control and global system view. Localized, decentralized decision making is needed.
    - Scale of system and volume of resources/tasks. Efficient mechanisms are required to handle large scale.
    - Dynamism of resources and workload. The system state is constantly changing so management strategies must adapt.
    - Partial failures and unreliability. The system must be fault tolerant and handle resource failures/unavailability.
- Some example frameworks/systems for distributed resource management:
    - Hadoop YARN - For cluster resource management.
    - Kubernetes - For container resource management.
    - Mesos - A distributed systems kernel for resource sharing.
- Mnemonics: Distributed resource management is like solving a jigsaw puzzle with moving, changing pieces. You have to discover the pieces, put them together efficiently despite challenges, and adapt as the puzzle changes.

- Learning tricks: Understand the key aspects and challenges first. Then look at examples of frameworks/systems to see how they solve the problems. Implement/deploy a simple system to get hands-on experience of the concepts.
