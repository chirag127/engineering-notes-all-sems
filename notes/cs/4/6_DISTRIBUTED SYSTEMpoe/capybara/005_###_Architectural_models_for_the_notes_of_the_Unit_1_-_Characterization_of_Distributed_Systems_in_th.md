### Architectural models for the notes of the Unit 1 - Characterization of Distributed Systems in the subject of DISTRIBUTED SYSTEM

Distributed systems are systems that are composed of multiple autonomous computers that communicate with each other in order to achieve a common goal. There are several architectural models that are commonly used in distributed systems, each with its own advantages and disadvantages. In this section, we will discuss some of the most commonly used architectural models.

1. Client-Server Model:

The client-server model is one of the most common architectural models used in distributed systems. In this model, there are two types of computers: clients and servers. Clients request services from servers, which provide the requested services. The client-server model is widely used for providing web services, such as web pages, email, and file sharing.

Advantages:
- Easy to implement and understand
- Scalable
- Centralized control

Disadvantages:
- Single point of failure
- High latency
- Limited flexibility

2. Peer-to-Peer Model:

The peer-to-peer model is another popular architectural model used in distributed systems. In this model, all computers are considered equal and communicate directly with each other. There is no central server, and each computer can act as both a client and a server. The peer-to-peer model is commonly used for file sharing and content distribution.

Advantages:
- No single point of failure
- Decentralized control
- Highly scalable

Disadvantages:
- Difficult to implement and manage
- Security concerns
- Limited control over network traffic

3. Hybrid Model:

The hybrid model combines aspects of both the client-server and peer-to-peer models. In this model, some computers act as servers, while others act as clients. The servers provide centralized control, while the clients provide scalability and flexibility. The hybrid model is commonly used in cloud computing and distributed databases.

Advantages:
- Scalable
- Centralized control
- Decentralized control

Disadvantages:
- Complex to implement and manage
- Security concerns
- Limited flexibility

Mnemonics and Learning Tricks:

To remember the advantages and disadvantages of each architectural model, you can use the acronym "S-C-D" for the client-server model, "N-D-C" for the peer-to-peer model, and "S-C-D-D-F" for the hybrid model. The first letter of each word represents an advantage or disadvantage of the model. For example, "S" stands for "Scalable", "C" stands for "Centralized control", "D" stands for "Difficult to implement and manage", and "F" stands for "Limited flexibility".
