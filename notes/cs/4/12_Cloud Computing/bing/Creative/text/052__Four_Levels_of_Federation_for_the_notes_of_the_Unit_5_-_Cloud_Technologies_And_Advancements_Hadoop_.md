### Four Levels of Federation for the notes of the Unit 5 - Cloud Technologies And Advancements Hadoop in the subject of Cloud Computing

- Federation is the process of integrating multiple independent systems or subclusters into a single logical system or cluster, while preserving their autonomy and heterogeneity.
- Federation can improve the scalability, availability, fault tolerance, and performance of the system or cluster, as well as enable data sharing and collaboration among different subclusters.
- Federation can be applied at different levels of the system or cluster, depending on the degree of integration and coordination required.
- According to , there are four levels of federation:

  - **Level 1: Data Federation**. This level involves federating the data stored in different subclusters, without changing the underlying data structures or formats. The data federation can be achieved by using a common interface or a query language that can access and manipulate data from multiple subclusters. For example, HDFS Federation  allows multiple independent NameNodes/namespaces to share the same pool of DataNodes, while maintaining their own block pools and metadata. The users can access any namespace transparently, using a common HDFS interface or a mount table.
  - **Level 2: Service Federation**. This level involves federating the services or applications that run on different subclusters, without changing the underlying service or application logic. The service federation can be achieved by using a common API or a protocol that can invoke and coordinate services or applications from multiple subclusters. For example, YARN Federation  allows multiple independent ResourceManagers to share the same pool of NodeManagers, while maintaining their own resource allocation and scheduling policies. The users can submit and monitor applications to any ResourceManager transparently, using a common YARN API or a router.
  - **Level 3: Resource Federation**. This level involves federating the resources or nodes that belong to different subclusters, without changing the underlying resource or node configuration. The resource federation can be achieved by using a common platform or a framework that can manage and utilize resources or nodes from multiple subclusters. For example, OpenStack  allows multiple independent cloud providers to share the same pool of physical or virtual machines, while maintaining their own cloud services and policies. The users can request and provision resources from any cloud provider transparently, using a common OpenStack platform or a dashboard.
  - **Level 4: Policy Federation**. This level involves federating the policies or rules that govern the behavior and interaction of different subclusters, without changing the underlying policy or rule definition. The policy federation can be achieved by using a common language or a mechanism that can express and enforce policies or rules from multiple subclusters. For example, OAuth  allows multiple independent service providers to share the same pool of user credentials, while maintaining their own authentication and authorization policies. The users can access and use services from any service provider transparently, using a common OAuth language or a token.

- The four levels of federation are not mutually exclusive, and can be combined or nested to achieve different degrees of integration and coordination among subclusters. For example, HDFS Router-based Federation  combines data federation and service federation to provide a unified view of multiple HDFS subclusters, using a router component that forwards the client requests to the correct subcluster, based on a state store that contains the mount table and the subcluster information.
