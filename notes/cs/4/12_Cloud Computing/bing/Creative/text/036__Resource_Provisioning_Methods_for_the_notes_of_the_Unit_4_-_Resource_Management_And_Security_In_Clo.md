### Resource Provisioning Methods

Resource provisioning is the process of choosing, deploying, and managing software and hardware resources to assure application performance in cloud computing. Resource provisioning can be done in different ways depending on the application needs, the demand fluctuations, and the cost considerations. Some of the common resource provisioning methods are:

- **Static provisioning or advance provisioning**: This method is suitable for applications with known and typically constant demands or workloads. In this method, the cloud provider allocates a fixed number of resources to the customer, who can then use them as needed. The customer is responsible for ensuring that the resources are not overutilized or underutilized. This method is simple and predictable, but it may not be cost-effective or scalable for dynamic or unpredictable workloads. For example, a customer may want to use a database server with a set amount of CPU, RAM, and storage for a long-term project. 

- **Dynamic provisioning or on-demand provisioning**: This method is suitable for applications with variable or unpredictable demands or workloads. In this method, the cloud provider adds or removes resources as needed and charges the customer based on the actual usage. The customer does not have to worry about overprovisioning or underprovisioning, as the cloud provider handles the resource management automatically. This method is flexible and scalable, but it may incur higher costs or lower performance due to resource fluctuations. For example, a customer may want to use a web server that can handle sudden spikes in traffic without compromising the response time. 

- **Automatic on-demand provisioning**: This method is a variation of dynamic provisioning that allows the customer to specify some rules or policies for the resource allocation and deallocation. The cloud provider then follows these rules or policies to provision or deprovision resources automatically based on the demand or other triggers. This method gives the customer more control and visibility over the resource usage and costs, while still benefiting from the flexibility and scalability of dynamic provisioning. For example, a customer may want to use a machine learning model that can scale up or down based on the number of requests or the time of the day.
