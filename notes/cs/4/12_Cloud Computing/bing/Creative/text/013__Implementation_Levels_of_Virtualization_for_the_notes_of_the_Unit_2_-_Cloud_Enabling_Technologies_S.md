### Implementation Levels of Virtualization

Virtualization is a computer architecture technology by which multiple virtual machines (VMs) are multiplexed in the same hardware machine. The idea of VMs can be dated back to the 1960s. It aims to improve resource sharing by several users and enhance computer performance in resource utilization and application adaptability. Virtualization is also the technology that enables cloud computing economics. It allows cloud providers to offer users with their existing physical computer hardware. It also allows cloud users to acquire only the computing resources they need when they need it and scale those resources cost-effectively as their workloads expand.

There are different levels of virtualization implementation, depending on how the virtualization layer interacts with the hardware and the guest operating systems. The virtualization layer is also called a hypervisor or a virtual machine monitor (VMM). The hypervisor acts as a bridge between the virtual OS and the hardware to enable its smooth functioning of the instance. The different levels of virtualization implementation are:

- **Instruction Set Architecture Level (ISA)**: In this level, virtualization works through an ISA emulation. This is helpful to run heaps of legacy code which was originally written for different hardware configurations. These codes can be run on the virtual machine through an ISA. A binary code that might need additional layers to run can now run on an x86 machine or with some tweaking, even on x64 machines. ISA helps make this a hardware-agnostic virtual machine. The basic emulation, though, requires an interpreter. This interpreter interprets the source code and converts it to a hardware readable format for processing. This level has the highest implementation complexity and the lowest performance among the levels of virtualization .

- **Hardware Abstraction Level (HAL)**: As the name suggests, this level helps perform virtualization at the hardware level. It uses a bare hypervisor for its functioning. This level helps form the virtual machine and manages the hardware through virtualization. It enables virtualization of each hardware component such as I/O devices, processors, memory, etc. This way multiple users can use the same hardware with numerous instances of virtualization at the same time. This level has a lower implementation complexity and a higher performance than the ISA level .

- **Operating System Level**: At the operating system level, the virtualization model creates an abstract layer between the applications and the OS. This layer allows multiple instances of the same OS to run on the same hardware. The applications running on different OS instances are isolated from each other and can have different configurations and permissions. This level does not require a hypervisor, but rather relies on the OS kernel to provide the virtualization functionality. This level has a lower implementation complexity and a higher performance than the HAL level, but it also has some limitations, such as the lack of support for different OS types and the dependency on the OS kernel .

- **Library Support Level**: In this level, virtualization is achieved by providing a library that supports the execution of applications written for different platforms. The library acts as a translator that converts the system calls and instructions of the applications to the native ones of the host OS and hardware. This level does not require a hypervisor or a kernel modification, but rather relies on the library to provide the virtualization functionality. This level has a lower implementation complexity and a higher performance than the OS level, but it also has some limitations, such as the need for recompiling the applications for the library and the lack of support for some system features .

- **Application Level**: In this level, virtualization is achieved by providing an application that supports the execution of other applications written for different platforms. The application acts as a container that encapsulates the applications and provides them with the necessary resources and services. This level does not require a hypervisor, a kernel modification, or a library, but rather relies on the application to provide the virtualization functionality. This level has the lowest implementation complexity and the highest performance among the levels of virtualization, but it also has some limitations, such as the need for modifying the applications for the container and the lack of support for some system features .

The levels of virtualization implementation can be summarized in the following table:

| Level | Hypervisor | Kernel Modification | Library | Application | Performance | Complexity |
|-------|------------|---------------------|---------|-------------|-------------|------------|
| ISA | Yes | No | No | No | Low | High |
| HAL | Yes | No | No | No | Medium | Medium |
