### Data persistence using Core Data and SQLite for the notes of the Unit 5 - TECHNOLOGY II –iOS in the subject of Design & Development Of Applications
Data persistence is the ability of an application to store data even after it has been closed. In iOS, there are two common ways to achieve data persistence: Core Data and SQLite. 

Core Data is an object-oriented framework that provides a way to manage the model layer objects in your application. It allows you to create, fetch, update, and delete objects, and it automatically persists those changes to disk. Core Data is a high-level framework that abstracts the underlying database, so you don't have to write any SQL code.

SQLite is a lightweight, file-based database that is commonly used in mobile applications. With SQLite, you can interact with the database using SQL statements to create, fetch, update, and delete data. SQLite is a low-level framework, so you need to write the SQL code yourself.

When deciding which option to use, consider the complexity of your data model, the size of your data set, and your performance requirements. If your data model is complex and you need to perform complex queries, Core Data may be a better choice. If your data set is small and you just need to store and retrieve data, SQLite may be a better choice.

In the context of the Unit 5 - TECHNOLOGY II – iOS in the subject of Design & Development Of Applications, you may be expected to use either Core Data or SQLite to store the notes for the unit.
