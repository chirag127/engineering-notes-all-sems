### Configuration Audits for the notes of the Unit 1 - Review of Software Engineering in the subject of Software Testing

Configuration audits are the process of examining the configuration items of a software system against a known standard. In this process, the system is thoroughly checked for its adherence to the configuration management plan and its compliance with the specified requirements.

Here are some important points to keep in mind while conducting configuration audits:

1. **Purpose**: The purpose of configuration audits is to ensure that the software system is developed and maintained in a controlled manner. It also ensures that the changes made to the system are properly documented and tracked.

2. **Types of Configuration Audits**: There are three types of configuration audits - Functional Configuration Audit (FCA), Physical Configuration Audit (PCA), and System Verification Review (SVR).

3. **Functional Configuration Audit (FCA)**: FCA is conducted to verify that the system's functional and performance characteristics meet the specified requirements.

4. **Physical Configuration Audit (PCA)**: PCA is conducted to verify that the configuration items of the software system have been correctly implemented and installed.

5. **System Verification Review (SVR)**: SVR is conducted to verify that the software system meets all the requirements and specifications as specified in the contract.

6. **Benefits of Configuration Audits**: Configuration audits provide several benefits to the software development process, including improved quality, traceability, and documentation of changes made to the software system.

7. **Mnemonics and Learning Tricks**: While there are no specific mnemonics or learning tricks for configuration audits, it is important to keep in mind the purpose and types of audits. A good way to remember the types of configuration audits is to use the acronym FPS - FCA, PCA, and SVR.

Overall, configuration audits are an essential aspect of software engineering and software testing. They ensure that the software system is developed and maintained in a controlled manner and meet the specified requirements.
