### Regression Test cases selection for the notes of the Unit 4 - Regression Testing in the subject of Software Testing

The following points can be considered for selecting regression test cases:

1. Select tests that have revealed faults in the past: Tests that have found bugs or defects in the previous iterations or versions of the software are priority for regression testing. These tests have higher probability of finding regression bugs.
2. Focus on critical and complex features: Complex features and functionalities that are critical for the software are important to regression test. Even a small bug in these can have high impact. So tests focusing on these areas should be given more priority in regression testing.
3. Choose boundary value tests: Boundary value analysis is an important technique for testing. The test cases focusing on boundaries of input and output domains should be selected for regression testing as bugs are more likely to appear near boundaries.
4. Prioritize business critical functions: Business critical functions and workflows that are key to the business goals should be tested thoroughly in regression testing to avoid any disruption to business due to bugs. So tests covering these business critical functions should be given high priority.
5. Select tests with high code coverage: Code coverage is a measure of amount of code executed by tests. Tests that achieve high code coverage have higher chance of finding bugs. So existing tests with high code coverage should be selected for regression testing. Additionally, more tests can be added to increase the coverage.
6. Consider recent bug fixes: The areas of software that have recently seen bug fixes are more prone to regression bugs. So tests focusing on these areas should be prioritized in regression testing to validate that the fixes have not introduced any new bugs.
7. Consult stakeholders: Besides technical factors, regression test cases can also be selected based on inputs from stakeholders like product owners and business analysts. They can provide valuable insights into critical functionality and user scenarios that are important to test. These inputs can be additional factors in prioritizing regression test cases.

The above points can help determine a good subset of test cases from the existing test suite to use for regression testing. Using a mix of these strategies leads to a comprehensive regression test plan. Additionally, automation of regression tests is highly recommended to repeatedly execute the selected test cases and catch bugs early.
