## Unit 3 - Structural Testing

Structural testing involves testing the internal structure of the software to identify structural flaws. It checks for things like:

- Independent paths - Ensures that all independent paths through the code are tested at least once.
- Branch coverage - Ensures that all branches or decision points in the code are executed at least once.
- Condition coverage - Ensures that all possible outcomes of each condition in a decision takes place at least once.
- Path coverage - Ensures that all possible paths through the code are executed at least once.

Some advantages of structural testing are:

- It can uncover complex bugs or flaws in the software.
- It provides a measure of thoroughness of the test suite.
- It can be used to generate test cases to target specific areas of the code.

Some disadvantages are:

- It may be difficult to achieve high coverage, especially with complex code.
- It can lead to an excessive number of test cases being generated.
- It does not necessarily guarantee that relevant or important functionality will be tested.

 Mnemonics and learning tricks:
 - Think of branches as decision points and ensure each one is tested at least once.
 - Imagine conditions as forks in the road and check that you travel down each path.
 - Consider paths as journeys through the code and try to traverse each one.
