### Configuration Audits for the notes of the Unit 1 - Review of Software Engineering in the subject of Software Testing

Configuration audits are used to verify that the software product under test meets its specifications and is consistent with the requirements. They help identify any deviations from the expected configuration.

The steps involved in a configuration audit are:

1. Prepare Audit Schedule - Plan and schedule the audit activities. Determine the areas and features to be audited.
2. Prepare Audit Checklist - Prepare a checklist of configuration items to be verified. This could include verification of modules, interfaces, data structures, etc.
3. Execute Audit - Perform the audit as per the schedule and checklist. Compare the actual configuration with the expected configuration and note down any deviations or issues.
4. Report Audit Issues - Report any problems or issues identified in the audit along with suggestions for fixes.
5. Track Resolution - Track that the issues reported in the audit are properly resolved. A follow-up audit may be required for critical issues.

Advantages:

- Helps identify inconsistencies between actual and expected configuration early on.
- Avoids costly rework by detecting issues early in the development lifecycle.
- Enforces adherence to requirements and specifications.

Disadvantages:

- Can be time-consuming and tedious for large complex software.
- Requires clear documentation of specifications and requirements which may not always be available.
- Effectiveness depends on the rigor and thoroughness of the audit process.

Examples:

- Auditing software features and components against specifications.
- Verifying software interfaces against interface documentation.
- Checking software data structures against design diagrams.

Applications: Used in the software development lifecycle before major milestone releases or deployments. Helps improve software quality and reduce defects.
