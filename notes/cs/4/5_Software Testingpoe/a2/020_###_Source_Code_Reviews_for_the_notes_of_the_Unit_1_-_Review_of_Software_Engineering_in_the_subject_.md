### Source Code Reviews for the notes of the Unit 1 - Review of Software Engineering in the subject of Software Testing

Source code review is a systematic examination of the code to identify flaws and errors. It is a very important activity in software testing that helps to detect bugs early and improve code quality.

Some key points about source code reviews:

- They are done manually by reviewers reading through the code line by line.
- Reviewers look for compliance to coding standards, logic errors, vulnerability to common attacks, performance issues, etc.
- It is best done by a team of 3-4 reviewers to get diverse perspectives.
- Reviewers can use tools like code browsers, diff tools, etc. to aid the review process.
- Review meetings are conducted to discuss findings, get clarifications, and agree on resolutions.
- It results in cleaner, more efficient, and more secure code.
- It reduces rework and associated costs by catching issues early.

Tips for effective source code reviews:

- Review small chunks of code at a time, around 200-400 lines.
- Focus on design, architecture, and functionality rather than styling.
- Come prepared by understanding the requirements and design.
- Maintain a constructive approach and give specific suggestions.
- Track issues found and ensure they are addressed.
- Automate repetitive checks using tools to speed up the process.

In conclusion, source code reviews are a key software testing technique that should not be skipped as they provide significant technical and business benefits in terms of reduced bugs and costs. With the help of effective planning and execution, they can considerably boost code quality.
