### Impracticality of Testing All Data for the notes of the Unit 1 - Review of Software Engineering in the subject of Software Testing

- It is impractical and infeasible to test a software/application with all possible input data and scenarios. Some of the reasons for this are:
- The input domain could be extremely large. For example, testing all integers or all strings of a particular length.
- The number of input combinations could be very high. For example, testing all combinations of inputs in a multi-input function.
- Not all combinations of inputs may be meaningful or valid. Identifying and testing only the valid and meaningful combinations is challenging.
- It could take an extremely long time to test all cases which is not practical in terms of cost and project timelines.
- Instead of testing all cases, we focus on:
- Identifying and testing the most important, commonly used, and boundary scenarios.
- Using equivalence partitioning to group inputs and test representative values from each partition.
- Using techniques like random testing, fuzz testing to sample a subset of possible inputs.
- Being random and risk-based in selecting what to test when 100% coverage is not feasible.
