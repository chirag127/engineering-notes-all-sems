### Verification Methods for the notes of the Unit 1 - Review of Software Engineering in the subject of Software Testing

Following are the verification methods for testing software:

1. Reviews:
- Informal review: Done by peers, colleagues or managers. Checks for obvious errors, omissions, etc.
- Walkthrough: Led by author, reviewers are guided through document step-by-step. Participants suggest improvements.
- Technical review: Formal review, evaluators examine and document technical issues. Often more stringent entry criteria/exit criteria.
- Inspection: Highly structured process, individual preparations followed by a group meeting. Detects major defects.

Advantages:
- Cheap and easy.
- Finds defects early.
- Provides training/learning.

Disadvantages:
- Subjective.
- Depends on reviewer expertise.
- Labor-intensive.

2. Analysis:
- Static analysis: Analysis of software artifacts without execution. e.g. control flow analysis, data flow analysis, complexity analysis.
- Dynamic analysis: Analysis of software by executing it. e.g. memory error detectors, execution profilers, code coverage analyzers.

Advantages:
- Automated.
- Finds certain classes of defects.
- Provides metrics/measures.

Disadvantages:
- Prone to false positives/false alarms.
- Limited classes of defects detected.
- Extra effort required to investigate/fix issues.
