### Cause Effect Graphing Technique for the notes of the Unit 2 - Functional Testing in the subject of Software Testing

The Cause Effect Graphing Technique is a graphical representation technique used in Functional Testing to analyze the functional requirements and trace them with test cases.

Following are the key points about Cause Effect Graphing Technique:

- It is a top down approach where the overall system functionality is broken down into high level functions which are further branched out into low level functions.
- The high level functions are represented by rectangles and low level functions are represented by ovals.
- The arrows show the dependency between the functions. The functions which receive the input are shown with incoming arrows and functions which provide the output are shown with outgoing arrows.
- Once the cause effect graph is created, test cases can be derived by considering all independent paths in the graph. This ensures maximum coverage of functional requirements.
- The advantages of this technique are that it is easy to understand, helps in analyzing dependencies and deriving test cases. The disadvantage is that for complex systems, the graphs can become unstructured and difficult to analyze.
- For example, a cause effect graph can be created for an ATM system showing high level functions like 'Validate Card', 'Validate Pin', 'Select Transaction' etc. and low level functions under each high level function. Test cases can then be derived from the graph.

 Mnemonics:

- Rectangles represent high level functions.
- Ovals represent low level functions.
- Arrows show input/output dependencies.

Thus, the Cause Effect Graphing Technique can be effectively used to analyze functional requirements and derive test cases ensuring good coverage. With the help of mnemonics, it can be easy to remember the key points about this technique.
