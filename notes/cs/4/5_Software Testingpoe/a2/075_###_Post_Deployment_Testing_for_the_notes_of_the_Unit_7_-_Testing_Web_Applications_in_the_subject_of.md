### Post Deployment Testing

Post Deployment Testing is done after the software is deployed to the customer environment or released to the market. following types of testing are done:

- Compatibility Testing: Testing the software with different hardware, OS, browsers, networks, etc to check compatibility.
- Performance Testing: Checking the performance of the software with large data and load. Checks response time, throughput, resource utilization, etc.
- Stress Testing: Testing the software under extreme workload conditions to check its robustness.
- Load Testing: Gradually increasing the load on the software to check its performance under different load conditions.
- Recovery Testing: Inducing faults to check the recovery mechanism of the software.
- Security Testing: Checking the software's security from threats like hacking, XSS attacks, SQL injection, etc.
- Operational Acceptance Testing: The software is tested in the customer's environment by the customer to check if it meets the requirements.

Advantages:
- Finds issues in the customer's environment and compatibility issues.
- Checks performance and scalability.
- Checks security and recovery mechanisms.

Disadvantages:
- Difficult to perform.
- Expensive to set up the required environments and workloads.
- Time-consuming process.

Mnemonics:
PACCSOP - Performance, Acceptance, Compatibility, Stress, Operational, load, Security, Post deployment testing

Learning Tricks:
- Remember real-time issues you or your friends faced after using some software to understand the importance of post deployment testing.
- Try putting extremely high load on some software and see how it responds to understand load and stress testing.
