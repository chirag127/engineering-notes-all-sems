### Levels of Testing for the notes of the Unit 5 - Software Testing Activities in the subject of Software Testing

The various levels of testing are:

1. Unit Testing:
- Testing individual software components or units.
- Mnemonic: Check smallest part.
- Performed by developers.
- Checks whether each unit of the software behaves as designed.
- Examples: Checking an individual method or function.

2. Integration Testing:
- Testing combined parts of the software.
- Mnemonic: Check connections.
- Performed by testers or developers.
- Checks whether units combine correctly.
- Examples: Checking interface between modules, interaction between front-end and back-end, etc.

3. System Testing:
- Testing the complete software product as a whole.
- Mnemonic: Check entire system.
- Performed by testers.
- Checks whether the software meets its specified requirements.
- Examples: Recovery testing, Compatibility testing, Usability testing, etc.

4. Acceptance Testing:
- Testing to confirm readiness of the software product for delivery.
- Performed by client or end users.
- Checks whether the software satisfies the client requirements.
- Examples: Checking major functionalities, user interfaces, performance, etc. as per client needs.

The levels of testing increase in scope as we go down the list. Lower-level testing needs to be completed first before proceeding to higher-level testing. This ensures defects are identified and fixed early, leading to cost-effectiveness and better software quality. Mnemonics and examples can help in easy memorization of the levels of testing. However, they should only be used if they are simple and logical to remember.
