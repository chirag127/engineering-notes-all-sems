### Validation for the notes of the Unit 1 - Review of Software Engineering in the subject of Software Testing

- Software Testing is a process of evaluating a software product to find whether the product meets the required expectations and specifications or not and to identify the defects to ensure that the product is defect-free.
- Software Testing Life Cycle involves the following stages:
	- Requirement Analysis: In this stage, the testers analyze the requirements to understand the application and identify test scenarios.
	- Test Planning: In this stage, the testers create a test plan that describes the testing objectives and techniques.
	- Test Case Development: In this stage, the testers develop a number of test cases to verify and validate the functionality of the software application.
	- Test Execution: In this stage, the developed test cases are executed to find the defects in the software.
	- Defect Reporting and Tracking: In this stage, the detected defects are reported and tracked until they are fixed.
	- Test Cycle Closure: In this stage, a test cycle closure report is prepared with information like unfixed defects, test coverage, etc.
- There are three main types of software testing:
	- Black Box Testing: It is a functional testing technique that verifies the functionality of the application based on requirements. The internal structure of the application is not considered.
	- White Box Testing: It is a structural testing technique that verifies the internal structure of the application. The path coverage of the code is tested to identify the structural flaws.
	- Grey Box Testing: It is a combination of black box testing and white box testing. The functionality as well as the internal structure is tested.
- Some important software testing techniques are Boundary Value Analysis, Equivalence Partitioning, Decision table testing, State Transition testing, etc.
- Mnemonics:
	- SPICE: An acronym for Software Testing techniques - Static, Dynamic, Interface, Compatibility, and Environment Testing.
	- D.R.Y: Don't Repeat Yourself. Refers to avoiding duplication while writing test cases.
