## Unit 4 - Regression Testing

Regression Testing is a type of software testing to confirm that a recent program or code change has not adversely affected existing features.

- It is done after functional, integration or system testing.
- It verifies that the unchanged parts of the software still function correctly after a change has been implemented.
- It ensures that bug fixes have worked and that no new bugs were introduced due to the changes.
- It is difficult and time-consuming to execute all test cases each time a change is made, so typically automation testing tools are used to perform regression testing.

**Mnemonics:**

- RTT: Re-Test to Trust - Regression Testing re-tests the software to build trust that changes have not broken existing functionality.

**Tips for Learning:**

- Understand the purpose of Regression Testing and when it is performed.
- Know that it requires re-running test cases that were used to validate unaffected parts of the software.
- Be aware of challenges like time required to run many test cases and use of automation to address this.
- Study examples of scenarios where Regression Testing is necessary to solidify concepts.

**Advantages:**

- Helps identify bugs early and ensures high quality software.
- Prevents software regression where introducing a fix or new feature leads to the introduction of defects.
- Provides confidence for future changes.

**Disadvantages:**

- Can be time-consuming and resource intensive to execute test cases.
- Automation may require initial effort to set up testing environment and suites.
- Difficult to determine how much regression testing is sufficient.

**Applications:** Regression Testing is commonly done in software development and for web applications/APIs after updates are deployed. It is a key part of the SDLC to deliver high quality software and websites/services.
