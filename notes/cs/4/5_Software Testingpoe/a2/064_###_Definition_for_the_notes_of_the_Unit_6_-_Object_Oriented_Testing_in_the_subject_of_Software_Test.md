### Definition for the notes of the Unit 6 - Object Oriented Testing in the subject of Software Testing

- Object Oriented Testing (OOT) is a black-box software testing approach based on object-oriented programming concepts.
- In OOT, test cases are designed to exercise objects and their interactions.
- Test cases are designed from object diagrams and use cases.
- Following are the key steps in OOT:

1. Identify objects and their relationships from object diagrams and use cases.
2. Identify object interfaces and interactions.
3. Identify test scenarios that exercise the objects and their interfaces.
4. Design test cases for the test scenarios that validate the correctness of objects and their interactions.

- Advantages of OOT:

- Tests are designed from object diagrams and use cases, so they are related to functional requirements.
- Tests are designed to exercise objects and their interactions, so good object coverage can be achieved.
- The technique is easy to learn for testers with an object-oriented programming background.

- Disadvantages of OOT:

- The technique may not be suitable for non-object-oriented systems.
- The technique requires detailed object diagrams and use cases, which may not always be available.
- The technique can lead to a large number of test cases, resulting in low maintainability.

- In summary, OOT is a useful technique to validate object-oriented software. It complements other black-box techniques by providing object-oriented concepts and principles to the testing process. While employing the technique, care should be taken to keep the number of test cases manageable.
