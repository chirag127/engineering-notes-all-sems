### Risk Analysis for the notes of the Unit 4 - Regression Testing in the subject of Software Testing

- Risk Analysis is done to identify the potential risks in the software that can affect the Regression Testing. Some of the risks that can be identified are:
- Changes in requirements can lead to changes in the software that can affect the Regression test cases. This can be mitigated by updating the Regression test cases with the changes in the requirements.
- Bugs or defects left unfixed from previous releases can lead to failure of Regression test cases. This can be mitigated by fixing all the bugs from previous releases before starting Regression Testing for the new release.
- Inadequate or no documentation of changes made to the software can make it difficult to update the Regression test cases. This can be mitigated by properly documenting all the changes made to the software.
- Technical debt or code smells in the software code can make it fragile and prone to breaking of Regression test cases. This can be mitigated by refactoring the code to remove technical debt and code smells.
- Limited time available for Regression Testing can lead to not covering all the necessary test cases leading to risk of bugs escaping to production. This can be mitigated by planning Regression Testing phase and prioritizing the high impact test cases.

Some mnemonics and learning tricks for remembering the risks:

- Change in Reqs -> Update RT cases
- Previous bugs -> Fix before RT
- No change docs -> Difficult to update RT cases
- Tech debt / Code smells -> Refactor code
- Limited time -> Prioritize high impact RT cases
