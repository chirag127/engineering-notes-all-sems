### Terminologies in Testing for the notes of the Unit 1 - Review of Software Engineering in the subject of Software Testing

Following are the key terminologies and concepts in Software Testing:

- **Verification**: The process of evaluating software to determine whether the products of a given development phase satisfy the conditions imposed at the start of that phase. It typically reviews documents, plans, code, and specifications to find errors and omissions.
- **Validation**: The process of evaluating software during or at the end of the development process to determine whether it satisfies specified requirements. It involves actual testing and takes into account the end user's point of view.
- **Error**: A mistake, flaw, or fault in the software system.
- **Defect**: A variant of an error that is actual or potential and can impact the system's functionality, quality characteristics, or both. Defects are typically found at test or review time.
- **Fault**: The identified cause of an error. A fault can be generated from a mistake in the software coding process.
- **Failure**: The inability of a software system or component to perform its required functions within specified performance requirements. A failure occurs when a defect executes.
- **Test case**: A set of conditions or variables under which a tester will determine if a requirement upon a product is partially or fully satisfied.
- **Test suite**: A collection of test cases for a component or system under test.
- **Regression testing**: Retesting software multiple times to ensure that modifications have not induced unintended effects that might negatively impact correct functionality. Regression testing is often automated to reduce costs.

Some mnemonics and learning tricks for the key terminologies:

- VV for Verification and Validation - ensures software meets requirements
- DEFF for Defect, Error, Fault, Failure - Defect -> Error -> Fault -> Failure
- TC and TS for Test Case and Test Suite - Individual test and collection of tests
- Regression testing - retesting to check for unintended impacts of changes
