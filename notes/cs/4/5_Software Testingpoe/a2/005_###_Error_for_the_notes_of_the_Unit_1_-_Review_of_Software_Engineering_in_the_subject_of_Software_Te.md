### Error for the notes of the Unit 1 - Review of Software Engineering in the subject of Software Testing

1. Software Errors:
- Syntax Errors: Errors due to violation of the syntactic rules of the programming language. Eg: Missing semicolon, misspelled variable name, etc. These are caught by the compiler.
- Logical Errors: Errors in the logic of the program. The program compiles fine but produces incorrect output. Eg: Infinite loop, less than (>) sign used instead of greater than sign, etc. These are difficult to detect and debug.
- Runtime Errors: Errors that occur while the program is executing. Eg: Division by zero, out of bound array access, etc. The program crashes when these errors occur.

2. Types of Software Testing:
- White Box Testing: Internal logic/structure is tested. Tests are based on code coverage, branches, paths, conditions, etc.
- Black Box Testing: External functionality/behavior is tested. Tests are based on requirements and specifications. No knowledge of internal code is required.
- Gray Box Testing: Combines black box and white box testing methods.

3. Software Testing Strategies:
- Top-down: Starts with most abstract components and moves downwards.
- Bottom-up: Starts with lowest level components and moves upwards.
- Big Bang: Tests the entire system as a whole once everything is ready.
- Sandwich or Hybrid: Combination of Top-down and Bottom-up.

4. Software Testing Techniques:
- Boundary Value Analysis: Test boundary values of input domains.
- Equivalence Partitioning: Dividing input domain into equivalent classes and testing one value from each class.
- Cause-Effect Graphing: Graphical representation of inputs and outputs to identify test cases.
- Error Guessing: Based on experience, testers guess situation that are likely to cause errors.
- Specification-based testing: Deriving test cases from specifications.
