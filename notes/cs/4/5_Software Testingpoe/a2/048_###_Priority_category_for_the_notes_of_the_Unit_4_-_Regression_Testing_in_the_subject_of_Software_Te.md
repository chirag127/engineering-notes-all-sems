### Priority category for the notes of the Unit 4 - Regression Testing in the subject of Software Testing

1. Regression Testing - Testing the application to ensure that changes made to the system/software has not impacted the existing functionality. It is done to verify that the existing functionality is working as expected even after changes/modifications.
2. Reasons for Regression Testing -
   - Modifications/Enhancements/Fixes made to the software.
   - Environmental Changes.
   - New Platform/Hardware/DB releases.
3. Types of Regression Testing -
   - Retest All - Testing all the functionalities of the software after a change.
   - Selective Testing - Testing only the impacted areas/functionalities.
4. Challenges in Regression Testing -
   - Increased test cases and time required for testing due to repeated testing.
   - Deciding scope of testing (all functionalities vs impacted functionalities).
   - Maintaining test cases and test data.
   - Identifying the impact of changes and areas to re-test.
5. Best Practices -
   - Maintain test cases and test data systematically.
   - Automate regression test cases to save time and effort.
   - Classify test cases and prioritize areas to test.
   - Ensure test environment closely matches production environment.

* Mnemonics - "Re-check functionality after change" can be used to remember the purpose of Regression Testing.
* Learning Trick - Think of Regression Testing as re-testing the journey from your home to office taking a new route (modification) to ensure you reach office (functionality) as expected and nothing is impacted.
