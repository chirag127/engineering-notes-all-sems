## Unit 5 - Software Testing Activities

1. Unit Testing - Testing individual software components (units) to validate that each unit of the software performs as designed. Done by developers.
- Helps find bugs early and isolate the source of the bug.
- Improves code coverage and quality.
- Easy to automate.
- Mnemonic: Think of unit testing as testing the smallest *units* or components of the software.

2. Integration Testing - Testing combined parts of a system to verify that they function correctly together. Done by testers or developers.
- Ensures individual components work together.
- Helps identify interface defects and integration bugs.
- Can be either incremental (bottom-up) or big-bang (top-down) approach.
- Mnemonic: Integration testing *integrates* separate components and tests them as a group.

3. System Testing - Testing a fully integrated system to validate that it meets specified requirements. Done by testers.
- Ensures that the system meets functional and non-functional requirements.
- Includes testing of inputs/outputs, interfaces, performance, etc.
- Includes beta/acceptance testing - testing by end users in a real environment.
- Mnemonic: System testing tests the whole *system* to check if it really works.
