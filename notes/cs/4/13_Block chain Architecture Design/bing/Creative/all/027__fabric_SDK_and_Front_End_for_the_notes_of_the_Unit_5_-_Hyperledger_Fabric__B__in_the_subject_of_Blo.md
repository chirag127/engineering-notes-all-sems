### Fabric SDK and Front End for the notes of the Unit 5 - Hyperledger Fabric (B) in the subject of Block chain Architecture Design

- Fabric SDK is a set of libraries and tools that allow developers to interact with a Fabric network using various programming languages, such as Node.js, Java, Python, etc.
- Fabric SDK provides APIs for creating and joining channels, installing and invoking chaincodes, querying the ledger, registering and enrolling identities, and more.
- Fabric SDK also supports event services, which allow applications to receive notifications from the network about transactions, blocks, and chaincode events.
- Fabric SDK abstracts the details of the Fabric protocol and the gRPC communication, and provides a high-level interface for application development.
- Fabric SDK can be used to develop both the back-end and the front-end of a Fabric application, depending on the choice of the programming language and the web framework.
- For example, Fabric SDK for Node.js can be used to create a web server that exposes RESTful APIs for the front-end to consume, or to create a web application that directly communicates with the network using the Fabric SDK APIs.
- Similarly, Fabric SDK for Java can be used to create a Spring Boot application that serves as the back-end for the front-end, or to create a JavaFX application that directly communicates with the network using the Fabric SDK APIs.
- The front-end of a Fabric application is the user interface that allows the end-users to interact with the Fabric network and the smart contracts deployed on it.
- The front-end can be developed using any web framework or technology that suits the requirements and preferences of the developers and the users, such as React, Angular, Vue, Bootstrap, etc.
- The front-end can communicate with the back-end using various methods, such as HTTP, WebSocket, Socket.IO, etc.
- The front-end can also communicate with the Fabric network directly using the Fabric SDK, if the programming language and the web framework support it.
- The front-end should provide a user-friendly and secure way of authenticating and authorizing the users, managing their identities and certificates, and signing and submitting transactions to the network.
- The front-end should also provide a way of displaying the results of the transactions, querying the ledger state, and subscribing to the events from the network.

#### Mnemonics and learning tricks

- To remember the main functions of the Fabric SDK, you can use the acronym CIIQER, which stands for Create, Install, Invoke, Query, Enroll, and Register.
- To remember the main components of the Fabric network, you can use the acronym OPEL, which stands for Orderer, Peer, Endorser, and Ledger.
- To remember the main steps of developing a Fabric application, you can use the acronym CID, which stands for Chaincode, Identity, and Deployment.
