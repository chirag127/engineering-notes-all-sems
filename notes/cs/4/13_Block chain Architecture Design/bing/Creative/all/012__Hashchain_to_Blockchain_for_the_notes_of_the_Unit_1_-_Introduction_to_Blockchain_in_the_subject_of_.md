### Hashchain to Blockchain for the notes of the Unit 1 - Introduction to Blockchain in the subject of Block chain Architecture Design

- A hash chain is the successive application of a cryptographic hash function to a piece of data. A hash function is a mathematical function that takes any input and produces a fixed-length output, called a hash or a digest. A hash function has the property of being deterministic, meaning that the same input will always produce the same output. A hash function also has the property of being collision-resistant, meaning that it is hard to find two different inputs that produce the same output.
- A hash chain can be used to produce many one-time keys from a single key or password, by applying the hash function repeatedly. For example, if Alice has a secret key k, she can generate a hash chain of length n by computing h(k), h(h(k)), h(h(h(k))), ..., h^n(k), where h is the hash function and h^n(k) denotes applying the hash function n times to k. Alice can then use the hashes in the chain as one-time keys for authentication or encryption, starting from the last one and moving backwards. For example, she can send h^n(k) to Bob as a one-time key, and then use h^(n-1)(k) for the next communication, and so on. Bob can verify that Alice knows the secret key k by applying the hash function to the received hash and checking if it matches the previous one. For example, if Bob receives h^n(k) from Alice, he can compute h(h^n(k)) and check if it matches h^(n-1)(k), which he received earlier. This way, Alice and Bob can use a hash chain to establish a secure communication channel without revealing the secret key k.
- A hash chain can also be used to record the chronology of data's existence, by applying the hash function successively to additional pieces of data. For example, if Alice wants to prove that she created a document d at a certain time t, she can compute a hash of the document and the time, h(d,t), and append it to her hash chain. She can then publish the hash chain or send it to a trusted third party for verification. Anyone who has access to the hash chain can verify that Alice created the document d at time t by computing the hash of the document and the time and checking if it matches the last hash in the chain. They can also verify that Alice did not tamper with the document or the time by checking the integrity of the hash chain. A hash chain can thus provide a proof of existence and a proof of integrity for any data.
- A blockchain is a distributed ledger that stores transactions in a sequence of blocks, where each block contains a hash of the previous block, a timestamp, and a set of transactions. A blockchain can be seen as a special case of a hash chain, where the data is structured as transactions and the hash function is applied to the block headers. A blockchain can provide the same benefits as a hash chain, such as authentication, encryption, proof of existence, and proof of integrity, but with the added advantage of being decentralized and distributed. A blockchain does not rely on a single authority or a trusted third party to maintain and verify the ledger, but rather on a network of nodes that follow a consensus protocol to agree on the validity and order of the blocks.
- A blockchain can also provide additional benefits that a hash chain cannot, such as immutability, transparency, and accountability. A blockchain is immutable, meaning that once a block is added to the ledger, it cannot be modified or deleted without breaking the hash chain and invalidating the subsequent blocks. A blockchain is transparent, meaning that anyone can access and inspect the ledger and verify the transactions and the blocks. A blockchain is accountable, meaning that anyone can trace the origin and the history of any transaction and any block, and identify the parties involved and their actions.
