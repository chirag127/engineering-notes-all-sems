### Beyond Chaincode

- Chaincode is the term used for smart contracts in Hyperledger Fabric. It is a program that runs on the peers and interacts with the ledger.
- Chaincode can be written in various languages, such as Go, Node.js, or Java. It can implement any logic or functionality that the application requires.
- Chaincode can be invoked by clients through transactions, or by other chaincodes through chaincode-to-chaincode calls. It can also query the ledger state or history, or emit events to notify external applications.
- Chaincode has two main functions: `Init` and `Invoke`. The `Init` function is called when the chaincode is instantiated or upgraded, and it can be used to initialize the ledger state. The `Invoke` function is called when the chaincode is invoked by a transaction, and it can implement any business logic or validation rules.
- Chaincode can be deployed in two modes: `dev` mode and `net` mode. In `dev` mode, the chaincode is built and run by the developers on their local machines, and it can be tested without installing or instantiating it on the network. In `net` mode, the chaincode is installed and instantiated on the network by the administrators, and it can be invoked by the clients or other chaincodes.
- Chaincode can be upgraded to a new version by the administrators, who need to install the new chaincode on the peers, and then instantiate it with a new name or version. The old chaincode will still be available on the ledger, but it will not be invoked by new transactions. The new chaincode can access the same ledger state and history as the old chaincode, but it can also implement new logic or functionality.
- Chaincode can be extended or customized by using various features or components, such as:

  - Chaincode libraries: reusable modules or functions that can be imported and used by the chaincode, such as the `shim` library that provides the chaincode API, or the `fabric-contract-api` library that provides a higher-level abstraction for the chaincode development.
  - Chaincode plugins: external modules or functions that can be loaded and executed by the chaincode, such as the `endorsement` plugin that can implement custom endorsement policies, or the `validation` plugin that can implement custom validation rules.
  - Chaincode events: messages that can be emitted by the chaincode to notify external applications or services about the changes or results of the transactions, such as the `eventhub` service that can subscribe and listen to the chaincode events, or the `fabric-sdk` that can register and handle the chaincode events.
  - Chaincode metadata: information that can be attached to the chaincode to describe its properties or characteristics, such as the `chaincode.yaml` file that can specify the chaincode name, version, language, path, or policies, or the `metadata.json` file that can specify the chaincode arguments, parameters, or return values.
