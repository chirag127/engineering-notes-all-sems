## Unit 1 - Characterization of Distributed Systems

- A distributed system is a collection of independent computers that appears to its users as a single coherent system .
- A distributed system is one in which components located at networked computers communicate and coordinate their actions only by passing messages .
- This definition leads to the following especially significant characteristics of distributed systems:
  - Concurrency of components: the components can execute simultaneously and independently, without waiting for each other.
  - Lack of a global clock: there is no single source of time or synchronization for the components, which may have different local clocks and speeds.
  - Independent failures of components: the components can fail or recover without affecting the whole system, and the system can tolerate partial failures.
- The main reason for building distributed systems is resource sharing , which means the ability to use any hardware, software, or data anywhere in the system.
- Resource sharing can be achieved by different communication models, such as remote procedure call, remote method invocation, message passing, message queueing, publish-subscribe, or stream processing.
- Resource sharing can also involve different types of resources, such as files, databases, web services, sensors, devices, or computational power.
- Some examples of distributed systems are  :
  - The Internet: a global network of interconnected computers that provides various services, such as web, email, DNS, FTP, etc.
  - An Intranet: a portion of the Internet with clearly defined boundaries in which local security policies can be enforced, such as a corporate or academic network.
  - Mobile and ubiquitous computing: the use of portable and embedded devices, such as laptops, smartphones, smart watches, or sensors, that can communicate wirelessly and access distributed services.
  - Cloud computing: the provision of on-demand computing resources, such as servers, storage, or applications, over the Internet, using virtualization and scalability techniques.
  - Distributed information systems: systems that distribute information across different servers via multiple communication models, such as web search engines, social networks, or e-commerce platforms.
  - Distributed pervasive systems: systems that use embedded computer devices, such as ECG monitors, sensors, or RFID tags, to monitor and control physical environments or human activities.
  - Distributed computing systems: systems that use computers in a network to perform parallel or distributed computations, such as grid computing, cluster computing, or peer-to-peer computing.
- Some design issues and challenges of distributed systems are :
  - Transparency: the ability to hide the complexity and heterogeneity of the system from the users and developers, such as location, replication, migration, concurrency, or failure transparency.
  - Scalability: the ability to handle increasing numbers of components, users, or requests, without degrading the performance or functionality of the system, using techniques such as load balancing, caching, or replication.
  - Reliability: the ability to ensure the correct and consistent operation of the system, despite the possibility of component failures, network failures, or malicious attacks, using techniques such as fault tolerance, recovery, or security.
  - Consistency: the ability to ensure that the data and state of the system are coherent and up-to-date across all the components, despite the lack of a global clock or synchronization, using techniques such as distributed algorithms, consensus protocols, or distributed transactions.
  - Performance: the ability to provide efficient and timely service to the users, despite the latency and bandwidth limitations of the network, using techniques such as compression, encryption, or optimization.
