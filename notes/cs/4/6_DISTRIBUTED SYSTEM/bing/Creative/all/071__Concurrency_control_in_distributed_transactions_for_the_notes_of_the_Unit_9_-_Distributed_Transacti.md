### Concurrency control in distributed transactions for the notes of the Unit 9 - Distributed Transactions in the subject of DISTRIBUTED SYSTEM

- Concurrency control is the process of managing simultaneous access to shared data by multiple transactions in a distributed database system.
- Concurrency control ensures that the transactions preserve the ACID properties (Atomicity, Consistency, Isolation, and Durability) and produce serializable schedules, which are equivalent to some sequential execution of the transactions.
- Concurrency control in distributed transactions is more challenging than in centralized transactions, because the data is distributed over multiple servers, the communication between servers is costly and unreliable, and the transactions may span multiple servers and involve multiple participants.
- There are two main approaches for concurrency control in distributed transactions: locking-based and timestamp-based.
- Locking-based concurrency control protocols use locks to prevent conflicting operations on the same data item by different transactions. A lock is a variable associated with a data item that determines whether read/write operations can be performed on that data item. A transaction must acquire a lock on a data item before accessing it, and release the lock after finishing the access. There are different types of locks, such as shared locks, exclusive locks, and intention locks, that allow different degrees of concurrency.
- Locking-based concurrency control protocols can be classified into one-phase and two-phase locking protocols. One-phase locking protocol requires each transaction to lock an item before use and release the lock as soon as it has finished using it. This protocol provides high concurrency, but does not guarantee serializability. Two-phase locking protocol requires each transaction to follow two phases: a growing phase, where the transaction only acquires locks and does not release any lock, and a shrinking phase, where the transaction only releases locks and does not acquire any new lock. This protocol ensures serializability, but reduces concurrency and may cause deadlocks.
- Timestamp-based concurrency control algorithms use timestamps to order the transactions and ensure serializability. A timestamp is a unique identifier given by the system to a transaction that represents the transaction's start time. The timestamps are used to determine the precedence of transactions and to resolve conflicts. An older transaction should commit before a younger transaction, since the older transaction enters the system before the younger one.
- Timestamp-based concurrency control algorithms can be classified into basic, conservative, and multiversion algorithms. Basic timestamp ordering algorithm assigns a timestamp to each transaction and to each data item. A transaction can read or write a data item only if its timestamp is greater than the timestamp of the last transaction that wrote the data item, and less than the timestamp of the last transaction that read the data item. Otherwise, the transaction is aborted and restarted with a new timestamp. Conservative timestamp ordering algorithm assigns a timestamp to each transaction, but not to each data item. A transaction can read or write a data item only if its timestamp is greater than the timestamp of the last transaction that wrote the data item. Otherwise, the transaction is delayed until the conflicting transaction commits or aborts. Multiversion timestamp ordering algorithm maintains multiple versions of each data item, each with a timestamp. A transaction can read the latest version of a data item that has a timestamp less than or equal to the transaction's timestamp. A transaction can write a new version of a data item only if its timestamp is greater than the timestamp of the latest version of the data item. Otherwise, the transaction is aborted and restarted with a new timestamp.

- A mnemonic to remember the difference between one-phase and two-phase locking protocols is: One-phase locking is **O**ver **Q**uickly, Two-phase locking is **T**oo **S**low.
- A mnemonic to remember the difference between basic, conservative, and multiversion timestamp ordering algorithms is: Basic timestamp ordering is **B**rutal, Conservative timestamp ordering is **C**autious, Multiversion timestamp ordering is **M**oderate.
