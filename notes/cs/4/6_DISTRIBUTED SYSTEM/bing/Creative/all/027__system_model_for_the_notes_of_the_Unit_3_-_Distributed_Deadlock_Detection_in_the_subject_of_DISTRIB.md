### System model for the notes of the Unit 3 - Distributed Deadlock Detection in the subject of DISTRIBUTED SYSTEM

- A distributed system consists of a set of **processors** that are connected by a **communication network**. The communication delay is finite but unpredictable.
- A processor can execute one or more **processes** that can request, use, and release **resources**. Resources can be local or remote, and can be either **reusable** or **consumable**.
- A reusable resource can be used by only one process at a time, and can be requested again after it is released. A consumable resource is created and destroyed upon request and release, respectively.
- A process can request a resource while holding others, and can request resources in any order, which may not be known a priori.
- A **deadlock** is a situation where a set of processes are blocked because each process is holding a resource and waiting for another resource acquired by some other process in the set.
- Deadlocks can be handled by any of the following three strategies: **deadlock prevention**, **deadlock avoidance**, and **deadlock detection**.
- Deadlock prevention is achieved by imposing some constraints on the resource allocation policies, such as requiring a process to acquire all the needed resources simultaneously before it begins execution, or pre-empting a process that holds the needed resource.
- Deadlock avoidance is based on the idea of granting a resource to a process only if the resulting global system is **safe**, meaning that there exists a sequence of resource allocations that allows all the processes to finish without causing a deadlock.
- Deadlock detection involves examining the status of the process-resource interaction for the presence of a deadlock condition, and resolving the deadlock by aborting one or more deadlocked processes.
- Deadlock detection in distributed systems can be classified into three approaches: **centralized**, **distributed**, and **hierarchical**.
- In the centralized approach, there is a single **coordinator** node that is responsible for deadlock detection. The coordinator collects information about the resource requests and releases from all the other nodes, and constructs a **wait-for graph** (WFG) to detect cycles that indicate deadlocks. The advantages of this approach are simplicity and ease of implementation, while the drawbacks include excessive workload at the coordinator, single-point failure, and communication overhead.
- In the distributed approach, there is no coordinator node, and each node participates in deadlock detection. The nodes exchange messages to construct a WFG or a **global resource graph** (GRG) to detect cycles that indicate deadlocks. The advantages of this approach are no single-point failure, load balancing, and faster detection, while the drawbacks include complexity, message overhead, and false or phantom deadlocks.
- In the hierarchical approach, there is a combination of both centralized and distributed approaches. The nodes are organized into clusters, and each cluster has a **cluster-head** node that acts as a coordinator for the cluster. The cluster-heads communicate with each other to detect deadlocks at the inter-cluster level. The advantages of this approach are scalability, reliability, and flexibility, while the drawbacks include cluster formation and maintenance, and cluster-head selection and failure.
