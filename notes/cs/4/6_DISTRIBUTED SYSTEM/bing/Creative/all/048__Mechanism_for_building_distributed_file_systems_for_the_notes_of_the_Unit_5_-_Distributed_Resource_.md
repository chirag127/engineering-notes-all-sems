### Mechanism for building distributed file systems for the notes of the Unit 5 - Distributed Resource Management in the subject of DISTRIBUTED SYSTEM

A distributed file system (DFS) is a file system that allows multiple clients to access and modify files stored on one or more servers over a network. A DFS provides a transparent and consistent view of the files to the clients, regardless of their physical location or the type of storage device. A DFS also supports concurrent access, fault tolerance, scalability, and security.

To build a DFS, the following mechanisms are typically used:

- **File models**: A file model defines the structure and modifiability of a file. A file can be unstructured (a sequence of bytes) or structured (a collection of records, fields, or objects). A file can also be immutable (read-only) or mutable (read-write). Different file models have different advantages and disadvantages for different applications and scenarios. For example, unstructured files are more flexible and portable, but structured files are more efficient and easier to query. Immutable files are more suitable for caching and replication, but mutable files are more convenient for updates and collaboration.
- **File accessing models**: A file accessing model defines how a client can access a file stored on a remote server. There are three main file accessing models: upload/download, remote access, and remote service. In the upload/download model, the client copies the entire file from the server to the local disk, modifies it, and then uploads it back to the server. This model reduces network traffic and server load, but increases latency and storage overhead. In the remote access model, the client reads and writes the file directly on the server using a network file protocol (such as NFS or SMB). This model reduces latency and storage overhead, but increases network traffic and server load. In the remote service model, the client sends requests to the server, and the server performs the file operations and returns the results to the client. This model reduces network traffic and storage overhead, but increases latency and server load.
- **File sharing semantics**: File sharing semantics define the consistency and coherence of a file when it is accessed by multiple clients concurrently. There are three main file sharing semantics: UNIX semantics, session semantics, and immutable semantics. In the UNIX semantics, the client sees the latest version of the file at any time, and any update by one client is immediately visible to all other clients. This semantics provides the strongest consistency and coherence, but requires frequent synchronization and locking. In the session semantics, the client sees a cached version of the file during a session, and any update by one client is visible to other clients only after the session ends. This semantics reduces synchronization and locking overhead, but may cause inconsistency and incoherence. In the immutable semantics, the file is read-only and cannot be modified by any client. This semantics eliminates synchronization and locking overhead, but does not support updates and collaboration.
- **File replication**: File replication is the process of creating and maintaining multiple copies of a file on different servers. File replication can improve file availability, reliability, performance, and scalability. However, file replication also introduces challenges such as replica placement, replica management, replica consistency, and replica recovery. Different replication strategies have different trade-offs between these factors. For example, eager replication ensures strong consistency but incurs high overhead, while lazy replication reduces overhead but may cause inconsistency.
