### Limitation of Distributed system for the notes of the Unit 1 - Characterization of Distributed Systems in the subject of DISTRIBUTED SYSTEM

A distributed system is a collection of autonomous computers that communicate and cooperate with each other by message passing. To an external observer, a distributed system appears as a single coherent system. However, there are certain limitations that affect the design and implementation of distributed systems, such as:

- **Absence of a global clock**: In a distributed system, there is no single clock that can synchronize all the computers. Each computer has its own local clock that may run at a different rate or granularity, leading to asynchronous behavior. This makes it difficult to order events, collect consistent information, and schedule processes in a distributed system. To overcome this limitation, distributed systems use various algorithms and protocols to synchronize clocks, such as the Network Time Protocol (NTP) or the Lamport's logical clock.
- **Absence of shared memory**: In a distributed system, there is no physically shared memory among the computers. Each computer has its own private memory that is not accessible by other computers. This makes it impossible to know the global state of the distributed system, as each computer only has a partial view of the system. To overcome this limitation, distributed systems use various techniques to share data and coordinate actions, such as replication, consistency models, distributed transactions, and consensus algorithms.

These limitations pose challenges for the development and debugging of distributed systems, as they require careful design and testing to ensure correctness, reliability, and performance. Some examples of distributed systems that deal with these limitations are:

- **Google File System (GFS)**: A distributed file system that provides scalable and reliable storage for large-scale data-intensive applications. GFS uses a master-slave architecture, where a single master server manages the metadata and coordinates the operations of multiple chunk servers that store the data. GFS handles the absence of a global clock by using leases and operation logs to ensure consistency and fault tolerance. GFS handles the absence of shared memory by using replication and checksums to ensure data availability and integrity.
- **MapReduce**: A distributed programming model that allows parallel processing of large-scale data sets on a cluster of computers. MapReduce consists of two phases: map and reduce. In the map phase, each computer applies a user-defined function to a subset of the input data and produces intermediate key-value pairs. In the reduce phase, each computer aggregates the intermediate values associated with the same key and produces the final output. MapReduce handles the absence of a global clock by using a master-worker architecture, where a single master server assigns tasks and monitors the progress of multiple worker servers. MapReduce handles the absence of shared memory by using a distributed file system (such as GFS) to store the input and output data, and by using a shuffle and sort mechanism to transfer the intermediate data between the map and reduce phases.
