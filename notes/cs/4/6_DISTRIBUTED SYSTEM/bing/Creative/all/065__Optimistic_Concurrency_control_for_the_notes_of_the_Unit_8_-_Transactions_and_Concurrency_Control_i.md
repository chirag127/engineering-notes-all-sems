### Optimistic Concurrency Control for the notes of the Unit 8 - Transactions and Concurrency Control in the subject of DISTRIBUTED SYSTEM

- Optimistic concurrency control (OCC) is a method of managing concurrent access to shared data in a distributed system, such as a database or a software transactional memory.
- OCC assumes that conflicts among transactions are rare, and therefore it does not use locking or blocking mechanisms to prevent them. Instead, it allows transactions to execute optimistically, without checking for conflicts until the commit time. If a conflict is detected, the transaction is aborted and restarted.
- OCC has the advantage of avoiding the overhead and complexity of locking, and allowing more concurrency and scalability in the system. However, it also has the drawback of wasting resources and increasing latency when conflicts are frequent, and requiring the ability to abort and restart transactions.
- OCC can be implemented using different techniques, such as timestamps, versions, or validation. These techniques differ in how they assign identifiers to transactions and data items, and how they detect and resolve conflicts.

#### Timestamp Ordering Protocol
- A timestamp is a unique identifier that represents the logical or physical time when a transaction or a data item is created or accessed. Timestamps can be generated by a global clock, a logical counter, or a hybrid approach.
- Timestamp ordering protocol uses timestamps to order the transactions and data items, and to ensure serializability and consistency. Each transaction is assigned a timestamp when it starts, and each data item has two timestamps: a read-timestamp (R-timestamp) and a write-timestamp (W-timestamp), which record the latest time when the data item was read or written, respectively.
- When a transaction T tries to read a data item X, it compares its timestamp with the W-timestamp of X. If T's timestamp is smaller, it means that X has been updated by a later transaction, and T is aborted and restarted with a new timestamp. If T's timestamp is larger, it means that T can read X safely, and the R-timestamp of X is updated to the maximum of T's timestamp and the current R-timestamp of X.
- When a transaction T tries to write a data item X, it compares its timestamp with the R-timestamp and the W-timestamp of X. If T's timestamp is smaller than either of them, it means that X has been read or written by a later transaction, and T is aborted and restarted with a new timestamp. If T's timestamp is larger than both of them, it means that T can write X safely, and the W-timestamp of X is updated to T's timestamp.

#### Multiversion Concurrency Control
- Multiversion concurrency control (MVCC) is a technique that maintains multiple versions of each data item, and assigns them different timestamps or version numbers. MVCC allows transactions to read older versions of data items, without blocking or aborting them, and to write new versions of data items, without overwriting the existing ones.
- MVCC can improve the performance and concurrency of the system, by reducing the conflicts and aborts among transactions, and by allowing read-only transactions to access consistent snapshots of the data. However, it also increases the storage and maintenance costs of the system, by requiring the creation and deletion of multiple versions of data items.
- MVCC can be implemented using different techniques, such as two-phase locking, timestamp ordering, or validation. These techniques differ in how they create, access, and delete the versions of data items, and how they ensure serializability and consistency.

#### Validation Concurrency Control
- Validation concurrency control (VCC) is a technique that divides the execution of a transaction into three phases: read phase, validation phase, and write phase. In the read phase, the transaction reads the data items it needs, without checking for conflicts or acquiring locks. In the validation phase, the transaction checks whether its read set (the set of data items it has read) is still valid, i.e., whether it has been modified by any other concurrent transaction. If the read set is valid, the transaction proceeds to the write phase, where it writes the data items it has modified. If the read set is invalid, the transaction is aborted and restarted.
- VCC can improve the performance and concurrency of the system, by delaying the conflict detection and resolution until the validation phase, and by avoiding the overhead and complexity of locking. However, it also has the drawback of requiring the ability to store and compare the read sets of transactions, and of wasting resources and increasing latency when conflicts are frequent.
