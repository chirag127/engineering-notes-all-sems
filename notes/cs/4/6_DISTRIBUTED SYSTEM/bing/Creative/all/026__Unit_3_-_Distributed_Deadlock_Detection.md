## Unit 3 - Distributed Deadlock Detection

- A deadlock is a condition where a set of processes request resources that are held by other processes in the set, and none of them can proceed.
- Deadlocks are a fundamental problem in distributed systems, where a process may request resources in any order, and a process can request a resource while holding others.
- Deadlocks can be dealt with using any one of the following three strategies: deadlock prevention, deadlock avoidance, and deadlock detection.
- Deadlock prevention is commonly achieved by either having a process acquire all the needed resources simultaneously before it begins execution or by pre-empting a process that holds the needed resource.
- Deadlock avoidance is the approach where a resource is granted to a process if the resulting global system is safe, that is, there is no possibility of a deadlock in the future.
- Deadlock detection is the approach where the status of the process–resources interaction is examined periodically or on demand for the presence of a deadlock condition. To resolve the deadlock, one or more deadlocked processes have to be aborted or rolled back.
- Deadlock detection in distributed systems requires the following properties:
  - Progress: The method should be able to detect all the deadlocks in the system.
  - Safety: The method should not detect false or phantom deadlocks, that is, deadlocks that do not actually exist or have been resolved by the time of detection.
- There are three main approaches to deadlock detection in distributed systems: centralized, distributed, and hierarchical.
- Centralized approach: In this approach, there is only one responsible node or coordinator that collects information about the resource requests and allocations of all the processes in the system, and constructs a global wait-for graph (WFG) to detect cycles. A WFG is a directed graph where the nodes represent processes and the edges represent resource dependencies. A cycle in the WFG indicates a deadlock. The advantage of this approach is that it is simple and easy to implement, while the drawbacks include excessive workload and communication overhead at the coordinator, single-point failure, and lack of scalability.
- Distributed approach: In this approach, different nodes work together to detect deadlocks, without relying on a single coordinator. Each node maintains a local WFG for the processes and resources it controls, and exchanges information with other nodes as needed. There are two main techniques for distributed deadlock detection: edge chasing and diffusing computation. Edge chasing is a technique where a node initiates a probe message that traverses the WFG along the resource dependencies, and returns to the initiator if a cycle is found. Diffusing computation is a technique where a node initiates a computation that involves other nodes that share the same resource dependencies, and terminates when the initiator receives a reply from all the involved nodes. The advantage of this approach is that it avoids single-point failure and reduces the communication overhead, while the drawbacks include the possibility of false or phantom deadlocks, and the complexity of implementation.
- Hierarchical approach: This approach is a combination of both centralized and distributed approaches, where the system is divided into clusters of nodes, and each cluster has a designated coordinator that is responsible for deadlock detection within the cluster. The coordinators of different clusters communicate with each other to detect inter-cluster deadlocks. The advantage of this approach is that it balances the workload and communication overhead among the nodes, and improves the scalability and reliability of the system, while the drawback is the increased complexity of coordination and synchronization among the clusters.
