### Dynamic voting protocols for the notes of the Unit 7 - Fault Tolerance in the subject of DISTRIBUTED SYSTEM

- Dynamic voting protocols are techniques for consistency and recovery control of replicated files or objects in distributed systems   .
- The purpose of replication is to improve the availability and performance of a logical file or object in the presence of site failures and network partitions  .
- Dynamic voting protocols assign a number of votes to each replica, and only the group of replicas with a majority of votes is allowed to perform a restricted operation, such as reading or writing   .
- Dynamic voting protocols allow the vote values to be changed dynamically upon node or link failure, in an attempt to make the system more resilient and adaptable .
- Dynamic voting protocols ensure mutual exclusion and consistency among replicas by following some rules, such as    :
  - The total number of votes in the system is fixed and known by all nodes.
  - The vote value of a replica is an integer greater than or equal to zero.
  - A replica can only change its vote value when it is not involved in any operation.
  - A replica can only change its vote value to a value that is available in the system, i.e., not assigned to any other replica.
  - A replica can only change its vote value by exchanging votes with another replica, i.e., the sum of their votes remains constant.
  - A replica can only exchange votes with another replica that is reachable and not involved in any operation.
  - A replica can only exchange votes with another replica that has the same version number, i.e., they are consistent.
  - A replica can only exchange votes with another replica that agrees to the exchange, i.e., they have a common goal.
  - A replica can only exchange votes with another replica that has a lower priority, i.e., it is less likely to be accessed by clients.
- Dynamic voting protocols can be classified into two types, depending on how the vote exchange is initiated :
  - Proactive: A replica initiates a vote exchange when it detects a change in the system configuration, such as a node or link failure, or a network partition. The goal is to maximize the availability of the file or object by increasing the number of quorums in the system.
  - Reactive: A replica initiates a vote exchange when it receives a request for an operation that it cannot perform, such as a write request when it does not have a majority of votes. The goal is to minimize the response time of the operation by finding a quorum as soon as possible.
- Dynamic voting protocols have some advantages, such as    :
  - They can cope with dynamic changes in the system, such as node or link failures, network partitions, and node or link recoveries.
  - They can improve the availability and performance of the file or object by adapting the vote distribution to the access patterns and the system configuration.
  - They can reduce the communication and synchronization overhead by avoiding global coordination and using local information.
- Dynamic voting protocols also have some disadvantages, such as    :
  - They can introduce additional complexity and overhead in the system, such as maintaining vote values, initiating and executing vote exchanges, and resolving conflicts and deadlocks.
  - They can cause temporary unavailability or inconsistency of the file or object, such as when a replica changes its vote value or exchanges votes with another replica, or when a replica is isolated from a quorum due to a network partition.
  - They can have unpredictable behavior and performance, such as when a replica initiates a vote exchange that is not beneficial or necessary, or when a replica fails to find a quorum after a vote exchange.
