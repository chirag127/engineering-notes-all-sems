### Token based and non token based algorithms for the notes of the Unit 2 - Distributed Mutual Exclusion in the subject of DISTRIBUTED SYSTEM

- Distributed mutual exclusion is the problem of ensuring that no two processes running on different processors in a distributed system can access the same shared resource (such as a file, a database, or a critical section) at the same time.
- There are two main approaches to solve this problem: token based and non token based algorithms.
- In token based algorithms, a unique token is shared among all the processes in the system. A process can enter the critical section only if it possesses the token. The token is passed from one process to another according to some protocol, such as a logical ring or a queue.
- In non token based algorithms, there is no token in the system. Instead, processes exchange messages with each other to request and grant permission to enter the critical section. These algorithms use timestamps or logical clocks to order the requests and resolve conflicts.
- Some examples of token based algorithms are:
  - Suzuki-Kasami algorithm: This algorithm uses a logical ring to pass the token among the processes. The token contains a vector of sequence numbers, indicating the latest request of each process. A process can enter the critical section only if its request number matches the token number. The token is sent to the process with the highest request number in the system.
  - Raymond's algorithm: This algorithm uses a logical tree to pass the token among the processes. The token is initially held by the root of the tree. A process can enter the critical section only if it holds the token. A process can request the token by sending a REQUEST message to its parent in the tree. The parent forwards the request to the token holder, or grants the token if it has it. The process that receives the token becomes the new parent of the requester.
- Some examples of non token based algorithms are:
  - Ricart-Agrawala algorithm: This algorithm uses a logical clock to order the requests. A process that wants to enter the critical section broadcasts a REQUEST message with its timestamp to all other processes. A process that receives a REQUEST message replies with a REPLY message, unless it is in the critical section or it has a pending request with a smaller timestamp. A process can enter the critical section only if it has received a REPLY message from all other processes.
  - Lamport's algorithm: This algorithm uses a logical clock and a queue to order the requests. A process that wants to enter the critical section sends a REQUEST message with its timestamp to all other processes and puts itself in the queue. A process that receives a REQUEST message replies with a REPLY message and puts the requester in its queue. A process can enter the critical section only if it is at the head of its queue and it has received a REPLY message from all other processes. A process that exits the critical section sends a RELEASE message to all other processes and removes itself from the queue.
- Some advantages of token based algorithms are:
  - They are free from deadlock, since there is always a unique token in the system that can break the cycle of waiting processes.
  - They produce less message traffic, since a process only needs to communicate with one or a few other processes to obtain the token.
  - They ensure that requests are executed in the order they are made, since the token contains the information about the request sequence.
- Some disadvantages of token based algorithms are:
  - They are prone to token loss or duplication, due to network failures or process crashes. This can lead to starvation or violation of mutual exclusion.
  - They are not scalable, since the token has to be passed through all the processes in the system, which increases the latency and the overhead.
  - They are not fair, since some processes may have to wait longer than others to get the token, depending on the token passing protocol.
- Some advantages of non token based algorithms are:
  - They are robust, since they do not rely on a single token that can be lost or duplicated. They can tolerate network failures and process crashes, as long as a majority of processes are alive and reachable.
  - They are scalable, since a process only needs to communicate with a subset of processes to enter the critical section, which reduces the latency and the overhead.
  - They are fair, since they use timestamps or logical clocks to order the requests, which ensures that the earliest request is granted first.
