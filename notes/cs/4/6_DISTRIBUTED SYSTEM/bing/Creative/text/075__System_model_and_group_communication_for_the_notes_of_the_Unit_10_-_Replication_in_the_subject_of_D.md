### System model and group communication for replication in distributed systems

- A distributed system is a collection of independent and geographically dispersed processes that communicate and coordinate their actions by exchanging messages.
- Replication is a technique to improve the availability, performance, and fault tolerance of a distributed system by maintaining multiple copies of data or services across different processes or nodes.
- A system model defines the assumptions and properties of a distributed system, such as the communication model, the failure model, the timing model, and the security model.
- A communication model specifies how processes can exchange messages in a distributed system, such as the network topology, the message ordering, the message delivery, and the message reliability.
- A failure model defines the types and causes of failures that can occur in a distributed system, such as crash failures, omission failures, timing failures, Byzantine failures, etc.
- A timing model describes the assumptions and guarantees about the timing of events and messages in a distributed system, such as the clock synchronization, the message latency, the process speed, etc.
- A security model defines the threats and countermeasures for protecting the confidentiality, integrity, and availability of data and services in a distributed system, such as the encryption, the authentication, the authorization, etc.
- Group communication is a form of communication model that allows a process to send a message to a subset of processes in a distributed system, called a group, rather than to a single process or to all processes.
- Group communication can be classified into three types: broadcast, multicast, and unicast.
- Broadcast communication is when a process sends a message to all processes in a distributed system, regardless of their group membership. Broadcast communication is useful for disseminating common information or for discovering processes in a dynamic system.
- Multicast communication is when a process sends a message to a specific group of processes in a distributed system, based on some criteria or interest. Multicast communication is useful for implementing replication, as it allows a process to update or query multiple copies of data or services efficiently and consistently.
- Unicast communication is when a process sends a message to a single process in a distributed system, based on its identity or address. Unicast communication is useful for implementing point-to-point communication or for sending individual requests or responses.
- Group communication can also be characterized by the properties and guarantees it provides, such as the reliability, the ordering, the atomicity, and the agreement of message delivery.
- Reliable group communication ensures that a message sent by a process to a group is delivered by all processes in the group, unless they fail. Reliable group communication can be further divided into two categories: reliable broadcast and reliable multicast.
- Reliable broadcast ensures that a message sent by a process to all processes in a distributed system is delivered by all processes, unless they fail. Reliable broadcast can be implemented by using a flooding algorithm, where each process forwards the message to all its neighbors, or by using a spanning tree algorithm, where each process forwards the message to its children in a pre-defined tree structure.
- Reliable multicast ensures that a message sent by a process to a specific group of processes in a distributed system is delivered by all processes in the group, unless they fail. Reliable multicast can be implemented by using a group membership service, which maintains the list of processes in each group and notifies the processes of any changes, or by using a gossip algorithm, where each process randomly forwards the message to a subset of processes in the group.
- Ordering group communication ensures that the messages sent by different processes to a group are delivered by all processes in the group in the same order. Ordering group communication can be further divided into three categories: FIFO ordering, causal ordering, and total ordering.
- FIFO ordering ensures that the messages sent by the same process to a group are delivered by all processes in the group in the same order as they were sent. FIFO ordering can be implemented by using sequence numbers, where each process assigns a monotonically increasing number to each message it sends and delivers the messages in ascending order of their numbers.
- Causal ordering ensures that the messages sent by different processes to a group are delivered by all processes in the group in the same order as they were causally related. Two messages are causally related if the sender of one message has received or sent the other message before. Causal ordering can be implemented by using vector clocks, where each process maintains a vector of numbers that represents the causal history of the messages it has received or sent and delivers the messages in ascending order of their vectors.
