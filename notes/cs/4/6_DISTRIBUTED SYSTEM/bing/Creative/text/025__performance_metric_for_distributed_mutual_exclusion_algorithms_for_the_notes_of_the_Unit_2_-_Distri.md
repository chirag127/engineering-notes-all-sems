### Performance metric for distributed mutual exclusion algorithms

Distributed mutual exclusion algorithms are algorithms that ensure that only one process can access a shared resource or execute a critical section at a time in a distributed system. There are different approaches for implementing distributed mutual exclusion, such as token-based, non-token-based, and quorum-based methods. Each approach has its own advantages and disadvantages in terms of complexity, scalability, fault-tolerance, and performance.

The performance of distributed mutual exclusion algorithms can be measured by the following four metrics:

- **Response time**: It is the interval of time when a request waits for the end of its critical section execution after its request messages have been delivered. It indicates how fast a process can enter the critical section after requesting it.
- **Synchronization delay**: It is the time required for the next process to enter the critical section after a process leaves the critical section. It indicates how efficiently the algorithm can synchronize the access to the shared resource among the processes.
- **Message complexity**: It is the number of messages that are required per critical section execution by a process. It indicates how much communication overhead the algorithm imposes on the system.
- **Throughput**: It is the amount at which the system executes requests for the critical section. It indicates how well the algorithm can utilize the shared resource and serve the requests.

These metrics can vary depending on the best-case and worst-case scenarios of the algorithm. For example, the response time can be minimal if the process requesting the critical section already has the token or the permission, or it can be maximal if the process has to wait for a long time to receive the token or the permission. Similarly, the synchronization delay can be minimal if the algorithm can quickly transfer the token or the permission to the next process in the queue, or it can be maximal if the algorithm has to wait for a timeout or a confirmation from other processes. The message complexity can be minimal if the algorithm uses a single message to request and grant the access to the critical section, or it can be maximal if the algorithm uses multiple messages to coordinate and communicate with other processes. The throughput can be maximal if the algorithm can serve a large number of requests per unit of time, or it can be minimal if the algorithm has a low concurrency level or a high blocking rate.

The performance metrics can be used to compare and evaluate different distributed mutual exclusion algorithms and to choose the most suitable one for a given system and application. However, there is no single optimal algorithm that can achieve the best performance in all metrics and scenarios. Therefore, the trade-offs and the design goals of the system and the application should be considered when selecting an algorithm.
