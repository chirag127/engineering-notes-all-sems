### Classification of Agreement Problem

An agreement problem is a fundamental problem in fault-tolerant distributed systems, where a set of processes need to agree on a common value or action, despite the possibility of failures or asynchrony. There are different versions of this problem, depending on the type of failures, the type of communication, and the type of agreement. Some of the most well-known agreement problems are:

- **Consensus**: Each process proposes a value, and all correct processes must agree on the same value, which must be one of the proposed values. Consensus is the most general agreement problem, and it can be used to implement other agreement problems.
- **Atomic Commitment**: Each process decides to commit or abort a transaction, and all correct processes must agree on the same decision, which must be commit if and only if all processes decided to commit. Atomic commitment is a special case of consensus, where the proposed values are commit or abort.
- **Atomic Broadcast**: Each process broadcasts a message, and all correct processes must deliver the same set of messages, in the same order. Atomic broadcast is also a special case of consensus, where the proposed values are ordered sets of messages.
- **Group Membership**: Each process maintains a view of the current set of processes in the system, and all correct processes must agree on the same view, which must reflect the actual failures and recoveries of processes. Group membership is related to consensus, but it is not equivalent, since the views may change over time.
- **Interactive Consistency**: Each process has a private value, and all correct processes must agree on a vector of values, where the i-th value is the private value of the i-th process, or a default value if the i-th process is faulty. Interactive consistency is a generalization of consensus, where each process proposes a vector of values, instead of a single value.

These agreement problems have different applications in distributed systems, such as coordination, replication, fault tolerance, and distributed algorithms. They also have different solvability conditions, depending on the system model. For example, consensus is impossible to solve in a purely asynchronous system with one or more crash failures, but it is possible to solve in a synchronous system, or in an asynchronous system with additional assumptions, such as randomization, failure detectors, or partial synchrony.
