## Unit 8 - Transactions and Concurrency Control

- A **transaction** is a logical unit of work that consists of a sequence of database operations, such as queries, updates, inserts, or deletes.
- A transaction has the following properties: **atomicity**, **consistency**, **isolation**, and **durability** (ACID).
  - **Atomicity** means that either all the operations of a transaction are executed or none of them are. A transaction is treated as a single unit and cannot be divided into parts.
  - **Consistency** means that a transaction preserves the integrity constraints of the database. A transaction cannot leave the database in an inconsistent state.
  - **Isolation** means that a transaction is executed as if it were the only one running in the system. A transaction cannot see the intermediate results of other concurrent transactions.
  - **Durability** means that the effects of a transaction are permanent and will not be lost in case of a system failure. A transaction is recorded in a persistent storage device before it is committed.
- **Concurrency control** is the process of managing the simultaneous execution of transactions in a multi-user database system. The main goals of concurrency control are to ensure the **serializability** and **recoverability** of transactions.
  - **Serializability** means that the concurrent execution of transactions produces the same result as some serial execution of the same transactions. A serial execution is one in which transactions are executed one after another, without any overlap.
  - **Recoverability** means that the system can restore the database to a consistent state after a transaction failure. A transaction failure can be caused by various reasons, such as user abort, system crash, or deadlock.
- There are different methods of concurrency control, such as **locking**, **timestamping**, **validation**, and **multiversion**. Each method has its own advantages and disadvantages, depending on the characteristics of the transactions and the database system.
  - **Locking** is a method of concurrency control that uses locks to prevent conflicting operations on the same data item. A lock is a mechanism that grants or denies access to a data item by a transaction. There are different types of locks, such as **shared locks**, **exclusive locks**, **read locks**, **write locks**, etc. A lock manager is responsible for granting, releasing, and enforcing locks according to a locking protocol.
  - **Timestamping** is a method of concurrency control that uses timestamps to order the operations of transactions. A timestamp is a unique identifier that reflects the logical start time of a transaction. Each transaction and each data item has a timestamp assigned to it. A timestamp manager is responsible for generating and comparing timestamps according to a timestamping protocol.
  - **Validation** is a method of concurrency control that uses a validation test to check whether the operations of a transaction are serializable. A validation test is a procedure that examines the read and write sets of a transaction and determines whether it can be committed or aborted. A validation manager is responsible for performing the validation test according to a validation protocol.
  - **Multiversion** is a method of concurrency control that uses multiple versions of data items to allow concurrent read and write operations. A version is a copy of a data item that reflects its state at a certain point in time. A version manager is responsible for creating and maintaining versions according to a multiversion protocol.
