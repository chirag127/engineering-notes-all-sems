### Total Causal Order

- Total causal order is a property of message ordering in distributed systems that ensures that all messages are delivered in the same order to all processes, and that this order is consistent with the causal order of the messages .
- Causal order is a partial order relation that captures the potential causal dependencies between events in a distributed system. An event a is causally dependent on an event b if b happened before a and b could have influenced a. For example, if a process sends a message m1 and then sends another message m2, then m1 is causally dependent on m2, and we write m1 -> m2. Similarly, if a process receives a message m1 and then sends a message m2, then m2 is causally dependent on m1, and we write m1 -> m2 .
- Total causal order implies that if m1 -> m2, then every process that receives both m1 and m2 must receive m1 before m2. Moreover, if m1 and m2 are concurrent, meaning that neither is causally dependent on the other, then every process that receives both m1 and m2 must receive them in the same order .
- Total causal order is useful for implementing reliable and consistent distributed services, such as replicated data, distributed transactions, distributed consensus, etc. It ensures that all processes have a consistent view of the global state and the history of events in the system .
- Total causal order can be implemented using various protocols, such as vector clocks, logical clocks, sequence numbers, etc. These protocols typically require each process to attach some metadata to each message, such as a timestamp, a counter, a vector, etc., that encodes the causal dependencies of the message. The processes then use this metadata to order the messages according to some rules, such as comparing timestamps, taking the maximum of counters, etc. Some protocols also require the processes to exchange additional messages, such as acknowledgments, markers, etc., to ensure the delivery of all messages in the same order .
