### Survey routing protocols for the notes of the Unit 4 - Network & Communication aspects in IoT in the subject of Internet of Things

- Routing protocols are the rules and algorithms that determine how data packets are transmitted and received in a network of devices, such as the Internet of Things (IoT).
- Routing protocols for IoT need to consider the characteristics and challenges of low-power and lossy networks (LLNs), such as limited bandwidth, energy, memory, and processing capabilities, as well as dynamic topology, heterogeneity, scalability, and security issues.
- There are different types of routing protocols for IoT, such as flat, hierarchical, geographic, and context-based, depending on the network structure, routing criteria, and objectives.
- Some of the common routing protocols for IoT are:

  - **RPL**: Routing Protocol for Low-power and Lossy Networks. It is an IPv6-based protocol that uses a tree-like topology called Destination Oriented Directed Acyclic Graph (DODAG) to route data packets from multiple sources to one or more destinations. It supports multipoint-to-point (MP2P), point-to-multipoint (P2MP), and point-to-point (P2P) traffic flows. It uses objective functions and metrics to optimize the routing performance according to different criteria, such as hop count, latency, energy, reliability, etc. It also provides mechanisms for loop detection and avoidance, local repair, and security. It is standardized by the IETF ROLL working group and is widely used in IoT applications, such as smart grid, smart city, industrial automation, etc.   

  - **AODV**: Ad hoc On-Demand Distance Vector. It is a reactive protocol that establishes routes on-demand, i.e., only when a source node needs to communicate with a destination node. It uses a route discovery process that involves broadcasting route request (RREQ) packets and receiving route reply (RREP) packets. It maintains a routing table that contains the next hop information for each destination. It also uses sequence numbers and hop counts to ensure loop-free and fresh routes. It can handle dynamic topology changes and network partitions by using route error (RERR) packets and local repair techniques. It is suitable for IoT networks that have low traffic and mobility. 

  - **OLSR**: Optimized Link State Routing. It is a proactive protocol that periodically exchanges topology information among nodes, i.e., each node maintains a global view of the network. It uses a concept of multipoint relays (MPRs) to reduce the overhead of flooding control messages. MPRs are a subset of nodes that are responsible for forwarding control messages to their neighbors. Each node selects its MPRs based on the degree of connectivity and the willingness of the nodes. It also uses a concept of MPR selectors to determine the routes to the destinations. It can adapt to network changes by updating the topology information and recalculating the routes. It is suitable for IoT networks that have high traffic and stability. 

  - **CBRP**: Context-Based Routing Protocol. It is a hybrid protocol that combines the features of reactive and proactive protocols. It uses a hierarchical structure that divides the network into clusters based on the context information of the nodes, such as location, speed, direction, etc. Each cluster has a cluster head that maintains the routing table for the intra-cluster communication and the gateway nodes that connect to other clusters. It uses a reactive approach for the inter-cluster communication, i.e., it initiates a route discovery process when a source node needs to communicate with a destination node in another cluster. It can reduce the routing overhead and improve the scalability and efficiency of the network. It is suitable for IoT networks that have heterogeneous and dynamic nodes. 

- A comparative analysis of the routing protocols for IoT can be done based on the following parameters:

  - **Overhead**: The amount of control messages and routing information that are exchanged and stored by the nodes. It affects the bandwidth, energy, and memory consumption of the network. A lower overhead is desirable for IoT networks.
  - **Delay**: The time taken by a data packet to reach its destination from its source. It affects the quality of service (QoS) and the user experience of the network. A lower delay is desirable for IoT networks.
  - **Throughput**: The amount of data packets that are successfully delivered to their destinations per unit time. It affects the reliability and efficiency of the network. A higher throughput is desirable for IoT networks.
