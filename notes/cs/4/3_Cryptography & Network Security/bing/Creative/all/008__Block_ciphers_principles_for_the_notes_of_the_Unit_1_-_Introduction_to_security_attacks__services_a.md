- A block cipher is a deterministic algorithm that operates on fixed-length groups of bits, called blocks, and uses a secret key to encrypt and decrypt them.
- A block cipher consists of two paired algorithms, one for encryption, E, and the other for decryption, D. Both algorithms accept two inputs: an input block of size n bits and a key of size k bits; and both yield an n-bit output block. The decryption algorithm D is defined to be the inverse function of encryption, i.e., D = E<sup>-1</sup>.
- A block cipher can be designed by following some principles that affect its security and efficiency. These principles are :
  - Number of rounds: The number of rounds is the number of times the block cipher algorithm is repeated to produce the ciphertext. The more rounds, the more secure the algorithm, but also the more time-consuming. For example, DES has 16 rounds, while AES has 10, 12, or 14 rounds depending on the key size.
  - Design of function F: The function F is the core part of the block cipher algorithm that performs some operations on the input block and the key to produce some output. The function F should be nonlinear, complex, and unpredictable, so that it is hard for an attacker to reverse-engineer it or find any patterns in the ciphertext. The function F should also produce the avalanche effect, which means that a small change in the input block or the key should result in a large change in the output block.
  - Key schedule algorithm: The key schedule algorithm is the algorithm that generates subkeys from the main key for each round of the block cipher. The subkeys should be different and independent from each other, and should also produce the avalanche effect. The key schedule algorithm should be secure and efficient, so that it is hard for an attacker to guess the subkeys or the main key, and also easy for the legitimate user to generate them.
- A block cipher can operate in different modes, which determine how the input blocks are processed and how the ciphertext blocks are combined. The most common modes are:
  - Electronic Codebook (ECB): In this mode, each input block is encrypted independently with the same key, and the ciphertext blocks are concatenated. This mode is simple and fast, but insecure, as it does not hide any patterns or repetitions in the plaintext, and also allows parallel attacks and modifications on the ciphertext blocks.
  - Cipher Block Chaining (CBC): In this mode, each input block is XORed with the previous ciphertext block before being encrypted with the same key, and the ciphertext blocks are concatenated. The first input block is XORed with an initialization vector (IV), which is a random or pseudorandom value. This mode is more secure than ECB, as it hides the patterns and repetitions in the plaintext, and also prevents parallel attacks and modifications on the ciphertext blocks. However, it is slower and requires synchronization between the sender and the receiver.
  - Cipher Feedback (CFB): In this mode, each input block is XORed with the encrypted previous ciphertext block, and the ciphertext blocks are concatenated. The first input block is XORed with the encrypted IV. This mode is similar to CBC, but it allows the block cipher to work as a stream cipher, which means that it can encrypt and decrypt variable-length blocks or even individual bits. This mode is also more secure than ECB, but slower and requires synchronization.
  - Output Feedback (OFB): In this mode, each input block is XORed with the encrypted previous output block, and the ciphertext blocks are concatenated. The first input block is XORed with the encrypted IV. This mode is similar to CFB, but it does not use the ciphertext blocks as inputs for the encryption, which makes it more resistant to transmission errors and modifications. However, it also requires synchronization and may produce keystream reuse if the same IV is used more than once.
