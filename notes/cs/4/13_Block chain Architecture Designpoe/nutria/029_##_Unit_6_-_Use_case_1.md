
## Unit 6 - Use case 1

This unit covers the concept of use cases, which are a way to document the requirements of a system. Use cases are used to identify and document the functionality of a system, and are often used in software development.

1. **What is a Use Case?** A use case is a set of steps, typically defining interactions between a role (known as an actor) and a system, to achieve a goal. The actor can be a user, an external system, or time.

2. **What are the Benefits of Use Cases?** Use cases provide a structured way to document and analyze the requirements of a system. They help to identify the actors involved, the goals they are trying to achieve, and the steps they need to take to achieve those goals. They also provide a way to identify any potential problems or conflicts between actors.

3. **How to Create a Use Case?** Use cases are typically created using a diagram that shows the interactions between the actors and the system. This diagram can then be used to create a document that outlines the use case. This document should include the steps involved in the use case, the actors involved, the goals, and any potential problems or conflicts.

4. **What are the Mnemonics and Learning Tricks for Use Cases?** 
- **U**se **C**ase **A**nalysis: UCA is an acronym for Use Case Analysis, which is the process of analyzing a system's requirements to identify the use cases. 
- **A**ctors **I**nteract **W**ith **S**ystem: AIWS is an acronym for Actors Interact With System, which is the process of identifying the actors involved in a use case and how they interact with the system. 
- **R**equirements **A**re **E**xplicit: RAE is an acronym for Requirements Are Explicit, which is the process of documenting the requirements of a system in a use case. 
- **F**low **O**f **E**vents: FOE is an acronym for Flow Of Events, which is the process of outlining the steps involved in a use case. 
- **R**esources **A**re **M**apped: RAM is an acronym for Resources Are Mapped, which is the process of documenting the resources available to each actor in a use case.
