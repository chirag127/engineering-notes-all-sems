## Unit 2 - Cloud Enabling Technologies Service Oriented Architecture

Service Oriented Architecture (SOA) is a style of software design where applications are built as a suite of interoperable services. These services can be reused for other applications and are made available over the network, mostly using web service standards.

Key points about Service Oriented Architecture:

- Services are self-contained, modular applications that perform a specific task or function.
- Services are loosely coupled, interact via interfaces and can be developed and deployed independently.
- Services communicate with each other over a network using standard protocols and formats like HTTP, XML, JSON, SOAP, etc.
- Services can be discovered and composed into new applications using service registries.
- The modular nature of services leads to flexibility, reusability and scalability.

Advantages of Service Oriented Architecture:

- Increased flexibility and reusability through loosely coupled services.
- Improved maintainability and modularity as services can be maintained or upgraded independently.
- Scalability and reliability through geographical distribution of services.
- Separation of concerns as each service focuses on a specific task or function.
- Technology agnostic as services can use different platforms and languages as long as they adhere to interface and communication standards.

Disadvantages of Service Oriented Architecture:

- Can introduce latency due to network communications between distributed services.
- Debugging and monitoring distributed systems can be challenging.
- Governance and management overhead to ensure quality of service and security.
- Difficult to handle transactions and rollbacks across multiple services.
- Initial migration to SOA can be costly and time-consuming for large systems.
