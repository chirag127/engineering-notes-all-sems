## Unit 1 - Introduction: SOA and MSA Basics

### Service Oriented Architecture (SOA)

- SOA is a style of software design where applications are built as a collection of interoperable services.
- Each service is a reusable software module that performs a specific function.
- Services are loosely coupled and communicate with each other using a messaging protocol.
- The key benefits of SOA are reusability, interoperability, and accessibility.

**Mnemonics:**

- Think of services as Lego blocks: Many reusable services assembled to build applications.
- Loosely coupled: Services are independent and interact via messages. Like coworkers communicating via email.

**Examples:**

- A product catalog service: Returns product data
- A shopping cart service: Manages shopping carts
- A payment processing service: Handles credit card payments

**Advantages:**

- Reusability: Services can be used in multiple applications
- Interoperability: Services use standard interfaces to interact
- Accessibility: Services can be accessed via the network
- Scalability: Services can be replicated to handle load
- maintainability: Services can be updated/replaced independently

**Disadvantages:**

- Complexity: SOA implementations can be complex to design and deploy
- Performance: Remote service calls can impact performance
- Governance: Managing services and dependencies can be challenging
- Vendor lock-in: Dependent on specific products/standards
