### Various Size Oriented Measures

- Size oriented measures are software metrics that are derived by normalizing quality and/or productivity measures by considering the size of the software that has been produced .
- Size oriented measures are based on the assumption that the size of the software is a predictor of other attributes, such as effort, cost, complexity, reliability, etc.
- Size oriented measures are also used for measuring and comparing the productivity of programmers and teams.
- The most common size oriented measure is the **lines of code (LOC)**, which counts the number of executable statements in the source code .
- LOC can be measured in different ways, such as physical LOC (counting each line of code as one unit), logical LOC (counting each statement or instruction as one unit), or effective LOC (counting only the lines of code that contribute to the functionality of the software).
- LOC has some advantages, such as being easy to measure, widely available, and independent of programming language.
- LOC also has some disadvantages, such as being affected by coding style, comments, blank lines, reuse, and quality.
- Another size oriented measure is the **function point (FP)**, which measures the functionality of the software from the user's perspective .
- FP is based on the number and complexity of inputs, outputs, inquiries, files, and interfaces in the software .
- FP has some advantages, such as being independent of programming language, reflecting user requirements, and being applicable to different phases of software development.
- FP also has some disadvantages, such as being subjective, difficult to measure, and requiring expert judgment.
- Other size oriented measures include **object points**, which count the number and complexity of objects in object-oriented software, and **feature points**, which extend function points by adding the number and complexity of algorithms in the software.
