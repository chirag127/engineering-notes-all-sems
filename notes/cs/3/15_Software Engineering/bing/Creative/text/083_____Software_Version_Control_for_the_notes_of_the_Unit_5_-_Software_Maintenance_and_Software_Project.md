### Software Version Control

- Software version control (SVC) is a management strategy to track and store changes to a software development document or set of files that follow the development project from beginning to end-of-life .
- SVC is a component of software configuration management, which is the process of controlling the evolution of software products.
- SVC helps software teams to:
  - Manage changes to source code over time and avoid conflicts or errors .
  - Collaborate effectively and coordinate their work on shared files .
  - Recover previous versions of code in case of bugs, errors, or loss of data .
  - Trace the history of changes and identify who, when, and why made them .
  - Experiment with new features or ideas without affecting the main codebase .
- SVC systems are software tools that help implement SVC by taking snapshots of the files and saving them permanently in a repository .
- SVC systems can be classified into two main types: centralized and distributed .
  - Centralized SVC systems have a single server that stores all the files and their versions, and clients that access them through a network .
  - Distributed SVC systems have multiple repositories that can be synchronized with each other, and each client has a full copy of the files and their versions .
- Some examples of popular SVC systems are: Subversion (centralized), Git (distributed), Mercurial (distributed), and Team Foundation Version Control (centralized) .
- SVC systems use different terms and concepts to describe the changes and operations on the files, such as: revision, commit, branch, merge, tag, checkout, clone, pull, push, etc .
- SVC systems also provide various features and tools to support the software development process, such as: graphical user interfaces, command-line interfaces, web interfaces, integration with other tools, code review, code analysis, code quality, etc .
