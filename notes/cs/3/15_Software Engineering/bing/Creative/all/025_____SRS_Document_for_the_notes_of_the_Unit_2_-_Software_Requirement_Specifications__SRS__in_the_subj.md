# SRS Document for the notes of the Unit 2 - Software Requirement Specifications (SRS) in the subject of Software Engineering

- An SRS document is a comprehensive description of a software system that specifies what features and functions it must have  .
- An SRS document is also called a black-box specification because it focuses on the external behavior and interfaces of the system, not on the internal implementation details.
- An SRS document is essential for a successful software development project because it provides a clear and consistent roadmap for all the stakeholders involved, such as developers, testers, customers, and users  .
- An SRS document should be written in a clear, concise, and unambiguous language that can be understood by both technical and non-technical readers  .
- An SRS document should follow a standard structure and format that covers the following sections   :

  - Introduction: This section provides an overview of the purpose, scope, definitions, acronyms, abbreviations, references, and overview of the document.
  - Overall description: This section provides a general description of the product, its perspective, functions, user characteristics, constraints, assumptions, and dependencies.
  - Specific requirements: This section provides a detailed description of the functional and non-functional requirements of the product, such as user interface, performance, security, reliability, maintainability, etc. This section may also include use cases, scenarios, data models, and diagrams to illustrate the requirements.
  - Appendices: This section provides any additional information that may be relevant to the document, such as glossary, index, issues, risks, etc.

- An SRS document should be reviewed and validated by all the stakeholders to ensure that it is complete, consistent, correct, feasible, testable, and traceable   .
- An SRS document should be updated and maintained throughout the software development life cycle to reflect any changes or modifications in the requirements   .
