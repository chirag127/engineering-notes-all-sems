# Software Quality Frameworks

Software quality frameworks are models or standards that help to define, measure, and improve the quality of software products. Software quality frameworks can be classified into two main categories: product-oriented and process-oriented.

## Product-oriented frameworks

Product-oriented frameworks focus on the characteristics and attributes of the software product itself, such as functionality, reliability, usability, efficiency, maintainability, and portability. Product-oriented frameworks can be further divided into two types: internal and external.

- Internal frameworks deal with the quality of the software code and design, such as complexity, cohesion, coupling, modularity, readability, testability, etc. Internal frameworks are mainly used by developers and testers to ensure the quality of the software during development and testing phases. Examples of internal frameworks are:

  - ISO/IEC 9126: Software engineering - Product quality
  - ISO/IEC 25010: Systems and software engineering - Systems and software quality requirements and evaluation (SQuaRE) - System and software quality models
  - CISQ: Consortium for Information and Software Quality
  - CK metrics: Chidamber and Kemerer metrics
  - MOOD metrics: Metrics for Object-Oriented Design
  - Halstead metrics: Halstead complexity measures

- External frameworks deal with the quality of the software from the perspective of the end-users and stakeholders, such as functionality, reliability, usability, efficiency, maintainability, and portability. External frameworks are mainly used by customers and evaluators to assess the quality of the software after delivery and deployment. Examples of external frameworks are:

  - ISO/IEC 14598: Information technology - Software product evaluation
  - ISO/IEC 25040: Systems and software engineering - Systems and software quality requirements and evaluation (SQuaRE) - Evaluation process
  - ISO/IEC 25051: Software engineering - Software product Quality Requirements and Evaluation (SQuaRE) - Requirements for quality of Commercial Off-The-Shelf (COTS) software product and instructions for testing
  - ISO/IEC 25012: Software engineering - Software product Quality Requirements and Evaluation (SQuaRE) - Data quality model
  - ISO/IEC 25020: Software engineering - Software product Quality Requirements and Evaluation (SQuaRE) - Measurement reference model and guide
  - ISO/IEC 25030: Software engineering - Software product Quality Requirements and Evaluation (SQuaRE) - Quality requirements
  - ISO/IEC 25045: Systems and software engineering - Systems and software Quality Requirements and Evaluation (SQuaRE) - Evaluation module for recoverability

## Process-oriented frameworks

Process-oriented frameworks focus on the activities and practices that are involved in the software development life cycle, such as planning, analysis, design, implementation, testing, deployment, and maintenance. Process-oriented frameworks aim to ensure the quality of the software by following a systematic and disciplined approach to software engineering. Process-oriented frameworks can be further divided into two types: prescriptive and descriptive.

- Prescriptive frameworks provide a set of guidelines, principles, and best practices that should be followed by the software development team to achieve the desired quality goals. Prescriptive frameworks are mainly used by managers and auditors to monitor and control the quality of the software process. Examples of prescriptive frameworks are:

  - ISO/IEC 12207: Systems and software engineering - Software life cycle processes
  - ISO/IEC 15504: Information technology - Process assessment
  - ISO/IEC 33000: Information technology - Process assessment
  - ISO/IEC 29110: Systems and software engineering - Lifecycle profiles for Very Small Entities (VSEs)
  - ISO/IEC 90003: Software engineering - Guidelines for the application of ISO 9001:2008 to computer software
  - CMMI: Capability Maturity Model Integration
  - SPICE: Software Process Improvement and Capability Determination
  - PSP: Personal Software Process
  - TSP: Team Software Process
  - RUP: Rational Unified Process
  - XP: Extreme Programming
  - Scrum: Scrum framework
  - Lean: Lean software development
  - Kanban: Kanban method
  - DevOps: DevOps culture
