## Unit 3 - Software Design

Software design is the process of defining the architecture, components, interfaces, and other characteristics of a software system. Software design is a creative and iterative activity that involves various methods, tools, and principles.

Some of the topics covered in this unit are:

- Software design principles: These are general guidelines or best practices that help to achieve desirable qualities in a software system, such as modularity, cohesion, coupling, abstraction, encapsulation, etc. Some examples of software design principles are:

  - Single responsibility principle: A class or module should have only one reason to change.
  - Open-closed principle: A class or module should be open for extension but closed for modification.
  - Liskov substitution principle: A subclass should be substitutable for its superclass without breaking the program.
  - Interface segregation principle: A class or module should not depend on methods or properties that it does not use.
  - Dependency inversion principle: A class or module should depend on abstractions rather than concretions.

- Software design patterns: These are reusable solutions to common problems that occur in software design. Software design patterns provide a common vocabulary and a standard way of structuring and communicating software design. Some examples of software design patterns are:

  - Creational patterns: These patterns deal with the creation of objects, such as factory, singleton, prototype, builder, etc.
  - Structural patterns: These patterns deal with the composition and arrangement of objects, such as adapter, bridge, composite, decorator, facade, etc.
  - Behavioral patterns: These patterns deal with the interaction and communication of objects, such as observer, strategy, command, mediator, etc.

- Software design models: These are graphical or textual representations of the software design that help to visualize, communicate, and document the software design. Software design models can be classified into two types:

  - Static models: These models show the structure and relationships of the software components, such as class diagrams, object diagrams, component diagrams, etc.
  - Dynamic models: These models show the behavior and interactions of the software components, such as sequence diagrams, state diagrams, activity diagrams, etc.

- Software design methods: These are systematic approaches or processes that guide the software design activities, such as analysis, synthesis, evaluation, etc. Software design methods can be classified into two types:

  - Structured methods: These methods are based on the principles of functional decomposition and data abstraction, such as structured analysis and design, Jackson structured programming, etc.
  - Object-oriented methods: These methods are based on the principles of object orientation and encapsulation, such as object-oriented analysis and design, unified modeling language, etc.
