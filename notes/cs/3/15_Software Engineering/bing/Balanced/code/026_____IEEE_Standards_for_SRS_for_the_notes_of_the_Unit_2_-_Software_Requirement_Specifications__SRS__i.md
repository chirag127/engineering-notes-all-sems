### IEEE Standards for SRS

- A software requirements specification (SRS) is a description of a software system to be developed. It is modeled after business requirements specification (CONOPS) .
- The IEEE standard for SRS is ISO/IEC/IEEE 29148:2018, which covers the processes and information it recommends for a software requirements specification document, as well as its format .
- The IEEE standard defines the following characteristics of a good SRS :
  - Correct: The SRS should be consistent with the actual requirements of the system and free of errors.
  - Unambiguous: The SRS should be clear and precise, with no room for interpretation or confusion.
  - Complete: The SRS should cover all the requirements of the system and its environment, without any gaps or omissions.
  - Consistent: The SRS should be coherent and compatible, with no contradictions or conflicts.
  - Ranked for importance and/or stability: The SRS should indicate the relative priority and stability of each requirement, to help with planning and trade-offs.
  - Verifiable: The SRS should be testable and measurable, with clear criteria for validation and verification.
  - Modifiable: The SRS should be structured and organized, with clear traceability and change control mechanisms.
  - Traceable: The SRS should be linked to the source and rationale of each requirement, as well as to the design and implementation of the system.
- The IEEE standard provides several suggestions of how to organize functional requirements: by mode, user class, object, feature, stimulus, functional hierarchy or combinations of these criteria . There is no single organizational approach that's best; use whatever makes sense for your project.
- The IEEE standard also provides a sample outline of an SRS document, which includes the following sections :
  - Introduction: This section provides an overview of the SRS document, its purpose, scope, definitions, acronyms, abbreviations, references and overview.
  - Overall description: This section provides a general description of the software system, its perspective, functions, user characteristics, constraints, assumptions and dependencies.
  - Specific requirements: This section provides a detailed specification of the functional and non-functional requirements of the software system, such as external interfaces, performance, security, reliability, maintainability, portability, etc.
  - Appendices: This section provides any additional information that may be relevant to the SRS document, such as data models, diagrams, tables, charts, etc.
  - Index: This section provides an alphabetical listing of the terms and topics covered in the SRS document, with page numbers for easy reference.
