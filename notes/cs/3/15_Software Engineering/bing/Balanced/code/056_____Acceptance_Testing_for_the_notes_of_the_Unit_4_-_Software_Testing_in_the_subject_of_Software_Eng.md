### Acceptance Testing

Acceptance testing is a type of software testing that verifies that a system meets the requirements and specifications that guided its design and development . It is performed after system testing and before making the system available for actual use. The main purpose of acceptance testing is to determine whether the system satisfies the acceptance criteria and to enable the user, customer or other authorized entity to decide whether to accept the system.

Some points to note about acceptance testing are:

- Acceptance testing is usually done by the end users or the customers, not by the developers or testers.
- Acceptance testing can be done at various levels of software development, such as unit, integration, system or release.
- Acceptance testing can be based on various types of requirements, such as functional, non-functional, business, user or regulatory.
- Acceptance testing can be done in various ways, such as formal, informal, alpha, beta, contract or regulatory.

Some types of acceptance testing are:

- User acceptance testing (UAT): User acceptance testing is used to determine whether the product is working for the user correctly. It involves testing the system with real or simulated data and scenarios that reflect the user's expectations and needs .
- Operational acceptance testing (OAT): Operational acceptance testing is used to conduct operational readiness (pre-release) of a product, service or system as part of a quality management system. It assures that the software is ready for production and that workflows exist, including maintenance processes, security checks, user training and backup plans .
- Contract acceptance testing (CAT): Contract acceptance testing is used to verify that the system meets the contractual requirements agreed between the customer and the supplier. It involves testing the system against the acceptance criteria specified in the contract.
- Regulatory acceptance testing (RAT): Regulatory acceptance testing is used to ensure that the system complies with the relevant laws, standards and regulations. It involves testing the system against the regulatory requirements and guidelines.
