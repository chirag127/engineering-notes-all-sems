### Various Size Oriented Measures

- Size oriented measures are based on the size of the software product, such as the number of lines of code, the number of pages of documentation, or the number of function points.
- Size oriented measures are used to estimate the effort, cost, and quality of software projects, as well as to compare the productivity and efficiency of software developers and teams.
- Size oriented measures are derived by normalizing quality and/or productivity measures by considering the size of the software that has been produced .
- Some examples of size oriented measures are:

  - **Lines of Code (LOC)**: This is the most common and simple measure of software size. It counts the number of executable statements or instructions in the source code of a program. LOC can be measured in physical lines (number of lines in a file) or logical lines (number of statements or instructions). LOC can vary depending on the programming language, coding style, and level of abstraction used. LOC can be used to estimate the effort, cost, and quality of software projects, as well as to compare the productivity and efficiency of software developers and teams.
  - **Function Points (FP)**: This is a measure of software size that considers the functionality and complexity of the software product. It counts the number of inputs, outputs, inquiries, files, and interfaces that the software provides to the user or other systems. FP can be adjusted by applying a complexity factor that reflects the technical and environmental characteristics of the software project. FP can be used to estimate the effort, cost, and quality of software projects, as well as to compare the productivity and efficiency of software developers and teams.
  - **Object Points (OP)**: This is a measure of software size that considers the number and complexity of the objects in an object-oriented software product. It counts the number of classes, methods, attributes, and associations in the software design. OP can be adjusted by applying a complexity factor that reflects the inheritance, polymorphism, and encapsulation features of the software project. OP can be used to estimate the effort, cost, and quality of object-oriented software projects, as well as to compare the productivity and efficiency of software developers and teams.
  - **Feature Points (FPt)**: This is a measure of software size that considers the number and complexity of the features or requirements of the software product. It counts the number of functional, performance, security, usability, and reliability requirements that the software must satisfy. FPt can be adjusted by applying a complexity factor that reflects the technical and environmental characteristics of the software project. FPt can be used to estimate the effort, cost, and quality of software projects, as well as to compare the productivity and efficiency of software developers and teams.
