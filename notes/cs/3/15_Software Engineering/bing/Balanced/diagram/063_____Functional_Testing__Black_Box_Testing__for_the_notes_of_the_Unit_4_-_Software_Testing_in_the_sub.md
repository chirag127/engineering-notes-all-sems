### Functional Testing (Black Box Testing) for the notes of the Unit 4 - Software Testing in the subject of Software Engineering

- Functional testing is a type of testing that seeks to establish whether each application feature works as per the software requirements.
- Black box testing is a method of software testing that examines the functionality of an application without peering into its internal structures or workings.
- Black box testing can be applied to all levels of software testing: unit, integration, system and acceptance. It is sometimes referred to as specification-based testing.
- Black box testing does not require knowledge of the internal code structure of the software. It only focuses on the input and output of the software system.
- Black box testing can be divided into two types: functional testing and non-functional testing.
  - Functional testing is related to the functional requirements of a system; it is done by software testers. It checks if the software can perform a specific action as expected.
  - Non-functional testing is not related to testing of specific functionality, but non-functional requirements such as performance, scalability, usability. It checks how the software performs that action.
- Black box testing can be done in different ways, depending on the type of software and the level of testing. Some of the common techniques are:
  - Syntax-driven testing: This type of testing is applied to systems that can be syntactically represented by some language, such as compilers or languages that can be represented by a context-free grammar.
  - Boundary value analysis: This type of testing is applied to systems that have input or output ranges defined by boundaries, such as numerical or date values. It checks the behavior of the system at the boundary values and near the boundary values.
  - Equivalence partitioning: This type of testing is applied to systems that have input or output values that can be divided into equivalent classes, such as valid or invalid inputs. It checks the behavior of the system for one representative value from each class.
  - Decision table testing: This type of testing is applied to systems that have logical conditions or rules that determine the output, such as business rules or workflows. It checks the behavior of the system for different combinations of conditions and actions.
  - State transition testing: This type of testing is applied to systems that have different states and transitions between them, such as user interfaces or finite state machines. It checks the behavior of the system for different sequences of events and states.
  - Use case testing: This type of testing is applied to systems that have user scenarios or use cases that describe the interaction between the user and the system, such as web applications or mobile apps. It checks the behavior of the system for different use cases and user roles.
