### Object Oriented Design

- Object Oriented Design (OOD) is a software design approach that focuses on modeling the system as a collection of interacting objects, each with its own state and behavior.
- OOD aims to achieve high cohesion, low coupling, modularity, reusability, extensibility, and maintainability of the software system.
- OOD follows some principles and concepts, such as abstraction, encapsulation, inheritance, polymorphism, and association.
- Abstraction is the process of hiding the irrelevant details and focusing on the essential features of an object or a problem domain.
- Encapsulation is the mechanism of bundling the data and the methods that operate on the data together in a single unit, called an object. Encapsulation also protects the data from unauthorized access and modification by providing access modifiers, such as public, private, and protected.
- Inheritance is the mechanism of creating new classes from existing ones, by reusing the common attributes and methods and adding new ones. Inheritance enables code reuse and specialization of behavior.
- Polymorphism is the ability of an object to take different forms and behave differently depending on the context. Polymorphism can be achieved by using method overloading, method overriding, and dynamic binding.
- Association is the relationship between two or more objects that interact with each other. Association can be of different types, such as aggregation, composition, and dependency.
- Aggregation is a type of association where an object is composed of other objects, but the objects can exist independently. For example, a car is composed of wheels, engine, and doors, but the wheels, engine, and doors can exist without the car.
- Composition is a type of association where an object is composed of other objects, and the objects cannot exist without the whole. For example, a human is composed of heart, brain, and lungs, but the heart, brain, and lungs cannot exist without the human.
- Dependency is a type of association where an object depends on another object for some functionality or information. For example, a student depends on a teacher for learning, but the student and the teacher are not part of each other.

- OOD follows some steps, such as identifying the objects, defining the classes, establishing the relationships, and implementing the design.
- Identifying the objects is the process of finding the entities that are relevant to the problem domain and the system requirements. Objects can be identified by using techniques such as noun-verb analysis, use case analysis, and CRC cards.
- Defining the classes is the process of specifying the attributes and methods of each object, and assigning them appropriate access modifiers. Classes can be defined by using techniques such as class diagrams, data dictionaries, and pseudocode.
- Establishing the relationships is the process of determining how the objects interact with each other and what kind of association they have. Relationships can be established by using techniques such as collaboration diagrams, sequence diagrams, and state diagrams.
- Implementing the design is the process of translating the OOD into executable code, using a programming language that supports object orientation, such as Java, C++, or Python. Implementation can be done by using techniques such as coding standards, testing, and debugging.
