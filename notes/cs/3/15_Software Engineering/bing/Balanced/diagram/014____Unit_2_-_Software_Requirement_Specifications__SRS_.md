## Unit 2 - Software Requirement Specifications (SRS)

- Software Requirement Specifications (SRS) is a document that describes the features, functions, and constraints of a software system.
- SRS is also known as Software Requirements Document (SRD), Software Requirements Specification, or Functional Specification.
- SRS is a communication tool between the stakeholders and the developers of the software system.
- SRS helps to ensure that the software system meets the needs and expectations of the stakeholders and the users.
- SRS also serves as a basis for software design, testing, validation, verification, and maintenance.

### Contents of SRS

- SRS typically contains the following sections:

  - Introduction: This section provides an overview of the software system, its purpose, scope, objectives, and intended users. It also defines the acronyms, abbreviations, and terms used in the document.
  - General Description: This section describes the general features and characteristics of the software system, such as its context, functions, user characteristics, assumptions, dependencies, and constraints.
  - Specific Requirements: This section specifies the detailed requirements of the software system, such as functional requirements, non-functional requirements, performance requirements, interface requirements, data requirements, security requirements, quality attributes, and acceptance criteria.
  - Appendices: This section contains any additional information that supports the SRS, such as glossary, references, diagrams, tables, charts, etc.

### Characteristics of SRS

- SRS should have the following characteristics:

  - Correct: SRS should accurately reflect the needs and expectations of the stakeholders and the users.
  - Complete: SRS should cover all the requirements of the software system and avoid any ambiguity or inconsistency.
  - Consistent: SRS should not have any conflicting or contradictory requirements or statements.
  - Clear: SRS should use simple, precise, and unambiguous language and terminology.
  - Verifiable: SRS should state the requirements in a way that can be checked or tested.
  - Modifiable: SRS should be easy to change and update as the requirements evolve or change.
  - Traceable: SRS should be able to trace the origin and rationale of each requirement and its relationship with other requirements and components of the software system.
