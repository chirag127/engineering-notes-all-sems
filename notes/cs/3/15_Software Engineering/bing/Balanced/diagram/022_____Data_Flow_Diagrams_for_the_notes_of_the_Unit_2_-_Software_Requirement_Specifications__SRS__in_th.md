### Data Flow Diagrams

- A data flow diagram (DFD) is a graphical representation of the flow of data and information in a system or process.
- A DFD shows the sources and destinations of data, the processes that transform data, the data stores that hold data, and the data flows that connect them.
- A DFD can be used to model the logical or physical aspects of a system, or both.
- A DFD can be used for analysis or design of software systems, business processes, or any other system that involves data processing.
- A DFD can help software engineers to understand the requirements, limitations, and interactions of a system, and to communicate them to stakeholders.

#### Symbols and Notations

- A DFD uses four basic symbols to represent the components of a system:

  - A circle or oval represents a process, which is an activity that transforms data or performs some function.
  - A rectangle or square represents an external entity, which is a source or destination of data outside the system boundary.
  - An open-ended rectangle represents a data store, which is a place where data is stored or retrieved.
  - An arrow represents a data flow, which is a movement of data from one component to another.

- A DFD can also use labels, annotations, and colors to provide additional information about the components and data flows.

#### Levels and Decomposition

- A DFD can be drawn at different levels of abstraction and detail, depending on the purpose and scope of the analysis or design.
- A DFD can be decomposed into smaller and more detailed DFDs, showing the sub-processes and data flows within a process.
- A DFD can be organized into a hierarchy of levels, where each level shows a different degree of detail and complexity.
- A DFD can use a numbering scheme to indicate the level and sequence of each process and data flow.
