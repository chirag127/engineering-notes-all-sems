# Software Configuration Management Activities

Software configuration management (SCM) is a process that systematically manages, organizes, and controls the changes in the documents, codes, and other entities during the software development life cycle. The primary goal is to increase productivity with minimal mistakes.

SCM includes the following activities  :

- **Configuration identification** – Identifying configurations, configuration items and baselines. A configuration is a set of software components that work together to deliver a specific function. A configuration item is a unit of configuration that can be uniquely identified and managed. A baseline is a reference point that marks a stable state of a configuration item.
- **Configuration control** – Implementing a controlled change process. This involves reviewing, approving, and tracking the changes made to the configuration items. It also involves resolving conflicts and dependencies among the changes.
- **Configuration status accounting** – Recording and reporting all the necessary information on the status of the development process. This includes the history, current state, and future plans of the configuration items and their changes.
- **Configuration auditing** – Verifying that the configuration items and their changes are consistent with the requirements, design, and test specifications. This also involves checking the compliance with the standards, policies, and procedures of the organization.
- **Release management and delivery** – Preparing and distributing the configuration items to the customers, users, or other stakeholders. This involves packaging, labeling, installing, and testing the configuration items. It also involves managing the versions, variants, and patches of the configuration items.
