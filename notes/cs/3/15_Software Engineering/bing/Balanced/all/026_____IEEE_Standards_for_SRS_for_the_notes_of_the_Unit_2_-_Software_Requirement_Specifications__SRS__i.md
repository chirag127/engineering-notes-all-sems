# IEEE Standards for SRS

- A software requirements specification (SRS) is a description of a software system to be developed. It is modeled after business requirements specification (CONOPS) .
- The IEEE standard 830, last revised in 1998, has since been replaced by standard ISO/IEC/IEEE 29148:2011, with an update in 2018 . This standard covers the processes and information it recommends for an SRS document, as well as its format .
- The content and qualities of a good SRS are described in the standard. A good SRS should be:
  - Correct: It should state the true requirements of the system.
  - Unambiguous: It should have only one possible interpretation.
  - Complete: It should cover all the requirements of the system.
  - Consistent: It should not have any conflicting or contradictory requirements.
  - Ranked: It should prioritize the requirements based on their importance, stability, and difficulty.
  - Verifiable: It should be possible to check whether the requirements are met by the system.
  - Modifiable: It should be easy to update and maintain the SRS as the system evolves.
  - Traceable: It should be possible to trace the origin and impact of each requirement.
- The format and organization of an SRS document can vary depending on the project and the preferences of the stakeholders. However, the standard suggests some common sections that should be included in an SRS document, such as:
  - Introduction: It should provide an overview of the purpose, scope, definitions, acronyms, abbreviations, references, and overview of the SRS document.
  - Overall description: It should describe the general factors that affect the system and its requirements, such as product perspective, product functions, user characteristics, constraints, assumptions, and dependencies.
  - Specific requirements: It should state all the functional and nonfunctional requirements of the system in detail, using one or more of the following criteria: mode, user class, object, feature, stimulus, functional hierarchy, or combinations of these criteria .
  - Appendices: It should provide any additional or supplementary information that is relevant to the SRS document, such as data models, diagrams, tables, charts, etc.
  - Index: It should provide an alphabetical list of terms and topics covered in the SRS document, along with their page numbers.
