# Static Testing Strategies

Static testing is a software testing technique that involves checking the software artifacts without executing the code. Static testing can help to find defects and improve the quality of software products at an early stage of development. Static testing can be done in two ways: review and static analysis.

## Review

Review is a process of examining the software documents to find and eliminate errors or ambiguities. Review can be done by the author of the document, by peers, by managers, by customers, or by external experts. Review can be formal or informal, depending on the level of rigor and documentation required. Review can be applied to various software documents, such as requirements, design, code, test cases, user manuals, etc. Review can help to:

- Verify the consistency, completeness, and correctness of the software documents.
- Ensure that the software documents meet the standards and guidelines.
- Identify the gaps, inconsistencies, or contradictions between the software documents.
- Detect the defects and suggest the improvements or corrections.
- Enhance the communication and collaboration among the stakeholders.

## Static Analysis

Static analysis is a process of analyzing the software code or design to find and report the defects, errors, or vulnerabilities. Static analysis can be done by using tools or manually. Static analysis can be applied to various software artifacts, such as source code, object code, executable code, design models, etc. Static analysis can help to:

- Check the syntax, semantics, and logic of the software code or design.
- Detect the coding standards violations, code smells, or bad practices.
- Identify the potential bugs, errors, or security risks.
- Measure the complexity, maintainability, or testability of the software code or design.
- Suggest the optimizations or refactorings to improve the software code or design.
