# Waterfall Model

The waterfall model is a linear, sequential approach to the software development lifecycle (SDLC) that is popular in software engineering and product development. The waterfall model uses a logical progression of SDLC steps for a project, similar to the direction water flows over the edge of a cliff.

The waterfall model in software engineering divides project activities into linear sequential phases that are handed down to each other, with each phase relying on the deliverables of the preceding one to get its corresponding task done. This method is common in many areas of engineering design.

The waterfall model is the first SDLC model to be used for software development and is also known as the linear-sequential life cycle model. Winston Royce first debuted it in 1970.

The phases of the waterfall model are  :

- **Requirements analysis**: In this phase, the project team gathers and documents the functional and non-functional requirements of the software system from the stakeholders. This phase also defines the scope, objectives, and constraints of the project.
- **System design**: In this phase, the project team designs the overall architecture and structure of the software system, such as the modules, components, interfaces, data models, and algorithms. This phase also defines the hardware and software specifications, as well as the testing and deployment strategies.
- **Implementation**: In this phase, the project team codes and tests the software system according to the design specifications. This phase also involves debugging, integration, and documentation of the software system.
- **Verification**: In this phase, the project team verifies and validates the software system against the requirements and design specifications. This phase also involves conducting various types of testing, such as unit testing, integration testing, system testing, and acceptance testing.
- **Maintenance**: In this phase, the project team provides support and maintenance for the software system after it is deployed to the end-users. This phase also involves fixing bugs, enhancing features, and updating documentation.

The advantages of the waterfall model are  :

- It is simple and easy to understand and follow.
- It is well-structured and disciplined, with clear deliverables and milestones for each phase.
- It is suitable for small and simple projects with stable and well-defined requirements.
- It facilitates documentation and communication among the project team and stakeholders.

The disadvantages of the waterfall model are  :

- It is rigid and inflexible, with no room for changes or feedback during the development process.
- It is risky and costly, as errors and defects are detected late in the development process, leading to rework and delays.
- It is not suitable for large and complex projects with dynamic and uncertain requirements.
- It does not accommodate user involvement and satisfaction, as the software system is delivered only at the end of the development process.
