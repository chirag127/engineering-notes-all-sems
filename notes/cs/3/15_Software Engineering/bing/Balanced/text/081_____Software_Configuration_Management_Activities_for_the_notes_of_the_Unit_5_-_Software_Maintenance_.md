### Software Configuration Management Activities

Software configuration management (SCM) is a process that systematically manages, organizes, and controls the changes in the documents, codes, and other entities during the software development life cycle. The primary goal is to increase productivity with minimal mistakes.

The major activities of SCM are :

- **Configuration identification** – Identifying configurations, configuration items and baselines. A configuration is a set of software components that work together to deliver a specific function. A configuration item is a unit of configuration that can be uniquely identified and managed. A baseline is a reference point that marks a stable state of a configuration item.
- **Configuration control** – Implementing a controlled change process. This involves reviewing, approving, and tracking the changes made to the configuration items. It also involves managing the dependencies and conflicts among the configuration items.
- **Configuration status accounting** – Recording and reporting all the necessary information on the status of the development process. This includes the history, version, location, and ownership of the configuration items. It also includes the documentation of the changes and their impact on the configuration items.
- **Configuration auditing** – Verifying that the configuration items conform to the specifications and requirements. This involves checking the completeness, consistency, and correctness of the configuration items. It also involves validating the quality and functionality of the configuration items.
- **Release management and delivery** – Preparing and distributing the configuration items to the intended users or customers. This involves packaging, labeling, and delivering the configuration items. It also involves ensuring the compatibility and interoperability of the configuration items with the target environment.
