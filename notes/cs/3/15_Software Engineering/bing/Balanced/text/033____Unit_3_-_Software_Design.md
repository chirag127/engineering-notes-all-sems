## Unit 3 - Software Design

- Software design is the process of defining the architecture, components, interfaces, and other characteristics of a software system.
- Software design is based on the requirements and specifications of the software system, which are derived from the analysis of the problem domain and the needs of the stakeholders.
- Software design aims to achieve the following goals:
  - Functionality: the software system should provide the required functions and features for the intended users and purposes.
  - Quality: the software system should meet the desired standards of reliability, performance, usability, security, maintainability, and other quality attributes.
  - Efficiency: the software system should use the available resources (such as time, memory, disk space, network bandwidth, etc.) optimally and avoid unnecessary waste or overhead.
  - Modularity: the software system should be composed of well-defined and independent modules that can be developed, tested, and reused separately.
  - Abstraction: the software system should hide the unnecessary details and complexity of the implementation and provide a clear and simple interface for the users and other modules.
  - Cohesion: the software system should have high cohesion, which means that each module should have a single and clear responsibility and function.
  - Coupling: the software system should have low coupling, which means that the modules should have minimal dependencies and interactions with each other.
  - Reusability: the software system should allow the reuse of existing modules or components, either within the same system or across different systems, to reduce development cost and time and improve quality and consistency.
  - Scalability: the software system should be able to handle the increasing or changing demands of the users and the environment without compromising the functionality or quality.
  - Maintainability: the software system should be easy to modify, update, debug, and extend in response to the changing requirements or defects.
  - Portability: the software system should be able to run on different platforms (such as operating systems, hardware, browsers, etc.) with minimal or no changes.
  - Documentation: the software system should have clear and comprehensive documentation that describes the design, implementation, testing, and usage of the system.

- Software design can be performed at different levels of abstraction and detail, such as:
  - Architectural design: the high-level design that defines the overall structure, components, and relationships of the software system.
  - Component design: the intermediate-level design that defines the internal structure, behavior, and interfaces of each component or module of the software system.
  - Algorithm design: the low-level design that defines the logic, data structures, and operations of each algorithm or function of the software system.

- Software design can be performed using different methods and techniques, such as:
  - Top-down design: the design process that starts from the general and abstract aspects of the software system and proceeds to the specific and concrete aspects.
  - Bottom-up design: the design process that starts from the specific and concrete aspects of the software system and proceeds to the general and abstract aspects.
  - Object-oriented design: the design process that uses the concepts of objects, classes, inheritance, polymorphism, encapsulation, and abstraction to model the software system.
  - Structured design: the design process that uses the concepts of functions, data, and control structures to model the software system.
  - Modular design: the design process that divides the software system into independent and cohesive modules that can be developed and tested separately.
  - Design patterns: the reusable and proven solutions to common and recurring design problems that can be applied to different software systems.
  - UML: the Unified Modeling Language, a standard and graphical notation for describing and documenting the software design using various diagrams, such as use case diagrams, class diagrams, sequence diagrams, etc.
