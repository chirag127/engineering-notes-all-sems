### Decision Tables

- A decision table is a tabular representation of the logical rules that govern the behavior of a system or a component based on different combinations of inputs and outputs.
- A decision table consists of four quadrants: condition stubs, condition entries, action stubs, and action entries.
- Condition stubs are the names of the input variables or conditions that affect the system or component.
- Condition entries are the possible values or states of the input variables or conditions, usually represented by symbols such as Y (yes), N (no), or - (don't care).
- Action stubs are the names of the output variables or actions that the system or component performs or produces.
- Action entries are the possible values or states of the output variables or actions, usually represented by symbols such as X (execute), - (don't execute), or / (optional).
- A decision table can have one or more rules, which are the horizontal rows that define the relationship between the condition entries and the action entries.
- A decision table can be used to specify the functional requirements of a system or a component in a clear, concise, and unambiguous way.
- A decision table can also be used to verify the completeness and consistency of the requirements, by checking for missing, redundant, or conflicting rules.
- A decision table can be derived from other sources of requirements, such as use cases, user stories, or natural language specifications, by identifying the relevant input and output variables and their possible values or states.
- A decision table can be converted into other forms of specifications, such as pseudocode, flowcharts, or decision trees, by following a systematic procedure.
