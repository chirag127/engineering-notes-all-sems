### Data Flow Diagrams for the notes of the Unit 2 - Software Requirement Specifications (SRS) in the subject of Software Engineering.

Data Flow Diagrams (DFD) are graphical representations of the flow of data within a system. It is an important tool for analyzing, designing, and documenting the software requirements of a system. Here are some key points to keep in mind while studying Data Flow Diagrams:

- A Data Flow Diagram depicts how data flows through a system, from input to output. It shows the processes that transform the data, data stores, and the external entities that interact with the system.
- A DFD consists of four main components: Processes, Data Flows, Data Stores, and External Entities. Processes represent the activities that take place within the system. Data Flows represent the movement of data between processes, data stores, and external entities. Data Stores represent the places where data is stored within the system. External Entities represent the sources or destinations of data outside the system.
- A DFD can be decomposed into a series of more detailed DFDs, each representing a smaller part of the overall system. This technique is called functional decomposition.
- There are two types of Data Flow Diagrams: Logical and Physical. Logical DFDs describe the functional requirements of the system, while Physical DFDs describe the implementation of the system.
- DFDs can be used to identify potential errors, redundancies, and inefficiencies within a system. They can also be used to communicate system requirements to developers and stakeholders.

In conclusion, Data Flow Diagrams are an essential tool for analyzing and documenting software requirements. By understanding the components of a DFD and how to decompose it into smaller parts, you can effectively communicate the requirements of a system to stakeholders and developers.
