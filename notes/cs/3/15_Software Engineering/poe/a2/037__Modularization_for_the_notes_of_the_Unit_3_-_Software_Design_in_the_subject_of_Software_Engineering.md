### Modularization for the notes of the Unit 3 - Software Design in the subject of Software Engineering

1. What is Modularization?
- Dividing the whole system into independent modules that can be designed and developed separately.
- Each module has a specific functionality which interacts with other modules through interfaces.
- Helps in managing complexity, applying divide and conquer, isolation, and reuse.

2. Why Modularization?
- Managing complexity: Breaking down the whole system into smaller modules makes the system easy to understand, develop and test.
- Isolation: Modules are isolated from each other, so changes in one module do not affect other modules.
- Reuse: Modules can be reused in other systems, which increases productivity and reduces cost.
- Parallel development: Multiple modules can be designed and developed in parallel, which saves time.

3. Characteristics of Good Modules
- High cohesion: Modules should have a specific focused functionality.
- Loose coupling: Modules should be loosely coupled with other modules.
- Minimal interaction: Interaction between modules should be minimal.
- Information hiding: Modules should hide internal implementation details from other modules.
- Understandability: Modules should be easy to understand, develop and maintain.

4. Approaches to Modularization
- Functional decomposition: Dividing the system based on major functions.
- Sequential decomposition: Dividing based on execution sequence.
- Physical decomposition: Dividing based on physical components.
- Object-oriented decomposition: Dividing based on objects and classes.
- Aspect-oriented decomposition: Dividing based on aspects like logging, security, etc.
