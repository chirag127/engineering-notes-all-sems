### Acceptance Testing

1. Acceptance Testing is a type of testing performed to determine whether or not the software system has met the requirement specifications. It is done to accept or reject the system by the customer.

2. Acceptance Testing is usually done by the client or the end user to validate the functionalities and the non-functional requirements as specified in the Software Requirements Specification (SRS) document.

3. The different types of Acceptance Testing are:

- User Acceptance Testing (UAT): It is performed by the end user or the client to test the software system.
- Operational Acceptance Testing (OAT): It is performed by the system administrators or infrastructure team to test the operational readiness of the software system.
- Contract Acceptance Testing: It is performed by the client to check whether the system meets the acceptance criteria specified in the contract or agreement between the client and the software development company.

4. The goals of Acceptance Testing are:

- To check if the software system meets the requirements specified by the customer.
- To ensure that the system functions as intended.
- To confirm that the system is usable and manageable.
- To verify that the output of the system for selected input conditions matches the expected output.

5. The inputs for Acceptance Testing are:

- Software Requirements Specification (SRS) document
- List of test scenarios and test cases
- Test Environment

6. The outputs of Acceptance Testing are:

- Acceptance Test Report
- Defect Report
- Approval/Rejection of the software system
