
## Unit 2 - Software Requirement Specifications (SRS)

1. Software Requirement Specifications (SRS) is a document that describes the features, functions, and behavior of a system or software application.

2. It is created by the software development team, which includes developers, business analysts, and other stakeholders.

3. The purpose of the SRS is to ensure that all stakeholders have a clear understanding of the software requirements and what the software will do.

4. The SRS should include a description of the system's functionality, user interface, data requirements, and performance requirements.

5. The SRS should also include a list of any assumptions made about the system and any constraints that must be followed.

6. The SRS should be reviewed and approved by all stakeholders before the software development process begins.

7. Once the SRS is approved, it serves as the basis for the software design and development process.
