### Reusability for the Notes of the Unit 3 - Object Oriented Analysis in the Subject of Object Oriented System Design

In Unit 3 of Object Oriented Analysis, we will learn about the importance of reusability in Object Oriented System Design. Here are some key points to keep in mind:

- Reusability is the ability to use existing code or design elements in new systems, without having to start from scratch.
- Reusability can save time, effort, and money in software development.
- In Object Oriented System Design, reusability is achieved through the use of classes, objects, and inheritance.
- By creating reusable classes and objects, we can avoid duplicating code and reduce the risk of errors.
- Inheritance allows us to create new classes that are based on existing ones, inheriting their properties and methods.
- We can also use interfaces to define common behavior that can be shared among different classes.
- Design patterns are another way to achieve reusability in Object Oriented System Design. They provide proven solutions to common design problems, making it easier to create reusable and maintainable code.
- Some examples of design patterns include the Singleton pattern, the Factory pattern, and the Observer pattern.
- When designing for reusability, it's important to keep in mind the principles of cohesion and coupling. Cohesion refers to the degree to which the elements of a module or class are related to each other, while coupling refers to the degree to which one module or class depends on another.
- High cohesion and low coupling are desirable for achieving reusability, as they make it easier to change and reuse code without affecting other parts of the system.

By understanding the importance of reusability in Object Oriented System Design and applying these principles in our design and development process, we can create more efficient, maintainable, and scalable software systems.
