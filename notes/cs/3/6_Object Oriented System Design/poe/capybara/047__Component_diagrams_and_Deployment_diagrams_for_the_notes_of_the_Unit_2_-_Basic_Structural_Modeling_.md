### Component diagrams and Deployment diagrams

In the Unit 2 of Object Oriented System Design, we will be discussing the basic structural modeling of the system. Two important diagrams that we will be focusing on are Component diagrams and Deployment diagrams.

#### Component diagrams

A Component diagram is a type of structural diagram that shows how the system is divided into components and how these components are related to each other. The components can be classes, interfaces, packages, or any other modular part of the system.

The main purpose of the Component diagram is to visualize the system's architecture and to help in designing and implementing the system. It also helps in understanding the relationships between different components and their dependencies.

In a Component diagram, the components are represented as rectangles with their name and stereotype. The relationships between the components are represented using connectors such as dependency, association, and realization.

#### Deployment diagrams

A Deployment diagram is a type of structural diagram that shows the physical deployment of the system on hardware. It illustrates how software components are deployed on hardware nodes and how these nodes are connected to each other.

The main purpose of the Deployment diagram is to visualize the physical deployment of the system and to help in planning and managing the deployment process.

In a Deployment diagram, the nodes represent the hardware elements such as servers, routers, and firewalls. The software components are represented as rectangles with their name and stereotype. The connections between the nodes and components are represented using connectors such as deployment, association, and communication.

In conclusion, understanding Component diagrams and Deployment diagrams is essential for designing, implementing, and deploying a system. These diagrams help in visualizing the system's architecture and physical deployment, and they assist in planning and managing the deployment process.
