### Relationships

In Object Oriented System Design, relationships are used to define the way in which objects interact with each other. There are different types of relationships, each of which serves a specific purpose. Here are some key points to keep in mind:

- **Association:** Association is a relationship in which two or more objects are linked together. This relationship is often used to represent the fact that one object uses another object, or that one object is related to another object in some way. Association can be either uni-directional or bi-directional.

- **Aggregation:** Aggregation is a type of association in which one object represents a collection of other objects. The aggregated objects can exist independently of the aggregate object. Aggregation is often used to represent the relationship between a whole and its parts.

- **Composition:** Composition is a type of aggregation in which the aggregated objects only exist as part of the aggregate object. If the aggregate object is destroyed, the aggregated objects are also destroyed. Composition is often used to represent the relationship between a container and its contents.

- **Inheritance:** Inheritance is a relationship in which one class derives properties and behavior from another class. The class that derives properties and behavior is called the subclass, and the class from which properties and behavior are derived is called the superclass.

- **Dependency:** Dependency is a relationship in which one object depends on another object to perform some function. The dependent object does not contain a reference to the object it depends on, but rather it uses the object indirectly.

Understanding the different types of relationships is essential for creating effective object-oriented designs. By using relationships effectively, you can create objects that are modular, reusable, and easy to maintain.
