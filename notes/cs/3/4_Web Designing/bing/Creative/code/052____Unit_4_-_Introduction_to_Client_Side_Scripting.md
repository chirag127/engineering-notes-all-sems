## Unit 4 - Introduction to Client Side Scripting

- Client side scripting is a technique of writing code that runs on the web browser, rather than on the web server.
- Client side scripting can enhance the interactivity, functionality, and usability of web pages by allowing the user to interact with the web page without reloading it or sending requests to the server.
- Client side scripting can also reduce the load on the web server and the network bandwidth by performing some tasks on the browser, such as validating user input, manipulating the document object model (DOM), and storing data locally.
- Some examples of client side scripting languages are JavaScript, VBScript, JScript, TypeScript, and Dart.
- Client side scripting languages are usually embedded in HTML documents using the `<script>` tag or linked to external files using the `src` attribute.
- Client side scripting languages can access and manipulate the DOM, which is a tree-like representation of the HTML elements and attributes of a web page.
- Client side scripting languages can also use various APIs (application programming interfaces) to access and use the features and functionalities of the web browser, such as the window object, the navigator object, the location object, the history object, the document object, the XMLHttpRequest object, the localStorage object, the sessionStorage object, the cookie object, the canvas object, the geolocation object, the web worker object, and the web socket object.
- Client side scripting languages can also use various libraries and frameworks to simplify and enhance the development of web applications, such as jQuery, React, Angular, Vue, Bootstrap, and D3.
- Client side scripting languages have some limitations and challenges, such as browser compatibility, security, performance, and debugging.
- Browser compatibility refers to the issue that different web browsers may support different versions and features of client side scripting languages, which may cause inconsistencies and errors in the web page behavior and appearance.
- Security refers to the issue that client side scripting code is exposed to the user and can be modified or exploited by malicious users or hackers, which may compromise the confidentiality, integrity, and availability of the web page and the web server.
- Performance refers to the issue that client side scripting code may consume a lot of memory and CPU resources on the browser, which may affect the responsiveness and speed of the web page and the web application.
- Debugging refers to the issue that client side scripting code may be difficult to test and debug, especially when it involves asynchronous operations, callbacks, promises, and events.
