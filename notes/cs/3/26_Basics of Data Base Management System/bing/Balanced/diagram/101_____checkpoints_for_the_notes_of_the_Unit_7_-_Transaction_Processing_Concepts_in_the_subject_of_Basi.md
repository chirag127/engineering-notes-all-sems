### Checkpoints for the notes of the Unit 7 - Transaction Processing Concepts in the subject of Basics of Data Base Management System

- A transaction is a logical unit of database processing that includes one or more database access operations such as insertion, deletion, modification, and retrieval.
- A transaction is atomic, consistent, isolated, and durable (ACID) in nature, meaning that it either executes completely or not at all, preserves the consistency of the database, does not interfere with other transactions, and survives any system failures .
- Transaction processing systems are systems with large databases and hundreds of concurrent users executing database transactions.
- Online transaction processing (OLTP) is the management of transactional data using computer systems that record business interactions as they occur in the day-to-day operation of the organization, and support querying of this data to make inferences.
- A transaction state can be active, partially committed, committed, failed, or aborted, depending on the execution status of the operations in the transaction.
- A transaction manager is a component of the database system that controls the execution of transactions and ensures their ACID properties.
- A transaction can be implemented using SQL statements, embedded within an application program or specified interactively via a high-level language such as SQL.
- A transaction can be classified into read-only transactions, update transactions, distributed transactions, and long-duration transactions, depending on the nature and scope of the operations in the transaction.
- A transaction can be affected by concurrency control, recovery management, and security enforcement mechanisms in the database system .
- A transaction can be evaluated by its performance, reliability, availability, and scalability in the transaction processing system.
