### Unit 3: Database Design & Normalization

In this unit, we will learn about database design and normalization. Database design refers to the process of creating a database schema, which is a blueprint for organizing data into tables, fields, and relationships. Normalization is a technique used to eliminate data redundancy and ensure data integrity.

Here are some key concepts to understand:

- **Entities**: An entity is a person, place, thing or event that we want to store information about in the database. For example, in a university database, entities could include students, courses, and professors.

- **Attributes**: Attributes are characteristics of an entity. For example, the attributes of a student entity could include name, ID number, and major.

- **Relationships**: Relationships describe how entities are related to each other. For example, a course entity and a student entity could be related through a registration relationship.

- **Keys**: A key is a unique identifier for an entity. For example, a student's ID number could serve as a key for the student entity.

- **Normalization**: Normalization is the process of organizing data in a database to eliminate redundancy and ensure data integrity. This is done by dividing larger tables into smaller ones and establishing relationships between them.

There are several levels of normalization, known as normal forms. Each level builds on the previous one, and the goal is to achieve the highest level of normalization possible. The most common levels are:

- **First Normal Form (1NF)**: Each table cell should contain a single value, and each column should have a unique name.

- **Second Normal Form (2NF)**: All non-key attributes should be dependent on the primary key.

- **Third Normal Form (3NF)**: All non-key attributes should be independent of each other.

By following these principles of database design and normalization, we can create efficient, effective, and reliable databases that can be easily maintained and updated.
