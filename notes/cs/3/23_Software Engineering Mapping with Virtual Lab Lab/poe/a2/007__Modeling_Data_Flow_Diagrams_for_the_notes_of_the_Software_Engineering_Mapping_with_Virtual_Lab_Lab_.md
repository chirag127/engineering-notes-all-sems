## Modeling Data Flow Diagrams

1. Data Flow Diagrams (DFDs) are graphical representations of the "flow" of data through an information system. They can be used to model processes or systems.
2. DFDs consist of four main elements:
 - External entities: entities outside the system that interact with it. Represented as rectangles.
 - Data flows: the movement of data between different elements of the system. Represented as arrows.
 - Processes: that transform incoming data flows into outgoing data flows. Represented as rounded rectangles.
 - Data stores: the holding of data within the system. Represented as open-ended rectangles.
3. There are three levels of DFDs:
 - Context level: shows the overall system and how it interacts with external entities.
 - Level 1 DFD: breaks down the main processes of the context level into more detail.
 - Level 2 DFD (or lower levels): break down the level 1 processes into further detail.
4. Guidelines for drawing DFDs:
 - Keep them simple and avoid clutter. Only include major flows and processes.
 - Clearly label all elements and flows.
 - Arrows should have a clear start and end point.
 - The inputs and outputs of processes should be clearly shown.
 - Data flows should not merge or split.
5. DFDs are useful for:
 - Gaining an overview of a system and its major components/flows.
 - Communicating with others about a system.
 - Identifying processes/data flows to focus on.
 - Determining the scope of a system.
