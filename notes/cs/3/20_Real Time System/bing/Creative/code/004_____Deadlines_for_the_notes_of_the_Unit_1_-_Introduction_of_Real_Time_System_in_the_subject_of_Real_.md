### Deadlines for the notes of the Unit 1 - Introduction of Real Time System

- A deadline is a time constraint that specifies the latest time by which a task or an event must be completed or occur.
- Deadlines are important for real time systems because they ensure the timeliness and predictability of the system's behavior and performance.
- There are different types of deadlines for real time systems, such as:
  - Hard deadline: A hard deadline is a deadline that must be met at all costs, otherwise the system will fail or cause severe consequences. For example, a hard deadline for an airbag deployment system is the time before the collision occurs.
  - Soft deadline: A soft deadline is a deadline that can be missed occasionally or with some tolerable degradation of the system's quality of service. For example, a soft deadline for a video streaming system is the time before the buffer underflows or overflows.
  - Firm deadline: A firm deadline is a deadline that can be missed, but there is no benefit or value in completing the task or event after the deadline. For example, a firm deadline for a lottery ticket system is the time before the draw takes place.
- Deadlines can also be classified as:
  - Static deadline: A static deadline is a deadline that is fixed and known in advance, and does not change during the system's execution. For example, a static deadline for a periodic task is the period of the task.
  - Dynamic deadline: A dynamic deadline is a deadline that is variable and depends on the system's state, input, or environment, and may change during the system's execution. For example, a dynamic deadline for a sporadic task is the time between the arrival of the task and its completion.
- Deadlines can be specified as:
  - Absolute deadline: An absolute deadline is a deadline that is expressed as a fixed point in time, relative to a global clock or a reference point. For example, an absolute deadline for a task can be 10:00 AM on March 15, 2023.
  - Relative deadline: A relative deadline is a deadline that is expressed as an offset or a duration from the start or the end of a task or an event. For example, a relative deadline for a task can be 5 seconds after its arrival or 10 seconds before its completion.
