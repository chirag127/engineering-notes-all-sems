- Enterprise Java Beans (EJB) are server-side components that encapsulate the business logic of an application. They run inside a container that provides services such as security, transaction management, concurrency control, and dependency injection.
- EJBs can be divided into two types: session beans and message-driven beans. Session beans are stateful or stateless components that handle requests from clients. Message-driven beans are stateless components that process messages from a message queue or topic.
- EJBs follow a component-based architecture that separates the interface, implementation, and deployment of the beans. The interface defines the methods that the bean exposes to the clients. The implementation contains the business logic of the bean. The deployment descriptor specifies the configuration and properties of the bean.
- EJBs can be accessed by local or remote clients using the Java Naming and Directory Interface (JNDI). JNDI is a standard API that allows clients to look up and invoke EJBs using logical names. The container is responsible for registering the EJBs in the JNDI namespace and providing the references to the clients.
- EJBs can use annotations or XML files to specify the metadata of the beans. Annotations are Java code elements that provide information about the bean to the container and the tools. XML files are external files that contain the same information as annotations. Annotations are preferred over XML files as they are simpler and less error-prone.
- EJBs can use dependency injection to obtain references to other EJBs or resources. Dependency injection is a technique that allows the container to inject the required dependencies into the bean without the need for explicit lookup or creation. Dependency injection can be done using annotations or XML files.
- EJBs can use interceptors to add cross-cutting functionality to the beans. Interceptors are classes or methods that intercept the invocation of the bean methods and execute some logic before or after the invocation. Interceptors can be used for logging, auditing, security, caching, or validation purposes. Interceptors can be defined using annotations or XML files.
