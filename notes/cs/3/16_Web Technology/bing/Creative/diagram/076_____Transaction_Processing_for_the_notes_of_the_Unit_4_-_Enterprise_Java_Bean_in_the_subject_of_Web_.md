### Transaction Processing for the notes of the Unit 4 - Enterprise Java Bean in the subject of Web Technology

- Transaction processing is the execution of a series of operations on a set of data sources, such as databases, message queues, or files, in a way that ensures atomicity, consistency, isolation, and durability (ACID) properties.
- Atomicity means that either all the operations in a transaction are completed successfully, or none of them are. Consistency means that the data sources are left in a valid state after the transaction. Isolation means that concurrent transactions do not interfere with each other. Durability means that the effects of a transaction are permanent and not lost due to a system failure.
- Enterprise JavaBeans (EJB) is a technology that supports distributed transactional component-based applications written in Java. EJB components, also called enterprise beans, are managed by an EJB container that provides services such as transaction management, security, concurrency control, and dependency injection.
- There are two types of enterprise beans: session beans and message-driven beans. Session beans are used to implement business logic and can be stateless, stateful, or singleton. Message-driven beans are used to process messages asynchronously from a message queue or topic.
- There are two ways to handle transactions with enterprise beans: container-managed transactions and bean-managed transactions.
- In container-managed transactions, the EJB container sets the boundaries of the transactions and controls when they are committed or rolled back. The developer can specify the transaction attributes for each method of the enterprise bean using annotations or deployment descriptors. The transaction attributes define the behavior of the method when it is invoked within or outside a transaction context. The possible transaction attributes are:
  - REQUIRED: The method must run within a transaction. If there is an existing transaction, the method joins it. If there is no transaction, a new one is started.
  - REQUIRES_NEW: The method must run within a new transaction. If there is an existing transaction, it is suspended and resumed after the method completes.
  - SUPPORTS: The method can run within or outside a transaction. If there is an existing transaction, the method joins it. If there is no transaction, the method runs without one.
  - NOT_SUPPORTED: The method must run outside a transaction. If there is an existing transaction, it is suspended and resumed after the method completes.
  - MANDATORY: The method must run within an existing transaction. If there is no transaction, an exception is thrown.
  - NEVER: The method must run outside a transaction. If there is an existing transaction, an exception is thrown.
- In bean-managed transactions, the enterprise bean is responsible for marking the transaction boundaries using the Java Transaction API (JTA). The developer can obtain a reference to the UserTransaction interface from the EJB context and use its methods to begin, commit, or rollback a transaction. Bean-managed transactions can be used with session or message-driven beans, but not with entity beans. There are two types of bean-managed transactions:
  - JDBC type: The enterprise bean uses the commit and rollback methods of the Connection interface to delimit JDBC transactions. This type of transaction is limited to a single data source and does not support distributed transactions.
  - JTA type: The enterprise bean uses the UserTransaction interface to delimit JTA transactions. This type of transaction can span multiple data sources and supports distributed transactions.
