# Joining for the notes of the Unit 4 - Enterprise Java Bean in the subject of Web Technology

- Enterprise Java Beans (EJB) are server-side components that encapsulate the business logic of an application. They run inside a container that provides services such as security, transaction management, concurrency control, and dependency injection.
- EJBs can be divided into two types: session beans and message-driven beans. Session beans are stateful or stateless components that handle requests from clients. Message-driven beans are components that receive and process messages asynchronously from a message queue or topic.
- EJBs follow a component-based architecture that allows for reusability, scalability, and portability. EJBs can be deployed on any Java EE compliant application server, such as GlassFish, JBoss, or WebLogic.
- EJBs can interact with other components using various protocols, such as Remote Method Invocation (RMI), Java Naming and Directory Interface (JNDI), Java Message Service (JMS), Java Database Connectivity (JDBC), and Java Persistence API (JPA).
- EJBs can be accessed by clients using different interfaces, such as local, remote, web service, or no-interface. Local interfaces are used for communication within the same application server. Remote interfaces are used for communication across different application servers. Web service interfaces are used for communication using SOAP or REST protocols. No-interface views are used for communication without defining an interface.
- EJBs can be annotated with various annotations to specify their type, name, interface, transaction attributes, security roles, and other properties. For example, @Stateless, @Stateful, @MessageDriven, @EJB, @Resource, @TransactionAttribute, @RolesAllowed, etc.
