### Congestion control algorithms

Congestion control algorithms are methods to regulate the flow of data packets in a network and prevent congestion, which can degrade the performance and reliability of the network. Congestion occurs when the demand for network resources exceeds the available capacity. Congestion control algorithms can be implemented at different layers of the network stack, such as the transport layer or the network layer.

Some of the common congestion control algorithms are:

- **Leaky bucket**: This algorithm simulates a leaky bucket that can hold a fixed number of tokens. Tokens are generated at a constant rate and added to the bucket. A packet can be sent only if there is a token available in the bucket. If the bucket is full, any incoming token is discarded. This algorithm limits the burstiness of the traffic and enforces a constant output rate .
- **Token bucket**: This algorithm is similar to the leaky bucket, but it allows some burstiness in the traffic. The bucket can hold a maximum number of tokens, and tokens are generated at a constant rate. A packet can be sent if there is a token available in the bucket, and the token is removed. The bucket can accumulate tokens up to its capacity, allowing a burst of packets to be sent. If the bucket is empty, no packet can be sent .
- **Additive increase multiplicative decrease (AIMD)**: This algorithm is used by TCP to adjust the size of the congestion window, which is the number of packets that can be sent without waiting for an acknowledgment. The algorithm increases the window size by one packet for every round trip time (RTT) if there is no packet loss, and decreases the window size by half if there is a packet loss. This algorithm tries to probe the available bandwidth and back off when congestion occurs .
- **Slow start**: This algorithm is also used by TCP to initialize the congestion window. The algorithm starts with a small window size and doubles it for every RTT until it reaches a threshold value or a packet loss occurs. This algorithm allows TCP to quickly ramp up the transmission rate at the beginning of a connection or after a packet loss .
- **Congestion avoidance**: This algorithm is used by TCP to avoid entering the slow start phase too often. The algorithm increases the window size by one packet for every RTT if the window size is below the threshold value, and increases the window size by one packet for every window size packets if the window size is above the threshold value. This algorithm tries to maintain a linear growth of the window size and avoid congestion .
- **Fast retransmit and fast recovery**: These algorithms are used by TCP to recover from a packet loss without reducing the window size too much. The fast retransmit algorithm detects a packet loss by receiving three duplicate acknowledgments for the same packet, and retransmits the lost packet without waiting for a timeout. The fast recovery algorithm maintains the window size at half of the value before the packet loss, and increases it by one packet for every duplicate acknowledgment received. These algorithms try to avoid the slow start phase and resume the normal transmission rate quickly .
