# Domain Name System

- The Domain Name System (DNS) is a method for mapping alphabetic names to numeric IP addresses on the Internet, similar to how a phone book maps a person's name to a phone number.
- DNS is a hierarchical and decentralized naming system that allows computers, servers, services, resources, network devices and components to be identified and located on large networks such as the public Internet .
- A network domain is an administrative grouping of multiple private computer networks or local hosts within the same infrastructure. Domains can be identified using a domain name; domains which need to be accessible from the public Internet can be assigned a globally unique name within the Domain Name System (DNS).
- A domain name consists of one or more labels, each separated by a dot. The rightmost label is the top-level domain (TLD), such as .com, .org, .net, etc. The second-level domain (SLD) is the label to the left of the TLD, such as google, amazon, wikipedia, etc. The third-level domain (TLD) is the label to the left of the SLD, such as www, mail, docs, etc. The labels can be up to 63 characters long and can contain letters, digits, hyphens, and underscores.
- Domain names can be internationalized using the Internationalized Domain Name (IDN) system, which allows the use of non-ASCII characters such as accented letters, symbols, or scripts. IDNs are encoded using the Punycode algorithm, which converts them to ASCII labels that start with xn--. For example, the IDN bücher.de is encoded as xn--bcher-kva.de.
- Name servers are the servers that store and provide the domain name to IP address mappings. They are organized in a hierarchical structure, with the root name servers at the top, followed by the TLD name servers, the SLD name servers, and so on. Each name server is authoritative for a certain zone, which is a portion of the domain name space that it is responsible for.
- The process of finding the IP address of a domain name is called address resolution. It involves sending queries to different name servers until the authoritative name server for the domain name is reached. The queries can be sent either iteratively or recursively. In iterative queries, the client contacts each name server in the hierarchy and receives a referral to the next name server. In recursive queries, the client contacts a single name server, which contacts other name servers on behalf of the client and returns the final answer.
- A recursive and caching name server is a name server that performs recursive queries and caches the results for future use. It can reduce the latency and network traffic of address resolution by avoiding repeated queries to the same name servers. However, it also introduces the problem of cache consistency, which means that the cached records may become outdated or invalid over time.
- DNS resolvers are the clients that initiate the address resolution process. They are usually part of the operating system or the web browser of the user. They send queries to the name servers and receive the responses. They may also cache the results locally for faster access.
- Circular dependencies and glue records are special cases that occur when the name servers for a domain name are themselves part of the same domain name. For example, if the name servers for example.com are ns1.example.com and ns2.example.com, then there is a circular dependency between the domain name and the name servers. To resolve this, the parent name server (in this case, the .com name server) provides glue records, which are the IP addresses of the name servers, along with the referral to the child name server.
- Record caching is the process of storing the results of address resolution in a local or remote cache for a certain period of time. This can improve the performance and efficiency of DNS by reducing the number of queries and the network load. However, it also introduces the problem of cache consistency, which means that the cached records may become outdated or invalid over time. To deal with this, each record has a Time to Live (TTL) value, which specifies how long the record can be cached before it expires and needs to be refreshed.
