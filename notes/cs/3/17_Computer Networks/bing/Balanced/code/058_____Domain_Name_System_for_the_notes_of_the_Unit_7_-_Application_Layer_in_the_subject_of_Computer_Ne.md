### Domain Name System

- The Domain Name System (DNS) is a method for mapping alphabetic names to numeric IP addresses on the Internet, similar to how a phone book maps a person's name to a phone number.
- DNS is a hierarchical and decentralized naming system that allows computers, servers, services, resources, network devices and components to be identified and located on large networks such as the public Internet .
- A network domain is an administrative grouping of multiple private computer networks or local hosts within the same infrastructure. Domains can be identified using a domain name; domains which need to be accessible from the public Internet can be assigned a globally unique name within the Domain Name System (DNS).
- A domain name consists of one or more labels, each separated by a dot. The rightmost label is the top-level domain (TLD), such as .com, .org, .net, etc. The second-level domain (SLD) is the label to the left of the TLD, such as google, amazon, wikipedia, etc. The third-level domain (3LD) is the label to the left of the SLD, such as www, mail, blog, etc. The labels can be up to 63 characters long and can contain letters, digits, hyphens, and underscores.
- Domain names can be internationalized using the Internationalized Domain Name (IDN) system, which allows the use of non-ASCII characters such as accented letters, symbols, or scripts. IDNs are encoded using the Punycode algorithm, which converts them to ASCII labels that start with xn--. For example, the IDN for café.com is xn--caf-dma.com.
- Name servers are the servers that store and provide the domain name to IP address mappings. They are organized in a tree-like structure, with the root name servers at the top, followed by the TLD name servers, the SLD name servers, and so on. Each name server is authoritative for a certain zone, which is a portion of the domain name space that it is responsible for.
- The process of finding the IP address of a domain name is called address resolution. It involves sending queries to different name servers until the desired answer is obtained. There are two types of queries: iterative and recursive. In an iterative query, the client asks a name server for the IP address of a domain name, and the name server either returns the answer or a referral to another name server that is closer to the answer. In a recursive query, the client asks a name server for the IP address of a domain name, and the name server either returns the answer or queries another name server on behalf of the client until the answer is obtained.
- A recursive and caching name server is a type of name server that performs recursive queries for the clients and caches the results for future use. This reduces the number of queries sent to the authoritative name servers and improves the performance and efficiency of the DNS system.
- A DNS resolver is a software component that runs on the client side and initiates the queries to the name servers. It can be configured to use a specific recursive and caching name server or to perform iterative queries by itself. The resolver also handles the conversion of IDNs to Punycode and vice versa.
- A circular dependency occurs when a name server needs to query another name server whose domain name it does not know the IP address of. For example, if the name server for example.com needs to query the name server for foo.com, but the name server for foo.com is ns.foo.com, then there is a circular dependency. To resolve this, the name server for example.com can use a glue record, which is an additional record that provides the IP address of ns.foo.com along with the referral to foo.com.
- Record caching is the mechanism by which name servers and resolvers store the results of previous queries for a certain period of time, called the time to live (TTL). This reduces the number of queries sent to the authoritative name servers and improves the performance and efficiency of the DNS system. However, it also introduces the possibility of stale or outdated records, which can cause errors or inconsistencies.
