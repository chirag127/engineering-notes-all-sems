### Congestion control algorithms

Congestion control algorithms are methods to regulate the flow of data packets in a network and prevent congestion, which can degrade the performance and reliability of the network. Congestion occurs when the demand for network resources exceeds the available capacity. Congestion control algorithms can be implemented at different layers of the network stack, but most commonly at the transport layer, such as TCP.

Some of the common congestion control algorithms are:

- **Leaky bucket**: This algorithm simulates a leaky bucket that can hold a fixed number of tokens. Tokens are generated at a constant rate and added to the bucket. A packet can be sent only if there is a token available in the bucket. If the bucket is full, any incoming token is discarded. This algorithm limits the output rate to a constant value and smooths out bursty traffic .
- **Token bucket**: This algorithm is similar to the leaky bucket, but it allows some burstiness in the output rate. The bucket can hold a maximum number of tokens, but tokens are not discarded when the bucket is full. Instead, the bucket can accumulate tokens up to its capacity, and then use them to send packets at a higher rate than the token generation rate. This algorithm allows the sender to use the available bandwidth efficiently and adapt to the network conditions .
- **Additive increase multiplicative decrease (AIMD)**: This algorithm is used by TCP to adjust the size of the congestion window, which is the number of packets that can be sent without receiving an acknowledgment. The algorithm increases the congestion window by one packet for every round trip time (RTT) until a packet loss occurs, which indicates congestion. Then, the algorithm reduces the congestion window by half. This algorithm probes the network for the available bandwidth and reacts to congestion by backing off exponentially .
- **Slow start**: This algorithm is also used by TCP to initialize the congestion window. The algorithm starts with a small congestion window, usually one or two packets, and doubles it for every RTT until a threshold is reached or a packet loss occurs. The threshold is usually set to half of the congestion window size before the packet loss. This algorithm allows TCP to quickly ramp up the transmission rate and discover the network capacity .
- **Congestion avoidance**: This algorithm is used by TCP after the slow start phase or after a packet loss. The algorithm increases the congestion window by one packet per RTT, but not by doubling it. This algorithm avoids congestion by increasing the transmission rate more slowly and linearly .
- **Fast retransmit and fast recovery**: These algorithms are used by TCP to handle packet losses. Fast retransmit detects packet losses by receiving three duplicate acknowledgments for the same packet, and retransmits the lost packet without waiting for a timeout. Fast recovery reduces the congestion window by half, but not to one packet, and continues the congestion avoidance phase. These algorithms improve the performance of TCP by reducing the number of timeouts and retransmissions .
