### Learning bridge and spanning tree algorithms for the notes of the Unit 4 - Medium Access Control and Local Area Networks in the subject of Computer Networks

- A bridge is a device that connects two or more LAN segments and forwards frames between them based on the MAC addresses of the destination and source hosts.
- A bridge operates at the data link layer of the OSI model and can filter, forward, or flood frames depending on the destination MAC address and the bridge's forwarding table.
- A bridge can also learn the MAC addresses of the hosts connected to its ports by examining the source MAC address of the incoming frames and updating its forwarding table accordingly.
- A bridge can create a loop-free logical topology for a network of LAN segments by running a spanning tree algorithm  .
- A spanning tree is a subset of the network that connects all the LAN segments without forming any loops.
- A spanning tree algorithm is a distributed algorithm that runs on each bridge and uses bridge protocol data units (BPDUs) to exchange information with other bridges and agree on a spanning tree for the network  .
- A BPDU is a data message that contains the bridge's identifier, the identifier of the root bridge (the bridge with the lowest identifier in the network), the cost of the path from the bridge to the root bridge, and the port identifier of the port that sent the BPDU .
- The spanning tree algorithm consists of the following steps  :
  - Each bridge assumes that it is the root bridge and broadcasts a BPDU with its own identifier as the root bridge identifier and zero as the path cost out of all its ports.
  - When a bridge receives a BPDU, it compares the root bridge identifier in the BPDU with its own root bridge identifier. If the BPDU has a lower root bridge identifier, the bridge updates its root bridge identifier, its root port (the port that received the BPDU), and its path cost to the root bridge. It then broadcasts a new BPDU with the updated information out of all its ports except the root port. If the BPDU has the same root bridge identifier, the bridge compares the path cost to the root bridge. If the BPDU has a lower path cost, the bridge updates its root port and its path cost and broadcasts a new BPDU. If the BPDU has the same path cost, the bridge compares the bridge identifier of the sender. If the BPDU has a lower bridge identifier, the bridge updates its root port and broadcasts a new BPDU. If the BPDU has a higher bridge identifier, the bridge discards it.
  - The process repeats until all the bridges agree on the same root bridge, the same path cost to the root bridge, and the same root port for each bridge. The root bridge is the only bridge that does not have a root port and has a path cost of zero.
  - Each bridge then determines its designated ports, which are the ports that provide the lowest cost path from the LAN segment to the root bridge. A designated port is the only port that can forward frames from or to the LAN segment. All the other ports are blocked and do not forward any frames. A blocked port can still receive BPDUs and participate in the spanning tree algorithm.
  - The result is a spanning tree that connects all the LAN segments without forming any loops. The root bridge is the center of the spanning tree and the designated ports are the edges of the spanning tree. The blocked ports are the redundant links that provide fault tolerance in case of an active link failure.
  - The spanning tree algorithm is dynamic and can adapt to changes in the network topology. If a link fails, the bridge that detects the failure sends a BPDU with an increased path cost to the root bridge. This triggers a recomputation of the spanning tree and a possible activation of a blocked port. If a new bridge or a new link is added to the network, the bridge sends a BPDU with its own identifier as the root bridge identifier and zero as the path cost. This triggers a recomputation of the spanning tree and a possible deactivation of a designated port. The spanning tree algorithm ensures that the network always converges to a loop-free logical topology.
