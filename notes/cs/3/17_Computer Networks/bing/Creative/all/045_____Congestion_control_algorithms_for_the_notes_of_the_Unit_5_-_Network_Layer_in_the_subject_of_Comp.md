# Congestion control algorithms

Congestion control algorithms are methods to regulate the flow of data packets in a network and prevent congestion, which can degrade the performance and reliability of the network. Congestion occurs when the demand for network resources exceeds the available capacity. Congestion control algorithms can be implemented at different layers of the network stack, such as the transport layer or the network layer.

Some of the common congestion control algorithms are:

- **Leaky bucket**: This algorithm simulates a leaky bucket that can hold a fixed number of tokens. Tokens are generated at a constant rate and added to the bucket. A packet can be sent only if there is a token available in the bucket. If the bucket is full, any incoming token is discarded. This algorithm limits the burstiness of the traffic and smooths out the data rate .
- **Token bucket**: This algorithm is similar to the leaky bucket, but it allows some burstiness in the traffic. The bucket can hold a maximum number of tokens, but tokens are not generated at a constant rate. Instead, the token generation rate depends on the network conditions. A packet can be sent only if there is a token available in the bucket. If the bucket is not full, any incoming token is added to the bucket. This algorithm allows the sender to use the available bandwidth when the network is not congested, and to reduce the data rate when the network is congested .
- **Additive increase multiplicative decrease (AIMD)**: This algorithm is used by TCP to adjust the window size, which is the number of packets that can be sent without waiting for an acknowledgment. The algorithm increases the window size by one packet for every successful acknowledgment received, and decreases the window size by half for every packet loss detected. This algorithm ensures that the sender probes the network capacity gradually and backs off quickly when congestion occurs .
- **Congestion avoidance and control (CAC)**: This algorithm is also used by TCP to avoid congestion before it happens. The algorithm uses a threshold value to determine the state of the network. If the window size is below the threshold, the algorithm is in slow start mode and increases the window size exponentially. If the window size is above the threshold, the algorithm is in congestion avoidance mode and increases the window size linearly. If a packet loss is detected, the algorithm reduces the window size and the threshold by half. This algorithm allows the sender to adapt to the changing network conditions and avoid sending too many packets that can cause congestion .
- **Random early detection (RED)**: This algorithm is implemented at the network layer by routers to prevent congestion. The algorithm monitors the average queue length of the router and compares it with two threshold values: a minimum and a maximum. If the average queue length is below the minimum, the router accepts all incoming packets. If the average queue length is between the minimum and the maximum, the router randomly drops some incoming packets with a probability that increases with the queue length. If the average queue length is above the maximum, the router drops all incoming packets. This algorithm signals the sender to reduce the data rate before the queue overflows and causes packet losses.
