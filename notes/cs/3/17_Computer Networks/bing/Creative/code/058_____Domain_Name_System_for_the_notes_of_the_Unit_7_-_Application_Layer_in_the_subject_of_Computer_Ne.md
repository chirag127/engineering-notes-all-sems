### Domain Name System

- The Domain Name System (DNS) is a method for mapping alphabetic names to numeric IP addresses on the Internet, similar to how a phone book maps a person's name to a phone number.
- DNS is a hierarchical and decentralized naming system that allows computers, servers, services, resources, network devices and components to be identified and located on large networks such as the public Internet .
- A network domain is an administrative grouping of multiple private computer networks or local hosts within the same infrastructure. Domains can be identified using a domain name; domains which need to be accessible from the public Internet can be assigned a globally unique name within the Domain Name System (DNS).
- A domain name consists of one or more labels, each separated by a dot. The right-most label is the top-level domain (TLD), such as .com, .org, .net, etc. The second-level domain (SLD) is the label to the left of the TLD, such as google, amazon, wikipedia, etc. The third-level domain (TLD) is the label to the left of the SLD, such as www, mail, blog, etc. The labels can be up to 63 characters long and can contain letters, digits, hyphens, and underscores.
- Domain names can be internationalized using the Internationalized Domain Name (IDN) system, which allows the use of non-ASCII characters such as accented letters, symbols, or scripts. IDNs are encoded using the Punycode algorithm, which converts them to ASCII labels that start with xn--. For example, the IDN for café.com is xn--caf-dma.com.
- Name servers are the servers that store and provide the domain name to IP address mappings. They are organized in a hierarchical structure, with the root name servers at the top, followed by the TLD name servers, the SLD name servers, and so on. Each name server is authoritative for a certain zone, which is a portion of the domain name space that it is responsible for.
- The process of finding the IP address of a domain name is called address resolution. It involves sending queries to different name servers until the authoritative name server for the domain name is reached. The queries can be sent either iteratively or recursively. In iterative queries, the client contacts each name server in the hierarchy and receives a referral to the next name server. In recursive queries, the client contacts a recursive name server, which contacts other name servers on behalf of the client and returns the final answer.
- DNS resolvers are the clients that initiate the DNS queries. They can be either stub resolvers or full resolvers. Stub resolvers are simple clients that rely on recursive name servers to perform the address resolution. Full resolvers are more complex clients that perform the address resolution themselves by sending iterative queries.
- Circular dependencies and glue records are special cases that arise when the name server for a domain name is itself under that domain name. For example, if the name server for example.com is ns.example.com, then there is a circular dependency between the two. To resolve this, the parent name server (in this case, the .com name server) provides a glue record, which is an extra record that contains the IP address of the child name server (in this case, ns.example.com).
- Record caching is a technique that improves the efficiency and performance of DNS by storing the results of previous queries in a local cache. This reduces the number of queries that need to be sent to the name servers and speeds up the address resolution. However, cached records have a limited time to live (TTL), which specifies how long they are valid for. After the TTL expires, the cached record is discarded and a new query is sent to the name servers.
- Reverse lookup is the process of finding the domain name of an IP address. It uses a special domain name called in-addr.arpa, which is the reverse of the IP address in dotted decimal notation. For example, the reverse lookup domain name for 192.168.1.1 is 1.1.168.192.in-addr.arpa. The reverse lookup queries are sent to the name servers that are authoritative for the in-addr.arpa domain.
