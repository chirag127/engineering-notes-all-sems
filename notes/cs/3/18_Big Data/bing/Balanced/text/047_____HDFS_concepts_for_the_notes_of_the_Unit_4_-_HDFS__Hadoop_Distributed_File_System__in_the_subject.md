### HDFS concepts

HDFS is a distributed file system that is designed to store and process large amounts of data on clusters of commodity hardware. HDFS is one of the core components of Apache Hadoop, an open-source framework for distributed computing and data analytics. Some of the key concepts of HDFS are:

- **Blocks**: HDFS divides each file into fixed-size blocks, usually 128 MB, and stores them across multiple data nodes in the cluster. Each block is replicated on a configurable number of data nodes, typically three, to ensure fault tolerance and high availability. HDFS does not store any metadata (such as file name, permissions, etc.) with the blocks, but only the block ID and checksum.
- **NameNode**: HDFS has a master-slave architecture, where the NameNode is the master node that manages the namespace and the metadata of the file system. The NameNode maintains a mapping of files to blocks, and blocks to data nodes, in its memory. The NameNode also coordinates the replication, deletion, and movement of blocks across data nodes. The NameNode periodically receives heartbeat and block report messages from the data nodes, which indicate the health and status of the data nodes and the blocks they store.
- **DataNode**: HDFS has multiple slave nodes, called DataNodes, that store and serve the blocks of data to clients. DataNodes are responsible for reading, writing, creating, deleting, and replicating blocks as instructed by the NameNode. DataNodes also perform local checksum verification and report any corrupted or missing blocks to the NameNode.
- **Client**: HDFS has a client component that interacts with the file system through a Java API. The client can perform operations such as creating, reading, writing, appending, deleting, and renaming files and directories. The client communicates with the NameNode to obtain the location of the blocks for a file, and then directly transfers data to and from the DataNodes. The client also handles the block replication and recovery in case of failures.
- **Rack Awareness**: HDFS is aware of the network topology of the cluster, and tries to optimize the data placement and replication based on the rack information. HDFS follows a rack-aware replica placement policy, which ensures that the first replica of a block is stored on the same node as the client, the second replica is stored on a different node in the same rack, and the third replica is stored on a node in a different rack. This policy reduces the network bandwidth consumption and improves the data reliability.
