### Hadoop file system interfaces

- Hadoop file system interfaces are the Java abstract classes and interfaces that define the client API to interact with various file systems in Hadoop.
- The main abstract class is `org.apache.hadoop.fs.FileSystem`, which represents a generic file system and provides methods for creating, deleting, renaming, reading and writing files and directories.
- Hadoop supports multiple implementations of the `FileSystem` class, each corresponding to a different file system protocol or scheme. For example, `HDFS` is the default file system implementation for Hadoop, which uses the `hdfs://` scheme. Other file system implementations include `LocalFileSystem` for local files (`file://`), `FTPFileSystem` for FTP files (`ftp://`), `S3FileSystem` for Amazon S3 files (`s3://`), and so on.
- Hadoop uses the URI scheme to select the appropriate `FileSystem` instance to communicate with. For example, if the URI is `hdfs://namenode:port/path`, Hadoop will use the `HDFS` file system implementation to access the file or directory at the given path on the namenode server with the specified port number.
- Hadoop also provides some subclasses of `FileSystem` that add additional functionality or modify the behavior of the base class. For example, `FilterFileSystem` is a subclass of `FileSystem` that delegates all operations to another file system, but can override some methods or add extra logic. `ViewFileSystem` is another subclass of `FileSystem` that allows mounting multiple file systems under a single namespace.
- Hadoop file system interfaces are designed to be portable, scalable, fault-tolerant, and efficient. They support streaming access to file system data, as well as random access and seek operations. They also support compression and decompression of file data, checksum verification, and encryption and decryption of file data. They also support file system permissions, quotas, and access control lists.
