# Failures in MapReduce

MapReduce is a programming model and framework for processing large-scale data sets in parallel and distributed manner. However, MapReduce is not immune to failures, and there are three main types of failures that can occur in MapReduce: task failure, tasktracker failure, and jobtracker failure. Here are some details about each type of failure and how MapReduce handles them.

- **Task failure**: A task is a unit of work assigned to a worker node (tasktracker) by the master node (jobtracker). A task can fail due to various reasons, such as user code errors, hardware failures, network failures, or timeouts. When a task fails, the tasktracker reports the failure to the jobtracker, and the jobtracker marks the task as failed and reschedules it to another tasktracker. The jobtracker also keeps track of the number of failed attempts for each task, and if the number exceeds a certain threshold (configured by `mapreduce.map.failures.maxpercent` and `mapreduce.reduce.failures.maxpercent` properties), the jobtracker marks the task as killed and aborts the whole job. Task failures are the most common type of failures in MapReduce, and they are handled by retrying the failed tasks on different tasktrackers until they succeed or the job fails.

- **Tasktracker failure**: A tasktracker is a worker node that runs map and reduce tasks assigned by the jobtracker. A tasktracker can fail due to various reasons, such as hardware failures, network failures, or software crashes. When a tasktracker fails, the jobtracker detects the failure by periodically sending heartbeat messages to the tasktracker. If the jobtracker does not receive a heartbeat from a tasktracker for a certain period of time (configured by `mapreduce.tasktracker.expiry.interval` property), the jobtracker marks the tasktracker as lost and reschedules all the tasks that were running or pending on the lost tasktracker to other tasktrackers. The jobtracker also removes the lost tasktracker from the pool of available tasktrackers. Tasktracker failures are less common than task failures, but they are more severe, as they affect multiple tasks and may cause data loss if the failed tasktracker was storing intermediate or final output data on its local disk.

- **Jobtracker failure**: A jobtracker is the master node that coordinates the execution of a MapReduce job. It splits the input data into input splits, assigns map and reduce tasks to tasktrackers, monitors the progress and status of the tasks, and collects the final output data. A jobtracker can fail due to various reasons, such as hardware failures, network failures, or software crashes. When a jobtracker fails, the whole MapReduce job is aborted, and the user has to resubmit the job. Jobtracker failures are the most serious type of failures in MapReduce, as they affect the entire job and require manual intervention. Jobtracker failures are also very rare, as the jobtracker is usually run on a reliable and dedicated machine. However, to improve the availability and fault-tolerance of the jobtracker, some MapReduce implementations, such as Hadoop 2.x, use a high-availability (HA) mode, where there are two jobtrackers: an active one and a standby one. The active jobtracker performs the normal functions of the jobtracker, while the standby jobtracker monitors the active jobtracker and takes over its role in case of a failure. The two jobtrackers use a shared storage system, such as ZooKeeper, to store the job metadata and state information, and synchronize with each other periodically.
