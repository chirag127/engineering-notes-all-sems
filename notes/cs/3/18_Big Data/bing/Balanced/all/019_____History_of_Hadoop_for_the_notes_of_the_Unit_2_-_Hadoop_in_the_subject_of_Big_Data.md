# History of Hadoop

- Hadoop is an open-source software framework for storing and processing big data in a distributed manner on large clusters of commodity hardware.
- Hadoop was started with Doug Cutting and Mike Cafarella in the year 2002 when they both started to work on Apache Nutch project, which was a process of building a search engine system that can index 1 billion pages.
- Apache Nutch project was inspired by a white paper written by Google in 2003 that described the Google File System (GFS) and the MapReduce programming model.
- GFS is a distributed file system that can store large amounts of data across multiple machines, and MapReduce is a programming model that can process large-scale data in parallel by dividing the work into smaller tasks and combining the results.
- Cutting and Cafarella realized that the existing technologies were not scalable enough to handle the massive amount of data generated by the web, and decided to implement their own version of GFS and MapReduce using Java.
- In 2005, Cutting joined Yahoo and took the Nutch project with him. He named the project Hadoop after his son's toy elephant.
- In 2006, Hadoop was moved to the Apache Software Foundation and became an open-source project. Hadoop consisted of two main components: Hadoop Distributed File System (HDFS) and Hadoop MapReduce.
- HDFS is a distributed file system that can store data across multiple nodes in a cluster, and provide high availability, fault tolerance, and scalability. HDFS follows a master-slave architecture, where one node acts as the NameNode (master) and manages the metadata of the file system, and the other nodes act as DataNodes (slaves) and store the actual data blocks.
- Hadoop MapReduce is an implementation of the MapReduce programming model for large-scale data processing. MapReduce consists of two phases: map and reduce. In the map phase, the input data is split into smaller chunks and assigned to different map tasks that run on different nodes. Each map task applies a user-defined function to the input data and produces a set of intermediate key-value pairs. In the reduce phase, the intermediate key-value pairs are shuffled and sorted by their keys and assigned to different reduce tasks that run on different nodes. Each reduce task applies another user-defined function to the intermediate data and produces the final output.
- In 2008, Hadoop defeated the supercomputers and became the fastest system on the planet for sorting terabytes of data. Hadoop also became the de facto standard for big data processing in the industry.
- In 2012, Hadoop introduced a new component called Hadoop YARN (Yet Another Resource Negotiator), which is a platform responsible for managing computing resources in clusters and using them for scheduling users' applications. YARN decoupled the resource management and scheduling functions from the MapReduce framework, and enabled Hadoop to support other types of applications besides MapReduce, such as Spark, Hive, Pig, etc.
- In 2020, Hadoop introduced another component called Hadoop Ozone, which is an object store for Hadoop that can handle billions of small files and provide compatibility with S3 API. Ozone is designed to overcome the limitations of HDFS, such as the scalability of the NameNode, the inefficient storage of small files, and the lack of support for object storage semantics.
- Hadoop has evolved over the years and become a comprehensive ecosystem of tools and frameworks for big data storage, processing, analysis, and visualization. Some of the popular components of the Hadoop ecosystem are:

  - HBase: a distributed, column-oriented database that provides random access and strong consistency for structured and semi-structured data.
  - Hive: a data warehouse system that provides a SQL-like interface for querying and analyzing large datasets stored in HDFS or other compatible file systems.
  - Pig: a high-level scripting language that allows users to write complex data transformations using a set of operators and data types.
  - Spark: a fast and general-purpose engine for large-scale data processing that supports batch, streaming, interactive, and machine learning applications.
  - Kafka: a distributed messaging system that can handle high-throughput and low-latency data ingestion and delivery.
  - Flume: a service that can collect, aggregate, and transport large amounts of streaming data from various sources to HDFS or other destinations.
  - Sqoop: a tool that can transfer data between Hadoop and relational databases.
  - ZooKeeper: a service that provides coordination, configuration, and synchronization for distributed systems
