# Cluster Specification for the Notes of the Unit 5 - Hadoop Environment in the Subject of Big Data

- A Hadoop cluster is a collection of computers, known as nodes, that are networked together to perform parallel computations on big data sets .
- A Hadoop cluster is designed to store and analyze large amounts of structured, semi-structured, and unstructured data in a distributed environment. It is often referred to as a shared-nothing system because the only thing that is shared between the nodes is the network itself.
- A Hadoop cluster can be divided into four distinctive layers:
  - Distributed Storage Layer: Each node in a Hadoop cluster has its own disk space, memory, bandwidth, and processing. The incoming data is split into individual data blocks, which are then stored within the HDFS distributed storage layer. HDFS stands for Hadoop Distributed File System, which is a fault-tolerant and scalable file system that can handle petabytes of data.
  - Data Processing Layer: This layer is responsible for processing the data stored in HDFS using various frameworks and tools. The most common framework is MapReduce, which is a programming model that allows parallel processing of large data sets across multiple nodes. Other frameworks include Spark, Hive, Pig, and HBase.
  - Resource Management Layer: This layer is responsible for managing the resources and scheduling the tasks across the cluster. The main component of this layer is YARN, which stands for Yet Another Resource Negotiator. YARN is a platform that allocates resources to different applications and monitors their progress. YARN daemons are ResourceManager, NodeManager, and WebAppProxy.
  - Cluster Coordination Layer: This layer is responsible for coordinating the activities and ensuring the reliability of the cluster. The main component of this layer is ZooKeeper, which is a service that maintains configuration information, provides distributed synchronization, and implements group services.
- To configure the Hadoop cluster, you will need to configure the environment in which the Hadoop daemons execute as well as the configuration parameters for the Hadoop daemons. HDFS daemons are NameNode, SecondaryNameNode, and DataNode. NameNode is the master node that manages the metadata and namespace of the file system. SecondaryNameNode is a backup node that periodically merges the namespace image with the edit log. DataNode is the slave node that stores the actual data blocks and communicates with the NameNode.
- You will also need to set up SSH access between the nodes, install Java on each node, download and extract the Hadoop distribution, and edit the configuration files such as core-site.xml, hdfs-site.xml, mapred-site.xml, and yarn-site.xml. You can also use tools such as Ambari, Cloudera Manager, or Hortonworks Data Platform to simplify the cluster setup and management.
- After configuring the cluster, you can start the Hadoop daemons using the start-dfs.sh and start-yarn.sh scripts, and stop them using the stop-dfs.sh and stop-yarn.sh scripts. You can also use the Hadoop commands to interact with the file system, run MapReduce jobs, and monitor the cluster status.
