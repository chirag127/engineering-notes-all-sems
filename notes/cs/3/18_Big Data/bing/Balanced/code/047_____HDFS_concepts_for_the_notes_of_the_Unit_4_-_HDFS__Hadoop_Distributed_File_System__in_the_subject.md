### HDFS concepts

HDFS is a distributed file system that is designed to store and process large amounts of data on clusters of commodity hardware. HDFS is one of the core components of Apache Hadoop, an open-source framework for distributed computing and data analytics. Some of the key concepts of HDFS are:

- **Blocks**: HDFS divides each file into fixed-size blocks, usually 128 MB, and stores them across multiple data nodes in the cluster. Each block is replicated on a configurable number of data nodes, typically three, to ensure fault tolerance and high availability. HDFS does not store any metadata about the blocks or the files on the data nodes, only the raw data.
- **NameNode**: HDFS has a master node called the NameNode, which is responsible for managing the namespace and the metadata of the file system. The NameNode maintains a mapping of files to blocks, and blocks to data nodes, in its memory. The NameNode also coordinates the read and write operations from the clients, and the replication and recovery of blocks among the data nodes. The NameNode periodically receives heartbeat and block report messages from the data nodes, which indicate their status and the blocks they store. The NameNode is a single point of failure in HDFS, and it is backed up by a secondary NameNode or a standby NameNode, which can take over in case of failure.
- **DataNode**: HDFS has multiple slave nodes called the DataNodes, which store the blocks of the files and serve the read and write requests from the clients. The DataNodes also perform block operations such as replication, deletion, and verification, as instructed by the NameNode. The DataNodes communicate with the NameNode and other DataNodes using TCP/IP protocols.
- **Client**: HDFS has a client component that interacts with the file system through a Java API. The client can perform operations such as creating, reading, writing, appending, deleting, and renaming files and directories. The client also can query the file system for information such as the location of blocks, the size of files, and the replication factor. The client does not directly communicate with the DataNodes, but rather with the NameNode, which provides the necessary information and instructions for the data transfer. The client then streams the data to or from the DataNodes using a custom protocol over TCP/IP.
