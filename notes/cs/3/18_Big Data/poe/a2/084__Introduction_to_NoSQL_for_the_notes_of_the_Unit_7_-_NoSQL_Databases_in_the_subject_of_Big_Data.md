### Introduction to NoSQL for the notes of the Unit 7 - NoSQL Databases in the subject of Big Data

1. NoSQL databases are non-relational databases. They have a simple schema design and scale easily with large amounts of data and high performance requirements.
2. The prominent types of NoSQL databases are:
- Key-Value stores: Data is stored in an array of key-value pairs. Ex: Redis
- Document databases: Data is stored in documents (instead of rows & columns in a table) in a JSON-like format. Ex: MongoDB, CouchDB
- Wide-column stores: Data is stored in columns instead of rows. Ex: Cassandra, HBase
- Graph databases: Data is stored in graphs with nodes, properties, and lines. Ex: Neo4J, InfiniteGraph
3. The reasons to use NoSQL databases are:
- Schema-less: The schema is dynamic and flexible. Easy to modify.
- Scalability: They scale out easily by adding more servers in a cluster.
- Distributed: The data is distributed across multiple servers.
- Open source: Most NoSQL databases are open source.
- Performance: They have high performance and can handle large data volumes and traffic.
4. The reasons not to use NoSQL databases are:
- Limited querying capabilities: The query language is limited. Some complex queries cannot be performed.
- Eventual consistency: The data may not be consistent across all servers at all times.
- Lower ACID compliance: The ACID properties are not strictly followed. Some allow eventual consistency.
- Limited tools and resources: The ecosystem around NoSQL databases is not as mature as SQL databases. Fewer tools and resources are available.
