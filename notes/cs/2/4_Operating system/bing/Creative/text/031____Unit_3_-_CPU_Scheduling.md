## Unit 3 - CPU Scheduling

- CPU scheduling is the process of selecting a process from the ready queue and allocating the CPU to it.
- The main objective of CPU scheduling is to maximize the CPU utilization and minimize the waiting time, turnaround time, response time and context switching overhead.
- There are different types of CPU scheduling algorithms, such as:
  - First Come First Serve (FCFS): The process that arrives first in the ready queue is executed first by the CPU. This algorithm is simple, but it may cause long waiting time and low CPU utilization for some processes.
  - Shortest Job First (SJF): The process with the shortest burst time (the time required to execute on the CPU) is executed first by the CPU. This algorithm minimizes the average waiting time, but it may cause starvation for some long processes.
  - Shortest Remaining Time First (SRTF): The process with the shortest remaining burst time is executed first by the CPU. This algorithm is a preemptive version of SJF, which means that the CPU can be taken away from a running process if a new process arrives with a shorter burst time. This algorithm minimizes the average response time, but it may cause more context switches and overhead.
  - Priority Scheduling: The process with the highest priority is executed first by the CPU. The priority can be either static (assigned at the time of creation) or dynamic (based on some factors such as age, burst time, etc.). This algorithm can be either preemptive or non-preemptive. This algorithm may cause starvation for some low priority processes.
  - Round Robin (RR): The processes in the ready queue are executed in a circular order, with each process getting a fixed amount of time (called quantum) on the CPU. If a process does not finish within its quantum, it is preempted and moved to the end of the queue. This algorithm is fair and suitable for time-sharing systems, but it may cause high context switches and overhead.
  - Multilevel Queue (MLQ): The processes are divided into different queues based on some criteria (such as type, priority, memory size, etc.), and each queue has its own scheduling algorithm. The CPU is allocated to the processes from the highest priority queue that is not empty. This algorithm can handle the diversity of processes, but it may cause starvation for some low priority queues.
  - Multilevel Feedback Queue (MLFQ): The processes are divided into different queues based on some criteria (such as type, priority, memory size, etc.), and each queue has its own scheduling algorithm. The CPU is allocated to the processes from the highest priority queue that is not empty. However, unlike MLQ, the processes can move between the queues based on their behavior (such as CPU burst, IO burst, etc.). This algorithm can adapt to the changing needs of the processes, but it may cause complexity and overhead.
