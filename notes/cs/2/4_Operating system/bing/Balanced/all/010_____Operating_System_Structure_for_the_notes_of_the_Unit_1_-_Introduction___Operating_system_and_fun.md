# Operating System Structure

An operating system is a program that manages a computer's resources, especially the allocation of those resources among other programs. For efficient performance and implementation, an operating system should be partitioned into separate subsystems, each with carefully defined tasks, inputs, outputs, and performance characteristics. These subsystems can then be arranged in various architectural configurations.

Some of the common components of an operating system are:

- Process management: This component is responsible for creating, scheduling, and terminating processes, as well as providing mechanisms for communication and synchronization among them.
- Memory management: This component is responsible for allocating and deallocating memory space to processes, as well as managing the virtual memory and the physical memory.
- File system: This component is responsible for organizing and storing files and directories on secondary storage devices, as well as providing access and protection mechanisms for them.
- I/O system: This component is responsible for managing the input and output devices, such as keyboards, mice, monitors, printers, disks, etc., as well as providing device drivers and buffering techniques for them.
- Network management: This component is responsible for enabling communication and data transfer among different computers connected by a network, as well as providing protocols and services for them.

There are many structures of the operating system, depending on how these components are interconnected and melded into the kernel. The kernel is the core part of the operating system that runs in the privileged mode and has direct access to the hardware. Some of the common structures of the operating system are:

- Simple structure: Such operating systems do not have well defined structure and are small, simple and limited systems. They run as a single program in the kernel mode and do not have any abstraction or modularity. An example of such a system is MS-DOS.
- Monolithic structure: Such operating systems run as a single program in the kernel mode, but have a well defined structure and are more complex and powerful than simple systems. They have a collection of various procedures linked together in a binary file, which can invoke each other as needed. However, they do not have any protection or isolation among them, which makes them prone to errors and difficult to maintain. An example of such a system is UNIX.
- Layered structure: Such operating systems have a hierarchical structure, where each layer provides a set of functions and services to the layer above it, and uses the functions and services of the layer below it. The lowest layer interacts with the hardware, and the highest layer interacts with the user applications. This structure provides modularity and abstraction, which makes the system easier to design, implement, and debug. However, it also introduces overhead and inefficiency, as each layer adds its own data structures and functions. An example of such a system is THE operating system.
- Microkernel structure: Such operating systems have a minimal kernel that provides only the most essential functions, such as process management, memory management, and inter-process communication. The other components, such as file system, I/O system, and network management, are implemented as user-level processes that communicate with the kernel through message passing. This structure provides flexibility and reliability, as the user-level processes can be modified or replaced without affecting the kernel. However, it also introduces performance degradation, as the message passing involves context switching and data copying. An example of such a system is Mach.
