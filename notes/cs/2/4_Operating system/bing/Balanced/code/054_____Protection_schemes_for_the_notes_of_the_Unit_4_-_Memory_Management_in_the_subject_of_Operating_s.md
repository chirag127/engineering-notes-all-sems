### Protection schemes for the notes of the Unit 4 - Memory Management in the subject of Operating system

- Memory management is the process of allocating and deallocating memory to processes and ensuring efficient and effective use of the available memory resources.
- Memory protection is a mechanism that prevents a process from accessing memory that is not allocated to it or that belongs to another process or the operating system.
- Memory protection is essential for the security, reliability, and performance of the operating system and the processes running on it.
- There are different schemes for implementing memory protection, depending on the hardware and software architecture of the system. Some of the common schemes are:

  - **Base and limit registers**: This scheme uses two registers, called the base and the limit registers, to define the logical address space of a process. The base register holds the starting physical address of the process, and the limit register holds the size of the process. The hardware checks every memory reference generated by the process and compares it with the limit register. If the reference is valid, it adds the base register to the logical address to get the physical address. If the reference is invalid, it raises an exception and terminates the process. This scheme is simple and fast, but it does not support dynamic memory allocation or sharing of memory among processes.
  - **Paging**: This scheme divides the physical memory into fixed-size blocks, called frames, and the logical memory of each process into blocks of the same size, called pages. The hardware maintains a page table for each process, which maps the logical pages to the physical frames. The page table also contains protection bits for each page, which indicate the access rights and the validity of the page. The hardware checks every memory reference generated by the process and uses the page table to translate the logical address to the physical address. If the reference is valid and the protection bits allow the access, the hardware performs the memory operation. If the reference is invalid or the protection bits deny the access, it raises an exception and terminates the process. This scheme supports dynamic memory allocation and sharing of memory among processes, but it introduces overhead due to the page table lookup and the fragmentation of memory.
  - **Segmentation**: This scheme divides the logical memory of each process into variable-size blocks, called segments, which correspond to logical units of the program, such as functions, data structures, or modules. The hardware maintains a segment table for each process, which maps the logical segments to the physical memory. The segment table also contains protection bits for each segment, which indicate the access rights and the validity of the segment. The hardware checks every memory reference generated by the process and uses the segment table to translate the logical address to the physical address. If the reference is valid and the protection bits allow the access, the hardware performs the memory operation. If the reference is invalid or the protection bits deny the access, it raises an exception and terminates the process. This scheme supports dynamic memory allocation and sharing of memory among processes, and it also allows better access protection than other schemes because memory references are relative to a specific segment and the hardware will not permit the application to reference memory not defined for that segment. However, this scheme introduces overhead due to the segment table lookup and the fragmentation of memory.
