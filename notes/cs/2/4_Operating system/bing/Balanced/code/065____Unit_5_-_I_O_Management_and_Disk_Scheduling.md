## Unit 5 - I/O Management and Disk Scheduling

- I/O management is the process of coordinating and controlling the communication between the CPU and the external devices, such as disks, printers, keyboards, mice, etc.
- I/O devices vary in their characteristics, such as data transfer rate, access method, capacity, and functionality. Therefore, the operating system needs to provide a uniform interface for the applications to access the devices, and also to manage the allocation, buffering, caching, spooling, and error handling of the I/O operations.
- Disk scheduling is a specific aspect of I/O management that deals with the order in which the disk requests are serviced by the disk controller. Disk scheduling is important because:
  - Multiple I/O requests may arrive by different processes and only one I/O request can be served at a time by the disk controller. Thus other I/O requests need to wait in the waiting queue and need to be scheduled.
  - The disk access time depends on the seek time, rotational latency, and transfer time. The seek time is the time required to move the disk head to the desired track, and it is the most significant factor in the disk access time. The seek time can be reduced by scheduling the disk requests in a way that minimizes the head movement.
  - The disk performance can be measured by the disk throughput, which is the number of requests serviced per unit time, and the average response time, which is the average time for a request to be completed.
- There are various disk scheduling algorithms that aim to optimize the disk performance, such as:
  - First Come First Served (FCFS): This is the simplest algorithm that services the requests in the order they arrive. It is fair but not efficient, as it does not take into account the seek time or the location of the requests.
  - Shortest Seek Time First (SSTF): This algorithm chooses the request that is closest to the current head position, thus minimizing the seek time. It is more efficient than FCFS, but it may cause starvation for some requests that are far away from the head.
  - SCAN: This algorithm moves the head in one direction, servicing all the requests until it reaches the end of the disk, then it reverses the direction and repeats the process. It is also known as the elevator algorithm, as it resembles the movement of an elevator in a building. It is more fair than SSTF, as it prevents starvation, but it may cause longer waiting time for the requests at the ends of the disk.
  - C-SCAN: This algorithm is a variation of SCAN, where the head only goes in one direction, servicing the requests until it reaches the end of the disk, then it jumps back to the beginning of the disk and repeats the process. It is also known as the circular SCAN algorithm, as it treats the disk as a circular list of tracks. It provides more uniform waiting time than SCAN, as it eliminates the difference between the end and the beginning of the disk.
  - LOOK and C-LOOK: These algorithms are similar to SCAN and C-SCAN, except that they do not go all the way to the end of the disk, but only to the last request in that direction. They are more realistic and efficient, as they avoid unnecessary head movement.
