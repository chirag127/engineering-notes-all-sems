### Virtual memory
- Virtual memory is a **technique** and not a physical memory present in the computer system.
- Virtual memory provides an **illusion** of a large main memory to the programmer, when in reality the physical memory is limited .
- Virtual memory uses some of the **space** from the secondary storage, such as a hard disk, and maps it to the address space of the process .
- Virtual memory allows the computer to run **large** and **sophisticated** programs that may not fit entirely in the physical memory.
- Virtual memory also enables the **multiprogramming** and **memory protection** features of the operating system.

### How virtual memory works
- Virtual memory works by using a **translation mechanism** that converts the logical addresses generated by the program into physical addresses used by the memory system.
- The translation mechanism is implemented by a hardware device called the **memory management unit (MMU)**.
- The MMU uses a data structure called the **page table** to store the mapping between logical and physical addresses.
- The page table is divided into **entries**, each corresponding to a fixed-size block of memory called a **page**.
- The logical address space of a process is divided into pages, and the physical address space of the memory is divided into **frames** of the same size.
- The page table entry for a page contains the frame number where the page is stored in the physical memory, and a **valid bit** that indicates whether the page is present in the memory or not.
- When the MMU receives a logical address, it splits it into two parts: a **page number** and an **offset**.
- The page number is used to index the page table and find the corresponding page table entry.
- If the valid bit is set, the MMU concatenates the frame number and the offset to form the physical address.
- If the valid bit is not set, the MMU generates a **page fault** exception, which triggers the operating system to bring the page from the secondary storage into the physical memory and update the page table.
- The operating system may need to **replace** an existing page in the memory with the new page, using some **replacement algorithm** such as FIFO, LRU, or optimal.
- The operating system may also need to **write back** the replaced page to the secondary storage, if it has been modified since it was loaded into the memory.
- The operating system may use a **dirty bit** in the page table entry to indicate whether the page has been modified or not.

### Benefits of virtual memory
- Virtual memory allows the programmer to write programs that are **larger** than the physical memory, without worrying about the memory allocation and management.
- Virtual memory enables the operating system to run **multiple** programs concurrently, by giving each program a separate logical address space and swapping pages in and out of the memory as needed.
- Virtual memory provides **memory protection** by preventing one program from accessing or modifying the memory space of another program.
- Virtual memory improves the **performance** of the computer system by reducing the disk access time and increasing the memory utilization.
- Virtual memory also supports **dynamic linking** and **shared memory** features, which allow the programs to load and share libraries and data at run time.

### Drawbacks of virtual memory
- Virtual memory introduces an **overhead** in the memory system, as the MMU needs to perform the address translation for every memory access.
- Virtual memory may cause **page faults**, which interrupt the normal execution of the program and require the operating system to transfer pages between the memory and the disk.
- Virtual memory may also cause **thrashing**, which is a situation where the operating system spends more time swapping pages than executing the program.
- Virtual memory may degrade the **reliability** of the computer system, as the disk may fail or become corrupted, resulting in the loss of data or code.
