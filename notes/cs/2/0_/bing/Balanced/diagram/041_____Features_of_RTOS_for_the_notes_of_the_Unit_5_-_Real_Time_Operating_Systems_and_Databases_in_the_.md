### Features of RTOS

A real-time operating system (RTOS) is an operating system that can guarantee the timely and predictable execution of tasks, regardless of the system load. An RTOS has the following features   :

- **Small and fast**: An RTOS is designed to occupy very less memory and consume fewer resources, as it often runs on embedded devices with limited hardware capabilities. An RTOS also has a fast boot time and a low interrupt latency, which means it can respond quickly to external events.
- **Responsive and deterministic**: An RTOS can meet the deadlines and performance requirements of real-time applications, such as industrial control, robotics, or multimedia. An RTOS can ensure that tasks are executed within a tight time bound, and that the system behaves as expected every time, without any unexpected delays or failures.
- **Preemptive and priority-based scheduling**: An RTOS uses a preemptive scheduling algorithm, which means that the scheduler can interrupt a running task and switch to a higher-priority task at any time. This ensures that the most urgent and critical tasks are always given the highest priority and the CPU time they need. The priority of each task is unique and fixed, and can be set by the programmer or the system.
- **Cooperative and event-driven**: An RTOS can also use a cooperative scheduling algorithm, which means that the tasks voluntarily yield the CPU to other tasks when they are done or when they are waiting for an event. This reduces the overhead of context switching and allows the tasks to cooperate with each other. An RTOS is also event-driven, which means that the tasks are triggered by external or internal events, such as interrupts, signals, or messages.
- **Support for concurrency and synchronization**: An RTOS can support multiple tasks running concurrently and sharing the system resources, such as memory, I/O devices, or communication channels. An RTOS also provides mechanisms for synchronization and communication among the tasks, such as semaphores, mutexes, message queues, or pipes. These mechanisms help to prevent race conditions, deadlocks, or data corruption.
