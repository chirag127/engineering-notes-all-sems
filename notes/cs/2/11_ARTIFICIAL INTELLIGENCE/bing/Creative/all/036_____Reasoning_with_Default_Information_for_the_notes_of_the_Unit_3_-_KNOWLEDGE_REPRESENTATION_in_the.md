# Reasoning with Default Information

- Reasoning with default information is a form of non-monotonic reasoning that allows an agent to draw conclusions based on incomplete or uncertain information, using default rules or assumptions that can be overridden by more specific or reliable information.
- Default rules are conditional statements of the form: if P then normally Q, where P is the antecedent and Q is the consequent. Normally means that Q is true in most cases, but not necessarily in all cases. For example, if X is a bird then normally X can fly.
- Default rules can be used to infer new facts from a given knowledge base, using a process called default reasoning. Default reasoning consists of three steps: 
  - Selection: choose a default rule that is applicable to the current situation, i.e., its antecedent is true or derivable from the knowledge base.
  - Extension: add the consequent of the default rule to the knowledge base, as a tentative or provisional fact.
  - Revision: check if the new fact is consistent with the rest of the knowledge base, and if not, retract it and try another default rule or backtrack to a previous step.
- Default reasoning can be formalized using different logical frameworks, such as default logic, circumscription, autoepistemic logic, and logic programming. These frameworks differ in how they represent and apply default rules, and how they handle conflicts and exceptions.
- Some of the advantages of reasoning with default information are:
  - It can model common sense reasoning and deal with incomplete or uncertain information in a natural way.
  - It can capture generalizations and exceptions in a flexible and modular way.
  - It can support defeasible reasoning and argumentation, where conclusions can be challenged and revised based on new evidence or counterarguments.
- Some of the challenges and limitations of reasoning with default information are:
  - It can lead to inconsistency or ambiguity, if there are conflicting or contradictory default rules or facts.
  - It can be computationally complex or intractable, depending on the size and structure of the knowledge base and the default rules.
  - It can be difficult to acquire and maintain default rules, as they may depend on the context and the domain of application.
