### Unix and windows access control summary

- Access control is the mechanism that determines who can access what resources in a system.
- Unix and Windows have different access control models and mechanisms.
- Unix uses access control lists (ACLs) on each file and directory. An ACL consists of three sets of permissions: read, write and execute. Each set applies to one of three categories of users: owner, group and others.
- Windows uses security descriptors on each object. A security descriptor consists of an owner, a primary group, a discretionary access control list (DACL) and a system access control list (SACL). A DACL contains access control entries (ACEs) that specify the permissions granted or denied to security principals (users and groups). A SACL contains audit entries that specify the events to be logged for security principals.
- Unix and Windows have different ways of assigning and inheriting permissions. Unix uses the user identifier (UID) and group identifier (GID) of the process that creates a file or directory to determine its owner and group. Unix also uses the set-user-ID (SUID) and set-group-ID (SGID) bits to allow a process to run with the permissions of the file or directory owner or group. Unix also uses the sticky bit to prevent deletion of files or directories by other users. Unix inherits permissions from the parent directory by default, but can be changed by using the umask command or the chmod command. Windows uses the security identifier (SID) of the user or group that creates an object to determine its owner and primary group. Windows also uses the access token of the process that accesses an object to determine its effective permissions. Windows inherits permissions from the parent object by default, but can be changed by using the advanced security settings or the icacls command.
