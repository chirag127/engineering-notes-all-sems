### Detour into Unix User IDs, Process IDs and Privileges

- In Unix-like operating systems, each user account has a unique identifier called a user ID (UID). The UID 0 is reserved for the superuser (system administrator) who has full access to the system. A user account can belong to one or more groups, each with a group ID (GID).
- A subject is a process that runs on behalf of a user and has a pair of UID and GID associated with it. The UID and GID determine the permissions and privileges of the process to access files and other resources on the system. A file is an object that has an owner (UID) and a group (GID) and a set of permissions for each of them.
- A process can have three types of UIDs: real, effective and saved. The real UID is the UID of the user who created the process. The effective UID is the UID that is used to evaluate the privileges of the process to perform a particular action. The saved UID is the UID of the file that has the setuid bit on, which means that the process can execute with the privileges of the file owner.
- A process can change its effective UID by using the setuid() system call. This can be used to drop or restore privileges temporarily or permanently. For example, a process that runs with root privileges can drop its privileges by setting its effective UID to a non-root UID. This can prevent unauthorized or malicious actions by the process. Alternatively, a process that runs with a non-root UID can restore its privileges by setting its effective UID to the saved UID, which is the root UID. This can allow the process to perform some privileged actions that are necessary for its functionality.
