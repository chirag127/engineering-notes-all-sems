# Public key cryptography

Public key cryptography, also known as asymmetric cryptography, is a type of cryptographic system that uses two different keys for encryption and decryption. The keys are mathematically related, but not identical. One key is called the public key, and the other is called the private key. The public key can be shared with anyone, while the private key must be kept secret by the owner.

Some of the main features and applications of public key cryptography are:

- Public key encryption: This is a method of encrypting a message with the recipient's public key, so that only the recipient can decrypt it with their private key. This ensures the confidentiality and authenticity of the message, as no one else can read or modify it. For example, Alice can send an encrypted email to Bob using Bob's public key, and Bob can decrypt it using his private key.
- Digital signatures: This is a method of signing a message with the sender's private key, so that anyone can verify it with the sender's public key. This ensures the integrity and non-repudiation of the message, as no one else can create or forge the signature. For example, Alice can sign an email with her private key, and Bob can verify it with Alice's public key.
- Key exchange: This is a method of securely exchanging a secret key between two parties using their public and private keys. The secret key can then be used for symmetric encryption, which is faster and more efficient than public key encryption. For example, Alice and Bob can use the Diffie-Hellman protocol to generate a shared secret key using their public and private keys, and then use the secret key to encrypt their communication.
- Digital certificates: This is a method of binding a public key to an identity or a domain name using a trusted third party, called a certificate authority (CA). The CA issues a digital certificate that contains the public key and the identity of the owner, and signs it with its own private key. The certificate can be verified by anyone using the CA's public key. For example, Alice can obtain a digital certificate from a CA that proves that she owns the domain name example.com, and Bob can verify it using the CA's public key.
