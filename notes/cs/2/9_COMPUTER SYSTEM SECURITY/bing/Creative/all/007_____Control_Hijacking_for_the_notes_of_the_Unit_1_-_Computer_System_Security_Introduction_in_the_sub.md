# Control Hijacking

- Control hijacking is a type of attack that exploits a program error, particularly a memory corruption vulnerability, at application runtime to subvert the intended control flow of a program.
- Control hijacking can allow an attacker to execute arbitrary code, bypass security mechanisms, escalate privileges, steal sensitive data, or cause denial of service.
- Control hijacking can be performed by various techniques, such as:
  - Buffer overflow attacks: These attacks occur when an attacker writes more data to a buffer than it can hold, overwriting adjacent memory locations that may store important information, such as return addresses, function pointers, or local variables . By overwriting these values, the attacker can alter the control flow of the program and execute malicious code .
  - Integer overflow attacks: These attacks occur when an arithmetic operation results in a value that is too large or too small to fit in the data type of the variable that stores it, causing a wraparound or truncation . This can lead to unexpected behavior, such as memory allocation errors, array index errors, or incorrect comparisons . By exploiting these errors, the attacker can manipulate the program logic and execute malicious code .
  - Format string attacks: These attacks occur when an attacker passes a maliciously crafted string as an argument to a function that expects a format string, such as printf . The format string can contain specifiers that instruct the function to read or write data from arbitrary memory locations, or to execute arbitrary code . By passing a carefully crafted format string, the attacker can read or modify sensitive data, or execute malicious code .
  - Session hijacking attacks: These attacks occur when an attacker gains unauthorized access to a victim's online account or profile by intercepting or cracking session tokens  . Session tokens are cookies sent from a web server to users to verify their identity and website settings. By obtaining a valid session token, the attacker can impersonate the victim and perform actions on their behalf, such as accessing private information, sending messages, or making transactions  .
- Control hijacking can be prevented by various defense mechanisms, such as:
  - Ciphering the packets: This can prevent network level hijacks by encrypting the data sent between the client and the server, so that the attacker cannot decipher the packet headers, to obtain any information that will aid in spoofing.
  - Validating the input: This can prevent buffer overflow, integer overflow, and format string attacks by checking the length, type, and format of the data received from the user or other sources, and rejecting any invalid or malicious input .
  - Using safe functions: This can prevent buffer overflow and format string attacks by replacing unsafe functions, such as strcpy, strcat, gets, or printf, with safer alternatives, such as strncpy, strncat, fgets, or snprintf, that limit the amount of data copied or printed, or check for null terminators .
  - Using stack canaries: This can prevent buffer overflow attacks by placing a random value, called a canary, between the buffer and the return address on the stack, and checking its integrity before returning from the function . If the canary is overwritten, it indicates a buffer overflow, and the program can terminate or raise an exception .
  - Using address space layout randomization (ASLR): This can prevent buffer overflow attacks by randomizing the base addresses of the stack, the heap, and the code segments, making it harder for the attacker to predict the location of the return address or the malicious code .
  - Using non-executable memory: This can prevent buffer overflow attacks by marking the memory regions that store data, such as the stack and the heap, as non-executable, preventing the execution of any code stored in them .
