# Finding vulnerabilities for the notes of the Unit 3 - Secure architecture principles isolation and least privilege in the subject of computer system security

- A security vulnerability is a weakness or flaw in a system or application that can be exploited by an attacker to compromise its confidentiality, integrity, or availability.
- Security vulnerabilities can arise from various sources, such as design errors, coding errors, configuration errors, user errors, or environmental changes.
- Security design principles are guidelines or best practices that help to design and implement a securely architected system.
- Some of the security design principles are :
  - **Isolation**: Separating different components or layers of a system to limit the impact of a compromise or failure of one component on the others. For example, using virtual machines, containers, firewalls, or network segmentation to isolate different workloads or services.
  - **Least privilege**: Assigning the minimum level of access or permissions to each user or process that is required to perform their tasks. For example, using role-based access control, user accounts, or encryption keys to limit the access to sensitive data or resources.
  - **Separation of privilege**: Avoiding unnecessary sharing of elevated privileges or credentials among different users or processes. For example, using separate accounts or keys for different roles or functions, or requiring multiple factors or approvals for critical operations.
  - **Least common mechanism**: Minimizing the reuse of code or components that are shared by multiple users or processes, especially if they have different levels of trust or privilege. For example, using dedicated libraries, modules, or services for each application or workload, or avoiding the use of shared memory or files.
  - **Defense in depth**: Applying multiple layers of security controls or defenses to protect a system or application from different types of threats or attacks. For example, using encryption, authentication, authorization, logging, monitoring, auditing, or backup to enhance the security posture of a system or application.
- Finding vulnerabilities for the notes of the Unit 3 involves the following steps :
  - **Proactively monitor** for vulnerabilities in the security processes, application code, infrastructure configurations, and user behavior of the system or application. For example, using vulnerability scanners, code analyzers, configuration checkers, or user activity trackers to identify potential weaknesses or flaws.
  - **Prioritize vulnerabilities** and fix them, based on the severity of the potential attack, the impact of the compromise, and the feasibility of the mitigation. For example, using risk assessment, threat modeling, or vulnerability scoring to rank the vulnerabilities and allocate resources for remediation.
  - **Apply security design principles** to design and implement a securely architected system or application that follows the concepts of isolation, least privilege, separation of privilege, least common mechanism, and defense in depth. For example, using secure coding practices, secure configuration settings, secure access control policies, secure communication protocols, or secure backup and recovery strategies to reduce the attack surface and enhance the resilience of the system or application.
