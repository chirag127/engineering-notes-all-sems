### Cookies, frames and frame busting

- Cookies are small pieces of data that are stored by the browser on the user's device. They are used to store information such as preferences, session state, authentication tokens, etc. Cookies can be sent by the server using the `Set-Cookie` HTTP header, or created by the client using JavaScript. Cookies have attributes that control their scope, duration, and security, such as `domain`, `path`, `expires`, `secure`, and `samesite`.
- Frames are HTML elements that allow a web page to display another web page within a rectangular area. Frames can be used to create layouts, embed content, or perform cross-domain communication. Frames have different types, such as `iframe`, `frame`, and `object`. Frames can also be nested, creating a hierarchy of frames within a web page.
- Frame busting is a technique that prevents a web page from being loaded inside a frame by another web page. Frame busting is used to defend against clickjacking attacks, where an attacker overlays a transparent frame over a legitimate web page, and tricks the user into clicking on the frame, which performs an action on the underlying web page. Frame busting can be implemented using various methods, such as:
  - Checking the `window.top` or `window.parent` properties in JavaScript, and redirecting the browser to the original web page if they are not equal to the current window.
  - Using the `X-Frame-Options` or `Content-Security-Policy` HTTP headers, which instruct the browser to not load the web page in a frame, or only allow frames from certain origins.
  - Using the `SameSite` cookie attribute, which prevents the browser from sending cookies when the web page is loaded in a frame by a different site. This can prevent the web page from functioning properly, or force the user to re-authenticate.
