### Git/GitHub for the notes of the Unit 3 - Hardware Communication in the subject of Programming and Interfacing with Microcontrollers

- Git is a distributed version control system that allows you to track and manage the changes in your source code. It also enables collaboration among multiple developers working on the same project.   
- GitHub is a code hosting platform that uses Git as its underlying technology. It provides various features such as repositories, branches, commits, pull requests, issues, and more. It also allows you to connect with other developers and the GitHub community.   
- A repository is a collection of files and folders that are associated with a project. It can be either local (on your computer) or remote (on GitHub or another platform). You can create, clone, fork, or import a repository.   
- A branch is a parallel version of a repository that contains a different set of changes. It allows you to work on multiple features or bug fixes without affecting the main branch (usually called master or main). You can create, switch, merge, or delete branches.   
- A commit is a snapshot of the changes you have made in your working directory. It has a unique identifier (a hash) and a message that describes the changes. You can create, view, amend, or revert commits.   
- A pull request is a request to merge one branch into another. It allows you to review, discuss, and approve the changes before they are applied. You can create, review, merge, or close pull requests.   
- To use Git and GitHub, you need to install Git on your computer, set up your username and email, and configure your credentials. You also need to create a GitHub account and sign in.   
- To work with a repository, you need to clone it from GitHub to your local machine, or create a new one locally and push it to GitHub. You can then make changes in your working directory, stage them, and commit them. You can also fetch, pull, or push changes from or to the remote repository.  
- To work with a branch, you need to create a new one from an existing branch, or switch to an existing one. You can then make changes in your branch, and merge it with another branch when you are done. You can also create a pull request to propose your changes to another branch.  
- To work with a pull request, you need to create one from your branch to another branch, or review one that someone else has created. You can then comment on the changes, request or make changes, approve or reject the changes, and merge or close the pull request.
