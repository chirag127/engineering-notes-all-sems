### Transport Layer for the notes of the Unit 4 - Transport & Session Layer Protocols in the subject of IOT ARCHITECTURE AND PROTOCOLS

- The transport layer is the fourth layer in the OSI model and the TCP/IP model. It is responsible for end-to-end communication and data transfer between applications or devices over a network.
- The transport layer provides features such as reliability, congestion control, flow control, error detection and correction, and ordering of data packets.
- The transport layer can use different protocols depending on the requirements of the applications or devices. Some of the commonly used transport layer protocols in IoT are:

  - TCP (Transmission Control Protocol): TCP is a connection-oriented and reliable protocol that ensures the delivery of data packets in the same order and without errors. TCP uses a three-way handshake to establish a connection, and a four-way handshake to terminate a connection. TCP also uses mechanisms such as acknowledgments, retransmissions, windowing, and congestion avoidance to ensure reliable data transfer. TCP is suitable for applications or devices that need high reliability and data integrity, such as web browsing, email, file transfer, etc.
  - UDP (User Datagram Protocol): UDP is a connectionless and unreliable protocol that does not guarantee the delivery of data packets or their order. UDP does not use any handshaking, acknowledgment, retransmission, or congestion control mechanisms. UDP is suitable for applications or devices that need low latency and high performance, such as streaming, gaming, voice over IP, etc.
  - DCCP (Datagram Congestion Control Protocol): DCCP is a connection-oriented and unreliable protocol that provides congestion control for unreliable datagrams. DCCP uses a four-way handshake to establish a connection, and a three-way handshake to terminate a connection. DCCP also uses mechanisms such as acknowledgments, retransmissions, and congestion control algorithms to ensure efficient data transfer. DCCP is suitable for applications or devices that need congestion control but not reliability, such as multimedia streaming, telephony, etc.
  - SCTP (Stream Control Transmission Protocol): SCTP is a connection-oriented and reliable protocol that supports multiple streams of data within a single connection. SCTP uses a four-way handshake to establish a connection, and a four-way handshake to terminate a connection. SCTP also uses mechanisms such as acknowledgments, retransmissions, windowing, congestion control, and checksums to ensure reliable data transfer. SCTP is suitable for applications or devices that need multiple streams of data, such as web servers, voice over IP, etc.
  - RSVP (Resource Reservation Protocol): RSVP is a signaling protocol that allows applications or devices to reserve network resources for data transfer. RSVP uses a two-way handshake to establish a reservation, and a two-way handshake to terminate a reservation. RSVP also uses mechanisms such as refresh messages, teardown messages, and error messages to maintain and manage reservations. RSVP is suitable for applications or devices that need quality of service, such as video conferencing, online gaming, etc.
  - DTLS (Datagram Transport Layer Security): DTLS is a security protocol that provides encryption, authentication, and integrity for datagram-based transport protocols, such as UDP and DCCP. DTLS uses a four-way handshake to establish a secure connection, and a two-way handshake to terminate a secure connection. DTLS also uses mechanisms such as certificates, keys, ciphers, and hashes to ensure secure data transfer. DTLS is suitable for applications or devices that need security, such as web browsing, email, file transfer, etc.
  - TLS (Transport Layer Security): TLS is a security protocol that provides encryption, authentication, and integrity for stream-based transport protocols, such as TCP and SCTP. TLS uses a four-way handshake to establish a secure connection, and a two-way handshake to terminate a secure connection. TLS also uses mechanisms such as certificates, keys, ciphers, and hashes to ensure secure data transfer. TLS is suitable for applications or devices that need security, such as web browsing, email, file transfer, etc.
  - RPL (Routing Protocol for Low-Power and Lossy Networks): RPL is a routing protocol that provides efficient and scalable routing for low-power and lossy networks, such as wireless sensor networks, smart grid networks, etc. RPL uses a tree-based topology to organize nodes into a destination-oriented directed acyclic graph (DODAG). RPL also uses mechanisms such as control messages, rank, objective function, and metrics to ensure efficient routing. RPL is suitable for applications or devices that need low-power and lossy routing, such as environmental monitoring, smart metering, etc.
