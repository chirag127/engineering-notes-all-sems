# Get the status of a bulb at a remote place (on the LAN) through web.

- To get the status of a bulb at a remote place (on the LAN) through web, we need to use a web server, a web client, and a network protocol.
- A web server is a software program that listens for requests from web clients and sends responses back. A web client is a software program that sends requests to web servers and receives responses. A network protocol is a set of rules that define how data is exchanged between web servers and web clients.
- One example of a web server is Apache, which can run on various operating systems and support various web technologies. One example of a web client is a web browser, such as Chrome or Firefox, which can display web pages and interact with web servers. One example of a network protocol is HTTP, which stands for Hypertext Transfer Protocol, and defines how web pages and other resources are requested and delivered over the Internet.
- To get the status of a bulb at a remote place (on the LAN) through web, we need to do the following steps:

  - Connect the bulb to a microcontroller, such as Arduino or Raspberry Pi, that can control its state (on or off) and communicate with a web server. The microcontroller should be connected to the same LAN as the web server.
  - Install and configure a web server on a computer that is connected to the same LAN as the microcontroller. The web server should be able to handle requests from web clients and send commands to the microcontroller. The web server should also have a web page that displays the status of the bulb and allows the user to change it.
  - Access the web page from a web client, such as a web browser, that is connected to the same LAN as the web server. The web client should be able to send requests to the web server and receive responses. The web client should also be able to see the status of the bulb and change it by clicking a button or a switch on the web page.
  - The web server, the microcontroller, and the web client should use the same network protocol, such as HTTP, to communicate with each other. The network protocol should define the format and content of the requests and responses, such as the URL, the method, the headers, and the body. The network protocol should also define the status codes, such as 200 OK, 404 Not Found, or 500 Internal Server Error, that indicate the outcome of the requests and responses.
