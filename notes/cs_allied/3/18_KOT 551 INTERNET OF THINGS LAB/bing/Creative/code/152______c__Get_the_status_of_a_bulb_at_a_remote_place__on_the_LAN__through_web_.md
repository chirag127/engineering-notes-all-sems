#### c) Get the status of a bulb at a remote place (on the LAN) through web.

- In this scenario, the bulb is connected to a **microcontroller** that acts as a web server. The web client can be any device that has a web browser, such as a laptop, a smartphone, or a tablet.
- The microcontroller and the web client are connected to the same **local area network (LAN)**, which is a network of devices that share a common communication medium, such as a cable or a wireless router. The LAN has a unique **IP address**, which is a numerical identifier that specifies the location of a device on the network.
- To get the status of the bulb, the web client needs to send a **HTTP request** to the microcontroller's IP address. HTTP stands for **Hypertext Transfer Protocol**, which is a standard protocol for communication between web servers and web clients. A HTTP request consists of a **method**, a **URL**, and optional **headers** and **body**. The method specifies the type of action to be performed, such as GET, POST, PUT, or DELETE. The URL specifies the resource to be accessed, such as a file, a directory, or a query. The headers provide additional information about the request, such as the content type, the user agent, or the authorization. The body contains the data to be sent to the server, such as form data, JSON data, or binary data.
- In this case, the web client can send a GET request to the microcontroller's IP address, with the URL containing a query parameter that specifies the bulb's ID. For example, if the microcontroller's IP address is 192.168.1.10 and the bulb's ID is 1, the URL can be http://192.168.1.10/?id=1. The query parameter can be used by the microcontroller to identify which bulb's status to send back.

It then reads the bulb's state from a **GPIO pin**, which is a general-purpose input/output pin that can be used to interface with external devices. The GPIO pin can have two values: HIGH (3.3V) or LOW (0V), corresponding to the bulb being on or off. The microcontroller then sends a **HTTP response** to the web client, containing the bulb's state. A HTTP response consists of a **status code**, a **status message**, and optional **headers** and **body**. The status code indicates the outcome of the request, such as 200 (OK), 404 (Not Found), or 500 (Internal Server Error). The status message provides a human-readable explanation of the status code. The headers provide additional information about the response, such as the content type, the content length, or the server name. The body contains the data to be sent to the client, such as HTML, XML, JSON, or binary data.
