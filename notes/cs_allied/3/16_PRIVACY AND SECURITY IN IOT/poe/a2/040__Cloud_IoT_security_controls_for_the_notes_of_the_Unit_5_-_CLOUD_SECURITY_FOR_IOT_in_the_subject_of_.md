### Cloud IoT security controls for the notes of the Unit 5 - CLOUD SECURITY FOR IOT

1. Data encryption: Data encryption is a must for any IoT deployment. All the data in transit as well as at rest should be encrypted. This ensures that even if the data is somehow stolen, it would be difficult for an attacker to decipher and make sense of it.

2. Secure boot: IoT devices should have secure boot capabilities to ensure that only authenticated software boots up on the device. This prevents an attacker from installing malicious software on the device to gain control.

3. Software updates: There should be a secure mechanism to remotely update the software/firmware on IoT devices. This ensures that security patches and bug fixes can be deployed in a timely manner to mitigate vulnerabilities. However, the software update process itself should be secured to prevent an attacker from pushing malicious updates.

4. Access control: There should be strong access control mechanisms to authenticate and authorize access to IoT devices and data. This could include authentication using certificates, access keys, etc. Authorization should be based on the principle of least privilege to minimize damage due to compromised credentials.

5. Monitoring: Continuously monitor the IoT environment to detect and prevent potential attacks. Look out for anomalies in device behavior, unauthorized access attempts, high-volume data exfiltration, etc. IoT devices and data can then be promptly investigated and remedial actions can be taken.

6. Incident response: Have a detailed incident response plan in place to handle IoT security incidents. The plan should define steps to contain attacks, revoke access, patch vulnerabilities, recover devices/data, and improve security to prevent similar incidents in the future. Regular drills/testing of the incident response plan is also important.
