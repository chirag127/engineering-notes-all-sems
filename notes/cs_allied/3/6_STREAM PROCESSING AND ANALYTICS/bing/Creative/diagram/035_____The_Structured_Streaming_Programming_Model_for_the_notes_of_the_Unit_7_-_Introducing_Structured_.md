### The Structured Streaming Programming Model

- Structured Streaming is a scalable and fault-tolerant stream processing engine built on the Spark SQL engine .
- The key idea in Structured Streaming is to treat a live data stream as a table that is being continuously appended   .
- This leads to a new stream processing model that is very similar to a batch processing model, where you can express your streaming computation the same way you would express a batch computation on static data .
- The main components of the Structured Streaming programming model are:
  - **Input sources**: These are the sources of streaming data, such as Kafka, Flume, socket, files, etc. You can read data from these sources using the `spark.readStream` method, which returns a `DataFrame` representing the unbounded input table.
  - **Output sinks**: These are the destinations where you can write the output of your streaming query, such as console, files, memory, Kafka, etc. You can write data to these sinks using the `writeStream` method, which returns a `StreamingQuery` object that can be used to manage and monitor the query.
  - **Transformations**: These are the operations that you can apply on the input `DataFrame` to produce the output `DataFrame`. You can use the same SQL or DataFrame API operations that you use for batch processing, such as `select`, `filter`, `join`, `group by`, `window`, etc. Some of these operations require specifying a watermark, which is a way of handling late and out-of-order data.
  - **Output modes**: These are the ways of updating the output sink with the result of the streaming query. You can choose from three output modes: `append`, `update`, or `complete`. The `append` mode only adds new rows to the output sink, the `update` mode only updates the rows that have changed since the last trigger, and the `complete` mode rewrites the entire output sink with the current result of the query. The output mode depends on the type of the query and the sink.
  - **Triggers**: These are the settings that control the frequency and timing of the query execution. You can specify a trigger using the `trigger` method, which takes a `Trigger` object as an argument. You can choose from different types of triggers, such as `ProcessingTime`, `Once`, or `Continuous`. The `ProcessingTime` trigger executes the query at a fixed interval, the `Once` trigger executes the query only once, and the `Continuous` trigger executes the query as fast as possible with a fixed checkpoint interval. The default trigger is `ProcessingTime(0)`, which means the query will be executed as soon as possible.
