### Understanding Latency-Throughput-Oriented Processing for the notes of the Unit 4 - Apache Spark as a Stream-Processing Engine in the subject of STREAM PROCESSING AND ANALYTICS

- Latency is the time taken to process a single record or a batch of records in a stream-processing system. Throughput is the number of records processed per unit time. Latency and throughput are two important performance metrics for stream-processing systems.
- Apache Spark is a popular framework for large-scale data processing that supports both batch and stream processing. Spark uses a micro-batch model for stream processing, where incoming data is divided into small batches and processed by Spark's core engine. This allows Spark to leverage its existing optimizations for batch processing, such as memory management, fault tolerance, and scheduling, for stream processing as well.
- However, micro-batching also introduces some trade-offs between latency and throughput. For example, a smaller batch size can reduce the latency, but it can also increase the overhead of scheduling and launching tasks. A larger batch size can increase the throughput, but it can also increase the latency and the memory consumption. Therefore, Spark users need to tune the batch size and other parameters to achieve the desired balance between latency and throughput for their applications.
- Spark also provides several features and techniques to improve the latency and throughput of stream processing, such as:

  - Structured Streaming: A high-level API for stream processing that allows users to express their logic using SQL queries or DataFrames. Structured Streaming automatically optimizes the execution plan, handles late and out-of-order data, and provides end-to-end exactly-once guarantees. Structured Streaming also supports adaptive query execution, which can dynamically adjust the query plan based on the data characteristics and the available resources.
  - Project Lightspeed: A recent initiative by Databricks to make Spark Structured Streaming faster and simpler. Project Lightspeed introduces several enhancements, such as:

    - Continuous Processing: An alternative execution mode for Structured Streaming that processes each record individually with low latency, instead of micro-batching. Continuous Processing can achieve sub-millisecond latency for some applications, but it does not support all the features of micro-batching, such as stateful operations and watermarking.
    - Delta Lake: An open-source storage layer that provides ACID transactions, schema enforcement, and versioning for data lakes. Delta Lake can be used as a source and a sink for Structured Streaming, and it can handle concurrent reads and writes, schema evolution, and data consistency. Delta Lake can also improve the performance of stream processing by using indexes, caching, and compaction.
    - Auto Loader: A feature that simplifies the ingestion of streaming data from various sources, such as cloud storage, Kafka, and IoT devices. Auto Loader can automatically detect new files and partitions, and load them into Delta Lake with minimal configuration. Auto Loader can also handle schema inference, schema evolution, and schema enforcement for streaming data.
    - SQL Analytics: A service that enables users to run interactive SQL queries on their data lake using a familiar interface and standard connectors. SQL Analytics can leverage the optimizations and features of Delta Lake and Structured Streaming, and provide fast and scalable query execution for streaming and historical data.
