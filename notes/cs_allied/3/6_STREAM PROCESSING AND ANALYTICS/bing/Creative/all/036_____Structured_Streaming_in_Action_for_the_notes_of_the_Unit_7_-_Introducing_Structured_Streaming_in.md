# Structured Streaming in Action

- Structured Streaming is a **scalable and fault-tolerant stream processing engine** built on the Spark SQL engine.
- Structured Streaming allows you to **take the same operations that you perform in batch mode** using Spark’s structured APIs, and **run them in a streaming fashion**. This can reduce latency and allow for incremental processing.
- Structured Streaming lets you **express computation on streaming data in the same way you express a batch computation on static data**. The Structured Streaming engine performs the computation incrementally and continuously updates the result as streaming data arrives.
- In Structured Streaming, a data stream is treated as a **table that is being continuously appended** . This leads to a stream processing model that is very similar to a batch processing model. You express your streaming computation as a standard batch-like query as on a static table, but Spark runs it as an incremental query on the unbounded input table.
- Structured Streaming provides **fast, scalable, fault-tolerant, end-to-end exactly-once stream processing** without the user having to reason about streaming. This is achieved by ensuring that the output of a streaming query is always equivalent to the result of executing a batch query on a prefix of the data.
- Structured Streaming supports two types of streaming queries: **output mode** and **trigger**. Output mode specifies what data will be written to the output sink when there is new data available in a streaming DataFrame/Dataset. Trigger specifies the trigger interval, or the processing rate, at which the streaming query will be executed.
- Structured Streaming supports various types of **input sources** and **output sinks**. Input sources are the sources of streaming data, such as Kafka, Flume, socket, rate, etc. Output sinks are the destinations where the results of the streaming query are written, such as console, file, memory, Kafka, etc.
- Structured Streaming also supports **event-time processing** and **watermarking**. Event-time processing is the processing of data based on the time embedded in the data itself, rather than the time when the data is received. Watermarking is the mechanism to specify how late the data is expected to be and accordingly handle old data or data that arrives out of order.
- Structured Streaming also provides **built-in operations** for common stream processing scenarios, such as aggregations, windowing, deduplication, etc. These operations can be applied on streaming DataFrames/Datasets using the same APIs as on static DataFrames/Datasets.
- Structured Streaming also allows **arbitrary stateful stream processing** using the mapGroupsWithState and flatMapGroupsWithState operations. These operations allow users to define their own stateful logic to update the state for each group and generate arbitrary output.
