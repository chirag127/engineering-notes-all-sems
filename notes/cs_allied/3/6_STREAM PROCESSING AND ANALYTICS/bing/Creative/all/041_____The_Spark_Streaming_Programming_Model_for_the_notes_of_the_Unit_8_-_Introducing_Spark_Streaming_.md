# The Spark Streaming Programming Model

Spark Streaming is an extension of the core Spark API that enables scalable, high-throughput, fault-tolerant stream processing of live data streams. Some of the key features of the Spark Streaming programming model are:

- **DStreams**: Spark Streaming provides a high-level abstraction called discretized stream or DStream, which represents a continuous stream of data. DStreams can be created either from input data streams from sources such as Kafka, Flume, and Kinesis, or by applying high-level operations on other DStreams. DStreams are internally represented as a sequence of RDDs, which are Spark's core abstraction for distributed datasets.
- **Transformations and Actions**: Spark Streaming supports a rich set of transformations and actions on DStreams, such as map, filter, reduce, join, window, updateStateByKey, foreachRDD, etc. These operations allow users to express complex stream processing logic using the familiar Spark API. Transformations are lazy and are only executed when an action is performed on the output DStream.
- **Output Operations**: Spark Streaming provides several output operations to write the processed data to external systems, such as saveAsHadoopFiles, saveAsTextFiles, foreachRDD, etc. These operations allow users to store the results of stream processing in various formats and locations, such as HDFS, S3, databases, etc.
- **Micro-batch Processing**: By default, Spark Streaming queries are executed using micro-batch processing model. The model treats streaming data as batch table, but in micro batches. Here the spark engine checks the input source periodically for new data arrival since the last micro batch ended. The frequency of checking the input source and processing the data is controlled by a parameter called batch interval, which can be set by the user. The batch interval determines the latency and throughput of the stream processing application.
- **Fault Tolerance**: Spark Streaming provides fault tolerance guarantees for both the input data and the processing logic. For the input data, Spark Streaming can handle data loss and duplication from unreliable sources, such as Kafka and Flume, by using a write-ahead log (WAL) mechanism. For the processing logic, Spark Streaming can recover from failures and stragglers by using Spark's resilient distributed datasets (RDDs), which can be recomputed from lineage information or checkpointed to a reliable storage.
- **Integration with Spark SQL and Structured Streaming**: Spark Streaming can interoperate with Spark SQL and Structured Streaming, which are higher-level APIs for structured and semi-structured data processing. Spark SQL allows users to query streaming data using SQL or DataFrame/Dataset API, and supports various streaming sources and sinks, such as Kafka, file, socket, etc. Structured Streaming is a scalable and fault-tolerant stream processing engine built on Spark SQL, which provides a declarative way to define streaming computations using SQL or DataFrame/Dataset API, and handles event-time processing, state management, and output mode automatically.
