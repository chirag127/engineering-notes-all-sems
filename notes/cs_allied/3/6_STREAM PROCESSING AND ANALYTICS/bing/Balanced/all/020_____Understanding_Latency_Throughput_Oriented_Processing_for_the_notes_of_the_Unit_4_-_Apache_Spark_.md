# Understanding Latency Throughput Oriented Processing

- Latency is the delay between an input and an output in a system. It measures how long it takes for a data item to be processed and delivered. Low latency means fast response time and high performance.
- Throughput is the rate at which a system can process data items. It measures how many data items can be processed and delivered per unit of time. High throughput means high efficiency and high capacity.
- Latency and throughput are two important metrics for evaluating the performance of a stream-processing system, such as Apache Spark. However, they are often inversely related, meaning that improving one may degrade the other.
- Latency oriented processing is a design approach that focuses on minimizing the latency of each data item. It aims to make the results available as soon as possible, without waiting for a large batch of data to be accumulated. This is suitable for applications that require real-time or near-real-time processing, such as fraud detection, anomaly detection, or interactive queries.
- Throughput oriented processing is a design approach that focuses on maximizing the throughput of the system. It aims to process as many data items as possible per unit of time, by exploiting parallelism and batching techniques. This is suitable for applications that require high efficiency and scalability, such as data analytics, machine learning, or batch processing.
- Apache Spark is a stream-processing engine that can support both latency oriented and throughput oriented processing, depending on the configuration and the application requirements. Spark provides two APIs for stream processing: Spark Streaming and Structured Streaming.
- Spark Streaming is based on the concept of micro-batches, which are small batches of data that are processed periodically. Spark Streaming allows the user to control the size and frequency of the micro-batches, which affect the trade-off between latency and throughput. Smaller and more frequent micro-batches result in lower latency but lower throughput, while larger and less frequent micro-batches result in higher latency but higher throughput.
- Structured Streaming is based on the concept of incremental processing, which is a continuous update of the results as new data arrives. Structured Streaming allows the user to specify the output mode and the trigger interval, which affect the trade-off between latency and throughput. The output mode determines how the results are updated, such as append, update, or complete. The trigger interval determines how often the results are updated, such as every second, every minute, or every hour. Lower trigger intervals result in lower latency but lower throughput, while higher trigger intervals result in higher latency but higher throughput.
