### Data Delivery Semantics: Microbatching and One-Element-at-a-Time

- Data delivery semantics refer to the guarantees that a system provides about how data is delivered from a source to a destination, such as a stream processor or a database.
- There are three main types of data delivery semantics: at-most-once, at-least-once, and exactly-once.
- At-most-once semantics mean that each data element is delivered once or not at all. This can result in data loss, but also low latency and high throughput. An example of a system that uses at-most-once semantics is UDP.
- At-least-once semantics mean that each data element is delivered at least once, but possibly more than once. This can result in data duplication, but also high reliability and fault tolerance. An example of a system that uses at-least-once semantics is TCP.
- Exactly-once semantics mean that each data element is delivered exactly once, with no data loss or duplication. This is the most desirable but also the most challenging semantics to achieve, as it requires coordination and synchronization among multiple components. An example of a system that uses exactly-once semantics is Kafka.
- Microbatching and one-element-at-a-time are two different approaches to process streaming data, which have different implications for data delivery semantics.
- Microbatching is a technique where incoming data is grouped into small batches and processed periodically, rather than individually and continuously. This can improve the performance and scalability of the system, as well as enable stateful and windowed operations. However, it also introduces some latency and complexity, as the system has to manage the batch size, frequency, and ordering. Microbatching can support at-least-once or exactly-once semantics, depending on how the system handles failures and retries. An example of a system that uses microbatching is Spark Streaming  .
- One-element-at-a-time is a technique where incoming data is processed as soon as it arrives, without waiting for a batch to form. This can reduce the latency and simplify the logic of the system, as well as enable real-time and event-driven operations. However, it also limits the performance and functionality of the system, as it cannot perform stateful or windowed operations. One-element-at-a-time can support at-most-once or at-least-once semantics, depending on how the system handles failures and acknowledgments. An example of a system that uses one-element-at-a-time is Storm.
