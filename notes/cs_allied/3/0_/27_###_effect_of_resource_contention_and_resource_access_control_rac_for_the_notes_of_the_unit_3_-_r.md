Unit 3: Resources Sharing in Real-Time Systems

Effect of Resource Contention and Resource Access Control (RAC)

In real-time systems, multiple tasks may need to access shared resources, such as memory, input/output devices, and communication networks. This can result in resource contention, where multiple tasks compete for the same resource, leading to delays and missed deadlines. 

To address the problem of resource contention, real-time systems use Resource Access Control (RAC) mechanisms to control access to shared resources. RAC mechanisms determine which tasks have access to which resources and when they have access to those resources. 

There are several types of RAC mechanisms, including priority-based resource allocation, rate-monotonic resource allocation, and deadline-based resource allocation. Priority-based resource allocation assigns a priority to each task, and tasks with higher priority have access to resources before tasks with lower priority. Rate-monotonic resource allocation assigns a fixed rate to each task, and tasks are scheduled based on their rate. Deadline-based resource allocation assigns a deadline to each task, and tasks are scheduled based on their deadline.

In conclusion, resource contention and Resource Access Control (RAC) are important aspects of real-time systems that deal with the sharing of resources. RAC mechanisms are used to control access to shared resources and to prevent resource contention, which can lead to delays and missed deadlines. Understanding the effect of resource contention and Resource Access Control (RAC) is an important aspect of the subject of Real-Time Systems.
