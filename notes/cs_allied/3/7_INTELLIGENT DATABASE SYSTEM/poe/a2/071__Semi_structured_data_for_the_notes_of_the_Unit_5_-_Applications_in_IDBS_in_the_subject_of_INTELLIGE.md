### Semi-structured data

- Semi-structured data does not have a fixed data model or schema.
- It contains tags or other markers to separate semantic elements and indicate hierarchies and types.
- Examples: XML, JSON, YAML, CSV, HTML, Emails, etc.
- These data formats are flexible and can evolve over time by adding or removing fields/attributes.
- This flexibility makes semi-structured data suitable for modern applications where data models tend to be dynamic.
- However, the lack of structure also makes it difficult to query and process the data efficiently.
- New data management techniques and systems have been developed to handle semi-structured data (e.g. XML databases).
- Modern databases also support semi-structured data along with SQL queries. Query languages for semi-structured data (e.g. XQuery for XML) are also available.

The key points to note about semi-structured data are:

1. It does not have a fixed schema. The tags/markers provide some structure.
2. It is flexible and can evolve by adding/removing fields.
3. The lack of structure makes querying and processing challenging.
4. Specialized techniques and systems are available to handle semi-structured data.
