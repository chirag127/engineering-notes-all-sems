#### Network architecture with reference to Computer Networks

The network architecture refers to the overall structure of a computer network. It defines how the components in a network are organized and interact with each other. The main components of a network architecture are:

- Network devices: Routers, switches, firewalls, etc. that transport and route data across the network.
- Protocols: Rules and standards that govern communication between network devices and applications. Examples are IP, TCP, UDP, etc.
- Services: Functionality offered to end-user applications such as email, web browsing, file sharing, etc.

The most common types of network architectures are:

1. Client-server: In this architecture, client machines request resources or services from centralized server machines. For example, a client machine may request access to files or databases on a server. This is a very common architecture for business and internet services.
2. Peer-to-peer: In this architecture, two or more computers share resources and services directly with each other instead of through a centralized server. Each machine acts as both a "client" and a "server". File sharing systems that allow users to share files directly between their machines are examples of peer-to-peer networks.
3. Distributed: In this architecture, components are decentralized and spread across multiple computers or servers. There is no centralized authority and the components work together to provide a coherent service. The World Wide Web is an example of a distributed network.

Some learning tricks to remember the network architectures:

- Think of a client-server network as a "master-slave" relationship where the server is the master and clients are the slaves that request services from the master.
- The peer-to-peer network has a "equal" relationship where every machine can act as both client and server.
- The distributed network has a "decentralized" structure with no single point of control.

The choice of a network architecture depends on factors such as scalability, cost, security, complexity, etc. There is no "one size fits all" architecture and each has its pros and cons which must be evaluated based on the specific use case and requirements.
