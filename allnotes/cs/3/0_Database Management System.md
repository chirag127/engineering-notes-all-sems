### Database System vs File System for the notes of the Unit 1 - Introduction in the subject of Database Management System

Database System vs File System:

Unit 1 of the subject of Database Management System introduces the concept of databases and the difference between database systems and file systems.

A database system is a collection of data that is organized and stored in a structured manner, making it easy to retrieve, manipulate, and update data. It uses a database management system (DBMS) to manage the data and provide users with a user-friendly interface for accessing and manipulating the data.

A file system, on the other hand, is a simple method of storing data on a computer. Files are stored in folders and can be manipulated using basic file management tools, such as copy, paste, and delete. However, file systems are not designed to handle large amounts of data and are not well suited for complex data relationships.

The main difference between a database system and a file system is the level of organization and structure of the data. In a database system, data is organized into tables, with each table having a specific structure and set of relationships with other tables. This makes it easier to manage and manipulate data, as well as to enforce data integrity and consistency.

In a file system, data is stored in individual files, with no inherent structure or relationships between files. This makes it difficult to manage and manipulate data, as well as to enforce data integrity and consistency.

In conclusion, a database system is a more sophisticated and structured method of storing data, while a file system is a simple method of storing data. Database systems are well suited for complex data relationships and large amounts of data, while file systems are better suited for small amounts of data that do not require a high level of structure or organization.

2. Relationships: Relationships in the ER diagram are represented as lines connecting entities. These relationships are transformed into foreign keys in the relational database, which link the tables representing the related entities. 

3. Attributes: Attributes in the ER diagram are represented as oval shapes attached to entities. Attributes become columns in the corresponding tables in the relational database. 

4. Normalization: During the reduction process, it is important to ensure that the tables are in normal form. This means that the data in the tables is organized in a way that minimizes data redundancy and ensures data consistency. 

5. Primary and Foreign Keys: In the relational database, each table must have a primary key, which is a unique identifier for each record in the table. Foreign keys are used to link tables and enforce referential integrity, ensuring that data in related tables is consistent.
