1. Inner Join: An inner join returns only the rows that have matching values in both tables being joined.

2. Outer Join: An outer join returns all the rows from one table and the matching rows from the other table. If there is no match, the result will contain NULL values.

3. Left Join: A left join returns all the rows from the left table and the matching rows from the right table. If there is no match, the result will contain NULL values for the right table.

4. Right Join: A right join returns all the rows from the right table and the matching rows from the left table. If there is no match, the result will contain NULL values for the left table.

5. Cross Join: A cross join returns the Cartesian product of the two tables, meaning that every row from the first table is paired with every row from the second table.

6. Natural Join: A natural join returns only the rows that have matching values in both tables being joined, based on the common columns between the two tables.

## Unit 4 - Enterprise Java Bean

Enterprise Java Beans (EJB) is a component-based architecture for developing and deploying server-side Java applications. The following are some of the key concepts related to EJB:

1. Components: EJB components are Java classes that provide business logic and data management services to client applications. EJB components are deployed on an EJB server, and can be accessed by client applications using remote method invocation (RMI) or web services.

2. Containers: EJB containers are runtime environments that manage the lifecycle of EJB components, providing services such as security, transaction management, and resource pooling.

3. Session Beans: Session beans are EJB components that provide business logic and data management services to client applications. Session beans can be stateful or stateless, depending on whether they maintain state between client invocations.

4. Entity Beans: Entity beans are EJB components that represent persistent data in a database. Entity beans provide a way to access, manipulate, and persist data in a database using Java.

5. Message-Driven Beans: Message-driven beans are EJB components that receive and process messages asynchronously. Message-driven beans can be used to implement message-oriented middleware (MOM) applications, such as JMS (Java Message Service) applications.

6. Remote Method Invocation (RMI): RMI is a Java technology for invoking methods on remote objects. RMI can be used to access EJB components from client applications.

7. Web Services: Web services are a standards-based way to access and exchange data over the Internet. EJB components can be exposed as web services, allowing client applications to access and use the services provided by the EJB components.

In this unit, you will learn about Enterprise Java Beans (EJB) and the key concepts related to it, including components, containers, session beans, entity beans, message-driven beans, remote method invocation (RMI), and web services.

This unit will provide a foundation for understanding the principles and practices of EJB, and for exploring the various concepts and techniques used in the field of Enterprise Java Development.

### Multithread programming for the notes of the Unit 1 - Introduction in the subject of Web Technology

Multithread programming is a programming model that involves multiple threads of execution within a single process. The following are some of the key concepts related to multithread programming:

1. Thread: A thread is a unit of execution within a process. A process can contain multiple threads, each of which can run concurrently.

2. Concurrent Execution: Concurrent execution is the execution of multiple threads simultaneously. This allows multiple tasks to be performed at the same time, improving the performance and responsiveness of the application.

3. Thread Synchronization: Thread synchronization is the process of coordinating the activities of multiple threads to ensure that they work together correctly. This can involve using synchronization primitives, such as locks and semaphores, to control access to shared resources.

4. Deadlocks: Deadlocks are a type of synchronization problem that occurs when two or more threads are blocked, waiting for each other to release a resource. Deadlocks can cause the application to hang or become unresponsive.

5. Race Conditions: Race conditions are a type of synchronization problem that occurs when the outcome of a multithreaded program depends on the order in which threads are executed. Race conditions can cause unpredictable behavior and incorrect results.

6. Thread Pool: A thread pool is a collection of worker threads that are managed by the operating system. Thread pools are used to manage the execution of multithreaded applications, and can improve performance by reducing the overhead associated with creating and destroying threads.
