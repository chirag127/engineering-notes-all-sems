Database System vs File System


A database system is a system that stores data in an organized and structured way, so that it can be accessed and manipulated easily. A file system, on the other hand, is a system that stores data in a unstructured way, so that it is difficult to access and manipulate.


Database System Concept and
Architecture


A database system is a collection of data that is organized in a specific way. This collection can be divided into two main types: relational and non-relational. A relational database system (RDBMS) is a database system that uses a relational model to store and access data. A non-relational database system (NoSQL) is a database system that does not use a relational model to store and access data.

The main difference between these two types of database systems is the way they store and access data. RDBMSs store data in tables, which are like folders in a file system. Each table has a name and a set of columns, which are like the files in a folder. Tables are connected to each other by relationships, which are like the links between files in a file system. NoSQL databases store data in documents, which are like the files in a file system. each document has a name and a set of fields, which are like the columns in a table. Documents are connected to each other by links, which are like the relationships between tables in an RDBMS.

The way data is accessed also differs between these two types of database systems. RDBMSs use a query language called SQL (Structured Query Language) to access data. NoSQL databases use a variety of different query languages, depending on the type of database.

Both relational and non-relational database systems have their own advantages and disadvantages. RDBMSs are better for storing data that is structured and easy to query. NoSQL databases are better for storing data that is unstructured and difficult to query.

Mapping Constraints


A mapping constraint is a restriction on the way data is transformed from one format to another. It is typically used to ensure that data conforms to a specific schema or to prevent loss of information during the conversion process.

Mapping constraints can be either structural or value-based. Structural constraints are imposed on the structure of the data, such as the number of fields or the order of the fields. Value-based constraints are imposed on the values of the data, such as the data type or the range of values.

Mapping constraints can be either mandatory or optional. Mandatory constraints must be satisfied in order for the data to be transformed. Optional constraints are not required, but if they are not satisfied, the data may be transformed in an unexpected way.

Mapping constraints can be either local or global. Local constraints are specific to a particular transformation, while global constraints are imposed across all transformations.

Mapping constraints can be either explicit or implicit. Explicit constraints are those that are explicitly stated in the transformation rules. Implicit constraints are those that are not stated explicitly, but are still necessary for the transformation to be successful.

Referential Integrity


In computer science, referential integrity is the consistency of data across multiple tables in a relational database. When data in one table relies on data in another table, referential integrity ensures that changes to the data in the first table do not create inconsistencies in the second table. For example, if a table of customers has a column for customer ID, and another table of orders has a column for customer ID, referential integrity would ensure that every customer ID in the orders table also exists in the customers table.

There are a few different ways to enforce referential integrity:

1. By using foreign keys: A foreign key is a column in one table that contains values that correspond to the primary key of another table. This way, when data is entered into the foreign key column, the database can check to see if that value exists in the other table. If it does not, the database will return an error.

2. By using triggers: A trigger is a piece of code that is automatically executed when certain conditions are met. For example, a trigger could be set up to check if a customer ID exists in the orders table before allowing it to be entered. If the customer ID does not exist, the trigger would prevent the data from being entered and return an error.

3. By using stored procedures: A stored procedure is a piece of code that is stored in the database and can be executed whenever needed. Like triggers, stored procedures can be used to check if data is consistent before allowing it to be entered into the database.

Enforcing referential integrity is important for maintaining the accuracy of data in a database. It can help to prevent data inconsistencies and errors, and can make it easier to spot problems when they do occur.
