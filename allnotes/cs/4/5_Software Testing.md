Advantages of Decision Table Based Testing include:
- It is a clear and concise way to represent complex business rules.
- It is easy to understand and maintain.
- It is a systematic and organized way to test the functional requirements of a system.

Disadvantages of Decision Table Based Testing include:
- It can be time-consuming to create the decision table.

This helps to uncover any errors or unexpected behavior that may occur when the system is processing values at the edge of the domain.

For example, if the input domain is a range of integers from 1 to 10, the test cases would include the values 0, 1, 10, 11, and other values that are close to the boundaries.

Boundary Value Analysis is often used in conjunction with other testing techniques, such as equivalence partitioning and decision table testing, to ensure that the system is thoroughly tested and all possible scenarios are covered.

### Performance Testing for the notes of the Unit 7 - Testing Web Applications in the subject of Software Testing
Performance Testing is a type of software testing that focuses on determining the speed, responsiveness, and stability of a system under a particular workload. It helps to identify bottlenecks and determine the maximum operating capacity of an application. 

There are several types of performance testing, including:
1. Load testing: Testing the application's behavior under normal and peak load conditions.
2. Stress testing: Testing the application's behavior when it is pushed beyond normal limits.
3. Endurance testing: Testing the application's behavior over an extended period of time.
4. Spike testing: Testing the application's behavior when it experiences sudden, extreme increases in load.

Performance testing should be done in a controlled environment using tools such as Apache JMeter, LoadRunner, Gatling, etc. The results of performance testing can be used to optimize the application's performance and scalability.

It is important to note that performance testing should be an ongoing process and not just a one-time event. This is because changes to the system, such as new features or increased load, can impact the application's performance.
