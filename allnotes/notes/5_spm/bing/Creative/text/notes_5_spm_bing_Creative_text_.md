

# Software Project Management

Software project management is the process of planning, organizing, leading, and controlling software projects. It involves the following activities:

- **Project initiation**: This is the first phase of software project management, where the project scope, objectives, deliverables, stakeholders, and constraints are defined. The project charter, which is a document that summarizes the project vision, goals, and scope, is also created in this phase.
- **Project planning**: This is the second phase of software project management, where the project activities, resources, schedule, budget, quality, risk, and communication plans are developed. The project plan, which is a document that describes how the project will be executed, monitored, and controlled, is also created in this phase.
- **Project execution**: This is the third phase of software project management, where the project team performs the tasks and produces the deliverables according to the project plan. The project manager monitors and controls the project performance, quality, scope, schedule, budget, risk, and communication, and reports the project status to the stakeholders.
- **Project closure**: This is the fourth and final phase of software project management, where the project is formally completed and closed. The project manager verifies that all the project deliverables have been accepted by the stakeholders, and that all the project requirements have been met. The project manager also conducts a project review, where the project outcomes, lessons learned, best practices, and recommendations for future projects are documented and communicated. The project manager also releases the project resources and closes the project contracts.



## Unit - 1 - Project Evaluation and Project Planning

- Project evaluation is the process of assessing the feasibility, desirability, and viability of a software project before initiating it.
- Project planning is the process of defining the scope, objectives, tasks, resources, schedule, budget, and quality standards of a software project after it has been evaluated and approved.
- Project evaluation and planning are essential for software project management, as they help to align the project with the organizational goals, stakeholder expectations, and technical requirements, and to ensure the project is realistic, achievable, and beneficial.
- Project evaluation and planning involve the following steps:

  - **Identify the project idea and need**: This step involves identifying the problem or opportunity that the project aims to address, and the potential benefits and risks of pursuing it.
  - **Conduct a feasibility study**: This step involves analyzing the technical, economic, social, legal, and environmental aspects of the project, and determining whether the project is feasible and desirable in terms of costs, benefits, resources, time, and quality.
  - **Prepare a project proposal**: This step involves preparing a document that summarizes the project idea, need, feasibility, objectives, scope, deliverables, assumptions, constraints, risks, and stakeholders, and requesting approval from the decision-makers.
  - **Define the project scope and objectives**: This step involves defining the boundaries, requirements, and expected outcomes of the project, and ensuring they are clear, specific, measurable, achievable, relevant, and time-bound.
  - **Identify the project tasks and dependencies**: This step involves breaking down the project scope into manageable and interrelated tasks, and identifying the logical and temporal relationships among them.
  - **Estimate the project resources and duration**: This step involves estimating the amount and type of resources (such as human, material, financial, and information) and time needed to complete each task, and applying appropriate estimation techniques and tools.
  - **Develop the project schedule and budget**: This step involves allocating the resources and duration to each task, and creating a timeline and a cost plan for the project, and applying appropriate scheduling and budgeting techniques and tools.
  - **Define the project quality standards and metrics**: This step involves defining the criteria and measures for evaluating the quality of the project processes and products, and applying appropriate quality management techniques and tools.
  - **Identify and analyze the project risks**: This step involves identifying the potential threats and opportunities that may affect the project, and analyzing their probability and impact, and applying appropriate risk management techniques and tools.
  - **Communicate the project plan**: This step involves communicating the project plan to the project team and stakeholders, and obtaining their feedback and approval, and applying appropriate communication management techniques and tools.

### Activities in Software Project Management

Software project management is the process of leading, organizing, and controlling a software development project. It involves a range of activities, such as:

- **Scope management**: This activity involves defining and controlling the scope of the software product, including its features, functions, and requirements. Scope management helps to ensure that the project delivers what the client expects and avoids scope creep or gold plating.
- **Project planning and tracking**: This activity involves creating and maintaining a project plan that outlines the tasks, milestones, deliverables, dependencies, resources, and schedule of the project. Project planning and tracking helps to ensure that the project is on track, on time, and on budget .
- **Project resource management**: This activity involves identifying, acquiring, and managing the human, physical, and financial resources needed for the project. Project resource management helps to optimize the allocation and utilization of resources, as well as to resolve any resource conflicts or shortages .
- **Scheduling management**: This activity involves estimating and assigning the duration and effort of each task, as well as the sequence and dependencies of tasks. Scheduling management helps to create a realistic and feasible project schedule that meets the project deadlines and constraints .
- **Project communication management**: This activity involves planning, executing, and monitoring the communication among the project stakeholders, such as the client, the project team, the management, and the end-users. Project communication management helps to ensure that the project information is clear, consistent, timely, and relevant .
- **Estimation management**: This activity involves estimating the size, cost, effort, and quality of the software product and the project. Estimation management helps to provide a basis for planning, tracking, and controlling the project, as well as to manage the expectations and risks of the project .
- **Project risk management**: This activity involves identifying, analyzing, prioritizing, and mitigating the potential risks that may affect the project. Project risk management helps to reduce the uncertainty and impact of the risks, as well as to increase the chances of project success .
- **Project configuration management**: This activity involves managing the changes and versions of the software product and the project artifacts, such as the requirements, design, code, and documentation. Project configuration management helps to ensure the integrity, traceability, and quality of the software product and the project .

These activities are not necessarily sequential or independent, but rather iterative and interrelated. They may vary depending on the size, complexity, and nature of the software project, as well as the software development methodology and the project management approach used .



### Methodologies in Software Project Management

- A methodology is a set of principles, tools and techniques that are used to plan, execute and manage projects.
- A methodology helps project managers lead team members and manage work while facilitating team collaboration.
- There are many different methodologies, and they all have pros and cons.
- Some of the most popular methodologies in software project management are:

  - **Agile**: Agile is a flexible and iterative approach that focuses on delivering value to customers in short cycles called sprints. Agile principles include fast responses to feedback and changes, effective communication, and collaborative efforts. Agile methods include Scrum, Kanban, Extreme Programming, and others .
  - **Waterfall**: Waterfall is a linear and sequential approach that follows a predefined set of phases, such as requirements, design, development, testing, and deployment. Waterfall principles include clear documentation, upfront planning, and strict control. Waterfall is suitable for projects with stable and well-defined requirements .
  - **Scrum**: Scrum is an agile framework that divides a project into small and manageable units called user stories, which are prioritized and delivered in fixed-length iterations called sprints. Scrum principles include self-organizing teams, frequent reviews, and continuous improvement. Scrum roles include the product owner, the scrum master, and the development team   .
  - **PRINCE2**: PRINCE2 is a structured and process-based methodology that covers the entire lifecycle of a project, from initiation to closure. PRINCE2 principles include defined roles and responsibilities, tailored approach, business justification, and quality focus. PRINCE2 processes include starting, directing, initiating, controlling, managing, and closing a project.
  - **Lean**: Lean is a methodology that aims to eliminate waste and maximize value in software development. Lean principles include optimizing the whole, delivering fast, building quality in, empowering the team, and learning continuously. Lean methods include value stream mapping, pull systems, kanban boards, and others .
  - **Six Sigma**: Six Sigma is a methodology that focuses on improving the quality and efficiency of software processes by reducing defects and variations. Six Sigma principles include customer focus, data-driven decision making, and systematic problem solving. Six Sigma methods include DMAIC (define, measure, analyze, improve, control), DMADV (define, measure, analyze, design, verify), and others .
  - **Critical path method**: Critical path method is a technique that identifies the longest sequence of activities that must be completed on time for a project to finish on schedule. Critical path method helps project managers estimate the duration, cost, and resources of a project, and identify the critical and non-critical activities. Critical path method also helps project managers monitor and control the progress and performance of a project .
  - **Gantt chart method**: Gantt chart method is a tool that visually represents the tasks, dependencies, durations, and milestones of a project on a horizontal timeline. Gantt chart method helps project managers plan, schedule, and track the activities and resources of a project, and communicate the status and progress of a project to stakeholders .

- These are some of the most common methodologies in software project management, but there are many others that can be used depending on the nature, scope, and complexity of a project. Project managers should choose the methodology that best suits their project goals, requirements, and constraints.

### Categorization of Software Projects in SPM

Software Project Management (SPM) is a sub-field of Project Management in which software projects are planned, implemented, monitored and controlled . Software projects can be categorized based on different criteria, such as:

- **By Development Model**: This refers to the methodology or process used to develop the software product, such as Agile, Waterfall, Iterative, and Incremental. Each model has its own advantages and disadvantages, depending on the nature and requirements of the project.
- **By Platform**: This refers to the type of hardware or software environment in which the software product operates, such as Desktop, Mobile, Web-based, and Embedded. Each platform has its own characteristics and challenges, such as performance, security, compatibility, and usability.
- **By Scope**: This refers to the size and complexity of the software project, such as Small, Medium, and Large. The scope of the project affects the resources, time, cost, and quality of the software product, as well as the risks and uncertainties involved.
- **By User Interaction**: This refers to the mode of communication between the software product and its users, such as Batch and Interactive. Batch software products process data without user intervention, while interactive software products require user input and feedback.
- **By Maturity Level**: This refers to the stage of development or evolution of the software product, such as New, Legacy, and Mature. New software products are those that are being developed for the first time, legacy software products are those that are outdated or obsolete, and mature software products are those that are stable and reliable.
- **By Open-Source Software Participation**: This refers to the extent of involvement or contribution of the software project to the open-source software community, such as None, Partial, or Full. Open-source software projects are those that allow anyone to access, modify, and distribute the source code of the software product, while closed-source software projects are those that restrict or prohibit such activities.
- **By Delivery Method**: This refers to the way the software product is deployed or distributed to the end-users, such as Internal, Outsource, Hosted, or Cloud-Based. Internal software products are those that are developed and used within the same organization, outsource software products are those that are developed by a third-party vendor and delivered to the client, hosted software products are those that are installed and maintained on a remote server and accessed via the internet, and cloud-based software products are those that are provided as a service over the internet.

These are some of the common ways of categorizing software projects in SPM. However, there may be other ways of categorizing software projects based on different factors or perspectives. The purpose of categorizing software projects is to help the software project manager and the software development team to understand the nature and characteristics of the software project, and to plan and manage it accordingly.

### Management Principles in SPM

Software Project Management (SPM) is the process of planning, organizing, leading, and controlling software projects. SPM aims to deliver software products that meet the customer's requirements, budget, and schedule, while ensuring quality, efficiency, and effectiveness. SPM involves applying various principles, methods, tools, and techniques to manage the software development life cycle. Some of the management principles in SPM are:

- Define and document requirements: The software project manager should elicit, analyze, validate, and document the functional and non-functional requirements of the software product. This helps to establish a clear and shared understanding of what the software should do and how it should perform. Requirements documentation also serves as a basis for planning, estimation, design, testing, and evaluation of the software product.

- Manage changes effectively: The software project manager should anticipate, monitor, and control changes that may occur during the software development process. Changes may arise from changing customer needs, new technologies, errors, or feedback. The software project manager should use a change management process that defines how changes are requested, approved, implemented, and verified. The change management process should also assess the impact of changes on the scope, cost, quality, and schedule of the software project.

- Prioritize projects: The software project manager should prioritize the software projects based on their strategic value, urgency, feasibility, and alignment with the organizational goals. The software project manager should use a portfolio management approach that evaluates and selects the software projects that best support the business objectives and maximize the return on investment. The portfolio management approach should also balance the available resources, risks, and dependencies among the software projects  .

- Maintain quality: The software project manager should ensure that the software product meets the quality standards and expectations of the customer and the stakeholders. The software project manager should use a quality management process that defines the quality criteria, metrics, methods, and tools for measuring and improving the quality of the software product. The quality management process should also involve quality assurance, quality control, and quality improvement activities throughout the software development life cycle.

- Utilize automation: The software project manager should leverage automation tools and techniques to increase the efficiency, effectiveness, and reliability of the software development process. Automation can help to reduce human errors, save time and cost, and enhance quality and consistency. The software project manager should use automation for tasks such as requirements management, configuration management, testing, deployment, and monitoring.

- Establish communication protocols: The software project manager should facilitate clear, timely, and accurate communication among the software project team, the customer, and the stakeholders. The software project manager should use a communication management process that defines the communication objectives, channels, methods, and frequency for exchanging information and feedback. The communication management process should also address the communication challenges, risks, and issues that may arise during the software development process.

- Manage risk: The software project manager should identify, analyze, evaluate, and mitigate the potential risks that may affect the software project. Risks may include technical, operational, financial, legal, or environmental uncertainties that may cause negative outcomes or deviations from the planned objectives. The software project manager should use a risk management process that defines the risk identification, assessment, response, and monitoring strategies and actions. The risk management process should also prioritize the risks based on their probability and impact.

- Utilize a systematic approach: The software project manager should use a systematic approach that guides the software development process from initiation to closure. The systematic approach should be based on a software development methodology that defines the phases, activities, tasks, deliverables, and roles and responsibilities of the software development process. The software development methodology should also be aligned with the software project characteristics, such as the size, complexity, scope, and domain.

### Stepwise Project Planning in SPM

Stepwise project planning in software project management (SPM) is the process of breaking down the development process into smaller, manageable steps. This makes it easier for the project manager to plan and track progress, as each step is clearly defined. It also allows for tasks to be divided up and delegated to different team members .

The steps involved in stepwise project planning are  :

- **Step 0: Select project.** This involves choosing a project that is feasible, beneficial, and aligned with the organization's goals and strategies.
- **Step 1: Identify project scope and objectives.** This involves defining the boundaries, deliverables, and expected outcomes of the project, as well as the criteria for success and acceptance.
- **Step 2: Identify project infrastructure.** This involves identifying the resources, roles, responsibilities, and communication channels that will support the project execution and management.
- **Step 3: Analyze project characteristics.** This involves analyzing the complexity, size, uncertainty, and interdependencies of the project, as well as the risks and assumptions involved.
- **Step 4: Identify project products and activities.** This involves identifying the main outputs and inputs of the project, as well as the tasks and subtasks required to produce them. This can be done using techniques such as work breakdown structure (WBS) and product breakdown structure (PBS).
- **Step 5: Estimate effort for each activity.** This involves estimating the time, cost, and quality of each activity, using methods such as expert judgment, analogy, parametric, or bottom-up estimation.
- **Step 6: Identify activity risks.** This involves identifying the potential threats and opportunities that may affect the project, as well as their probability and impact. This can be done using techniques such as risk identification, risk analysis, and risk response planning.
- **Step 7: Allocate resources.** This involves assigning the available resources, such as human, material, financial, and technological, to the activities, based on their availability, suitability, and priority. This can be done using techniques such as resource leveling, resource allocation, and resource scheduling.
- **Step 8: Review/publicize plan.** This involves reviewing the plan for completeness, consistency, and feasibility, as well as communicating it to the relevant stakeholders, such as the project team, the project sponsor, the customer, and the end-users.
- **Step 9: Execute plan/lower levels of planning.** This involves implementing the plan and monitoring and controlling the project performance, as well as refining and updating the plan as needed. This can be done using techniques such as project execution, project tracking, project reporting, and project change management.







### Software Process and Process Models

- A software process is a set of activities for designing, implementing, and testing a software system.
- A software process model is an abstraction of the software process, which specifies the stages and order of the activities .
- Software process models help provide a visual representation of the development process for both the team and the customer to review.
- Software process models also help project managers plan their processes, estimate costs, identify challenges and communicate with teams and customers.
- There are different types of software process models, each with its own advantages and disadvantages. Some of the common software process models are :
  - Waterfall: The waterfall software process model is one of the simplest and most effective software process models. It involves a linear sequence of stages, such as requirements analysis, design, implementation, testing, and maintenance. Each stage must be completed before moving to the next one. The waterfall model is easy to understand and follow, but it does not allow for changes or feedback during the development process.
  - Prototyping: Prototyping is another common type of software process model. Prototyping involves creating a working model of the software system, which is then evaluated by the customer and refined based on the feedback. Prototyping allows for early detection of errors and customer satisfaction, but it can also be time-consuming and costly.
  - Incremental: Incremental software process model is a type of software process model that involves developing the software system in small increments, each of which adds some functionality to the system. Each increment is tested and delivered to the customer, who can provide feedback and request changes. Incremental model allows for flexibility and customer involvement, but it also requires careful planning and coordination.
  - Spiral: Spiral software process model is a type of software process model that combines the features of the waterfall and prototyping models. It involves a cyclic process of four phases: planning, risk analysis, engineering, and evaluation. Each cycle produces a prototype of the software system, which is then reviewed by the customer and improved based on the feedback. Spiral model allows for risk management and customer satisfaction, but it also requires a lot of documentation and expertise.
  - Agile: Agile software process model is a type of software process model that emphasizes collaboration, communication, and adaptability. It involves a series of short iterations, each of which delivers a working product to the customer, who can provide feedback and request changes. Agile model allows for rapid delivery and customer satisfaction, but it also requires a high level of customer involvement and trust.
  - Rational Unified Process (RUP): RUP is a type of software process model that is based on the best practices of software engineering. It involves four phases: inception, elaboration, construction, and transition. Each phase consists of several iterations, each of which follows a disciplined process of analysis, design, implementation, and testing. RUP allows for quality assurance and risk management, but it also requires a lot of resources and expertise.
  - Extreme Programming (XP): XP is a type of software process model that is based on the principles of agile development. It involves a series of short iterations, each of which follows a set of practices, such as pair programming, test-driven development, code reviews, and refactoring. XP allows for high-quality and customer satisfaction, but it also requires a high level of skill and discipline.



### Choice of Process Models in Software Project Management

- A software process model is an abstraction of the software development process that specifies the stages and order of the activities involved in designing, implementing, and testing a software system.
- There are different types of software process models, each with its own advantages and disadvantages, depending on the nature, size, complexity, and scope of the software project  .
- Some of the most popular and important software process models are:
  - Waterfall model: A linear sequential model that divides the software project into distinct phases, such as requirements analysis, design, implementation, testing, and maintenance. Each phase must be completed before the next one can begin, and there is no overlap or iteration between phases. This model is simple, easy to follow, and suitable for well-defined and stable projects with clear requirements and minimal changes. However, it is also rigid, inflexible, and unable to accommodate changing customer needs or feedback. It also assumes that all the risks and problems can be identified upfront, which is often unrealistic in software development.
  - V model: An extension of the waterfall model that emphasizes the verification and validation of the software product at each phase. It establishes a one-to-one correspondence between the phases of specification and testing, such as requirements specification and acceptance testing, design specification and system testing, and so on. This model ensures that the quality of the software product is checked and assured at every stage, and that the defects are detected and fixed early. However, it also inherits the drawbacks of the waterfall model, such as lack of flexibility, adaptability, and customer involvement.
  - Incremental model: A model that divides the software project into smaller and manageable increments, each of which delivers a subset of the functionality and can be developed and delivered independently. The increments are prioritized based on the customer value and feedback, and are integrated into the final product as they are completed. This model allows for early delivery of working software, frequent customer feedback, and better risk management. However, it also requires careful planning, coordination, and integration of the increments, and may result in inconsistent or incompatible software architecture and design.
  - Spiral model: A model that combines the iterative and risk-driven aspects of the incremental model with the systematic and disciplined aspects of the waterfall model. It consists of four phases: planning, risk analysis, engineering, and evaluation. The software project passes through these phases repeatedly in a spiral manner, with each iteration producing a more refined and complete version of the software product. This model allows for flexibility, adaptability, and customer involvement, as well as risk identification and mitigation at every iteration. However, it also requires a high level of expertise, experience, and commitment from the project team, and may be costly and complex to implement and manage.
  - Agile model: A model that follows a set of principles and values that emphasize customer satisfaction, collaboration, responsiveness, and quality. It advocates an iterative, incremental, and adaptive approach to software development, where the software product is delivered in short and frequent cycles, called sprints. Each sprint involves the collaboration of cross-functional teams that work together to plan, design, implement, test, and deliver a potentially shippable product increment. This model enables rapid delivery of working software, continuous customer feedback, and improvement, and high customer satisfaction. However, it also requires a high level of communication, coordination, and trust among the project team and the customer, and may not be suitable for large, complex, or regulated projects.
- The choice of a software process model for a software project depends on various factors, such as :
  - The nature and scope of the project: The size, complexity, duration, and objectives of the project determine the level of detail, formality, and rigor required in the software process model. For example, a large, complex, and long-term project may benefit from a more structured and disciplined model, such as the waterfall or the V model, while a small, simple, and short-term project may benefit from a more flexible and agile model, such as the incremental or the agile model.
  - The requirements and expectations of the customer: The clarity, stability, and priority of the customer requirements and expectations influence the degree of customer involvement, feedback, and satisfaction in the software process model. For example, a project with clear, stable, and well-defined requirements may benefit from a more linear and sequential model, such as the waterfall or the V model, while a project with vague, changing, and evolving requirements may benefit from a more iterative and incremental model,



### Rapid Application Development in Software Project Management

- Rapid application development (RAD) is an agile software development process that primarily focuses on the effective and timely development of software applications .
- RAD typically involves using pre-built, reusable code libraries and frameworks and agile development techniques such as incremental development and prototyping.
- RAD was a response to plan-driven waterfall processes, developed in the 1970s and 1980s, such as the Structured Systems Analysis and Design Method (SSADM). One of the problems with these methods is that they were based on a traditional engineering model used to design and build things like bridges and buildings.
- RAD aims to deliver software applications faster and with higher quality by reducing the complexity and uncertainty of software development projects.
- RAD consists of four main phases: requirements planning, user design, construction, and cutover.
  - Requirements planning: This phase involves gathering and analyzing the business needs and objectives of the software project. The scope, budget, and schedule of the project are also defined in this phase.
  - User design: This phase involves creating and testing prototypes of the software application with the end-users and stakeholders. The prototypes are used to elicit feedback and refine the requirements and design of the application.
  - Construction: This phase involves developing and integrating the software components and modules using the pre-built code libraries and frameworks. The construction phase is iterative and incremental, meaning that the software application is built and tested in small chunks that are added to the previous ones.
  - Cutover: This phase involves deploying and transitioning the software application to the production environment. The cutover phase also includes training, documentation, and maintenance activities.
- RAD has several benefits, such as:
  - Faster delivery: RAD can reduce the time to market of software applications by minimizing the planning and documentation overhead and by enabling parallel development and testing activities.
  - Higher quality: RAD can improve the quality of software applications by incorporating user feedback and testing throughout the development process and by using proven code libraries and frameworks.
  - Greater flexibility: RAD can accommodate changing requirements and expectations by allowing frequent revisions and refinements of the software application based on user feedback and testing results.
  - Higher user satisfaction: RAD can increase the user satisfaction and acceptance of software applications by involving them in the design and development process and by delivering software applications that meet their needs and expectations.
- RAD also has some challenges, such as:
  - Higher risk: RAD can increase the risk of software failures and defects by relying on untested or incompatible code libraries and frameworks and by skipping or reducing some quality assurance activities.
  - Higher cost: RAD can increase the cost of software development by requiring more skilled and experienced developers and by using more expensive code libraries and frameworks.
  - Higher complexity: RAD can increase the complexity of software development by requiring more coordination and communication among the developers, users, and stakeholders and by managing multiple iterations and prototypes of the software application.



### Agile Methods in Software Project Management

- Agile methods are a set of project management frameworks that break projects down into several dynamic phases, commonly known as sprints.
- Agile methods are based on delivering requirements iteratively and incrementally throughout the life cycle.
- Agile methods are an iterative methodology, meaning that after every sprint, teams reflect and look back to see if there was anything that could be improved so they can adjust their strategy for the next sprint.
- Agile methods are suitable for projects that have changing or unclear requirements, need frequent feedback from users and stakeholders, and value working software over comprehensive documentation.
- Agile methods are an umbrella term for various specific approaches, such as scrum, kanban, extreme programming, lean, and DSDM .
- Agile methods have some common principles and values, such as customer satisfaction, collaboration, self-organization, adaptability, simplicity, and continuous improvement.
- Agile methods have some common practices and tools, such as user stories, backlog, burndown chart, daily stand-up, retrospective, and online Kanban board  .



### Dynamic System Development Method in spm

- Dynamic System Development Method (DSDM) is an agile project delivery framework that was initially used as a software development method.

### Effort and Cost Estimation Techniques in SPM

- Software Project Management (SPM) is the process of planning, organizing, monitoring, and controlling software projects.
- One of the most important part in SPM is cost and effort estimation. Cost estimation is the process of predicting the amount of money required to develop a software project. Effort estimation is the process of predicting the amount of human resources and time required to develop a software project.
- Accurate cost and effort estimation is critical for both developers and customers to make informed decisions, allocate resources, monitor progress, and evaluate quality.
- However, conducting cost and effort estimation is not an easy task, as software projects are often complex, uncertain, and dynamic. Therefore, various techniques have been proposed to assist the estimation process.
- Some of the common techniques are:

  - **Decomposition techniques**: These techniques take a divide and conquer approach. They break down a project into smaller and manageable units, such as functions, modules, or activities, and estimate the size, effort, and cost of each unit. Then, they aggregate the estimates of the units to obtain the estimate of the whole project. Examples of decomposition techniques are Function Point Analysis (FPA) and Work Breakdown Structure (WBS).
  - **Analogy techniques**: These techniques use historical data from similar completed projects to estimate the size, effort, and cost of the current project. They rely on the assumption that projects with similar characteristics will have similar outcomes. Examples of analogy techniques are Regression Analysis and Case-Based Reasoning (CBR).
  - **Algorithmic techniques**: These techniques use mathematical models and formulas to estimate the size, effort, and cost of a project based on some input parameters, such as lines of code, number of functions, or complexity factors. They rely on the assumption that there is a relationship between the input parameters and the output measures. Examples of algorithmic techniques are Constructive Cost Model (COCOMO) and Putnam Model.
  - **Expert judgment techniques**: These techniques use the opinions and experiences of experts to estimate the size, effort, and cost of a project. They rely on the assumption that experts have sufficient knowledge and intuition to provide reliable estimates. Examples of expert judgment techniques are Delphi Method and Wideband Delphi Method.

- Each technique has its own advantages and disadvantages, and no single technique can guarantee accurate estimates for all projects. Therefore, it is important to choose the appropriate technique based on the project characteristics, the availability of data, and the accuracy requirements. It is also advisable to use multiple techniques and compare the results to improve the confidence and validity of the estimates.

### COCOMO II in SPM

- COCOMO II stands for Constructive Cost Model II, which is a software cost estimation model developed at the University of Southern California  .
- COCOMO II is a revised version of the original COCOMO model published in 1981, which was based on the analysis of 63 software projects  .
- COCOMO II is designed to address the software development practices in the 1990s and 2000s, such as rapid application development, reuse, prototyping, and object-oriented programming .
- COCOMO II consists of three sub-models: Application Composition, Early Design, and Post-Architecture .
- Application Composition model is used for estimating the effort and schedule of projects that use rapid application development tools or application generators .
- Early Design model is used for estimating the effort and schedule of projects in the early stages of software development, when only the size and functionality of the system are known .
- Post-Architecture model is used for estimating the effort and schedule of projects after the software architecture is defined and the detailed design is underway .
- COCOMO II uses the concept of source lines of code (SLOC) as the primary measure of software size, and adjusts it based on various factors, such as reuse, complexity, and productivity  .
- COCOMO II also uses a set of 17 cost drivers and 5 scale factors to account for the effects of different attributes of the software product, the platform, the personnel, and the project on the effort and schedule  .
- COCOMO II provides a set of equations and coefficients to calculate the effort and schedule based on the adjusted SLOC, the cost drivers, and the scale factors  .
- COCOMO II is a well-tested and widely used model that provides about 20% cost and 70% time estimate accuracy. It can be applied to various types of software projects, such as application generator, system integration, or infrastructure developments. It can also be calibrated and tailored to specific organizational contexts and environments.

### Forward Pass & Backward Pass Techniques in SPM

- SPM stands for Software Project Management, which is the process of planning, organizing, executing, monitoring and controlling software projects.
- Forward pass and backward pass are two techniques used in SPM to analyze the project network diagram and determine the project duration, critical path, and slack/float time of each activity.
- A project network diagram is a graphical representation of the sequence and dependencies of the project activities, usually using nodes to represent activities and arrows to represent dependencies.
- Forward pass is a technique to move forward through the network diagram from the start node to the end node, calculating the early start (ES) and early finish (EF) dates of each activity.
  - ES is the earliest possible date that an activity can start, based on the EF of its predecessors (or the project start date if it has no predecessors).
  - EF is the earliest possible date that an activity can finish, calculated by adding the activity duration to the ES.
  - The forward pass can be done using the following formula: EF = ES + duration - 1
- Backward pass is a technique to move backward through the network diagram from the end node to the start node, calculating the late start (LS) and late finish (LF) dates of each activity.
  - LS is the latest possible date that an activity can start without delaying the project completion date, based on the LF of its successors (or the project end date if it has no successors).
  - LF is the latest possible date that an activity can finish without delaying the project completion date, calculated by subtracting the activity duration from the LS.
  - The backward pass can be done using the following formula: LS = LF - duration + 1
- The forward pass and backward pass can be used to identify the critical path and the slack/float time of each activity.
  - The critical path is the longest path in the network diagram, which determines the minimum project duration. It consists of the activities that have zero slack/float time, meaning they cannot be delayed without affecting the project completion date.
  - The slack/float time is the amount of time that an activity can be delayed without affecting the project completion date. It can be calculated by subtracting the EF from the LF, or the ES from the LS, of the same activity.
  - The slack/float time can be used to prioritize the activities, allocate resources, and manage risks in the project. Activities with low or zero slack/float time are more critical and require more attention, while activities with high slack/float time are more flexible and can be adjusted if needed.



### Critical Path Method (CPM) in SPM

- Critical Path Method (CPM) is a technique where you identify tasks that are necessary for project completion and determine scheduling flexibilities.
- A critical path in project management is the longest sequence of activities that must be finished on time in order for the entire project to be complete.
- CPM helps you to plan, monitor, and control your project by finding the optimal sequence and duration of tasks.
- There are six steps in the CPM:

  - Step 2: Establish Dependencies (Activity Sequence). Determine the logical order of the tasks and identify which tasks depend on others for their start or finish.
  - Step 3: Draw the Network Diagram. Use a graphical representation of the tasks and their dependencies to show the flow of the project. Each task is represented by a node and each dependency is represented by an arrow.
  - Step 4: Estimate Activity Completion Time. Assign a realistic estimate of how long each task will take to complete, based on the resources and constraints available.
  - Step 5: Identify the Critical Path. Calculate the earliest and latest start and finish times for each task, using the forward and backward pass methods. The critical path is the path with the longest duration, which determines the minimum time required to complete the project. Any delay in the critical path will delay the project completion.
  - Step 6: Update the Critical Path Diagram to Show Progress. Monitor the actual progress of the tasks and compare them with the planned estimates. Adjust the network diagram and the critical path accordingly, and take corrective actions if necessary.
- CPM is a useful tool for managing complex and uncertain projects, as it helps you to identify the most important tasks, optimize the use of resources, and avoid schedule risks.

Some of the benefits of performing risk assessment in project management are:

- Reduction of project risk exposure by identifying and mitigating the sources and consequences of uncertainty and variability.
- Precise and clear decision making on key issues within every project phase by prioritizing and allocating resources based on the level and nature of risk.
- Clearer definition of risks related to particular projects with the risk assessment approach by using consistent and standardized methods and tools.
- Improved communication and collaboration among stakeholders by sharing and documenting the risk information and the risk response strategies.

SPM systems are used to transfer crude oil, liquefied natural gas, or other fluids from offshore production facilities or storage units to the tanker vessels.

Risk assessment in SPM involves the following steps:

- Establishing the context: defining the scope, objectives, criteria, and assumptions of the risk assessment, as well as the relevant legal and regulatory requirements, standards, and best practices.
- Identifying the risks: identifying the potential hazards and threats that may affect the SPM system, such as corrosion, fatigue, marine growth, environmental conditions, human error, sabotage, etc.
- Analyzing the risks: estimating the likelihood and consequence of each risk, and assigning a risk rating based on a predefined matrix or scale.
- Evaluating the risks: comparing the risk ratings with the acceptable risk levels, and prioritizing the risks for further treatment or monitoring.
- Treating the risks: selecting and implementing the appropriate risk response strategies, such as avoidance, reduction, transfer, or retention, to reduce the risk to an acceptable level.
- Monitoring and reviewing the risks: monitoring the effectiveness and performance of the risk treatment measures, and reviewing the risk assessment periodically or when there are significant changes in the context, risk sources, or risk outcomes.

Risk assessment in SPM helps to ensure the integrity, reliability, and safety of the SPM system, and to optimize and reduce the inspection and maintenance activities, while keeping the operational risk levels within acceptable limits.



### Risk Planning in SPM

- Risk planning is the process of identifying, analyzing, and managing the potential risks that may affect a software project.
- Risk planning is one of the core activities of software project management (SPM), which aims to deliver software products that meet the customer's requirements, budget, and schedule.
- Risk planning involves the following steps:

  - **Risk identification**: This is the process of finding out the possible sources of uncertainty that may affect the project's objectives, such as technical, organizational, environmental, or external factors. Some techniques for risk identification are brainstorming, checklists, interviews, surveys, historical data, etc.
  - **Risk analysis**: This is the process of assessing the probability and impact of each identified risk, and prioritizing them according to their severity and urgency. Some techniques for risk analysis are qualitative methods (such as risk matrices, risk registers, etc.) and quantitative methods (such as expected value, decision trees, Monte Carlo simulation, etc.).
  - **Risk response planning**: This is the process of developing strategies and actions to reduce, avoid, transfer, or accept the risks, depending on their level of exposure and tolerance. Some techniques for risk response planning are contingency plans, fallback plans, risk reserves, risk owners, risk triggers, etc.
  - **Risk monitoring and control**: This is the process of tracking, reviewing, and updating the risk status, and implementing the risk response plans as needed. Some techniques for risk monitoring and control are risk audits, risk reports, risk reviews, risk metrics, etc.

- Risk planning is an iterative and ongoing process throughout the project life cycle, as new risks may emerge or existing risks may change over time.
- Risk planning is a collaborative and proactive process that involves the project team, stakeholders, and experts, as well as tools and techniques to support the risk management activities.
- Risk planning is a critical process that can help the project manager to anticipate and mitigate the potential threats and opportunities that may affect the project's success.



### Risk Management in SPM

- Risk management is a sequence of steps that help a software team to understand, analyze and manage uncertainty.
- Risk management is one of the core tents of the philosophy of SPM, as it helps to ensure the quality, timeliness and budget of the software project.
- Risk management consists of the following steps :
  - Risk identification: The process of identifying the potential sources of risk that may affect the software project, such as technical, organizational, operational, environmental, legal, or market factors.
  - Risk analysis: The process of assessing the probability and impact of each identified risk, and prioritizing them according to their severity and urgency.
  - Risk planning: The process of developing strategies to avoid, reduce, transfer, or accept the risks, and allocating resources and responsibilities for implementing them.
  - Risk monitoring: The process of tracking the status of the risks and their mitigation actions, and updating the risk register and plan as needed.
- Risk management requires the involvement of all stakeholders, including the software team, the customers, the sponsors, the suppliers, and the users.
- Risk management is an iterative and continuous process that should be performed throughout the software project life cycle .
- Risk management can benefit the software project by:
  - Improving the decision making and planning processes
  - Reducing the uncertainty and surprises
  - Enhancing the communication and collaboration among stakeholders
  - Increasing the customer satisfaction and trust
  - Minimizing the losses and maximizing the opportunities



### PERT Technique in SPM

- PERT stands for Program Evaluation and Review Technique. It is a statistical tool used in project management to analyze and represent the tasks involved in completing a given project.
- PERT was first developed by the US Navy in 1958 during the Polaris missile development program and then applied to other industries .
- PERT is used to identify task dependencies and critical paths, plan resources, estimate task duration, and identify potential risks  .
- PERT helps to define and sequence activities, coordinate resources, and track progress .
- PERT uses a network diagram to represent the project activities and their interrelationships. Each activity is represented by a node and each dependency is represented by an arrow .
- PERT uses a three-point estimating technique to calculate the expected duration of each activity. The three points are the optimistic, pessimistic, and most likely estimates. The expected duration is the weighted average of these three estimates  .
- PERT uses the expected durations and the network diagram to calculate the earliest and latest start and finish times of each activity. These times are used to determine the critical path, which is the longest path in the network and the shortest possible time to complete the project  .
- PERT also calculates the slack or float of each activity, which is the amount of time that an activity can be delayed without affecting the project completion time. The activities on the critical path have zero slack, while the activities off the critical path have positive slack  .
- PERT can be used to identify and manage the risks associated with the project. The variance and standard deviation of each activity duration can be calculated from the three-point estimates. These values can be used to determine the probability of completing the project within a given time frame  .
- PERT is a useful technique for planning and controlling complex and uncertain projects. It helps to optimize the project schedule, allocate the resources efficiently, and monitor the project progress and performance  .



### Monte Carlo Simulation in SPM

- Monte Carlo simulation is a mathematical technique that allows you to account for risks in decision-making. It helps determine the impact of identified risks by running multiple simulations and finding a range of outcomes  .
- Monte Carlo simulation is useful for project management (SPM) because it can help estimate the project costs, schedules, and quality by considering the uncertainties and variability of the project inputs and outputs .
- The basic steps of Monte Carlo simulation in SPM are :
  - Define the project scope, objectives, and deliverables.
  - Identify the project risks and their probability and impact.
  - Establish the project baseline, which is the best-case scenario for the project.
  - Define the input parameters, such as cost, time, and quality, and their distributions, such as normal, uniform, or triangular.
  - Define the output parameters, such as project completion date, budget, and performance, and their criteria, such as mean, median, or percentile.
  - Run the simulation, which involves generating random values for the input parameters and calculating the output parameters for each iteration.
  - Analyze the results, which involves plotting the output parameters in histograms, frequency curves, or confidence intervals, and identifying the most likely, optimistic, and pessimistic outcomes.
  - Report the findings, which involves presenting the summary statistics, graphs, and recommendations for the project stakeholders.



### Resource Allocation in SPM

- Resource allocation in SPM (software project management) is the process of allocating, sequencing, and managing resources for a given project.
- Resources include staff, budgets, materials, and equipment needed for the successful completion of a project.
- Resource allocation in SPM is important because it gives a clear picture of the amount of work that has to be done, the time and cost required, and the progress and performance of the project team.
- Resource allocation in SPM involves the following steps:
  - Divide the project into tasks and assign them to the project team members according to their skills, availability, and preferences.
  - Estimate the duration, effort, and cost of each task and the dependencies among them.
  - Create a project schedule that shows the start and end dates of each task and the resources allocated to them.
  - Monitor and control the resource utilization and availability throughout the project lifecycle and make adjustments as needed to cope with changes, risks, and issues.
  - Evaluate the resource allocation outcomes and lessons learned for future improvement.
- Resource allocation in SPM can be done using various methods and tools, such as :
  - Resource leveling: balancing the demand and supply of resources by adjusting the project schedule and priorities.
  - Resource smoothing: minimizing the fluctuations in resource usage by shifting or splitting tasks within the project constraints.
  - Resource allocation matrix: a table that shows the allocation of resources to tasks and the availability of resources over time.
  - Resource histogram: a chart that shows the distribution of resource usage over time and the resource capacity and demand.
  - Resource management software: a software application that helps plan, track, and optimize the resource allocation in SPM.







### Cost Schedules in SPM

- Cost schedules are detailed and accurate estimates of the weekly or monthly costs of a software project over its life cycle.
- Cost schedules are used to analyze and forecast the project's total costs and help the project manager allocate the project's budget .
- Cost schedules also allow the project manager to keep track of actual costs vs. planned costs and identify any cost variances .
- Cost schedules are derived from the project plan, which includes the cost and schedule baselines.
- The cost baseline is the approved version of the time-phased project budget, which is used to measure and monitor cost performance.
- The schedule baseline is the approved version of the project schedule, which is used to measure and monitor schedule performance.
- Cost schedules are created by using cost estimation techniques, such as analogous, parametric, bottom-up, or three-point estimating.
- Cost schedules are updated and controlled throughout the project by using cost management processes, such as estimate costs, determine budget, and control costs.
- Cost schedules are influenced by various factors, such as project scope, quality, resources, risks, and changes.
- Cost schedules are essential for ensuring that the project is executed within the approved budget and delivered on time.
