### Types of Digital Data

Digital data refers to information that is stored in a digital format. There are several types of digital data that are commonly used in the context of big data:

1. **Structured data:** This type of data is organized in a predefined manner, usually in the form of tables with rows and columns. Examples of structured data include spreadsheets, databases, and data stored in a comma-separated values (CSV) format.

2. **Unstructured data:** This type of data does not have a predefined structure and can come in many different forms. Examples of unstructured data include text documents, images, videos, and audio files.

3. **Semi-structured data:** This type of data falls between structured and unstructured data. It has some level of organization, but not as rigid as structured data. Examples of semi-structured data include XML and JSON files.

4. **Time-series data:** This type of data is collected over time and is used to track changes and trends. Examples of time-series data include stock prices, weather data, and sensor data.

5. **Geospatial data:** This type of data is used to represent geographical information and can include coordinates, addresses, and maps.

These are some of the common types of digital data that are used in the context of big data. Understanding the different types of data is important when working with big data, as it can help determine the best methods for storing, processing, and analyzing the data.

- In 1970, IBM mathematician Edgar F Codd presented his framework for a “relational database”.

### History of Hadoop

- Hadoop was started with Doug Cutting and Mike Cafarella in the year 2002 when they both started to work on Apache Nutch project. Apache Nutch project was the process of building a search engine system that can index 1 billion pages .
- Hadoop was named after an extinct specie of mammoth, a so called Yellow Hadoop .
- Hadoop is an open-source software framework for storing and processing big data. It was created by Apache Software Foundation in 2006, based on a white paper written by Google in 2003 that described the Google File System (GFS) and the MapReduce programming model .
- In 2008, Hadoop defeated the supercomputers and became the fastest system on the planet for sorting terabytes of data .
- Hadoop YARN was introduced in 2012 as a platform responsible for managing computing resources in clusters and using them for scheduling users' applications .

### The Hadoop Distributed File System

- The Hadoop Distributed File System (HDFS) is the primary data storage system used by Hadoop applications .
- HDFS employs a NameNode and DataNode architecture to implement a distributed file system that provides high-performance access to data across highly scalable Hadoop clusters .
- The core of Apache Hadoop consists of a storage part, known as Hadoop Distributed File System (HDFS), and a processing part which is a MapReduce programming model .
- Hadoop splits files into large blocks and distributes them across nodes in a cluster. It then transfers packaged code into nodes to process the data in parallel .
- As the primary component of the Hadoop ecosystem, HDFS is a distributed file system that provides high-throughput access to application data with no need for schemas to be defined up front .
- HDFS is a distributed file system that handles large data sets running on commodity hardware. It is used to scale a single Apache Hadoop cluster to hundreds (and even thousands) of nodes .
- HDFS is one of the major components of Apache Hadoop, the others being MapReduce and YARN .

### Scaling Out

Scaling out refers to the process of adding more nodes to a distributed system to handle increased workload. This is in contrast to scaling up, which involves adding more resources to a single node, such as more memory or a faster processor.

In the context of Hadoop, scaling out is achieved by adding more data nodes to the Hadoop Distributed File System (HDFS) and more task trackers to the MapReduce framework. This allows the system to store and process more data in parallel, increasing the overall performance of the system.

Some benefits of scaling out in Hadoop include:

1. Increased performance: By adding more nodes to the system, the workload can be distributed across more machines, allowing for faster processing of data.
2. Cost-effectiveness: Scaling out can be more cost-effective than scaling up, as commodity hardware can be used to add more nodes to the system.
3. Fault tolerance: Hadoop is designed to be fault-tolerant, and adding more nodes to the system increases the level of redundancy, allowing the system to continue functioning even if some nodes fail.

In summary, scaling out is an important concept in Hadoop and allows the system to handle increased workload by adding more nodes to the distributed system. This can result in increased performance, cost-effectiveness, and fault tolerance.

### Anatomy of a Spark Job Run

1. **Client Mode**: In client mode, the driver program runs on the client machine, and the application master is only used for requesting resources from the cluster manager.

2. **Cluster Mode**: In cluster mode, the driver program runs on a worker node in the cluster, and the client can go away after submitting the application.

3. **Job Submission**: When an action is called on an RDD, a job is submitted to the Spark scheduler.

4. **Stages**: The scheduler divides the job into stages, where each stage contains a sequence of transformations that can be pipelined.

5. **Tasks**: Each stage is further divided into tasks, where each task corresponds to a partition of the RDD being processed.

6. **Task Scheduling**: The scheduler assigns tasks to workers based on data locality and available resources.

7. **Task Execution**: The worker executes the task and stores the result in memory or on disk.

8. **Shuffling**: If a stage requires data from multiple partitions of the previous stage, a shuffle operation is performed to redistribute the data.

9. **Result Retrieval**: Once all tasks have completed, the result is returned to the driver program or written to an external storage system.

### Data Processing Operators

In the context of the Hadoop ecosystem, data processing operators refer to the various tools and frameworks used to process and analyze large datasets. Some of the key data processing operators in the Hadoop ecosystem include:

2. **Pig**: A high-level platform for creating MapReduce programs using a scripting language called Pig Latin. Pig abstracts the complexity of writing MapReduce programs and allows users to focus on the logic of their data processing tasks.

4. **Spark**: An open-source data processing engine that can be used for a wide range of data processing tasks, including batch processing, stream processing, machine learning, and graph processing. Spark is designed to be fast and efficient, and can be used with a variety of data sources, including HDFS.

These are just a few examples of the many data processing operators available in the Hadoop ecosystem. Each operator has its own strengths and capabilities, and can be used in combination with others to build powerful and scalable data processing pipelines.
