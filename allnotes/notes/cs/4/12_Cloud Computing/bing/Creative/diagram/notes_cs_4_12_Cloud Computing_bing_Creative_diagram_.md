

## Unit 1 - Introduction To Cloud Computing

Cloud computing is the delivery of computing services over the internet, such as servers, storage, databases, networking, software, analytics, and intelligence. Cloud computing enables users to access scalable, on-demand, and pay-per-use IT resources without investing in or managing physical infrastructure.

Some of the benefits of cloud computing are:

- Cost savings: Cloud computing eliminates the capital expense of buying hardware and software, and the operational expense of running and maintaining IT systems.
- Scalability: Cloud computing allows users to scale up or down their IT resources according to their needs, without having to worry about capacity planning or hardware limitations.
- Performance: Cloud computing offers high-performance computing resources that are constantly upgraded and optimized by the cloud providers, ensuring fast and reliable service delivery.
- Security: Cloud computing provides various security measures to protect the data and applications of the users, such as encryption, firewalls, identity and access management, backup and recovery, and compliance.
- Innovation: Cloud computing enables users to access the latest technologies and services offered by the cloud providers, such as artificial intelligence, machine learning, internet of things, and blockchain, and to experiment and innovate faster and easier.

Some of the challenges of cloud computing are:

- Privacy and data protection: Cloud computing involves storing and processing sensitive data on remote servers that may be located in different jurisdictions and subject to different laws and regulations, raising concerns about data sovereignty, ownership, and access.
- Reliability and availability: Cloud computing depends on the internet connection and the service level agreements of the cloud providers, which may not guarantee 100% uptime or fault tolerance, and may result in service disruptions or outages.
- Vendor lock-in: Cloud computing may create dependencies on the cloud providers and their proprietary platforms, tools, and standards, making it difficult or costly for the users to switch to another provider or to migrate back to on-premises systems.
- Security and compliance: Cloud computing requires users to trust the cloud providers and their security practices, and to comply with the policies and regulations of the cloud providers and the cloud environments, which may not align with the users' own security and compliance requirements.

Some of the common cloud service models are:

- Infrastructure as a Service (IaaS): The cloud provider offers the basic computing infrastructure, such as servers, storage, network, and virtualization, and the user can install and run any operating system and application on top of it.
- Platform as a Service (PaaS): The cloud provider offers the computing platform, such as operating system, middleware, runtime, and development tools, and the user can develop and deploy applications using the platform.
- Software as a Service (SaaS): The cloud provider offers the software application, such as email, CRM, ERP, or office suite, and the user can access and use the application via a web browser or a mobile app.

Some of the common cloud deployment models are:

- Public cloud: The cloud provider owns and operates the cloud infrastructure and offers it to the general public or to a large group of organizations over the internet.
- Private cloud: The cloud infrastructure is dedicated to a single organization and can be owned, managed, and operated by the organization, by the cloud provider, or by a third party, and can be located on or off premises.
- Hybrid cloud: The cloud infrastructure is a composition of two or more distinct cloud infrastructures (public or private) that remain separate entities but are connected by standardized or proprietary technology that enables data and application portability and interoperability.
- Community cloud: The cloud infrastructure is shared by several organizations that have common goals, interests, or concerns, and can be owned, managed, and operated by one or more of the organizations, by the cloud provider, or by a third party, and can be located on or off premises.



### Definition of Cloud

- Cloud computing is the **delivery of computing services** over the internet, rather than using local servers or personal computers  .
- Cloud computing services include **servers, storage, databases, networking, software, analytics, and intelligence**.
- Cloud computing provides **on-demand access, faster innovation, flexible resources, and economies of scale**.
- Cloud computing is based on some form of **virtualized IT infrastructure** that can be pooled and divided irrespective of physical hardware boundaries.
- Cloud computing requires a **cloud service provider (or CSP)** that manages the remote data center and the computing resources.
- Cloud computing can be classified into different **service models** and **deployment models** depending on the level of abstraction and control, and the location of the resources  .

### Evolution of Cloud Computing

- Cloud computing is the delivery of computing resources and services over the internet on demand.
- The idea of cloud computing dates back to the 1960s, when J.C.R. Licklider envisioned a network of interconnected computers that could access data and programs from anywhere.
- The term "cloud" was first used in the 1990s to refer to the network of servers and switches that formed the backbone of the internet.
- The evolution of cloud computing can be divided into three phases:

  - The pre-cloud phase (before 1999): This phase involved the development of technologies such as utility computing, grid computing, and virtualization, which enabled the sharing and pooling of computing resources across multiple machines and locations.
  - The early cloud phase (1999-2006): This phase witnessed the emergence of web-based applications and services that could be accessed through browsers, such as Salesforce, Amazon Web Services, and Google Apps. These services offered scalable, pay-as-you-go, and self-service models of cloud computing.
  - The modern cloud phase (2006-present): This phase is characterized by the proliferation of cloud platforms, services, and models, such as software as a service (SaaS), platform as a service (PaaS), infrastructure as a service (IaaS), and hybrid cloud. This phase also involves the adoption of cloud computing by various industries, sectors, and domains, such as e-commerce, social media, education, health care, and government.

- The evolution of cloud computing is driven by several factors, such as:

  - The increasing demand for computing power, storage, and bandwidth, due to the growth of data, applications, and users.
  - The need for cost-efficiency, flexibility, and scalability, as traditional IT infrastructure is expensive, rigid, and underutilized.
  - The advancement of technologies, such as virtualization, containerization, serverless computing, and cloud security, that enable the abstraction, orchestration, and optimization of cloud resources and services.
  - The innovation of business models, such as subscription, pay-per-use, and freemium, that offer value-added and customized cloud solutions to customers.

- The evolution of cloud computing is expected to continue in the future, with trends such as:

  - The emergence of new cloud paradigms, such as edge computing, fog computing, and quantum computing, that extend the cloud capabilities to the edge of the network, the intermediate layer between the cloud and the devices, and the quantum realm, respectively.
  - The integration of cloud computing with other technologies, such as artificial intelligence, blockchain, and internet of things, that enhance the intelligence, security, and connectivity of cloud services and applications.
  - The transformation of cloud computing into a social and environmental responsibility, as cloud providers and users adopt green and ethical practices to reduce the carbon footprint and the social impact of cloud computing.

### Underlying Principles of Parallel and Distributed Computing

- Parallel and distributed computing are two paradigms that aim to improve the performance and efficiency of complex applications by using multiple processors or computers to execute tasks simultaneously.
- Parallel computing involves using multiple processors or cores within a single computer to divide a large problem into smaller subproblems that can be solved concurrently.
- Distributed computing involves using multiple computers connected by a network to cooperate on a common task or problem, where each computer may have its own local memory and resources.
- Parallel and distributed computing build on fundamental systems concepts, such as :
  - Concurrency: the ability of multiple processes or threads to execute simultaneously, either on the same or different processors or computers.
  - Mutual exclusion: the mechanism that ensures that only one process or thread can access a shared resource or critical section at a time, to avoid conflicts or inconsistencies.
  - Consistency: the property that ensures that the state or memory of a system is coherent and reliable across all processors or computers, despite concurrent updates or failures.
  - Message-passing: the communication model that allows processes or threads to exchange data or information by sending and receiving messages over a network or a shared memory.
  - Shared-memory: the memory model that allows processes or threads to access and modify the same memory locations, either physically or logically, by using synchronization primitives such as locks or semaphores.
- Parallel and distributed computing occur across many different topic areas in computer science, including algorithms, computer architecture, networks, operating systems, and software engineering.
- Parallel and distributed computing have many applications and benefits, such as :
  - Speeding up the execution of computationally intensive or data-intensive tasks, such as scientific simulations, image processing, machine learning, or web search.
  - Improving the scalability, reliability, and availability of systems and services, such as cloud computing, distributed databases, or fault-tolerant systems.
  - Reducing the cost and energy consumption of computing, by using cheaper or more efficient hardware or software components, such as multicore processors, clusters, or grids.

### Cloud Characteristics

Cloud computing is a model of delivering computing services over the internet, on demand and at scale. Cloud computing has some key characteristics that distinguish it from traditional computing models. According to the National Institute of Standards and Technology (NIST), these characteristics are:

- **On-demand self-service**: Cloud users can provision and release computing resources, such as servers, storage, network, and software, without requiring human intervention from the service provider. Users can access and manage these resources through a web-based interface or an application programming interface (API).
- **Broad network access**: Cloud services are available over the network and can be accessed by various devices, such as laptops, smartphones, tablets, and sensors. Cloud services are typically delivered through standard protocols and formats, such as HTTP, REST, and JSON, to ensure interoperability and compatibility.
- **Resource pooling**: Cloud service providers use a multi-tenant architecture to share and allocate computing resources among multiple users, according to their demand and availability. Resource pooling enables economies of scale and higher utilization of resources. Users do not have control or knowledge of the exact location of the resources, but they can specify some general parameters, such as region, performance, and security.
- **Rapid elasticity**: Cloud services can be scaled up or down quickly and automatically, depending on the user's needs and the service level agreement (SLA). Users can access as much or as little resources as they need, and pay only for what they use. Cloud services can also handle peak loads and sudden spikes in demand, without compromising the quality of service.
- **Measured service**: Cloud service providers monitor and measure the usage of resources and services by the users, and charge them accordingly. Users can also track and optimize their consumption of resources and services, and adjust their plans and budgets. Measured service enables transparency and accountability for both the provider and the user.

These characteristics make cloud computing a flexible, efficient, and cost-effective way of delivering computing services, and enable various benefits and challenges for the users and the providers.



### Elasticity in Cloud

- Elasticity is a defining characteristic that differentiates cloud computing from previously proposed computing paradigms, such as grid computing.
- Elasticity is the ability to quickly expand or decrease computer processing, memory, and storage resources to meet changing demands without worrying about capacity planning and engineering for peak usage.
- Elasticity can be automatic, without need to perform capacity planning in advance of the occasion, or it can be a manual process where the organization is notified they are approaching their limit and can choose to add more resources.
- Elasticity is also known as rapid elasticity or cloud elasticity .
- Elasticity is closely related to scalability, which is the ability to add or remove capacity, mostly processing, memory, or both, from an IT environment.
- However, elasticity is more dynamic and responsive than scalability, as it implies that the system can adapt to workload changes by provisioning and de-provisioning resources in an autonomic manner, such that at each point in time the available resources match the current demand as closely as possible.
- Elasticity enables cloud computing to offer various benefits, such as cost-efficiency, performance, reliability, and availability.
- Elasticity can be measured by various metrics, such as response time, throughput, resource utilization, and quality of service.
- Elasticity can be achieved by various techniques, such as virtualization, load balancing, auto-scaling, and cloud bursting .
- Elasticity can be applied to various types of cloud services, such as infrastructure as a service (IaaS), platform as a service (PaaS), and software as a service (SaaS).

## Unit 2 - Cloud Enabling Technologies Service Oriented Architecture

Service-oriented architecture (SOA) is a method of software development that uses software components called services to create business applications. Each service provides a business capability, and services can also communicate with each other across platforms and languages.

SOA is a key enabling technology for cloud computing as it allows the construction of applications from loosely coupled services that can be easily integrated and reused. SOA also supports the scalability, availability, and reliability of cloud applications by enabling the distribution of services across multiple servers and locations.

Some of the benefits of SOA for cloud computing are:

- Reduced development and maintenance costs by reusing existing services and avoiding duplication of functionality.
- Increased agility and flexibility by allowing the modification and addition of services without affecting the whole application.
- Improved interoperability and compatibility by using common interface standards and protocols for service communication.
- Enhanced security and governance by applying policies and rules to control the access and behavior of services.
- Facilitated innovation and experimentation by enabling the creation of new services and applications from existing ones.

Some of the challenges of SOA for cloud computing are:

- Increased complexity and overhead by requiring the coordination and management of multiple services and their interactions.
- Potential performance and reliability issues by introducing network latency and dependency on external services.
- Difficulty in testing and debugging by involving multiple services and components that may have different versions and configurations.
- Risk of vendor lock-in by relying on proprietary or incompatible service platforms and technologies.

SOA is not a new concept, but it has become a central component of modern cloud computing and virtualization in things like middleware and microservices. Microservices are a type of SOA that use small, independent, and loosely coupled services that communicate via lightweight protocols. Microservices are often used to build cloud-native applications that can scale and adapt to changing business needs. However, SOA and microservices are not the same, and they have different trade-offs and best practices.



### REST and Systems of Systems

- REST stands for REpresentational State Transfer, an architectural style for providing standards between computer systems on the web.
- REST-compliant systems, often called RESTful systems, are stateless and separate the concerns of client and server.
- RESTful systems use HTTP methods (such as GET, POST, PUT, DELETE) to perform operations on resources, which are identified by URIs.
- RESTful systems can support different data formats, such as XML, JSON, HTML, etc.
- RESTful systems can be scalable, interoperable, and adaptable to changing requirements.
- REST is widely used in software systems (e.g. ERP, MES, PLS) and especially on the web in cloud-based systems.
- REST can be used to address the entire functional scope of a software system or to create user-specific endpoints.
- Systems of systems (SoS) is a collection of task-oriented or dedicated systems that pool their resources and capabilities together to create a new, more complex system.
- SoS offers more functionality and performance than simply the sum of the constituent systems.
- SoS can be classified into four types: directed, acknowledged, collaborative, and virtual.
- SoS can be characterized by five attributes: operational independence, managerial independence, evolutionary development, emergent behavior, and geographical distribution.
- SoS can be challenging to design, manage, and evaluate due to their complexity, heterogeneity, and dynamism.
- SoS can benefit from using REST as a communication protocol, as it can enable interoperability, scalability, and adaptability among the constituent systems.



### Web Services

- A web service is a software system that supports interoperable machine-to-machine interaction over a network .
- A web service has an interface that is described in a machine-processable format, such as WSDL (Web Services Description Language) or OpenAPI (Open Application Programming Interface)  .
- A web service can be accessed by other applications or devices using standard web protocols, such as HTTP (Hypertext Transfer Protocol) or HTTPS (Hypertext Transfer Protocol Secure)  .
- A web service can provide data in different formats, such as XML (Extensible Markup Language), JSON (JavaScript Object Notation), or images  .
- A web service can be used for various purposes, such as data exchange, integration, communication, or computation .
- A web service can be classified into two types: SOAP (Simple Object Access Protocol) or REST (Representational State Transfer) .
  - SOAP is a protocol that uses XML to define the structure and content of messages exchanged between the web service and the client .
  - REST is an architectural style that uses HTTP methods (such as GET, POST, PUT, or DELETE) to define the operations performed by the web service on the resources identified by URIs (Uniform Resource Identifiers) .
- A web service can be hosted on a server, a cloud platform, or a distributed network .
- A web service can be discovered and invoked over the network using various methods, such as UDDI (Universal Description, Discovery, and Integration), WS-Discovery (Web Services Dynamic Discovery), or API gateways .



### Publish, Subscribe Model

- Publish, subscribe model, or pub/sub model, is a software architecture model by which applications create and share data.
- Pub/sub model is a form of asynchronous service-to-service communication used in serverless and microservices architectures.
- Pub/sub model enables event-driven architectures and asynchronous parallel processing, while improving performance, reliability and scalability.
- Pub/sub model separates the client (publisher) that sends the message from the client (subscriber) that receives the message. The publisher and the subscriber do not need to establish direct contact.
- Pub/sub model involves:
  - A publisher who sends a message to a topic.
  - A topic which is a logical channel that groups messages by subject or type.
  - A subscriber who receives the message from the topic.
  - A broker or a messaging system that manages the topics and delivers the messages from publishers to subscribers.
- Pub/sub model has the following benefits:
  - Decoupling: Publishers and subscribers are independent and do not need to know each other's identity, location or implementation.
  - Scalability: Pub/sub model can handle high volumes of messages and subscribers without affecting the performance of the publishers.
  - Reliability: Pub/sub model ensures that messages are delivered to the subscribers even if the publishers or the broker fail or become unavailable.
  - Flexibility: Pub/sub model allows subscribers to dynamically subscribe or unsubscribe to topics of interest, and publishers to dynamically create or delete topics.
  - Extensibility: Pub/sub model can support various message formats, protocols and transports, and can integrate with other systems and services.



### Basics of Virtualization

Virtualization is a process that allows for more efficient utilization of physical computer hardware by creating multiple virtual computers, called virtual machines (VMs), that run on a single physical computer or server. Virtualization uses software to create an abstraction layer over the hardware elements, such as processors, memory, storage, and network, and allows them to be divided and shared among the VMs. Virtualization is the foundation of cloud computing, as it enables the delivery of computing resources as a service over the internet.

Some of the benefits of virtualization are:

- Cost reduction: Virtualization reduces the need for purchasing and maintaining multiple physical servers, as well as the power and cooling costs associated with them.
- Resource optimization: Virtualization allows for better utilization of the available hardware resources, as multiple VMs can run on the same physical server and use only the resources they need.
- Scalability: Virtualization enables the creation and deletion of VMs on demand, as well as the migration of VMs across different physical servers, to meet the changing workload requirements.
- Isolation: Virtualization provides a degree of isolation between the VMs, as each VM has its own operating system and applications, and does not interfere with the other VMs on the same physical server.
- Security: Virtualization can enhance the security of the VMs, as they can be isolated from the physical network and protected by firewalls and encryption.

There are different types of virtualization, depending on the level of abstraction and the type of resource being virtualized. Some of the common types of virtualization are:

- Hardware virtualization: This is the most common type of virtualization, where the entire physical server is virtualized and divided into multiple VMs, each with its own operating system and applications. The software that creates and manages the VMs is called a hypervisor or a virtual machine monitor (VMM). Examples of hypervisors are VMware ESXi, Microsoft Hyper-V, and KVM.
- Operating system virtualization: This is a type of virtualization where the operating system kernel is virtualized and shared among multiple VMs, each with its own user space and applications. The VMs are also called containers, as they are lightweight and portable. The software that creates and manages the containers is called a container engine or a container runtime. Examples of container engines are Docker, LXC, and rkt.
- Application virtualization: This is a type of virtualization where the application is virtualized and separated from the underlying operating system and hardware. The application runs in a runtime environment that provides the necessary libraries and dependencies. The application can be delivered to the end user device in different ways, such as local application virtualization, where the entire application runs on the device, application streaming, where the application is streamed from a server and runs on the device, or remote application virtualization, where the application runs on a server and the user interacts with it through a remote display protocol. Examples of application virtualization software are Microsoft App-V, Citrix XenApp, and VMware ThinApp.

### Implementation Levels of Virtualization

Virtualization is the process of creating a virtual representation of something, such as a hardware platform, an operating system, a storage device, or a network resource. Virtualization can enable multiple applications and operating systems to run on the same physical machine, or allow a single application to run on multiple machines.

There are different levels of virtualization implementation, depending on how the virtualization is performed and where it is located in the system architecture. The following are the five main levels of virtualization implementation:

- **Instruction Set Architecture Level (ISA)**: In this level, virtualization works through an ISA emulation, which means that the virtual machine (VM) mimics the instruction set of a different hardware platform. This allows the VM to run applications and operating systems that are not compatible with the host hardware. For example, an ISA emulator can enable a Windows application to run on a Linux machine, or a Mac OS X application to run on a Windows machine. ISA emulation is the most flexible but also the most resource-intensive and slowest form of virtualization .

- **Hardware Abstraction Level (HAL)**: In this level, virtualization works at the hardware level, by creating a layer of abstraction between the physical hardware and the VMs. This allows the VMs to access the hardware resources without being aware of the underlying details, such as the device drivers, the memory management, or the interrupt handling. HAL virtualization can improve the performance and compatibility of the VMs, as they can use the native instruction set of the host hardware. However, HAL virtualization also requires some modifications to the guest operating systems, as they need to communicate with the HAL layer instead of the hardware directly .

- **Operating System Level**: In this level, virtualization works at the operating system level, by creating an abstract layer between the applications and the OS. This allows multiple instances of the same or different operating systems to run on the same machine, each with its own set of applications and processes. Operating system level virtualization can improve the efficiency and security of the system, as the OS instances are isolated from each other and can share the same hardware resources. However, operating system level virtualization also requires some support from the host operating system, as it needs to manage the allocation and scheduling of the resources among the OS instances .

- **Library Level**: In this level, virtualization works at the library level, by providing a set of APIs or libraries that can be used by the applications to access the virtualized resources. This allows the applications to run on different platforms or environments, without being aware of the underlying differences. Library level virtualization can improve the portability and interoperability of the applications, as they can use the same APIs or libraries regardless of the host system. However, library level virtualization also requires some modifications to the applications, as they need to use the virtualization libraries instead of the native system calls .

- **Application Level**: In this level, virtualization works at the application level, by creating a virtual environment within the application itself. This allows the application to run multiple instances of itself or other applications, each with its own configuration and state. Application level virtualization can improve the scalability and availability of the application, as it can create and destroy the virtual instances on demand. However, application level virtualization also requires some support from the application itself, as it needs to implement the virtualization logic and manage the virtual instances .

# Tools and Mechanisms for Service Oriented Architecture

Service Oriented Architecture (SOA) is an architectural style that enables the development and integration of loosely coupled, self-contained, and interoperable services that can be reused and orchestrated to create business processes or applications   .

Some of the tools and mechanisms that support SOA are:

- **Service interface**: A service interface defines the contract or specification of a service, including its inputs, outputs, operations, and quality of service requirements. A service interface is typically expressed using a standard language such as Web Services Description Language (WSDL) or OpenAPI  .
- **Service registry**: A service registry is a repository that stores and publishes the metadata of available services, such as their names, locations, interfaces, and policies. A service registry enables service discovery and governance by allowing service providers and consumers to register, query, and manage services  .
- **Service bus**: A service bus is a middleware component that facilitates the communication and integration of services across different platforms, protocols, and formats. A service bus provides features such as routing, transformation, mediation, orchestration, and security  .
- **Service composition**: Service composition is the process of creating new services or applications by combining and coordinating existing services. Service composition can be achieved using various techniques, such as workflows, business process management (BPM), or service mashups  .
- **Service adaptation**: Service adaptation is the ability to modify or evolve services in response to changing requirements, environments, or contexts. Service adaptation can be performed at design time or runtime, and can involve techniques such as service versioning, service substitution, service reconfiguration, or service adaptation frameworks .



### Virtualization of CPU

- CPU virtualization is a technique that creates multiple versions of various system resources, including your CPU, server, storage, etc. 
- CPU virtualization involves a single CPU acting as if it were multiple separate CPUs. The most common reason for doing this is to run multiple different operating systems on one machine. 
- CPU virtualization emphasizes performance and runs directly on the available CPUs whenever possible. 
- CPU virtualization can be achieved by using software or hardware methods. 
- Software-based CPU virtualization uses a hypervisor, which is a software layer that runs between the hardware and the operating systems. The hypervisor creates and manages virtual machines, which are isolated environments that run different operating systems. 
- Hardware-based CPU virtualization uses special features in the CPU that allow the hypervisor to run more efficiently and securely. Some examples of these features are Intel VT-x and AMD-V. 
- CPU virtualization has many benefits, such as:
  - Increased utilization of CPU resources and reduced power consumption. 
  - Improved scalability and flexibility of the system. 
  - Enhanced security and isolation of the virtual machines. 
  - Easier migration and backup of the virtual machines. 
  - Support for legacy applications and operating systems.

### Virtualization Support and Disaster Recovery

- Virtualization is the process of creating virtual versions of physical resources, such as servers, storage, networks, and applications, that can run on a single or multiple physical machines.
- Virtualization can help improve data protection and disaster recovery by:
  - Simplifying backup storage: Virtualization allows for creating multiple copies of virtual machines (VMs) and storing them on different media, such as cloud servers, external hard drives, or tapes. This reduces the risk of data loss due to hardware failure, theft, or natural disasters.
  - Reducing recovery time: Virtualization enables faster and easier recovery of VMs in case of a disaster, as they can be restored from the backup media to any compatible physical machine, regardless of the underlying hardware. This eliminates the need to reinstall the operating system, applications, and data on the new machine.
  - Enhancing business continuity: Virtualization ensures that the critical business functions can continue to operate even in the event of a disaster, as the VMs can be migrated or replicated to another location, such as a secondary data center or a cloud service provider. This minimizes the downtime and the impact of the disaster on the business operations and customers.
- Virtualization can support different types of disaster recovery strategies, such as:
  - Backup and restore: This is the simplest and most common strategy, where the VMs are backed up periodically and restored to the same or a different physical machine in case of a disaster. This strategy requires sufficient storage space and bandwidth for the backup and restore operations, and may result in data loss if the backup is not up to date.
  - Replication and failover: This is a more advanced and reliable strategy, where the VMs are continuously replicated to another location, such as a secondary data center or a cloud service provider, and automatically switched to the replicated VMs in case of a disaster. This strategy requires high-speed network connectivity and synchronization between the primary and secondary sites, and ensures minimal data loss and downtime.
  - Snapshot and rollback: This is a more granular and flexible strategy, where the VMs are periodically captured as snapshots, which are point-in-time images of the VM state, and rolled back to a previous snapshot in case of a disaster. This strategy allows for restoring the VMs to a specific point in time, and can be used to recover from logical errors, such as data corruption, malware infection, or human mistakes.

### Layered Cloud Architecture Design

- Cloud architecture is how individual technologies are integrated to create clouds IT environments that abstract, pool, and share scalable resources across a network.
- Cloud architecture is typically composed of several layers, each with a specific function and responsibility. The layers are connected by user interfaces, application programming interfaces, and middleware.
- The common layers of cloud architecture are:

  - **Application layer**: This is the top layer where the actual cloud applications are located. Cloud applications can take advantage of the automatic-scaling functionality to gain greater performance, availability, and lower operational costs.
  - **Platform layer**: This layer provides the tools and services for developing, testing, deploying, and managing cloud applications. It includes frameworks, databases, web servers, and other components that support various programming languages and models.
  - **Infrastructure layer**: This layer serves as the central hub of the cloud environment, where resources are constantly added using a variety of virtualization techniques. It consists of the virtualized network, storage, and computing resources that form the basis for the platform layer.
  - **Virtualization layer**: This layer enables the abstraction and pooling of physical resources, such as servers, disks, and networks, into logical units that can be dynamically allocated and released. It also provides isolation and security for the virtual machines and containers that run on the infrastructure layer.
  - **Physical layer**: This is the bottom layer that consists of the actual hardware and devices that provide the raw computing power, storage capacity, and network connectivity for the cloud. It includes servers, switches, routers, firewalls, and other physical components.

- Depending on the type and level of service offered by the cloud provider, the users and developers can access different layers of the cloud architecture. For example, in **Infrastructure as a Service (IaaS)**, the users can access the infrastructure layer and the virtualization layer, and have full control over the configuration and management of the virtual machines and containers. In **Platform as a Service (PaaS)**, the users can access the platform layer and the application layer, and have the ability to create and deploy cloud applications using the tools and services provided by the cloud provider. In **Software as a Service (SaaS)**, the users can only access the application layer, and have the convenience of using the cloud applications without worrying about the underlying infrastructure and platform.

  - **Event-driven**: This style triggers the cloud application based on events or messages that occur in the cloud environment or external sources. ### NIST Cloud Computing Reference Architecture

- The NIST Cloud Computing Reference Architecture (NIST SP 500-292) is a document that defines a neutral and generic cloud computing architecture and taxonomy to facilitate communication and understanding of various cloud services and offerings .
- The NIST Cloud Computing Reference Architecture consists of five major components: cloud consumer, cloud provider, cloud broker, cloud auditor, and cloud carrier .
- Cloud consumer is the entity that uses cloud services from a cloud provider. Cloud consumer can be an individual, an organization, or a software system.
- Cloud provider is the entity that provides cloud services to cloud consumers. Cloud provider can offer different types of cloud service models, such as Software as a Service (SaaS), Platform as a Service (PaaS), or Infrastructure as a Service (IaaS).
- Cloud broker is an intermediary entity that manages the use, performance, and delivery of cloud services for cloud consumers. Cloud broker can provide three types of services: service intermediation, service aggregation, or service arbitrage.
- Cloud auditor is an independent entity that conducts audits and assessments of cloud services, such as security, privacy, performance, or compliance.
- Cloud carrier is the entity that provides connectivity and transport of cloud services between cloud consumers and cloud providers. Cloud carrier can be a network provider, a telecommunication provider, or an internet service provider.
- The NIST Cloud Computing Reference Architecture also defines a set of roles and activities for each component, as well as the interactions and dependencies among them.
- The NIST Cloud Computing Reference Architecture is intended to be a tool for describing, analyzing, and comparing different cloud services and architectures, and to provide a common vocabulary and framework for cloud computing.
- The NIST Cloud Computing Reference Architecture is not a prescriptive or normative standard, but rather a descriptive and informative one. It does not specify any implementation details, technologies, or standards for cloud computing.
- The NIST Cloud Computing Reference Architecture is based on the NIST Cloud Computing Definition (NIST SP 800-145), which defines cloud computing as a model for enabling ubiquitous, convenient, on-demand network access to a shared pool of configurable computing resources that can be rapidly provisioned and released with minimal management effort or service provider interaction .
- The NIST Cloud Computing Reference Architecture is also aligned with the NIST Cloud Computing Standards Roadmap (NIST SP 500-291), which identifies the existing and emerging standards relevant for cloud computing, and the NIST Cloud Computing Technology Roadmap (NIST SP 500-293), which identifies the technical requirements and priorities for cloud computing .
- The NIST Cloud Computing Reference Architecture is a living document that will be updated and revised as the cloud computing landscape evolves and new requirements and challenges emerge.



### Public, Private and Hybrid Clouds

- Cloud computing is the delivery of computing services over the internet, such as servers, storage, databases, networking, software, analytics, and intelligence.
- There are three main types of cloud deployment models: public, private, and hybrid clouds. Each one has its own advantages and disadvantages, depending on the needs and preferences of the organization.
- **Public cloud** is cloud computing that’s delivered via the internet and shared across organizations. Anyone can subscribe to and access public cloud services, such as Amazon Web Services (AWS), Microsoft Azure, or Google Cloud Platform (GCP). Some of the benefits of public cloud are:
  - Lower costs, as the cloud provider is responsible for the maintenance and security of the infrastructure and software.
  - Higher scalability and elasticity, as the cloud provider can offer virtually unlimited resources on demand.
  - Greater innovation and flexibility, as the cloud provider can offer a wide range of services and features that can be easily integrated and customized.
- Some of the drawbacks of public cloud are:
  - Less control and visibility, as the cloud provider has the ultimate authority over the infrastructure and software, and may not disclose all the details or allow full customization.
  - Higher security and compliance risks, as the data and applications are stored and processed on shared servers that may be accessed by other users or malicious actors.
  - Potential vendor lock-in, as the cloud provider may use proprietary technologies or standards that make it difficult to migrate to another provider or platform.
- **Private cloud** is cloud computing that is dedicated solely to your organization. It can be hosted on-premises or off-premises by a third-party provider, such as IBM Cloud, Oracle Cloud, or VMware Cloud. Some of the benefits of private cloud are:
  - Higher control and visibility, as the organization has the full ownership and management of the infrastructure and software, and can customize it to meet its specific needs and preferences.
  - Higher security and compliance, as the data and applications are stored and processed on isolated servers that are protected by firewalls and encryption.
  - Greater performance and reliability, as the organization can optimize the infrastructure and software to suit its workload and availability requirements.
- Some of the drawbacks of private cloud are:
  - Higher costs, as the organization is responsible for the capital and operational expenses of the infrastructure and software, as well as the maintenance and security of the cloud environment.
  - Lower scalability and elasticity, as the organization is limited by the physical and financial resources that it can allocate to the cloud environment.
  - Greater complexity and expertise, as the organization needs to have the technical skills and knowledge to design, deploy, and manage the cloud environment.
- **Hybrid cloud** is any environment that uses both public and private clouds. It can leverage the best of both worlds, by combining the cost-efficiency and scalability of public cloud with the control and security of private cloud. Some of the benefits of hybrid cloud are:
  - Greater flexibility and agility, as the organization can choose the most suitable cloud model for each application or workload, and switch between them as needed.
  - Greater resilience and redundancy, as the organization can use multiple cloud providers and platforms to avoid single points of failure and improve disaster recovery.
  - Greater innovation and competitiveness, as the organization can access the latest technologies and services from different cloud providers and platforms, and integrate them with its existing systems and processes.
- Some of the drawbacks of hybrid cloud are:
  - Higher complexity and integration, as the organization needs to ensure the compatibility and interoperability of the different cloud models, providers, and platforms, and manage them in a consistent and coherent way.
  - Higher security and compliance challenges, as the organization needs to protect the data and applications that move across different cloud environments, and adhere to the regulations and standards of each cloud provider and platform.
  - Higher dependency and governance, as the organization needs to coordinate and collaborate with multiple cloud providers and platforms, and monitor and optimize the performance and costs of the cloud environment.

### Resource Provisioning Methods

Resource provisioning is the process of allocating and managing cloud resources to meet the requirements of cloud consumers. Resource provisioning methods are the techniques or strategies used to perform this process. Some of the common resource provisioning methods in cloud computing are:

- **Static provisioning or advance provisioning**: This method is suitable for applications with known and constant demands or workloads. The cloud consumer requests a fixed amount of resources from the cloud provider in advance and pays for them regardless of the actual usage. This method can ensure the availability and performance of the resources, but it can also lead to underutilization and waste of resources if the demand fluctuates or decreases.  

- **Dynamic provisioning or on-demand provisioning**: This method is suitable for applications with unpredictable or variable demands or workloads. The cloud consumer requests resources from the cloud provider as needed and pays for them based on the actual usage. This method can optimize the resource utilization and cost efficiency, but it can also introduce challenges such as resource contention, scalability, and elasticity.  

- **Adaptive provisioning or self-adaptive provisioning**: This method is suitable for applications that can adapt to the changing conditions of the cloud environment. The cloud consumer specifies the desired goals or objectives of the application, such as response time, throughput, availability, etc. The cloud provider monitors the application performance and adjusts the resources accordingly to meet the goals or objectives. This method can improve the quality of service and user satisfaction, but it can also require complex algorithms and mechanisms to implement.  

- **Hybrid provisioning or mixed provisioning**: This method is suitable for applications that have both predictable and unpredictable demands or workloads. The cloud consumer combines the static and dynamic provisioning methods to achieve a balance between resource availability, utilization, and cost. The cloud consumer reserves a minimum amount of resources in advance for the predictable part of the demand or workload, and requests additional resources on-demand for the unpredictable part of the demand or workload. This method can provide flexibility and adaptability, but it can also increase the complexity and overhead of resource management.

### Security Overview

Cloud security is the collection of procedures and technology designed to address external and internal threats to business security in the cloud computing environment . Cloud security encompasses three core capabilities: confidentiality, integrity, and availability.

- Confidentiality is the ability to keep information secret from people who shouldn't have access. This can be achieved by using encryption, authentication, and access control mechanisms.
- Integrity means that systems operate as they are intended to function and produce outputs that are not unexpected or misleading. This can be achieved by using checksums, digital signatures, and audit logs.
- Availability means that systems are accessible and reliable when needed. This can be achieved by using redundancy, backup, and recovery mechanisms.

Cloud security also involves the following aspects:

- Compliance: ensuring that the cloud services and data meet the regulatory and legal requirements of the organization and the industry.
- Governance: establishing the roles, responsibilities, and policies for managing the cloud resources and data.
- Risk management: identifying, assessing, and mitigating the potential risks and threats to the cloud environment.
- Identity and access management: controlling who can access the cloud resources and data and what they can do with them.
- Data protection: safeguarding the data from unauthorized access, modification, deletion, or leakage.
- Incident response: responding to and recovering from security breaches or incidents in the cloud environment.

Cloud security can be implemented at different levels of the cloud architecture, such as:

- Infrastructure level: securing the physical and virtual servers, networks, and storage devices that provide the cloud services.
- Platform level: securing the operating systems, middleware, and frameworks that run the cloud applications.
- Application level: securing the software, data, and APIs that interact with the cloud users and customers.
- User level: securing the devices, browsers, and credentials that access the cloud services and data.

Cloud security can be shared between the cloud service provider (CSP) and the cloud customer, depending on the type of cloud service model, such as:

- Infrastructure as a service (IaaS): the CSP provides the infrastructure, while the customer is responsible for the platform, application, and user level security.
- Platform as a service (PaaS): the CSP provides the infrastructure and the platform, while the customer is responsible for the application and user level security.
- Software as a service (SaaS): the CSP provides the infrastructure, the platform, and the application, while the customer is responsible for the user level security.

Cloud security can also be influenced by the type of cloud deployment model, such as:

- Public cloud: the CSP offers the cloud services to the general public over the internet, and the customer has limited control over the security settings and policies.
- Private cloud: the CSP offers the cloud services to a single organization over a private network, and the customer has more control over the security settings and policies.
- Hybrid cloud: the CSP offers the cloud services to a combination of public and private clouds, and the customer has to manage the security across different environments.
- Community cloud: the CSP offers the cloud services to a group of organizations with shared interests or goals, and the customer has to coordinate the security with other members.

Cloud security is an essential and challenging aspect of cloud computing, and it requires the collaboration and trust between the CSP and the customer, as well as the adoption of best practices and standards.



### Cloud Security Challenges

Cloud security challenges are the potential risks and threats that arise from using cloud computing services and platforms. Cloud security challenges can affect the confidentiality, integrity, and availability of the data and resources stored and processed in the cloud. Some of the common cloud security challenges are:

- **Less visibility and lack of control**: When using cloud-based technologies, the user can make the required servers function without having to manage it directly. However, this also means that the user has less visibility and control over the cloud infrastructure and operations, which can increase the risk of unauthorized access, misconfiguration, and data leakage.
- **Non-compliance with regulatory requirements**: Cloud computing involves the transfer and storage of data across different locations and jurisdictions, which can pose challenges for complying with various legal and regulatory standards. For example, some data protection laws may require the user to obtain consent from the data subjects before transferring their personal data to a third-party cloud provider or to a different country.
- **Concerns of data breach and data privacy**: One of the most important challenges of cloud security is the risk of data breaches and issues of data privacy. Before the entry of advanced technologies such as the Cloud, the IT team of every organization had control and hold over the network structure and systems. However, with cloud computing, the data is stored and processed by a third-party provider, which may not have the same level of security and encryption as the user's own systems. Moreover, the data may be accessed by malicious actors who exploit the vulnerabilities in the cloud platform or the user's credentials .
- **Alerts in situations of data breaches**: Another challenge of cloud security is the detection and response to data breaches. As cloud computing involves multiple layers of abstraction and complexity, it can be difficult to monitor and audit the cloud activities and identify any anomalies or incidents. Moreover, the user may not receive timely and accurate alerts from the cloud provider or the security tools in case of a data breach, which can delay the remediation and mitigation actions.
- **Access control to users**: Cloud computing enables the user to access the data and resources from anywhere and any device, which can enhance the productivity and flexibility of the user. However, this also means that the user has to manage the access rights and permissions of different users and devices, which can be challenging and error-prone. For example, the user may grant excessive or unnecessary privileges to some users or devices, or fail to revoke the access of former employees or compromised devices, which can increase the risk of unauthorized access and data misuse .
- **Migration to vendors**: Cloud computing involves the migration of data and applications from the user's own systems to the cloud provider's systems, which can pose several challenges for cloud security. For example, the user may face compatibility issues, data loss, or downtime during the migration process, or may not be able to migrate some legacy or sensitive applications to the cloud due to technical or regulatory constraints. Moreover, the user may become dependent on the cloud provider and face vendor lock-in, which can limit the user's ability to switch to a different provider or to a different cloud model .
- **Lack of experienced workforce**: Cloud computing requires a different set of skills and knowledge than traditional IT systems, which can create a gap in the user's workforce. The user may not have enough qualified and experienced staff who can design, implement, and manage the cloud security strategy and policies, or who can handle the cloud security incidents and challenges. Moreover, the user may face difficulties in training and retaining the cloud security staff, as the cloud technologies and threats are constantly evolving and changing .
- **Vulnerable entry points**: Cloud computing exposes the user to various entry points that can be exploited by malicious actors to gain access to the cloud data and resources. For example, the user may use insecure or weak passwords, or may not enable multi-factor authentication, which can allow the attackers to compromise the user's credentials and access the cloud account. Moreover, the user may use unsecured or public networks or devices to access the cloud, which can expose the user to man-in-the-middle attacks, malware infections, or phishing scams .
- **Multicloud and hybrid cloud configurations**: Cloud computing enables the user to use multiple cloud providers and platforms, or to combine cloud and on-premise systems, which can offer the user more flexibility and scalability. However, this also increases the complexity and diversity of the cloud environment, which can pose challenges for cloud security.

### IAM

Identity and access management (IAM) is a process of defining and managing the roles and access privileges of individual network entities (users and devices) to a variety of cloud and on-premises applications. IAM ensures that only authorized and authenticated entities can access the resources they need, and that they can do only what they are allowed to do.

Some of the benefits of IAM are:

- Enhanced security: IAM reduces the risk of data breaches, identity theft, and unauthorized access by enforcing strong authentication and authorization policies.
- Improved user experience: IAM simplifies the login process for users by providing single sign-on (SSO) and federated identity capabilities, which allow users to access multiple applications with one set of credentials.
- Reduced costs and complexity: IAM eliminates the need for multiple identity systems and passwords, and streamlines the management of user accounts and permissions across the organization.
- Increased compliance: IAM helps organizations comply with various regulations and standards, such as GDPR, HIPAA, PCI DSS, and ISO 27001, by providing audit trails, reports, and alerts on user activities and access events.

Some of the challenges of IAM are:

- Scalability: IAM systems need to handle a large and dynamic number of users and devices, as well as a variety of applications and resources, across different platforms and environments.
- Integration: IAM systems need to integrate with existing identity providers, directories, and applications, as well as support new and emerging technologies, such as cloud, mobile, and IoT.
- Governance: IAM systems need to ensure that the roles and access privileges of users and devices are aligned with the business objectives and policies of the organization, and that they are updated and reviewed regularly.
- Security: IAM systems need to protect the identity data and credentials of users and devices from unauthorized access, modification, and theft, as well as detect and respond to any malicious or anomalous activities.

Some of the components of IAM are:

- Identity providers: These are the sources of identity information, such as user names, passwords, email addresses, phone numbers, etc. They can be internal (e.g., Active Directory, LDAP) or external (e.g., Google, Facebook, Twitter).
- Identity repositories: These are the databases or directories that store and manage the identity information, such as user profiles, attributes, roles, groups, etc. They can be relational (e.g., SQL) or non-relational (e.g., NoSQL).
- Identity services: These are the applications or APIs that provide the functionality of IAM, such as authentication, authorization, SSO, federation, provisioning, deprovisioning, etc. They can be cloud-based (e.g., Google Cloud IAM, AWS IAM, Azure AD) or on-premises (e.g., Microsoft AD FS, IBM Tivoli, Oracle IAM).
- Identity consumers: These are the applications or resources that rely on IAM for access control, such as web applications, mobile apps, cloud services, servers, databases, etc. They can be internal or external, and can use various protocols or standards, such as SAML, OAuth, OpenID Connect, etc.

### MapReduce

MapReduce is a programming paradigm that enables massive scalability across hundreds or thousands of servers in a Hadoop cluster. As the processing component, MapReduce is the heart of Apache Hadoop.

The term "MapReduce" refers to two separate and distinct tasks that Hadoop programs perform:

- The **map** job: This is where a set of data is converted into another set of data, where individual elements are broken down into tuples (key/value pairs).
- The **reduce** job: This is where the output of the map job is combined to form a smaller set of tuples.

MapReduce works by breaking down the processing of large data sets into smaller chunks, which are then processed in parallel on different nodes of the cluster. This allows for faster and more efficient processing of big data.

Some of the benefits of MapReduce are:

- It can handle structured, semi-structured, and unstructured data.
- It can handle data that does not fit in memory.
- It can handle data that is distributed across multiple sources.
- It can handle data that is prone to errors and failures.
- It can handle data that is dynamic and evolving.

Some of the challenges of MapReduce are:

- It requires a lot of programming and debugging skills.
- It may not be suitable for complex or iterative algorithms.
- It may not be optimal for interactive or real-time queries.
- It may not be compatible with existing tools and frameworks.

Some of the applications of MapReduce are:

### Future of Federation for Hadoop

- Hadoop is a framework for distributed storage and processing of large-scale data sets using clusters of commodity hardware.
- Hadoop consists of two main components: Hadoop Distributed File System (HDFS) and MapReduce.
- HDFS is a distributed file system that provides high-throughput access to data across the cluster. MapReduce is a programming model that allows parallel processing of data using key-value pairs.
- HDFS Federation is a feature introduced in Hadoop 2.x that allows multiple NameNodes to manage different namespaces in the same cluster. This improves the scalability, performance, and isolation of HDFS.
- A NameNode is the master node that maintains the metadata of the file system, such as the file names, locations, permissions, etc. A namespace is a logical grouping of files and directories in HDFS.
- In the original HDFS architecture, there was only one NameNode per cluster, which was a single point of failure and a bottleneck for the system. If the NameNode failed, the entire cluster became inaccessible. Moreover, the NameNode had to handle all the requests from the clients and the DataNodes, which limited the throughput and the number of files that could be stored in the cluster.
- In HDFS Federation, there can be multiple NameNodes, each managing a separate namespace. The namespaces are independent of each other and do not share any metadata. The DataNodes can store blocks from multiple namespaces and report to multiple NameNodes. The clients can access any namespace by contacting the corresponding NameNode.
- HDFS Federation provides the following benefits:
  - It increases the scalability of the system by allowing more files and directories to be stored in the cluster. Each namespace can have its own configuration and tuning parameters, such as block size, replication factor, etc.
  - It improves the performance of the system by distributing the load among multiple NameNodes. The clients can access the data faster by contacting the nearest NameNode. The DataNodes can also balance the disk space and network bandwidth usage by storing blocks from different namespaces.
  - It enhances the isolation of the system by preventing the failure or corruption of one namespace from affecting the others. The administrators can also apply different security and access policies to different namespaces.
- HDFS Federation also opens up the architecture for future innovations, such as:
  - Supporting multiple file systems, such as HBase, S3, etc., in the same cluster.
  - Enabling cross-namespace operations, such as copying, moving, or renaming files and directories across different namespaces.
  - Implementing advanced features, such as snapshots, quotas, encryption, etc., for each namespace.
  - Integrating with other Hadoop components, such as YARN, Hive, Spark, etc., to leverage the federated namespaces for data processing and analysis.
