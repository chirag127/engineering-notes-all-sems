## Unit 1 - Introduction to IDBS

1. IDBS stands for Integrated Database Management System. It is a software system that manages and facilitates access to large structured data collections.

2. IDBS has a centralized and integrated database which stores and manages data as a single repository. This avoids data redundancy and inconsistency which may occur if data is stored in multiple locations.

3. IDBS provides capabilities to define, query and manipulate data. It allows users to share data and database resources. It provides backup and recovery functions to prevent data loss.

4. The core components of an IDBS are:

- Data Dictionary: Contains metadata about the database such as table definitions and table relationships.
- Data Manipulation Language (DML): Used to add, update, delete and retrieve data. Example: SQL.
- Data Control Language (DCL): Used to control access to data. Example: GRANT and REVOKE statements in SQL.
- Data Definition Language (DDL): Used to define database schemas. Example: CREATE, ALTER, DROP statements in SQL.
- Query Language: Used to retrieve data from the database. Example: SQL.

5. IDBS has a multi-user and multi-tasking architecture. It allows multiple users to access the database simultaneously while ensuring data integrity, security and consistency. It handles memory and process management to prevent issues like deadlocks that may occur with concurrent access.

6. Popular commercial IDBS products are Oracle Database, Microsoft SQL Server, IBM DB2, etc. Open-source IDBS include MySQL, PostgreSQL, etc. IDBS are widely used to store and manage data in applications such as banking systems, airline reservation systems, enterprise resource planning systems, etc.

### Data models and the relational data model

1. Data model: A data model is a conceptual representation of data structures required for a database and is defined in a data modeling language. It provides definitions for representing entities, relationships, and the constraints on the data.

2. Relational data model: The relational data model is the primary data model for commercial databases. It is intuitive and flexible and represents data in the form of tables (relations) with rows and columns.

3. Tables: In the relational model, data is stored in tables called relations. A table is made up of rows and columns. Each row represents a record and each column represents an attribute (field). The values in the table cells represent the relationships.

4. Schemas: The definition of a database is known as the schema. It specifies the tables in the database, the fields in each table, and the relationships between the tables. The schema is used to create and update the database.

5. Relationships: Relationships show how data in one table is linked to data in another table. They are represented by common fields (columns) between tables. The relational model enforces referential integrity between the tables - the relationships must be consistent and valid.

6. Constraints: Constraints are rules that are applied to the data in a table. They are used to limit the type of data that can be inserted into a table. Examples include NOT NULL to prevent empty fields, UNIQUE to prevent duplicate values, and PRIMARY KEY to uniquely identify each row.

7. Queries: Queries are used to retrieve and manipulate data from a database. The Structured Query Language (SQL) is used to write queries in the relational model. Queries allow users to specify filtering, aggregation, and joining criteria to manipulate the data.

- RDF is a framework for representing information in the Web.
- It uses statements to represent information in the form of subject-predicate-object expressions.
- Subject denotes the resource, predicate denotes the properties or characteristics and object contains the value of the properties.

- SPARQL is an RDF query language for fetching data from RDF graphs.
- It is used to retrieve and manipulate data stored in RDF format.

- They store data in triples (subject-predicate-object) format and provide interfaces to query the data using SPARQL.

2. In the nested relational model, relations can have relations as attribute values. These embedded relations are called nested relations.

### Objectoriented database systems

- Objectoriented database systems (OODBMS) are database management systems that are based on objectoriented programming paradigm.
- They incorporate the features of objectoriented programming languages into database systems.
- The data in OODBMS is stored in the form of objects and the relationships between data are also expressed in the form of objects.

- Encapsulation: The data is hidden and cannot be accessed directly. Only the object methods can access the data.
- Inheritance: The ability of a class to inherit the properties and methods of another class. This results in reusability of code and sharing of common features.
- Polymorphism: The ability of an object to take on different forms based on the context. The same interface can exhibit different behaviors in different scenarios.
- Complex data types: OODBMS can handle various complex data types like multimedia, graphs, etc.
- Native query language: The query language provides an easy way to retrieve data in the form of objects and navigate between related objects.
- Persistence: The objects persist beyond the lifetime of the application that created them. The data is stored permanently in the database.
- Concurrency: The database allows multiple users to access the data simultaneously while maintaining data consistency.
- Scalability: The database can be scaled to handle growth in data volume and users.

### The ODMG standard for the notes of the Unit 2 - Semantic Data Models in the subject of INTELLIGENT DATABASE SYSTEM.

1. The Object Data Management Group (ODMG) standard
- The ODMG is an industry consortium that aims to develop standards for object-oriented database systems.
- The ODMG standard specifies a data model, an object definition language, an object-oriented query language, and interfaces to enable interoperability and portability across OODBMSs.
- The ODMG data model adopts a number of features from object-oriented programming languages, including classes, objects, attributes, relationships, methods, and inheritance.
- The ODMG Object Definition Language (ODL) is used to define database schemas for OODBMSs. It supports the specification of classes, attributes, relationships, methods, and inheritance hierarchies.
- The ODMG Object Query Language (OQL) is based on SQL but has additional capabilities for object-oriented modeling constructs. It supports queries involving classes, subclasses, and paths.
- The ODMG interfaces include a binding interface between application programs and OODBMSs and a portability interface for enabling OODBMS portability.

2. Strengths and weaknesses of the ODMG standard
- Strengths: Provides standards for OODBMSs; incorporates key object-oriented concepts; enables interoperability and portability.
- Weaknesses: The standard is quite complex; not all OODBMS vendors have fully implemented the standard; the standard has not gained widespread use in industry. The ODMG consortium is no longer very active.

### DATALOG language

- DATALOG is a declarative logic programming language used to represent knowledge bases.
- It is a subset of Prolog and has a simple syntax.
- In DATALOG, facts and rules are represented in the form of relationships/predicates.

- Rules are of the form 'head :- body' where head is a predicate and body is a conjunction of atomic formulas (facts and predicates). It means that if body is true, then head must also be true.
- Variables begin with capital letters and constants begin with lowercase letters.
- DATALOG programs can be executed using a backward chaining algorithm to infer new facts.
- Some advantages of DATALOG are simplicity, understandability, and efficient implementations and query evaluations.
- However, it has some limitations like inability to express recursion and inability to handle negation efficiently.

### Deductive database systems and logic programming systems—differences

- Deductive database systems use declarative languages to specify rules and queries. Logic programming systems use procedural languages.
- Deductive database systems have a clear separation between the database of facts and the rules. Logic programming blends facts and rules.
- Deductive database systems evaluate queries using a fixed strategy, typically based on query rewriting and SLD resolution. Logic programming systems allow control strategies and use SLD resolution.
- Deductive database systems typically have additional features for effective implementation, such as stratification and other safety and termination analyses. Logic programming systems have a stronger theoretical foundation.
- Users of deductive database systems see themselves as declarative database users, while users of logic programming see themselves as programming in a logic-based language.

### Temporal databases for the notes of the Unit 5 - Applications in IDBS in the subject of INTELLIGENT DATABASE SYSTEM

1. A temporal database manages time-varying data. It keeps track of valid time, transaction time, and user-defined time.
- Valid time: The time when a fact was true in the real world. e.g. John was an employee of company X from 1 Jan 2019 to 31 Dec 2020.

- Retrieve the employees who were hired after 1 Jan 2018. (Using valid time)
- Show the salary updates made to John's record in 2019. (Using transaction time)
- Get the products that were ordered on 10 Oct 2018. (Using user-defined time)

3. Additional elements in temporal databases:
- Bitemporal: Data is tracked using both valid time and transaction time.
- Point in time: Data as per a particular timestamp.
- Interval: Data over a range of time.
- Previous, current and next versions: Previous, current and next values of an attribute based on time.

- Complexity in modeling time-varying data.
- Additional storage and computational costs to maintain the time-varying data.
- Transaction management gets more complex with temporality.
- Query performance can degrade due to the additional time-related processing.

### Basic indexing methods for the notes of the Unit 5 - Applications in IDBS in the subject of INTELLIGENT DATABASE SYSTEM

1. B-tree indexing:
- B-tree is a self-balancing data structure that keeps data sorted and allows searches, sequential access, insertions, and deletions all in logarithmic time.
- B-trees are commonly used in databases and filesystems due to their performance on modern storage and memory hardware.
- B-trees keep all keys in sorted order, allowing range queries to be processed efficiently.

2. Hash indexing:
- A hash index uses a hash function to compute an index into an array from each value to be indexed.
- This results in fast lookups, inserts, and deletes as long as the hash function distributes the values evenly.
- However, hash indexes do not support efficient traversal of keys or values in sorted order. They also do not support range queries.

3. Bitmap indexing:
- Bitmap indexing is a space-efficient indexing technique suitable for highly cardinal domains.
- Instead of storing index entries for distinct values as in a B-tree, a bitmap is used with one bit per distinct value.
- Bitmaps allow efficient intersection, union, and difference operations useful for various analytics. However, bitmap indexes are only suitable for low-cardinality domains.
