### On RFID False Authentications

1. RFID spoofing: An adversary can create fake RFID tags that contain the ID of a legitimate tag. This is known as RFID spoofing or tag cloning. The adversary can then use the spoofed tag to bypass security systems that rely on RFID for authentication.

2. Relay attacks: In a relay attack, an adversary places themselves between the RFID reader and the target tag. The adversary's device relays signals from the reader to the tag and back, allowing the adversary to steal information from the tag or use the tag to forge authentication. Relay attacks allow adversaries to access RFID tags from a greater distance than normally allowed.

3. Surprise attacks: An adversary may suddenly present an RFID tag to a reader in an attempt to gain access before the system has time to fully authenticate the tag. This type of attack is known as a surprise attack and takes advantage of the fact that RFID authentication is often not strongly time-bounded. Tightly controlling when tags can be read can help mitigate surprise attacks.

4. Security flaws in RFID authentication protocols: Many proprietary RFID authentication protocols have been found to have cryptographic weaknesses or implementation flaws that allow for spoofing, relay attacks, tracking, or information leakage. Adopting standardized, peer-reviewed protocols and properly implementing strong cryptography can help reduce vulnerabilities from protocol flaws.

2. Use of Unique IDs: Each RFID tag should be assigned a unique ID. Using the same ID for multiple tags can enable an adversary to replicate a tag and gain unauthorized access.
3. Restricted Access to Encryption Keys: The encryption keys should be securely stored and access to them should be restricted. If the keys are compromised, it can lead to replication of tags and false authentications.
4. Proximity Checks: Proximity checks can be done to ensure that only authenticated RFID readers can access the data on the tags. If a reader is unable to authenticate itself or is beyond a certain proximity, access to the tag can be denied.
5. Kill Command: RFID tags should support a kill command which can permanently disable the tag if tampering is detected or it is compromised. This prevents further misuse of the compromised tag.

## Unit 3 - FOG COMPUTING

1. Fog Computing: Fog computing refers to a decentralized computing infrastructure in which data, compute, storage, and applications are distributed in the most logical, efficient place between the data source and the cloud.

2. Need for Fog Computing: As IoT devices are generating huge amounts of data, it is not feasible to send all the data to the cloud for processing due to bandwidth constraints and latency issues. Fog computing tackles these challenges by providing compute, storage, and networking services between end devices and traditional cloud computing data centers.

3. Fog Computing Architecture: The fog computing architecture consists of three layers:

- End Devices Layer: This layer consists of IoT devices and sensors that generate data.
- Fog Layer: This layer consists of fog nodes that are located at the edge of the network. Fog nodes provide computing, storage, and networking resources for IoT applications.
- Cloud Layer: This layer consists of cloud data centers that provide virtually unlimited computing and storage resources.

4. Benefits of Fog Computing:
- Reduced latency: Computing is done at the edge, closer to the data source, thereby reducing latency.
- Bandwidth optimization: Only the required data is sent to the cloud, optimizing bandwidth utilization.
- Mobility support: Fog computing supports mobility of IoT devices and data.
- Location awareness: Fog computing enables location-aware IoT applications by processing data close to its source.
- Scalability: Additional fog nodes can be added to scale the fog computing infrastructure.

- Heterogeneity: The fog layer consists of heterogeneous devices and platforms, making it challenging to implement a common framework.
- Limited resources: Fog nodes have limited computing, storage, and networking resources compared to cloud data centers.

- Security: The distribution of resources in fog computing poses security challenges and makes the infrastructure vulnerable to attacks.

-- Low latency: Fog computing reduces latency by bringing computing resources close to the end devices that generate or act on the data.

-- Reduced network bandwidth usage: By processing data locally, fog computing reduces the amount of data that needs to be sent to the cloud.

- Fog computing complements cloud computing and is increasingly being deployed alongside cloud infrastructure. It enables a new class of applications and services that harness the power of cloud resources along with the low latency, location awareness and ubiquity of the edge.

**Point 3:** Some of the key measures and metrics in SNA include:

- Degree centrality: Number of direct connections a node has. A higher degree means a node is more well-connected.
- Betweenness centrality: Measure of how often a node lies on the shortest path between two other nodes. A higher betweenness means a node connects disparate parts of the network.
- Closeness centrality: Measure of how close a node is to all other nodes in the network. A higher closeness means a node can reach other nodes more quickly.
- Density: Measure of how connected the overall network is. A higher density means there are more connections relative to the maximum possible number of connections.
