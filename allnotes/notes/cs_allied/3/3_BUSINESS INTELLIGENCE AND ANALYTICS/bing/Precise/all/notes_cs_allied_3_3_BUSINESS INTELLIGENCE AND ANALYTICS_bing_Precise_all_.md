# Introduction - History and Evolution

Business Intelligence (BI) refers to the technologies, applications, and practices for the collection, integration, analysis, and presentation of business information. The purpose of BI is to support better business decision making.

The concept of BI has been around for many years, with roots dating back to the late 19th century. In 1865, Richard Millar Devens used the term "business intelligence" in his book "Cyclopædia of Commercial and Business Anecdotes" to describe how a banker used information about his competitors to gain a competitive advantage.

In the 20th century, the development of computer technology and the increasing availability of data led to the evolution of BI. In the 1950s and 1960s, computer systems were used to generate reports and perform basic data analysis. In the 1970s, decision support systems (DSS) were introduced, which provided more advanced data analysis capabilities.

In the 1980s and 1990s, the focus shifted towards data warehousing and online analytical processing (OLAP). These technologies allowed for the storage and analysis of large amounts of data, enabling more sophisticated BI capabilities.

In the 21st century, the rise of the internet and the increasing availability of data have led to the development of new BI technologies, such as data mining, predictive analytics, and real-time BI. These technologies allow businesses to gain insights from their data in real-time, enabling faster and more informed decision making.

Overall, the history and evolution of BI have been driven by the need for businesses to make better decisions based on the data available to them. As technology continues to advance, it is likely that BI will continue to evolve, providing businesses with even more powerful tools for decision making.

# Functionalities & Classifications of Data Mining

Data mining is the process of discovering patterns and knowledge from large amounts of data. The data sources can include databases, data warehouses, the internet, and other sources.

The main functionalities of data mining are:

1. **Association rule learning:** This is a method for discovering interesting relations between variables in large databases. For example, a supermarket might gather data on customer purchasing habits. Using association rule learning, the supermarket can determine which products are frequently bought together and use this information for marketing purposes.

2. **Classification:** This is the task of generalizing known structure to apply to new data. For example, an email program might attempt to classify an email as "legitimate" or as "spam".

3. **Clustering:** This is the task of discovering groups and structures in the data that are in some way or another "similar", without using known structures in the data.

4. **Regression:** This is the task of mapping a data item to a real-valued prediction variable.

5. **Summarization:** This involves methods for finding a compact description for a subset of data.

Data mining can be classified into two categories: descriptive data mining and predictive data mining.

- **Descriptive data mining** is concerned with finding patterns that describe the data and can be interpreted by humans. Examples of descriptive data mining tasks include clustering, association rule learning, and summarization.

- **Predictive data mining** is concerned with finding patterns that can be used to predict future behavior or outcomes. Examples of predictive data mining tasks include classification and regression.

# Data Mart

A data mart is a subset of a data warehouse that is designed to serve a specific business unit or function. It is a subject-oriented database that is focused on meeting the specific demands of a particular group of users within an organization.

Here are some key points to consider when discussing data marts:

1. Data marts are designed to provide a more focused view of the data than a data warehouse. They are typically smaller in size and scope than a data warehouse and are optimized for the specific needs of a particular business unit or function.

2. Data marts can be created using a top-down or bottom-up approach. In a top-down approach, the data mart is created as part of the overall design of the data warehouse. In a bottom-up approach, the data mart is created independently of the data warehouse and may be integrated with it at a later time.

3. Data marts can be used to improve the performance of data analysis and reporting. By limiting the scope of the data, data marts can reduce the time and resources required to process queries and generate reports.

4. Data marts can be used to provide a more user-friendly interface to the data. By organizing the data in a way that is more intuitive to the end-users, data marts can make it easier for business users to access and analyze the data.

5. Data marts can be used to improve data quality. By focusing on a specific subset of the data, data marts can provide a more controlled environment for data validation and cleansing.

In summary, a data mart is a subject-oriented database that is designed to meet the specific needs of a particular group of users within an organization. It can provide a more focused view of the data, improve performance, provide a more user-friendly interface, and improve data quality. It is an important tool in the overall architecture of a business intelligence and analytics system.

# Difference between OLAP and OLTP

OLAP (Online Analytical Processing) and OLTP (Online Transaction Processing) are two different types of database systems. They are designed to serve different purposes and have different characteristics.

1. **Purpose**: OLAP is designed for data analysis and decision making. It is used to extract insights from large volumes of data. On the other hand, OLTP is designed for transaction processing and is used to manage day-to-day operations.

2. **Data Structure**: OLAP systems use a multidimensional data model, which allows for complex queries and analysis. OLTP systems use a relational data model, which is optimized for data entry and retrieval.

3. **Data Volume**: OLAP systems typically handle large volumes of data, often in the range of terabytes or petabytes. OLTP systems, on the other hand, handle smaller volumes of data, typically in the range of gigabytes or terabytes.

4. **Query Complexity**: OLAP systems are designed to handle complex queries that involve aggregations and calculations. OLTP systems are designed to handle simple queries that retrieve or update a small number of records.

5. **Performance**: OLAP systems are optimized for query performance, while OLTP systems are optimized for transaction processing. OLAP systems can handle complex queries quickly, while OLTP systems can handle a large number of transactions per second.

6. **Data Update**: OLAP systems are typically updated periodically, often on a daily, weekly, or monthly basis. OLTP systems are updated in real-time, as transactions occur.

These are some of the key differences between OLAP and OLTP systems. They serve different purposes and have different characteristics, and it is important to choose the right type of system for your needs.



# Schema – Star and Snowflake Schemas

## Star Schema
- A star schema is a type of data warehouse design.
- It is called a star schema because the diagram resembles a star, with points radiating from a central table.
- The central table is the fact table and the points of the star are the dimension tables.
- The fact table contains the measures or facts, and the dimension tables contain the descriptive information about the facts.
- The fact table is connected to the dimension tables through foreign keys.
- The star schema is simple and easy to understand.
- It is also easy to write queries against a star schema.

## Snowflake Schema
- A snowflake schema is a variation of the star schema.
- It is called a snowflake schema because the diagram resembles a snowflake.
- The main difference between a star schema and a snowflake schema is that the dimension tables in a snowflake schema are normalized.
- This means that the dimension tables are split into multiple related tables.
- The snowflake schema is more complex than the star schema.
- It can be more difficult to write queries against a snowflake schema.
- However, the snowflake schema can be more efficient in terms of storage space and query performance.

# Data Transformation – Standardization and Feature Extraction

Data transformation is the process of converting data from one format or structure to another, to make it more suitable for analysis or to support specific business requirements. Two common data transformation techniques are standardization and feature extraction.

## Standardization

Standardization is the process of transforming data to have zero mean and unit variance. This is done to ensure that all features have the same scale and can be compared directly. Standardization is important when dealing with data that has different units of measurement or when the range of values for different features varies widely.

To standardize a feature, the mean and standard deviation of the feature are calculated. Then, each value of the feature is transformed using the following formula:

z = (x - mean) / standard deviation

where z is the standardized value, x is the original value, mean is the mean of the feature, and standard deviation is the standard deviation of the feature.

## Feature Extraction

Feature extraction is the process of creating new features from existing ones, to better represent the underlying patterns in the data. This can be done by combining multiple features into a single feature, or by transforming a feature to better capture its relationship with the target variable.

Some common feature extraction techniques include:

- Principal Component Analysis (PCA): PCA is a technique used to reduce the dimensionality of a dataset by creating new features that are linear combinations of the original features. These new features, called principal components, capture the maximum amount of variance in the data.

- Factor Analysis: Factor analysis is similar to PCA, but instead of capturing the maximum amount of variance, it tries to identify underlying factors that explain the correlations between the original features.

# Data Reduction – Sampling

Data reduction is the process of reducing the amount of data that needs to be stored, processed, and analyzed while still maintaining the integrity and usefulness of the data. One of the techniques used for data reduction is sampling.

Sampling is the process of selecting a subset of the data to represent the entire population. The goal of sampling is to obtain a representative sample that can be used to make inferences about the population.

There are several types of sampling techniques that can be used, including:

1. **Simple Random Sampling**: In this technique, each member of the population has an equal chance of being selected for the sample.

2. **Stratified Sampling**: In this technique, the population is divided into strata or subgroups, and a sample is selected from each stratum.

3. **Cluster Sampling**: In this technique, the population is divided into clusters, and a sample of clusters is selected. All members of the selected clusters are included in the sample.

4. **Systematic Sampling**: In this technique, a starting point is selected, and every nth member of the population is included in the sample.

Sampling can be an effective way to reduce the amount of data that needs to be processed and analyzed while still maintaining the integrity and usefulness of the data. However, it is important to carefully select the sampling technique and sample size to ensure that the sample is representative of the population.

# Iris Datasets

The Iris flower data set, also known as Fisher's Iris data set, is a multivariate data set introduced by the British statistician and biologist Ronald Fisher in his 1936 paper "The use of multiple measurements in taxonomic problems" as an example of linear discriminant analysis. It is sometimes called Anderson's Iris data set because Edgar Anderson collected the data to quantify the morphologic variation of Iris flowers of three related species.

The data set contains 3 classes of 50 instances each, where each class refers to a type of iris plant. One class is linearly separable from the other 2; the latter are NOT linearly separable from each other. The predicted attribute is the class of iris plant.

The dataset contains five columns namely – Petal Length, Petal Width, Sepal Length, Sepal Width, and Species Type. Iris is a flowering plant, the researchers have measured various features of the different iris flowers and recorded them digitally.

The iris dataset is considered as the "Hello World" for data science. It is a built-in dataset in R that contains measurements on 4 different attributes (in centimeters) for 50 flowers from 3 different species.

### Root Cause Analysis

2. **Gather data:** Collect data and information related to the problem. This can include interviewing those involved, reviewing documentation, and analyzing data.

4. **Determine the root cause:** Analyze the possible causes to determine the underlying root cause of the problem. This may involve further investigation and data analysis.

5. **Develop and implement solutions:** Once the root cause has been identified, develop and implement solutions to address it. This can include changes to processes, procedures, and systems.

6. **Monitor and evaluate:** Monitor the effectiveness of the solutions implemented and evaluate their impact. This can help to ensure that the problem has been resolved and prevent similar issues from occurring in the future.

Root Cause Analysis is an important tool in the implementation of BI, as it can help to improve processes and prevent future issues. By systematically identifying and addressing the underlying causes of problems, organizations can improve their BI capabilities and achieve better results.
