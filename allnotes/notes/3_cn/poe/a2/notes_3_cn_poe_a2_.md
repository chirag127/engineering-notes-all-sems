#### Layering principles with reference to Network Architecture in Computer Networks:

1. Layered architecture: The network architecture is divided into layers, each layer performing a distinct function. Information passes from one layer to the next, starting at the application layer in one host and proceeding down to the physical layer, across the transmission medium to the next host and back up the layer hierarchy.
2. Encapsulation: As information passes down through the layers, each layer prepends its own header to the data received from the upper layer. This is known as encapsulation. The headers are stripped off as the information passes up through the layers. This allows the layers to be oblivious of the internal structure of information used by the neighboring layers.
3. Well defined interfaces: Between each pair of adjacent layers there is an interface that defines which services the lower layer offers to the upper layer. This allows layers to operate independently as long as they adhere to the interface specifications.
4. Information hiding: By using encapsulation and well-defined interfaces, each layer hides its internal operation and data structures from the layers above and below. This information hiding principle simplifies system design and allows changes to be made in one layer without affecting the other layers.

The above points highlight the key layering principles followed in the network architecture to facilitate modular design, simplified operation and accommodate changes. The layered approach enables diverse technologies and protocols to be implemented at each layer to meet the required functions.

#### The OSI reference model in Computer Networks

The OSI reference model is a conceptual framework used to describe and standardize the internal functions of a communication system by partitioning it into abstraction layers.

The OSI reference model consists of seven layers:

1. Physical layer: deals with the physical connections between the devices. It converts data into signals and transmits over the medium.
2. Data link layer: provides node-to-node data transfer. It handles data transmission between the devices. It adds MAC addresses to identify the devices.
3. Network layer: handles routing and forwarding of the packets. It determines the best path to route the packets. It uses IP addresses to identify the devices.
4. Transport layer: provides end-to-end data transfer. It handles segmenting and reassembling of packets. It provides protocols like TCP and UDP.
5. Session layer: manages the sessions between applications. It establishes, maintains and terminates the connections between the local and remote applications.
6. Presentation layer: handles data formatting and conversion. It converts the data to a format that the application layer can understand.
7. Application layer: provides interfaces for the applications to access the network. It has protocols like HTTP, FTP, SMTP, etc. for different applications.

The OSI reference model is a conceptual framework to understand the networking concepts and protocols in a structured manner. Though the model is rarely implemented entirely in practice, it serves as a useful tool for teaching, designing and standardizing network protocols.

### Network topology design in Computer Networks

1. Bus topology: All devices are connected to a central cable called bus. Data is transmitted across the bus and received by all devices. Devices checks the destination address and accepts the data intended for it. Advantage: Inexpensive, easy to connect new devices. Disadvantage: Heavy traffic can slow down the network, troubleshooting is difficult.
2. Star topology: All devices are connected to a central switch. Data is transmitted between the source and destination devices through the switch. Advantage: Easy to troubleshoot, scalable. Disadvantage: Dependency on the central switch, single point of failure.
3. Ring topology: All devices are connected in a closed loop. Data is transmitted in one direction around the ring. Advantage: Equal access to bandwidth for all devices. Disadvantage: Troubleshooting is difficult, failure of one device affects the whole network.
4. Mesh topology: Each device is connected to every other device in the network. Data can take multiple paths to reach the destination. Advantage: Fault tolerant, robust. Disadvantage: Complex, costly and difficult to configure.

The topology to be chosen depends on factors like cost, scalability, fault-tolerance, etc. A hybrid of two or more basic topologies can also be used to achieve various objectives.

#### Network performance and transmission impairments in Computer Networks.

1. Bandwidth - The amount of data that can be transmitted through a network at a given time. Higher bandwidth leads to faster data transmission. Limited bandwidth can lead to slower access of resources and latency.
2. Latency - The time taken for data to travel from source to destination. Higher latency leads to slower response times and can affect real-time applications like video calling. Causes include limited bandwidth, long physical path, and processing delays.
3. Jitter - Variation in latency between packets. Can affect real-time applications and voice/video quality. Causes include congestion, improper queuing, etc. Buffering and delay compensation techniques are used to minimize jitter.
4. Packet Loss - Loss of packets during transmission due to congestion, corruption, etc. Can affect application performance and lead to retransmission of packets, increasing latency. Techniques like forward error correction (FEC) and retransmission are used to recover from packet loss.
5. Security attacks - Malicious actors can launch attacks to breach network security, access data, or disrupt network performance. Examples include denial-of-service (DoS) attacks, man-in-the-middle (MITM) attacks, and spoofing attacks. Strong authentication and encryption techniques are used to prevent such attacks.

The above points cover the major network performance parameters and transmission impairments that can impact the performance of applications and services running on the network. Optimizing and monitoring these parameters is critical for providing a good quality of service and user experience.

#### Switching techniques and multiplexing in Computer Networks.

- Circuit switching: Establishes a dedicated end-to-end path between two nodes before the actual transmission of data. inefficient use of bandwidth. Example: Traditional telephone network.

- CDM (Code Division Multiplexing): Using different codes to differentiate between multiple data streams transmitted over the same bandwidth. Example: 3G/4G cellular networks.

#### Elementary Data Link Protocols in link layer in Computer Networks.

### Congestion control algorithms in cn

1. Slow start: When a connection is established, congestion window is initialized to 1 or 2 segments. In each RTT, congestion window is increased by 1. This leads to exponential increase in congestion window. This phase is called slow start. The goal of slow start is to quickly open up the window and grab as much bandwidth as possible.
2. Congestion avoidance: Once slow start threshold is reached, congestion avoidance phase starts. In this phase, congestion window is increased linearly (one segment per RTT). This is done to probe the network for available bandwidth without overloading the network.
3. Fast retransmit: If duplicate ACKs are received, it indicates that segments have been dropped. So the dropped segments are retransmitted without waiting for the timeout. This is called fast retransmit.
4. Fast recovery: After fast retransmit, congestion window is set to half its previous value. This is called fast recovery. New segments are sent only after 3 duplicate ACKs are received. This helps in preventing bursty traffic into the network.
5. Timeouts: If an ACK is not received for a segment within a certain amount of time called timeout, the segment is retransmitted. This is required when duplicate ACKs are not received. Timeout values can be quite high leading to noticeable delays.

The above points summarise the key congestion control algorithms used in TCP to control congestion and achieve maximum throughput without overloading the network. The algorithms work in tandem with each other to adapt to the changing network conditions.

### Flow control in transport layer

1. Flow control is a technique to regulate the transmission of data to prevent overflow. In transport layer, flow control is implemented to prevent the receiving device from being overwhelmed by too much data sent by the sending device.
2. The receiving device has a fixed buffer size. If data is received faster than it can be processed, the buffer may overflow resulting in loss of data. Flow control mechanisms help avoid this situation by controlling the transmission rate.
3. The most commonly used flow control mechanisms are:
 - Sliding window protocol: The sending device is allowed to send only a fixed number of frames before waiting for an acknowledgement from the receiving device. The window size determines how many frames can be sent at a time.
 - Credit-based flow control: The receiving device sets a limit on the number of bytes that can be received, known as credit. The sending device can only send data if it has credits available. As the receiver processes data, it releases credits back to the sender.
4. Flow control is implemented using feedback messages from the receiver to the sender conveying information about its buffer occupancy. The sender can then adjust its transmission rate accordingly to prevent overflow. Effective flow control mechanisms allow for efficient utilization of the network bandwidth while avoiding congestion.

### TCP Congestion control in transport layer

1. TCP employs a congestion avoidance algorithm that aims to reduce congestion in the network and prevent packet loss.
2. TCP monitors the rate of returning acknowledgements (ACKs) from the receiver. If ACKs return at a slower rate than expected, it is a sign of congestion in the network. TCP will then slow down its transmission rate.
3. TCP uses an "Additive Increase Multiplicative Decrease" (AIMD) algorithm. The transmission rate is increased additively on each round trip time (RTT) if there is no congestion. However, upon detection of congestion via loss of ACKs, TCP reduces its transmission rate multiplicatively. This leads to a sawtooth pattern of slow increase followed by a sharp decrease in transmission rate. This probes for available bandwidth in the network while avoiding persistent high congestion.
4. Modern TCP implementations use mechanisms like slow start and congestion avoidance to more efficiently probe for bandwidth and recover from losses. TCP optimizes throughput while avoiding congestion collapse.
5. TCP's congestion control makes it a "responsive" and "fair" transport protocol that adapts to the available bandwidth and shares it fairly with other TCP flows in the network. This makes the Internet's packet-switched network more efficient and robust.

3. Key exchange - Two parties communicating over the network need to establish a shared secret key to encrypt their data. Key exchange protocols are used to negotiate and establish a shared key. Some popular key exchange protocols are Diffie-Hellman key exchange and Elliptic curve Diffie-Hellman key exchange.

4. Hashing - Hashing functions are used to generate a short digest of a larger data such as files and messages. Even a small change in the data results in a different hash value. This is useful to verify data integrity. Some commonly used hashing algorithms are SHA-1, SHA-256, MD5 etc. Hashing is used to store passwords in databases in a secured way.

### Basic concepts of Cryptography in application layer

1. Encryption - Converting plain text into ciphertext using a encryption algorithm and key. It ensures confidentiality.
2. Decryption - Converting ciphertext back to plain text using a decryption algorithm and key. The decryption key is same as encryption key.
3. Symmetric key cryptography - Uses a single key for both encryption and decryption. Eg: AES, DES, Blowfish.
4. Asymmetric key cryptography - Uses a pair of public and private keys. Eg: RSA, ECC. Public key is used for encryption and private key is used for decryption.
5. Hash functions - Produces a fixed-size hash value from a variable size input. Eg: MD5, SHA-1, SHA-256. It is a one-way function and used to verify data integrity.
6. Digital signatures - Encrypts hash of a message using private key. Used to achieve authentication and non-repudiation. The message can be verified using public key.
7. Certificates - Used in public key infrastructure to bind public keys with identities. It contains public key and other identity details digitally signed by a CA.
