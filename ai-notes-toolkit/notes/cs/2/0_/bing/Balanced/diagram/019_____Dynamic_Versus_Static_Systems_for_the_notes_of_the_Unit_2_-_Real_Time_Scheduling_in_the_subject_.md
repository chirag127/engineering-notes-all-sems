### Dynamic Versus Static Systems

- A **static system** is one where the tasks and their attributes (such as arrival time, execution time, deadline, priority, etc.) are known in advance and do not change during the system execution. A static system can be scheduled offline, i.e., before the system runs, by using a fixed priority or a fixed order of execution for the tasks. A static system can be validated for its correctness and timeliness, i.e., whether it meets all the deadlines and satisfies all the constraints. A static system provides a predictable and deterministic behavior, which is desirable for hard real-time systems. However, a static system may not be able to handle dynamic changes in the workload or the environment, and may not utilize the system resources efficiently.   

- A **dynamic system** is one where the tasks and their attributes may change during the system execution, or may not be known in advance. A dynamic system requires online scheduling, i.e., during the system runs, by using a variable priority or a variable order of execution for the tasks. A dynamic system can adapt to the changing workload or the environment, and may utilize the system resources more efficiently. However, a dynamic system may not be able to guarantee the correctness and timeliness of the tasks, and may introduce more complexity and overhead in the scheduling algorithm. A dynamic system provides a flexible and adaptive behavior, which is suitable for soft real-time systems.   

- The choice of static or dynamic system depends on the characteristics and requirements of the real-time application. For simple real-time systems, that have a small and fixed number of tasks that function in a pipeline fashion, one may use static scheduling. For more complex real-time systems, that have a large but fixed number of tasks that do not function in a pipeline fashion, one may need static scheduling. And for real-time systems where the workload keeps changing, one may need dynamic scheduling.
