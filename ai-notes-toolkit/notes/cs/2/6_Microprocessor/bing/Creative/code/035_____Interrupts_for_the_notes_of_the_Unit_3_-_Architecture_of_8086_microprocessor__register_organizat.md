### Interrupts

- Interrupts are signals that cause the CPU to suspend its current execution and transfer the control to a predefined service routine, called an interrupt handler or an interrupt service routine (ISR).
- Interrupts can be classified into two types: hardware interrupts and software interrupts.
- Hardware interrupts are generated by external devices, such as keyboards, timers, printers, etc., to request the CPU's attention. Software interrupts are generated by the CPU itself or by a program to invoke an operating system service or a user-defined function.
- The 8086 microprocessor has two hardware interrupt pins: NMI (Non-Maskable Interrupt) and INTR (Interrupt Request). NMI is a high-priority interrupt that cannot be disabled or ignored by the CPU. INTR is a low-priority interrupt that can be enabled or disabled by the software using the STI (Set Interrupt Flag) and CLI (Clear Interrupt Flag) instructions.
- The 8086 microprocessor also has one software interrupt instruction: INT (Interrupt). The INT instruction takes an 8-bit operand that specifies the type of interrupt to be generated. The type number ranges from 0 to 255, and each type corresponds to a different service routine.
- The 8086 microprocessor uses an Interrupt Vector Table (IVT) to store the addresses of the interrupt handlers. The IVT is a 256-entry table that starts from the memory address 0x0000 and ends at 0x03FF. Each entry in the IVT is a 4-byte pointer that contains the segment and offset addresses of the interrupt handler. The type number of the interrupt is used as an index to access the corresponding entry in the IVT.
- When an interrupt occurs, the CPU performs the following steps:
  - It pushes the flags register, the code segment register, and the instruction pointer onto the stack.
  - It clears the interrupt flag (IF) to disable further interrupts.
  - It calculates the address of the interrupt handler by multiplying the type number by 4 and adding it to the base address of the IVT (0x0000).
  - It fetches the segment and offset addresses of the interrupt handler from the IVT and loads them into the code segment register and the instruction pointer, respectively.
  - It executes the interrupt handler until it encounters an IRET (Interrupt Return) instruction.
  - It pops the instruction pointer, the code segment register, and the flags register from the stack and resumes the execution of the interrupted program.
