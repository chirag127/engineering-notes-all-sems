### Security interface for the notes of the Unit 3 - Secure architecture principles isolation and leas in the subject of COMPUTER SYSTEM SECURITY

- The security interface is a set of user interface elements that provide access to security features such as authorization, access to digital certificates, and access to items in keychains.
- The security interface framework is based on the Objective-C programming language and is part of the macOS operating system.
- The security interface framework allows applications to request the user's permission to perform privileged operations, such as modifying system files, installing software, or accessing protected resources.
- The security interface framework also allows applications to display and manage digital certificates, which are used to verify the identity and authenticity of entities on the internet, such as websites, servers, or users.
- The security interface framework also allows applications to access and manipulate items in keychains, which are secure storage containers for passwords, encryption keys, certificates, and other sensitive information.

- Secure architecture principles are the guidelines and best practices for designing and implementing secure systems and applications.
- Secure architecture principles include the following:

  - Compartmentalization: This principle involves dividing a system or application into smaller and isolated components, each with a specific function and minimal access to other components. This reduces the attack surface and the impact of a compromise.
  - Isolation: This principle involves separating different components or processes from each other, either physically or logically, to prevent unauthorized or unintended interactions. This enhances the confidentiality, integrity, and availability of the system or application.
  - Principle of least privilege: This principle involves granting the minimum amount of privileges or permissions to each component or process, based on its function and need. This limits the potential damage or misuse of the system or application.
  - Defense in depth: This principle involves using multiple and diverse security mechanisms to protect the system or application from different types of threats and vulnerabilities. This increases the resilience and robustness of the system or application.
  - Secure the weakest link: This principle involves identifying and strengthening the most vulnerable or exposed parts of the system or application, such as the network, the user interface, or the data storage. This prevents the exploitation of the weakest link to compromise the whole system or application.
  - Fail securely: This principle involves designing and implementing the system or application to handle errors, exceptions, or failures in a secure manner, without exposing sensitive information or allowing unauthorized access. This preserves the security and functionality of the system or application.
  - Keep it simple: This principle involves avoiding unnecessary complexity or functionality in the system or application, which may introduce errors, bugs, or vulnerabilities. This improves the maintainability and reliability of the system or application.
