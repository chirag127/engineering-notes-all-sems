### Secure development for the notes of the Unit 3 - Secure architecture principles isolation and least privilege

Secure development is the process of creating software systems that are resilient to security threats and vulnerabilities. Secure development requires following a set of principles, practices, and tools that help identify and prevent security flaws during early stages of software development, when it is most cost effective to do so.

Some of the secure development principles are:

- **Minimize attack surface area**: This principle states that every feature or functionality added to a software system increases the risk of a security vulnerability. Therefore, developers should only implement the essential features and functionalities that are required by the system, and avoid unnecessary or unused code that could expose the system to attacks.
- **Establish secure defaults**: This principle states that the default configuration and settings of a software system should be secure and not expose the system to unnecessary risks. For example, the default permissions for files and directories should be restrictive, the default passwords should be strong and unique, and the default encryption should be enabled.
- **The principle of least privilege**: This principle states that every user, process, or component of a software system should only have the minimum level of access or privilege that is necessary to perform its function. This principle reduces the impact of a security breach, as an attacker would have limited access to the system resources and data .
- **The principle of defense in depth**: This principle states that a software system should have multiple layers of security controls and mechanisms that protect it from different types of attacks. For example, a software system could have firewalls, encryption, authentication, authorization, logging, monitoring, and auditing as different layers of defense. This principle increases the difficulty and cost of an attack, as an attacker would have to bypass multiple security barriers to compromise the system.
- **Fail securely**: This principle states that a software system should handle errors and exceptions in a secure manner, and not reveal sensitive information or expose the system to further attacks. For example, a software system should not display detailed error messages that could disclose the system configuration or vulnerabilities, but rather display generic messages that inform the user of the problem.
- **Don't trust services**: This principle states that a software system should not blindly trust the inputs, outputs, or communications from other services or components that it interacts with. For example, a software system should validate and sanitize the inputs from users or other systems, encrypt and authenticate the communications with other systems, and verify the integrity and authenticity of the outputs from other systems.
- **Separation of duties**: This principle states that a software system should separate the roles and responsibilities of different users, processes, or components that are involved in the system's operation. For example, a software system should not allow the same user or process to perform both the creation and the approval of a transaction, as this could lead to fraud or abuse. This principle reduces the risk of collusion, corruption, or compromise of the system.
- **Avoid security by obscurity**: This principle states that a software system should not rely on hiding or obscuring the details of its design, implementation, or configuration as a means of security. For example, a software system should not use secret algorithms, hard-coded passwords, or hidden backdoors as security measures, as these could be discovered and exploited by attackers. This principle advocates for using open and standard security mechanisms that are well-known and tested.

These are some of the secure development principles that can help create software systems that are secure by design. However, these principles are not exhaustive or definitive, and they should be applied with care and context. Developers should also use secure development tools and practices, such as security testing, code review, threat modeling, and security training, to ensure the quality and security of their software systems   .
