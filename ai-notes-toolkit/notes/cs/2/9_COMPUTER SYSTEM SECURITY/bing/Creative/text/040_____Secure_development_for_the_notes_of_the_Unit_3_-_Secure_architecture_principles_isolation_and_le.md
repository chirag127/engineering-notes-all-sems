### Secure development for the notes of the Unit 3 - Secure architecture principles isolation and least privilege

Secure development is the process of creating software systems that are resilient to security threats and vulnerabilities. Secure development requires following a set of principles, practices and tools that help identify and prevent security flaws during early stages of software development, when it is most cost effective to do so.

Some of the secure development principles are:

- **Minimize attack surface area**: This principle states that every feature or functionality added to a software system increases the risk of a security vulnerability. Therefore, developers should only implement the essential features and functionalities that are required by the system, and avoid unnecessary or unused code, services, ports, protocols, etc. that could expose the system to attacks.
- **Establish secure defaults**: This principle states that the default configuration and settings of a software system should be secure and not expose the system to unnecessary risks. For example, the default permissions, passwords, encryption keys, etc. should be strong and not easily guessed or compromised. Developers should also provide clear and secure guidance for users to change the default settings if needed.
- **The principle of least privilege**: This principle states that every user, process, or component of a software system should only have the minimum level of access or privilege that is necessary to perform its function. This principle reduces the impact of a security breach, as an attacker would have limited access to the system resources and data. For example, a web application should not run as a root or administrator user, but as a low-privileged user that can only access the files and databases that are relevant to the application .
- **The principle of defense in depth**: This principle states that a software system should have multiple layers of security controls and mechanisms that protect it from different types of attacks. This principle increases the difficulty and cost of an attack, as an attacker would have to bypass or compromise multiple security barriers to reach the system assets. For example, a web application should have security measures at the network, application, and data layers, such as firewalls, encryption, authentication, authorization, input validation, output encoding, etc.
- **Fail securely**: This principle states that a software system should handle errors and exceptions in a secure manner that does not compromise the security or functionality of the system. For example, a web application should not display sensitive or detailed error messages to the users, as they could reveal information about the system architecture, configuration, or vulnerabilities. Instead, the application should log the errors internally and display generic or friendly error messages to the users.
- **Don’t trust services**: This principle states that a software system should not blindly trust the inputs, outputs, or communications from other services or components that it interacts with. For example, a web application should not assume that the data received from a web service or a database is valid, safe, or accurate. Instead, the application should verify, sanitize, and validate the data before processing or storing it.
- **Separation of duties**: This principle states that a software system should have different roles and responsibilities for different users, processes, or components that are involved in the system operations. This principle prevents conflicts of interest, collusion, or abuse of power that could compromise the security or integrity of the system. For example, a web application should have separate roles for developers, testers, administrators, and users, and enforce the appropriate access controls and audit trails for each role.
- **Avoid security by obscurity**: This principle states that a software system should not rely on hiding or obscuring its security mechanisms or vulnerabilities as a form of protection. For example, a web application should not use encryption algorithms or keys that are proprietary, secret, or hard-coded. Instead, the application should use standard, well-known, and tested encryption algorithms and keys that are securely managed and stored.

These are some of the secure development principles that can help developers create software systems that are more secure and robust. However, these principles are not exhaustive or sufficient by themselves, and developers should also follow the best practices and guidelines for secure software development that are relevant to their specific domain, technology, and platform   .
