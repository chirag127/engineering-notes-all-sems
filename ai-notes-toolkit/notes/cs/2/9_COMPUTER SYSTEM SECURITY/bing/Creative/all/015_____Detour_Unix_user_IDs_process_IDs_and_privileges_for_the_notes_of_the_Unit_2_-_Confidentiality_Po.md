# Detour Unix user IDs process IDs and privileges

- Unix is a multi-user operating system that allows multiple users to access the same system and share its resources.
- Each user of a Unix system has a unique identifier called a user ID (UID). The UID is an integer number that is assigned to the user when the account is created. The UID is used to identify the owner of files and processes, and to determine the access permissions for the system resources.
- The UID 0 is reserved for the superuser (also known as root or system administrator), who has full access and control over the system. The superuser can create, modify, or delete any file or process, regardless of the owner or permissions.
- A user account can belong to multiple groups, each of which has a unique identifier called a group ID (GID). The GID is also an integer number that is assigned to the group when it is created. The GID is used to identify the members of a group and to determine the access permissions for the system resources.
- A group can have a special GID called a setgid bit, which means that any file or process created by a member of the group will inherit the group ownership and permissions of the group, rather than the user who created it.
- A process is an instance of a running program that has a unique identifier called a process ID (PID). The PID is also an integer number that is assigned to the process when it is created. The PID is used to identify the process and to manage its execution and resources.
- A process is associated with a pair of UID and GID, which determine the privileges and permissions of the process. The process inherits the UID and GID of the user who executed the program, unless the program has a special bit called a setuid bit, which means that the process will run with the UID and GID of the owner of the program, rather than the user who executed it.
- A process can have three types of UIDs and GIDs: real, effective, and saved. The real UID and GID are the original UID and GID of the user who executed the program. The effective UID and GID are the current UID and GID of the process, which are used to evaluate the privileges and permissions of the process. The saved UID and GID are the UID and GID of the program file, which are stored in case the process needs to restore its privileges.
- A process can change its effective UID and GID as long as the new UID and GID are the same as either the real or the saved UID and GID. This allows the process to drop or restore its privileges temporarily or permanently, depending on the needs of the program. For example, a process that executes a setuid program can drop its privilege permanently by setting its effective, real, and saved UIDs and GIDs to the same value, or drop its privilege temporarily by setting its effective UID and GID to the same value as the real UID and GID, and later restore its privilege by setting its effective UID and GID to the same value as the saved UID and GID.
