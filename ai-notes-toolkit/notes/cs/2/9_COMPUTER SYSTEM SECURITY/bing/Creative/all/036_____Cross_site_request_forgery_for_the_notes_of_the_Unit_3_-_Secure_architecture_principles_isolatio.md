# Cross Site Request Forgery (CSRF)

- Cross Site Request Forgery (CSRF) is a type of web application attack that exploits the trust between a user and a web application.
- CSRF occurs when an attacker tricks a user into performing an action on a web application that the user is already authenticated with, such as changing their password, transferring funds, or deleting their account.
- CSRF can be performed by sending a malicious link, image, or form to the user via email, chat, or social media, and making the user click on it or view it in their browser.
- CSRF can also be performed by embedding malicious code in a third-party website that the user visits, and making the user's browser send a request to the web application without the user's knowledge or consent.
- CSRF can cause serious damage to the user and the web application, such as data theft, identity theft, account takeover, or financial loss.
- CSRF can be prevented by using various techniques, such as:
  - Using anti-CSRF tokens, which are unique and random values that are generated by the web application and sent to the user along with the form or request, and verified by the web application before processing the request.
  - Using the SameSite attribute, which is a flag that can be set on cookies to indicate whether they should be sent along with cross-site requests or not.
  - Using the Origin or Referer headers, which are HTTP headers that indicate the source of the request, and can be checked by the web application to ensure that the request is coming from a legitimate origin or referer.
  - Using the Content Security Policy (CSP), which is a mechanism that allows the web application to specify which sources of content are allowed or disallowed in the web page, and can prevent the execution of malicious code from third-party websites.
