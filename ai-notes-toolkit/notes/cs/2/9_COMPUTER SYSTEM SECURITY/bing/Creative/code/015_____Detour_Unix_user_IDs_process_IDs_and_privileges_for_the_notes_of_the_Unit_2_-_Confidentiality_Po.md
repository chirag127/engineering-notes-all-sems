### Detour Unix user IDs process IDs and privileges

- Unix is a multi-user operating system that allows multiple users to access the same system and share its resources.
- Each user of a Unix system has a unique identifier called a user ID (UID), which is an integer number that represents the identity of the user.
- The UID 0 is reserved for the superuser or the system administrator, who has the highest level of privileges and can perform any action on the system.
- A user can belong to one or more groups, which are collections of users that share some common attributes or permissions. Each group has a group ID (GID), which is another integer number that represents the identity of the group.
- A process is an instance of a running program that executes some instructions on the system. Each process has a process ID (PID), which is a unique integer number that identifies the process among other processes on the system.
- A process is also associated with a UID and a GID, which determine the privileges of the process to access the system resources, such as files, devices, memory, etc. The UID and GID of a process are inherited from the user who created the process, unless the process executes a special program that changes them.
- A process can have three types of UIDs and GIDs: real, effective, and saved.
  - The real UID (RUID) and GID (RGID) are the original UID and GID of the user who created the process. They are used to identify the owner of the process and cannot be changed by the process itself.
  - The effective UID (EUID) and GID (EGID) are the current UID and GID of the process. They are used to evaluate the privileges of the process to perform a particular action, such as opening a file, sending a signal, etc. They can be changed by the process itself, but only to the values of the real or the saved UID and GID.
  - The saved UID (SUID) and GID (SGID) are the UID and GID of the program that the process is executing. They are used to store the privileged UID and GID of a program that has the setuid or setgid bit on it. The setuid and setgid bits are special permissions that allow a program to run with the privileges of its owner or group, regardless of the user who executes it. The saved UID and GID can be changed by the process itself, but only to the values of the real or the effective UID and GID.
- A process can change its effective UID and GID by using the system calls setuid, seteuid, setgid, and setegid. These system calls allow the process to drop or restore its privileges temporarily or permanently, depending on the arguments passed to them.
  - To drop privileges permanently, the process must set its effective, real, and saved UID and GID to the same value, which is usually the UID and GID of the user who executed the program. This prevents the process from regaining its privileges later.
  - To drop privileges temporarily, the process must set its effective UID and GID to the value of its real UID and GID, and store its privileged UID and GID in its saved UID and GID. This allows the process to restore its privileges later by setting its effective UID and GID to the value of its saved UID and GID.
- Dropping privileges is a common technique used by setuid and setgid programs to limit their exposure to security risks. For example, a setuid program that needs to perform some privileged actions at the beginning, such as opening a file or binding a socket, can drop its privileges after completing those actions and before executing any untrusted code or input from the user. This reduces the chances of the program being exploited by malicious users or attackers.
