# Hijacking & Defense

- Hijacking is a type of network security attack in which the attacker takes control of computer systems, software programs and/or network communications .
- Hijacking can be used for various malicious purposes, such as stealing information, spying on users, displaying persistent advertising, redirecting traffic, executing commands, or disrupting services .
- Hijacking can be performed at different levels of the network stack, such as the application layer, the transport layer, or the network layer .
- Some common examples of hijacking attacks are:
  - **Browser hijacking**: The attacker modifies the user's browser settings, such as the home page, the search engine, the toolbar, or the extensions, to redirect the user to unwanted or malicious websites.
  - **Session hijacking**: The attacker intercepts and exploits the user's session with a web server, such as an online banking or shopping site, to gain unauthorized access to the user's account or data.
  - **IP hijacking**: The attacker takes over an IP address or a range of IP addresses that belong to another entity, such as an Internet Service Provider (ISP) or a domain name registrar, to redirect or block network traffic.
  - **Control hijacking**: The attacker exploits a vulnerability in the software running on the user's computer, such as a buffer overflow or an integer overflow, to inject malicious code or alter the control flow of the program.
- Defense against hijacking attacks requires a combination of preventive, detective, and corrective measures, such as:
  - **Preventive measures**: These are aimed at reducing the likelihood or impact of hijacking attacks, such as using strong encryption, authentication, and authorization protocols, applying software patches and updates, configuring firewalls and antivirus software, and educating users about safe browsing habits .
  - **Detective measures**: These are aimed at identifying and analyzing hijacking attacks, such as using network monitoring and auditing tools, performing penetration testing and vulnerability scanning, and reporting and sharing information about hijacking incidents .
  - **Corrective measures**: These are aimed at restoring the normal functioning of the system or network after a hijacking attack, such as removing malicious software, changing passwords and security settings, recovering lost or corrupted data, and contacting the relevant authorities or service providers .
- Some specific defense techniques against hijacking attacks are:
  - **Defense against browser hijacking**: The user can use a reputable browser that has built-in security features, such as blocking pop-ups, warning about suspicious sites, and allowing the user to reset the browser settings. The user can also avoid clicking on unknown links or attachments, downloading untrusted software, or granting permissions to unknown websites or extensions.
  - **Defense against session hijacking**: The web server can use secure protocols, such as HTTPS and SSL/TLS, to encrypt the communication between the server and the client. The web server can also use session tokens or cookies that are unique, random, and time-limited, and validate them at each request. The web server can also implement logout and timeout mechanisms to terminate inactive or suspicious sessions.
  - **Defense against IP hijacking**: The network administrator can use secure routing protocols, such as BGPsec and RPKI, to verify the authenticity and integrity of the routing information exchanged between different network entities. The network administrator can also monitor the network traffic and detect any anomalies or deviations from the normal patterns.
  - **Defense against control hijacking**: The software developer can use secure coding practices, such as input validation, bounds checking, and exception handling, to prevent or mitigate the exploitation of software vulnerabilities. The software developer can also use techniques such as complete memory safety, code pointer integrity, and control flow integrity, to protect the software from malicious code injection or alteration.
