### Web security definitions goals and threat models

- Web security is the practice of protecting web applications and web servers from unauthorized access, modification, or destruction by malicious actors or accidental events.
- The goals of web security are to ensure the confidentiality, integrity, and availability of web resources and data, as well as to prevent or mitigate the impact of web-based attacks such as cross-site scripting, SQL injection, denial-of-service, phishing, etc.
- A threat model is a structured process for identifying and assessing the potential threats and vulnerabilities that may affect a web system, and for prioritizing and implementing the appropriate countermeasures to reduce or eliminate the risks.
- A threat model typically consists of the following steps  :
  - Define the scope and boundaries of the web system, such as the components, interfaces, data flows, assets, users, and trust boundaries.
  - Identify the security objectives and requirements of the web system, such as the desired level of confidentiality, integrity, and availability, as well as the compliance and regulatory standards that apply.
  - Identify the potential threats and vulnerabilities that may compromise the security objectives and requirements of the web system, such as the sources, methods, and motivations of the attackers, and the weaknesses or flaws in the web system design, implementation, or configuration.
  - Analyze the likelihood and impact of each threat and vulnerability, and assign a risk rating based on the severity and probability of occurrence.
  - Identify and evaluate the possible countermeasures that can prevent, detect, or mitigate each threat and vulnerability, and estimate the cost and benefit of each option.
  - Prioritize and implement the most effective and feasible countermeasures, and document the rationale and assumptions behind the decisions.
  - Review and update the threat model periodically, or whenever there are significant changes to the web system or the threat landscape.
- A threat model can use various methods and tools to facilitate the process, such as diagrams, checklists, frameworks, or software. Some examples of threat modeling methods and tools are  :
  - STRIDE: A mnemonic that stands for Spoofing, Tampering, Repudiation, Information disclosure, Denial of service, and Elevation of privilege, which are six categories of threats that can be used to classify and analyze the potential attacks on a web system.
  - DREAD: A mnemonic that stands for Damage, Reproducibility, Exploitability, Affected users, and Discoverability, which are five factors that can be used to quantify and compare the risk level of different threats on a web system.
  - Application Security Frame (ASF): A framework that defines seven categories of security requirements for web applications, such as Auditing & Logging, Authentication, Authorization, Configuration Management, Data Protection in Storage and Transit, Data Validation, and Exception Management, which can be used to guide the threat identification and countermeasure selection process.
  - OWASP Cheat Sheet Series: A collection of concise and practical guides on various web security topics, such as threat modeling, secure coding, testing, and deployment, which can be used as references and checklists for web security best practices.
