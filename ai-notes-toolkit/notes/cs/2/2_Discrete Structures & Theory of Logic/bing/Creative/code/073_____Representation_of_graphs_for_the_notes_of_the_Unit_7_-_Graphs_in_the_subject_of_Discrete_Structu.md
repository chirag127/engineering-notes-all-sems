### Representation of graphs

A graph is a mathematical structure that consists of a set of vertices and a set of edges that connect pairs of vertices. A graph can be used to model various phenomena, such as networks, relations, paths, circuits, etc.

There are different ways to represent a graph, depending on the purpose and the type of the graph. Some of the common representations are:

- **Adjacency matrix**: An adjacency matrix is a two-dimensional array of size n x n, where n is the number of vertices in the graph. Each entry A[i][j] of the matrix indicates whether there is an edge from vertex i to vertex j in the graph. If the graph is undirected, the matrix is symmetric, meaning A[i][j] = A[j][i] for all i and j. If the graph is directed, the matrix is not necessarily symmetric, meaning A[i][j] may not equal A[j][i]. If the graph is weighted, the matrix entries can store the weights of the edges, instead of just 0 or 1. The advantage of using an adjacency matrix is that it is easy to check if two vertices are adjacent, or to find the degree of a vertex, by looking at the corresponding row or column of the matrix. The disadvantage is that it takes O(n^2) space, which can be wasteful if the graph is sparse (has few edges).

- **Adjacency list**: An adjacency list is a one-dimensional array of size n, where n is the number of vertices in the graph. Each entry A[i] of the array stores a list of vertices that are adjacent to vertex i in the graph. If the graph is undirected, each edge appears twice in the adjacency list, once for each endpoint. If the graph is directed, each edge appears only once, from the source to the destination. If the graph is weighted, the list entries can store the weights of the edges, along with the adjacent vertices. The advantage of using an adjacency list is that it takes O(n + m) space, where m is the number of edges in the graph, which can be much less than O(n^2) if the graph is sparse. The disadvantage is that it takes O(d) time to check if two vertices are adjacent, or to find the degree of a vertex, where d is the maximum degree of any vertex in the graph.

- **Incidence matrix**: An incidence matrix is a two-dimensional array of size n x m, where n is the number of vertices and m is the number of edges in the graph. Each entry B[i][j] of the matrix indicates whether vertex i is incident to edge j in the graph. If the graph is undirected, the matrix entries are either 0 or 1, meaning vertex i is either not incident or incident to edge j. If the graph is directed, the matrix entries can be -1, 0, or 1, meaning vertex i is either the source, not incident, or the destination of edge j. If the graph is weighted, the matrix entries can store the weights of the edges, instead of just 0, 1, or -1. The advantage of using an incidence matrix is that it is easy to find the endpoints of an edge, or to find the edges incident to a vertex, by looking at the corresponding column or row of the matrix. The disadvantage is that it takes O(nm) space, which can be wasteful if the graph is dense (has many edges).

- **Edge list**: An edge list is a one-dimensional array of size m, where m is the number of edges in the graph. Each entry E[i] of the array stores a pair of vertices that form an edge in the graph. If the graph is undirected, the order of the vertices in the pair does not matter. If the graph is directed, the order of the vertices in the pair indicates the direction of the edge. If the graph is weighted, the pair entries can store the weight of the edge, along with the vertices. The advantage of using an edge list is that it takes O(m) space, which can be less than O(n^2) or O(nm) if the graph is sparse and has few vertices. The disadvantage is that it takes O(m) time to check if two vertices are adjacent, or to find the degree of a vertex, by scanning the entire edge list.
