### Programming problems based on the properties of CFLs

- A context-free language (CFL) is a language that can be generated by a context-free grammar (CFG) or accepted by a pushdown automaton (PDA).
- CFLs have some closure properties, which means that if L1 and L2 are CFLs, then the following languages are also CFLs:
  - Union: L1 ∪ L2
  - Concatenation: L1L2
  - Kleene star: L1*
  - Reversal: L1R
  - Homomorphism: h(L1), where h is a function that maps each symbol of the alphabet to a string
  - Inverse homomorphism: h-1(L1), where h-1 is the inverse function of h
- CFLs are not closed under the following operations:
  - Intersection: L1 ∩ L2
  - Complement: L1C
  - Difference: L1 - L2
  - Substitution: L1[L2/x], where x is a symbol of the alphabet and L2 is a language
- There are some decision problems that are decidable for CFLs, which means that there is an algorithm that can answer yes or no for any given input. Some examples are:
  - Membership: Given a string w and a CFL L, is w ∈ L?
  - Emptiness: Given a CFL L, is L = ∅?
  - Finiteness: Given a CFL L, is L finite?
  - Equivalence: Given two CFLs L1 and L2, is L1 = L2?
- There are some decision problems that are undecidable for CFLs, which means that there is no algorithm that can answer yes or no for any given input. Some examples are:
  - Ambiguity: Given a CFG G, is G ambiguous?
  - Inclusion: Given two CFLs L1 and L2, is L1 ⊆ L2?
  - Universality: Given a CFL L, is L = Σ*, where Σ is the alphabet?
- A deterministic context-free language (DCFL) is a CFL that can be accepted by a deterministic pushdown automaton (DPDA), which is a PDA that has at most one transition for each input symbol and stack symbol.
- DCFLs are a proper subset of CFLs, which means that every DCFL is a CFL, but not every CFL is a DCFL.
- DCFLs have some additional closure properties, such as:
