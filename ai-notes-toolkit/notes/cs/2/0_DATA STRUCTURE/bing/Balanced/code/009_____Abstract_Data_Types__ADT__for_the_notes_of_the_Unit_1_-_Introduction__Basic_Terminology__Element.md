# Abstract Data Types (ADT)

- An abstract data type (ADT) is a mathematical model of a data structure that specifies the type of data stored, the operations supported and the behavior of those operations.
- An ADT does not specify how the data structure is implemented, only the interface that it provides to the user or the programmer.
- An ADT can be implemented using different data structures, such as arrays, linked lists, trees, etc.
- An ADT provides a level of abstraction that hides the details of the implementation and allows the user to focus on the functionality and efficiency of the data structure.
- An ADT can be defined using a specification language that describes the syntax and semantics of the data type and its operations.
- An ADT can also be defined using an axiomatic approach that specifies the properties and invariants of the data type and its operations.

## Examples of ADT

- Some common examples of ADT are:

  - Stack: A linear data structure that follows the last-in first-out (LIFO) principle. It supports two basic operations: push (insert an element at the top) and pop (remove and return the element at the top).
  - Queue: A linear data structure that follows the first-in first-out (FIFO) principle. It supports two basic operations: enqueue (insert an element at the rear) and dequeue (remove and return the element at the front).
  - List: A linear data structure that allows insertion and deletion of elements at any position. It supports operations such as: insert (add an element at a given position), delete (remove an element at a given position), search (find an element in the list), traverse (visit each element in the list), etc.
  - Set: A collection of distinct elements that does not allow duplicates. It supports operations such as: add (insert an element in the set), remove (delete an element from the set), contains (check if an element is in the set), union (combine two sets into one), intersection (find the common elements of two sets), difference (find the elements that are in one set but not in another), etc.
  - Map: A collection of key-value pairs that associates a unique key with a value. It supports operations such as: put (insert or update a key-value pair in the map), get (retrieve the value associated with a key in the map), remove (delete a key-value pair from the map), containsKey (check if a key is in the map), containsValue (check if a value is in the map), etc.
  - Graph: A data structure that represents a set of vertices (nodes) and a set of edges (links) between them. It supports operations such as: addVertex (add a node to the graph), addEdge (add a link between two nodes in the graph), removeVertex (delete a node from the graph), removeEdge (delete a link between two nodes in the graph), adjacent (check if two nodes are connected by an edge in the graph), degree (find the number of edges incident to a node in the graph), etc.

## Benefits of ADT

- Some benefits of using ADT are:

  - It allows the user to focus on the problem domain and the functionality of the data structure, rather than the implementation details and the low-level operations.
  - It provides a clear and consistent interface that defines the behavior and the expected results of the data structure and its operations.
  - It enables the reuse of the data structure and its operations in different contexts and applications, without modifying the implementation or the interface.
  - It facilitates the design and analysis of algorithms that use the data structure and its operations, by providing the complexity and the performance guarantees of the ADT.
  - It allows the implementation of the data structure to be changed or improved, without affecting the user or the algorithm that uses the ADT, as long as the interface and the behavior are preserved.
