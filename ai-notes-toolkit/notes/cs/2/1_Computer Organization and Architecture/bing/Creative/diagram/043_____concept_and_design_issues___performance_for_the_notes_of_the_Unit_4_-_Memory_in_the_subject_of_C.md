### Concept and Design Issues & Performance

- Memory is a crucial component of a computer system that stores data and instructions for processing.
- Memory hierarchy is a way of organizing memory levels with different capacities, speeds, and costs to optimize the performance and cost of the system.
- The memory hierarchy consists of the following levels:
  - Registers: the fastest and most expensive memory level, located inside the CPU and used to store operands and results of arithmetic and logic operations.
  - Cache memory: a small and fast memory level, located close to the CPU and used to store frequently accessed data and instructions from the main memory.
  - Main memory: the primary memory level, also known as RAM (Random Access Memory), that stores the data and instructions currently needed by the CPU.
  - Secondary memory: the largest and slowest memory level, also known as auxiliary memory or external memory, that stores the data and instructions that are not currently needed by the CPU, such as files and programs on disks, tapes, or optical media.
- The performance of the memory hierarchy depends on several factors, such as:
  - Access time: the time it takes to read or write a data item from or to a memory level.
  - Bandwidth: the amount of data that can be transferred per unit time between a memory level and the CPU.
  - Hit ratio: the fraction of memory accesses that are found in a memory level.
  - Miss ratio: the fraction of memory accesses that are not found in a memory level and require accessing a lower level of the hierarchy.
  - Miss penalty: the additional time required to access a lower level of the hierarchy when a miss occurs.
- The design issues of the memory hierarchy include:
  - How to allocate the limited space of a memory level among the data and instructions that need to be stored.
  - How to map the addresses of the data and instructions from a higher level to a lower level of the hierarchy.
  - How to replace the data and instructions that are no longer needed in a memory level with new ones from a lower level of the hierarchy.
  - How to ensure the consistency and correctness of the data and instructions across different levels of the hierarchy.
- The design issues of the cache memory include:
  - Cache size: the total amount of data and instructions that can be stored in the cache.
  - Cache line size: the unit of data and instructions that are transferred between the cache and the main memory.
  - Cache organization: the way of dividing the cache into sets and ways, where a set is a group of cache lines that can store data and instructions with the same index, and a way is a cache line within a set.
  - Cache mapping: the method of assigning the addresses of the data and instructions from the main memory to the cache lines, such as direct mapping, associative mapping, or set-associative mapping.
  - Cache replacement: the policy of choosing which cache line to evict when a new data or instruction needs to be stored in the cache, such as FIFO (First In First Out), LRU (Least Recently Used), or LFU (Least Frequently Used).
  - Cache write policy: the strategy of updating the data in the cache and the main memory when a write operation occurs, such as write-through, write-back, or write-allocate.
- The design issues of the virtual memory include:
  - Virtual address space: the range of addresses that can be generated by the CPU and used by the programs.
  - Physical address space: the range of addresses that can be accessed by the main memory and the secondary memory.
  - Page size: the unit of data and instructions that are transferred between the main memory and the secondary memory.
  - Page table: the data structure that stores the mapping between the virtual addresses and the physical addresses of the pages.
  - Page fault: the event that occurs when a page is not found in the main memory and needs to be brought from the secondary memory.
