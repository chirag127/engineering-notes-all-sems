### Real Time System for the notes of the Unit 1 - Introduction : Operating system and functions in the subject of Operating system

- A real time system is a system that has to respond to events or data within a specific time limit, otherwise it may fail or cause undesirable consequences .
- A real time operating system (RTOS) is an operating system that supports the development and execution of real time applications by providing features such as predictability, determinism, multitasking, inter-task communication, synchronization, and memory management    .
- There are different types of real time systems and RTOS, depending on the criticality and flexibility of the time constraints :
  - Hard real time system: A system that has to meet all the deadlines, otherwise it may cause catastrophic failure or loss of life. For example, a nuclear reactor control system, a pacemaker, or an air traffic control system.
  - Soft real time system: A system that can tolerate some missed deadlines, but the quality of service may degrade. For example, a video streaming system, a voice over IP system, or a multimedia system.
  - Firm real time system: A system that has to meet most of the deadlines, otherwise it may cause some loss of revenue or reputation. For example, a stock trading system, a web server, or a robotics system.
- The functions of an RTOS are similar to those of a general-purpose operating system, but with some additional or modified features to support real time applications    :
  - Scheduler: The RTOS scheduler is responsible for allocating CPU time to the tasks or threads according to their priorities, deadlines, and resource requirements. The scheduler may use different algorithms, such as preemptive, cooperative, or hybrid, to achieve the desired performance and responsiveness.
  - Kernel: The RTOS kernel is the core component of the operating system that provides the basic services, such as interrupt handling, context switching, memory management, inter-task communication, and synchronization. The kernel may be monolithic, modular, or microkernel, depending on the design and complexity of the system.
  - Device drivers: The RTOS device drivers are the software modules that interface with the hardware devices, such as sensors, actuators, timers, or communication ports. The device drivers may use different techniques, such as polling, interrupt, or DMA, to transfer data between the devices and the tasks or threads.
  - Middleware: The RTOS middleware is the software layer that provides higher-level services and functionalities, such as networking, file system, graphical user interface, or security. The middleware may use different protocols, such as TCP/IP, HTTP, or MQTT, to enable communication and data exchange between the tasks or threads and the external systems or devices.
  - Application programming interface (API): The RTOS API is the set of functions, data structures, and constants that the application developers can use to create and control the tasks or threads, access the kernel and device drivers, and use the middleware services. The API may be standardized, such as POSIX, or proprietary, depending on the RTOS vendor and compatibility.
