### Process generation for the notes of the Unit 2 - Concurrent Processes in the subject of Operating system

- Process generation is the process of creating a new process in an operating system by allocating memory, assigning a unique identifier, and initializing the process control block.
- A process can be generated by one of the following methods:
  - Booting: The first process is created when the system boots up and loads the kernel into memory. This process is called the init process and has a PID of 1. It is responsible for starting other system processes and services.
  - System call: A process can create a new process by invoking a system call, such as fork() in Unix/Linux or CreateProcess() in Windows. The system call copies the parent process's address space, file descriptors, and other attributes to the child process. The child process can then execute a different program by using another system call, such as exec() in Unix/Linux or CreateProcess() in Windows .
  - User request: A user can request a new process by running a program from a command line or a graphical user interface. The operating system creates a new process for the program and assigns it a PID and a priority. The process then executes the program instructions and terminates when it finishes or encounters an error.
- Process deletion is the process of terminating a process and releasing its resources, such as memory, CPU, and files. A process can be deleted by one of the following methods:
  - Normal exit: A process can terminate itself by executing a system call, such as exit() in Unix/Linux or ExitProcess() in Windows. The system call informs the operating system that the process has completed its execution and returns a status code. The operating system then removes the process from the ready queue, deallocates its memory, and closes its files .
  - Error exit: A process can terminate abnormally due to an error, such as a segmentation fault, a divide by zero, or an illegal instruction. The operating system detects the error and sends a signal to the process, such as SIGSEGV, SIGFPE, or SIGILL in Unix/Linux or EXCEPTION_ACCESS_VIOLATION, EXCEPTION_INT_DIVIDE_BY_ZERO, or EXCEPTION_ILLEGAL_INSTRUCTION in Windows. The process can either handle the signal and continue its execution or terminate with an error code. The operating system then performs the same steps as in normal exit .
  - External termination: A process can be terminated by another process or by the user. A process can send a signal to another process, such as SIGTERM, SIGINT, or SIGKILL in Unix/Linux or TerminateProcess() in Windows, to request its termination. The operating system then performs the same steps as in normal exit. A user can also terminate a process by using a command, such as kill in Unix/Linux or taskkill in Windows, or by using a graphical user interface, such as Task Manager in Windows .
