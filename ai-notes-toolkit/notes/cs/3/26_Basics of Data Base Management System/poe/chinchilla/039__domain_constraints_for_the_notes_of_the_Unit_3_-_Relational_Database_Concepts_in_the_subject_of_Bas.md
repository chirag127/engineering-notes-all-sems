### Domain Constraints for the Notes of Unit 3 - Relational Database Concepts

Domain constraints are a set of rules that define the valid values for a particular attribute in a database table. These constraints ensure data integrity and accuracy by preventing the insertion of invalid or incorrect data into the database. In this unit of Relational Database Concepts, we will learn about the different types of domain constraints and their importance in maintaining data quality. 

Here are the different types of domain constraints that we will cover in this unit:

1. NOT NULL Constraint: This constraint ensures that a particular attribute in a table cannot contain NULL values. It is used to enforce mandatory data entry for a particular column in a table.

2. DEFAULT Constraint: This constraint specifies a default value for an attribute if no value is specified during data entry. It is used to provide a default value for a particular column in a table.

3. CHECK Constraint: This constraint specifies a condition that must be satisfied for the values in a particular attribute in a table. It is used to ensure that only valid data is entered into the table.

4. UNIQUE Constraint: This constraint ensures that the values in a particular attribute in a table are unique. It is used to enforce uniqueness for a particular column in a table.

5. PRIMARY KEY Constraint: This constraint specifies a unique identifier for each row in a table. It is used to ensure that each row in a table is uniquely identified by a primary key.

6. FOREIGN KEY Constraint: This constraint establishes a relationship between two tables based on a common attribute. It is used to maintain referential integrity between two tables.

In summary, domain constraints are an essential aspect of database design as they ensure data integrity and accuracy. Understanding the different types of domain constraints and their usage is crucial for designing efficient and effective relational databases.
