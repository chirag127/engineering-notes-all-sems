### Normal Forms for the Notes of the Unit 4 - Data Base Design & Normalization in the Subject of Basics of Data Base Management System

Normal forms are a set of rules or guidelines for designing relational databases in order to reduce data redundancy and improve data integrity. Normal forms are based on the concept of functional dependency, which means that the value of one attribute depends on the value of another attribute. Normal forms help to ensure that the database is well-structured and easy to maintain and query.

There are several normal forms, each with a different level of normalization. The most common normal forms are:

- **First Normal Form (1NF)**: A relation is in 1NF if it does not contain any composite or multi-valued attributes. This means that each attribute has a single atomic value and each row is unique. For example, a relation with a column for phone numbers that can store multiple values separated by commas is not in 1NF. To convert a relation to 1NF, we need to split the column into multiple columns, each with a single value, or create a separate relation for phone numbers and link it with a foreign key.
- **Second Normal Form (2NF)**: A relation is in 2NF if it is in 1NF and every non-key attribute is fully functionally dependent on the primary key. This means that there is no partial dependency, where a non-key attribute depends on only a part of the primary key. For example, a relation with a composite primary key of student ID and course ID and a column for student name is not in 2NF, because student name depends only on student ID and not on the whole key. To convert a relation to 2NF, we need to remove the partial dependencies and create separate relations for them.
- **Third Normal Form (3NF)**: A relation is in 3NF if it is in 2NF and every non-key attribute is non-transitively dependent on the primary key. This means that there is no transitive dependency, where a non-key attribute depends on another non-key attribute that depends on the primary key. For example, a relation with a primary key of employee ID and columns for employee name, department name, and department manager is not in 3NF, because department manager depends on department name, which depends on employee ID. To convert a relation to 3NF, we need to remove the transitive dependencies and create separate relations for them.
- **Boyce-Codd Normal Form (BCNF)**: A relation is in BCNF if it is in 3NF and every determinant is a candidate key. A determinant is an attribute or a set of attributes that determines the value of another attribute. A candidate key is a minimal set of attributes that can uniquely identify a row. For example, a relation with a primary key of employee ID and columns for employee name, department name, and department code is not in BCNF, because department code determines department name, but department code is not a candidate key. To convert a relation to BCNF, we need to decompose the relation into two relations, one with employee ID and department code, and another with department code and department name.

There are other normal forms, such as 4NF, 5NF, and 6NF, but they are less commonly used and more complex to understand and apply. The higher the normal form, the more normalized the database is, but also the more relations and joins are required. Therefore, there is a trade-off between normalization and performance, and the optimal level of normalization depends on the requirements and characteristics of the database.
