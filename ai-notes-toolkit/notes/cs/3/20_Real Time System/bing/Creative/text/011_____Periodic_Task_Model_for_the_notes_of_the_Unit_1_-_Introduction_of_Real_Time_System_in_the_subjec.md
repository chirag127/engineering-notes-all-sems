### Periodic Task Model

- The periodic task model is a well-known deterministic workload model that characterizes accurately many traditional hard real-time applications, such as digital control, real-time monitoring, and constant bit-rate voice/video transmission .
- A periodic task is one that repeats itself after a fixed time interval, called the period. A periodic task is denoted by four tuples: Ti = < Φi, Pi, ei, Di > Where, Φi – is the phase of the task, Pi – is the period of the task, ei – is the worst-case execution time of the task, and Di – is the relative deadline of the task.
- The periodic task model assumes that each task has a known and fixed period, execution time, and deadline, and that each task releases its first job at the same time or with a known offset. The periodic task model also assumes that each task is independent of other tasks and that the system is preemptive.
- The periodic task model can be extended by adding a jitter Ji for each task τi, to allow the flexibility that the actual release time of a job may be at most Ji time units earlier or later than the exact start time of the period. The jitter can be used to model uncertainties in the arrival times of periodic tasks, such as network delays or sensor sampling errors.
- The periodic task model can be further extended by adding a minimum inter-arrival time Mi for each task τi, to ensure that the jobs of a task are not released too frequently. The minimum inter-arrival time can be used to model the minimum separation between consecutive events that trigger a periodic task, such as sensor readings or user inputs.
- The periodic task model can also be generalized by allowing different deadlines for different jobs of the same task, or by allowing different execution times for different jobs of the same task, depending on the input data or the system state. These extensions can be used to model the variability in the workload or the timing requirements of periodic tasks, such as adaptive control or adaptive compression.
