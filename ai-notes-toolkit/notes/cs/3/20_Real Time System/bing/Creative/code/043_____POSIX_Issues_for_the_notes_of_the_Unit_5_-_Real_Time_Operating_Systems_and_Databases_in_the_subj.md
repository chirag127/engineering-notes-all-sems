### POSIX Issues

- POSIX stands for Portable Operating System Interface, and it is a family of standards that define a common interface for operating systems, especially UNIX-like systems.
- POSIX aims to achieve application portability across different operating systems, by providing a consistent set of services and interfaces for the application to use.
- However, POSIX does not address the specific needs of real-time applications, which require predictable and timely responses from the operating system and the hardware.
- Real-time applications are those that have strict deadlines and constraints on their performance, such as control systems, multimedia systems, and embedded systems.
- Therefore, a real-time working group was established in POSIX to develop standards for real-time extensions to POSIX, such as POSIX.4 (real-time signals and timers), POSIX.13 (real-time streams), and POSIX.1b (real-time scheduling and synchronization).
- Some of the issues that POSIX real-time standards address are:

  - Scheduling: POSIX.1b defines two real-time scheduling policies, namely FIFO (first-in first-out) and RR (round-robin), which are based on fixed priorities and preemptive scheduling. These policies allow real-time tasks to have higher priority than non-real-time tasks, and to run until they block, terminate, or are preempted by a higher-priority task. POSIX.1b also defines a set of functions to manipulate the scheduling parameters and attributes of tasks, such as `sched_setparam`, `sched_getparam`, `sched_setscheduler`, and `sched_getscheduler`.
  - Synchronization: POSIX.1b defines a set of synchronization primitives that support priority inheritance and priority ceiling protocols, which are used to prevent priority inversion problems in real-time systems. Priority inversion occurs when a high-priority task is blocked by a low-priority task that holds a shared resource, and the low-priority task is preempted by a medium-priority task. Priority inheritance allows the low-priority task to inherit the priority of the high-priority task that is waiting for the resource, and priority ceiling sets the priority of the task that acquires the resource to the highest priority of any task that may use the resource. The synchronization primitives defined by POSIX.1b include mutexes, condition variables, semaphores, and message queues.
  - Timers: POSIX.4 defines a set of functions to create and manipulate timers, which are used to measure time intervals and generate periodic or one-shot events. Timers can be associated with signals or threads, and can have different resolutions and accuracies. The functions defined by POSIX.4 include `timer_create`, `timer_settime`, `timer_gettime`, and `timer_delete`.
  - Signals: POSIX.4 defines a set of real-time signals, which are used to notify events and deliver data to tasks. Real-time signals have several advantages over the standard POSIX.1 signals, such as being queued, prioritized, and carrying a value. The functions defined by POSIX.4 include `sigqueue`, `sigwaitinfo`, and `sigtimedwait`.
  - Streams: POSIX.13 defines a set of functions to create and manipulate streams, which are used to transfer data between tasks and devices. Streams are similar to pipes, but they support multiple sources and destinations, and they allow the insertion and removal of modules that can perform data processing, such as filtering, compression, encryption, etc. The functions defined by POSIX.13 include `stream_open`, `stream_close`, `stream_read`, `stream_write`, and `stream_ioctl`.

- POSIX real-time standards provide a common and portable interface for real-time applications, but they also have some limitations and challenges, such as:

  - Implementation: Not all operating systems support POSIX real-time standards, and even those that do may have different levels of compliance and quality. Some operating systems may not implement all the features or functions defined by the standards, or they may have different interpretations or extensions of the standards. Therefore, real-time applications may still face portability issues across different operating systems, and they may need to use platform-specific functions or libraries to achieve the desired functionality or performance.
  - Overhead: POSIX real-time standards introduce additional complexity and overhead to the operating system and the application, which may affect the performance and predictability of real-time systems.
