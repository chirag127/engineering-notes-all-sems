### Temporal Consistency

- Temporal consistency is a property of real-time systems that ensures that the data stored in the database reflects the current state of the physical environment.
- Temporal consistency is different from logical consistency, which is a property of non-real-time systems that ensures that the data stored in the database satisfies the integrity constraints and the consistency rules.
- Temporal consistency is important for real-time systems because they need to make decisions and take actions based on the most up-to-date information about the physical environment.
- Temporal consistency can be violated by two factors: data staleness and data inconsistency.
  - Data staleness occurs when the data stored in the database is outdated and does not reflect the current state of the physical environment. This can happen due to the delay in sensing, processing, or updating the data.
  - Data inconsistency occurs when the data stored in the database is contradictory and does not agree with each other or with the physical environment. This can happen due to the concurrency of transactions, the replication of data, or the failure of components.
- Temporal consistency can be maintained by using various techniques, such as:
  - Triggered updates, which are updates that are initiated by the occurrence of some events or conditions in the physical environment or the database. For example, a triggered update can be used to update the temperature data when it changes by more than a certain threshold.
  - Absolute validity, which is a temporal consistency constraint that requires the data stored in the database to be within a certain range of the actual data in the physical environment. For example, an absolute validity constraint can be used to ensure that the temperature data is within 5 degrees of the actual temperature.
  - Relative validity, which is a temporal consistency constraint that requires the data stored in the database to be within a certain range of the data read by a transaction. For example, a relative validity constraint can be used to ensure that the temperature data read by a transaction is within 5 degrees of the temperature data stored in the database.
  - Data freshness, which is a temporal consistency constraint that requires the data stored in the database to be updated within a certain time interval. For example, a data freshness constraint can be used to ensure that the temperature data is updated every 10 seconds.
  - Data currency, which is a temporal consistency constraint that requires the data stored in the database to be updated before a certain time point. For example, a data currency constraint can be used to ensure that the temperature data is updated before the deadline of a transaction that needs it.
  - Data recency, which is a temporal consistency constraint that requires the data stored in the database to be updated after a certain time point. For example, a data recency constraint can be used to ensure that the temperature data is updated after the occurrence of a certain event in the physical environment.
- Temporal consistency can be measured by using various metrics, such as:
  - Temporal deviation, which is the difference between the data stored in the database and the actual data in the physical environment. For example, the temporal deviation of the temperature data can be calculated as the absolute value of the difference between the temperature stored in the database and the temperature sensed by the sensor.
  - Temporal error, which is the difference between the data read by a transaction and the actual data in the physical environment. For example, the temporal error of the temperature data can be calculated as the absolute value of the difference between the temperature read by a transaction and the temperature sensed by the sensor.
  - Temporal inconsistency, which is the difference between the data read by a transaction and the data stored in the database. For example, the temporal inconsistency of the temperature data can be calculated as the absolute value of the difference between the temperature read by a transaction and the temperature stored in the database.
