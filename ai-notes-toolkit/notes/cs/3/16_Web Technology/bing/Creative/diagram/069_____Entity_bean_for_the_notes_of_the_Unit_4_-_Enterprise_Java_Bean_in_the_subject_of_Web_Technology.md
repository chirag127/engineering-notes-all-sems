### Entity bean

- An entity bean is a type of Enterprise JavaBean (EJB), a server-side component that runs on an application server and provides business logic and data access to clients.
- An entity bean represents persistent data stored in a relational database or another data source. It can have a one-to-one, one-to-many, or many-to-many relationship with other entity beans or other Java objects.
- An entity bean has a primary key, a unique identifier that distinguishes it from other entity beans of the same type.
- An entity bean can be either container-managed or bean-managed, depending on how it handles its persistence operations.
  - A container-managed entity bean (CMEB) delegates the responsibility of persisting its state to the EJB container, which uses a persistence provider to interact with the data source. The persistence provider can be a Java Persistence API (JPA) implementation or a vendor-specific solution. The CMEB defines its mapping to the data source using annotations or an XML deployment descriptor.
  - A bean-managed entity bean (BMEB) implements its own persistence logic using JDBC, JPA, or other APIs. The BMEB is responsible for opening and closing database connections, executing SQL statements, and managing transactions. The BMEB has more control and flexibility over its persistence operations, but also more complexity and responsibility.
- An entity bean can be either session-aware or session-unaware, depending on how it interacts with the client session.
  - A session-aware entity bean (SAEB) maintains a conversational state with the client, and can be cached by the EJB container for better performance. The SAEB can use the extended persistence context, which allows it to access and modify the persistent data without explicitly synchronizing with the data source. The SAEB is also known as an extended persistence context entity bean (EPCB).
  - A session-unaware entity bean (SUEB) does not maintain a conversational state with the client, and is always synchronized with the data source. The SUEB can use the transaction-scoped persistence context, which is bound to the current transaction and is closed when the transaction ends. The SUEB is also known as a transaction-scoped persistence context entity bean (TPCB).
- An entity bean can be accessed by local or remote clients, depending on the interface it implements.
  - A local entity bean (LEB) implements the javax.ejb.Local interface, and can be accessed by clients within the same application or module. The LEB has better performance and lower overhead than a remote entity bean, but cannot be accessed by clients outside the application or module.
  - A remote entity bean (REB) implements the javax.ejb.Remote interface, and can be accessed by clients across different applications, modules, or machines. The REB has lower performance and higher overhead than a local entity bean, but can be accessed by clients anywhere. The REB uses the Java Remote Method Invocation (RMI) protocol to communicate with the clients.
