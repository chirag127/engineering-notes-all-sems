# Session Tracking

- Session tracking is a mechanism to maintain the state of a user across multiple requests or visits to a web application.
- A session is a logical grouping of related interactions between a user and a web server, such as browsing a catalog, adding items to a shopping cart, and checking out.
- Session tracking enables the web server to identify the user and provide personalized and consistent services.
- Session tracking is also useful for collecting statistics about user behavior, preferences, and interests, which can be used for marketing or analysis purposes.

## Need for Session Tracking

- HTTP is a stateless protocol, which means that each request and response are independent and do not carry any information about the previous or subsequent ones.
- This makes it difficult for the web server to recognize the user and maintain the context of the interaction.
- For example, if a user logs in to a web application and then requests another page, the web server does not know that the user is already authenticated and may ask for the login credentials again.
- Similarly, if a user adds some items to a shopping cart and then navigates to another page, the web server does not know which items belong to the user and may display an empty cart.
- To overcome this limitation, session tracking techniques are used to associate a unique identifier with each user and store some information about the user's state on the server or the client side.

## Session Tracking Techniques

- There are several techniques to implement session tracking in web applications, such as cookies, URL rewriting, hidden form fields, and HttpSession objects.
- Each technique has its own advantages and disadvantages, and the choice depends on the requirements and constraints of the web application.

### Cookies

- Cookies are small pieces of data that are sent by the web server to the web browser and stored on the client side.
- Cookies can store information such as user name, preferences, shopping cart items, etc.
- Cookies can be sent back to the web server with each subsequent request, so that the web server can identify the user and retrieve the stored information.
- Cookies are easy to implement and widely supported by web browsers and servers.
- However, cookies have some limitations and drawbacks, such as:

  - Cookies have a limited size (usually 4 KB) and can store only textual data.
  - Cookies can be disabled or deleted by the user, which may affect the functionality of the web application.
  - Cookies can be intercepted or modified by malicious parties, which may compromise the security and privacy of the user.
  - Cookies can cause network overhead and performance issues, as they are sent with every request and response.

### URL Rewriting

- URL rewriting is a technique to append the session identifier to the URL of each request and response.
- The session identifier is usually a random string that is generated by the web server and assigned to the user.
- The web server can use the session identifier to identify the user and access the stored information.
- URL rewriting does not require any client-side support and works even if cookies are disabled or deleted by the user.
- However, URL rewriting has some limitations and drawbacks, such as:

  - URL rewriting can make the URL longer and less user-friendly.
  - URL rewriting can expose the session identifier to the user and other parties, which may compromise the security and privacy of the user.
  - URL rewriting can cause problems with bookmarking, caching, and linking, as the session identifier may change or expire over time.

### Hidden Form Fields

- Hidden form fields are input elements in an HTML form that are not visible to the user, but can store some information that can be submitted to the web server along with the form data.
- Hidden form fields can store information such as session identifier, user name, preferences, etc.
- The web server can use the hidden form fields to identify the user and retrieve the stored information.
- Hidden form fields do not require any client-side support and work even if cookies are disabled or deleted by the user.
- However, hidden form fields have some limitations and drawbacks, such as:

  - Hidden form fields can only be used with forms that use the POST method, and not with links or images that use the GET method.
  - Hidden form fields can be viewed or modified by the user or other parties, which may compromise the security and privacy of the user.
  - Hidden form fields can cause network overhead and performance issues, as they are sent with every form submission.

### HttpSession Objects

- HttpSession objects are Java objects that are created by the web server and associated with each user session.
