# Joining for the notes of the Unit 4 - Enterprise Java Bean in the subject of Web Technology

- Enterprise Java Beans (EJB) are server-side components that encapsulate the business logic of an application. They run inside a container that provides services such as security, transaction management, concurrency control, and dependency injection.
- EJBs can be divided into two types: session beans and message-driven beans. Session beans are stateful or stateless components that handle requests from clients. Message-driven beans are components that receive and process messages asynchronously from a message queue or topic.
- EJBs follow a component-based architecture that allows for reusability, scalability, and portability. EJBs can be deployed on any Java EE compliant application server, such as GlassFish, JBoss, or WebLogic.
- EJBs can interact with other components using various protocols, such as Remote Method Invocation (RMI), Java Naming and Directory Interface (JNDI), Java Message Service (JMS), Java Database Connectivity (JDBC), and Java Persistence API (JPA).
- EJBs can be developed using annotations or XML descriptors. Annotations are preferred as they reduce the amount of configuration and boilerplate code. XML descriptors can be used to override or customize the annotations.
- EJBs can be accessed by clients using different methods, such as local, remote, or web service interfaces. Local interfaces are used when the client and the EJB are in the same application. Remote interfaces are used when the client and the EJB are in different applications or servers. Web service interfaces are used when the client and the EJB communicate using SOAP or REST protocols.
- EJBs can use dependency injection to obtain references to other components or resources. Dependency injection simplifies the code and reduces the coupling between components. Dependency injection can be done using annotations or XML descriptors.
- EJBs can use interceptors to add cross-cutting concerns, such as logging, auditing, or security, to the business methods. Interceptors are classes or methods that are invoked before or after the execution of a business method. Interceptors can be defined using annotations or XML descriptors.
- EJBs can use timers to schedule tasks that need to be executed periodically or at a specific time. Timers are objects that are created and managed by the container. Timers can be defined using annotations or programmatically.
