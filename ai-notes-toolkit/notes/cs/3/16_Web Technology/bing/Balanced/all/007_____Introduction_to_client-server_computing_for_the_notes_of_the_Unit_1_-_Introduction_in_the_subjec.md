# Introduction to client-server computing

- Client-server computing is a distributed computing model that involves a client application that requests services from a server application, and a server application that provides those services to the client application.
- A client is a software program or a device that initiates a communication with a server over a network. A client can be a web browser, an email client, a chat client, a mobile app, etc.
- A server is a software program or a device that listens for and responds to requests from clients over a network. A server can be a web server, an email server, a chat server, a database server, etc.
- A network is a system of interconnected devices that can communicate with each other using standard protocols. A network can be a local area network (LAN), a wide area network (WAN), the Internet, etc.
- The client-server model is based on the principle of separation of concerns, which means that different tasks or functions are assigned to different components or modules. This allows for modularity, scalability, reliability, and security of the system.
- The client-server model can be classified into two types: thin client and thick client.
  - A thin client is a client that performs minimal processing and relies on the server for most of the functionality. A thin client is usually lightweight, easy to maintain, and consumes less resources. An example of a thin client is a web browser that displays web pages rendered by the web server.
  - A thick client is a client that performs substantial processing and relies on the server for less functionality. A thick client is usually more complex, harder to maintain, and consumes more resources. An example of a thick client is a desktop application that runs locally on the user's machine and interacts with the server for data storage or synchronization.
- The client-server model can also be classified into different architectures based on the number of tiers or layers involved. A tier or a layer is a logical division of functionality or responsibility in a system. The most common architectures are:
  - One-tier architecture: In this architecture, there is only one layer that combines the client and the server functionality in the same program or device. This architecture is simple, but has limited scalability, reliability, and security. An example of a one-tier architecture is a standalone application that runs on a single machine and does not communicate with any other device.
  - Two-tier architecture: In this architecture, there are two layers: the client layer and the server layer. The client layer handles the user interface and the presentation logic, while the server layer handles the business logic and the data access logic. This architecture is easy to implement, but has moderate scalability, reliability, and security. An example of a two-tier architecture is a web application that uses a web browser as the client and a web server as the server.
  - Three-tier architecture: In this architecture, there are three layers: the client layer, the application layer, and the data layer. The client layer handles the user interface and the presentation logic, the application layer handles the business logic and the application logic, and the data layer handles the data access logic and the data storage. This architecture is more complex, but has high scalability, reliability, and security. An example of a three-tier architecture is a web application that uses a web browser as the client, an application server as the application layer, and a database server as the data layer.
  - N-tier architecture: In this architecture, there are more than three layers, each of which can be further divided into sub-layers or components. The client layer and the data layer are the same as in the three-tier architecture, but the application layer can be split into multiple layers or components that perform different functions or services. This architecture is the most flexible, but also the most difficult to design, implement, and maintain. An example of an n-tier architecture is a web application that uses a web browser as the client, a web server, a load balancer, a cache server, a message queue, a microservice, a REST API, and a database server as the application layer, and a data warehouse, a data lake, a data mart, and a data cube as the data layer.
