### Transaction Processing for the notes of the Unit 4 - Enterprise Java Bean in the subject of Web Technology

- Transaction processing is the execution of a series of operations on a set of data, such as a database, in a reliable, consistent, and atomic way. A transaction is a logical unit of work that either succeeds or fails as a whole.
- Enterprise JavaBeans (EJB) is a technology that supports distributed transactional component-based applications written in Java. EJB provides a standard way to implement business logic on the server side, using reusable and portable components called enterprise beans.
- There are two types of transactions in EJB: container-managed transactions and bean-managed transactions.
  - Container-managed transactions are transactions that are automatically controlled by the EJB container, which sets the boundaries of the transactions based on the configuration of the enterprise beans. The developer does not need to write any code to start, commit, or rollback the transactions. Container-managed transactions simplify development and ensure consistency across different enterprise beans.
  - Bean-managed transactions are transactions that are explicitly controlled by the enterprise bean code, using the Java Transaction API (JTA). The developer is responsible for writing code to begin, commit, or rollback the transactions, as well as handling any exceptions or errors. Bean-managed transactions provide more flexibility and control over the transaction behavior, but also require more coding and testing.
- EJB supports flat transactions, which are transactions that are decoupled from and independent of other transactions in the system. Flat transactions do not allow nesting of transactions, which means that a new transaction cannot be started until the current transaction is completed.
- EJB transactions can span across multiple resources, such as databases, message queues, or web services, that support the XA protocol. XA is a standard for distributed transaction processing, which enables the coordination and synchronization of multiple resources in a transaction. XA uses a two-phase commit protocol, which ensures that all the resources either commit or rollback the transaction as a whole.
