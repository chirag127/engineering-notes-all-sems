## Identifying Domain Classes from the Problem Statements

- A domain class is a representation of a concept or an entity that is relevant to the problem domain and the system's requirements.
- A domain class has attributes (properties or characteristics) and operations (behaviors or actions) that describe its state and behavior.
- A domain class diagram is a graphical notation that shows the domain classes and their relationships in the problem domain.
- To identify domain classes from the problem statements, we can use the following steps:

  - Identify the nouns and noun phrases in the problem statements. These are potential candidates for domain classes.
  - Eliminate the irrelevant, vague, or abstract nouns that are not important for the system's functionality or the problem domain. These include user interface elements, implementation details, or general terms.
  - Group the remaining nouns into categories based on their common attributes and operations. These are the domain classes.
  - Assign meaningful and unique names to the domain classes. Use singular nouns or noun phrases that describe the concept or entity.
  - Identify the attributes and operations of each domain class. Use descriptive and concise names for the attributes and operations. Use verbs or verb phrases for the operations.
  - Identify the relationships and associations among the domain classes. Use lines to connect the domain classes and label the relationships with multiplicity and role names. Use different types of lines to indicate different types of relationships, such as inheritance, aggregation, or composition.
  - Draw the domain class diagram using a standard notation, such as UML. Follow the conventions and guidelines for creating a clear and consistent diagram.
