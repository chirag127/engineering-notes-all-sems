## Modeling Data Flow Diagrams

- A data flow diagram (DFD) is a graphical representation of the flow of data and information in a system or process.
- A DFD shows the sources and destinations of data, the processes that transform data, and the data stores that hold data.
- A DFD can be used to model the logical or physical aspects of a system, or both.
- A DFD can be used to document the existing system, analyze the system requirements, design the new system, or communicate the system design to stakeholders.

### Components of a DFD

- A DFD consists of four basic components: external entities, processes, data flows, and data stores.
- An external entity is a person, organization, or system that interacts with the system, providing or receiving data. It is represented by a rectangle with a name.
- A process is a function or activity that transforms data from one form to another. It is represented by a circle or a rounded rectangle with a name and a number.
- A data flow is a movement of data from one component to another. It is represented by an arrow with a name and an optional data description.
- A data store is a collection of data that is stored for later use. It is represented by an open-ended rectangle with a name and an optional data description.

### Levels of a DFD

- A DFD can be decomposed into different levels of detail, from a high-level overview to a low-level specification.
- A level 0 DFD, also called a context diagram, shows the system as a single process and its interactions with external entities. It provides a summary of the system scope and boundaries.
- A level 1 DFD shows the main processes of the system and their data flows. It provides a breakdown of the system functionality and data exchanges.
- A level 2 DFD shows the sub-processes of each process in the level 1 DFD and their data flows. It provides a further decomposition of the system logic and data processing.
- A level 3 DFD shows the detailed steps of each sub-process in the level 2 DFD and their data flows. It provides a complete specification of the system design and implementation.

### Rules and Guidelines for a DFD

- A DFD should be clear, consistent, and complete, following some basic rules and guidelines.
- A DFD should have a unique name and number for each process, data flow, and data store.
- A DFD should have a balanced decomposition, meaning that the inputs and outputs of a process at one level should match the inputs and outputs of the corresponding process at the next lower level.
- A DFD should have a logical sequence, meaning that the data flows should follow the order of data processing and transformation.
- A DFD should have a minimal crossing of data flows, meaning that the data flows should avoid crossing each other as much as possible.
- A DFD should have a meaningful naming and labeling, meaning that the names and labels of the components should reflect the data content and purpose.
