## Modeling UML Class Diagrams and Sequence diagrams for the notes of the Software Engineering Mapping with Virtual Lab Lab in the subject of Software Engineering

1. UML Class Diagrams:
- Class diagrams are static structure diagrams that show the classes in a system and their relationships.
- They are used to model the static view of a system.
- Classes are represented by rectangles with three sections: Name, Attributes, and Operations.
- Relationships between classes include:
-- Association: A relationship between two classes that represents that instances of the two classes are associated.
-- Inheritance: A relationship between two classes where one class (child) inherits the structure and behavior of another class (parent).
-- Dependency: A relationship where one class (client) depends on another class (supplier).
-- Aggregation: A relationship where one class is a collection of other classes.
-- Composition: A strong form of aggregation where the contained classes cannot exist independently.

2. UML Sequence Diagrams:
- Sequence diagrams are interaction diagrams that show the time-ordering of messages between objects for a scenario.
- They are used to model the dynamic view of a system.
- Objects are shown as lifelines running down the page with messages passed between the lifelines showing the interaction.
- Different types of messages include:
-- Synchronous: Solid arrow from sender to receiver. Execution waits for a reply.
-- Asynchronous: Open arrowhead from sender to receiver. Execution continues without waiting for a reply.
-- Found Message: Solid arrow sticking back on the same lifeline. Object sends a message to itself.
-- Return Message: Solid arrow from a lifeline back to itself.
