# Specification methods for the notes of the Unit 5 - Software tools in the subject of Human Computer Interface

- Specification methods are techniques to describe the requirements and design of a software system in a precise and unambiguous way.
- Specification methods can be classified into two categories: functional and behavioral.
- Functional specifications describe what the software does, such as the features, the external behavior, and the user interface. They are often written in natural language, bullet lists, or diagrams.
- Behavioral specifications describe how the software works, such as the internal structure, the algorithms, and the data structures. They are often written in formal languages, such as logic, mathematics, or programming languages.
- Specification methods can help to improve the quality, consistency, completeness, and correctness of the software system, as well as to facilitate communication, verification, and testing.

## Examples of specification methods

- Transition diagrams: a graphical notation to represent the states and transitions of a software system. They can be used to model the user interface, the control flow, or the data flow of the system.
- State charts: an extension of transition diagrams that can capture more complex behaviors, such as parallelism, hierarchy, and events. They can be used to model the dynamic aspects of the system, such as the user actions, the system responses, or the internal states.
- Interface-building tools: software tools that can help to create, modify, and test the user interface of the system. They can provide features such as drag-and-drop, widgets, templates, code generation, or simulation.
- Interface mockup tools: software tools that can help to create quick sketches of the user interface during the early design stage. They can facilitate the exploration of multiple alternatives, the communication with stakeholders, and the feedback collection.
