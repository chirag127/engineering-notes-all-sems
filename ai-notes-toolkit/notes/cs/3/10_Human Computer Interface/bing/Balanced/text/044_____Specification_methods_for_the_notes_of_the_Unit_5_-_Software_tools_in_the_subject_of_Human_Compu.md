### Specification methods for the notes of the Unit 5 - Software tools in the subject of Human Computer Interface

- Specification methods are techniques to describe the requirements and design of a software system in a precise and unambiguous way .
- Specification methods can be classified into two categories: functional and behavioral.
- Functional specifications describe what the software does, what its external behavior is, and what its user interface looks like. They are often written in natural language, bullet lists, or diagrams.
- Behavioral specifications describe how the software works, what its internal structure is, and how it responds to events and inputs. They are often written in formal languages, such as logic, algebra, or state machines.
- Specification methods can help to improve the quality, consistency, completeness, and correctness of software design and development. They can also facilitate communication and collaboration among different stakeholders, such as engineers, customers, and users.
- Some examples of specification methods are:
  - Transition diagrams: a set of nodes that represents system states and a set of links between the nodes that represents possible transitions.
  - State charts: a graphical notation to model the dynamic behavior of a system using states, events, actions, and transitions.
  - Use cases: a technique to capture the functional requirements of a system from the perspective of the user.
  - User stories: a technique to express the user needs and goals in a concise and informal way.
  - Scenarios: a technique to describe a specific situation or interaction that involves the system and the user.
  - Wireframes: a technique to sketch the layout and structure of the user interface.
  - Prototypes: a technique to create a working or simulated version of the user interface.
