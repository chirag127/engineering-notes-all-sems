### Integrity Constraints for the notes of the Unit 2 - Relational data Model and Language in the subject of Database Management System

Integrity constraints are rules that ensure the correctness and consistency of data in a database. They help to maintain the quality of data and prevent errors or inconsistencies from being introduced into the database. In this unit, we will learn about various types of integrity constraints that can be applied to a relational database.

Here are some of the common types of integrity constraints:

1. **Primary Key Constraint:** A primary key constraint is used to uniquely identify a record in a table. It ensures that the same record cannot be inserted twice into the table.

2. **Foreign Key Constraint:** A foreign key constraint is used to maintain referential integrity between two tables. It ensures that the value of a column in one table matches the value of a column in another table.

3. **Unique Constraint:** A unique constraint is used to ensure that the values in a column or a group of columns are unique. It prevents duplicate values from being inserted into the table.

4. **Check Constraint:** A check constraint is used to enforce a specific condition on the values in a column. It can be used to limit the range of values that can be inserted into a column.

5. **Default Constraint:** A default constraint is used to assign a default value to a column if no value is specified during insertion.

6. **Not Null Constraint:** A not null constraint is used to ensure that a column cannot have a null value. It ensures that all records in the table have a value for that column.

These constraints are essential for maintaining the integrity of the data in a database. By applying these constraints, we can ensure that the data is accurate, consistent, and free from errors or inconsistencies. It is important to understand these constraints and apply them correctly to ensure the quality of data in a database.
