### Keys Constraints for the notes of the Unit 2 - Relational data Model and Language in the subject of Database Management System

Here are some key constraints that you should know when working with relational data models and languages:

* **Primary Key Constraint**: A primary key constraint is a unique identifier for each record in a table. It ensures that each record in a table is unique and can be easily accessed. The primary key constraint is created using the `PRIMARY KEY` keyword.

* **Foreign Key Constraint**: A foreign key constraint is used to link two tables together. It ensures that data in one table corresponds to data in another table. The foreign key constraint is created using the `FOREIGN KEY` keyword.

* **Unique Constraint**: A unique constraint ensures that the data in a column is unique. It is similar to the primary key constraint, but it does not have to be the unique identifier for the table. The unique constraint is created using the `UNIQUE` keyword.

* **Check Constraint**: A check constraint is used to ensure that data in a column meets certain conditions. For example, you can use a check constraint to ensure that a value is greater than or equal to a certain number. The check constraint is created using the `CHECK` keyword.

* **Not Null Constraint**: A not null constraint ensures that a column cannot be null. It is created using the `NOT NULL` keyword.

* **Default Constraint**: A default constraint is used to set a default value for a column. If a value is not specified for the column, the default value is used. The default constraint is created using the `DEFAULT` keyword.

By understanding these key constraints, you can create more efficient and effective relational data models and languages.
