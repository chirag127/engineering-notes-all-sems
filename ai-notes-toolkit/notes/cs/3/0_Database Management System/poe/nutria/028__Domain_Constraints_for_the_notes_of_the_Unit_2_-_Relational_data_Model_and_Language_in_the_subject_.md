
### Domain Constraints for the notes of the Unit 2 - Relational data Model and Language in the subject of Database Management System

1. A domain is a set of values from which an attribute can take its value. 
2. Domain constraints are used to ensure that the values of an attribute are valid. 
3. Domain constraints are used to restrict or limit the values that an attribute can take. 
4. Domain constraints can be specified by using the data type of the attribute. 
5. Domain constraints can also be specified by using integrity constraints such as NOT NULL, UNIQUE, and CHECK. 
6. NOT NULL constraint ensures that the value of an attribute is not null. 
7. UNIQUE constraint ensures that the values of an attribute are unique within the relation. 
8. CHECK constraint ensures that the value of an attribute satisfies a certain condition. 
9. Domain constraints can also be specified by using domain integrity rules such as referential integrity, functional dependencies, and normalization. 
10. Referential integrity ensures that the values of a foreign key attribute are valid values of the primary key attribute in the referenced relation. 
11. Functional dependencies ensure that the values of a dependent attribute can be determined by the values of the determinant attribute. 
12. Normalization ensures that the relation is in the desired normal form.
