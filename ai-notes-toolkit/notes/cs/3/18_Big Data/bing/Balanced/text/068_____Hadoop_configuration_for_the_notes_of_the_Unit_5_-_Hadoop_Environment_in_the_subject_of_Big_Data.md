### Hadoop Configuration

- Hadoop configuration is the process of setting the parameters and properties of the Hadoop system and its components, such as HDFS, YARN, and MapReduce.
- Hadoop configuration is driven by two types of important configuration files  :
  - Read-only default configuration files that are provided by Hadoop and contain the default values for the configuration parameters. These files are located in the `share/hadoop/common` directory and have names like `core-default.xml`, `hdfs-default.xml`, `yarn-default.xml`, and `mapred-default.xml`.
  - Site-specific configuration files that are customized by the user and override the default values for the configuration parameters. These files are located in the `etc/hadoop` directory and have names like `core-site.xml`, `hdfs-site.xml`, `yarn-site.xml`, and `mapred-site.xml`.
- To configure the Hadoop cluster, the user needs to edit the site-specific configuration files and specify the values for the parameters that are relevant for the cluster setup, such as the hostnames and ports of the Hadoop daemons, the directories for storing data, the memory and CPU allocation for the nodes, the replication factor and block size for HDFS, the scheduler and resource manager for YARN, and the map and reduce tasks for MapReduce.
- To configure the environment of the Hadoop daemons, the user needs to edit the `etc/hadoop/hadoop-env.sh` file and set the environment variables that are required for running Hadoop, such as the `JAVA_HOME` variable that points to the Java installation directory, the `HADOOP_CONF_DIR` variable that points to the configuration directory, and the `HADOOP_OPTS` variable that sets the Java options for the Hadoop daemons  .
- To apply the configuration changes, the user needs to restart the Hadoop daemons using the `sbin/start-dfs.sh` and `sbin/start-yarn.sh` scripts for HDFS and YARN respectively, or the `sbin/start-all.sh` script for both. The user can also use the `sbin/stop-dfs.sh` and `sbin/stop-yarn.sh` scripts for stopping the Hadoop daemons, or the `sbin/stop-all.sh` script for both.
