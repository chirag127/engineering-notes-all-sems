## Unit 8 - MongoDB

- MongoDB is a cross-platform, document-oriented database that works on the concept of collections and documents.
- MongoDB is one of the most popular NoSQL databases, which means it does not use the relational model of tables, rows, and columns, but rather stores data as JSON-like documents with dynamic schemas.
- MongoDB offers high performance, scalability, availability, and flexibility, as well as a rich query language and powerful aggregation framework.
- Some of the key features of MongoDB are:

  - BSON format: MongoDB uses a binary representation of JSON called BSON (Binary JSON) to store and manipulate data. BSON supports additional data types, such as dates, binary data, and decimals, and allows for faster parsing and indexing.
  - Collections: MongoDB organizes data into collections, which are analogous to tables in relational databases. A collection can contain any number of documents, and each document can have a different structure or schema.
  - Documents: MongoDB stores data as documents, which are similar to JSON objects. A document consists of one or more key-value pairs, where the keys are strings and the values can be of various data types, such as strings, numbers, arrays, subdocuments, or null. Documents are the basic unit of data in MongoDB, and each document has a unique identifier called _id.
  - CRUD operations: MongoDB supports the basic operations of creating, reading, updating, and deleting data, which are commonly abbreviated as CRUD. MongoDB provides various methods and commands to perform these operations on collections and documents, such as insertOne, find, updateOne, and deleteOne.
  - Indexes: MongoDB uses indexes to speed up the queries on collections. An index is a data structure that stores a subset of the collection's data in an easy-to-traverse form. MongoDB creates a default index on the _id field of each document, and allows users to create additional indexes on any field or combination of fields.
  - Aggregation: MongoDB provides a powerful aggregation framework that allows users to perform complex data analysis and manipulation on collections. The aggregation framework consists of a pipeline of stages, where each stage applies a certain operation on the input documents and passes the output to the next stage. Some of the common aggregation stages are match, project, group, sort, and unwind.
  - Replication: MongoDB supports replication, which is the process of synchronizing data across multiple servers. Replication provides redundancy and increases data availability, as well as allows for load balancing and fault tolerance. MongoDB uses a replica set, which is a group of servers that maintain the same data set and elect a primary server to handle write operations. The other servers, called secondaries, replicate the data from the primary and can handle read operations.
  - Sharding: MongoDB supports sharding, which is the process of distributing data across multiple servers. Sharding allows for horizontal scaling, which means adding more servers to handle larger data sets and higher throughput. MongoDB uses a sharded cluster, which consists of three components: shards, mongos, and config servers. Shards are the servers that store the data, mongos are the routers that direct the queries to the appropriate shards, and config servers are the servers that store the metadata and configuration of the cluster.
