# HDFS Concepts

HDFS (Hadoop Distributed File System) is a distributed file system that runs on commodity hardware (low-cost devices) and stores large amounts of data across multiple nodes in a cluster. HDFS is one of the core components of Apache Hadoop, along with MapReduce and YARN. HDFS is designed to be highly fault-tolerant, scalable, and efficient. Some of the key concepts of HDFS are:

- **Blocks**: HDFS splits each file into fixed-size blocks, usually 128 MB, and distributes them across the data nodes in the cluster. Each block is replicated on multiple data nodes for fault tolerance. The default replication factor is 3, which means each block has 3 copies on different data nodes. The block size and replication factor can be configured according to the needs of the application.
- **NameNode**: NameNode is the master node that manages the metadata of the file system, such as the file names, directories, permissions, and locations of the blocks. NameNode also coordinates the read and write operations from the clients to the data nodes. NameNode is a critical component of HDFS, as it stores the namespace of the file system in memory. If the NameNode fails, the file system becomes inaccessible. To prevent data loss, NameNode periodically saves its metadata to a local disk and a remote disk. There can be only one active NameNode in a cluster at a time, but there can be a standby NameNode that takes over in case of failure.
- **DataNode**: DataNode is the slave node that stores the actual data blocks and serves the read and write requests from the clients. DataNode also performs block operations, such as creation, deletion, and replication, as instructed by the NameNode. DataNode periodically sends a report of its blocks to the NameNode, called a block report, to keep the NameNode updated about the status of the blocks. There can be multiple data nodes in a cluster, depending on the size and capacity of the cluster.
- **Client**: Client is the user or the application that interacts with HDFS. Client can perform operations such as creating, reading, writing, deleting, and copying files on HDFS. Client communicates with the NameNode to get the metadata of the files and the locations of the blocks. Client then directly accesses the data nodes to read or write the data blocks. Client also caches the block locations to reduce the communication overhead with the NameNode.
