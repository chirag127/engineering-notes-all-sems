### Spark on YARN

- Spark on YARN is a mode of running Spark applications on a cluster of nodes managed by YARN (Yet Another Resource Negotiator), which is a resource management framework for distributed systems.
- Spark on YARN requires a binary distribution of Spark which is built with YARN support. Binary distributions can be downloaded from the downloads page of the project website   .
- Spark on YARN supports two deploy modes: cluster mode and client mode.
  - In cluster mode, the Spark driver runs inside an application master process which is managed by YARN on the cluster, and the client can go away after initiating the application. This mode is suitable for production environments where the client machine may not be reliable or available.
  - In client mode, the Spark driver runs on the client machine that submits the application, and the application master is only responsible for requesting resources from YARN. This mode is suitable for development and testing purposes where the client machine can monitor and interact with the application.
- Spark on YARN can use two ways to distribute Spark runtime jars to the YARN cluster: spark.yarn.archive and spark.yarn.jars .
  - spark.yarn.archive is a configuration property that specifies a compressed archive file (such as zip or tar.gz) that contains the Spark runtime jars. The archive file should be uploaded to a distributed file system (such as HDFS or S3) and the property should point to its location. This way, YARN can cache the archive file on each node and reduce the network traffic and startup time for each application.
  - spark.yarn.jars is a configuration property that specifies a comma-separated list of jar files that contain the Spark runtime jars. The jar files can be either local files on the client machine or files on a distributed file system. This way, YARN can copy the jar files to each node and add them to the classpath of the application.
- Spark on YARN can use dynamic allocation to adjust the number of executors based on the workload of the application. This feature can improve the resource utilization and performance of the application. To enable dynamic allocation, the following configuration properties need to be set :
  - spark.dynamicAllocation.enabled=true
  - spark.shuffle.service.enabled=true
  - spark.dynamicAllocation.initialExecutors
  - spark.dynamicAllocation.minExecutors
  - spark.dynamicAllocation.maxExecutors
- Spark on YARN can also use external shuffle service to improve the reliability and performance of the shuffle operation. This service runs as a daemon on each node and serves the shuffle files generated by the executors. This way, the shuffle files can be preserved even if the executors are killed or removed, and the shuffle data can be transferred more efficiently between the nodes. To enable external shuffle service, the following configuration properties need to be set :
  - spark.shuffle.service.enabled=true
  - spark.shuffle.service.port
- Spark on YARN can also use YARN features such as node labels, placement constraints, and queue management to control the placement and scheduling of the application. These features can help the application to meet the requirements of availability, performance, and security. For more details, refer to the YARN documentation .
