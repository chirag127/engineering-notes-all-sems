### Hadoop I/O: compression

- Data compression is a technique to reduce the size of data files by using algorithms that encode the data more efficiently.
- Data compression can improve the performance of Hadoop applications by reducing the amount of I/O and network traffic, which are often the bottlenecks in distributed computing.
- Data compression can also save disk space and reduce the cost of storage.
- Data compression can be applied at different stages of the Hadoop data processing pipeline, such as:
  - Input data: Compression can be enabled for input data files stored in HDFS or other file systems. Hadoop supports various compression formats, such as gzip, bzip2, Snappy, LZO, etc. Hadoop can read compressed files directly without decompressing them first, as long as the compression format is splittable (meaning that the compressed file can be divided into independent chunks that can be processed in parallel by different mappers). Splittable compression formats include bzip2, LZO, and some variants of Snappy. Non-splittable compression formats include gzip and the default Snappy format. Non-splittable compression formats can still be used for input data, but they will limit the parallelism of the map phase, as each compressed file can only be processed by one mapper.
  - Intermediate data: Compression can be enabled for the intermediate data produced by the mappers and consumed by the reducers. This can reduce the network traffic and disk I/O during the shuffle and sort phase. Hadoop supports various compression codecs for intermediate data, such as gzip, Snappy, LZO, etc. The compression codec can be configured by setting the mapreduce.map.output.compress property to true and the mapreduce.map.output.compress.codec property to the desired codec class name. The compression codec for intermediate data does not need to be splittable, as the intermediate data is not split across mappers.
  - Output data: Compression can be enabled for the output data produced by the reducers and stored in HDFS or other file systems. This can save disk space and reduce the cost of storage. Hadoop supports various compression formats for output data, such as gzip, bzip2, Snappy, LZO, etc. The compression format can be configured by setting the mapreduce.output.fileoutputformat.compress property to true and the mapreduce.output.fileoutputformat.compress.codec property to the desired codec class name. The compression format for output data does not need to be splittable, as the output data is not split across reducers.
- Data compression can also be applied at the level of data serialization, which is the process of converting data objects into byte streams that can be stored or transmitted. Hadoop provides several data serialization frameworks, such as Writable, Avro, Thrift, Protocol Buffers, etc. Some of these frameworks support built-in compression, such as Avro, which can use Snappy or deflate compression for its data files. Some of these frameworks also support schema evolution, which is the ability to handle changes in the data structure over time, such as adding, removing, or renaming fields. Schema evolution can reduce the need for data conversion and increase the compatibility of data files across different versions of the application.
