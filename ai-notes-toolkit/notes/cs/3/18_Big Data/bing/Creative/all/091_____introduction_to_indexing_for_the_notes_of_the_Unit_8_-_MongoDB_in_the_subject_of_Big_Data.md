# Introduction to Indexing

Indexing is a technique that improves the performance of queries in MongoDB by creating special data structures that store a subset of the document fields in an ordered way. Indexes allow MongoDB to quickly locate and access the documents that match a query, without scanning the entire collection.

Some of the main points to know about indexing in MongoDB are:

- MongoDB automatically creates an index on the `_id` field of every collection, which is a unique identifier for each document. This index is called the primary index or the default index.
- MongoDB also supports user-defined indexes on single fields, compound fields (multiple fields in a specific order), multikey fields (fields that contain arrays), text fields (fields that contain string values), geospatial fields (fields that store location data), hashed fields (fields that store hashed values), and wildcard fields (fields that match a pattern).
- MongoDB provides a method called `createIndex()` to create an index on a collection. The syntax is `db.collection.createIndex(keys, options)`, where `keys` is a document that specifies the fields to index and their sort order, and `options` is a document that specifies additional parameters for the index, such as its name, uniqueness, expiration, etc.
- MongoDB provides a method called `dropIndex()` to drop an index from a collection. The syntax is `db.collection.dropIndex(index)`, where `index` is either the name of the index or a document that specifies the fields and their sort order.
- MongoDB provides a method called `getIndexes()` to list all the indexes on a collection. The syntax is `db.collection.getIndexes()`, which returns an array of documents that describe the indexes.
- MongoDB provides a method called `explain()` to analyze the query execution plan and the use of indexes. The syntax is `db.collection.find(query).explain(verbosity)`, where `query` is the filter criteria for the documents, and `verbosity` is the level of detail for the output, such as `queryPlanner`, `executionStats`, or `allPlansExecution`.
- MongoDB uses a B-tree data structure to store the indexes, which allows for efficient insertion, deletion, and retrieval of index entries. A B-tree consists of nodes that have a variable number of keys and child pointers, and leaves that store the index values and record pointers. The B-tree is balanced, meaning that the height of the tree is minimized and the nodes are evenly distributed.
- MongoDB supports various types of indexes, such as:

  - Single field indexes: These are indexes that are created on a single field of the documents. They can support queries that match on the exact value of the field, or use comparison operators, logical operators, or array operators. For example, `db.users.createIndex({name: 1})` creates an index on the `name` field of the `users` collection in ascending order.
  - Compound indexes: These are indexes that are created on multiple fields of the documents, in a specific order. They can support queries that match on the exact values of the fields, or use comparison operators, logical operators, or array operators, as long as the query follows the same order and prefix of the index fields. For example, `db.users.createIndex({name: 1, age: -1})` creates an index on the `name` and `age` fields of the `users` collection in ascending and descending order, respectively. This index can support queries that match on both fields, or only on the `name` field, but not on the `age` field alone.
  - Multikey indexes: These are indexes that are created on fields that contain arrays of values. MongoDB automatically detects if a field is an array and creates a separate index entry for each element of the array. These indexes can support queries that match on the exact values of the array elements, or use array operators, such as `$in`, `$all`, `$elemMatch`, etc. For example, `db.users.createIndex({hobbies: 1})` creates an index on the `hobbies` field of the `users` collection, which is an array of strings. This index can support queries that match on one or more hobbies of the users.
