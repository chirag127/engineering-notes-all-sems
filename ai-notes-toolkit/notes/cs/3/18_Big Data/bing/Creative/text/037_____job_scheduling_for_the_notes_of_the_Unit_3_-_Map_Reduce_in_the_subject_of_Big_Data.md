### Job Scheduling for the Notes of the Unit 3 - Map Reduce in the Subject of Big Data

- Job scheduling is the process of assigning tasks to resources in a distributed system, such as a Hadoop cluster, to process large-scale data sets efficiently and effectively.
- MapReduce is a programming model and an execution framework for parallel and distributed processing of big data using a cluster of commodity machines.
- A MapReduce job consists of two phases: map and reduce. The map phase applies a user-defined function to each input split (a chunk of the input data) and produces a set of intermediate key-value pairs. The reduce phase applies another user-defined function to all the values associated with the same key and produces a set of final output values.
- Job scheduling in MapReduce is challenging because of the following factors:
  - Data locality: The input data is usually distributed across the cluster nodes, and moving data across the network is costly. Therefore, it is desirable to schedule tasks on the nodes where the input data resides or on nearby nodes.
  - User share fairness: The cluster resources should be allocated fairly among different users or groups of users, according to their priorities or demands. This ensures that no user is starved or dominates the cluster resources.
  - Resource awareness: The cluster resources, such as CPU, memory, disk, and network, may vary across the nodes and may change over time. Therefore, the scheduler should be aware of the resource availability and utilization and assign tasks accordingly.
- Several job scheduling algorithms have been developed for MapReduce, which can be classified into the following categories :
  - Default scheduler: This is the original scheduler used in Hadoop 1.x, which assigns tasks to nodes in a first-come, first-served (FIFO) order, without considering data locality, user share fairness, or resource awareness. This scheduler is simple but inefficient and unfair.
  - Fair scheduler: This is a scheduler introduced in Hadoop 2.x, which assigns tasks to nodes based on the concept of weighted fair sharing. This means that each user or group of users is allocated a minimum share of resources, and any excess resources are distributed proportionally to their weights. This scheduler also considers data locality and supports preemption, which means that low-priority tasks can be killed to make room for high-priority tasks.
  - Capacity scheduler: This is another scheduler introduced in Hadoop 2.x, which assigns tasks to nodes based on the concept of queues. Each queue represents a user or a group of users and has a capacity limit, a priority, and an access control list. The scheduler allocates resources to each queue according to its capacity and priority, and then distributes the resources within each queue in a FIFO order. This scheduler also considers data locality and supports preemption.
  - Deadline-based scheduler: This is a scheduler that assigns tasks to nodes based on the deadlines of the jobs, which are specified by the users. The scheduler tries to minimize the number of jobs that miss their deadlines, while also considering data locality, user share fairness, and resource awareness. This scheduler is suitable for time-sensitive applications, such as real-time analytics and stream processing.
  - Performance-aware scheduler: This is a scheduler that assigns tasks to nodes based on the performance of the tasks, which are estimated by the scheduler using historical data or machine learning techniques. The scheduler tries to maximize the performance of the jobs, while also considering data locality, user share fairness, and resource awareness. This scheduler is suitable for performance-critical applications, such as machine learning and data mining.
