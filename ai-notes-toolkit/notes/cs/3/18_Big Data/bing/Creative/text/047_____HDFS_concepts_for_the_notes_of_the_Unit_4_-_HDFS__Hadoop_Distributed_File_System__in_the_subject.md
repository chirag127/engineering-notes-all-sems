### HDFS concepts

HDFS is a distributed file system that is designed to store and process large amounts of data on clusters of commodity hardware. HDFS is one of the core components of Apache Hadoop, an open-source framework for distributed computing and data analytics. Some of the key concepts of HDFS are:

- **Blocks**: HDFS divides each file into fixed-size blocks, usually 128 MB, and stores them across multiple data nodes in the cluster. Each block is replicated on a configurable number of data nodes, typically three, to ensure fault tolerance and availability. HDFS does not store any metadata (such as file name, permissions, etc.) with the blocks, but only a unique block ID and a checksum to verify the integrity of the data.
- **NameNode**: HDFS has a master-slave architecture, where the NameNode is the master node that manages the namespace and the metadata of the file system. The NameNode maintains a mapping of files to blocks, and blocks to data nodes, in its memory. The NameNode also coordinates the replication, deletion, and movement of blocks across data nodes, and handles the client requests for reading and writing files. The NameNode periodically receives heartbeat and block report messages from the data nodes, to monitor their status and update the block locations.
- **DataNode**: HDFS has multiple slave nodes, called DataNodes, that store and serve the blocks of data to the clients. Each DataNode registers itself with the NameNode at startup, and sends heartbeat and block report messages periodically. The DataNode also performs block operations, such as replication, deletion, and checksum verification, as instructed by the NameNode. The DataNode exposes a block scanner, which periodically verifies all the blocks stored on the node and reports any corrupted or missing blocks to the NameNode.
- **Client**: HDFS provides a client API and a command-line interface for the users to interact with the file system. The client communicates with the NameNode to obtain the metadata and the locations of the blocks for a given file, and then directly reads or writes the data from or to the DataNodes. The client also performs some of the tasks that are normally done by the file system, such as splitting the file into blocks, choosing the data nodes for replication, and recovering from failures. The client caches the block locations for better performance and reduces the load on the NameNode.
- **Secondary NameNode**: HDFS has a secondary node, called Secondary NameNode, that helps the NameNode in maintaining the file system metadata. The Secondary NameNode periodically merges the namespace image and the edit log of the NameNode, and creates a new checkpoint. The Secondary NameNode also acts as a backup for the NameNode, in case of a failure or a planned maintenance. However, the Secondary NameNode is not a hot standby for the NameNode, and cannot take over its role without manual intervention.
