
### Decision Tables for the Notes of the Unit 2 - Software Requirement Specifications (SRS) in the Subject of Software Engineering

* A decision table is a graphical representation of a set of logical conditions and their associated actions. It is used to represent a set of logical conditions and the actions that should be taken when these conditions are met. 
* A decision table is composed of two parts: the conditions and the actions. The conditions are the logical conditions that must be met in order for the action to be taken. The actions are the tasks that should be performed when the conditions are met. 
* Decision tables can be used to represent a wide variety of software requirements. For example, they can be used to represent the conditions and actions associated with a user interface, a business process, or a security policy. 
* Decision tables can also be used to represent the logic of a software system. For example, they can be used to represent the logic of a program, or the logic of a database. 
* Decision tables can be used to represent the logic of a system in a concise and easy to understand format. This makes them a powerful tool for software engineers and system designers. 
* Decision tables can also be used to represent the logic of a system in a way that is easy to maintain. This makes them a valuable tool for software maintenance.
