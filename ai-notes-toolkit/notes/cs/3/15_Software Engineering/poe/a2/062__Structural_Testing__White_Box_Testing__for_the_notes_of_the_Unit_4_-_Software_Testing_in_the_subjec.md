### Structural Testing (White Box Testing)

1. Structural Testing, also known as White Box Testing, verifies the internal structure of the software.
2. It focuses on the internal logic and structure of the software.
3. The test inputs are designed based on the internal structure of the software.
4. The key steps in Structural Testing are:
- Analyzing the internal structure (logic, modules, objects, etc.) of the software.
- Identifying paths or conditions to be tested.
- Designing input data to exercise the identified paths or conditions.
- Evaluating test outputs.

5. The goals of Structural Testing are:
- Exercise all independent paths or conditions.
- Ensure that all statements in the program are executed at least once.
- Detecting errors related to the internal logic of the program.

6. The techniques used in Structural Testing are:
- Control Flow Testing - All conditional logic and loops are tested.
- Data Flow Testing - All variables are traced and all definitions and uses are verified.
- Mutation Testing - Introducing defects (mutations) in the code and checking if test cases detect them.

7. The advantages of Structural Testing are:
- It discovers errors in the internal logic of the software.
- It provides a measure of test thoroughness.
- It can be automated.

The drawbacks are:
- It can be difficult and time-consuming to analyze complex program structures.
- 100% path coverage may not be feasible.
- It does not check for functional correctness.
