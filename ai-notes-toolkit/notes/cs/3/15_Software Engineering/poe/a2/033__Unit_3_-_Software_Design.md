## Unit 3 - Software Design

1. Software Architecture - The architectural design of software includes the decomposition of a system into components and interfaces between these components. It helps in managing the complexity of software systems through abstraction and modularization. Some key aspects of software architecture are:
- Components and interfaces
- Connectors
- Constraints
- Views

2. Design Patterns - Design patterns represent solutions to common software design problems. They provide a template for how to solve problems that can be reused in multiple situations. Some common software design patterns are:
- Creational patterns - Factory method, Singleton, Builder, Prototype
- Structural patterns - Adapter, Bridge, Composite, Decorator, Facade, Flyweight, Proxy
- Behavioral patterns - Chain of responsibility, Command, Interpreter, Iterator, Mediator, Memento, Observer, State, Strategy, Template method, Visitor

3. Object-Oriented Design - Object-oriented design focuses on modeling problems using objects and classes. Some key principles of object-oriented design are:
- Encapsulation - Hiding the internal details of a class
- Inheritance - Reusing code from parent classes
- Polymorphism - Same interface, different underlying logic
- Abstraction - Simplifying complex problems
- Coupling - Degree of dependency between classes
- Cohesion -Degree to which components belong together

4. Aspect-Oriented Design - Aspect-oriented design focuses on cross-cutting concerns that affect multiple modules. It uses techniques like aspect-oriented programming to implement features that transverse multiple modules. Some examples of cross-cutting concerns are:
- Logging
- Security
- Performance monitoring
- Error handling
- Transaction management

5. Domain-Driven Design - Domain-driven design focuses on modeling complex problems by deeply understanding the domain to develop a ubiquitous language to solve the problem. Key concepts in domain-driven design are:
- Domain model - Modeling core concepts and behaviors
- Context - Boundary defining applicability of the model
- Ubiquitous language - Shared language used to describe the domain
- Bounded context - Context boundaries defining valid usage
