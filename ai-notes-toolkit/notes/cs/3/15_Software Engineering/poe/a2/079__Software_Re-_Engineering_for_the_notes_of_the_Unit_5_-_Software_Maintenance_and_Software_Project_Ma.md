### Software Re-Engineering

* Software re-engineering refers to the examination and alteration of a system to reconstitute it in a new form and the subsequent implementation of the new form.
* It is usually done to reduce software maintenance costs, to eliminate legacy software, or to adapt to a changed environment.
* The steps involved in software re-engineering are:
** Understanding the existing system.
** Re-specifying the system.
** Re-designing the system.
** Implementing and testing the re-engineered system.
** Transitioning to the new system.
* The challenges involved in software re-engineering are:
** Lack of documentation - Difficulty in understanding the existing system.
** Technical debt - Additional rework required to fix the poor design/coding decisions made earlier.
** Tightly coupled components - Difficulty in isolating components for alteration.
** Performance issues - The re-engineered system may not meet the performance requirements.
** Cost and schedule overruns - The re-engineering process may take more time and effort than estimated.
* Some techniques used in software re-engineering are:
** Reverse engineering - Analyzing the existing system to extract design information.
** Restructuring - Altering the internal structure of the system.
** Automated code transformation - Using tools to automatically transform the code.
** Reconstruction - Re-implementing the system from scratch.
