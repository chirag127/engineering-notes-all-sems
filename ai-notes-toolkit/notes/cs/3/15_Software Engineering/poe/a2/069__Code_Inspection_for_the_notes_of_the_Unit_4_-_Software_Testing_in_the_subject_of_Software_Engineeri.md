### Code Inspection for the notes of the Unit 4 - Software Testing in the subject of Software Engineering

1. Code inspection is a formal technique for finding and fixing defects or faults in software artifacts like requirements specifications, design documents, source code, and test plans.
2. It is usually done as a team activity in a meeting, where each person examines the inspected artifact independently before meeting as a team to discuss their findings.
3. The main goals of code inspection are to:
- Find and fix defects and bugs early in the software lifecycle.
- Improve the overall quality of the product.
- Share knowledge among team members about the inspected artifact.
- Provide training and learning opportunities for team members.
4. The steps involved in a code inspection process are:
- Overview: The moderator explains the goal and process of the inspection. The author describes the artifact and highlights potential issues.
- Individual preparation: Each inspector examines the artifact individually and notes down any issues found.
- Team meeting: The issues are discussed as a team and classified as actual defects, questioned issues, or invalid issues. The author clarifies and the team agrees on defects to be fixed.
- Follow-up: The author fixes the defects and the cycle repeats if needed.
5. The benefits of code inspection are:
- Early detection of defects which reduces cost of fixing.
- Increased shared knowledge and learning within the team.
- Opportunity to improve the quality and clarity of specifications and design.
- Identification of common errors and patterns which can drive improvements to processes and tools.
