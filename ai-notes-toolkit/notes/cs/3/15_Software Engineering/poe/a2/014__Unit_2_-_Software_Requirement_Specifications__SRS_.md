## Unit 2 - Software Requirement Specifications (SRS)

1. Introduction
- SRS is a document that describes what the software will do and how it will be developed. It is like a contract between the customer and developer.
- It helps to understand customer needs and convert them into software requirements.
- It is developed in the initial stage of the software development lifecycle.

2. Purpose
- Establishes what the system will and will not do.
- Describes the major functional capabilities that make up the system.
- Describes software constraints, eg. resources, interfaces, and performance requirements.
- Establishes a baseline for validating system design and assessing task completion.
- Enables estimation of costs, effort, and risks.

3. Characteristics
- Correct: Accurately reflects user needs
- Unambiguous: Has only one interpretation
- Complete: Specifies all functional and non-functional requirements
- Consistent: Does not contradict itself
- Ranked for importance and/or stability
- Verifiable: Capable of being checked
- Modifiable: Can accommodate changes
- Traceable: Origin or rationale is identifiable
