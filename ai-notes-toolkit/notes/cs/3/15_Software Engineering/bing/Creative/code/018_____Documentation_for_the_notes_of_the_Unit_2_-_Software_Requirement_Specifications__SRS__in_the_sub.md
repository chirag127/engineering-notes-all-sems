# Unit 2 - Software Requirement Specifications (SRS)

## Introduction

- Software Requirement Specifications (SRS) is a document that describes the features, functions, and constraints of a software system.
- SRS is also known as Software Requirements Document (SRD), Software Requirements Specification (SRS), or Functional Specification (FS).
- SRS is a communication tool between the stakeholders and the developers of the software system.
- SRS is a basis for software design, development, testing, and maintenance.

## Purpose of SRS

- The purpose of SRS is to:
  - Define the scope and boundaries of the software system.
  - Specify the functional and non-functional requirements of the software system.
  - Provide a common understanding and agreement among the stakeholders and the developers of the software system.
  - Establish the criteria for verifying and validating the software system.
  - Reduce the risks of software development by identifying and resolving ambiguities, inconsistencies, and conflicts in the requirements.
  - Facilitate the reuse and modification of the software system.

## Characteristics of a Good SRS

- A good SRS should have the following characteristics:
  - Correct: The SRS should accurately reflect the needs and expectations of the stakeholders and the users of the software system.
  - Complete: The SRS should cover all the requirements of the software system, without any gaps or omissions.
  - Consistent: The SRS should not have any contradictions or conflicts among the requirements or with other documents.
  - Clear: The SRS should use precise, unambiguous, and understandable language and terminology.
  - Verifiable: The SRS should state the requirements in a way that can be checked and confirmed by tests, demonstrations, or inspections.
  - Modifiable: The SRS should be structured and organized in a way that allows easy and controlled changes and updates.
  - Traceable: The SRS should be able to track the origin, rationale, and dependencies of each requirement, as well as the impact of any changes to the requirements.

## Structure and Contents of SRS

- The structure and contents of SRS may vary depending on the type, size, and complexity of the software system, as well as the standards and guidelines followed by the organization or the project.
- However, a typical SRS may include the following sections:
  - Introduction: This section provides an overview of the SRS, including its purpose, scope, definitions, acronyms, abbreviations, references, and overview.
  - Overall Description: This section describes the general factors that affect the software system, such as the product perspective, product functions, user characteristics, constraints, assumptions, and dependencies.
  - Specific Requirements: This section details the specific requirements of the software system, such as the functional requirements, non-functional requirements, external interface requirements, performance requirements, security requirements, quality attributes, and design constraints.
  - Appendices: This section contains any additional or supplementary information that may be relevant to the SRS, such as data models, data dictionaries, use cases, user stories, scenarios, diagrams, charts, tables, etc.
  - Index: This section provides an alphabetical list of the terms and topics used in the SRS, along with their page numbers.
