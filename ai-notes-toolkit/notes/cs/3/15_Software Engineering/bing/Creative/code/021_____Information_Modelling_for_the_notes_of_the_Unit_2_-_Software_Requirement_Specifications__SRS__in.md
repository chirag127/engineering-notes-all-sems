# Information Modelling for the notes of the Unit 2 - Software Requirement Specifications (SRS) in the subject of Software Engineering

- Information modelling is a process of representing the concepts, relationships, constraints, rules and operations of a domain of interest in a formal and abstract way .
- Information modelling is useful for specifying the data semantics and structure of a software system, as well as for validating and verifying the requirements and design of the system .
- Information modelling can be done at different levels of abstraction and detail, depending on the purpose and scope of the model .
- Information modelling can be performed using various techniques and notations, such as entity-relationship diagrams, UML class diagrams, data flow diagrams, etc .
- Information modelling can be divided into three main phases:
  - Conceptual data modelling: This phase involves identifying the entities, attributes and relationships that are relevant to the domain and the system, and defining them in a high-level and independent way.
  - Logical data modelling: This phase involves refining and organizing the conceptual data model into a more structured and formal representation, such as a relational schema or an object-oriented model.
  - Physical data modelling: This phase involves mapping the logical data model to the specific data storage and manipulation technologies that are used by the system, such as databases, files, etc.
- Information modelling can help to improve the quality, consistency, completeness and accuracy of the software requirements and design, as well as to facilitate the communication and collaboration among the stakeholders of the system  .
