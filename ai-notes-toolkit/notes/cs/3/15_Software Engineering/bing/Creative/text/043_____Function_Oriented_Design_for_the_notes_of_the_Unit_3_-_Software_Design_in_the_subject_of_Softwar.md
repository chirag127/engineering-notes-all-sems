### Function Oriented Design

- Function Oriented Design is an approach to software design where the design is decomposed into a set of interacting units or modules where each unit or module has a clearly defined function .
- The main focus of Function Oriented Design is on the functions or operations that the software performs, rather than the data or information that the software manipulates.
- Function Oriented Design is based on the principle of top-down decomposition, where the software is divided into smaller and simpler sub-problems, and each sub-problem is further divided until it becomes a single function or module.
- Function Oriented Design follows a structured programming paradigm, where the control flow of the software is represented by using constructs such as sequence, selection, and iteration.
- Function Oriented Design uses various design notations and techniques to model the software, such as:
  - Data Flow Diagram (DFD): A graphical representation of the flow of data and functions in the software .
  - Data Dictionary: A repository of information about the data items defined in the DFD, such as their names, types, formats, and meanings .
  - Structure Chart: A hierarchical diagram of the modules and their relationships in the software .
  - Pseudo-code: A textual description of the logic and algorithm of each module in the software .
- Function Oriented Design has some advantages, such as:
  - It is easy to understand and implement, as it follows a natural way of problem solving.
  - It facilitates modularization and reusability of code, as each function or module can be tested and maintained independently.
  - It supports top-down testing and debugging, as each function or module can be verified before integrating with others.
- Function Oriented Design also has some disadvantages, such as:
  - It does not consider the data or information aspects of the software, which may lead to data redundancy and inconsistency.
  - It may result in poor performance and efficiency, as the software may have to pass large amounts of data between functions or modules.
  - It may not be suitable for complex and dynamic software systems, as it does not capture the interactions and behaviors of the software entities.
