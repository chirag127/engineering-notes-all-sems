# SQA Plans for the notes of the Unit 2 - Software Requirement Specifications (SRS) in the subject of Software Engineering

- Software Quality Assurance (SQA) is a process that assures that all software engineering processes, methods, activities, and work items are monitored and comply with the defined standards.
- Software Quality Assurance Plan (SQAP) is a document that defines the techniques, procedures, and tools that are employed to make sure that a product or service aligns with the requirements defined in the SRS .
- The purpose of an SQA plan is to ensure that the software product or service meets the customer's expectations, is delivered on time and within budget, and is free of defects .
- The content of an SQA plan may vary depending on the project, but it typically consists of the following sections  :
  - Purpose section: This section states the objectives and scope of the SQA plan, and identifies the software product or service that is subject to the plan.
  - Reference document: This section lists the documents that are relevant to the SQA plan, such as the SRS, the software development plan, the software testing plan, the software configuration management plan, and the software standards and guidelines.
  - Management: This section describes the roles and responsibilities of the SQA team, the SQA activities and tasks, the SQA schedule and resources, and the SQA reporting and communication mechanisms.
  - Documentation: This section specifies the documentation requirements for the software product or service, such as the documentation standards, formats, templates, reviews, approvals, and distribution.
  - Standards, practices, conventions, and metrics: This section defines the standards, practices, conventions, and metrics that will be followed and applied throughout the software development life cycle, such as the coding standards, the design standards, the testing standards, the quality metrics, and the defect tracking and reporting standards.
  - Reviews and audits: This section describes the reviews and audits that will be conducted to verify and validate the software product or service, such as the peer reviews, the walkthroughs, the inspections, the audits, and the corrective actions.
  - Testing: This section describes the testing activities and methods that will be performed to ensure the quality of the software product or service, such as the testing strategy, the testing levels, the testing techniques, the testing tools, the test cases, the test data, the test results, and the test reports.
  - Problem reporting and corrective action: This section describes the process and procedures for reporting and resolving the problems and defects that are identified during the software development and testing, such as the problem identification, the problem classification, the problem analysis, the problem resolution, the problem verification, and the problem closure.
  - Tools, techniques, and methodologies: This section describes the tools, techniques, and methodologies that will be used to support the SQA activities and tasks, such as the software configuration management tools, the software testing tools, the software quality measurement tools, the software quality improvement tools, and the software quality assurance methodologies.
  - Code control: This section describes the code control procedures and practices that will be followed to ensure the integrity and traceability of the software product or service, such as the code identification, the code versioning, the code branching, the code merging, the code labeling, the code storage, the code retrieval, and the code backup.
  - Media control: This section describes the media control procedures and practices that will be followed to ensure the security and availability of the software product or service, such as the media identification, the media labeling, the media storage, the media handling, the media distribution, and the media disposal.
  - Supplier control: This section describes the supplier control procedures and practices that will be followed to ensure the quality of the software products or services that are acquired from external sources, such as the supplier selection, the supplier evaluation, the supplier contract, the supplier monitoring, the supplier delivery, and the supplier acceptance.
  - Records collection, maintenance, and retention: This section describes the records collection, maintenance, and retention procedures and practices that will be followed to ensure the completeness and accuracy of the SQA documentation and data, such as the records identification, the records classification, the records storage, the records access, the records update, and the records retention.
