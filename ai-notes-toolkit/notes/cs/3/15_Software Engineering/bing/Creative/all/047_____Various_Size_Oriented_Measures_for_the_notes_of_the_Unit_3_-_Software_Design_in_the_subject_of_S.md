# Various Size Oriented Measures

- Size oriented measures are software metrics that are derived by normalizing quality and/or productivity measures by considering the size of the software that has been produced .
- Size oriented measures are also used for measuring and comparing the productivity of programmers and the efficiency of software.
- The size measurement is based on lines of code (LOC) computation, which is a direct measure of software.
- Some examples of size oriented measures are:
  - Lines of code per person-month (LOC/PM): This measure indicates the average amount of code produced by a programmer in a month. It can be used to estimate the effort and duration of a software project.
  - Errors per thousand lines of code (E/KLOC): This measure indicates the average number of errors found in a software product per thousand lines of code. It can be used to assess the quality and reliability of a software product.
  - Cost per line of code (C/LOC): This measure indicates the average cost of producing one line of code. It can be used to compare the cost-effectiveness of different software projects or methods.
  - Documentation pages per thousand lines of code (D/KLOC): This measure indicates the average number of pages of documentation produced for a software product per thousand lines of code. It can be used to evaluate the completeness and clarity of the documentation.
- Some advantages of size oriented measures are:
  - They are easy to collect and calculate.
  - They are widely used and understood in the software industry.
  - They can be applied to any programming language or paradigm.
- Some disadvantages of size oriented measures are:
  - They are dependent on the definition and counting method of lines of code, which may vary across projects and tools.
  - They do not account for the complexity, functionality, or quality of the software product.
  - They may encourage undesirable behaviors such as padding, cutting, or copying code to meet the targets.
