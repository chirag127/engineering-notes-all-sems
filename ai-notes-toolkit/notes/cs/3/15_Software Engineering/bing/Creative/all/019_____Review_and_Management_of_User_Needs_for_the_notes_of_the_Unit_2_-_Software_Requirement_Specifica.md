# Review and Management of User Needs

- User needs are the expectations and requirements of the end-users of a software system.
- User needs are derived from the problem domain, the environment, the stakeholders, and the user scenarios of the software system.
- User needs are expressed in natural language, diagrams, or other informal notations, and are often ambiguous, incomplete, inconsistent, or vague.
- Review and management of user needs are the activities of validating, verifying, prioritizing, organizing, and documenting the user needs for the software system.
- Review and management of user needs are essential for ensuring that the software system meets the user expectations and requirements, and for avoiding errors, conflicts, and changes in the later stages of software development.

## Review of User Needs

- Review of user needs is the process of checking the user needs for correctness, completeness, consistency, clarity, feasibility, and testability.
- Review of user needs can be done by using different techniques, such as inspection, walkthrough, prototyping, simulation, or formal methods.
- Review of user needs can involve different stakeholders, such as users, customers, developers, testers, analysts, or managers.
- Review of user needs can result in identifying and resolving errors, conflicts, gaps, or ambiguities in the user needs, and in improving the quality and understanding of the user needs.

## Management of User Needs

- Management of user needs is the process of organizing, prioritizing, tracing, and documenting the user needs for the software system.
- Management of user needs can be done by using different tools, such as spreadsheets, databases, matrices, or software tools.
- Management of user needs can involve different activities, such as grouping, ranking, filtering, or categorizing the user needs, and assigning attributes, identifiers, or dependencies to the user needs.
- Management of user needs can result in creating and maintaining a user needs document, which is a formal and structured representation of the user needs for the software system.
