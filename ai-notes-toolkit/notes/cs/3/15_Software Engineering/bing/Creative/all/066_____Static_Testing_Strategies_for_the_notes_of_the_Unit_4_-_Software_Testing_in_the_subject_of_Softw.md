# Static Testing Strategies

Static testing is a software testing technique that involves checking the software artifacts without executing the code. Static testing can help to find defects and improve the quality of software development at an early stage. Static testing can be done in two ways: review and static analysis .

## Review

Review is a process of examining the software documents to find and eliminate errors or ambiguities. Review can be done by the author of the document, by peers, by managers, by customers, or by external experts. Review can be formal or informal, depending on the level of rigor and documentation required. Review can be applied to various software documents, such as requirements, design, test cases, code, etc. Review can help to verify the consistency, completeness, correctness, and clarity of the software documents     .

## Static Analysis

Static analysis is a process of analyzing the software code or binaries to detect defects, vulnerabilities, or violations of coding standards. Static analysis can be done by using tools or manually. Static analysis can help to identify syntax errors, logical errors, memory leaks, buffer overflows, dead code, unused variables, etc. Static analysis can also measure the complexity, maintainability, and testability of the code     .

## Benefits of Static Testing

Static testing has several benefits, such as:

- It can detect defects early in the software development life cycle, which can reduce the cost and time of fixing them later.
- It can improve the quality and reliability of the software by preventing defects from reaching the dynamic testing or production stages.
- It can enhance the communication and collaboration among the stakeholders by providing feedback and suggestions on the software documents.
- It can increase the coverage and effectiveness of the dynamic testing by ensuring that the software documents are clear, consistent, and testable     .
