## Unit 2 - Software Requirement Specifications (SRS)

Software Requirement Specifications (SRS) is a document that describes the requirements of a software system. It is a comprehensive description of the intended purpose and environment for the software under development. The SRS fully describes what the software will do and how it will be expected to perform.

The main objectives of an SRS document are to:

1. Provide a detailed description of the software system to be developed.
2. Establish a basis for agreement between the customer and the developer on what the software product is to do.
3. Provide a reference for validation of the final product.
4. Facilitate transfer of the software product to new users or new machines.
5. Serve as a basis for enhancement of the product.

An SRS document typically includes the following sections:

1. Introduction: This section provides an overview of the entire SRS document and describes the purpose, scope, and organization of the document.
2. Overall Description: This section provides a general description of the software product, including its functionality, user characteristics, constraints, and assumptions.
3. Specific Requirements: This section provides a detailed description of the functional and non-functional requirements of the software product.
4. Appendices: This section may include any additional information, such as a glossary of terms or references to other documents.

An SRS document should be clear, concise, and complete. It should be written in a way that is understandable to both technical and non-technical readers. It is important to involve the customer in the development of the SRS to ensure that the requirements accurately reflect the needs of the user. The SRS should be reviewed and updated regularly to reflect any changes in the requirements of the software system.
