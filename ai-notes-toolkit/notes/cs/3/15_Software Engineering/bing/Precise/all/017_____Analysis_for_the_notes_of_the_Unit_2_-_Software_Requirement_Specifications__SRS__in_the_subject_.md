# Analysis for the notes of the Unit 2 - Software Requirement Specifications (SRS) in the subject of Software Engineering

1. Software Requirement Specifications (SRS) is a document that describes the requirements of a software system.
2. The purpose of the SRS is to provide a detailed description of the software system to be developed, including its functional and non-functional requirements.
3. The SRS serves as a contract between the customer and the developer, specifying what the software should do and how it should perform.
4. The SRS should be clear, concise, and complete, and should be written in a language that is understandable to both the customer and the developer.
5. The SRS should be organized in a logical manner, with sections for an introduction, overall description, specific requirements, and appendices.
6. The SRS should include a description of the software's intended users, its operating environment, and its constraints.
7. The SRS should also include a description of the software's functional requirements, including its inputs, processing, and outputs.
8. The SRS should also include a description of the software's non-functional requirements, such as performance, reliability, and security.
9. The SRS should be reviewed and approved by the customer before development begins.
10. The SRS should be updated as necessary throughout the development process to reflect changes in the requirements.
