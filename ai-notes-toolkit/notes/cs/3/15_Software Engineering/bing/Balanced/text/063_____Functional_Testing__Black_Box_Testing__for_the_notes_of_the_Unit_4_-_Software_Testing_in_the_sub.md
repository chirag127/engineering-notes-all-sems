### Functional Testing (Black Box Testing) for the notes of the Unit 4 - Software Testing in the subject of Software Engineering

- Functional testing is a type of testing that seeks to establish whether each application feature works as per the software requirements.
- Black box testing is a method of software testing that examines the functionality of an application without peering into its internal structures or workings.
- Black box testing can be applied to all levels of software testing: unit, integration, system and acceptance. It is sometimes referred to as specification-based testing.
- Black box testing does not require knowledge of the internal code structure of the software. It focuses on the input and output of the software under test.
- Black box testing can be divided into two types: functional testing and non-functional testing.
  - Functional testing is related to the functional requirements of a system; it is done by software testers. It verifies that the software performs the expected functions correctly.
  - Non-functional testing is not related to testing of specific functionality, but non-functional requirements such as performance, scalability, usability, security, etc. It checks how the software performs a specific action, rather than if it can perform it.
- Black box testing can be done in various ways, depending on the type of software and the testing objectives. Some of the common black box testing techniques are:
  - Equivalence partitioning: This technique divides the input domain of the software into a number of equivalent classes, such that each class represents a set of valid or invalid inputs. Then, one input from each class is selected for testing.
  - Boundary value analysis: This technique tests the software at the boundary values of the input domain, such as the minimum, maximum, or just inside or outside the boundaries. These values are more likely to cause errors than the normal values.
  - Decision table testing: This technique uses a table to represent the logical conditions and the corresponding actions of the software. Each row of the table corresponds to a test case that covers a combination of conditions and actions.
  - State transition testing: This technique models the software as a finite state machine, with a set of states and transitions between them. Each transition is triggered by an input or an event. The test cases are designed to cover all the possible states and transitions of the software.
  - Use case testing: This technique uses the use cases of the software, which describe the interactions between the software and the users or other systems. The test cases are derived from the scenarios and flows of events in the use cases.
  - Syntax-driven testing: This technique is applied to systems that can be syntactically represented by some language, such as compilers or interpreters. The test cases are generated based on the grammar rules of the language.
