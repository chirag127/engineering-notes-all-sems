### Various Size Oriented Measures

- Size oriented measures are software metrics that are derived by normalizing quality and/or productivity measures by considering the size of the software that has been produced .
- Size oriented measures are based on the assumption that the size of the software is a predictor of other attributes, such as complexity, effort, cost, quality, etc.
- Size oriented measures are also used for measuring and comparing the productivity of programmers and teams.
- The most common size oriented measure is the **lines of code (LOC)**, which counts the number of executable statements in the source code .
- LOC can be measured in different ways, such as physical LOC (counting each line of code as one unit), logical LOC (counting each statement or instruction as one unit), or effective LOC (counting only the lines of code that contribute to the functionality of the software).
- LOC has some advantages, such as being easy to measure, widely available, and independent of the programming language.
- LOC also has some disadvantages, such as being influenced by the coding style, the level of abstraction, the reuse of code, and the comments.
- Another size oriented measure is the **function point (FP)**, which measures the functionality of the software from the user's perspective .
- FP is based on the number and complexity of inputs, outputs, inquiries, files, and interfaces of the software .
- FP has some advantages, such as being independent of the programming language, the coding style, and the level of abstraction, and being more related to the user requirements and the value of the software.
- FP also has some disadvantages, such as being subjective, difficult to measure, and requiring more information and expertise.
- Other size oriented measures include **object points**, which count the number and complexity of objects, classes, methods, and attributes in object-oriented software, and **feature points**, which extend the function points by adding the number and complexity of algorithms.
