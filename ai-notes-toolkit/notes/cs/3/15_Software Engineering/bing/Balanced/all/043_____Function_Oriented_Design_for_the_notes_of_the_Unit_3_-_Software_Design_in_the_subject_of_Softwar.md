# Function Oriented Design

- Function Oriented Design is an approach to software design where the design is decomposed into a set of interacting units or modules where each unit or module has a clearly defined function .
- The system is designed from a functional viewpoint, meaning that the focus is on what the system does rather than how it does it.
- The main steps of Function Oriented Design are:
  - Identify the functions that the system needs to perform and the data that the system needs to process.
  - Draw a data flow diagram (DFD) to show the flow of information and data among the functions and data stores.
  - Define the data dictionary to store the information about the data items used in the DFD.
  - Refine the DFD by decomposing the functions into sub-functions and adding more details to the data items and data stores.
  - Structure the functions into a hierarchy using a structure chart to show the control and communication among the functions.
  - Design the algorithms and data structures for each function using pseudocode, flowcharts, or other notations.
- The advantages of Function Oriented Design are:
  - It is easy to understand and communicate the system functionality using DFDs and structure charts.
  - It supports top-down and modular design, which facilitates the development and maintenance of the system.
  - It allows reuse of existing functions or modules in other systems or projects.
- The disadvantages of Function Oriented Design are:
  - It does not capture the dynamic behavior or the state changes of the system.
  - It does not support object-oriented concepts such as encapsulation, inheritance, and polymorphism, which are widely used in modern software development.
  - It may result in poor data design, as the data is secondary to the functions and may be scattered across different modules.
