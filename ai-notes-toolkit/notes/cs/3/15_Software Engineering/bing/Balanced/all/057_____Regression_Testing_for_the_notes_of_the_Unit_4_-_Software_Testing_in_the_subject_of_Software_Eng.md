# Regression Testing

- Regression testing is a type of software testing that verifies that software previously developed and tested still performs correctly after it was changed or interfaced with other software.
- Regression testing is done to ensure that changes made in the software do not introduce new defects or break existing functionality.
- Regression testing can be performed at any level of testing, such as unit testing, integration testing, system testing, or acceptance testing.
- Regression testing can be done manually or automated, depending on the scope, complexity, and frequency of the changes.
- Regression testing can be classified into three types: retest all, selective, and test suite minimization.

## Retest All
- Retest all is a regression testing strategy that involves re-executing all the test cases that were previously executed on the software.
- Retest all is the most thorough and reliable strategy, but also the most expensive and time-consuming.
- Retest all is suitable when the changes made in the software are extensive, complex, or unpredictable, or when the test cases are not well documented or organized.

## Selective
- Selective is a regression testing strategy that involves re-executing only a subset of the test cases that were previously executed on the software.
- Selective is a more efficient and cost-effective strategy than retest all, but also less reliable and comprehensive.
- Selective is suitable when the changes made in the software are minor, simple, or predictable, or when the test cases are well documented and organized.
- Selective can be based on various criteria, such as the impact of the changes, the coverage of the test cases, the priority of the test cases, the risk of the test cases, or the history of the test cases.

## Test Suite Minimization
- Test Suite Minimization is a regression testing strategy that involves reducing the number of test cases in the test suite without compromising the effectiveness of the testing.
- Test Suite Minimization is a more advanced and sophisticated strategy than selective, but also more challenging and complex.
- Test Suite Minimization is suitable when the test suite is large, redundant, or outdated, or when the resources for testing are limited or constrained.
- Test Suite Minimization can be achieved by various techniques, such as test case prioritization, test case selection, test case clustering, or test case generation.
