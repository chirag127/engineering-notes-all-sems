## Unit 2 - Software Requirement Specifications (SRS)

- Software Requirement Specifications (SRS) is a document that describes the features, functions, and constraints of a software system.
- SRS is also known as Software Requirements Document (SRD), Software Requirements Specification, or Functional Specification.
- SRS is a communication tool between the stakeholders and the developers of the software system.
- SRS helps to ensure that the software system meets the needs and expectations of the stakeholders and the users.
- SRS also serves as a basis for software design, testing, validation, verification, maintenance, and evolution.

### Objectives of SRS

- To define the scope and boundaries of the software system.
- To establish a common understanding of the software system among the stakeholders and the developers.
- To specify the functional and non-functional requirements of the software system.
- To provide a reference for software design, testing, validation, verification, maintenance, and evolution.
- To reduce the risk of software failure, rework, and cost overrun.

### Characteristics of a Good SRS

- A good SRS should be clear, concise, consistent, complete, correct, traceable, verifiable, modifiable, and unambiguous.
- A good SRS should use simple and precise language, avoid jargon and technical terms, and use diagrams and tables to illustrate the requirements.
- A good SRS should avoid ambiguity, inconsistency, incompleteness, and contradiction in the requirements.
- A good SRS should state the requirements in a testable and measurable way, and provide criteria for validation and verification.
- A good SRS should allow for changes and updates in the requirements, and maintain a traceability matrix to link the requirements to the sources and the design elements.

### Components of SRS

- A typical SRS consists of the following components:

  - Introduction: This section provides an overview of the software system, its purpose, scope, objectives, assumptions, constraints, and references.
  - System Overview: This section provides a high-level description of the software system, its context, architecture, components, interfaces, and interactions.
  - Functional Requirements: This section specifies the functions and behaviors that the software system should perform, and the inputs, outputs, and data flows of each function.
  - Non-Functional Requirements: This section specifies the quality attributes and constraints that the software system should satisfy, such as performance, reliability, security, usability, maintainability, etc.
  - System Models: This section provides graphical and textual models of the software system, such as use case diagrams, data flow diagrams, entity-relationship diagrams, state transition diagrams, etc.
  - Glossary: This section defines the terms and acronyms used in the SRS document.
  - Appendices: This section provides additional information and documents that support the SRS document, such as user profiles, scenarios, prototypes, standards, etc.
