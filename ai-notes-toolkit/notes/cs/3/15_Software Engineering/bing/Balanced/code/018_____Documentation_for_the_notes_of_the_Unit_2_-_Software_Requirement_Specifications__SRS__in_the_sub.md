# Unit 2 - Software Requirement Specifications (SRS)

## Introduction
- Software Requirement Specifications (SRS) is a document that describes the features, functions, and constraints of a software system.
- SRS is also known as Software Requirements Document (SRD), Software Requirements Specification (SRS), or Functional Specification (FS).
- SRS is a communication tool between the stakeholders and the developers of the software system.
- SRS helps to ensure that the software system meets the needs and expectations of the stakeholders and the users.
- SRS also serves as a basis for software design, testing, and maintenance.

## Purpose of SRS
- The purpose of SRS is to:
  - Define the scope and boundaries of the software system.
  - Specify the functional and non-functional requirements of the software system.
  - Provide a common understanding and agreement among the stakeholders and the developers of the software system.
  - Establish the criteria for verifying and validating the software system.
  - Reduce the risks of software development and maintenance.

## Characteristics of SRS
- A good SRS should have the following characteristics:
  - Correct: The SRS should accurately reflect the needs and expectations of the stakeholders and the users.
  - Complete: The SRS should cover all the requirements of the software system, without any ambiguity or inconsistency.
  - Consistent: The SRS should not have any conflicting or contradictory requirements.
  - Clear: The SRS should be written in a clear and concise language, using well-defined terms and notations.
  - Verifiable: The SRS should be testable and measurable, using objective criteria and methods.
  - Modifiable: The SRS should be easy to change and update, using a systematic and traceable process.
  - Traceable: The SRS should be able to trace the origin and rationale of each requirement, and the impact of any change on the other requirements.

## Structure of SRS
- The structure of SRS may vary depending on the type and complexity of the software system, and the standards and guidelines followed by the organization.
- However, a typical SRS may have the following sections:
  - Introduction: This section provides an overview of the software system, its objectives, scope, assumptions, constraints, and references.
  - User Requirements: This section describes the needs and expectations of the users of the software system, in terms of user stories, use cases, scenarios, or user interfaces.
  - System Requirements: This section describes the functional and non-functional requirements of the software system, in terms of features, functions, performance, reliability, security, usability, etc.
  - System Models: This section describes the logical and physical structure of the software system, using diagrams, such as data flow diagrams, entity-relationship diagrams, state transition diagrams, etc.
  - System Specifications: This section describes the technical specifications of the software system, such as hardware, software, network, database, etc.
  - Appendices: This section provides any additional or supplementary information, such as glossary, acronyms, abbreviations, etc.
