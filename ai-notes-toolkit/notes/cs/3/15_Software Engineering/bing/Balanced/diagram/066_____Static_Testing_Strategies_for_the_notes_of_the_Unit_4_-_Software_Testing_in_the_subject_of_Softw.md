### Static Testing Strategies

Static testing is a software testing technique that examines a software application and its associated documents without executing the code. Static testing can help to find and eliminate errors or ambiguities in the software requirements, design, test cases, etc. Static testing can also improve the quality and efficiency of software development by detecting defects early in the development cycle.

Static testing can be done in two ways: review and static analysis.

- Review: A review is a process of checking the software documents for possible defects by a team of reviewers. The reviewers can be the developers, testers, managers, customers, or other stakeholders. The review can be formal, informal, walkthrough, inspection, or peer review, depending on the level of formality and rigor required. The review process typically involves the following steps:

  - Planning: The review objectives, scope, roles, and schedule are defined and agreed upon by the review team.
  - Preparation: The reviewers study the documents to be reviewed and identify the potential issues or questions.
  - Meeting: The review team meets to discuss the findings and reach a consensus on the defects and actions to be taken.
  - Reporting: The review results, such as the defects, recommendations, and metrics, are documented and communicated to the relevant stakeholders.
  - Follow-up: The review team verifies that the agreed actions have been implemented and the defects have been resolved.

- Static analysis: Static analysis is a process of analyzing the software code or design using tools or techniques that do not require the code to be executed. Static analysis can help to find syntax errors, logical errors, coding standards violations, security vulnerabilities, performance issues, etc. Static analysis can be done manually or automatically using various tools, such as compilers, code analyzers, code metrics tools, etc. The static analysis process typically involves the following steps:

  - Selection: The static analysis tools or techniques are selected based on the software characteristics, objectives, and requirements.
  - Configuration: The static analysis tools or techniques are configured to suit the software context, such as the programming language, coding standards, rules, etc.
  - Execution: The static analysis tools or techniques are applied to the software code or design and the results are generated.
  - Analysis: The static analysis results, such as the defects, warnings, suggestions, and metrics, are analyzed and interpreted by the software team.
  - Reporting: The static analysis results are documented and communicated to the relevant stakeholders.
  - Follow-up: The static analysis results are used to improve the software quality by fixing the defects, refactoring the code, optimizing the design, etc.
