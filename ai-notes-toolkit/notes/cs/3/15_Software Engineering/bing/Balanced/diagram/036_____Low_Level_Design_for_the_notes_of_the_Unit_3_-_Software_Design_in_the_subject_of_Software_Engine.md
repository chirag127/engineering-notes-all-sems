Low level design (LLD) is a component-level design process that follows a step-by-step refinement process. It involves specifying the individual modules, data structures, algorithms, interfaces, and inputs/outputs of a system. It describes every module in detail by incorporating the logic behind every component in the system. It delves deep into every specification of every system, providing a micro-level design.

Some of the topics that are covered in low level design are:

- Object-oriented principles: The user requirement is processed by using concepts of OOPS programming, such as abstraction, encapsulation, inheritance, and polymorphism.
- Process of analyzing and design: It is the first step where the real-world problems are identified and modeled using UML diagrams, such as use case diagrams, class diagrams, sequence diagrams, etc.
- Design patterns: They are reusable solutions to common software design problems, such as creational, structural, and behavioral patterns.
- Coding standards and guidelines: They are rules and conventions that help to write consistent, readable, and maintainable code, such as naming conventions, indentation, comments, etc.
- Testing and debugging: They are techniques and tools that help to verify the correctness, quality, and performance of the software, such as unit testing, integration testing, code coverage, debugging tools, etc.
