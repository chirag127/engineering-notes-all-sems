# Error Detection and Correction in Link Layer

- Error detection and correction in link layer is the process of identifying and re-transmitting data frames that have been corrupted or lost during transmission  .
- Error detection and correction techniques are essential for reliable and efficient data communication over noisy channels.
- Errors can occur due to various reasons, such as noise, interference, distortion, attenuation, crosstalk, etc.
- Errors can be classified into three types, namely single bit errors, multiple bit errors, and burst errors.
  - Single bit errors occur when only one bit in a data frame is changed from 0 to 1 or vice versa.
  - Multiple bit errors occur when two or more bits in a data frame are changed from 0 to 1 or vice versa.
  - Burst errors occur when a sequence of consecutive bits in a data frame are changed from 0 to 1 or vice versa.
- Error detection and correction techniques can be broadly divided into two categories, namely forward error correction (FEC) and backward error correction (BEC).
  - Forward error correction (FEC) is a technique where the sender adds some redundant bits to the data frame before transmission, which can be used by the receiver to detect and correct errors without requesting re-transmission.
  - Backward error correction (BEC) is a technique where the sender does not add any redundant bits to the data frame, but the receiver detects errors using some methods and requests re-transmission of the corrupted or lost frames.
- Some of the common error detection and correction methods are parity checks, checksums, cyclic redundancy check (CRC), hamming code, etc .
  - Parity checks are the simplest form of error detection, where the sender adds a single bit (called parity bit) to the data frame, such that the number of 1s in the frame is even (even parity) or odd (odd parity). The receiver checks the parity bit and detects a single bit error if the parity does not match. Parity checks cannot detect multiple bit errors or burst errors.
  - Checksums are a form of error detection, where the sender divides the data frame into equal segments of n bits (usually 8 or 16 bits) and adds them using one's complement arithmetic to get a sum (called checksum). The sender appends the checksum to the data frame and transmits it. The receiver performs the same operation on the received frame and compares the checksum with the appended one. If they do not match, an error is detected. Checksums can detect multiple bit errors, but not burst errors.
  - Cyclic redundancy check (CRC) is a form of error detection, where the sender treats the data frame as a polynomial and divides it by a fixed divisor (called generator polynomial) using binary arithmetic to get a remainder (called CRC). The sender appends the CRC to the data frame and transmits it. The receiver performs the same operation on the received frame and compares the CRC with the appended one. If they do not match, an error is detected. CRC can detect single bit errors, multiple bit errors, and burst errors up to a certain length.
  - Hamming code is a form of error detection and correction, where the sender adds some extra bits (called hamming bits) to the data frame, such that the position of each hamming bit is a power of 2 and the value of each hamming bit is determined by the parity of some subset of bits in the frame. The receiver checks the hamming bits and calculates a syndrome (a binary number indicating the position of the error). If the syndrome is zero, no error is detected. If the syndrome is non-zero, a single bit error is detected and corrected by flipping the bit at that position. Hamming code can detect and correct single bit errors, but not multiple bit errors or burst errors.
