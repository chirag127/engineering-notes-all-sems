### Framing
- Framing is the process of dividing a stream of bits into smaller units called frames for transmission over a link layer.
- Frames are delimited by special bit patterns called flags or headers and trailers that indicate the start and end of a frame.
- There are different methods of framing, such as character count, byte stuffing, bit stuffing, and physical layer coding violations.
- Character count: A frame consists of a fixed number of characters, and the first character indicates the length of the frame. This method is simple but unreliable, as any error in the count or the data can cause the receiver to lose synchronization with the sender.
- Byte stuffing: A frame consists of a flag byte at the beginning and end of the frame, and any occurrence of the flag byte in the data is replaced by an escape byte followed by a modified flag byte. This method is more reliable than character count, but it increases the overhead and complexity of the framing process.
- Bit stuffing: A frame consists of a flag bit pattern at the beginning and end of the frame, and any occurrence of five consecutive 1s in the data is followed by a 0. This method is more efficient than byte stuffing, as it avoids the need for an escape byte and reduces the overhead. However, it requires the sender and receiver to operate at the same bit rate and clock synchronization.
- Physical layer coding violations: A frame consists of a flag bit pattern at the beginning and end of the frame, and any occurrence of the flag bit pattern in the data is replaced by a violation of the physical layer encoding scheme. For example, in Manchester encoding, a 0 is represented by a high-to-low transition and a 1 by a low-to-high transition, so a violation would be a low-to-low or high-to-high transition. This method is more robust than bit stuffing, as it does not depend on the bit rate or clock synchronization, and it does not increase the overhead. However, it requires the sender and receiver to use the same physical layer encoding scheme.
