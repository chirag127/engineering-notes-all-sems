### Domain Name System

- The Domain Name System (DNS) is a method for mapping alphabetic names to numeric IP addresses on the Internet, similar to how a phone book maps a person's name to a phone number.
- DNS is a hierarchical and decentralized naming system that allows computers, servers, services, resources, network devices and components to be identified and located on large networks such as the public Internet .
- A network domain is an administrative grouping of multiple private computer networks or local hosts within the same infrastructure. Domains can be identified using a domain name; domains which need to be accessible from the public Internet can be assigned a globally unique name within the Domain Name System (DNS).
- A domain name consists of one or more labels, each separated by a dot. The right-most label is the top-level domain (TLD), such as .com, .org, .net, etc. The second-level domain (SLD) is the label to the left of the TLD, such as google, amazon, wikipedia, etc. The third-level domain (or subdomain) is the label to the left of the SLD, such as mail, www, blog, etc. The labels can be up to 63 characters long and can contain letters, digits, hyphens, and underscores.
- Domain names can be internationalized using the Internationalized Domain Name (IDN) system, which allows the use of non-ASCII characters such as accented letters, symbols, or scripts. IDNs are encoded using the Punycode algorithm, which converts them to ASCII labels that start with xn--. For example, the IDN for café.com is xn--caf-dma.com.
- Name servers are the servers that store and provide the DNS records for a domain name. A DNS record is a data structure that maps a domain name to an IP address or other information, such as mail servers, name servers, or text records. There are different types of DNS records, such as A, AAAA, CNAME, MX, NS, TXT, etc.
- An authoritative name server is a name server that has the original and definitive DNS records for a domain name. It is the ultimate source of truth for resolving a domain name. An authoritative name server can be either primary or secondary, depending on whether it obtains the DNS records from a master file or from another authoritative name server.
- The DNS resolution process is the mechanism by which a domain name is translated to an IP address. It involves a series of queries and responses between a DNS client (or resolver) and one or more DNS servers. The DNS resolution process can be either iterative or recursive, depending on how the queries are handled by the DNS servers.
- A recursive and caching name server is a type of DNS server that performs the entire DNS resolution process on behalf of the DNS client. It queries other DNS servers until it finds the authoritative name server for the domain name, and then returns the IP address to the DNS client. It also caches the DNS records for a period of time, to reduce the number of queries and improve the performance.
- A DNS resolver is a software component that initiates and handles the DNS resolution process for a DNS client. It can be either a stub resolver or a full resolver, depending on the level of functionality it provides. A stub resolver is a simple resolver that only queries a recursive and caching name server, and relies on it to perform the entire DNS resolution process. A full resolver is a complex resolver that can perform the DNS resolution process by itself, by querying multiple DNS servers iteratively or recursively.
- Circular dependencies and glue records are special cases that arise when the name servers for a domain name are also under the same domain name. For example, if the name servers for example.com are ns1.example.com and ns2.example.com, then there is a circular dependency, because to resolve example.com, one needs to know the IP addresses of ns1.example.com and ns2.example.com, but to resolve ns1.example.com and ns2.example.com, one needs to know the IP address of example.com. To break this cycle, glue records are used, which are additional DNS records that provide the IP addresses of the name servers for a domain name, and are stored in the parent domain's name servers. For example, the glue records for example.com are stored in the name servers for .com.
