### Sliding Window Protocols

Sliding window protocols are data link layer protocols for reliable and sequential delivery of data frames. They are also used in the Transmission Control Protocol (TCP) for flow control and congestion control. The sliding window technique allows the sender to send multiple frames at a time before receiving any acknowledgment from the receiver. The receiver uses the sequence number of each frame to detect any missing or duplicate frames and to reorder them if necessary. The sender and the receiver maintain a window of frames that indicates which frames are expected to be sent or received next. The window size is determined by the available buffer space and the bandwidth-delay product of the channel. The window slides forward as new frames are sent or received, and the sender can adjust the window size dynamically to adapt to the network conditions.

There are two main types of sliding window protocols: go-back-N and selective repeat. In go-back-N, the sender can send up to N frames without waiting for acknowledgments, where N is the window size. The receiver only sends a cumulative acknowledgment for the last correctly received frame in sequence. If the sender does not receive an acknowledgment for a frame within a timeout period, it assumes that the frame or the acknowledgment was lost, and it retransmits all the frames from that point onward. This protocol is simple but inefficient, as it may retransmit frames that the receiver has already received.

In selective repeat, the sender can send up to N frames without waiting for acknowledgments, where N is the window size. The receiver sends a selective acknowledgment for each correctly received frame, regardless of the sequence. If the sender does not receive an acknowledgment for a frame within a timeout period, it only retransmits that frame. This protocol is more efficient but more complex, as it requires the receiver to buffer out-of-order frames and the sender to keep track of individual acknowledgments.
