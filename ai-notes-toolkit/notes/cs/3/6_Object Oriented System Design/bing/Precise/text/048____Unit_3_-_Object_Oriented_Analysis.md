## Unit 3 - Object Oriented Analysis

Object-oriented analysis (OOA) is a process of analyzing software engineering requirements and developing software specifications in terms of a software system's object model, which comprises interacting objects.

1. **Object-oriented analysis** is the process of examining the problem domain to identify the objects and their interactions.
2. The goal of OOA is to model the real-world objects and their relationships in a way that can be easily translated into a software design.
3. OOA is typically performed as the first step in the object-oriented design (OOD) process.
4. OOA involves identifying the objects, their attributes, and their behaviors.
5. The objects are typically modeled using class diagrams, which show the attributes and methods of each class, as well as the relationships between classes.
6. OOA also involves identifying the use cases, which describe the interactions between the objects and the system.
7. Use case diagrams are used to model the use cases and their relationships with the actors (users or external systems) that interact with the system.
8. OOA is an iterative process, where the model is refined and updated as new information is discovered.
