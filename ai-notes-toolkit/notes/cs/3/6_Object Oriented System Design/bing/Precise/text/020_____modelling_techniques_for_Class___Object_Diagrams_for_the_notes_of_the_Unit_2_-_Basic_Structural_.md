### Modelling Techniques for Class & Object Diagrams

Unit 2 - Basic Structural Modeling in the subject of Object Oriented System Design

1. **Class Diagrams**: Class diagrams are used to represent the static structure of a system by showing its classes, attributes, operations, and relationships between objects.
2. **Object Diagrams**: Object diagrams are used to represent the static structure of a system at a particular moment in time. They show the objects in the system, their attributes, and the relationships between them.
3. **Use of Symbols**: In both class and object diagrams, symbols are used to represent the different elements. For example, a rectangle is used to represent a class, while an ellipse is used to represent an object.
4. **Use of Lines**: Lines are used to represent the relationships between the different elements in the diagram. For example, a solid line with an arrowhead is used to represent a generalization relationship, while a dashed line with an arrowhead is used to represent a dependency relationship.
5. **Use of Multiplicity**: Multiplicity is used to represent the number of instances of a class that can be associated with another class. For example, a multiplicity of 1..* indicates that one or more instances of a class can be associated with another class.
6. **Use of Aggregation and Composition**: Aggregation and composition are used to represent the relationship between a whole and its parts. Aggregation is represented by a diamond shape on the end of the line connecting the whole to its part, while composition is represented by a filled diamond shape.
7. **Use of Abstract Classes and Interfaces**: Abstract classes and interfaces are used to represent the common behavior of a set of classes. Abstract classes are represented by italicized class names, while interfaces are represented by a circle with the letter "I" inside.
