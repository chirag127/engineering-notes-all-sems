
### Activity Diagrams for the Notes of Unit 2 - Basic Structural Modeling in the Subject of Object Oriented System Design

1. Activity diagrams are used to model the behavior of a system. They are used to describe the flow of activities within a system and to illustrate how different activities are related to each other.

2. Activity diagrams are composed of activities, decisions, and transitions. Activities represent the actions that occur in a system, decisions represent the points at which a decision must be made, and transitions represent the flow of control from one activity to the next.

3. Activity diagrams can be used to represent a variety of different types of systems, including object-oriented systems, distributed systems, and concurrent systems.

4. Activity diagrams can also be used to model the behavior of a single object. In this case, the arrows represent the messages that the object sends and receives.

5. Activity diagrams can be used to model the workflow of a system. In this case, the arrows represent the flow of control from one activity to another.

6. Activity diagrams can also be used to model the behavior of a system over time. In this case, the arrows represent the temporal relationships between activities.

7. Activity diagrams can also be used to model the behavior of a system in response to external events. In this case, the arrows represent the flow of control from the external event to the activities that it triggers.
