### Procedural v/s OOP

In the study of Object Oriented Analysis, it is important to understand the difference between procedural programming and object-oriented programming.

#### Procedural Programming

Procedural programming is a programming paradigm that uses a linear approach to solving problems. It involves breaking down a problem into smaller sub-problems and solving them one at a time. The main focus is on functions or procedures that take inputs, process them, and produce outputs. 

##### Characteristics of Procedural Programming

- It is based on the concept of procedures or functions.
- The data is exposed to the entire program.
- The program is divided into smaller subroutines.
- It is a top-down approach to problem-solving.
- It is less secure as data can be accessed from anywhere in the program.

#### Object-Oriented Programming

Object-Oriented Programming (OOP) is a programming paradigm that uses objects to represent real-world entities. It is based on the concept of classes and objects. A class is a blueprint for creating objects, and an object is an instance of a class. 

##### Characteristics of OOP

- It is based on the concept of classes and objects.
- Data is encapsulated inside an object, making it more secure.
- It follows a bottom-up approach to problem-solving.
- It is more modular, making it easier to maintain and reuse code.
- It is more adaptable to changes in requirements.

#### Differences between Procedural and OOP

- Procedural programming is based on procedures or functions, whereas OOP is based on classes and objects.
- In procedural programming, data is exposed to the entire program, whereas in OOP, data is encapsulated inside objects, making it more secure.
- Procedural programming is a top-down approach to problem-solving, whereas OOP is a bottom-up approach.
- OOP is more modular and adaptable to changes in requirements, making it easier to maintain and reuse code.

In conclusion, while both procedural programming and OOP have their benefits, OOP is generally considered to be the better approach for developing complex software systems. It offers greater security, modularity, and adaptability to changes in requirements.
