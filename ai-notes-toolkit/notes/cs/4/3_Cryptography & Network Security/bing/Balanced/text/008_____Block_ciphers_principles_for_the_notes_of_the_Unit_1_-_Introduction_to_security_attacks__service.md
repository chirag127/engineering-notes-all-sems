### Block ciphers principles

- A block cipher is a symmetric encryption algorithm that operates on a fixed-length group of bits, called a block, with an unvarying transformation that is specified by a symmetric key.
- Block ciphers are widely used to encrypt data in bulk, such as files, messages, or network traffic.
- Block ciphers can be classified into two main types: substitution-permutation networks (SPNs) and Feistel networks.
- Substitution-permutation networks (SPNs) are block ciphers that consist of a series of rounds, each of which performs a substitution on the block using a round key derived from the main key, followed by a permutation that rearranges the bits of the block. An example of an SPN is the Advanced Encryption Standard (AES).
- Feistel networks are block ciphers that split the block into two halves and apply a round function to one half using a round key derived from the main key, then XOR the output with the other half, and swap the halves. This process is repeated for a number of rounds. An example of a Feistel network is the Data Encryption Standard (DES).
- Block ciphers are designed to achieve two main properties: confusion and diffusion. Confusion means that the relationship between the key and the ciphertext is complex and obscure, making it hard to deduce the key given the ciphertext. Diffusion means that a small change in the plaintext or the key affects many bits of the ciphertext, making it hard to find patterns or correlations in the ciphertext.
- Block ciphers can be used in different modes of operation, depending on the application and the security requirements. Some common modes of operation are:
  - Electronic Codebook (ECB): Each block of plaintext is encrypted independently with the same key. This mode is simple and fast, but insecure, as identical blocks of plaintext produce identical blocks of ciphertext, revealing patterns and repetitions in the data.
  - Cipher Block Chaining (CBC): Each block of plaintext is XORed with the previous block of ciphertext before being encrypted with the same key. This mode introduces randomness and dependency among the blocks, making it more secure than ECB, but also more vulnerable to errors and tampering, as a single bit error in a ciphertext block affects the decryption of all subsequent blocks.
  - Cipher Feedback (CFB): The ciphertext is generated by XORing the plaintext with the output of encrypting an initialization vector (IV) with the key. The IV is then updated with the ciphertext for the next block. This mode converts a block cipher into a stream cipher, making it suitable for encrypting data of arbitrary length, but also more susceptible to noise and plaintext attacks, as a single bit error in the ciphertext affects the decryption of the current and the next block.
  - Output Feedback (OFB): The ciphertext is generated by XORing the plaintext with the output of encrypting an IV with the key. The IV is then updated with the output for the next block. This mode also converts a block cipher into a stream cipher, but unlike CFB, it is immune to noise and plaintext attacks, as a single bit error in the ciphertext only affects the decryption of the current block.
  - Counter (CTR): The ciphertext is generated by XORing the plaintext with the output of encrypting a counter with the key. The counter is incremented for each block. This mode also converts a block cipher into a stream cipher, and has the same advantages as OFB, but also allows for parallel encryption and decryption, as each block is independent of the others.
