### Block ciphers principles

- A block cipher is a symmetric-key encryption algorithm that operates on fixed-length blocks of plaintext and ciphertext.
- A block cipher consists of two functions: an encryption function E and a decryption function D, such that D(E(P, K), K) = P, where P is the plaintext block, K is the secret key, and C is the ciphertext block.
- A block cipher can be characterized by its block size, key size, and number of rounds. The block size determines how much data can be encrypted or decrypted at a time. The key size determines the security level of the cipher. The number of rounds determines how complex the encryption or decryption process is.
- A block cipher can be designed using different principles, such as substitution, permutation, or a combination of both. Substitution replaces each element of the plaintext block with another element, according to a mapping determined by the key. Permutation rearranges the elements of the plaintext block, according to a pattern determined by the key.
- Shannon's theory of confusion and diffusion states that a good block cipher should achieve two properties: confusion and diffusion. Confusion means that the relationship between the plaintext and the ciphertext should be complex and obscure, so that an attacker cannot deduce the key from statistical analysis. Diffusion means that each element of the ciphertext should depend on every element of the plaintext, so that a small change in the plaintext results in a large change in the ciphertext, and vice versa.
- A common way to design a block cipher is to use a fiestal structure, which consists of multiple rounds of encryption or decryption, each involving a subkey derived from the main key, and a round function that applies substitution and permutation to the input block. A fiestal structure can be classified into two types: balanced and unbalanced. A balanced fiestal structure splits the input block into two equal halves, and applies the round function to one half, while XORing the other half with the output. An unbalanced fiestal structure splits the input block into two unequal parts, and applies the round function to the smaller part, while XORing the larger part with the output.
- A well-known example of a block cipher that uses a balanced fiestal structure is the Data Encryption Standard (DES), which was developed in the 1970s and standardized by NIST in 1977. DES has a block size of 64 bits, a key size of 56 bits, and 16 rounds of encryption or decryption. DES is considered insecure today, due to its small key size and the advances in cryptanalysis techniques, such as differential cryptanalysis and linear cryptanalysis, that can break it with less than brute-force effort.
- A variant of DES that improves its security is the Triple DES (3DES), which applies DES three times with either two or three different keys. 3DES has a block size of 64 bits, a key size of either 112 or 168 bits, and 48 rounds of encryption or decryption. 3DES is still widely used today, although it is slower than newer block ciphers, such as AES.
- A block cipher can be used in different modes of operation, depending on the application and the security requirements. The most common modes of operation are:

  - Electronic Codebook (ECB): This mode encrypts or decrypts each block of plaintext or ciphertext independently, using the same key. This mode is simple and fast, but insecure, as it does not provide any confidentiality or integrity protection, and reveals patterns in the data.
  - Cipher Block Chaining (CBC): This mode encrypts or decrypts each block of plaintext or ciphertext by XORing it with the previous ciphertext block or the initialization vector (IV), using the same key. This mode provides confidentiality, but not integrity, and requires padding to handle messages that are not multiples of the block size.
  - Cipher Feedback (CFB): This mode encrypts or decrypts each byte or bit of plaintext or ciphertext by XORing it with a segment of the previous ciphertext block or the IV, using the same key. This mode provides confidentiality, but not integrity, and does not require padding, as it can handle messages of any length.
  - Output Feedback (OFB): This mode encrypts or decrypts each byte or bit of plaintext or ciphertext by XORing it with a segment of the output of the encryption function applied to the previous output block or the IV, using the same key. This mode provides confidentiality, but not integrity, and does not require padding, as it can handle messages of any length.
