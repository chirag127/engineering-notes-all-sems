## Unit 3 - Structural Testing

Structural testing is a type of software testing that focuses on the internal structure of the software. It involves testing individual components or modules of the software to ensure that they function correctly and work together as expected. Here are some important points to keep in mind when it comes to structural testing:

- **Code coverage**: One of the main goals of structural testing is to achieve high code coverage. This means that all parts of the code have been executed during testing. There are various techniques for measuring code coverage, such as statement coverage, branch coverage, and path coverage.

- **White-box testing**: Structural testing is also known as white-box testing because it requires knowledge of the internal workings of the software. Testers need to have access to the source code in order to perform this type of testing effectively.

- **Unit testing**: Structural testing often involves unit testing, which is the process of testing individual units or components of the software in isolation. This allows developers to identify and fix issues early on in the development process.

- **Integration testing**: In addition to unit testing, structural testing also includes integration testing. This involves testing how different components of the software work together as a whole. Integration testing can help identify issues that may not be apparent during unit testing.

- **Boundary value analysis**: Structural testing often involves boundary value analysis, which is the process of testing inputs that are at the boundaries of acceptable values. For example, if a function accepts values between 0 and 10, boundary value analysis would involve testing inputs of 0, 10, and values just below and above those boundaries.

- **Mutation testing**: Mutation testing is a technique used in structural testing to measure the effectiveness of the test suite. It involves making small changes to the code (known as mutations) and running the test suite to see if it detects the changes. If the test suite does not detect the changes, it may indicate that the test suite is not comprehensive enough.

Overall, structural testing is an important part of the software development process. By testing the internal structure of the software, developers can ensure that it functions correctly and meets the requirements of the end user.
