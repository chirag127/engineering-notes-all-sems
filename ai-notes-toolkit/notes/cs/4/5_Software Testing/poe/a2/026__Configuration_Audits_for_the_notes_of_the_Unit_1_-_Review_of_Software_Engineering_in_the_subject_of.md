### Configuration Audits for the notes of the Unit 1 - Review of Software Engineering in the subject of Software Testing

1. Configuration audits are conducted to verify that the software configuration items (SCIs) that make up a software product are correct and consistent.
2. The key inputs to a configuration audit are the configuration identification documentation and the actual SCIs for the product.
3. The auditor reviews the configuration identification documentation to verify that it is complete and consistent. All SCIs should be identified and properly tracked in the configuration management system.
4. The auditor then verifies that the actual SCIs that make up the product match what is identified in the configuration identification documentation.
5. Any discrepancies or in consistencies are noted in a report produced by the auditor at the end of the configuration audit.
6. Corrective actions to address any issues noted in the configuration audit report are tracked through the normal change management process.
7. Frequent configuration audits, especially for highly complex or mission-critical software products, help to minimize the risk of unknown or undocumented changes making their way into a released software product.
