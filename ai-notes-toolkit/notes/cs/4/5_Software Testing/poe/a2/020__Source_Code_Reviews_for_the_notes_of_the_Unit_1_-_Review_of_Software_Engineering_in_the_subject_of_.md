### Source Code Reviews for the notes of the Unit 1 - Review of Software Engineering in the subject of Software Testing.

1. Code review is a systematic examination of computer source code. It is intended to find and fix mistakes overlooked in the initial development phase, improving both the overall quality of software and the developers' skills.

2. Some of the benefits of code review are:
- Finding bugs early and fixing them in time saving cost and effort.
- Improving the quality of code and making it more robust and optimized.
- Sharing knowledge among team members leading to better design and coding practices.
- Training and mentoring of new team members.

3. The steps involved in a code review process are:
- Planning: Deciding the objectives and scope of review, assigning roles and responsibilities.
- Overview: Having a quick look at the changes made for high-level understanding.
- Preparation: Reviewers examine the code in detail, look for bugs or areas of improvement and document the findings.
- Meeting: The author explains the code and rationale behind design decisions, reviewers discuss their findings and suggestions, and necessary changes are agreed upon.
- Rework: The author implements the changes and fixes agreed in the review meeting.
- Follow-up: Once rework is done, reviewers verify whether the changes were done properly. If everything is fine, the review is closed.

4. Some tips for an effective code review:
- Review code in small chunks to minimize context switching.
- Focus on high impact areas and major changes.
- Provide concrete and actionable feedback.
- Discuss differences in opinions respectfully.
- Ensure the author understands and agrees to the feedback.
- Track review metrics to monitor effectiveness.
