### Regression Test cases selection for the notes of the Unit 4 - Regression Testing in the subject of Software Testing.

1. Select test cases that have been identified as critical or high priority in previous testing efforts. These test cases are more likely to detect regression errors.
2. Select test cases that exercise core functionality or commonly used features. These portions of the system are more likely to be affected by changes.
3. Select test cases that have uncovered bugs in the past. These test cases are more likely to detect if a previous bug has recurred.
4. Select test cases that are impacted by the changes made to the system. The changes may affect specific areas of functionality, so test cases that exercise these areas should be included.
5. If insufficient time exists to rerun all test cases, sample test cases from across the system to increase coverage, including both positive and negative test cases. A mix of both types increases the likelihood of detecting regression errors.
6. Use risk analysis or failure mode and effects analysis results to focus on high-risk areas of the system. These high-risk or high-impact areas are good candidates for regression test cases.
7. If tester experience or product/system knowledge is limited, start with a small number of test cases and expand the test suite over time as coverage needs and knowledge increase.
8. Automate regression test cases when possible to make repeated testing more efficient. This is especially useful for test cases that will be run many times, such as after each build.
