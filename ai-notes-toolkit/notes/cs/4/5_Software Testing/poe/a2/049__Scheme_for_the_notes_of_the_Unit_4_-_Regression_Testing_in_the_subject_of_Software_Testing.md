### Scheme for the notes of the Unit 4 - Regression Testing in the subject of Software Testing.

1. Introduction to Regression Testing
- Definition: Testing the software again after modification to ensure that the previous functionality is still working fine and has not been affected by the changes.
- Importance: To ensure that the new changes have not impacted the existing functionality.
- Types: Retest all and incremental regression testing.

2. Techniques for Regression Testing
- Retest-all - Run all tests again.
- Regression test selection - Select and run only a subset of tests based on change impact analysis, code coverage data or operational profiles.
- Prioritization - Priority-order test case execution.

3. Automation of Regression Testing
- Recording and replaying techniques.
- Regression test suites and frameworks.
- Commercial tools for regression testing.
- Limitations of automation.

4. Best practices for Regression Testing
- Prepare a checklist of test cases to be included for regression testing.
- Automate the regression tests to the maximum extent possible.
- Execute regression tests regularly as per the project plan after changes.
- Track the defect leakage from regression tests and analyze the root causes.
- Review and refine the regression test suite as per the needs.
