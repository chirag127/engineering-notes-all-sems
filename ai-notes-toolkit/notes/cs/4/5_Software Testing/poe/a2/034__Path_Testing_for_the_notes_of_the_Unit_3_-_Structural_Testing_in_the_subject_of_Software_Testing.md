### Path Testing for the notes of the Unit 3 - Structural Testing in the subject of Software Testing

1. Path Testing is a White Box Testing technique that focuses on exercising different paths through the code.
2. The main goal of path testing is to exercise control flow of the code and test as many paths as possible through the code based on predefined inputs.
3. The three main types of path testing are:
- Basis Path Testing: Exercising the essential/basic paths through the code.
- Branch Testing: Exercising each decision point/branch in the code.
- Statement Coverage: Ensuring that each statement in the code is executed at least once.
4. Advantages:
- Identification of unimplemented paths/dead code.
- Increased test coverage.
- Increased defect detection.
5. Disadvantages:
- Difficult to identify all paths for complex control flows.
- Testing all paths might not be feasible due to time and cost constraints.
6. Path testing can be used to supplement other structural testing techniques to increase code coverage and defect detection. It is a form of white box testing and increases confidence in the correctness of the code.
