# Test Cases for the notes of the Unit 1 - Review of Software Engineering in the subject of Software Testing

- A test case is a set of actions executed to verify a particular feature or functionality of a software application.
- A test case contains test steps, test data, precondition, postcondition developed for specific test scenario to verify any requirement.
- The goal of test cases in software testing is to check behavior of the application under test (AUT) for an expected result.
- Test cases in software testing can be written using various formats and techniques, such as IEEE 829, boundary value analysis, equivalence partitioning, etc.
- Test cases in software testing should be clear, concise, complete, consistent, traceable, and maintainable.
- Test cases in software testing should be reviewed by another test engineer, known as a reviewer, for quality assurance.
- Test case review is a critical step in software testing, as it ensures that every functionality listed in the Software Requirement Specification is addressed by the test case.
- Test case review also helps to find defects, errors, and inconsistencies in the test cases, and to improve their coverage, effectiveness, and efficiency.
- Test case review can be done using various methods, such as peer review, walkthrough, inspection, etc.
- Test case review should follow some guidelines, such as defining the scope, objectives, and criteria of the review, selecting the appropriate reviewers, preparing the review checklist, conducting the review meeting, documenting the review findings, and implementing the review feedback.
- Test case review should be done before test execution, and the test cases should be updated and re-reviewed after any changes in the requirements or the application.
- Test case review is an important part of software engineering, as it helps to ensure the quality, reliability, and usability of the software product.
