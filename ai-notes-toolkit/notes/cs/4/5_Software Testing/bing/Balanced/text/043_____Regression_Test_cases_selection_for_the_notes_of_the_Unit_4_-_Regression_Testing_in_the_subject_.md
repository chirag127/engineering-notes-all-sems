### Regression Test cases selection

- Regression testing is the process of retesting the modified parts of a software system and the parts that might be affected by the modifications to ensure that no new defects have been introduced.
- Regression test cases are the test cases that are selected for regression testing based on some criteria or strategies.
- Regression test cases selection is an important activity in regression testing as it can affect the effectiveness and efficiency of the testing process.
- Some of the factors that influence the regression test cases selection are:
  - The scope and impact of the software changes
  - The availability and quality of the test cases
  - The test coverage and fault detection capability of the test cases
  - The time and resources constraints for regression testing
  - The test execution and maintenance costs of the test cases
- Some of the common strategies for regression test cases selection are:
  - Retest all: This strategy involves retesting all the existing test cases in the test suite regardless of the software changes. This strategy ensures high test coverage and fault detection capability, but it is also very expensive and time-consuming.
  - Retest modified: This strategy involves retesting only the test cases that are directly affected by the software changes. This strategy reduces the test execution and maintenance costs, but it may also miss some faults that are indirectly affected by the software changes.
  - Retest modified and related: This strategy involves retesting the test cases that are directly or indirectly affected by the software changes. This strategy balances the test coverage and fault detection capability with the test execution and maintenance costs, but it requires a good understanding of the software dependencies and traceability between the test cases and the software components.
  - Retest prioritized: This strategy involves retesting the test cases that are prioritized based on some criteria such as the severity and frequency of the faults, the importance and complexity of the software features, the risk and reliability of the software components, etc. This strategy aims to maximize the fault detection capability within the time and resources constraints, but it may also compromise the test coverage and miss some low-priority faults.
