### Test Data for the notes of the Unit 5 - Software Testing Activities in the subject of Software Testing

- Test data is the input data that is used to test the functionality, performance, reliability, and security of a software system or component.
- Test data can be generated manually, automatically, or semi-automatically, depending on the testing objectives, methods, and tools.
- Test data should be valid, realistic, representative, and sufficient to cover all the test cases and scenarios.
- Test data should also be traceable, reusable, maintainable, and secure.
- Test data generation techniques include:
  - Equivalence partitioning: dividing the input domain into equivalent classes based on the expected output or behavior of the system.
  - Boundary value analysis: selecting the values at the boundaries or edges of the input domain, such as minimum, maximum, or invalid values.
  - Pairwise testing: selecting the combinations of two input values that cover all the possible pairs of values in the input domain.
  - Orthogonal array testing: selecting the combinations of input values that cover all the possible interactions of values in the input domain, using a mathematical technique called orthogonal arrays.
  - Random testing: selecting the input values randomly from the input domain, using a random number generator or a tool.
  - Model-based testing: generating the input values based on a model of the system or its behavior, such as a state machine, a flowchart, or a specification.
  - Data-driven testing: generating the input values based on the data sources, such as databases, files, or web services.
  - Keyword-driven testing: generating the input values based on the keywords or commands that describe the test actions or steps.
- Test data management is the process of planning, designing, creating, storing, accessing, modifying, and deleting the test data throughout the testing lifecycle.
- Test data management activities include:
  - Test data planning: defining the test data requirements, objectives, scope, and strategy.
  - Test data design: designing the test data structure, format, and content, based on the test data requirements and the test design specifications.
  - Test data creation: creating the test data, using the test data generation techniques and tools, or obtaining the test data from the production or other sources.
  - Test data storage: storing the test data in a test data repository, such as a database, a file system, or a cloud service, and ensuring the test data availability, integrity, and security.
  - Test data access: accessing the test data from the test data repository, using the test data tools, or the test execution tools, and ensuring the test data quality, consistency, and compatibility.
  - Test data modification: modifying the test data, as needed, to reflect the changes in the test requirements, the test design, or the system under test, and ensuring the test data traceability, reusability, and maintainability.
  - Test data deletion: deleting the test data, when it is no longer needed, or when it is obsolete, redundant, or invalid, and ensuring the test data compliance, privacy, and security.
