#### How does HDFS store

HDFS stands for Hadoop Distributed File System. It is a distributed file system that stores large amounts of data across multiple nodes in a cluster. HDFS follows a master-slave architecture, where one node acts as the NameNode (master) and the rest of the nodes act as DataNodes (slaves).

The NameNode is responsible for managing the namespace, the metadata, and the access control of the files and directories in HDFS. It also coordinates the replication and the placement of the data blocks among the DataNodes. The NameNode does not store the actual data, but only the information about the data, such as the file name, the size, the permissions, the locations of the blocks, etc. The NameNode keeps this information in memory and also persists it on disk for recovery purposes.

The DataNodes are responsible for storing the actual data in HDFS. The data is divided into fixed-size blocks (typically 128 MB) and each block is replicated across multiple DataNodes for fault tolerance and availability. The default replication factor is 3, which means that each block has 3 copies on different DataNodes. The DataNodes periodically send heartbeat and block report messages to the NameNode to report their status and the blocks they store. The DataNodes also perform local checksum verification and block recovery when needed.

When a client wants to read or write a file in HDFS, it first contacts the NameNode to get the metadata and the locations of the blocks. Then, it directly communicates with the DataNodes that store the blocks to perform the actual data transfer. The client can also cache the block locations to avoid contacting the NameNode for every read or write operation. The client also follows the HDFS write pipeline, where it writes the data to the first DataNode in the pipeline, which then forwards the data to the next DataNode, and so on, until all the replicas are written. The client also receives acknowledgments from the DataNodes to ensure the data integrity and reliability.
