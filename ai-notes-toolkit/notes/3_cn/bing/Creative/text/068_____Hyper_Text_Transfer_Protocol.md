### Hyper Text Transfer Protocol

- Hyper Text Transfer Protocol (HTTP) is a protocol that defines how web browsers and web servers communicate and exchange data over the internet.
- HTTP is based on a request-response model, where a client (such as a browser) sends a request to a server (such as a web server) and the server responds with a status code, headers, and optionally a body.
- HTTP requests and responses can contain different types of data, such as text, images, audio, video, etc. The data is formatted using a standard syntax called Hyper Text Markup Language (HTML), which can include links to other resources (such as stylesheets, scripts, or other web pages).
- HTTP uses a uniform resource identifier (URI) to identify and locate a resource on the web. A URI consists of a scheme (such as http or https), a host (such as www.example.com), a port (such as 80 or 443), a path (such as /index.html), and optionally a query (such as ?q=hello) and a fragment (such as #section1).
- HTTP supports different methods (also called verbs) to perform different actions on a resource. The most common methods are GET, POST, PUT, DELETE, HEAD, and OPTIONS. Each method has a specific meaning and semantics, such as retrieving, creating, updating, deleting, or obtaining information about a resource.
- HTTP also supports different status codes to indicate the outcome of a request. The status codes are grouped into five categories: 1xx (informational), 2xx (success), 3xx (redirection), 4xx (client error), and 5xx (server error). Some of the most common status codes are 200 (OK), 301 (Moved Permanently), 404 (Not Found), and 500 (Internal Server Error).
- HTTP is a stateless protocol, which means that each request and response are independent and do not remember any previous interaction. However, HTTP can use cookies, headers, or other mechanisms to maintain state and session information between requests and responses.
- HTTP is an extensible protocol, which means that it can be modified and enhanced by adding new methods, headers, status codes, or features. For example, HTTP/1.1 introduced persistent connections, chunked encoding, and caching. HTTP/2 introduced binary framing, multiplexing, compression, and server push. HTTP/3 introduced the use of QUIC, a new transport protocol that improves performance and security.
