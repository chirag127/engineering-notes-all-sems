# Survey routing protocols for IoT

Routing protocols are essential for the efficient and reliable data communication in the Internet of Things (IoT) networks. IoT networks consist of heterogeneous devices with limited resources and capabilities, such as sensors, actuators, smart phones, etc. These devices are often deployed in large numbers and dynamic environments, where they need to cope with various challenges, such as network scalability, mobility, topology changes, energy consumption, security, etc. Therefore, routing protocols for IoT networks should be designed to meet the specific requirements and constraints of the IoT applications and scenarios.

There are different types of routing protocols for IoT networks, depending on the network architecture, routing strategy, and performance metrics. Some of the common types are:

- **Flat routing protocols**: These protocols do not use any hierarchical structure or clustering of nodes, and treat all nodes equally. They are suitable for small and static networks, where the overhead of maintaining routing tables and exchanging routing information is low. Examples of flat routing protocols are AODV, DSR, OLSR, etc.
- **Hierarchical routing protocols**: These protocols divide the network into clusters of nodes, where each cluster has a leader or a coordinator, called a cluster head. The cluster heads are responsible for aggregating and forwarding the data from their cluster members to the sink or the gateway node. They also maintain the routing information and coordinate the intra-cluster and inter-cluster communication. Hierarchical routing protocols are suitable for large and scalable networks, where they can reduce the energy consumption and the routing overhead by using data aggregation and multi-hop communication. Examples of hierarchical routing protocols are LEACH, PEGASIS, HEED, etc.
- **Geographic routing protocols**: These protocols use the location information of the nodes to make routing decisions. They do not require any global or local topology information, and can adapt to the dynamic changes in the network. They are suitable for mobile and sparse networks, where they can reduce the routing overhead and the latency by using greedy forwarding and local recovery techniques. Examples of geographic routing protocols are GPSR, GEAR, GAF, etc.
- **Data-centric routing protocols**: These protocols use the content or the attributes of the data to make routing decisions. They do not rely on any network or node identifiers, and can support query-based and event-based communication. They are suitable for sensor networks, where they can reduce the energy consumption and the data redundancy by using data aggregation and in-network processing techniques. Examples of data-centric routing protocols are SPIN, TAG, COUGAR, etc.

Some of the routing protocols for IoT networks are standardized by the Internet Engineering Task Force (IETF), such as:

- **RPL**: The IPv6 Routing Protocol for Low-Power and Lossy Networks (RPL) is a distance-vector routing protocol that uses a Directed Acyclic Graph (DAG) structure to route the packets from the nodes to the sink or the root node. RPL supports both point-to-multipoint and multipoint-to-point traffic, and can handle different types of link characteristics and application requirements. RPL uses an objective function to select the best path based on various metrics, such as hop count, expected transmission count, latency, etc. RPL also provides mechanisms for loop detection and avoidance, local repair, and security .
- **CoAP**: The Constrained Application Protocol (CoAP) is a web transfer protocol that enables the communication between resource-constrained devices and web services. CoAP is based on the RESTful architecture, and uses a request-response model to exchange messages between the client and the server. CoAP supports both reliable and unreliable transport, and can use UDP or DTLS as the underlying protocol. CoAP also provides features such as caching, discovery, observation, and group communication.
