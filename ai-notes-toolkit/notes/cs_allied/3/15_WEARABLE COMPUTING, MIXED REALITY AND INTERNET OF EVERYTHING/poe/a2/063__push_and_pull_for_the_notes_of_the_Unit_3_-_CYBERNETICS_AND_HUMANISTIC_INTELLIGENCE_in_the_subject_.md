### Push and Pull

- Push refers to sending information to users without the user initiating the request. For example, notifications, alerts, updates, etc. sent to users.
- Pull refers to users requesting information when needed. For example, searching for information, loading a web page, etc. The user initiates the request for information.
- In wearable devices and IoT, a balance of push and pull is required:
    - Push is needed to send important notifications or alerts to users. But excessive push can lead to alert fatigue.
    - Pull is needed to retrieve information on-demand. But if all information is pull-based, users may miss out on important updates or notifications.
- An optimal strategy is to use push for high-priority information and alerts but allow users to adjust the push frequency. Also, provide pull mechanisms to retrieve further details or related information.
- For mixed reality, push can be used to send notifications about events or activities nearby. But prolonged AR overlays on the user's view can be distracting. So, pull mechanisms can be provided to bring up AR displays on-demand when needed.
- In general, push should be used judiciously and pull should be the primary mechanism wherever possible. The specific balance of push vs pull depends on the use case and application. User preferences and controls should also be provided to customize the push-pull balance.
