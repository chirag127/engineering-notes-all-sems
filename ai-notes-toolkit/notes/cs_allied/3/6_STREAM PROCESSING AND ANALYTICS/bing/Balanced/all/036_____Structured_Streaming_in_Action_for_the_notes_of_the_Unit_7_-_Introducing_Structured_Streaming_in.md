# Structured Streaming in Action

- Structured Streaming is a **scalable and fault-tolerant stream processing engine** built on the Spark SQL engine.
- Structured Streaming allows you to **take the same operations that you perform in batch mode** using Spark’s structured APIs, and **run them in a streaming fashion**. This can reduce latency and allow for incremental processing.
- Structured Streaming lets you **express computation on streaming data in the same way you express a batch computation on static data**. The Structured Streaming engine performs the computation incrementally and continuously updates the result as streaming data arrives.
- In Structured Streaming, a data stream is treated as a **table that is being continuously appended** . This leads to a stream processing model that is very similar to a batch processing model. You express your streaming computation as a standard batch-like query as on a static table, but Spark runs it as an incremental query on the unbounded input table.
- Structured Streaming provides **fast, scalable, fault-tolerant, end-to-end exactly-once stream processing** without the user having to reason about streaming. This is achieved by ensuring that the output of a streaming query is always equivalent to the result of executing a batch query on a prefix of the data.
- Structured Streaming supports two types of output modes: **append mode** and **update mode**. Append mode is the default and only applicable when the queries do not contain any aggregations. Update mode allows the result table to be updated when new data arrives. Both modes can optionally output only the new rows generated in each trigger using the **output mode option**.
- Structured Streaming supports **event-time processing** and **late data handling** with **watermarking**. Watermarking tracks a threshold of how late the data is expected to be and allows the engine to accordingly limit the state. You can define the watermarking delay by using the **withWatermark** operator on a streaming Dataset/DataFrame.
- Structured Streaming supports **joining** a streaming Dataset/DataFrame with a static Dataset/DataFrame, or joining two streaming Datasets/DataFrames. There are different types of joins available: **inner joins, outer joins, left semi joins, and left anti joins**. The type of join can be specified using the **joinType parameter** in the join function.
- Structured Streaming supports **writing** the output of a streaming query to a file system, a database, or a message queue. The output can be written in various formats, such as **parquet, json, csv, orc, text, console, memory, kafka, or delta**. The output can be configured using the **writeStream** method on a streaming Dataset/DataFrame.
- Structured Streaming supports **reading** data from various sources, such as **files, sockets, rate, kafka, or delta**. The input can be read in various formats, such as **parquet, json, csv, orc, text, or binary**. The input can be configured using the **readStream** method on a SparkSession.
- Structured Streaming supports **monitoring** the progress and performance of a streaming query using the **query status** and the **Spark UI**. The query status provides information such as the **input rate, processing rate, latency, and state size** of a streaming query. The Spark UI provides a graphical interface to visualize the **query plan, event timeline, and statistics** of a streaming query.
