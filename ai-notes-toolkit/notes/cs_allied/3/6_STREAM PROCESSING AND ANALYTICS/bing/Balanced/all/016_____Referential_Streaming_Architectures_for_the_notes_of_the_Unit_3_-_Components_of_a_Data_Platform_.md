# Referential Streaming Architectures

- A referential streaming architecture is a design pattern that enables processing and analyzing data streams in real time.
- A data stream is a continuous flow of data records that are generated by one or more sources, such as sensors, devices, applications, or logs.
- A referential streaming architecture typically consists of the following components  :
  - Data sources: These are the originators of the data streams, such as IoT devices, web applications, or log files.
  - Data ingestion: This is the process of capturing, validating, and transferring the data streams from the sources to a centralized service, such as Azure Event Hubs, Amazon Kinesis, or Apache Kafka.
  - Stream processing: This is the process of applying transformations, aggregations, correlations, or analytics to the data streams in real time, such as Azure Stream Analytics, Amazon Kinesis Data Analytics, or Apache Spark Streaming.
  - Data storage: This is the process of persisting the data streams or the results of the stream processing to a durable storage layer, such as Azure Data Lake Storage, Amazon S3, or Apache Hadoop.
  - Data consumption: This is the process of accessing and using the data streams or the results of the stream processing for various purposes, such as dashboards, reports, applications, or machine learning models.
- A referential streaming architecture can provide several benefits, such as :
  - Low latency: The data streams can be processed and consumed within seconds or milliseconds of being generated, enabling near-real-time insights and actions.
  - Scalability: The data ingestion and stream processing components can scale horizontally to handle large volumes and velocities of data streams, enabling high throughput and availability.
  - Flexibility: The data streams can be processed and consumed in different ways, enabling multiple use cases and scenarios, such as real-time analytics, event-driven applications, or data lake integration.
