### Data Delivery Semantics: Microbatching and One-Element-at-a-Time

- Data delivery semantics refer to the guarantees that a system provides about how data is delivered from a source to a destination, such as a stream processing engine or a database.
- There are three main types of data delivery semantics: at-most-once, at-least-once, and exactly-once.
  - At-most-once semantics means that each data element is delivered once or not at all. This can result in data loss, but also avoids data duplication. This is the simplest and fastest delivery mode, but also the least reliable. An example of a system that uses at-most-once semantics is UDP.
  - At-least-once semantics means that each data element is delivered at least once, but possibly more than once. This can result in data duplication, but also avoids data loss. This is a more reliable delivery mode, but also requires more resources and logic to handle duplicates. An example of a system that uses at-least-once semantics is TCP.
  - Exactly-once semantics means that each data element is delivered exactly once, with no data loss or duplication. This is the most reliable and desirable delivery mode, but also the most complex and expensive to implement. It requires coordination and transactional guarantees between the source, the destination, and any intermediate systems. An example of a system that uses exactly-once semantics is Kafka.
- Microbatching and one-element-at-a-time are two different approaches to stream processing that have different implications for data delivery semantics.
  - Microbatching is a technique where incoming data is grouped into small batches and processed periodically, rather than continuously. This can improve the performance and scalability of stream processing, as well as enable stateful and windowed operations. However, it also introduces some latency and complexity in the data delivery, as the system has to wait for a batch to be completed before sending it to the next stage. Depending on the batch size and frequency, microbatching can achieve at-least-once or exactly-once semantics, but not at-most-once semantics. An example of a system that uses microbatching is Spark Streaming  .
  - One-element-at-a-time is a technique where incoming data is processed as soon as it arrives, without batching or buffering. This can minimize the latency and simplify the data delivery, as the system does not have to wait for any batch to be formed or completed. However, it also limits the performance and scalability of stream processing, as well as the ability to perform stateful and windowed operations. Depending on the implementation, one-element-at-a-time can achieve at-most-once, at-least-once, or exactly-once semantics. An example of a system that uses one-element-at-a-time is Flink.
