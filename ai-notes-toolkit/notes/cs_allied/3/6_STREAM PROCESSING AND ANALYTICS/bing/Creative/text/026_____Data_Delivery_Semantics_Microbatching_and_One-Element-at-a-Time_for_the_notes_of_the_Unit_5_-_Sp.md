### Data Delivery Semantics: Microbatching and One-Element-at-a-Time

- Data delivery semantics refer to the guarantees that a system provides about how data is delivered from a source to a destination, such as a stream processing engine or a database.
- There are three main types of data delivery semantics: at-most-once, at-least-once, and exactly-once.
- At-most-once semantics mean that each data element is delivered at most once, or not at all. This can result in data loss, but also reduces the complexity and overhead of the system. An example of a system that uses at-most-once semantics is UDP.
- At-least-once semantics mean that each data element is delivered at least once, or possibly multiple times. This can result in data duplication, but also ensures that no data is lost. An example of a system that uses at-least-once semantics is TCP.
- Exactly-once semantics mean that each data element is delivered exactly once, with no data loss or duplication. This is the most desirable but also the most challenging semantics to achieve, as it requires coordination and synchronization among multiple components of the system. An example of a system that uses exactly-once semantics is Kafka.
- Microbatching and one-element-at-a-time are two techniques that can be used to implement different data delivery semantics in stream processing systems.
- Microbatching is a technique where incoming data is grouped into small batches and processed periodically, rather than continuously. This can improve the performance and scalability of the system, as well as enable stateful and windowed operations on the data. However, microbatching also introduces some latency and complexity in the system, as well as the possibility of data duplication or loss depending on the batch size and frequency  .
- One-element-at-a-time is a technique where incoming data is processed as soon as it arrives, without batching or buffering. This can reduce the latency and complexity of the system, as well as enable more accurate and timely processing of the data. However, one-element-at-a-time also requires more resources and coordination among the system components, as well as the ability to handle failures and retries without affecting the data delivery semantics.
