### The Effect of Time for the notes of the Unit 2 - Stream-Processing Model in the subject of STREAM PROCESSING AND ANALYTICS

- Stream processing is a programming paradigm that views data streams, or sequences of events in time, as the central input and output objects of computation.
- Stream processing enables programs to react to new data events in real-time, rather than aggregating and collecting them at a predetermined frequency as batch processing does.
- Stream processing is designed for instant data processing and real-time analytics, providing current, up-to-the-millisecond insights into what’s happening within a system and helping to respond to critical events as soon as they occur.
- Stream processing is a compromise, driven by a data-centric model that works well for traditional DSP or GPU-type applications (such as image, video and digital signal processing) but less so for general purpose processing with more randomized data access (such as databases).
- Stream processing is often unpredictable, with events arriving in bursts, so the system has to be able to apply back-pressure, buffer events for processing, or scale dynamically to meet the load.
- Stream processing may include querying, filtering, and aggregating messages, and producing results with minimal latency.
- Stream processing requires a stream processing engine, which is a software system that can consume endless streams of data and perform operations on them.
- Stream processing engines can be classified into two types: stream processors and stream analytics.
- Stream processors are low-level engines that provide basic functionality such as ingestion, transformation, and routing of data streams. Examples of stream processors are Apache Kafka, Azure Event Hubs, and Azure IoT Hub.
- Stream analytics are high-level engines that provide complex functionality such as windowing, aggregation, join, and pattern matching of data streams. Examples of stream analytics are Apache Spark, Apache Flink, Azure Stream Analytics, and Azure Databricks.
