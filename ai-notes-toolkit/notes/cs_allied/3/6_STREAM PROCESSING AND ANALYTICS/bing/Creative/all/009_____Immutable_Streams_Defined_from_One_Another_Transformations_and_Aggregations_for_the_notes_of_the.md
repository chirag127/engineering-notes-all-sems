# Immutable Streams Defined from One Another Transformations and Aggregations

- Stream processing is a paradigm for processing data that is continuously generated by sources such as sensors, web servers, or social media platforms.
- Stream processing applications consume data from one or more input streams, apply some logic or computation to the data, and produce one or more output streams.
- Streams are immutable sequences of data records that are ordered by time. Each record has a key, a value, and a timestamp.
- Streams can be defined from one another by applying transformations and aggregations. Transformations are operations that change the content or structure of a stream, such as filtering, mapping, or joining. Aggregations are operations that summarize a stream into a smaller stream or a table, such as counting, summing, or averaging.
- Transformations and aggregations can be stateless or stateful. Stateless operations do not depend on any previous or future records in the stream, such as filtering or mapping. Stateful operations maintain some state across records in the stream, such as aggregating or joining.
- Window aggregations are a special type of stateful operations that divide a stream into finite segments based on time or record count, and apply an aggregation function to each segment. Window aggregations can be used to compute statistics over a sliding or fixed interval of time, such as hourly or daily averages.
- Stream processing frameworks, such as Apache Spark, Apache Kafka, or Apache Flink, provide APIs and tools for building and running stream processing applications. They also handle scalability, fault tolerance, and consistency issues that arise in distributed stream processing.
