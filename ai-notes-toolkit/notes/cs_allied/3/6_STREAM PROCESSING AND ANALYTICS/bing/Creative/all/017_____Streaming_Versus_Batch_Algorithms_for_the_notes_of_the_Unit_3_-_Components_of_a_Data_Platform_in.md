# Streaming Versus Batch Algorithms

- Streaming algorithms are algorithms that process data in real time as it arrives, without storing it in batches or intermediate buffers. Streaming algorithms are suitable for applications that require low latency, high throughput, and continuous analysis of data, such as fraud detection, anomaly detection, or sentiment analysis. Streaming algorithms can also handle unbounded and dynamic data sources, such as social media feeds, IoT sensors, or online transactions. Streaming algorithms are often implemented using frameworks such as Apache Kafka, Apache Flink, or Apache Spark Streaming  .
- Batch algorithms are algorithms that process data in batches, after collecting it over a period of time. Batch algorithms are suitable for applications that require high accuracy, complex computations, and historical analysis of data, such as machine learning, data warehousing, or reporting. Batch algorithms can also handle large and static data sources, such as log files, databases, or archives. Batch algorithms are often implemented using frameworks such as Apache Hadoop, Apache Hive, or Apache Spark  .
- The main differences between streaming and batch algorithms are:

  - Streaming algorithms process data in real time, while batch algorithms process data in batches.
  - Streaming algorithms have low latency and high throughput, while batch algorithms have high accuracy and complex computations.
  - Streaming algorithms handle unbounded and dynamic data sources, while batch algorithms handle large and static data sources.
  - Streaming algorithms use frameworks such as Apache Kafka, Apache Flink, or Apache Spark Streaming, while batch algorithms use frameworks such as Apache Hadoop, Apache Hive, or Apache Spark.
