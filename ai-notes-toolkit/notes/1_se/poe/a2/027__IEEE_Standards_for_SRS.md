### IEEE Standards for SRS

- IEEE Std 830-1998: Recommended Practice for Software Requirements Specifications
- It provides a format for writing SRS consisting of six major sections:

1. Introduction
    - Purpose
    - Scope
    - Definitions, Acronyms, Abbreviations
2. Overall Description
    - Product Perspective
    - User Characteristics
    - General Constraints
3. System Features
    - Functional requirements
4. External Interface Requirements
    - User Interfaces
    - Hardware Interfaces
    - Software Interfaces
5. Non-Functional Requirements
    - Performance Requirements
    - Safety Requirements
    - Security Requirements
    - Software Quality Attributes
6. Other Requirements
    - Business Rules
    - Apportioning of Requirements

- Requirements are specified in a numbered list using shall statements.
- Each requirement has a unique identifier for traceability.
- Requirements are unambiguous, verifiable, and necessary.
- The SRS is a contractual agreement between stakeholders. It forms the basis for designing and testing the software.
- The standard provides templates and examples to write SRS. It emphasizes on completeness, consistency, and clarity of SRS.
