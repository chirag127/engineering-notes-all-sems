### Review and Management of User Needs in Requirement Engineering Process in SRS

1. Identification of actual user needs: It is important to identify the actual user needs instead of perceived needs. Conducting interviews and surveys can help in identifying the actual user needs.
2. Prioritization of user needs: Once the user needs are identified, they should be prioritized based on their importance and impact. The Kano model or MoSCoW technique can be used for prioritization.
3. Refining and organizing user needs: The identified user needs should be refined and organized. Similar needs can be grouped together. The needs can be structured in a hierarchical manner with broader needs at higher levels and specific needs at lower levels.
4. Validation of user needs: The identified and refined user needs should be validated by consulting more users. This helps to ensure that no major user needs are missed out and the documented needs actually reflect the user needs accurately.
5. Managing changes to user needs: Requirements are prone to changes. Any changes to user needs should be properly managed throughout the product development lifecycle. The impact of changes should be analyzed and the requirements and design should be updated accordingly.

The review and proper management of user needs plays an important role in the requirement engineering process to generate a high quality SRS that meets the actual user needs. A systematic process should be followed to identify, prioritize, refine, validate and manage the user needs.
