### Integration Testing in Software Testing

1. Integration Testing is a level of software testing where individual units or components are combined and tested as a group. The purpose of this level of testing is to expose faults in the interaction between integrated units.

2. Integration Testing is performed after unit testing and before system testing. It is usually carried out in a controlled environment.

3. The major goals of Integration Testing are:

- To identify defects in the interfaces and interaction between integrated components or units.
- To ensure that the system meets all functional and performance requirements after integration of individual components.
- To ensure that the software system works as expected.

4. The different types of Integration Testing are:

- Big Bang Integration Testing: In this approach, all the modules are integrated at once and then tested. This approach is rarely adopted due to high risk.
- Incremental Integration Testing: In this approach, modules are integrated incrementally or iteratively in steps. Each step involves adding a module and then testing the integrated modules. This approach is commonly used.
- Sandwich or Top-down & Bottom-up Integration Testing: This strategy integrates modules in both directions in parallel. The main modules at top and bottom are integrated first, then the in-between modules are integrated. This helps to find integration defects early.

5. The inputs for Integration Testing are:

- Unit tested components
- Test cases for interactions between components
- Use cases and system requirements

6. The outputs of Integration Testing are:

- Identified interaction defects between integrated components
- Verified that system requirements are met on integrating components
