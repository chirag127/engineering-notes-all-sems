### Unit Testing in Software Testing

1. Unit Testing is a type of Software Testing where individual units or components of a software are tested. The purpose is to validate that each unit of the software performs as designed.

2. Unit Testing is done by the developers before integrating the units and doing integration testing. It helps to identify defects early in the development cycle and saves time and cost.

3. The key objectives of Unit Testing are:

- Verify that each unit implements the functionality it was designed for.
- Eliminate coding errors before proceeding to the next level of testing.
- Serve as documentation for the unit's intent and capabilities.

4. Important things to keep in mind for Unit Testing:

- Test one unit at a time.
- Write test cases that cover all paths and conditions.
- Stub and Driver components may be required if the unit under test interacts with other units.
- Automate the test cases for repeatable testing.
- Tests should be independent and repeatable.

5. The benefits of Unit Testing are:

- Identifies defects early leading to cost savings.
- Increases software reliability and quality.
- Acts as documentation for units.
- Supports Refactoring as existing test cases can be rerun to validate changes.
- Facilitates continuous integration by having automated unit test cases.
