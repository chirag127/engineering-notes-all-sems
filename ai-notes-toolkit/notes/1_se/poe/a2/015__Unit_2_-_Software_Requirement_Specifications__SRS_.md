## Unit 2 - Software Requirement Specifications (SRS)

- SRS is a formal document that captures all requirements for a software solution. It acts as a communication vehicle between customers and developers.
- It includes both functional and non-functional requirements. Functional requirements specify functions or capabilities a system must have, while non-functional requirements specify system properties such as performance, security, etc.
- SRS is usually created in the initial stages of SDLC by business analysts or requirements engineers after meeting with clients and stakeholders.
- Components of a good SRS:

- Introduction: Purpose, Scope, Definitions, References, Overview
- Overall Description: Product Perspective, System Features
- System Features: Functional requirements
- External Interface Requirements: User Interfaces, Hardware Interfaces, Software Interfaces, Communication Interfaces
- System Features: Non-functional requirements like Performance, Security, Safety, Reliability, etc.
- Other Requirements: Business Rules, Constraints, Assumptions,Dependencies

- Benefits of SRS: Helps bridge communication gap between stakeholders, Acts as a reference throughout the project, Increases productivity by avoiding rework, Reduces cost and time, Improves quality as requirements are clearly documented.

- Best practices for writing SRS:

- Use simple and clear language
- Be precise and unambiguous
- Prioritize requirements
- modularize the document
- Use diagrams/examples to enhance understanding
- Review and verify the SRS
