### Documentation in Requirement Engineering Process in SRS

1. Requirement Specification Document (SRS): It is the main documentation artifact in requirement engineering process. It contains requirements of the software to be developed in a well-structured manner. It helps in achieving a common understanding between stakeholders and developers.
2. Use Case Model: It captures system functionalities and main interactions between system and users. It is represented using use case diagrams and use case descriptions. It helps in identifying actors and use cases of the system.
3. Glossary: It contains definition of terms and acronyms used in requirements documentation. It helps in avoiding ambiguity and misunderstanding.
4. Mock-ups: They are hand-drawn sketches of user interfaces showing layout of windows or screens. They are useful in understanding user needs and validation of requirements.
5. Prototypes: They are executable models of a system which show how requirements may be implemented. They are useful in understanding, communicating and validating requirements.
6. Diagrams: Various diagrams such as activity diagrams, sequence diagrams, class diagrams, etc. are used to model behavior and structure of a system. They help in better understanding of requirements.
7. Traceability Matrix: It captures traceability between requirements and other artifacts such as design, code, test cases, etc. It helps in ensuring that all requirements are implemented and tested.

The above documentation artifacts play an important role in requirement engineering process. They facilitate communication between stakeholders, validation of requirements, and understanding requirements in a better way.
