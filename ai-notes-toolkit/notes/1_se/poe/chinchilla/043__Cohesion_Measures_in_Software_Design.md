#### Cohesion Measures in Software Design

Cohesion is a measure of the degree to which the elements of a module or system are related to each other. High cohesion means that the elements in a module or system are strongly related to each other, while low cohesion means that the elements are weakly related or unrelated.

Here are some common measures of cohesion in software design:

1. Functional Cohesion: This type of cohesion occurs when all the elements of a module or system are related to a single task or function. In other words, all the elements work together to achieve a specific goal or perform a specific function.

2. Sequential Cohesion: This type of cohesion occurs when the elements of a module or system are related to each other in a sequential order. In other words, the elements work together in a specific order to achieve a specific goal or perform a specific function.

3. Communicational Cohesion: This type of cohesion occurs when the elements of a module or system are related to each other through a shared data or communication channel. In other words, the elements work together to share information or data.

4. Procedural Cohesion: This type of cohesion occurs when the elements of a module or system are related to each other through a shared procedure or algorithm. In other words, the elements work together to perform a specific procedure or algorithm.

5. Temporal Cohesion: This type of cohesion occurs when the elements of a module or system are related to each other based on a specific time frame or event. In other words, the elements work together to achieve a specific goal or perform a specific function within a specific time frame or event.

6. Logical Cohesion: This type of cohesion occurs when the elements of a module or system are related to each other based on a logical relationship or dependency. In other words, the elements work together to achieve a specific goal or perform a specific function based on a logical relationship or dependency.

In software design, it is important to strive for high cohesion, as it leads to more maintainable, readable, and scalable code. By using the above measures of cohesion, software designers can ensure that their code is structured in a coherent and logical way, which makes it easier to understand and modify in the future.
