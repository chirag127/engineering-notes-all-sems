### Documentation in Requirement Engineering Process in SRS

- Software Requirements Specification (SRS) is a document that describes the requirements, scope, purpose, functionality, and quality of a software system.
- SRS is the output of the requirement engineering process, which involves eliciting, analyzing, validating, and managing the software requirements.
- SRS serves as a contract between the development team and the customer, as well as a basis for software design, testing, and maintenance.
- SRS should be clear, complete, consistent, traceable, verifiable, and modifiable.
- SRS should follow a standard structure and format, such as IEEE 830-1998, which includes the following sections:
  - Introduction: provides an overview of the document, its purpose, scope, definitions, acronyms, references, and assumptions.
  - Overall description: provides a general description of the software system, its context, functions, user characteristics, constraints, dependencies, and assumptions.
  - Specific requirements: provides a detailed description of the functional and non-functional requirements of the software system, such as user interfaces, data, performance, security, reliability, etc.
  - Appendices: provides any additional information that may be useful for understanding the SRS, such as glossary, use cases, diagrams, etc.
  - Index: provides a list of terms and topics covered in the SRS for easy reference.
- SRS should be written in a clear, concise, and unambiguous language, using terms and concepts that are familiar to the intended audience.
- SRS should be reviewed and approved by the stakeholders, such as the customer, the development team, the project manager, and the quality assurance team, before proceeding to the next phase of software development.
- SRS should be updated and maintained throughout the software development life cycle, to reflect any changes or modifications in the software requirements.

- A possible mnemonic to remember the main sections of SRS is **I Owe Some Serious Applesauce In** (Introduction, Overall description, Specific requirements, Appendices, Index).
