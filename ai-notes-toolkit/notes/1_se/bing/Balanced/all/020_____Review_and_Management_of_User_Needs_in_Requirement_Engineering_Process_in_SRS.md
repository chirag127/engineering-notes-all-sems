### Review and Management of User Needs in Requirement Engineering Process in SRS

- User needs are the expectations and requirements of the end-users and other stakeholders of the software system.
- Requirement engineering (RE) is the process of eliciting, analyzing, specifying, validating, and managing user needs throughout the software development lifecycle.
- Software requirement specification (SRS) is a document that describes the functional and non-functional requirements of the software system, as well as the constraints, assumptions, and dependencies.
- Review and management of user needs are essential activities in the RE process, as they ensure the quality, completeness, consistency, and traceability of the user needs and the SRS document.
- Review and management of user needs involve the following steps:

  - Elicitation: This is the process of gathering user needs from various sources, such as interviews, surveys, observations, prototypes, etc. The elicitation techniques should be appropriate for the type and scope of the user needs, as well as the domain and context of the software system.
  - Analysis: This is the process of refining, organizing, prioritizing, and modeling the user needs. The analysis techniques should be able to handle the complexity, ambiguity, and uncertainty of the user needs, as well as the conflicts and trade-offs among them.
  - Specification: This is the process of documenting the user needs in a clear, precise, and unambiguous way, using a standard format and language. The specification techniques should be able to capture the functional and non-functional requirements, as well as the constraints, assumptions, and dependencies of the software system.
  - Validation: This is the process of verifying and validating the user needs and the SRS document, using various methods, such as reviews, inspections, walkthroughs, testing, etc. The validation techniques should be able to detect and correct any errors, inconsistencies, incompleteness, or ambiguity in the user needs and the SRS document.
  - Management: This is the process of controlling and managing the changes and evolution of the user needs and the SRS document, using tools and techniques, such as configuration management, traceability, version control, etc. The management techniques should be able to track and document the changes and their impact on the user needs and the SRS document, as well as the stakeholders and the software system.

- Review and management of user needs are important for the following reasons:

  - They ensure that the user needs and the SRS document are aligned with the business goals and objectives of the software system.
  - They ensure that the user needs and the SRS document are consistent and coherent with each other and with the other software artifacts, such as design, code, test, etc.
  - They ensure that the user needs and the SRS document are complete and comprehensive, covering all the aspects and scenarios of the software system.
  - They ensure that the user needs and the SRS document are accurate and correct, reflecting the true and current needs and expectations of the end-users and other stakeholders.
  - They ensure that the user needs and the SRS document are feasible and realistic, considering the available resources, time, budget, and technology of the software system.
  - They ensure that the user needs and the SRS document are verifiable and testable, providing clear and measurable criteria for the evaluation and validation of the software system.

- A possible mnemonic to remember the steps of review and management of user needs is **EASVM** (Elicitation, Analysis, Specification, Validation, Management).
