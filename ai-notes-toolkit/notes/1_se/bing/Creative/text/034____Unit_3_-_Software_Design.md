## Unit 3 - Software Design

- Software design is the process of defining the architecture, components, interfaces, and other characteristics of a software system.
- Software design is based on the requirements and specifications of the software system, as well as the principles and practices of software engineering.
- Software design aims to achieve the following goals:
  - Functionality: the software system should meet the functional and non-functional requirements of the stakeholders.
  - Quality: the software system should have desirable attributes such as reliability, usability, efficiency, maintainability, and portability.
  - Feasibility: the software system should be within the constraints of budget, time, resources, and technology.
- Software design can be divided into two levels:
  - High-level design: the overall structure and organization of the software system, such as the modules, components, subsystems, and their relationships and interactions.
  - Low-level design: the detailed design of each module, component, or subsystem, such as the data structures, algorithms, interfaces, and control logic.
- Software design can follow different approaches or paradigms, such as:
  - Structured design: a top-down approach that decomposes the software system into smaller and simpler modules, using concepts such as abstraction, hierarchy, coupling, and cohesion.
  - Object-oriented design: a bottom-up approach that models the software system as a collection of objects that have state and behavior, and communicate through messages, using concepts such as encapsulation, inheritance, polymorphism, and association.
  - Component-based design: an approach that reuses existing software components that have well-defined interfaces and functionality, and integrates them into a software system, using concepts such as composition, delegation, and dependency injection.
  - Service-oriented design: an approach that exposes the functionality of the software system as a set of services that can be accessed through standard protocols and formats, using concepts such as service contract, service discovery, and service composition.
