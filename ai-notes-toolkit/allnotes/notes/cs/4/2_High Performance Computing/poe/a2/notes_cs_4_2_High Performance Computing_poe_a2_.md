## Unit 1 - Overview of Grid Computing Technology

1. Grid Computing - Grid computing is a distributed computing paradigm that involves coordinating and sharing computing resources in a network to solve large-scale computational problems. The key characteristics of grid computing are:
- Wide-area network: The computational resources are distributed across a wide-area network.
- Heterogeneous systems: The constituent systems are heterogeneous in nature with varying computing capacities, operating systems, network bandwidth, etc.
- Shared resources: The resources are shared to solve a common goal or task.
- Dynamic behavior: The resources can join or leave the grid dynamically.

2. Motivation for Grid Computing - The key motivations for grid computing are:
- Utilization of unused resources: Grid computing aims to utilize computing resources that would otherwise be unused. This can reduce costs and be more environmentally friendly.
- Scalability: By aggregating resources, grid computing aims to provide a scalable infrastructure to solve very large problems that cannot be solved by a single system.
- Resource sharing: By sharing resources, grid computing allows different groups to have access to resources that they would not have access to independently. This can enable new types of applications and scientific advances.

3. Challenges in Grid Computing - There are several key challenges involved in grid computing:
- Heterogeneity: The heterogeneous and dynamic nature of grid resources can make resource management and task scheduling complex.
- Security: With resource sharing comes issues of authentication, authorization, and security. Mechanisms are required to ensure that only authorized users can access resources.
- Data management: Efficient mechanisms are required to locate, replicate, and move data in the grid based on application requirements and resource locations.
- Fault tolerance: Mechanisms are needed to tolerate faults and ensure that applications can complete in the presence of system or network failures.
- Performance: The performance of applications can be hard to predict and optimize in a grid. Methods are needed to allocate resources and schedule tasks to meet performance requirements.

### History of Grid Computing

1. The concept of grid computing originated in the early 1990s as a way to utilize underutilized computing resources. The key idea was to aggregate computing resources from multiple administrative domains to solve large-scale computational problems.
2. The term "grid" was first used in 1997 by Ian Foster and Carl Kesselman in their seminal work "The Grid: Blueprint for a New Computing Infrastructure". They envisioned the computational grid as a hardware and software infrastructure that would provide dependable, consistent, pervasive, and inexpensive access to high-end computational resources.
3. The late 1990s and early 2000s saw the creation of pioneering grid computing projects like the NASA Information Power Grid, the Particle Physics Data Grid, and the Network Weather Service. These projects aimed to harness distributed computing resources to tackle complex scientific problems that require large amounts of computing power.
4. In the mid-2000s, there was growing interest in service-oriented architectures and web services for grid computing. This led to the development of standards like the Open Grid Services Architecture and key middleware like the Globus Toolkit. These technologies enabled greater interoperability between grid systems and leveraged service-oriented principles.
5. In recent years, cloud computing has gained more prominence and seen significant commercial adoption. However, grids are still used in scientific communities to aggregate computing resources for running compute-intensive applications and workflows. Additionally, grids and clouds are increasingly being integrated to form hybrid infrastructures to achieve greater scalability and flexibility.

- Cluster computing is a type of parallel and distributed processing system. The basic idea is to connect multiple computers to work as a single system.

    - Cost effectiveness: By connecting multiple low cost computers, a high performance computing solution can be built at lower cost.

    - Software complexity: Programming distributed applications and handling communication between nodes can be complex.

### Cluster Computer and its Architecture

- A cluster computer is a group of interconnected computers that work together as a single system.
- The clustered computers leverage multiple computers to solve a single problem by breaking it into smaller parts that are solved simultaneously. This provides performance and scalability.
- The key components of a cluster computer are:
- Nodes: Individual computers that are interconnected. They can be homogeneous or heterogeneous.
- Interconnect: The networking between the nodes that allows them to communicate and coordinate with each other. It can be a local area network or a high-speed interconnect like InfiniBand.
- System software: The software that makes the cluster of individual computers operate as a single system. It includes a distributed operating system, application software, and middleware.
- Cluster workload manager: Manages the distribution and coordination of work across the cluster. It assigns tasks to nodes and monitors for load balancing and fault tolerance.
- Storage: A central shared storage system provides a common file system for the cluster. The nodes access the shared storage over the network interconnect.

The architecture of a cluster computer enables it to leverage multiple nodes working in parallel to solve complex computational problems that are divisible into smaller parts. The interconnect and system software are key to facilitating the coordination between the nodes. The cluster workload manager and shared storage provide mechanisms for efficiency, load balancing, and fault tolerance. Overall, the cluster architecture aims to maximize performance and scalability for high-performance computing applications.

### Parallel Virtual Machine (PVM)

1. PVM (Parallel Virtual Machine) is a software package that permits a heterogeneous collection of Unix/Linux computers to be used as a single parallel computer.
2. PVM creates a "virtual machine" - a software abstraction that permits message passing and resource sharing (such as files) among a group of virtual parallel computers.
3. PVM provides a simple message passing interface for writing parallel programs. The programmer can use PVM routines to send and receive messages between tasks running on multiple computers.
4. PVM handles message routing, task scheduling, resource management, and error handling. The user can control these functions through an assortment of run-time library calls and environment variables.
5. PVM consists of a software library for sending and receiving messages, a daemon process (pvm_server) that starts up on each host machine, and various utility routines and scripts.
6. PVM permits heterogeneous collections of computers (different architectures and operating systems) to be used together in a single parallel computation. This heterogeneity is completely transparent to the user.
7. PVM provides a simple, flexible mechanism for writing portable parallel programs. Minimal changes, if any, are required when moving an application from one architecture/OS to another.

### Cloud Computing Architecture

1.  Infrastructure as a Service (IaaS): Provides access to computing resources like servers, storage, and networking. The service provider manages the infrastructure and the consumer can provision resources on-demand without the overhead of managing the physical infrastructure. Eg: Amazon Web Services (AWS), Google Cloud Platform (GCP), Microsoft Azure.
2.  Platform as a Service (PaaS): Provides a computing platform with a framework for developing, running, and managing applications without the overhead of maintaining the infrastructure or installing software. The service provider hosts the hardware and software on its own infrastructure. Eg: AWS Elastic Beanstalk, Google App Engine, Azure App Service.
3.  Software as a Service (SaaS): Provides access to application software and databases. The consumer doesn't manage the infrastructure or platforms that run the applications. Eg: Gmail, Google Drive, Microsoft Office 365, Salesforce.
4.  Serverless Computing: Enables computing without the need to manage servers. The cloud provider dynamically allocates machine resources to the applications. The consumer is billed based on the actual amount of resources consumed by the applications. Eg: AWS Lambda, Google Cloud Functions, Azure Functions.

The above points summarize the key types of cloud computing architectures namely IaaS, PaaS, SaaS, and Serverless computing. The examples of major cloud providers for each architecture are also listed for reference.
