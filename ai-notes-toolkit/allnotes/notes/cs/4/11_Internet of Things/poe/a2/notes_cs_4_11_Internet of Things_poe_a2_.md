### Design Principles for Connected Devices

1. Keep it Simple: Connected devices should be simple in design and functionality. They should perform specific tasks and not be overloaded with complex features. Simplicity makes them easy to use and less prone to errors or security vulnerabilities.

2. Secure by Design: Security should be a key consideration from the design stage itself. Devices and data should be protected from unauthorized access or tampering. This could include encrypted communications, secure boot processes, remote software updates, etc.

3. Limit Collection of Data: Only collect and store data that is necessary for the functioning of the device. Limit tracking and sharing of personal data. Data should be anonymized whenever possible.

4. Ensure Privacy: Data and personal information should be kept private and not shared without explicit user consent. Users should have control over their data and be aware of how it is collected and used.

5. Be Interoperable: Devices should be able to connect and exchange data with other devices and systems. Standard protocols and interfaces enable interoperability between devices from different manufacturers. This is crucial for the IoT to function as an integrated system.

6. Provide Over-the-air Updates: Connected devices may require software updates to fix vulnerabilities, add new features or improve performance. The ability to update device software over the air (without physical access) is important for security and usability. However, this also means that devices must be designed to accept only authentic and authorized updates.

7. Consider the User Experience: The user experience is key to the successful adoption of connected devices. The interface should be simple, intuitive and tailored to how the user interacts with the device. It should also ensure the user is in control of the device and aware of how data is collected or shared.

8. Build for Scale: The IoT ecosystem involves connecting billions of devices and handling massive amounts of data. Systems must be designed to handle this scale, with efficient protocols, minimal data and bandwidth requirements, decentralized architectures, etc. Performance and reliability cannot be compromised even at large scale.

### IoT/M2M systems layers and design standardization

- Physical layer: Comprises of sensors and actuators that capture and control the physical parameters. These include temperature, humidity, pressure sensors, motors, switches, etc.
- Device/Gateway layer: Consists of embedded systems and gateways that receive input from sensors and control the actuators. These devices collect the data, optionally aggregate and filter the data and send it to the network layer.
- Network layer: Responsible for establishing connectivity between the devices and gateways (device layer) and the servers (application layer) over various wired/wireless networks.
- Application/Middleware layer: Consists of software frameworks and applications that store, process and analyze the data received from the network layer and provide user interfaces to interact with the system.

Standardization in IoT/M2M systems:

- Hardware standardization: Standard protocols and interfaces for sensors and actuators to communicate with embedded devices. Example: OneM2M sensor interface standards
- Communication standardization: Standard communication technologies and protocols for device to device and device to server communication. Example: MQTT, CoAP, etc.
- Semantic standardization: Standard data formats and semantic models for representing information in IoT systems. Example: JSON, XML, O-MI, etc.
- Discovery and directory standardization: Standard mechanisms to discover IoT devices and directories to store device metadata. Example: DNS-SD, mDNS, etc.
- Security and privacy standardization: Standard authentication, authorization, encryption and privacy mechanisms for IoT systems. Example: DTLS, TLS, etc.

### Radio Frequency Identification (RFID) Technology

- RFID is a wireless technology that uses tiny tags or chips to store identification data and a reader to retrieve the data from the tags.
- The tags contain an antenna to enable them to receive and respond to radio-frequency queries from an RFID reader.
- Passive tags have no internal power supply and draw power from the radio signal sent by the reader. Active tags use an internal power source, so they have a longer range and can store more data than passive tags.
- RFID technology is used for contactless identification, tracking, and automated data collection. Some applications include:
- Access control and security. RFID tags can be used to control access to buildings, computers, networks, etc.
- Contactless payments. RFID-embedded cards or keys can be used to make secure payments without requiring physical contact.
- Supply chain management. RFID tags can be attached to products to track their movement and monitor inventory.
- Smartcards. RFID chips are embedded in cards to store information and enable functions like storing health records, public transit payments, etc.
- The main benefits of RFID are contactless identification, durability, and flexibility. However, there are privacy concerns due to the possibility of unauthorized scanning and tracking of RFID tags. Appropriate security measures need to be in place to address these concerns.

## Unit 3 - Embedded Platforms for IoT

### Wireless Medium access issues

1. Collision - When two or more devices transmit signals at the same time, collision occurs which corrupts the data. This needs to be avoided using protocols like CSMA/CA.
2. Hidden node problem - When a node is visible to the access point but not to other nodes, it can lead to collision at the receiver end. This can be avoided using RTS/CTS mechanism.
3. Exposed node problem - When a node avoids transmission due to overhearing of other transmissions unnecessarily, it leads to underutilization of the channel. This can be reduced by optimizing the transmission power and range.
4. Fairness - The medium access protocol should be fair to all nodes in getting access to the channel. This can be achieved using techniques like round-robin, weighted fair queuing, etc.
5. Throughput - The network throughput should be optimized by efficient utilization of the bandwidth and minimizing access delays. This can be done using both contention-based and contention-free protocols suitably.
6. Power consumption - The power consumption should be minimized by using sleep/wake-up schedules for nodes and minimizing retransmissions due to collisions or errors.
7. Scalability - The medium access protocol should be scalable to support a large number of devices in the network. Contention-free protocols offer more scalability compared to contention-based protocols.

### MAC protocol survey for the notes of the Unit 4 - Network & Communication aspects in IoT in the subject of Internet of Things.

1. ALOHA:
- Pure Aloha: Nodes transmit packets whenever they have data to send. If collision occurs, nodes retransmit after a random time. Low throughput.
- Slotted Aloha: Time is divided into slots. Nodes can only transmit at slot boundaries. If collision occurs, nodes retransmit in next slot. Higher throughput than pure Aloha.

2. Carrier Sense Multiple Access (CSMA):
- Nodes sense the medium before transmitting. If idle, they transmit. If busy, they wait for a random time and sense again.
- Example: CSMA/CD used in Ethernet. Colliding nodes detect collision and retransmit after a random wait.

3. Time Division Multiple Access (TDMA):
- Time is divided into slots assigned to each node. Nodes only transmit in their allocated slots. Coordinated allocation of slots to nodes required. Higher throughput and efficiency but requires synchronization among nodes.

4. Frequency Division Multiple Access (FDMA):
- The available bandwidth is divided into frequency bands assigned to nodes. Nodes only transmit in their allocated frequency bands. Frequency allocation to nodes must be coordinated. Susceptible to interference from adjacent frequency bands.

### Survey routing protocols for the notes of the Unit 4 - Network & Communication aspects in IoT

1. Protocol Independent Multicast (PIM): PIM is used for efficiently distributing data to large numbers of receivers. PIM routers build distribution trees that are multicast delivery paths between the sender and receivers. PIM has different modes:
- PIM-SM (Sparse-Mode): Used for multicast applications with widely dispersed receivers.
- PIM-DM (Dense-Mode): Used for dense receiver environments.

2. Distance Vector Multicast Routing Protocol (DVMRP): DVMRP uses a reverse path forwarding (RPF) check mechanism to build a distribution tree emanating from the source. It uses distance vectors to propagate reachability information between routers. The protocol specifies a mechanism to prune the distribution tree.

3. Multicast Open Shortest Path First (MOSPF): MOSPF is an extension to OSPF that supports multicast routing. OSPF link state advertisements are extended to include group membership information. The protocol computes multicast delivery trees that include only routers and links necessary to deliver packets to group members.

4. Core Based Trees (CBT): CBT creates a multicast distribution tree with a single core router at the root of the tree. Multicast data is forwarded along the tree from the source to the core and then from the core to the receivers. The core router is typically the router nearest the midpoint of the senders and receivers. The key advantage of CBT is that the core router aggregates state for the tree, limiting the amount of routing state in PIM routers.

### Communicating data with Hardware units

1. Sensors: Sensors collect data from the physical world like temperature, humidity, motion, etc. and convert the physical data into electrical signals which are then converted into digital data and sent to microcontrollers or gateways. eg. Temperature sensor, PIR sensor, Ultrasonic sensor, etc.
2. Microcontrollers: The digital data from sensors is sent to microcontrollers which perform processing on the data like data filtering or conversion and then transmit the data to gateways or servers. eg. Arduino, Raspberry Pi, ESP32, etc.
3. Gateways: Gateways act as an intermediate device to connect the hardware units to the Internet/cloud servers. They receive the data from microcontrollers and then forward it to the servers over the Internet. They can also be configured to perform some processing or aggregation on the data before sending it to the servers.
4. Servers: The data is received by servers over the Internet which then store, process and analyze the data. The analyzed data can be used to monitor the system or trigger some actions. The servers then optionally send a response back to the hardware units which can trigger some actions in the physical world.

The above steps demonstrate how the hardware units communicate with each other to send the data to the servers which can then be used for IoT applications. The communication between the units can be wired or wireless depending upon the requirements and distances. The data exchange also follows some protocols like MQTT, HTTP, etc.
