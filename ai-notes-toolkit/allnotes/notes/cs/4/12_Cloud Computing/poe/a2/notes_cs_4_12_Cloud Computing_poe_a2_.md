## Unit 1 - Introduction To Cloud Computing

1. Cloud Computing: Cloud computing refers to the delivery of computing services over the Internet. Instead of companies hosting software, data, and computing resources on their own in-house servers, all of that is hosted by a cloud provider in their data centers.

2. Benefits of Cloud Computing:
 - Increased Agility: Cloud computing increases the agility of an organization since resources can be easily provisioned and de-provisioned on demand.
 - Lower Costs: Cloud computing reduces the costs for organizations as they only pay for the resources they use. There are no upfront infrastructure costs.
 - Easy Access: Cloud computing provides easy access to resources from any location via the Internet.
 - Scalability: It is easy to scale resources up or down as per demand in cloud computing. This makes it a great fit for organizations with dynamic workload requirements.
 - Reliability: Cloud computing offers high reliability as the infrastructure is robust and monitored 24/7 by experts. Data is also backed up and replicated regularly.

3. Service Models: The three main service models of cloud computing are:
 - Infrastructure as a Service (IaaS): Provides access to computing resources such as servers, storage, and networking. The user has administrative access over the infrastructure.
 - Platform as a Service (PaaS): Provides a computing platform such as an operating system, programming language execution environment, database, etc. The user does not have administrative access over the infrastructure.
 - Software as a Service (SaaS): Provides access to applications that are run on cloud infrastructure. The user does not have administrative access over the platform or infrastructure.

4. Deployment Models: The two main deployment models of cloud computing are:
 - Public Cloud: In a public cloud, the infrastructure is owned and operated by a third-party cloud service provider and made available to the general public over the internet.
 - Private Cloud: In a private cloud, the infrastructure is operated solely for a single organization. It may be managed internally or by a third-party and located on-premises or off-premises.

1.  Grid and Utility Computing - The concept of sharing computing resources like storage, applications, and network bandwidth among multiple users over the internet originated with grid and utility computing in the 1990s.
2.  Application Service Providers (ASP) - In the late 1990s and early 2000s, the idea of offering software applications over the internet gained popularity. Companies like Salesforce started offering enterprise applications via the internet which users could access from anywhere via a web browser.

### Underlying Principles of Parallel and Distributed Computing

1. Parallelism: Processing multiple tasks simultaneously. The key benefits are increased throughput and reduced latency or time required to complete a task. Examples: Multiple CPU cores, GPUs.
2. Scalability: Ability to increase resources to handle increase in work. Examples: Adding more servers, scaling up or out.
3. Distribution: Workload is divided into multiple smaller parts that can be processed in parallel on multiple resources. Examples: Breaking up a big task into smaller tasks, distributing data across multiple servers.
4. Load balancing: Workload is distributed evenly across available resources to maximize resource utilization and throughput. Example: Sending new tasks to least loaded servers.
5. Data partitioning: Data is split and stored across multiple resources. How the data is partitioned impacts how parallel processes access the data and affect performance. Examples: Sharding databases, distributing inputs for map-reduce jobs.
6. Data locality: Placing data close to the resources processing it to reduce latency and network traffic. Examples: Placing frequently accessed data in cache, memory or local disks of servers that use the data.
7. Fault tolerance: System is able to continue functioning in the event of failure of one or more components. Examples: Data replication, checkpointing and recovery, speculative execution.

The above points cover the key underlying principles that enable parallel and distributed processing in cloud computing systems to achieve scalability, performance, fault tolerance and high availability. How a system is designed in terms of these principles impacts its latency, throughput and resource utilization.

### Cloud Characteristics

1. On-demand self-service: A consumer can unilaterally provision computing capabilities, such as server time and network storage, as needed automatically without requiring human interaction with each service provider.

2. Broad network access: Capabilities are available over the network and accessed through standard mechanisms that promote use by heterogeneous thin or thick client platforms (e.g., mobile phones, tablets, laptops, and workstations).

3. Resource pooling: The provider's computing resources are pooled to serve multiple consumers using a multi-tenant model, with different physical and virtual resources dynamically assigned and reassigned according to consumer demand. There is a sense of location independence in that the customer generally has no control or knowledge over the exact location of the provided resources but may be able to specify location at a higher level of abstraction (e.g., country, state, or data center).

4. Rapid elasticity: Capabilities can be elastically provisioned and released, in some cases automatically, to scale rapidly outward and inward commensurate with demand. To the consumer, the capabilities available for provisioning often appear to be unlimited and can be appropriated in any quantity at any time.

5. Measured service: Cloud systems automatically control and optimize resource use by leveraging a metering capability at some level of abstraction appropriate to the type of service (e.g., storage, processing, bandwidth, and active user accounts). Resource usage can be monitored, controlled, and reported, providing transparency for both the provider and consumer of the utilized service.

### REST and Systems of Systems

- REST or Representational State Transfer is an architectural style for building web services. It relies on a stateless, client-server, cacheable communications protocol - usually HTTP.
- RESTful web services provide interoperability between computer systems on the internet.
- Key principles of REST:
-- Client-server architecture: There is a clear separation between the client and the server. The client makes requests and the server provides responses.
-- Statelessness: Each request contains all the data necessary to complete itself and no client context is stored on the server between requests.
-- Cacheability: Responses must be labeled as cacheable or non-cacheable to improve network efficiency.
-- Layered system: The architecture is composed of layers of components, each performing a specific role.
-- Code on demand: Servers can extend functionality by sending executable code to the client.
-- Uniform interface: Resources are identified using URIs, manipulated using standard methods, and transmitted in a format such as JSON or XML.
- Systems of Systems refers to the integration of complex systems and applications. The systems and applications integrate with each other using standard interfaces and protocols to provide larger scale capabilities. RESTful web services enable Systems of Systems in a flexible, interoperable manner. The loose coupling and statelessness properties make it suitable for integration across systems and organizations.

- Decouples producers and consumers

- Manage the message queues
- Accept messages from producers and deliver to consumers
- May support multiple queues and topics

### Implementation Levels of Virtualization for the notes of the Unit 2 - Cloud Enabling Technologies Service Oriented Architecture in the subject of Cloud Computing

1. Full Virtualization: Entire guest OS is virtualized. Example: VMware, VirtualBox.
- Guest OS kernel is unaware of being virtualized.
- Requires more resources but more isolation and compatibility.

2. Para-Virtualization: Guest OS is modified to be virtualization-aware. Example: Xen.
- Hypervisor provides APIs to guest OS.
- Guest OS kernel is virtualization-aware and optimized to work with hypervisor.
- Better performance than full virtualization but less compatibility.

3. Operating System-Level Virtualization: Multiple isolated user-space instances. Example: OpenVZ, Linux-VServer.
- Partitions a single OS kernel into multiple isolated user-space instances.
- Lightweight with good performance but less isolation.

4. Application-Level Virtualization: Application is isolated from others. Example: Java Virtual Machine (JVM), .NET Common Language Runtime (CLR).
- Single application is virtualized.
- Good performance and isolation but limited to single application.

The levels provide different trade-offs between performance and isolation. Choice depends on specific requirements and use-cases. Full virtualization and para-virtualization are more common for cloud computing. Operating system-level and application-level virtualization are more suitable for limited scenarios.

Virtualization Support and Disaster Recovery

### What is Virtualization?
- Virtualization is a technology that creates virtual versions of physical resources.
- In virtualization, a software layer is created between the hardware and the operating system that enables running multiple virtual machines with different operating systems on the same physical machine.
- Each virtual machine has its own set of virtual hardware like CPU, memory, storage, and network interfaces. The software layer allocates physical resources dynamically to the virtual machines.
- Key benefits of virtualization are optimum utilization of resources, cost efficiency, agility, and easy scalability.

### Types of Virtualization
- Full Virtualization - A complete simulated hardware is created for the guest OS. Examples are VMware ESXi and VirtualBox.
- Para-virtualization - The guest OS is modified to use a special API to access the virtual hardware. Example is Xen.
- Operating System-level Virtualization - The resources of a single OS kernel are virtualized to run multiple isolated user space instances. Example is Docker and LXC.

### Disaster Recovery using Virtualization
- In virtualized environments, virtual machines can be backed up as images which can be used to quickly restore the service in case of a disaster.
- The virtual machine images can be stored in a remote location and used to spawn the virtual machines on any available hardware in case the primary data center goes down.
- This enables high availability and disaster recovery of services as the backup virtual machines can be quickly brought online to handle user requests.
- The disaster recovery time can be reduced significantly using virtualization as the entire machine state is captured and transferred instead of individual files and configuration.

### Layered Cloud Architecture Design

1. Infrastructure as a Service (IaaS): This is the lowest level service model in cloud computing. It provides the basic building blocks for cloud IT which includes networking, storage, servers, and virtualization. The consumer has the control over the infrastructure but does not manage the underlying hardware. Example: Amazon EC2, Microsoft Azure Virtual Machines, etc.

2. Platform as a Service (PaaS): This is the middle layer which provides the platform to develop, run, and manage applications without the complexity of maintaining the infrastructure. The consumer has control over the deployed applications and application hosting environment settings but does not have access to the underlying infrastructure. Example: AWS Elastic Beanstalk, Azure App Service, etc.

3. Software as a Service (SaaS): This is the topmost layer which provides the cloud-based end-user applications. The applications are accessed from various devices through a thin client interface such as a web browser. The customer does not have any control over the infrastructure or platforms. Example: G Suite, Office 365, Salesforce, etc.

This three-layer architecture enables the separation of concerns and increases the portability, interoperability, and reusability of the resources. The layers can be used independently or in combination based on the requirements of the use cases.

### NIST Cloud Computing Reference Architecture

1. The NIST Cloud Computing Reference Architecture consists of five major layers:

- Cloud consumer layer: The highest layer where the end users access the cloud services.
- Cloud provider layer: The layer where the cloud providers offer cloud services to the consumers.
- Cloud broker layer: The layer which acts as an intermediary between the consumers and providers to aggregate, integrate or customize cloud services.
- Cloud carrier layer: The layer which provides connectivity and delivery of cloud services.
- Cloud resource layer: The lowest layer which encompasses the computing resources.

2. The main components of the reference architecture are:

- Cloud auditor: To evaluate and monitor cloud services and data.

1. Hadoop - Hadoop is an open source software framework for distributed storage and processing of very large data sets on computer clusters built from commodity hardware.

2. Hadoop Components - Hadoop has two major components:

- Hadoop Distributed File System (HDFS) - A distributed file system that stores data on commodity machines, providing very high aggregate bandwidth across the cluster.
- Hadoop MapReduce - A software framework for distributed processing of large data sets on compute clusters.

3. Hadoop Ecosystem - There are several other Hadoop-related projects that complement and extend the Hadoop/HDFS/MapReduce core including: Hive, Pig, HBase, Oozie, Flume, Sqoop and ZooKeeper. These projects address tasks such as query processing (Hive), data modeling (Pig), database functionality (HBase), workflow coordination (Oozie), log processing (Flume), data transfer (Sqoop) and coordination (ZooKeeper).

4. Cloud Technologies - There are many Cloud platforms which provide Hadoop as a service like Amazon EMR, Microsoft HDInsight, Google Cloud Dataproc and IBM BigInsights. These cloud platforms provide a managed Hadoop framework and ecosystem projects, removing the complexity of manual configuration and maintenance.

5. Advancements - Some recent advancements in Hadoop include support for non-Java based processing engines such as Spark and Flink; ability to run interactive and iterative machine learning algorithms on Hadoop with Spark MLlib; and extensions to handle streaming data with frameworks such as Spark Streaming and Flink. The overall Hadoop ecosystem has continued to grow addressing more types of big data problems.

### MapReduce for the notes of the Unit 5 - Cloud Technologies And Advancements Hadoop in the subject of Cloud Computing

1. MapReduce is a programming model for processing large data sets with a parallel, distributed algorithm on a cluster.
2. It consists of two major tasks - Map and Reduce.
3. The Map task partitions the input data into chunks which are processed by the map tasks in parallel.
4. The Reduce task aggregates the output of the maps and produces the final output.
5. The key advantages of MapReduce are:
- Scalability: It can handle huge volumes of data by increasing the number of servers in the cluster.
- Fault Tolerance: It is fault tolerant and can handle server failures by re-allocating work to other servers.
- Simplicity: It hides the complex details of parallelization, fault-tolerance, data distribution and load balancing.

### Open Stack

- Open Stack is a free and open-source software platform for cloud computing, mostly deployed as infrastructure-as-a-service (IaaS).
- It allows businesses and organizations to control large pools of compute, storage, and networking resources throughout a data center which users can access through a web interface, command-line tools, or through its extensive API.
- Open Stack software components can be used to build public and private clouds, and telecom infrastructure.
- Open Stack consists of interrelated projects that control pools of processing, storage, and networking resources throughout a data center.
- The major components include:

- Nova (compute service) - creates and manages virtual machines and other compute resources
- Swift (object storage service) - scalable redundant storage system
- Glance (image service) - discovers, registers, and retrieves virtual machine images
- Keystone (identity service) - manages user accounts and authentication
- Neutron (networking service) -provides "network connectivity as a service" between interface devices managed by other Open Stack services
- Cinder (block storage service) - provides persistent block-level storage to running instances

- The services are not tightly coupled and are intended to be composed in flexible ways.
- Open Stack's goal is to give any organization the ability to create and offer cloud computing services running on standard hardware.
- It provides a flexible infrastructure for managing resources through a modular architecture with various plug-ins and add-ons available.

### Federation in the Cloud

- Cloud federation refers to the interconnection and collaboration between different cloud computing infrastructures to share resources and capabilities.
- It allows applications and data to be seamlessly transferred between the participating clouds. This increases resource utilization and availability.
- The key characteristics of cloud federation are:
-- Autonomy: Each participating cloud retains control over its resources.
-- Voluntary participation: Clouds join and leave the federation voluntarily.
-- Heterogeneity: Participating clouds can have different providers, architectures, and technologies.
-- Dynamism: The federation structure can change dynamically as clouds join or leave, or their loads and resources change.
- The benefits of cloud federation include:
-- Increased resource pool: The combined resources of participating clouds provide users with a larger resource pool.
-- Improved reliability: Resources from other clouds can be used when a cloud experiences temporary problems or failures. This improves reliability and availability.
-- Load balancing: Workloads can be transferred between clouds to balance loads and optimize performance.
-- Cost efficiency: Resources can be obtained from the most cost-efficient cloud based on factors like resource utilization and time of use.
- However, there are also challenges to cloud federation:
-- Technical challenges: Interoperability, monitoring, metering, and billing of resource usage across clouds.
-- Trust and security: Loss of control and visibility into how other clouds handle security and data protection. Establishing trust between participating clouds is difficult.
-- Business challenges: Determining fair pricing models and compensation between participating clouds. Cloud providers may not want to federate for competitive reasons.

### Four Levels of Federation for the notes of the Unit 5 - Cloud Technologies And Advancements Hadoop in the subject of Cloud Computing

1. Data level federation: Combining data from multiple sources into a unified view. This enables querying and analyzing data across sources.
2. Application level federation: Combining multiple applications or services into a single unified application or interface. This provides a single point of access for end users.
3. Process level federation: Combining multiple business processes or workflows into an integrated process. This enables seamless integration of cross-organizational processes.
4. Grid level federation: Combining computing resources from multiple administrative domains to create a single large-scale computing resource. This increases resource scalability and availability.

The above points highlight the four levels of federation which can help in scaling cloud technologies and advancing frameworks like Hadoop to handle larger volumes of data and more complex processing requirements.
