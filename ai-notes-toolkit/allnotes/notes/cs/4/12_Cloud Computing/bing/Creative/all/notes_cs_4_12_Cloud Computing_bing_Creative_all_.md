

## Unit 1 - Introduction To Cloud Computing

- Cloud computing is the delivery of computing services such as servers, storage, databases, networking, software, analytics, and intelligence over the internet.
- Cloud computing enables users to access and use computing resources on demand, without having to own or manage them.
- Cloud computing offers various benefits such as scalability, elasticity, cost-efficiency, reliability, security, and innovation.
- Cloud computing can be classified into three main service models: Infrastructure as a Service (IaaS), Platform as a Service (PaaS), and Software as a Service (SaaS).
- IaaS provides the basic computing infrastructure such as servers, storage, and networking, which users can rent and configure as per their needs.
- PaaS provides the platform and tools for developing and deploying applications, such as operating systems, databases, middleware, and frameworks, which users can use without having to manage the underlying infrastructure.
- SaaS provides the software applications that users can access and use over the internet, such as email, office, CRM, and ERP, which users do not have to install or maintain on their devices.
- Cloud computing can also be classified into four main deployment models: public cloud, private cloud, hybrid cloud, and community cloud.
- Public cloud is the cloud service that is available to anyone over the internet, and is owned and operated by a cloud service provider, such as Amazon Web Services, Microsoft Azure, or Google Cloud Platform.
- Private cloud is the cloud service that is dedicated to a single organization, and is owned and operated by the organization itself or a third party, such as IBM Cloud or Oracle Cloud.
- Hybrid cloud is the cloud service that combines public and private clouds, and allows data and applications to move between them, such as AWS Outposts or Azure Stack.
- Community cloud is the cloud service that is shared by a group of organizations that have common goals or interests, such as government agencies, research institutions, or non-profit organizations.



# Definition of Cloud

- Cloud computing is the **practice of using a network of remote servers hosted on the internet** to store, manage, and process data, rather than a local server or a personal computer .
- Cloud computing is also the **delivery of computing services**—including servers, storage, databases, networking, software, analytics, and intelligence—over the internet (“the cloud”) to offer faster innovation, flexible resources, and economies of scale.
- Cloud computing is the **on-demand availability of computing resources as services over the internet**. It eliminates the need for enterprises to procure, configure, or manage resources themselves, and allows them to pay only for what they use.
- Cloud computing is based on some form of **virtualized IT infrastructure**— servers, operating system software, networking, and other infrastructure that’s abstracted, using special software, so that it can be pooled and divided irrespective of physical hardware boundaries.



# Evolution of Cloud Computing

Cloud computing is the delivery of computing services such as servers, storage, databases, networking, software, analytics, and intelligence over the Internet. Cloud computing has evolved through various phases and technologies over the past decades. Here are some of the key milestones in the evolution of cloud computing:

- **The Idea Phase**: This phase incepted in the early 1960s with the emergence of utility and grid computing and lasted till pre-internet bubble era. Joseph Carl Robnett Licklider was the founder of cloud computing. He envisioned a network of interconnected computers that could access data and programs from anywhere. Utility computing is the concept of providing computing resources as a metered service, similar to a public utility. Grid computing is a computing infrastructure that pools computer resources from several geographic areas to achieve a common purpose.
- **The Virtualization Phase**: This phase started in the 1970s with the development of virtualization technology by IBM. Virtualization is the process of creating a virtual version of something, such as a server, a storage device, or a network. Virtualization allows multiple operating systems and applications to run on the same physical hardware, improving efficiency and flexibility. Virtualization also enabled the creation of virtual private networks (VPNs), which are secure connections between two or more devices over the Internet.
- **The Internet Phase**: This phase began in the 1990s with the advent of the Internet and the World Wide Web. The Internet enabled the widespread access and sharing of information and resources across the globe. The World Wide Web provided a platform for creating and hosting web applications and services. Some of the early examples of web-based cloud services are Hotmail, Amazon, and Salesforce. These services offered online email, e-commerce, and customer relationship management (CRM) respectively, without requiring users to install any software or hardware on their own devices.
- **The Cloud Phase**: This phase started in the 2000s with the emergence of cloud service providers such as Google, Microsoft, and IBM. These providers offered various types of cloud services, such as infrastructure as a service (IaaS), platform as a service (PaaS), and software as a service (SaaS). IaaS provides the basic computing resources, such as servers, storage, and networking. PaaS provides the development and deployment tools, such as operating systems, databases, and frameworks. SaaS provides the end-user applications, such as email, office, and social media. These services are delivered on-demand, scalable, and pay-per-use basis, reducing the cost and complexity of IT management for users.
- **The Future Phase**: This phase is ongoing and involves the development and adoption of new technologies and trends that enhance the capabilities and benefits of cloud computing. Some of the current and emerging trends are:

  - **Containers**: Containers are packaged applications, operating systems, and/or data that can be operated flexibly across different cloud environments. Containers isolate the application from the underlying infrastructure, improving portability, security, and performance.
  - **Serverless Computing**: Serverless computing is computing performed on managed infrastructure. It removes the need for users to provision, configure, and maintain servers. Users only pay for the execution time and resources consumed by their functions or applications. Serverless computing enables faster development, scalability, and cost-efficiency.
  - **Cloud Security**: As cloud computing becomes more prevalent and complex, cloud security becomes more important and challenging. Cloud security involves the protection of data, applications, and infrastructure from unauthorized access, modification, or destruction. Cloud security requires the collaboration of cloud providers, users, and third-party vendors. Some of the cloud security solutions include encryption, authentication, firewalls, and monitoring.
  - **Cloud Native**: Cloud native is an approach to designing and developing applications that are optimized for the cloud environment. Cloud native applications are built using microservices, containers, serverless, and other cloud technologies. Cloud native applications are scalable, resilient, and agile.
  - **Edge Computing**: Edge computing is the processing of data closer to the source or the user, rather than in a centralized cloud server. Edge computing reduces the latency, bandwidth, and cost of data transmission. Edge computing also enables real-time analysis and decision making for applications that require high performance and reliability, such as Internet of Things (IoT), artificial intelligence (AI), and augmented reality (AR).



# Underlying Principles of Parallel and Distributed Computing

- Parallel and distributed computing are two paradigms for enhancing the performance and scalability of complex applications by using multiple processors or computers to execute them concurrently .
- Parallel computing involves dividing a problem into smaller subproblems that can be solved simultaneously by multiple processors that share the same memory or communicate through a network .
- Distributed computing involves distributing a problem across multiple autonomous computers that communicate through a network and coordinate their actions to achieve a common goal .
- Parallel and distributed computing builds on fundamental systems concepts, such as concurrency, mutual exclusion, consistency in state/memory manipulation, message-passing, and shared-memory models  .
- Some of the benefits of parallel and distributed computing are:
  - Speedup: the ability to solve a problem faster by using more processors or computers .
  - Scalability: the ability to handle larger problems or more users by adding more processors or computers .
  - Fault tolerance: the ability to tolerate failures of some processors or computers without affecting the overall functionality .
  - Load balancing: the ability to distribute the workload evenly among the processors or computers to avoid bottlenecks or idle resources .
- Some of the challenges of parallel and distributed computing are:
  - Coordination: the need to synchronize and coordinate the actions of multiple processors or computers to ensure correctness and consistency .
  - Communication: the need to exchange data and messages among the processors or computers to facilitate cooperation and coordination .
  - Overhead: the extra cost of managing and maintaining the parallel or distributed system, such as communication, synchronization, scheduling, and fault detection .
  - Complexity: the increased difficulty of designing, developing, debugging, and testing parallel or distributed applications due to concurrency, distribution, heterogeneity, and dynamism .



# Cloud Characteristics

Cloud computing is a model for enabling convenient, on-demand network access to a shared pool of configurable computing resources (e.g., networks, servers, storage, applications, and services) that can be rapidly provisioned and released with minimal management effort or service provider interaction.

Some of the essential characteristics of cloud computing are:

- **On-demand self-service**: Users can request and access cloud services without human intervention from the cloud provider. For example, users can create, delete, or modify cloud resources such as virtual machines, storage, or applications using a web portal or an API .
- **Multi-tenancy and resource pooling**: Cloud providers use a multi-tenant architecture to accommodate multiple users on the same physical infrastructure, while isolating their data and applications from each other. The cloud resources are pooled and dynamically assigned and reassigned according to user demand. This enables efficient utilization of resources and economies of scale .
- **Broad network access**: Cloud services are accessible over the internet or other standard networks from various devices such as laptops, smartphones, tablets, etc. Users can access cloud services from anywhere and at any time, as long as they have network connectivity .
- **Rapid elasticity and scalability**: Cloud services can be scaled up or down quickly and automatically to meet the changing user demand. Users can access as much or as little resources as they need, and pay only for what they use. Cloud services can also handle peak loads and sudden spikes in demand without compromising performance or availability .
- **Measured service**: Cloud providers monitor and measure the usage of cloud resources by users, and charge them accordingly. Users can track and control their cloud consumption and costs through transparent and auditable billing mechanisms. Cloud providers can also optimize the allocation and utilization of resources based on the measured data .

Other benefits of cloud computing include:

- **Cost reduction**: Cloud computing eliminates the need for users to invest in and maintain their own IT infrastructure, such as hardware, software, power, cooling, security, etc. Users can save on capital expenditure (CAPEX) and operational expenditure (OPEX) by paying only for the cloud services they use .
- **Reliability**: Cloud computing offers high availability and fault tolerance by using multiple redundant servers, storage, and network devices across different geographic locations. Users can access cloud services even if one or more components fail or become unavailable. Cloud providers also offer backup and recovery options for data and applications in case of disasters .
- **Security**: Cloud computing provides various security measures to protect the data and applications of users from unauthorized access, modification, or deletion. These include encryption, authentication, authorization, firewalls, intrusion detection and prevention, etc. Cloud providers also comply with various security standards and regulations to ensure the privacy and confidentiality of user data .
- **Innovation**: Cloud computing enables users to access the latest technologies and capabilities without having to upgrade or replace their existing IT infrastructure. Users can leverage the cloud to experiment with new ideas, test new products, or launch new services faster and cheaper than before. Cloud computing also fosters collaboration and knowledge sharing among users and cloud providers .



# Elasticity in Cloud

- Elasticity in cloud computing is the ability to adapt to workload changes by provisioning and de-provisioning resources in an autonomic manner, such that at each point in time the available resources match the current demand as closely as possible.
- Elasticity is a defining characteristic that differentiates cloud computing from previously proposed computing paradigms, such as grid computing.
- Elasticity in cloud computing allows you to scale computer processing, memory, and storage capacity to meet changing demands.
- Elasticity in cloud computing can refer to 'cloudbursting' from on-premises infrastructure into the public cloud for example to meet a sudden or seasonal demand.
- Elasticity in cloud computing can also refer to the ability to grow or shrink the resources used by a cloud-based application.
- Elasticity in cloud computing has the following benefits:
  - It reduces the cost of over-provisioning or under-provisioning resources.
  - It improves the performance and availability of the application.
  - It enables the application to handle unpredictable or peak workloads.
  - It enhances the user experience and satisfaction.

- Elasticity in cloud computing is different from scalability in cloud computing:
  - Elasticity is used to meet the dynamic changes in the workload, while scalability is used to meet the static increase in the workload.
  - Elasticity is a short term planning and adopted by small companies, while scalability is a long term planning and adopted by giant companies.
  - Elasticity is more flexible and responsive, while scalability is more rigid and predictable.
  - Elasticity is more cost-effective and efficient, while scalability is more expensive and wasteful.



# On‐demand Provisioning

- On-demand provisioning is a feature of cloud computing that allows users to access and allocate cloud resources as and when they need them, without requiring human intervention or long-term commitment .
- On-demand provisioning enables cloud users to scale up or down their computing resources dynamically, depending on their workload and demand.
- On-demand provisioning also reduces the cost and complexity of managing cloud resources, as users only pay for what they use and do not have to worry about over-provisioning or under-provisioning.
- On-demand provisioning can be implemented in different ways, depending on the cloud service model and the cloud provider. Some examples are:
  - On-demand self-service: This is a service provided by cloud providers that enables users to provision cloud resources through an online control panel or an API, without requiring any approval or assistance from the provider . For example, users can create, delete, or resize virtual machines, storage, or databases on demand.
  - On-demand resource provisioning: This is a technique used by cloud providers to allocate cloud resources to users based on their estimated or actual load, and to release them when they are no longer needed. For example, cloud providers can use load balancing, auto-scaling, or elasticity mechanisms to adjust the number of servers, CPU, or memory available to users on demand.
  - On-demand provisioning in Azure Active Directory: This is a feature of Azure Active Directory that allows users to provision user accounts and groups from a source system (such as an on-premises Active Directory) to a target system (such as a cloud application) on demand, without requiring a scheduled synchronization . For example, users can provision a user account from their on-premises Active Directory to a cloud application when they sign in to the application for the first time.

# REST and Systems of Systems

## REST

- REST stands for REpresentational State Transfer and is an architectural style for providing standards between computer systems on the web .
- REST-compliant systems, often called RESTful systems, are characterized by how they are stateless and separate the concerns of client and server.
- RESTful systems use HTTP methods (such as GET, POST, PUT, DELETE) to perform operations on resources, which are identified by URIs.
- RESTful systems use a uniform and self-descriptive format to exchange data, such as JSON or XML.
- RESTful systems aim to improve scalability, performance, simplicity, modifiability, visibility, portability, and reliability.

## Systems of Systems

- Systems of systems is a collection of task-oriented or dedicated systems that pool their resources and capabilities together to create a new, more complex system which offers more functionality and performance than simply the sum of the constituent systems.
- Systems of systems can be classified into four types: directed, acknowledged, collaborative, and virtual.
- Directed systems of systems have a central authority that controls the operation and evolution of the constituent systems.
- Acknowledged systems of systems have a central authority that coordinates the operation and evolution of the constituent systems, but the constituent systems retain some autonomy and can operate independently.
- Collaborative systems of systems have no central authority, but the constituent systems voluntarily work together to achieve a common goal.
- Virtual systems of systems have no central authority and no pre-defined objective, but the constituent systems emerge and interact dynamically to respond to a situation.
- Systems of systems face challenges such as interoperability, emergence, evolution, governance, and security.

# Web Services

- Web services are software systems that support interoperable machine-to-machine interaction over a network .
- Web services are accessible via standard web protocols, such as HTTP or HTTPS.
- Web services have an interface that describes their functionality and input/output parameters in a machine-processable format, such as WSDL (Web Services Description Language).
- Web services can provide data in different formats, such as XML, JSON, or images .
- Web services are designed to communicate with other programs, rather than directly with users.
- Web services can be used independently of the hardware or software platform on which they are implemented, and independently of the programming language or technology used to create them.
- Web services can be composed of other web services to create complex and distributed applications.
- Web services can be classified into two types: SOAP (Simple Object Access Protocol) and REST (Representational State Transfer).
- SOAP web services use XML messages to exchange information between the service provider and the service consumer, and rely on a predefined contract (WSDL) to define the structure and semantics of the messages.
- REST web services use HTTP methods (GET, POST, PUT, DELETE) to perform operations on resources identified by URIs, and rely on a common understanding of the resource representation and state transitions.



# Publish, Subscribe Model

The publish, subscribe model is a software architecture model that enables distributed applications to communicate asynchronously and reliably. The publish, subscribe model involves the following components     :

- **Publishers**: The publishers are the applications that produce and send messages to a topic. A topic is a logical channel that categorizes the messages based on their content or purpose. Publishers do not need to know who will receive the messages or how they will be processed. Publishers can send messages to multiple topics.
- **Subscribers**: The subscribers are the applications that consume and process the messages from a topic. Subscribers do not need to know who sent the messages or how they were produced. Subscribers can receive messages from multiple topics. Subscribers can either pull the messages from the topic or push the messages to an endpoint.
- **Message Broker**: The message broker is the intermediary component that manages the topics and the message delivery between the publishers and the subscribers. The message broker ensures that the messages are stored, replicated, and delivered reliably and efficiently. The message broker also supports various features such as filtering, routing, security, and monitoring.

The publish, subscribe model has the following benefits   :

- **Decoupling**: The publishers and the subscribers are loosely coupled and do not depend on each other. This allows them to evolve independently and reduces the complexity and maintenance of the system.
- **Scalability**: The publish, subscribe model can handle high volumes of messages and traffic by adding more publishers, subscribers, or brokers. The message broker can also distribute the load across multiple nodes or regions.
- **Reliability**: The publish, subscribe model can ensure that the messages are delivered at least once, at most once, or exactly once, depending on the requirements and the configuration. The message broker can also handle failures and retries of the publishers or the subscribers.
- **Performance**: The publish, subscribe model can improve the performance and responsiveness of the system by enabling parallel and asynchronous processing of the messages. The publishers and the subscribers do not need to wait for each other or block the execution.
- **Flexibility**: The publish, subscribe model can support various types of messages and formats, such as text, binary, JSON, XML, etc. The message broker can also provide different options for filtering, routing, and transforming the messages based on the content or the metadata.

The publish, subscribe model is widely used in cloud computing and service oriented architecture, as it enables event-driven and microservices architectures. Some examples of cloud services that implement the publish, subscribe model are:

- **Amazon Simple Notification Service (SNS)**: A fully managed pub/sub messaging service that allows applications to send and receive notifications using topics and subscriptions. SNS supports various protocols and endpoints, such as HTTP, email, SMS, Lambda, etc.
- **Google Cloud Pub/Sub**: A fully managed pub/sub messaging service that allows applications to send and receive messages using topics and subscriptions. Pub/Sub supports various protocols and endpoints, such as HTTP, gRPC, Cloud Functions, etc.
- **Azure Service Bus**: A fully managed pub/sub messaging service that allows applications to send and receive messages using topics and subscriptions. Service Bus supports various protocols and endpoints, such as AMQP, HTTP, REST, Azure Functions, etc.
- **Apache Kafka**: A distributed streaming platform that allows applications to send and receive messages using topics and partitions. Kafka supports various protocols and endpoints, such as TCP, HTTP, REST, Kafka Streams, etc.



# Basics of Virtualization

Virtualization is a process that allows for more efficient utilization of physical computer hardware by creating multiple virtual environments that can run different operating systems and applications. Virtualization is the foundation of cloud computing, which enables the delivery of computing resources as a service over the internet.

There are different types of virtualization, depending on the level of abstraction and the hardware elements that are virtualized. Some of the common types of virtualization are:

- **Hardware virtualization**: This type of virtualization uses a software layer called a hypervisor to create virtual machines (VMs) that can run different operating systems and applications on the same physical machine. The hypervisor manages the allocation of hardware resources such as CPU, memory, disk, and network to the VMs. Hardware virtualization allows for the consolidation of multiple physical servers into fewer machines, reducing the cost and complexity of managing IT infrastructure.

- **Operating system virtualization**: This type of virtualization allows multiple instances of the same or different operating systems to run on the same physical machine, without the need for a hypervisor. Each instance, called a container, is isolated from the others and has its own file system, processes, and network interfaces. Operating system virtualization enables faster and more efficient deployment of applications, as containers can share the same kernel and libraries, reducing the overhead of loading and running them.

- **Application virtualization**: This type of virtualization allows applications to run on different platforms and devices, without requiring installation or configuration. Application virtualization can be achieved by different methods, such as:

  - Local application virtualization: The application runs on the endpoint device but in a runtime environment that isolates it from the underlying operating system and hardware. This allows the application to run on different devices and operating systems, without compatibility issues or conflicts with other applications.

  - Application streaming: The application lives on a server that sends small components of the software to run on the endpoint device, as needed. This reduces the bandwidth and storage requirements of the application, and allows for centralized management and updates.

  - Remote application virtualization: The application runs on a server and is accessed by the endpoint device through a remote display protocol. This allows the application to run on any device that has a network connection and a compatible client, regardless of the device's hardware or operating system.

Virtualization has many benefits for both users and providers of cloud computing services, such as:

- Improved performance and scalability: Virtualization allows for the optimal use of hardware resources, as virtual environments can be created, modified, and deleted on demand, according to the workload and user requirements. Virtualization also enables the distribution and balancing of workloads across multiple physical machines, improving the performance and availability of the services.

- Reduced cost and complexity: Virtualization reduces the need for purchasing and maintaining physical hardware, as well as the power and cooling costs associated with it. Virtualization also simplifies the management and administration of IT infrastructure, as virtual environments can be centrally monitored and controlled, and can be easily migrated, backed up, and restored.

- Enhanced security and reliability: Virtualization provides a layer of isolation and protection for the virtual environments, as they are separated from the physical hardware and from each other. Virtualization also enables the implementation of security policies and mechanisms at different levels, such as encryption, authentication, and access control. Virtualization also improves the reliability and availability of the services, as virtual environments can be easily replicated, recovered, and migrated in case of failures or disasters.

# Implementation Levels of Virtualization

Virtualization is the process of creating a virtual version of something, such as a hardware device, a software application, a network resource, or an operating system. Virtualization allows multiple virtual entities to share the same physical resources, such as CPU, memory, disk, and network, without interfering with each other. Virtualization can improve the efficiency, flexibility, scalability, and security of computing systems.

There are different levels of virtualization implementation, depending on how the virtualization is performed and what is being virtualized. The following are the five main levels of virtualization implementation:

- **Instruction Set Architecture Level (ISA)**: In this level, virtualization works through an ISA emulation. This means that the virtual machine (VM) emulates the instruction set of a different hardware architecture, such as x86, ARM, or MIPS. This allows the VM to run applications that are designed for a different hardware platform. For example, an x86 VM can run Windows applications on an ARM-based device. ISA level virtualization is the most flexible, but also the most resource-intensive and slowest level of virtualization.
- **Hardware Abstraction Level (HAL)**: In this level, virtualization works through a hardware abstraction layer. This means that the VM interacts with a virtual hardware device, such as a virtual disk, a virtual network card, or a virtual graphics card, instead of the physical hardware device. The virtual hardware device is then translated to the physical hardware device by the virtualization software. This allows the VM to run applications that are designed for the same hardware architecture, but with different hardware configurations. For example, a VM can run Linux applications on a Windows PC with a different disk layout or network interface. HAL level virtualization is less flexible, but more efficient and faster than ISA level virtualization.
- **Operating System Level**: In this level, virtualization works through an operating system abstraction layer. This means that the VM runs on top of a host operating system, and shares the same kernel and system resources with the host OS. The VM can run applications that are designed for the same operating system, but with different user environments and settings. For example, a VM can run a different version of Linux or Windows on the same host OS. Operating system level virtualization is also known as containerization, and it is the least flexible, but the most lightweight and fastest level of virtualization.
- **Library Level**: In this level, virtualization works through a library abstraction layer. This means that the VM runs on top of a host operating system, and uses a virtual library to access the system resources. The virtual library provides a common interface for different applications, regardless of the underlying operating system or hardware. For example, a VM can run Java applications on any platform that supports the Java Virtual Machine (JVM). Library level virtualization is also known as application virtualization, and it is mainly used for portability and compatibility purposes.
- **Application Level**: In this level, virtualization works through an application abstraction layer. This means that the VM runs on top of a host operating system, and uses a virtual application to access the system resources. The virtual application provides a specific functionality or service for different applications, regardless of the underlying operating system or hardware. For example, a VM can run web applications on any platform that supports a web browser. Application level virtualization is also known as service virtualization, and it is mainly used for scalability and security purposes.



# Virtualization Structures

Virtualization is a process that allows for more efficient utilization of physical computer hardware and is the foundation of cloud computing. Virtualization uses software to create an abstraction layer over computer hardware that allows the hardware elements of a single computer—processors, memory, storage and more—to be divided into multiple virtual machines (VMs) that can run different operating systems (OSes) and applications .

A virtualization architecture is a conceptual model of a virtual infrastructure that is most frequently applied in cloud computing. The architecture clearly specifies the arrangement and interrelationships among the particular components in the virtual environment. In cloud computing, virtualization facilitates the creation of virtual versions of hardware such as desktops, as well as virtual ecosystems for OS, storage, memory and networking resources . A virtualization architecture runs multiple OSes on the same machine using the same hardware and also ensures their smooth functioning.

There are different types of virtualization in cloud computing, such as:

- **Server virtualization**: This is the most common type of virtualization, where a physical server is partitioned into multiple VMs that can run different OSes and applications independently . Server virtualization improves the utilization of server resources, reduces power consumption and maintenance costs, and enables faster provisioning and scalability of applications .
- **Storage virtualization**: This is the process of pooling and abstracting multiple physical storage devices into a single logical storage unit that can be accessed by multiple VMs or applications . Storage virtualization improves the performance, availability, and manageability of storage resources, and enables data migration, backup, and recovery .
- **Network virtualization**: This is the process of combining and abstracting multiple physical network resources such as switches, routers, firewalls, and load balancers into a single logical network that can be configured and managed centrally . Network virtualization enhances the security, reliability, and scalability of network resources, and enables network isolation, segmentation, and automation .
- **Desktop virtualization**: This is the process of delivering a virtual desktop environment to a user's device, such as a laptop, tablet, or smartphone, over a network . Desktop virtualization decouples the user's OS, applications, and data from the physical device, and enables remote access, mobility, and personalization of the desktop experience .

Application virtualization simplifies the deployment, management, and compatibility of applications, and enables on-demand access, portability, and security of applications .



# Tools and Mechanisms for Service Oriented Architecture

Service Oriented Architecture (SOA) is an architectural style that enables the development and integration of software services that are loosely coupled, self-contained, and interoperable  . SOA supports the reuse of existing services to create new applications and workflows, as well as the adaptation and evolution of services to meet changing requirements  . SOA also facilitates the communication and collaboration among different service providers and consumers.

Some of the tools and mechanisms that are commonly used in SOA are:

- **Service interface**: A service interface defines the contract or specification of a service, including its inputs, outputs, operations, and policies. A service interface is typically expressed using a standard language such as Web Services Description Language (WSDL) or OpenAPI  .
- **Service registry**: A service registry is a repository that stores and publishes the metadata of available services, such as their names, locations, interfaces, and descriptions. A service registry enables service discovery and lookup by service consumers and other service providers. # Virtualization of CPU

- CPU virtualization is a technique that creates multiple versions of various system resources, including your CPU, server, storage, etc. 
- CPU virtualization involves a single CPU acting as if it were multiple separate CPUs. The most common reason for doing this is to run multiple different operating systems on one machine. 
- CPU virtualization emphasizes performance and runs directly on the available CPUs whenever possible. 
- CPU virtualization is one of the cloud-computing technologies that requires a single CPU to work, which acts as multiple machines working together. 
- CPU virtualization can be classified into two types: full virtualization and paravirtualization. 
- Full virtualization allows the guest operating system to run unmodified on the virtual machine, as if it were running on a physical machine. The virtualization software (hypervisor) intercepts and emulates the instructions that require privileged access from the guest operating system. 
- Paravirtualization requires the guest operating system to be modified to run on the virtual machine. The guest operating system is aware of the virtualization and communicates directly with the hypervisor, avoiding the need for emulation. Paravirtualization can offer better performance and efficiency than full virtualization. 
- CPU virtualization can be enabled in the BIOS settings of the computer. The steps may vary depending on the manufacturer and model of the computer, but generally involve accessing the Advanced Mode option, finding and selecting CPU configuration, and choosing Enabled for the virtualization feature.  
- CPU virtualization can provide various benefits, such as:
  - Increased utilization and efficiency of the CPU resources. 
  - Reduced costs and energy consumption by consolidating multiple physical machines into one. 
  - Enhanced security and isolation of the virtual machines. 
  - Improved scalability and flexibility of the computing environment. 
  - Easier backup and recovery of the virtual machines. 
  - Access to a larger library of apps and operating systems.

This eliminates the need for having identical hardware at the primary and secondary disaster recovery sites, and allows for more flexibility and scalability in disaster recovery planning and testing.
  - Maintain business continuity: Virtualization helps ensure that the critical business functions and applications can continue to operate in the event of a disaster, by storing the data and VMs in the cloud servers or in a remote location. This minimizes the impact of the disaster on the business operations and customers, and reduces the risk of revenue loss and reputation damage.

## Cloud Architecture

- Cloud architecture is the way technology components combine to build a cloud, in which resources are pooled through virtualization technology and shared across a network.
- Cloud architecture enables organizations to reduce or eliminate their reliance on on-premises server, storage, and networking infrastructure.
- The components of a cloud architecture include:
  - A front-end platform (the client or device used to access the cloud)
  - A back-end platform (servers and storage)
  - A cloud-based delivery (the network that connects the front-end and the back-end)
  - A cloud service (the software or application that runs on the cloud)
- Cloud architecture can be classified into two types:
  - Service Oriented Architecture (SOA): A design pattern that allows services to communicate with each other through standardized interfaces and protocols.
  - Event Driven Architecture (EDA): A design pattern that allows services to react to events or messages from other services or sources.

## Cloud Services

- Cloud services are the software or applications that run on the cloud and provide various functionalities to the users or customers.
- Cloud services can be categorized into three types based on the level of abstraction and control they offer:
  - Infrastructure as a Service (IaaS): The most basic type of cloud service that provides access to raw computing resources such as servers, storage, and networks. The user is responsible for managing and configuring the resources.
  - Platform as a Service (PaaS): A type of cloud service that provides a platform for developing, testing, and deploying applications. The user does not have to worry about the underlying infrastructure, but only the application code and configuration.
  - Software as a Service (SaaS): The most advanced type of cloud service that provides ready-to-use applications that run on the cloud. The user does not have to install, maintain, or update the applications, but only access them through a web browser or a mobile app.
- Cloud services can also be categorized into four types based on the deployment model they use:
  - Public cloud: A cloud service that is available to anyone over the internet and is owned and operated by a third-party provider.
  - Private cloud: A cloud service that is dedicated to a single organization and is either hosted on-premises or off-premises by a provider.
  - Hybrid cloud: A cloud service that combines public and private clouds and allows data and applications to move between them.
  - Multi-cloud: A cloud service that uses multiple public clouds from different providers and optimizes the performance, cost, and reliability of each cloud.

## Cloud Storage

- Cloud storage is a type of cloud service that provides scalable, durable, and accessible storage for data in the cloud.
- Cloud storage can store different types of data, such as text, binary, structured, unstructured, or big data .
- Cloud storage can offer various benefits, such as:
  - Cost efficiency: Cloud storage can reduce the capital and operational expenses of buying and maintaining storage hardware and software.
  - Scalability: Cloud storage can easily adjust to the changing storage needs of the users and provide unlimited capacity on demand.
  - Durability: Cloud storage can protect the data from hardware failures, natural disasters, or human errors by replicating and backing up the data across multiple locations.
  - Accessibility: Cloud storage can allow the users to access the data from anywhere and any device through the internet or a dedicated network connection.
  - Security: Cloud storage can encrypt the data in transit and at rest and provide various authentication and authorization mechanisms to control the access to the data.
- Cloud storage can be classified into four types based on the data model they use:
  - Blob storage: A type of cloud storage that stores unstructured data, such as images, videos, or documents, as binary large objects (blobs).
  - File storage: A type of cloud storage that stores structured data, such as spreadsheets, databases, or code, as files in a hierarchical folder structure.
  - Queue storage: A type of cloud storage that stores messages or events that need to be processed by other services or applications in a first-in, first-out (FIFO) order.
  - Table storage: A type of cloud storage that stores semi-structured data, such as user profiles, product catalogs, or logs, as key-value pairs in a table format.



# Layered Cloud Architecture Design

Cloud computing is a paradigm that enables the delivery of computing resources as services over the internet. Cloud computing is based on a layered architecture that consists of several components and layers. The following are the main layers of cloud architecture:

- **Physical layer**: This is the lowest layer of the cloud architecture that provides the physical infrastructure such as servers, storage, network devices, power, cooling, etc. The physical layer is responsible for hosting and maintaining the hardware resources that are shared by multiple cloud users and providers. The physical layer is usually located in data centers that are distributed across different geographical locations.

- **Virtualization layer**: This is the layer that creates and manages the virtual machines (VMs) that run on the physical layer. Virtualization is a technique that allows the abstraction and isolation of the physical resources, such that multiple VMs can run on the same physical machine without interfering with each other. Virtualization also enables the dynamic allocation and deallocation of resources to the VMs based on the demand and availability. The virtualization layer is implemented by software such as hypervisors, virtual machine monitors, or operating systems.

- **Infrastructure as a Service (IaaS) layer**: This is the layer that provides the basic computing resources such as CPU, memory, disk, network, etc. as services to the cloud users. The IaaS layer allows the users to create, configure, and manage their own VMs on the cloud, and to access them through a web interface or an application programming interface (API). The IaaS layer is also responsible for providing security, scalability, reliability, and availability of the resources. Examples of IaaS providers are Amazon Web Services, Microsoft Azure, Google Cloud Platform, etc.

- **Platform as a Service (PaaS) layer**: This is the layer that provides the development and deployment environment for cloud applications. The PaaS layer offers various tools and services such as programming languages, frameworks, libraries, databases, middleware, etc. that enable the developers to create and run their applications on the cloud without worrying about the underlying infrastructure. The PaaS layer also provides features such as load balancing, auto-scaling, monitoring, testing, etc. that enhance the performance and quality of the applications. Examples of PaaS providers are Google App Engine, Microsoft Azure App Service, Heroku, etc.

- **Software as a Service (SaaS) layer**: This is the layer that provides the end-user applications that run on the cloud. The SaaS layer allows the users to access and use the applications through a web browser or a mobile device, without installing or maintaining them on their own devices. The SaaS layer also handles the updates, patches, backups, etc. of the applications. Examples of SaaS providers are Google Workspace, Microsoft Office 365, Salesforce, etc.

# NIST Cloud Computing Reference Architecture

The NIST Cloud Computing Reference Architecture (NIST SP 500-292) is a document that provides a common framework and terminology for describing the essential components and interactions of cloud computing systems. It is intended to facilitate communication and understanding among cloud stakeholders, such as cloud service providers, consumers, brokers, auditors, and carriers  .

The NIST Cloud Computing Reference Architecture consists of five major components :

- **Cloud Consumer**: The entity that uses cloud services to support its business or organizational goals. The cloud consumer can be a person or an organization that accesses the cloud services through various interfaces, such as web browsers, mobile devices, or APIs. The cloud consumer can also manage its cloud service usage, such as provisioning, monitoring, and billing, through a cloud service management interface provided by the cloud provider or broker.
- **Cloud Provider**: The entity that provides cloud services to cloud consumers. The cloud provider can offer different types of cloud services, such as infrastructure as a service (IaaS), platform as a service (PaaS), software as a service (SaaS), or function as a service (FaaS). The cloud provider can also offer different deployment models, such as public, private, community, or hybrid clouds. The cloud provider is responsible for managing the physical and virtual resources that support the cloud services, as well as ensuring the security, performance, availability, and reliability of the cloud services.
- **Cloud Broker**: The entity that intermediates between cloud consumers and cloud providers. The cloud broker can offer various value-added services, such as cloud service aggregation, integration, customization, arbitrage, or governance. The cloud broker can also help cloud consumers to select the best cloud service offerings that meet their requirements, negotiate the service level agreements (SLAs) with cloud providers, and monitor the quality of service (QoS) of the cloud services.
- **Cloud Auditor**: The entity that conducts independent assessments of cloud services, information systems, or controls of cloud providers or consumers. The cloud auditor can perform various types of audits, such as security audits, privacy audits, performance audits, or compliance audits. The cloud auditor can also verify the conformance of cloud services to standards, best practices, or regulations. The cloud auditor can provide assurance, attestation, or certification to cloud stakeholders regarding the quality, security, or compliance of cloud services.
- **Cloud Carrier**: The entity that provides connectivity and transport of cloud services between cloud consumers and cloud providers. The cloud carrier can be a network service provider, a telecommunication service provider, or an internet service provider. The cloud carrier can also offer value-added network services, such as encryption, caching, or routing, to enhance the security, performance, or availability of cloud services.

The NIST Cloud Computing Reference Architecture also defines a set of roles and activities for each component, as well as a set of reference scenarios that illustrate how the components interact in different cloud service models and deployment models.

The NIST Cloud Computing Reference Architecture is not a prescriptive or normative standard, but rather a descriptive and informative guide that can be adapted and extended by cloud stakeholders to suit their specific needs and contexts . It is also not a complete or comprehensive architecture, but rather a high-level and abstract architecture that focuses on the essential aspects of cloud computing. The NIST Cloud Computing Reference Architecture is intended to complement and align with other cloud computing standards and frameworks, such as the ISO/IEC 17788, ISO/IEC 17789, and ITU-T Y.3500 series .

## Introduction

Cloud computing is a model of delivering computing resources and services over the internet, on demand and pay-per-use basis. Cloud computing can offer various benefits to organizations, such as scalability, flexibility, cost-efficiency, and innovation. However, not all cloud environments are the same. There are three main types of cloud deployment models: public, private, and hybrid clouds. Each of these models has its own advantages and disadvantages, depending on the specific needs and goals of the organization.

## Public Cloud

A public cloud is a cloud environment that is accessible over the internet and shared by multiple organizations or users. The public cloud provider owns and manages the cloud infrastructure and services, and offers them to the customers on a self-service basis. The customers do not have to worry about the maintenance, security, or scalability of the cloud resources, as they are handled by the provider. The customers only pay for the resources and services they use, and can access them from anywhere and any device.

Some of the benefits of public cloud are:

- Low upfront cost: The customers do not have to invest in purchasing, installing, or managing any hardware or software for the cloud. They can simply use the cloud services as they need them, and pay as they go.
- High scalability: The customers can easily scale up or down their cloud resources and services, depending on their demand and workload. The public cloud provider can offer virtually unlimited capacity and availability, as they have a large pool of resources across multiple data centers.
- Wide range of services: The customers can access a variety of cloud services from the public cloud provider, such as compute, storage, networking, database, analytics, artificial intelligence, and more. The customers can also leverage the latest technologies and innovations that the provider offers, without having to update or upgrade their own systems.
- Ease of use: The customers can access the cloud services through a web browser or an application programming interface (API), and use them with minimal technical knowledge or skills. The public cloud provider also offers user-friendly tools and interfaces for managing and monitoring the cloud resources and services.

Some of the challenges of public cloud are:

- Security and privacy: The customers have to trust the public cloud provider with their sensitive data and applications, as they are stored and processed on the provider's servers. The customers have to comply with the provider's security policies and practices, and may have limited control or visibility over their data and applications. The customers also have to share the cloud resources and services with other users, which may increase the risk of cyberattacks, data breaches, or unauthorized access.
- Performance and reliability: The customers may experience latency or downtime issues, as they access the cloud services over the internet, which may be affected by network congestion, bandwidth limitations, or outages. The customers also have to rely on the public cloud provider's service level agreements (SLAs), which may not guarantee the desired level of performance or availability for the cloud services.
- Vendor lock-in: The customers may face difficulties in migrating or integrating their data and applications from one public cloud provider to another, or to a different cloud model, as they may use different standards, formats, or protocols. The customers may also become dependent on the specific features or functionalities of the public cloud provider, and lose the flexibility or interoperability of their cloud solutions.

A private cloud is a cloud environment that is dedicated to a single organization or user. The private cloud can be hosted either on the organization's own premises, or on a third-party provider's data center. The organization owns and manages the cloud infrastructure and services, and can customize them to meet their specific requirements and preferences. The organization can also control the access and security of the cloud resources and services, and ensure their compliance with their own policies and regulations.

Some of the benefits of private cloud are:

# Architectural Design Challenges

Cloud computing is the delivery of computing services such as servers, storage, databases, networking, software, analytics, and intelligence over the internet. Cloud computing architecture consists of two main components: the front end and the back end. The front end is the interface that the users interact with, such as web browsers, mobile apps, or desktop applications. The back end is the collection of servers, storage, databases, and other resources that provide the computing services. The front end and the back end are connected by a network, usually the internet, and communicate through a set of protocols and standards.

Cloud computing architecture faces several challenges in terms of design, implementation, and management. Some of these challenges are:

- **Scalability**: Cloud computing architecture should be able to scale up or down according to the demand and workload of the users. Scalability can be achieved by adding or removing resources, such as servers, storage, or network bandwidth, dynamically and automatically. Scalability can also be achieved by distributing the workload across multiple resources, such as load balancing, caching, or partitioning.

- **Reliability**: Cloud computing architecture should be able to provide consistent and uninterrupted service to the users, even in the case of failures, errors, or disasters. Reliability can be achieved by designing the architecture with redundancy, fault tolerance, backup, and recovery mechanisms. Reliability can also be achieved by monitoring the performance and health of the resources, and detecting and resolving issues quickly.

- **Security**: Cloud computing architecture should be able to protect the data and applications of the users from unauthorized access, modification, or disclosure. Security can be achieved by implementing encryption, authentication, authorization, and auditing techniques. Security can also be achieved by complying with the regulations and standards of the industry and the government.

- **Interoperability**: Cloud computing architecture should be able to communicate and integrate with other systems and platforms, such as legacy systems, on-premises systems, or other cloud providers. Interoperability can be achieved by using common protocols, standards, and formats, such as REST, SOAP, JSON, or XML. Interoperability can also be achieved by using adapters, gateways, or brokers that translate and mediate between different systems.

- **Cost**: Cloud computing architecture should be able to optimize the cost and benefit of using the cloud services. Cost can be optimized by selecting the appropriate service model, such as infrastructure as a service (IaaS), platform as a service (PaaS), or software as a service (SaaS), and the appropriate deployment model, such as public cloud, private cloud, or hybrid cloud. Cost can also be optimized by using the pay-as-you-go pricing model, where the users only pay for the resources they use, and by using the elasticity and automation features of the cloud.

- **Complexity**: Cloud computing architecture should be able to manage the complexity and diversity of the cloud environment, such as the variety of services, resources, providers, and users. Complexity can be managed by using design patterns, best practices, and frameworks that provide guidance and solutions for common problems and scenarios. Complexity can also be managed by using tools and platforms that simplify and automate the development, deployment, and operation of the cloud applications.

# Advantages of Cloud Storage

Cloud storage is a service that allows users to store and access data on remote servers over the internet, rather than on local devices. Cloud storage has many advantages for both individuals and organizations, such as:

- **Usability and accessibility**: Cloud storage enables users to access their data from any device and any location, as long as they have an internet connection. This makes it easier to share and collaborate on files, as well as to backup and restore data in case of device failure or loss .
- **Security**: Cloud storage providers use various methods to protect the data stored on their servers, such as encryption, authentication, firewalls, and backup systems. These methods can offer a higher level of security than storing data on local devices, which can be vulnerable to theft, damage, or malware .
- **Cost-efficiency**: Cloud storage can reduce the costs of data storage for users, as they only pay for the amount of storage they use, rather than investing in expensive hardware and maintenance. Cloud storage also eliminates the need for data migration, duplication, or synchronization, as the data is always updated and accessible on the cloud .
- **Scalability**: Cloud storage can easily adapt to the changing needs of users, as they can increase or decrease their storage capacity on demand, without affecting the performance or availability of their data. Cloud storage also offers unlimited storage space, unlike local devices, which have finite and fixed capacities .
- **Disaster recovery**: Cloud storage can help users recover their data in case of natural disasters, power outages, or human errors, as the data is replicated and stored on multiple servers in different locations. Cloud storage also offers automatic backup and restore features, which can save time and resources for users .
- **Support**: Cloud storage providers offer technical support and customer service to their users, which can help them troubleshoot any issues or problems they may encounter with their data or the service. Cloud storage providers also update and upgrade their systems and software regularly, which can improve the functionality and security of their service .

# S3

S3 stands for Simple Storage Service, and it is a cloud object storage solution provided by Amazon Web Services (AWS). S3 allows users to store and retrieve any amount of data from anywhere on the internet, using a web services interface. S3 is designed for durability, availability, scalability, and performance. Some of the features and benefits of S3 are:

- **Object storage**: S3 stores data as objects, which consist of data and metadata. Objects are identified by unique keys, which are composed of a bucket name and an object name. Buckets are containers for objects, and they can be configured with different settings, such as access control, encryption, versioning, lifecycle policies, etc. S3 supports various types of objects, such as standard, intelligent-tiering, infrequent access, one zone-infrequent access, glacier, and deep archive.
- **Data lake**: S3 can be used as a data lake, which is a centralized repository for storing structured and unstructured data from various sources, such as applications, databases, IoT devices, etc. S3 can integrate with other AWS services, such as Athena, Redshift, EMR, Glue, etc., to enable data analysis, processing, and transformation. S3 can also support multiple data formats, such as CSV, JSON, Parquet, ORC, etc.
- **Backup and restore**: S3 can be used as a backup and restore solution, which can protect data from accidental deletion, corruption, or disaster. S3 can enable cross-region replication, which can automatically copy objects across different AWS regions for redundancy and compliance. S3 can also enable versioning, which can keep multiple versions of an object in the same bucket. S3 can also enable lifecycle policies, which can automatically move objects to different storage classes based on their age and access patterns, to optimize cost and performance.
- **Archival**: S3 can be used as an archival solution, which can store data that is rarely accessed or needs to be retained for a long time. S3 offers two storage classes for archival purposes: Glacier and Deep Archive. Glacier is designed for data that is accessed once or twice a year, and it has a retrieval time of minutes to hours. Deep Archive is designed for data that is accessed once a year or less, and it has a retrieval time of 12 hours. Both storage classes offer low-cost storage and high durability.
- **Mobile applications**: S3 can be used as a mobile application solution, which can store and serve data for mobile devices, such as photos, videos, documents, etc. S3 can integrate with other AWS services, such as Cognito, Amplify, AppSync, etc., to enable authentication, authorization, synchronization, and offline access. S3 can also enable transfer acceleration, which can speed up data transfers by using edge locations of the AWS network.
- **ML, AI, and analytics**: S3 can be used as a ML, AI, and analytics solution, which can store and access data for machine learning, artificial intelligence, and analytics applications. S3 can integrate with other AWS services, such as SageMaker, Rekognition, Comprehend, etc., to enable data labeling, training, inference, and evaluation. S3 can also enable S3 Select and S3 Glacier Select, which can query and retrieve specific data from objects without downloading the entire object, to improve performance and reduce cost.

## Resource Management in Cloud
- Resource management in cloud is the process of allocating, monitoring, and optimizing the use of cloud resources such as compute, storage, network, and applications.
- Resource management in cloud aims to achieve the following objectives:
  - Maximize the performance and availability of cloud services and applications.
  - Minimize the cost and waste of cloud resources.
  - Ensure the compliance and security of cloud resources.
- Resource management in cloud involves the following tasks:
  - Resource provisioning: The process of creating, configuring, and deploying cloud resources according to the user's requirements and specifications.
  - Resource scaling: The process of adjusting the capacity and performance of cloud resources according to the changing workload and demand.
  - Resource monitoring: The process of collecting, analyzing, and reporting the metrics and status of cloud resources such as utilization, performance, availability, and health.
  - Resource optimization: The process of applying policies, rules, and algorithms to improve the efficiency and effectiveness of cloud resources such as load balancing, auto-scaling, and resource pooling.
  - Resource governance: The process of defining, enforcing, and auditing the policies, standards, and best practices for cloud resource management such as access control, security, compliance, and quality of service.

## Security in Cloud
- Security in cloud is the process of protecting the confidentiality, integrity, and availability of cloud resources, data, and applications from unauthorized access, modification, or destruction.
- Security in cloud aims to achieve the following objectives:
  - Prevent and mitigate the risks and threats of cyberattacks, data breaches, and malicious insiders.
  - Ensure the compliance and accountability of cloud providers and users with the relevant laws, regulations, and standards.
  - Enhance the trust and confidence of cloud users and customers in the cloud services and applications.
- Security in cloud involves the following tasks:
  - Security assessment: The process of identifying and evaluating the security risks and vulnerabilities of cloud resources, data, and applications.
  - Security design: The process of applying the security principles and best practices to the architecture and configuration of cloud resources, data, and applications.
  - Security implementation: The process of deploying and integrating the security tools and controls to the cloud resources, data, and applications such as encryption, authentication, authorization, firewall, antivirus, and intrusion detection and prevention systems.
  - Security monitoring: The process of collecting, analyzing, and reporting the security events and incidents of cloud resources, data, and applications such as logs, alerts, and audits.
  - Security response: The process of responding and recovering from the security events and incidents of cloud resources, data, and applications such as incident management, forensics, and remediation.



# Inter Cloud Resource Management

Inter cloud resource management is the process of managing the resources of multiple clouds that are interconnected and interdependent. Inter cloud resource management aims to optimize the performance, cost, availability, and security of cloud services by dynamically allocating and releasing resources across different clouds.

Some of the challenges and benefits of inter cloud resource management are:

- Challenges:
  - Interoperability: Different clouds may have different APIs, protocols, standards, and architectures, which make it difficult to communicate and exchange data and services among them.
  - Security: Inter cloud resource management involves sharing sensitive data and resources across different clouds, which may have different security policies, mechanisms, and levels of trust.
  - Quality of Service: Inter cloud resource management has to ensure that the quality of service requirements of the cloud users and providers are met, such as latency, bandwidth, reliability, availability, and scalability.
  - Governance: Inter cloud resource management has to deal with the legal, regulatory, and contractual issues that arise from using multiple clouds, such as data sovereignty, privacy, compliance, and liability.
- Benefits:
  - Scalability: Inter cloud resource management can increase the scalability of cloud services by using the resources of multiple clouds to handle peak demands and unexpected failures.
  - Cost-efficiency: Inter cloud resource management can reduce the cost of cloud services by using the resources of the most suitable and cheapest clouds according to the user's preferences and needs.
  - Availability: Inter cloud resource management can improve the availability of cloud services by using the resources of multiple clouds to provide backup and redundancy in case of failures or disasters.
  - Diversity: Inter cloud resource management can offer more diversity and choice of cloud services by using the resources of different clouds that have different features, capabilities, and specialties.

Some of the types and examples of inter cloud resource management are:

- Types:
  - Federation Clouds: A federation cloud is a type of inter cloud where several cloud service providers voluntarily link their cloud infrastructures together to exchange resources. Cloud service providers in the federation trade resources in an open manner, and may have common goals, policies, and standards.
  - Brokerage Clouds: A brokerage cloud is a type of inter cloud where a third-party broker mediates the resource exchange between different cloud service providers and users. The broker acts as an intermediary that matches the supply and demand of resources, and may provide value-added services, such as negotiation, arbitration, and optimization.
  - Multi-Clouds: A multi-cloud is a type of inter cloud where a cloud user or provider uses the resources of multiple clouds simultaneously or sequentially to achieve a specific goal. The cloud user or provider may have different reasons to use multiple clouds, such as performance, cost, availability, security, or compliance.
- Examples:
  - Inter-Cloud Initiatives: There are several research and development projects that aim to create inter cloud platforms and frameworks, such as OPTIMUS, Contrail, MOSAIC, STRATOS, and Intercloud . These initiatives leverage multi-cloud services and address various aspects of inter cloud resource management, such as interoperability, security, quality of service, and governance.
  - Multi-Cloud Libraries: There are also several software libraries that enable cloud users and providers to use multiple clouds in a consistent and transparent way, such as Apache Libcloud, jclouds, Fog, and Deltacloud. These libraries provide a uniform cloud API that abstracts the differences among different clouds and allows the users and providers to create their own brokers.



# Resource Provisioning

Resource provisioning is the process of allocating, deploying, and managing the computing, storage, network, and software resources in a cloud environment. Resource provisioning aims to optimize the performance, availability, scalability, and cost-efficiency of cloud services.

Some of the key concepts and techniques related to resource provisioning are:

- **Resource demand**: The amount and type of resources required by a cloud service or application to meet the service level objectives (SLOs) and quality of service (QoS) expectations of the users and providers.
- **Resource capacity**: The amount and type of resources available in a cloud environment to serve the resource demand. Resource capacity can be static or dynamic, depending on the cloud deployment model and the resource provisioning strategy.
- **Resource allocation**: The process of assigning resources to cloud services or applications based on the resource demand and capacity. Resource allocation can be static or dynamic, depending on the resource provisioning strategy.
- **Resource scheduling**: The process of determining the order and timing of resource allocation and deallocation for cloud services or applications. Resource scheduling can be based on various criteria, such as priority, deadline, cost, or load balancing.
- **Resource scaling**: The process of adjusting the amount and type of resources allocated to cloud services or applications based on the changes in resource demand and capacity. Resource scaling can be horizontal or vertical, and proactive or reactive, depending on the resource provisioning strategy.
- **Resource elasticity**: The ability of a cloud service or application to automatically scale the resources up or down according to the resource demand and capacity. Resource elasticity is a desirable property of cloud computing that enables efficient and flexible resource utilization and cost saving.
- **Resource reservation**: The process of reserving resources in advance for cloud services or applications that have predictable or periodic resource demand. Resource reservation can reduce the risk of resource contention and improve the performance and reliability of cloud services or applications.
- **Resource overcommitment**: The process of allocating more resources than the available resource capacity to cloud services or applications that have variable or bursty resource demand. Resource overcommitment can increase the resource utilization and cost-efficiency of cloud services or applications, but it also introduces the risk of resource contention and performance degradation.
- **Resource migration**: The process of moving resources from one location to another in a cloud environment to optimize the resource provisioning. Resource migration can be triggered by various factors, such as load balancing, fault tolerance, energy efficiency, or data locality.



# Resource Provisioning Methods

Resource provisioning is the process of allocating and managing cloud resources to meet the needs and demands of cloud consumers. Resource provisioning methods are the techniques and strategies used to provision resources in cloud computing. Some of the common resource provisioning methods are:

- **Static provisioning or advance provisioning**: This method involves reserving a fixed amount of resources for a specific period of time, regardless of the actual usage or demand. Static provisioning can be used successfully for applications with known and typically constant workloads. However, it may lead to underutilization or overutilization of resources, depending on the fluctuations in demand. Static provisioning is also less flexible and scalable than dynamic provisioning .

- **Dynamic provisioning or on-demand provisioning**: This method involves adding or removing resources as needed, based on the current demand and usage. Dynamic provisioning allows for more flexibility and scalability, as well as better resource utilization and cost efficiency. However, it may also introduce challenges such as resource contention, performance degradation, and security risks. Dynamic provisioning requires effective monitoring and management tools to ensure optimal resource allocation and service quality .

- **Adaptive provisioning or self-adaptive provisioning**: This method involves using artificial intelligence and machine learning techniques to automatically adjust the resource allocation according to the changing conditions and requirements. Adaptive provisioning aims to achieve self-optimization, self-healing, and self-protection of cloud resources and services. Adaptive provisioning can enhance the performance, reliability, and security of cloud computing, as well as reduce the human intervention and errors. However, it may also require complex algorithms and models, as well as high computational and communication overheads .

# Security Overview

Security is one of the major concerns in cloud computing, as it involves storing and processing sensitive data and applications on shared and distributed platforms. Cloud security aims to protect the confidentiality, integrity, and availability of cloud resources and services from various threats and risks.

Some of the key aspects of cloud security are:

- **Confidentiality**: The ability to keep information secret from unauthorized parties. This can be achieved by using encryption, access control, authentication, and authorization mechanisms.
- **Integrity**: The ability to ensure that data and systems are not tampered with or corrupted by malicious or accidental actions. This can be achieved by using hashing, digital signatures, checksums, and audit logs.
- **Availability**: The ability to ensure that cloud services and resources are accessible and functional at all times. This can be achieved by using redundancy, backup, recovery, load balancing, and fault tolerance techniques.

Cloud security also involves complying with various standards and regulations that govern the protection of data and privacy, such as GDPR, HIPAA, PCI DSS, etc.

Cloud security can be divided into two categories:

- **Cloud provider security**: The security measures and controls that the cloud service provider (CSP) implements to protect its infrastructure, platform, and software from external and internal attacks. This includes physical security, network security, host security, application security, data security, etc.
- **Cloud customer security**: The security measures and controls that the cloud service customer (CSC) implements to protect its data and applications that are hosted on the cloud. This includes data encryption, identity and access management, firewall, antivirus, etc.

Cloud security requires a shared responsibility model between the CSP and the CSC, where each party is accountable for securing its own domain and collaborating with the other party to ensure end-to-end security. The level of responsibility depends on the type of cloud service model, such as IaaS, PaaS, or SaaS. For example, in IaaS, the CSP is responsible for securing the infrastructure, while the CSC is responsible for securing the operating system, middleware, applications, and data. In SaaS, the CSP is responsible for securing the entire stack, while the CSC is responsible for securing the user access and data.



# Cloud Security Challenges

Cloud security challenges are the potential risks and threats that arise from using cloud computing services and platforms. Cloud security challenges can affect the confidentiality, integrity, and availability of the data and applications stored and processed in the cloud. Some of the common cloud security challenges are:

- **Less visibility and lack of control**: When using cloud-based technologies, the user can make the required servers function without having to manage it directly. However, this also means that the user has less visibility and control over the cloud infrastructure and operations, which can increase the risk of unauthorized access, misconfiguration, and data leakage.
- **Non-compliance with regulatory requirements**: Cloud computing involves the transfer and storage of data across different locations and jurisdictions, which can pose challenges for complying with various legal and regulatory requirements. For example, some data protection laws may require the user to obtain consent from the data subjects before transferring their personal data to another country or region. The user also needs to ensure that the cloud service provider complies with the relevant standards and frameworks for data security and privacy, such as ISO 27001, GDPR, HIPAA, etc.
- **Concerns of data breach and data privacy**: One of the most important challenges of cloud security is the risk of data breaches and issues of data privacy. Before the entry of advanced technologies such as the Cloud, the IT team of every organization had control and hold over the network structure and systems. However, with the cloud, the user has to share the responsibility of data security and privacy with the cloud service provider, who may have access to the user's sensitive and confidential data. Moreover, the cloud environment can be vulnerable to cyberattacks, such as phishing, ransomware, denial-of-service, etc., that can compromise the data and applications in the cloud .
- **Alerts in situations of data breaches**: Another challenge of cloud security is the detection and response to data breaches and incidents in the cloud. The user needs to have effective mechanisms and tools to monitor the cloud activities and events, and to receive timely alerts and notifications in case of any anomalies or suspicious behaviors. The user also needs to have a clear and coordinated incident response plan with the cloud service provider, and to report and disclose the data breaches to the relevant authorities and stakeholders.
- **Access control to users**: Access control is a key aspect of cloud security, as it determines who can access what data and resources in the cloud. The user needs to implement proper authentication and authorization methods, such as passwords, tokens, biometrics, etc., to verify the identity and privileges of the users accessing the cloud. The user also needs to enforce the principle of least privilege, which means granting the minimum level of access required for the users to perform their tasks. Additionally, the user needs to manage the access rights and roles of the users, and to revoke or modify them when necessary .
- **Migration to vendors**: Migration to vendors is the process of moving data and applications from one cloud service provider to another, or from the cloud to the on-premises environment. Migration to vendors can pose several challenges for cloud security, such as data loss, data corruption, compatibility issues, downtime, etc. The user needs to ensure that the data and applications are securely transferred and stored in the new cloud environment, and that the old cloud environment is properly decommissioned and erased. The user also needs to verify that the new cloud service provider meets the user's security and compliance requirements .
- **Lack of experienced workforce**: Cloud security requires a skilled and knowledgeable workforce that can understand and manage the complex and dynamic cloud environment. However, there is a shortage of qualified and experienced cloud security professionals in the market, which can hamper the user's ability to implement and maintain effective cloud security measures. The user needs to invest in training and educating the existing staff, and to recruit and retain the new talent, to ensure that the cloud security team is competent and capable of handling the cloud security challenges .

# Software‐as‐a‐Service Security

Software‐as‐a‐Service (SaaS) is a licensing model in which access to software is provided on a subscription basis, where the software is located on external servers rather than on servers located in-house. SaaS security refers to the practices and policies implemented by the providers of SaaS to ensure the privacy and security of customer data in cloud-based applications and other information assets.

# Virtual Machine Security for the notes of the Unit 4 - Resource Management And Security In Cloud in the subject of Cloud Computing

- Virtual machine (VM) security is the protection of the virtualized software components and data that run on cloud computing platforms.
- VM security is a subdomain of cloud security, which includes processes to protect services, applications, data, virtualized IP, and the related infrastructure of cloud computing systems.
- VM security is crucial for cloud computing, where operators construct workloads and applications on-demand, and where security services and functions need to move around with those on-demand-created workloads.
- VM security faces unique challenges and risks, such as:
  - VM sprawl: the uncontrolled proliferation of VMs that can lead to resource exhaustion, configuration drift, and security gaps.
  - VM escape: the exploitation of a vulnerability in the hypervisor or the guest OS that allows an attacker to break out of a VM and access the host or other VMs.
  - VM isolation: the separation of VMs from each other and from the host to prevent unauthorized access, data leakage, or interference.
  - VM mobility: the movement of VMs across hosts or clouds that can introduce compatibility, performance, or compliance issues.
- VM security can be achieved by following some best practices, such as:
  - Protecting VMs from viruses and malware by using antimalware software from security vendors such as Microsoft, Symantec, Trend Micro, and Kaspersky.
  - Encrypting sensitive data stored on VMs or in transit by using encryption tools such as BitLocker, Azure Disk Encryption, or Azure Key Vault .
  - Securing network traffic to and from VMs by using firewalls, network security groups, application security groups, or Azure Firewall .
  - Identifying and detecting threats to VMs by using monitoring and auditing tools such as Azure Security Center, Azure Monitor, or Azure Sentinel .
  - Meeting compliance requirements for VMs by using policies and standards such as Azure Policy, Azure Blueprints, or Azure Compliance Manager .

# Security Standards for the notes of the Unit 4 - Resource Management And Security In Cloud in the subject of Cloud Computing

  - **ISO/IEC 27017**: This is a security standard established for cloud service providers and consumers with the goal of reducing the risk of a security incident in the cloud. # MapReduce

MapReduce is a programming paradigm that enables massive scalability across hundreds or thousands of servers in a Hadoop cluster. As the processing component, MapReduce is the heart of Apache Hadoop. The term "MapReduce" refers to two separate and distinct tasks that Hadoop programs perform:

- The **map** job: A map job takes a set of data and converts it into another set of data, where individual elements are broken down into tuples (key/value pairs).
- The **reduce** job: A reduce job takes the output from a map as input and combines those data tuples into a smaller set of tuples.

MapReduce is a software framework for easily writing applications which process vast amounts of data (multi-terabyte data-sets) in-parallel on large clusters (thousands of nodes) of commodity hardware in a reliable, fault-tolerant manner .

Some of the features of MapReduce are:

- **Distributed processing**: MapReduce distributes the data and the computation across multiple nodes in a cluster, allowing for parallel and scalable processing.
- **Fault tolerance**: MapReduce handles failures of nodes, network, or disk by automatically re-executing failed tasks on other nodes.
- **Data locality**: MapReduce moves the computation to the data, rather than the other way around, minimizing the network traffic and improving the performance.
- **Simplicity**: MapReduce provides a simple and intuitive programming model, where the developer only needs to specify the map and reduce functions, and the framework takes care of the rest.

Some of the applications of MapReduce are:

- **Word count**: A simple example of counting the frequency of words in a large text file.
- **Inverted index**: A common technique for building search engines, where the output is a mapping of words to the documents that contain them.
- **PageRank**: A famous algorithm for ranking web pages based on their links, used by Google.
- **Machine learning**: Many machine learning algorithms, such as k-means clustering, linear regression, and logistic regression, can be implemented using MapReduce.

# Federated Services and Applications for Hadoop

- Hadoop is an open source framework that enables distributed processing and storage of large-scale data using clusters of commodity hardware.
- Hadoop consists of two main components: Hadoop Distributed File System (HDFS) and MapReduce.
- HDFS is a distributed file system that provides high-throughput access to data across multiple nodes in a cluster. HDFS stores data as blocks and replicates them for fault tolerance.
- MapReduce is a programming model that allows parallel processing of data using key-value pairs. MapReduce consists of two phases: map and reduce. The map phase applies a user-defined function to each input key-value pair and generates intermediate key-value pairs. The reduce phase aggregates the intermediate key-value pairs by key and produces the final output.
- Hadoop also supports a variety of other components and applications that run on top of HDFS and MapReduce, such as Hive, Pig, HBase, Spark, etc. These are collectively known as the Hadoop ecosystem.

## HDFS Federation

- HDFS federation is a feature introduced in Hadoop 2.x that allows multiple independent NameNodes/namespaces to coexist in a cluster. A NameNode is the master node that manages the metadata and namespace of a HDFS cluster. A namespace is a logical view of the file system hierarchy.
- HDFS federation improves the scalability, performance, and isolation of HDFS by allowing multiple NameNodes to share the same pool of DataNodes. A DataNode is a worker node that stores and serves data blocks. Each DataNode registers with all the NameNodes in the cluster and sends periodic heartbeats and block reports to them.
- HDFS federation also enables the use of different storage policies and quotas for different namespaces, as well as the possibility of running different versions of Hadoop on the same cluster.
- HDFS federation is backward compatible and does not require any changes to the existing single NameNode configuration. The new configuration is designed such that all the nodes in the cluster have the same configuration without the need for deploying different configurations based on the node type.

## Federated Services and Applications for Hadoop

- Federated services and applications for Hadoop are those that leverage the HDFS federation feature to provide enhanced functionality and performance for Hadoop users and developers.
- Some examples of federated services and applications for Hadoop are:

  - Federated HDFS: A service that allows users to access multiple HDFS namespaces using a single logical URI. Federated HDFS provides a unified view of the data across different namespaces and enables transparent data movement and replication among them.
  - Federated MapReduce: A service that allows users to run MapReduce jobs across multiple HDFS namespaces. Federated MapReduce provides a unified job submission and execution framework that can dynamically allocate resources and balance the workload among different namespaces.
  - Federated Hive: An application that allows users to query and analyze data stored in multiple HDFS namespaces using HiveQL. Federated Hive provides a unified schema and metadata management system that can handle heterogeneous data sources and formats.
  - Federated HBase: An application that allows users to store and access structured and semi-structured data in multiple HDFS namespaces using HBase. Federated HBase provides a unified table and column family management system that can handle different storage policies and consistency levels.

- Federated services and applications for Hadoop can benefit from the advantages of HDFS federation, such as increased scalability, performance, isolation, and flexibility. They can also enable new use cases and scenarios that were not possible or efficient with the single NameNode architecture.
