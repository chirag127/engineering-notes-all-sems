# Unit 1 - Introduction: History of Web and Internet

- The development of the World Wide Web was begun in 1989 by Tim Berners-Lee and his colleagues at CERN, an international scientific organization based in Geneva, Switzerland.
- They created a protocol, HyperText Transfer Protocol (HTTP), which standardized communication between servers and clients.
- The World Wide Web was introduced as an internet that was not simply a way to send files from one place to another but was itself a “web” of information that anyone on the Internet could retrieve.
- The Web was originally conceived and developed to meet the demand for automated information-sharing between scientists in universities and institutes around the world.
- The Internet, a system architecture that has revolutionized communications and methods of commerce by allowing various computer networks around the world to interconnect, emerged in the United States in the 1970s but did not become visible to the general public until the early 1990s.
- The term "World Wide Web" is often mistakenly used as a synonym for the Internet, but the Web is a service that operates over the Internet, just as email and Usenet do.



# Protocols Governing Web

1. **TCP/IP (Transmission Control Protocol/Internet Protocol)**: This is the set of protocols used to communicate across the internet. It is also widely used on many organizational networks due to its flexibility and wide array of functionality provided.
2. **SMTP (Simple Mail Transfer Protocol)**: These protocols are important for sending and distributing outgoing emails.
3. **HTTP (HyperText Transfer Protocol)**: This protocol is used to request the webpage contents from an IP address.
4. **FTP (File Transfer Protocol)**: This protocol is used for transferring files over the internet.
5. **DNS (Domain Name System)**: This protocol is used to convert a domain name into an IP address.

These are some of the common protocols governing the web. Each protocol has its own set of rules and is used to communicate applications to each other.

# Introduction to Client-Server Computing

- Client-server computing is a distributed computing model in which client applications request services from server processes.
- In this model, the client and server are separate entities, often running on different machines and communicating over a network.
- The client is responsible for the user interface and presentation logic, while the server handles the data storage and business logic.
- This separation of concerns allows for greater scalability, as multiple clients can access the same server resources.
- Common examples of client-server systems include web applications, where the client is a web browser and the server is a web server, and database systems, where the client is a database application and the server is a database server.
- The client-server model is widely used in modern computing and forms the basis of many internet-based services.

### Multithread Programming

Multithreading is a type of execution model that allows multiple threads to exist within the context of a process such that they execute independently but share their process resources.

- A thread is the smallest unit of processing that can be scheduled by an operating system.
- Multithreading enables the processing of multiple threads concurrently within a single process.
- Threads share the same address space and have access to the same data and resources as the parent process.
- Multithreading can improve the performance of certain types of applications by allowing multiple threads to work on different tasks concurrently.
- Multithreading can be implemented at the user level or the kernel level.
- User-level threads are managed by a user-level library and the kernel is not aware of them.
- Kernel-level threads are managed by the operating system and the kernel schedules them for execution.
- Multithreading can be used to implement parallelism, where multiple threads work on different parts of a problem concurrently to speed up the overall processing time.
- Multithreading can also be used to implement concurrency, where multiple threads work on different tasks concurrently to improve the responsiveness of an application.

# Introduction to AWT

AWT stands for Abstract Window Toolkit. It is a platform-dependent API for creating Graphical User Interfaces (GUIs) for Java programs. AWT was introduced in JDK 1.0 and is part of the Java Foundation Classes (JFC). Here are some key points to note about AWT:

1. AWT is platform-dependent, meaning that the appearance of AWT components may vary depending on the operating system and windowing system used.
2. AWT provides a set of pre-built components such as buttons, text fields, labels, and menus that can be used to create GUIs.
3. AWT also provides layout managers to control the positioning of components within a container.
4. AWT uses native system resources to create and manage GUI components, which can result in better performance and a more native look and feel.
5. AWT is not as feature-rich as its successor, Swing, and is generally considered to be outdated for modern GUI development.



### AWT Controls

AWT (Abstract Window Toolkit) is a set of Java classes used to create graphical user interfaces (GUIs). AWT controls are the basic building blocks of a GUI application. These controls are also known as components or widgets. Some of the commonly used AWT controls are:

1. **Label:** A label is a component that displays a single line of read-only text. It is used to provide information to the user.
2. **Button:** A button is a component that triggers an action when clicked by the user. It is used to initiate an action or submit data.
3. **TextField:** A text field is a component that allows the user to enter a single line of text. It is used to get input from the user.
4. **TextArea:** A text area is a component that allows the user to enter multiple lines of text. It is used to get input from the user.
5. **Checkbox:** A checkbox is a component that allows the user to select or deselect an option. It is used to get a boolean input from the user.
6. **Choice:** A choice is a component that allows the user to select one option from a list of options. It is used to get a single selection from the user.
7. **List:** A list is a component that allows the user to select one or more options from a list of options. It is used to get multiple selections from the user.

These are some of the basic AWT controls used in creating GUI applications. Each control has its own set of properties and methods that can be used to customize its appearance and behavior. AWT also provides layout managers to arrange these controls in a container. A container is a component that can hold other components. The most commonly used container is the Frame, which represents a window in a GUI application. AWT also provides event handling mechanisms to handle user interactions with the controls.



### Layout Managers

Layout managers are used to arrange components in a container. They are responsible for positioning and sizing components within the container based on the layout manager's rules. There are several layout managers available in Java, including:

1. **BorderLayout**: This layout manager arranges components in five regions: north, south, east, west, and center. Each region can contain only one component.

2. **FlowLayout**: This layout manager arranges components in a row, from left to right. If there is not enough space in the row, the layout manager moves the components to the next row.

3. **GridLayout**: This layout manager arranges components in a grid of rows and columns. All components are the same size and are placed in the cells of the grid.

4. **CardLayout**: This layout manager arranges components as a stack of cards. Only one card is visible at a time, and the user can switch between cards.

5. **GridBagLayout**: This layout manager is similar to GridLayout, but it allows for more flexibility in the placement and sizing of components. Components can span multiple rows and columns, and their size can be specified using weights.

6. **BoxLayout**: This layout manager arranges components either horizontally or vertically. Components can be aligned and their size can be specified using weights.

7. **SpringLayout**: This layout manager allows for precise positioning of components using constraints. Constraints can be used to specify the distance between components, or to align components relative to each other.

These are some of the commonly used layout managers in Java. Each layout manager has its own set of rules and behaviors, and it is important to choose the right layout manager for the task at hand.
